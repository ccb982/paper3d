# 动态支撑：接触约束优先，阻尼在可行域内

日期：2026-11-25

> 本文是动态支撑的修正定稿。
> 之前“支撑力矩固定、阻尼不能碰支撑”的表述过于简化。
> 正确原则：**接触可行性固定；支撑力是可行域内的变量；阻尼可以修改支撑力，但不能破坏接触，并且必须真的降低加速度。**

## 1. 优先级

```text
0. 接触硬约束
   foot contact / unilateral / friction / CoP / torque limits

1. 支撑
   fz / CoP，尽量平滑、尽量少产生加速度

2. 削加速度
   肌肉阻尼 + 被动刚度 + 加速度反馈
   可以修改支撑力，但只能在接触可行域内

3. IK / 回正
   接触稳定 + 近似静态 + 偏离足够大，才允许

CoM：只做参考/校验，不精确追
```

关键区分：

```text
“支撑优先”不是“支撑力矩固定不能改”
“接触优先”才是硬约束
```

支撑力可以变，只要：

```text
脚不丢接触
CoP 在脚底支撑面内
摩擦锥/单边/力矩限制满足
修改后的支撑力确实让加速度变小
```

## 2. 论文依据

### 2.1 接触约束是最高优先级

- **Sentis & Khatib 2006 / 2022**：
  支撑接触是 constraint task；任务和姿态必须投影到接触零空间。
- **Kim et al. 2018, Prioritized WBC with Contact Constraints**：
  接触约束是硬约束；第一任务加速度要投影到接触零空间；
  QP 再求接触力，满足单边、摩擦锥、CoP；
  法向力加上限，用于 smooth contact transition；
  contact force tracking 放在最低优先级。
- **Herzog et al. 2016**：
  分层逆动力学；接触约束高于动量/姿态。
- **Wensing 2023**：
  接触约束是“common and essential equality task”。

结论：

```text
接触/CoP/摩擦/单边 = 硬约束
支撑力 = 可行域内的决策变量
阻尼 = 可以改支撑力，但只能改可行域内的量
```

### 2.2 动态支撑要尽量少产生加速度

- **Hyon & Cheng 2006/2007**：
  GAF 只做抗重力 + 小任务力，再分配到接触点；
  最后 joint-wise damping 抑制内部运动。
- **Stephens & Atkeson 2010, DBFC**：
  先给 CoM 期望加速度，再反解接触力，不直接追关节。
- **DLR Humanoids 2019**：
  QP 同时最小化 CoM 残差和接触力，`Qc >> Qf`；
  接触力尽量小，法向力有上限，用于平滑接触力过渡。
- **Kim et al. 2018**：
  QP 里加 normal force upper bound，专门做 smooth contact force transition。

对应到我们：

```text
支撑力目标 = m(g + a_des)
a_des 尽量小
不是“用力把髋顶到某个高度”
```

### 2.3 阻尼可以进入支撑，但要被接触约束管住

- **DLR Humanoids 2019**：
  接触脚由 QP wrench 控制；
  为了稳脚，额外加 `w_stabil = -Dν` 到接触 wrench；
  它只在脚移动时生效，并作为 CoM 任务的 disturbance 被处理。
- **Kim et al. 2018**：
  接触力 QP 有法向力上限和接触约束；
  阻尼/任务不能绕过这些约束。

“削得对”意味着：

```text
1. 用速度/加速度反馈，不是随便加阻尼
2. 削完后的接触 wrench 仍在 CWC/CoP/friction 内
3. 如果阻尼会让支撑不可行，clip 阻尼，不是 clip 接触
4. 目标是最小化 ||a|| / ||q̈||，不是让关节硬住
```

## 3. 数学形式

浮动基动力学：

```text
M(q)ν̇ + C(q,ν)ν + G(q) = Sᵀτ + J_cᵀ f_c
```

接触约束：

```text
J_c ν̇ + J̇_c ν = 0
f_c ∈ 接触可行域（单边/摩擦/CoP/CWC/力矩上限）
```

支撑任务：

```text
f_z,total = m(g + a_des)
a_des 小；CoM 只做校验/慢参考
```

阻尼任务：

```text
τ_muscle = -D q̇ - K_passive Δq + τ_acc
D/K 来自肌肉模型：SRS、eccentric、共收缩
```

不能在接触方向随意外加。正确方式是二选一：

```text
A. 把阻尼作为接触力/全身 QP 的一个低优先级任务
   接触约束硬；阻尼只改可行域内的 f_c/τ

B. 支撑 base 先定，阻尼投影到接触零空间
   τ_leg = τ_support + N_cᵀ τ_muscle
   N_c = I - J_cᵀ J̄_cᵀ
```

不是：

```text
支撑力矩固定死 + 阻尼另开一个 torque 写手
```

## 4. 推荐控制结构

```text
Level 0：接触硬约束
  foot contact / CoP / friction / unilateral / torque

Level 1：支撑 + 抗重力
  fz/CoP，尽量平滑，a_des 小

Level 2：削加速度
  D/K/SRS/加速度反馈
  在接触可行域/零空间内修改支撑力

Level 3：姿态 / IK / 回正
  只在接触稳定、近似静态、偏离足够大时启用

CoM：参考/校验
```

## 5. 当前代码差距

已经具备：

```text
contactRead 单一接触读入口
FootAnkleModule 脚/踝单写手
supportQp 只输出 fz/CoP
pd()/computeMuscleDamping 肌肉 K/D/SRS
```

还没做到：

```text
1. 接触还不是硬约束；脚 roll/抬脚仍能破坏接触
2. 阻尼在 QP 模式下仍是全量叠加，没有严格投影到接触零空间
3. supportQp 只有 fz/CoP，没有 CWC/摩擦/单边硬约束
4. 旧 supportWbc/sagittalBase 仍存在，需归档
5. 踝 K/D 由踝肌群自己负责；不要求和髋/膝统一，只检查是否和支撑任务对拉
```

## 6. 验收

```text
1. 接触不丢：contact/CoP 始终可行
2. 削加速度只改可行域内的支撑力
3. 阻尼后 ||q̈|| / ||a_com|| 下降
4. fzUse / fzAct 链路闭合
5. IK 只在接触稳定后启用
6. CoM 只用于参考/校验
```
