# 动态支撑：接触约束优先，阻尼在可行域内

日期：2026-11-25

> 本文是动态支撑的修正定稿。
> 之前“支撑力矩固定、阻尼不能碰支撑”的表述过于简化。
> 正确原则：**接触可行性固定；支撑力是可行域内的变量；阻尼可以修改支撑力，但不能破坏接触，并且必须真的降低加速度。**

## 0. 串行求解是重中之重

禁止把 IK、支撑、CoM、CoP、加速度、阻尼全部塞进一个加权 QP 并行求解。
那不是“多任务”，是互相污染。

正确方式是严格串行/分层：

```text
Stage 0：抓地可行性
  contact 存在？
  CWC / CoP / 摩擦 / 单边 / fz_min 可行？
  → 输出可行接触力集合 F_grip

Stage 1：支撑
  在 F_grip 内求 fz/CoP
  min ||a_des|| + ||fz - fz_prev||²
  → 输出支撑接触力 f_support

Stage 2：削加速度
  在 f_support 的接触零空间/可行域内加 D/SRS/加速度反馈
  如果会破坏 F_grip，clip 阻尼，不是 clip 接触
  → 输出 f_support_damped

Stage 3：IK / 回正
  只在前两层稳定后，在剩余零空间里做

CoM：只做校验，不进入求解
```

串行原则：

```text
每阶段只解决一个问题
上一阶段的输出 = 下一阶段的约束/初值
下一阶段不能改变上一阶段的硬约束
不允许用一个大加权 QP 把冲突藏进权重里
```

论文对应：

```text
严格 HQP / lexicographic = 串行分层（Kim 2018, HRP-4 2019, Sentis/Khatib）
weighted QP 也存在，但不是我们这里的选择
接触约束在两种做法里都必须是硬约束
```

补充（2026-11-25 修正）：

```text
接触/抓地状态：硬约束，不能近似丢
  contact / unilateral / CWC / CoP / fz_min 必须满足
  求解器可以用 slack/relaxation，但约束本身不松

支撑力：范围内近似可行
  Stage 1 输出的是支撑力可行区间/包络，不追精确最优

阻尼：可以修改支撑力/接触 wrench
  但不能修改接触状态，也不能越过 CWC/CoP/fz_min
  越界时 clip 阻尼，不是 clip 接触
```

## 1. 优先级

```text
0. 接触硬约束
   foot contact / unilateral / friction / CoP / torque limits

1. 支撑
   fz / CoP，尽量平滑、尽量少产生加速度

2. 削加速度
   肌肉阻尼 + 被动刚度 + 加速度反馈
   可以修改支撑力，但只能在接触可行域内

3. IK / 回正
   接触稳定 + 近似静态 + 偏离足够大，才允许

CoM：只做参考/校验，不精确追
```

关键区分：

```text
“支撑优先”不是“支撑力矩固定不能改”
“接触优先”才是硬约束
```

### 1.1 上身范围（2026-11-25 定稿）

```text
上身不主动控制
  只做重力补偿 + 阻尼
  目标=当前姿态，不追回正
  不发主动摆臂/躯干姿态命令
  不参与支撑/IK
```

目的：

```text
上身不乱动
```

下身才做精确控制：

```text
脚/踝接触
→ 支撑力
→ 削加速度
→ IK/回正
```

也就是说：

```text
上身：被动 / 重力 / 阻尼
下身：精确接触、支撑、阻尼、IK
```

支撑不看姿态：

```text
支撑只维持当前状态需要的力矩：
  fz_total = m(g + a_des)
  + 当前几何/CoP 下的静态 ID
不把 contactIK 的目标角塞进支撑。
contactIK 不参与支撑，只在支撑/削加速度稳定后参与回正。
```

支撑力可以变，只要：

```text
脚不丢接触
CoP 在脚底支撑面内
摩擦锥/单边/力矩限制满足
修改后的支撑力确实让加速度变小
```

支撑不是精确解：

```text
fz ∈ [fz_min, fz_max]
CoP ∈ 支撑面（带 margin）
```

但接触/抓地状态不是“近似解”：

```text
contact / unilateral / CWC / CoP / fz_min 是硬约束
求解器 slack 不代表允许丢接触
```

阻尼可以修改支撑力/接触 wrench，只要还在这个可行包络里；
它不能把脚写成离地，也不能把 CoP 推出脚底。

## 2. 论文依据

### 2.1 接触约束是最高优先级

- **Sentis & Khatib 2006 / 2022**：
  支撑接触是 constraint task；任务和姿态必须投影到接触零空间。
- **Kim et al. 2018, Prioritized WBC with Contact Constraints**：
  接触约束是硬约束；第一任务加速度要投影到接触零空间；
  QP 再求接触力，满足单边、摩擦锥、CoP；
  法向力加上限，用于 smooth contact transition；
  contact force tracking 放在最低优先级。
- **Herzog et al. 2016**：
  分层逆动力学；接触约束高于动量/姿态。
- **Wensing 2023**：
  接触约束是“common and essential equality task”。

结论：

```text
接触/CoP/摩擦/单边 = 硬约束
支撑力 = 可行域内的决策变量
阻尼 = 可以改支撑力，但只能改可行域内的量
```

### 2.2 动态支撑要尽量少产生加速度

- **Hyon & Cheng 2006/2007**：
  GAF 只做抗重力 + 小任务力，再分配到接触点；
  最后 joint-wise damping 抑制内部运动。
- **Stephens & Atkeson 2010, DBFC**：
  先给 CoM 期望加速度，再反解接触力，不直接追关节。
- **DLR Humanoids 2019**：
  QP 同时最小化 CoM 残差和接触力，`Qc >> Qf`；
  接触力尽量小，法向力有上限，用于平滑接触力过渡。
- **Kim et al. 2018**：
  QP 里加 normal force upper bound，专门做 smooth contact force transition。

对应到我们：

```text
支撑力目标 = m(g + a_des)
a_des 尽量小
不是“用力把髋顶到某个高度”
```

### 2.3 阻尼可以进入支撑，但要被接触约束管住

- **DLR Humanoids 2019**：
  接触脚由 QP wrench 控制；
  为了稳脚，额外加 `w_stabil = -Dν` 到接触 wrench；
  它只在脚移动时生效，并作为 CoM 任务的 disturbance 被处理。
- **Kim et al. 2018**：
  接触力 QP 有法向力上限和接触约束；
  阻尼/任务不能绕过这些约束。

“削得对”意味着：

```text
1. 用速度/加速度反馈，不是随便加阻尼
2. 削完后的接触 wrench 仍在 CWC/CoP/friction 内
3. 如果阻尼会让支撑不可行，clip 阻尼，不是 clip 接触
4. 目标是最小化 ||a|| / ||q̈||，不是让关节硬住
```

## 3. 数学形式

浮动基动力学：

```text
M(q)ν̇ + C(q,ν)ν + G(q) = Sᵀτ + J_cᵀ f_c
```

接触约束：

```text
J_c ν̇ + J̇_c ν = 0
f_c ∈ 接触可行域（单边/摩擦/CoP/CWC/力矩上限）
```

支撑任务：

```text
f_z,total = m(g + a_des)
a_des 小；CoM 只做校验/慢参考
```

阻尼任务：

```text
τ_muscle = -D q̇ - K_passive Δq + τ_acc
D/K 来自肌肉模型：SRS、eccentric、共收缩
```

不能在接触方向随意外加。正确方式是二选一：

```text
A. 串行分层：
   先解接触/抓地可行性
   再解支撑
   最后在接触零空间里加阻尼
   不允许把三者加权成一个并行 QP

B. 关节层：
   τ_leg = τ_support + N_cᵀ τ_muscle
   N_c = I - J_cᵀ J̄_cᵀ
```

不是：

```text
支撑力矩固定死 + 阻尼另开一个 torque 写手
```

## 4. 推荐控制结构

```text
Level 0：接触硬约束
  foot contact / CoP / friction / unilateral / torque

Level 1：支撑 + 抗重力
  fz/CoP，尽量平滑，a_des 小

Level 2：削加速度
  D/K/SRS/加速度反馈
  在接触可行域/零空间内修改支撑力

Level 3：姿态 / IK / 回正
  只在接触稳定、近似静态、偏离足够大时启用

CoM：参考/校验
```


## 6. 验收

```text
1. 接触不丢：contact/CoP 始终可行
2. 削加速度只改可行域内的支撑力
3. 阻尼后 ||q̈|| / ||a_com|| 下降
4. fzUse / fzAct 链路闭合
5. IK 只在接触稳定后启用
6. CoM 只用于参考/校验
```
