# 架构评估：当前实现 vs 理论架构（2026-11-26）

## 0. 结论

当前实现已经具备：

```text
接触/CoP 硬约束入口
浮动基 ID 雏形
踝支撑命令层
支撑/姿态初步分离
踝直接力矩通道
```

但和理论上的完整架构相比，仍是**混合版**，不是完整 TSID。

## 1. 理论架构

```text
Stage 0：接触/抓地硬约束
  contact / CWC / CoP / fz_min / 单边

Stage 1：支撑
  support QP
  → 目标 fz / CoP / 接触 wrench W
  → 浮动基 ID
  → hip/knee/ankle 支撑力矩

Stage 2：削加速度
  接触可行域内的阻尼/加速度反馈

Stage 3：姿态/回正
  只改 qRef / CoP 目标
  不再生成支撑力矩

执行层：
  两组 PD 只执行角度
  Executor 执行直接力矩
```

已删：

```text

```

仍保留：

```text

```

所以还不是严格单写手。

## 4. 当前最大风险

```text
1. 支撑 fz 还没完全闭环
2. W 还没完整满足浮动基平衡
3. C/q̈ 不完整
4. 踝支撑仍是 5% mix，力矩偏小
5. Foot2.cop 旧写手仍存在
6. 浮动基 ID 10Hz + base trim 可能掉帧
```

## 5. 与理论架构的差距

| 模块 | 理论 | 当前 |
|---|---|---|
| Stage0 | CWC/CoP/fz_min 硬约束 | 部分 |
| Stage1 W | 约束 QP 满足浮动基 6 行 | 后处理 trim |
| 浮动基 ID | 完整 TSID | M/G/Jc + 静态近似 |
| C(q,q̇) | 全维 | 未完整 |
| q̈ | 全维目标 | 部分/近似 |
| Stage2 | 接触零空间阻尼 | PD 动态阻尼为主 |
| Stage3 | 独立姿态/回正层 | 仅剥离 IK |
| 写手 | 单写手 | 仍有 2-3 个 |

## 6. 建议顺序

```text
1. 收敛 squat.foot2.cop，确保踝支撑单写手
2. Stage 1：带 CoP/fz/CWC 的 W QP，满足浮动基 6 行
3. 补全维 C(q,q̇)
4. 补全维 q̈
5. 独立姿态层
6. 清工具与实验开关
```

当前基线：

```text
full hold ≈2.07s（历史回读）
Chrome 无抬脚
```

但基线仍有波动，不能把单次 hold 当成稳定性证明。
