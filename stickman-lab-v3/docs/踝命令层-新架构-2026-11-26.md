# 踝命令层新架构（2026-11-26）

## 0. 一句话

**接触/抓地是硬约束；支撑是命令层力矩；阻尼在支撑可行域内；回正只改 CoP 目标；PD 只执行。**

## 1. 分层边界

### 命令层

```text
Stage 0 接触/抓地
Stage 1 支撑
Stage 2 削加速度
Stage 3 回正
```

命令层负责：

```text
fz
CoP
踝支撑力矩
阻尼量
回正目标偏移
```

命令层不负责：

```text
关节角跟踪
PD 增益
电机电流
```

### 执行层

```text
两组 PD：
  A：髋 / 大腿 / 膝
  B：小腿 / 踝 / 脚

Executor：
  角度任务 → PD
  力矩任务 → addTorque / ext
```

执行层不负责：

```text
CoP
支撑力分配
回正决策
接触优先级
```

## 2. 当前已实现设计

### 2.1 支撑

```text
supportQp
→ fzUse / copXUse / tauZ
```

实际 CoP 同时进入支撑 ID：

```text
copXSupport = 实际 copXFiltered
```

### 2.2 踝命令

```text
ankleSupportCommand:
  τ = clamp(
    fzDes · (CoPDes − ankle)
  + fz · (Kp · (CoPDes − CoPAct) − Kd · CoPVel),
    ±τmax
  )
```

默认目标：

```text
CoPDes = copXDesired
```

### 2.3 执行

```text
lowerCommand.ankleSupport
  kind = ext
  tau = 20% ankleFf
```

同时：

```text
lowerCommand.ankleComp
  只保留踝角度/姿态
```

### 2.4 当前基线

```text
full hold ≈ 2.475s
Chrome 抬脚帧 = 0
fz 平均误差 ≈ 64.5N
fz 最大误差 ≈ 276.9N
foot2Applied 峰值 ≈ 12.5Nm
```

### 2.5 当前问题

```text
1. 踝支撑仍有多个来源：
   lowerCommand.ankleSupport
   squat.foot2.cop
   ankleComp 角度
2. 支撑力矩只有 20% 走直接 ext
3. Stage 1 QP 没有显式 tauMin
4. 旧 foot2Local 前馈还不能直接删
5. CP/回正反馈没有单独形成命令项
```

## 3. 目标踝命令层写手

### 3.1 唯一写手

```text
lowerCommand.ankleTorque
```

只允许它写踝支撑力矩。

删除或合并：

```text
squat.foot2.cop
ankleCopServo
qpAnkleTrim
FootAnkleModule 的 support qRef 偏移
ankleComp 的支撑分量
```

踝角度写手只保留：

```text
lowerCommand.anklePosture
```

负责脚姿态/接触姿态，不负责支撑。

### 3.2 命令层输入

```text
fzDes
fzAct
CoPDes
CoPAct
CoPVel
ankleX
foot polygon / margins
q, q̇
τmin / τmax
dt
```

### 3.3 命令层输出

```text
tauAnkle
copTarget
saturated
feasible
```

不输出：

```text
qRef 偏移
kp/kd
PD 力矩
```

### 3.4 命令层内部顺序

```text
Stage 0：接触门
  contact / CoP / CWC / 单边 / fz_min
  不满足 → 支撑/阻尼/回正全部退出

Stage 1：支撑
  CoPDes = clamp(CoP_support, 支撑面 − margin)
  τ_support = fzDes · (CoPDes − ankle)
  约束 τmin/τmax

Stage 2：削加速度
  τ_damp = −D · q̇
  只在 Stage 1 可行域内
  冲突时缩阻尼，不缩接触

Stage 3：回正
  CoPDes = clamp(CoP_support + CoP_right, 支撑面 − margin)
  回正只改 CoP 目标，不新增写手
```

### 3.5 最终公式

```text
CoPDes = clamp(
  CoP_support + CoP_right,
  支撑面 − margin
)

τ_support = fzDes · (CoPDes − ankle)

τ_fb =
  Kp · (CoPDes − CoPAct)
− Kd · CoPVel

τ_ankle = clamp(
  τ_support + τ_fb − D·q̇,
  τmin,
  τmax
)
```

### 3.6 优先级

```text
接触/抓地 > 支撑 > 削加速度 > 回正
```

冲突规则：

```text
接触不可破
支撑不可越 CoP/CWC
阻尼不可越支撑可行域
回正不可越剩余 margin
```

## 4. 执行层接口

命令层只发：

```text
tauAnkle
qRef（姿态）
```

执行层：

```text
PD(qRef, kp, kd)
Executor.addTorque(tauAnkle)
```

PD 不读：

```text
CoP
fz
支撑 QP
回正
```

PD 的动态阻尼只做局部关节阻尼：

```text
kd / tauDyn 随 q̈、q̇ 变化
```

它不能替代 Stage 2 的命令层阻尼。

## 5. 重构顺序

```text
1. 把 foot2Local 的整帧前馈移入 ankleTorqueCommand
2. 删除 squat.foot2.cop 的重复支撑写手
3. 删除 FootAnkleModule 支撑 qRef 偏移
4. 加 CP 反馈和 Stage 2 阻尼
5. Stage 1 加 τmin
6. 最后再提高直接力矩比例
```

## 6. 论文依据

```text
Stephens & Atkeson 2007
  CoP 与踝力矩近似成正比；参考力矩 + CoP clamp

Kim et al. 2018
  低层位置 PD + feedforward torque；PD 不负责平衡

HRP-4 2019（Caron et al.）
  wrench QP + foot damping；CoP 目标由命令层给

Lee & Goswami 2010
  每脚 GRF/CoP 分配；双支撑踝力矩分配

人体踝阻抗（Kearney & Hunter 等）
  τ = K(θ−θ0) + Bθ̇
  高刚度是阻抗，不是竖直 fz
```

## 7. 验收

```text
Stage 0：contact / CoP / CWC / 单边 / fz_min 成立
Stage 1：fzAct 跟 fzDes；CoP 在脚底
Stage 2：||q̈|| / ||a_com|| 下降，支撑残差不变
Stage 3：回正不破坏 CoP/接触

踝写手：
  支撑力矩只有一个来源
  角度姿态只有一个来源
  qRef 偏移不再承载支撑
```
