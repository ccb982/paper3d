# 髋稳定：诊断与论文依据（2026-11-16）

## 0. 结论

髋不是“力气不够”，是**命令层让髋一直在被大前馈拖着走**：

- `hip2` 的 PD 只有 `kp=50`，但基础力 `ff≈-73~-101 N·m`。
- `hip0/hip1` 的 `ff=0`，PD 只能靠很小的角度误差出力。
- `hipBudget` 在 CoP 边缘会把 hip0/1 的目标夹死。
- `SQC_RIGHTING_OFF=1`，ID 髋修正默认没接。
- `SQC_PD_PAIR_HIP_LAT=1` 让 `lock0/lock1` 分支根本不生效。

所以髋在“乱动”，而且一动就是大扰动。

论文里，髋是**大扰动策略**，不是常态主策略；小扰动下踝策略占 90% 以上。对蹲姿，默认应该**锁髋**，让踝去控 CoP；只有 CoP/CoM 大偏差时才放开慢速髋策略。

## 1. 实测：髋到底发生了什么

`_probe-shank-pd`（加入髋键）t=3.0~3.9：

```text
hip_l/0: tgt≈-8.3° act≈-8.7°  ff=0     pas≈±5   tau≈±8
hip_l/1: tgt≈4~5°  act≈4°    ff=0     pas≈±8   tau≈±10
hip_l/2: tgt≈105~112° act≈113→99° ff=-73~-101  cap=150  tau≈-80
```

解释：

- `hip0/1` 的 PD 误差很小，且没有前馈，基本“跟着走”。
- `hip2` 被一个很大的负基础力拉着，PD `kp=50` 完全压不住。
- `hip2` 的 `base2Ff ≈ out2Ff ≈ -73~-101`，说明基础力本身就是主要扰动源。

## 2. 论文依据

### 2.1 踝策略是默认，髋策略是大扰动

- Horak & Nashner 1986：踝策略用于小扰动；髋策略用于更大/更快扰动。
- Nashner & McCollum 1985：踝/髋是两种基本策略。
- Runge et al. 1999：快速平移时髋力矩叠加到踝力矩上；**纯髋策略很少见**，是连续混合。
- Blenkinsop et al. 2017：站立平衡中踝策略占 90% 以上。
- Frontiers 2022：混合策略只在边界情况有意义，常态是踝或髋之一。

结论：

```text
小偏差：踝控 CoP，髋锁住，不要乱动
大偏差：踝饱和后，髋再慢速接管
```

- Horak, Nashner 1986, J Neurophysiol 55:1369–1381
- Nashner, McCollum 1985, Behav Brain Sci 8:135–172
- Runge et al. 1999, Gait Posture 10:161–170
- Blenkinsop et al. 2017, R Soc Open Sci 4:161018
- https://royalsocietypublishing.org/rsos/article/4/7/161018
- Frontiers 2022, https://www.frontiersin.org/journals/computational-neuroscience/articles/10.3389/fncom.2022.956932/full

### 2.2 髋外展肌负责骨盆/大腿根稳定

- Neumann 2010：髋外展肌（臀中肌/臀小肌）在单腿支撑中稳定骨盆；臀中肌力可达体重的 2 倍以上。
- Stickler et al. 2015：髋外展力量是单腿蹲额状面膝/骨盆对线的最强预测因子之一。
- PMC10913509：臀中肌/臀小肌提供髋关节旋转和分离稳定性，作用随屈髋角度变化。

结论：

```text
髋的价值主要是“稳住骨盆/大腿根”，不是持续大范围摆动。
大腿根稳定 = 髋关节稳定；锁髋是最直接的实现。
```

- Neumann 2010, JOSPT 40:82–94
- https://www.jospt.org/doi/full/10.2519/jospt.2010.3025
- Stickler et al. 2015, Phys Ther Sport 16:66–71
- https://www.sciencedirect.com/science/article/abs/pii/S1466853X14000352
- PMC10913509, https://pmc.ncbi.nlm.nih.gov/articles/PMC10913509

### 2.3 髋刚度会影响策略

Nature Sci Rep 2025 的 RL 模型指出：髋刚度/CoP 约束会影响踝→髋策略切换；髋太软或太自由会让策略乱跳。

- https://www.nature.com/articles/s41598-025-97637-5

## 3. 推荐实现：默认锁髋

### 3.1 锁什么

在进入 squat / 释放时捕获：

```text
hip0_ref = t[s].hip0
hip1_ref = t[s].hip1
hip2_ref = t[s].hip2
```

锁髋模式：

```text
target = hip*_ref
kp = 4000 / 2500 / 2000
kd = 80 / 50 / 50
cap = 600 / 300 / 600
hip2_ff = 0（或很小的比例）
hipBudget 不夹锁髋目标
pairLat 不覆盖锁髋增益
```

这样髋不会再被基础力拖着走，也不会把扰动传到上身。

### 3.2 什么时候放开

```text
if |e_cop| > threshold or XCoM 出支撑面:
    慢速髋策略：kp 小、delay/ramp 大
else:
    继续锁髋
```

这和论文的 ankle→hip 切换一致；不是常开髋策略。

### 3.3 大腿根稳定

如果不想锁 `hip` 关节，可以在**大腿根**施加虚拟稳定力矩，保持大腿相对骨盆/世界姿态。数学上等价于锁髋；实现上更接近“external assist”。

优先级：

```text
1. 先锁髋关节（命令层，简单、可回读）
2. 不够再加 thigh-root 外力
```

## 4. 当前结果

```text
SQC_HIP_LOCK=0  npm run squat    1.565s
SQC_HIP_LOCK=1  npm run squat    2.719s
SQC_HIP_LOCK=1  npm run assist   2.052s（根力 + 关节力，反而更差）
SQC_HIP_LOCK=1 V3_AR_ROOT=0 npm run assist 2.285s
```

结论：

- 锁髋对**命令层**是明显提升：1.565 → 2.719s。
- 当前辅助外力与锁髋会打架；锁髋开启时，辅助层应先关，或重新标定 root 力。

## 6. 回退记录（2026-11-16）

锁髋默认已回退，原因是膝盖/小腿高频抖动：

```text
锁髋默认: knee0 qd 45.5Hz，knee2 qd 20.6Hz，foot2 qd 32.4Hz
无锁髋:   knee2 qd 3.7Hz，foot2 qd 5.0Hz
```

锁髋虽然把 fall 从 1.565 提到 2.719，但抖动不可接受；`SQC_PD_VEL_LP=0.05` 能压抖，但 fall 掉到 1.252。先回退默认，`SQC_HIP_LOCK=1` 保留为实验开关。

当前默认：

```text
npm run squat    1.565s
npm run assist   3.046s
```


## 7. 柔性锁髋尝试（2026-11-16）

试了 `SQC_HIP_LOCK_SOFT=1`：

```text
soft lock squat    1.265s
soft lock assist   2.648s
hip tau flips      48~73Hz
knee2 qd flips     43Hz
foot2 qd flips     40Hz
```

柔性锁髋没有解决抖动，反而 fall 变差；`SQC_HIP_SLEW=1` 也只能把 hard lock 从 2.719 压到 1.654。

结论：当前默认保持**锁髋关闭**；`SQC_HIP_LOCK`/`_SOFT` 只作为实验开关。膝/髋抖动的主因是 `pd()` 的速度阻尼（`SQC_PD_VEL_LP=0.2`）和髋高增益耦合，不是锁髋刚度本身。
