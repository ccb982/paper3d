# 辅助回正架构（Posture Assist / 虚拟外力）

日期：2026-11-16
适用：`stickman-lab-v3`（基于 `9baa02f6`，2026-11-10 v8 架构）

## 0. 一句话

用目标 IK 姿态和实际关节角的偏差，做一个**随时间增强的关节虚拟外力**：

```text
偏离初期：不出力
偏离持续：出力，且时间越久越强
回到目标：不出力，计时清零
```

不考虑力链、CoP、摩擦锥、QP，直接往目标姿态拉。

这是**纯关节外力层**：只读目标角和实际角，不读、不改力链，也不参与命令层的 IK/base force/PD/CoP 计算。命令层本身已经能坚持约 2s，够用；本模块不负责提升基础保持时间，只负责“偏离持续后，从外面把关节拉回来”。

只有一个外力写手：`v3.assistRighting`。每个 DOF 每步只产生一个外力矩，不存在两个外力对拉。现有命令层是内部伺服，不是外力；偏离持续后，外力会增长到足够大，压过残余伺服，把姿态拉回去。

## 1. 目标与非目标

### 1.1 目标

- 统一监控所有关节相对目标 IK 姿态的偏差。
- 偏差持续越久，辅助回正力矩越大。
- 回正顺序：腿最快 → 髋 → 上身 → 四肢。
- 只做“辅助”，不替换现有 PD；可以随时关闭。
- 第一版能模拟并观察回正过程（探针日志 + HUD）。
- 不要求提升命令层基础保持时间；当前约 2s 的基线够用，辅助只在偏离持续后接管。

### 1.2 非目标

- 不做力链/CoP/接触力分配。
- 不做 QP/WBC/逆动力学。
- 不做真实外力点，只做关节空间虚拟力矩。
- 不负责主姿态控制；主控制仍是 `squatClean` 的 IK + base force + PD。
- 不修改命令层：不改 IK、base force、CoP、PD 目标或增益。
- 不做“力链参与”：外力计算只依赖 `q`、`qd`、`q_ref`，不用 Fz/CoP/接触/摩擦。
- 不追求物理真实性；这是 v3 允许的“作弊层”。

### 1.3 纯外力边界

```text
允许读：q、qd、q_ref、时间、baseState
不允许算：Fz、CoP、摩擦锥、力链、逆动力学
输出：关节空间 tau，走唯一的 external 外力通道
```

命令层能站住 2s，这是本模块的前提；辅助回正不是“第二套平衡控制器”，只是在姿态偏差持续后加外力。`v3.assistRighting` 是唯一 external writer，其他层不要再加第二个外力写手。

## 2. 在现有架构中的位置

```text
World.advance
  updateDofState
  executor.beginStep
  control.step
    sensors.update
    PostureGuard.step          ← 本模块：监控 + 提交外力提案
    ⑥.95 提案仲裁
  drive.step
  executor.applyAll
  物理步进
```

放在 `ControlModule.step()` 内、提案仲裁之前，原因：

- 同一物理步生效，不引入额外一拍延迟。
- 网页/探针/以后其他模式共用同一入口。
- 仍然只通过 `propose()` 写提案，最终由 `Executor` 统一饱和和施加。

需要把 `v3.assistRighting` 加入 `control.ts` 的 `SQUAT_WRITERS` 白名单，否则蹲姿下提案会被过滤。

它不在命令层链路里：`squatFrame` 仍负责 IK/base/PD；本模块只旁路叠加纯外力，不插进命令层。

## 3. 数据流

```text
squatFrame / IK / 上身命令
        │
        ▼
PostureTarget（每 DOF 的目标角 q_ref + 有效位）
        │
sensors（q, qd）──► PostureGuard ──► AssistRighting
        │                               │
        │                               ▼
        │                    propose(kind:'ext', channel:'external')
        │                               │
        └──────────────► ControlModule 仲裁 ──► Executor
```

控制律只用 `q/qd/q_ref`；Fz/CoP/接触即使出现在监控数据里，也只用于 telemetry，不参与力矩计算。

### 3.1 PostureTarget

```ts
interface PostureTarget {
  t: number;
  q: Float64Array;      // 每个 DOF 的目标角（rad）
  valid: Uint8Array;    // 1 = 该 DOF 有可信目标
  source: 'ik' | 'command' | 'manual';
}
```

目标来源：

- 下盘：`squatFrame` 里的 IK 目标（hip0/1/2、knee0/2、foot0/1/2）。
- 上身：`upperBodyCommand` / `UpperTaskPD` 的目标（spine1-3、neck）。
- 四肢：动作层/手动目标；没有目标时 `valid=0`，该轴不参与辅助。
- `hip1` 如果 IK 没有明确目标，用命令层当前目标或捕获参考。

`PostureTarget` 由命令层发布，建议接口：

```ts
ctl.postureGuard.setTargets(targets);
```

`squatFrame` 当前在 `advance()` 之后运行，所以目标时间戳会比传感器晚一拍；目标变化慢，这一拍可以接受。若以后要求严格同步，可把 `squatFrame` 移到 `advance()` 之前。

## 4. 偏差与计时

### 4.1 偏差

```text
e_i   = q_ref_i - q_i
edot_i = -qdot_i
```

归一化：

```text
s_i = |e_i| / tol_i
```

### 4.2 偏离持续时间

每个 DOF 一个持久计时器 `D_i`：

```text
如果 |e_i| > e_in_i：
    D_i += dt
否则如果 |e_i| < e_out_i：
    保持 e_out 以下超过 t_hold_i 后，D_i = 0
否则：
    D_i 保持（迟滞区不增不减）
```

参数关系：

```text
e_in  > e_out        // 迟滞，防抖
t_hold = 0.2~0.4s    // 回到目标后多久清计时
```

### 4.3 目标变化

目标 IK 角变化超过阈值时，`D_i` 清零：

```text
if |q_ref_i(t) - q_ref_i(t-1)| > targetJump_i:
    D_i = 0
```

避免旧计时把新目标误判成“持续偏离”。

## 5. 随时间增强的回正力

### 5.1 增益曲线

```text
u_i = clamp((D_i - delay_i) / ramp_i, 0, 1)
g_i = g_max_i * smoothstep(u_i)
```

含义：

- `D_i < delay_i`：`g=0`，**偏离初期没有辅助**。
- `delay_i` 到 `delay_i + ramp_i`：平滑增强。
- 之后：保持 `g_max_i`，**偏离越久越强，但有上限**。

`g_max_i` 和 `cap_i` 按“最终能压过命令层残余伺服”来定：时间增长到 `g_max` 后保持，不衰减。压不过就调大 cap / 缩短 delay，不要引入第二个外力写手。

### 5.2 力矩

```text
tau_i = g_i * (kp_i * e_i - kd_i * qdot_i)
tau_i = clamp(tau_i, -cap_i, +cap_i)
```

`cap_i` 是外力自己的上限，不跟肌肉 τmax 共用。时间增长到 `g_max_i` 后，外力应足以压过该关节的命令层残余力矩。

可选：

- `deadband_i`：`|e_i| < deadband_i` 时 `tau=0`。
- `oneWay_i`：只在继续偏离时出力。
- `slew_i`：每步力矩变化限幅。

第一版**不做 contactScale**：外力只按角度偏差和时间出力，不引入 Fz/CoP/接触状态。若后续发现摆动腿被拉，再单独加角度/状态门控，但那不属于第一版。

### 5.3 回到目标

```text
if |e_i| < e_out_i:
    tau_i = 0
    如果持续时间 > t_hold_i：
        D_i = 0
        g_i = 0
```

满足“回正到位后没有辅助”。为了避免力矩瞬间断掉，可以在 `e_out` 附近做 0.05~0.1s 的淡出。

### 5.4 外力权限

目标：时间增长后，外力矩最终要大于命令层在该关节的残余力矩，把姿态拉回去。

```text
g_max_i = 1
cap_i   = max(V3_AR_CAP_MIN, V3_AR_AUTH * tauMax_i)
```

起点可以用 `V3_AR_AUTH = 2~3`，即外力上限是关节肌肉上限的 2~3 倍；走独立 external 通道，不受肌肉 τmax 饱和。

判定标准：

```text
在最大残余伺服力矩下，tau_ext 仍能把 e 拉回；
压不过就调大 cap / 缩短 delay；
不要加第二个外力写手。
```

## 6. 分层与优先级

### 6.1 层级

| 层 | 关节 | 响应 | 说明 |
|---|---|---|---|
| L0 腿 | `knee0/2`、`foot0/1/2`、`ankle` | 最快 | 先稳住支撑链末端 |
| L1 髋 | `hip0/1/2` | 次快 | 腿有支撑后再拉骨盆 |
| L2 上身 | `spine1-3`、`neck` | 中等 | 上身最后接管 |
| L3 四肢 | `shoulder`、`elbow`、`hand` | 最慢 | 只做姿态修饰，不抢平衡 |

### 6.2 参数起点

以下只是第一版起点，后面用探针扫：

```text
L0 腿：delay 0.03~0.08s，ramp 0.10~0.20s，kp 高，cap 高
L1 髋：delay 0.08~0.12s，ramp 0.20~0.30s，kp 中高
L2 上身：delay 0.15~0.25s，ramp 0.30~0.50s，kp 中
L3 四肢：delay 0.30~0.50s，ramp 0.50~0.80s，kp 低
```

### 6.3 总预算

所有关节的 `|tau|` 总和超过预算时，从最低优先级开始削减：

```text
1. 先削 L3 四肢
2. 再削 L2 上身
3. 再削 L1 髋
4. L0 腿最后削，尽量保
```

预算参数：

```text
V3_AR_BUDGET = 200~400 N·m（按体重和角色调）
```

## 7. 状态机

```text
OFF
  └─ 不监控、不出力

MONITOR
  └─ 只计算 e/D/g，不提交提案

PERSIST
  └─ D 在增长，但还没到 delay，不出力

ASSIST
  └─ g > 0，提交外力提案

RECOVER
  └─ |e| < e_out，tau=0；t_hold 后回 MONITOR/PERSIST
```

状态切换带迟滞，禁止单帧抖动。

## 8. 通道与冲突

### 8.1 单一外力写手

```text
src: 'v3.assistRighting'
每个 DOF 每步只产生一个 tau
```

不存在两个外力对拉：本模块是唯一的 external writer。现有命令层是内部伺服，不是外力；辅助允许在偏离持续后压过它。

推荐在 `Executor` 增加独立 `external` 并联通道（自己的记账和 cap，不跟肌肉 `cmd + pair` 的 τmax 共用）：

```text
最终力矩 = 肌肉 cmd/pair + support passive + external assist
```

这样外力可以随着时间增长到足够大，不受肌肉 τmax 限制。如果暂时不加新通道，可以用 `channel:'passive'` 走 `addPassiveTorque`，但它和 support passive 共用账本，不如独立通道干净；不建议用 `kind:'ext', channel:'support'`，那会和命令层抢同一通道。

### 8.2 后续：覆盖/锁死

如果确实需要“锁死/覆盖”：

- 覆盖：`channel:'support'` + `pri:PRI.direct`，同通道内赢过原命令。
- 绕过肌肉 τmax：`channel:'passive'`，走 `addPassiveTorque`。
- 真锁死：在 `Executor` 加独立 lock 通道，不要只靠高增益 PD。

这三种是不同语义，不要混在同一个 writer 里。

### 8.3 现有约束

- 蹲姿 `control.ts` 只允许 `SQUAT_WRITERS` 白名单里的 `src`。
- `Executor.applyAll` 仍然每 DOF 每步只施加一次。
- 不要直接调用 `executor.addTorque`；全部走提案总线。

## 9. 模拟回正过程

### 9.1 时间线示例

假设某个膝关节偏差 0.3 rad，`delay=0.08s`，`ramp=0.15s`：

```text
t=0.00  偏差出现，D=0，g=0，tau=0
t=0.05  仍在初期，g=0，tau=0
t=0.08  开始出力，g=0
t=0.12  g≈0.3，腿开始明显回拉
t=0.23  g=1.0，达到该层最大辅助
t=0.40  偏差缩小到 e_out 以下，tau=0
t=0.70  t_hold 到，D=0
```

### 9.2 分层响应

```text
0.0s  偏离
0.03s 腿开始出力（L0）
0.08s 髋开始出力（L1）
0.15s 上身穿插（L2）
0.30s 四肢最后（L3）
```

实际参数可以按层调整；上层不应该早于腿抢走预算。

### 9.3 观察指标

`_probe-assist-righting.ts` 输出 CSV：

```text
t, dof, e, D, g, tau, layer, totalTau, fall
```

对比三组：

```text
A: V3_AR_MODE=off
B: V3_AR_MODE=monitor
C: V3_AR_MODE=assist
```

看：

- `maxSeverity` 是否提前于倒下；
- 腿是否先出力；
- 回正后 `tau` 是否归零；
- 是否出现高频抖动或过冲；
- fall time 是否变长。

## 11. 风险

1. **压不过命令层**：不是“两个外力对拉”，而是外力 `cap/g_max` 不够或响应太慢；时间增长必须保证最终压过残余伺服，压不过就调大 cap / 缩短 delay。
2. **时间延迟导致救不回来**：delay 太长会错过窗口；腿层 delay 要短。
3. **增益过高抖动**：cap、slew、速度低通必须一起上。
4. **目标 IK 抖动**：目标变化要过滤；变化大时清计时。
5. **状态切换残留**：离开 squat/reset 时必须 `clear()`，否则站立时还在用蹲姿目标。
6. **饱和/泵能量**：总预算 + 分层削减；不要所有关节同时满力。
7. **双阻尼**：PD 的 kd、Drive 的 td、辅助的 kd 会叠加；第一版 kd 从小开始，必要时对辅助 DOF 关 Drive td。
8. **偷偷引入力链**：第一版禁止为了“更准”去读 Fz/CoP/接触；一旦引入，就变成第二套平衡控制器，和现有命令层打架。

## 12. 实施顺序

0. **确认基线**：命令层当前约 2s，够用；本模块不修命令层，只做外力。
0.5 **外力通道**：开 ASSIST 前，在 `Executor` 加独立 `external` 并联通道（独立 cap），或先用 `passive` 代跑。
1. **MONITOR**：`PostureTarget` + `PostureGuard` 传感器/计时/telemetry，不提交任何提案。
2. **L0 腿 ASSIST**：只开 `knee0/2`、`foot0/2`，小 cap，A/B fall time。
3. **L1 髋**：加 `hip0/1`，观察是否和主 PD 打架。
4. **L2 上身**：加 `spine1-3`、`neck`。
5. **L3 四肢**：最后加，低增益。
6. **预算/优先级**：总预算和分层削减。
7. 需要锁死时，再单独加 `Executor` lock 通道。

## 15. 根节点/CoM 外力（解决“拉不动身体”）

### 15.1 问题

纯关节力矩只改变关节角。如果身体整体倾倒/平移，关节误差可能不大，或者关节力矩被脚底接触和命令层抵消，表现为“力出了，但身体不动”。

### 15.2 方案

在同一个 `AssistRighting` 里增加一个全局外力，不是第二个 writer：

```text
comTarget = 支撑中心（X/Z）
e = comTarget - com
a = gain(t) * (kp * e - kd * comVel)
对每个刚体施加 m * a * dt 的冲量
```

效果等价于给全身加一个均匀外加速度场，直接拉 CoM；不走力链、不算 CoP/摩擦、不改命令层。

### 15.3 开关

```text
V3_AR_ROOT=0              # 关闭根力（默认 assist 模式下开）
V3_AR_ROOT_KP/KD/CAP
V3_AR_ROOT_DELAY/RAMP/EIN/EOUT/MAXGAIN
V3_AR_ROOT_Y=1            # 竖直根力（默认关；实测更差）
V3_AR_ROOT_KPY/KDY/CAP_Y
```

### 15.4 结果

```text
baseline monitor                 1.675s
root + 低腿/髋                   >6s（T_END=6 未倒）
T_END=10                        4.006s（总 6.006s）
root off                        1.535s
root Y on                       2.981s
```

根力是 v3 的“总拉手”；关节外力保留为姿态微调，默认低增益。
