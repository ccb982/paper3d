# 架构范围：命令层、执行层、接触层（2026-11-22）

## 1. 总范围

本架构只处理：

```text
低速
双脚支撑
蹲姿稳定/小偏差
不迈步
不上身主动回正
```

目标：

```text
先稳住蹲姿
再谈 CoM/CoP/IK 预测
```

---

## 2. 分层与所有权

```text
物理/接触层
  Rapier 接触
  body linear/angular damping
  脚/地接触
  不归命令层直接写冲量

执行层
  关节 PD / D
  被动 K/B
  执行器限幅
  Drive / Executor

支撑层
  tauBase
  当前 q + LoadState(fz/CoP)
  含 hip / knee / ankle

tauCorr 层
  只修 tauBase
  低频
  有限幅/限速率
  不接管轴
  不改脚世界位姿

WorldGrip
  脚世界位姿
  始终开
  最高优先级

上层
  CoM / CoP / IK 预测
  SAG / LAT 大偏差
  暂不参与
```

单轴单帧：

```text
只有一个主动写手
tauCorr 不是第二写手
```

## 3. 命令层能做什么

允许：

```text
目标角
前馈力矩
tauBase 的低频修正
tauCorr 的受限修正
```

不允许：

```text
直接给脚 applyImpulse
直接写接触力
高频虚拟阻尼
改脚世界位姿
和 PD 对拉
绕过执行器限幅
```

原因：

```text
命令层是低频意识层
不是接触层
不是机械阻尼
```


## 4.1 加速度三阶段

顺序固定，不能跳：

```text
阶段 A：削加速度
  阻尼 / 接触 / 执行层
  先把加速度降到人体合理水平

阶段 B：精确检测加速度
  EKF / momentum observer
  只做观测，不闭环

阶段 C：tauCorr 加速度补偿
  Δtau_acc = tauNeed − tauBase
  小修正、有限幅
```

阶段 A 不做完，不进入 B。
阶段 B 不做完，不进入 C。

### 阶段 A：阻尼削加速度

目标是实际加速度水平，不是“阻尼数值”：

```text
|a_com| p95 < 0.3 m/s²
|qdd|  p95 < 100 rad/s²
接触冲量不出现单帧尖峰
```

手段：

```text
body damping
物理/接触弹簧-阻尼
执行层 B
支撑/命令 slew
降低主动 Kp/Kd
```

禁止：

```text
命令层直接 applyImpulse
用高频虚拟阻尼硬顶尖峰
用大 Kd 代替接触柔顺
```

### 阶段 B：精确检测

```text
关节 qdd：EKF / momentum observer
肢体/COM：IMU + 编码器 + 接触力
不能裸差分
不能把 comAcc 差分当控制输入
```

阶段 B 的输出：

```text
qdd_est
a_com_est
置信度 / 延迟 / 饱和标记
```

### 阶段 C：补偿

```text
Δtau_acc = tauNeed − tauBase
```

只在：

```text
检测置信度足够
加速度缺口稳定
支撑有效
```

时开启。

## 13. 稳定状态是 CoP/CoM/IK 的前提

这条是硬约束，不是建议：

```text
加速度没抵消
支撑没稳定
禁止开 CoP / CoM / IK
```

原因：

```text
CoP/CoM/IK 是小偏差修正
不是用来接住大加速度的
```

人体也是这样：

```text
人做 CoP/CoM/IK 微调时
基本都处于已经稳定的状态
不是一边自由落体一边做精细预测
```

所以顺序必须是：

```text
1. tauBase 支撑
2. tauDyn 抵消主要加速度
3. 加速度残差小
4. 支撑稳定
5. 才允许 tauCorr 的 CoP/CoM/IK
```

禁止：

```text
加速度还大
支撑还在掉
先开 CoP/CoM/IK
用预测项去救支撑
```

过去两个月的教训：

```text
加速度没消掉就加 CoM/CoP/IK
效果一定烂
```

硬门控：

```text
|a_com| / qdd 残差超过阈值
或 fz/CoP 不稳定
或 tauDyn 饱和
→ CoP/CoM/IK 一律关闭
```

只有：

```text
tauBase 稳定
tauDyn 生效
残差小
```

才进入 CoP/CoM/IK。

当前代码状态：

```text
tauBase：有
tauDyn：未实装
tauCorr 的 CoP/CoM/IK：关闭
```

先做稳定状态，再做预测项。

## 15. 耗散与内部阻尼（论文方向）

当前问题：

```text
力传导偏刚性
内部耗散不足
能量主要靠足底接触散掉
```

人体不是没有噪音：

```text
运动单位放电抖动
肌肉共收缩
软组织/器官粘弹性
足垫/接触
```

但人体不共振，不是因为“噪音大”，而是：

```text
分布式软组织阻尼
肌肉短程刚度/阻尼
接触柔顺
宽带耗散
```

我们不能靠注入随机噪音解决共振。  
噪音只会让系统更脏，不会增加耗散。

### 15.1 论文手段

```text
Effective Viscous Damping, 2020
  物理黏性阻尼，响应 <5ms

Slack-based Tunable Damping, 2023
  扰动触发阻尼，恢复快

MR Compliant Foot, 2014
  足端弹簧 + 可调阻尼

Angle-dependent damping, 2025
  变阻尼削峰

Nonlinear Active Compliance, 2021
  非线性主动柔顺

TMD/MTMD, 2023
  针对共振频段吸振

Muscle short-range stiffness as Maxwell, 2024
  肌肉 = 弹簧 + 阻尼串联

van der Zee & Kuo, 2021
  软组织耗散占很大比例
```

### 15.2 补充顺序

```text
1. 足端接触阻尼
2. 腿部 wobbling mass（先单腿）
3. 关节高频阻尼（仅 |qd| 大时）
4. 15–18Hz 陷波 / TMD
```

### 15.3 层级

```text
物理/接触层：
  足端弹簧-阻尼
  接触摩擦

执行层：
  高频阻尼、限幅

命令层：
  不直接加接触冲量
  只保留 tauBase / tauDyn / tauCorr
```

### 15.4 禁止

```text
用随机噪音当阻尼
用全局大 Kd 当耗散
用命令层 applyImpulse
用 tauCorr 掩盖内部阻尼不足
```

当前内部耗散不足，是结构问题，不是 tauCorr 问题。


### 16.2 COM 能做什么

允许：

```text
1. 给 IK 一个方向偏好
2. 校验 IK 修正是否让 COM 更危险
3. 越界时冻结/缩小 IK 修正
```

方向偏好只允许很小：

```text
q_ik_target = q_ik_base + K_dir · f(COM/XCoM)
```

约束：

```text
方向偏置小
不改变 IK 主写手地位
不形成第二套回正
```

### 16.3 COM 不能做什么

禁止：

```text
COM 直接给关节力
COM 和 IK 同时抢目标
用 COM 生成 QP/WBC
用 COM 做约束逆动力学
```

### 16.4 越界处理

```text
COM 在安全区：
  IK 正常回正

接近边界：
  降低 IK 修正

越界：
  冻结 IK 修正
  只保支撑/踝/动态支撑
```

### 16.5 当前结论

```text
IK：主回正
COM：参考 + 校验
QP/WBC：不做
```

这是当前项目可执行、可收敛的路线。

## 17. IK 主回正执行顺序

本版执行顺序固定：

```text
1. WorldGrip / 接触
2. tauBase 静态支撑
3. tauDyn 削加速度
4. IK 回正
5. COM 校验
6. PD 执行
```

原则：

```text
动态支撑优先
IK 只用剩余权限
COM 只决定 IK 能不能做、做多少
```

### 17.1 先支撑，再 IK

每帧先算：

```text
tauBase = 静态支撑
tauDyn  = supportDyn(qdd)
tauPre  = tauBase + tauDyn
```

支撑条件不满足：

```text
脚滑
fz <= 0
CoP 越界
支撑越界
```

则：

```text
IK 修正 = 0
```

### 17.2 IK 只做 hip/thigh/knee

IK 回正只作用于：

```text
hip
thigh
knee
```

禁止：

```text
foot
ankle
WorldGrip
```

禁止新增写手：

```text
IK 只给目标角/前馈
PD 出力
```

### 17.3 IK 剩余权限

动态支撑饱和的轴，IK 不再加：

```text
ikScaleHip  = clamp(1 - |tauDynHip| / capHip)
ikScaleKnee = clamp(1 - |tauDynKnee| / capKnee)
```

如果：

```text
hip/knee tauDyn 都饱和
→ ikScale = 0
```

原则：

```text
支撑优先
IK 不与支撑抢权
```

### 17.4 COM 只做 gate

COM 不生成力，只校验：

```text
xcom
cop
support polygon
```

判断：

```text
IK 修正后 COM 是否更靠外
是否把 XCoM 推出支撑
是否让 CoP 更靠边
```

更危险：

```text
缩小 ikScale
严重时冻结
```

安全：

```text
正常执行 IK
```

### 17.5 输出

```text
hipCmd  += ikHip  * ikScaleHip
kneeCmd += ikKnee * ikScaleKnee
```

不是直接加力。

### 17.6 优先级

```text
接触/WorldGrip
  >
支撑 fz / CoP
  >
tauDyn 削加速度
  >
IK 回正
  >
COM 漂移
```

### 17.7 执行链

```text
支撑先稳住
加速度先削
IK 在剩余权限里回正
COM 只负责否决或限幅
PD 执行
```

这是本版唯一允许的 IK 主回正链路。

## 18. 论文依据：IK 只能在支撑零空间里调姿态

本版 IK 不“削支撑力矩”，也不和支撑对拉。

论文结论：

```text
Sentis & Khatib 2006
  接触/约束最高
  任务投影到约束零空间
  姿态用剩余自由度

Yoshida et al. 2006
  prioritized IK
  CoM/脚支撑高优先级
  任务在低优先级执行

Herzog et al. 2016
  物理约束/CoP/摩擦最高
  CoM/momentum 次之
  posture 最后

Kim & Oh 2013
  task-priority IK
  低优先级任务不能破坏高优先级约束
```

统一形式：

```text
Γ = Γ_constraint + N_c^T Γ_task
```

我们不做完整 QP，用标量版：

```text
1. tauBase + tauDyn 先算
2. 检查 fz、CoP、支撑、tauDyn 饱和
3. 算 IK 目标偏移
4. ikScale = 支撑剩余 × COM gate
5. 只把 ikScale·Δq_ik 加到 hip/knee 目标
```

IK 不是第二股力矩：

```text
IK 只改目标角
支撑仍由 tauBase/tauDyn 和 PD 出力
```

禁止：

```text
IK 降低支撑力矩
IK 和 tauDyn 反向对拉
IK 碰 foot/ankle/WorldGrip
支撑饱和时继续加大 IK
```

判断：

```text
支撑饱和
CoP 越界
COM/XCoM 更危险
IK 方向与支撑相反
→ ikScale = 0
```

本版是：

```text
用标量 ikScale 近似零空间投影
不是完整 QP/零空间矩阵
```

原则：

```text
支撑优先
IK 只调姿态
COM 只校验
```

## 19. IK 后置修幅，不与支撑并联求解

本版明确：

```text
先算支撑
后算 IK
IK 只能在支撑结果上做有限修幅
不允许支撑和 IK 同时算最终力矩
```

正确顺序：

```text
1. tauBase
2. tauDyn
3. tauSupport = tauBase + tauDyn
4. 检查支撑稳定
5. 算 IK 修正量
6. tauFinal = clamp(tauSupport + ΔtauIK)
```

禁止：

```text
同时把支撑目标和 IK 目标丢进一个求解器
同时参考支撑和 IK 算最终力矩
IK 与支撑并联闭环
QP/WBC 同时优化支撑和 IK
```

原因：

```text
两个参考同时进求解
会互相抵消/对拉
最终力矩不可解释
```

允许的 IK 修幅：

```text
ΔtauIK 有上限
只能占用支撑剩余力矩
支撑饱和 → ΔtauIK = 0
支撑不稳 → ΔtauIK = 0
```

也就是：

```text
支撑是基准
IK 是后置微调
最终只有一个力矩输出
```

一句话：

```text
支撑先独立算好
IK 再在合理范围内修
不并联、不共算、不互抢
```

## 20. 加速度必须先削，再让 IK 修

本版顺序补充：

```text
1. tauBase
2. tauDyn = 加速度削除/补偿
3. tauCorr = 残差微调
4. IK 后置修幅
```

也就是：

```text
tauSupport = tauBase + tauDyn
tauPre     = tauSupport + tauCorr
tauFinal   = clamp(tauPre + ΔtauIK)
```

原则：

```text
不削加速度
IK 就会在跟 qdd 对拉
```

所以：

```text
加速度补偿优先于 IK
IK 只处理姿态残差
IK 不负责补 qdd/C
```

禁止：

```text
IK 用来抵消未补偿加速度
IK 与 tauDyn 同时处理同一加速度
IK 先于加速度补偿
```

执行顺序：

```text
支撑
→ 加速度
→ 残差 tauCorr
→ IK 修幅
→ PD/最终力矩
```

一句话：

```text
先削加速度
再让 IK 修姿态
IK 不和加速度对拉
```

## 21. 串行零空间投影：禁止同时求解

结论：

```text
零空间投影不是同时算支撑和 IK
必须串行算
同时求解 = 禁止
```

正确形式：

```text
1. 先算 tauSupport
2. 固定支撑约束
3. 构造支撑雅可比 J_s
4. N_s = I - J_s^+ J_s
5. IK 修正投影到 N_s
6. 只输出一次最终力矩
```

形式：

```text
Δq_ik_proj = N_s Δq_ik
```

或力矩级：

```text
Δtau_ik_proj = N_s^T Δtau_ik
```

然后：

```text
tauFinal = tauSupport + Δtau_ik_proj
```

关键：

```text
支撑先固定
IK 只进支撑零空间
最终只输出一次
不需要 QP
不需要同时求解
```

当前标量：

```text
ikScale + clamp
```

只是简化版，会漏掉关节耦合。

升级方向：

```text
用 N_s 代替标量 ikScale
串行计算
```

固定顺序：

```text
1. 动态支撑
2. 加速度补偿
3. IK
4. COM 校验
5. 一次输出
```

约束：

```text
J_s 必须对应真实支撑/CoP/接触方向
N_s 数值要稳定
投影后仍需限幅
支撑饱和时仍归零
COM 校验不通过时仍归零
```

同时求解：

```text
禁止
不是“不要求”，是不允许
```
