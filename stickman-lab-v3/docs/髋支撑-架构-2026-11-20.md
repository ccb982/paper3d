# 髋支撑架构（2026-11-20）

## 1. 先定结论

“髋支撑”不是把髋关节往某个世界坐标推，也不是一个固定的 hip 基础力矩。

它应该拆成两层：

```text
髋基础支撑（ffBase）
  托住身体，承担重力/GRF 的静态分量
  hip2 只有一份基础前馈

矢状回正（AnkleRighting）
  通过踝/CoP 调 XCoM
  不通过 hip2 制造净水平力
```

单写手契约：

```text
每根 hip2：
  一个 qRef
  一个 kp/kd
  一个基础前馈 ffBase
  一个 PD 执行

τ_hip = kp·(qHipBase − q)
        − kd·ω
        + ffBase
```

`hipX` 后移是运动学结果，不是某个 X 写手。当前代码里没有直接写 hipX 的 writer；髋锚点位置由 hip2/knee2/foot2 角度、脚固定、骨盆/CoM 平衡共同决定。

矢状方向的净水平力只能来自地面/踝：

```text
GRF / CoP → 踝策略
hip/knee 只是传力和改变姿势
没有凭空 X 力写手
```

所以：

```text
不要用“推髋/拉髋”的虚拟力解决；
髋只做基础支撑，矢状回正放到踝/CoP。
```

## 2. 当前实现与证据

### 2.1 已有的基础支撑

- `squatDownCommand.ts`
  - `computeSquatSupport(...)`
  - `squatDynamicSupport(...)`
  - 输出 `tauGravity`
- `squatClean.ts`
  - `baseHipFf`
  - `computeSagittalBase(...)`
  - `hip2` PD + `baseHipFf`
- `Drive`
  - `supportTorque(...)` / passive support

这些是基础支撑，不是髋 X 回正。

### 2.2 实测

踝背屈默认值调整后：

```text
hipX  -31.7cm → -21.9cm
kneeX +10.3cm → +17.8cm
comX  -17.5cm → -3.5cm
```

提高髋基础支撑：

```text
PP_HIP_SUP=2 → hipX -21.0cm，comY 58cm
PP_HIP_SUP=3 → hipX -19.7cm，comY 60cm
```

它会把身体托高、蹲变浅，不能当作“髋 X 回正”。

前向 torso 虚拟力：

```text
10~30N → hipX 反而更后（-22.8 ~ -23.5cm）
```

结论：

```text
基础力可以托高度，但不能替代髋/CoM 回正；
前向平移力也不是正确方向。
```

## 3. 新分层

```text
┌─────────────────────────────────────────┐
│ 命令层：qRef / kp / kd / CoM 目标       │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│ HipSupport（唯一 hip 写手）               │
│   qHipRef = qBase                         │
│   ffBase = 重力/GRF 基础前馈              │
│   τ = PD(qHipRef; kp+kpPas, kd+bPas)     │
│       + ffBase                            │
│   不做 hip X 回正                         │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│ AnkleStrategy（矢状回正唯一来源）         │
│ CoP 目标 ← XCoM                          │
│ ankle torque 调 CoP                      │
│ PD 内部含 passive K/B                    │
│ 水平 GRF 只能从这里来                     │
└───────────────────┬─────────────────────┘
                    │

│ Safety                                   │
```

## 4. BaseSupport

### 4.1 目标

```text
让 hip/knee/ankle 承担身体重量和 GRF，不让骨盆自由下落。
```

### 4.2 输入

```text
质量、CoM、脚位置、CoP、关节角、GRF
```

### 4.3 输出

```text
每轴一个 ffBase 字段：
  hip2 一份
  knee2 一份
  foot2 一份

它不是独立写手；由 HipSupport 同一个 PD 一起执行。
```

### 4.4 约束

```text
不负责 X 位置回正；
不承担“把髋往前推”；
不允许超过关节 tauMax；
左右腿共享支撑预算；
同一轴只能有一个 ffBase，不能叠加两个基础力。
```

### 4.5 当前实现

保留：

```text
computeSquatSupport
squatDynamicSupport
baseHipFf
supportTorque
```

但不要用 `PP_HIP_SUP` 大幅放大；它主要改变蹲的深度。

### 4.6 第一阶段：被动刚度（PD 内部）

被动刚度不是新层，不是新写手，也不是 `addPassiveTorque` 通道。

它是同一个 PD 内部的 K/B 分量：

```text
τ = kp·(qRef − q)
    − kd·ω
    + kpPas·(qBase − q)
    − bPas·ω
    + ffBase
```

其中 `kpPas / bPas` 和主动 K/B 一起合成同一份 PD 力矩。  
没有第二个写手，没有第二个 PD。

关键缺口：

```text
squatDown 的 foot2/knee2 PD 里没有这组 passive K/B；
刚蹲下第一拍只有主动 PD 和执行器小阻尼；
→ 容易往后倒。
```

做法：

```text
在 squatDown 的 foot2/knee2 同一个 PD 里加 kpPas / bPas；
qBase 用基础目标，不用主动回正目标；
总力矩仍受同一个 cap/tauMax。
```

不要混淆：

```text
被动刚度 = PD 内部的 K/B
被动组织 = executor.passive（另一条物理并联）
```

被动刚度负责：

```text
刚接触/刚蹲下瞬间
脚踝高频小抖动
外力冲击的第一拍
```

不负责：

```text
慢速 CoM 漂移
髋后坐的几何问题
```

## 5. AnkleStrategy

### 5.1 目标

```text
CoP 在支撑多边形内，优先用踝把 XCoM 拉回。
```

### 5.2 目标

```text
ω   = sqrt(g / comY)
xco = comX + comVelX / ω
copTarget = clamp(xco, footMin, footMax)
```

### 5.3 执行

```text
τ_ankle = Kp_cop * (copTarget - copNow)
        - Kd_cop * copVel
```

限制：

```text
CoP 不越界；
ankle 不饱和；
不写 hipX。
```

### 5.4 与当前代码

```text
FootPad / ankle CoP / AnkleComp
```

Phase 1 仍然以踝策略为主。

### 5.5 间歇主动踝回正（并入基础命令，唯一 PD）

回正范围很小，不再做独立 righting 模块/PD。

最终只有一条命令：

```text
qAnkleRef = qAnkleBase + ΔqPulse
τ_ankle = kp·(qAnkleRef − q) − kd·ω + ffBase
```

`ΔqPulse` 是基础命令内部的短脉冲，最终仍由同一个 ankle PD 执行。  
不新增写手，不新增第二套 PD，不产生对拉。

输入：

```text
xcom = comX + comVX / ω
eX   = comTargetX - xcom
bodyBehind = eX > 0
```

触发：

```text
p > 0.2
且 |eX| > E_TRIG（建议 0.015m）
且持续 HOLD（建议 0.08~0.10s）
且 CoP margin > 0.015m
且未在脉冲/冷却期
```

输出：

```text
CoP_target_pulse = CoP_target_base + sign(eX) * PULSE
（建议 PULSE = 0.015~0.02m）
持续时间 PULSE_T（建议 0.12~0.16s）
冷却 COOL_T（建议 0.10~0.20s）

ΔqPulse 由这个 CoP 目标折算进 qAnkleRef；
仍然只有 ankle PD，不再有独立 righting PD。
```

限制：

```text
CoP_target 必须在脚掌内；
CoP 已经贴边时不再脉冲；
eX 变号立即取消；
掉落/接触丢失立即取消；
仍然是原来的 ankle PD 执行，不新增写手；
不新增独立 righting PD。
```

时序：

```text
IDLE
  → eX 超阈值并保持 HOLD
PULSE
  → 持续 PULSE_T，CoP 目标前移
COOL
  → 持续 COOL_T，不动作
IDLE
```

为什么不是角度脉冲：

```text
踝角已经 28~29°，接近目标上限；
角度脉冲没有增加 CoP 权限，实测 hipX 反而更差；
必须脉冲 CoP/地面反力，不是脉冲关节角。
```

### 5.6 论文里的间歇控制怎么做

论文不是“固定每 0.12s 给一个踝角脉冲”。主流做法是：

```text
1. 倒立摆/LIPM 状态
2. 状态/误差超过阈值才触发
3. 触发后闭环控制一小段（act）
4. 然后等待一段（wait）
5. 等待期靠被动刚度/阻尼，不连续闭环
6. 输出的是力矩/CoP/反馈控制量，不是关节角脉冲
```

代表工作：

```text
Asai et al. 2009, PLoS One
  A model of postural control in quiet standing:
  robust compensation of delay-induced instability using intermittent
  activation of feedback control.
  做法：延迟反馈 + 间歇激活；状态误差超阈值才开反馈。

Gawthrop et al. 2011, Biological Cybernetics
  Intermittent control: a computational theory of human control.
  做法：事件驱动/预测式间歇闭环；开/关区间由状态决定，
  不是固定周期。

Bottaro et al. 2005, Human Movement Science
  Body sway during quiet standing:
  is it the residual chattering of an intermittent stabilization process?
  做法：act-and-wait / 间歇稳定过程；sway 像间歇控制的残余抖动。

Loram et al. 2005, Journal of Physiology
  Human postural sway results from frequent, ballistic bias impulses
  by soleus and gastrocnemius.
  做法：踝肌产生短促、ballistic 的偏置冲量，不是连续弹簧。
```

对应到本架构：

```text
触发：eX / CoP margin / 状态持续
执行：CoP 目标短脉冲
保持：PULSE_T
等待：COOL_T，被动/连续基础继续
输出：ankle PD 的 CoP 目标，不改髋
```

所以论文的关键不是“脉冲角度”，而是：

```text
事件触发的反馈/CoP 脉冲 + act-and-wait
```

## 6. 为什么不做 hip X 回正

```text
髋/膝不能凭空产生净水平力。
矢状方向的净水平力只能来自地面反力（踝/CoP/摩擦）。
```

hip2 的力矩可以改变姿势和角动量，但不能直接写 hipX，也不能替代踝/CoP 的水平力。

当前约定：

```text
hip2：只做基础支撑 + 关节目标
ankle：负责矢状 XCoM/CoP
不存在 hip X 写手
```

之前试过：

```text
hipRightingOffset → ΔqHip     已移除
torso 前向虚拟力              已移除
```

原因：

```text
ΔqHip 只能改变姿势，不能稳定提供净水平力；
前向 torso 力反而让 hipX 更后。
```

所以不做：

```text
不用 hip2 的 Δq 去补矢状 CoM；
不新增 hip X 力矩/外力；
不写 hipX。
```

## 7. 协调

hip 轴不需要仲裁：

```text
hip2 只有 qBase + ffBase
→ 一个 qRef
→ 一个 PD
→ 一个力矩
```

跨关节协调：

```text
踝负责矢状 CoM/CoP；
hip 只做基础支撑；
安全层最后兜底。
```

规则：

```text
同一 hip2 轴只允许一个 hip 写手；
不允许第二个 hip torque；
不允许 hip X 闭环；
髋不回正矢状 X，只托住身体。
```

## 8. 写手边界

```text
HipSupport（唯一 hip 写手）：
  qHipRef = qBase
  ffBase = 一份基础前馈
  同一个 PD 输出最终 hip torque

AnkleStrategy：
  foot/ankle CoP，矢状 X 唯一来源
  间歇 CoP 脉冲只是它的内部状态，不是新写手

Safety：
  HipLateral(Z)
  JointLimit
  KneeGuard（阈值型）
```

禁止：

```text
直接写 hipX
用 torso/root 平移力推髋
用 hip 基础力矩替代矢状回正
两个 hip 闭环目标叠加
```

## 9. 实施顺序

### Phase 0：审计

```text
记录 hip2：
  qRef
  baseHipFf / tauGravity
  applied
  tauMax
  saturation
同时记录：
  comX / xcom / CoP margin / trunk pitch
```

先确认基础支撑符号和预算，不做大幅调参。

### Phase 1：基础支撑

```text
保留 computeSquatSupport / baseHipFf
只修符号、分配、饱和
不把 PP_HIP_SUP 当回正旋钮
```

### Phase 2：被动刚度（PD 内部）

```text
在 squatDown 的 foot2 / knee2 同一个 PD 里
加 kpPas / bPas（围绕 qBase）
不新增 addPassiveTorque 通道
不新增写手/PD
目标：刚蹲下第一拍不后倒
```

### Phase 3：踝策略

```text
CoP 目标 = clamp(XCoM)
ankle PD 跟踪 CoP
先保证 CoP margin
```

### Phase 4：踝间歇回正

```text
回正并入基础命令，不新建模块
qAnkleRef = qAnkleBase + ΔqPulse
eX 超阈值并保持 HOLD → CoP 前移脉冲
PULSE_T 后进入 COOL_T
CoP 越界/误差变号/接触丢失 → 取消
执行仍是同一个 ankle PD
不新增 hip/righting 写手
不写 hipX
```

### Phase 5：A/B

```text
A：基础 + 被动
B：基础 + 被动 + 主动踝
C：B + 间歇 CoP 脉冲
比较：
  comX
  CoP margin
  hipX
  hip torque
  pulse 次数/占空比
  fall rate
```

## 10. 验收指标

不要用 hipX 作为唯一目标。看：

```text
comX 跟踪误差
XCoM / CoP margin
hip2 力矩饱和度
躯干 pitch
左右腿 Fz
是否跌倒
```

建议：

```text
|comX - target| < 2cm
CoP margin > 1.5cm
hip2 不长期饱和
躯干 pitch 连续
```

`hipX` 只作为几何诊断：

```text
深蹲时 hipX 本来就会后移；
不要为了把 hipX 拉回 0 而制造新的虚拟力。
```

## 12. 一句话版本

```text
基础支撑先托住，被动刚度再补第一拍；
每根 hip2 只有一个写手、一个 PD、一个 ffBase；
矢状回正只由踝/CoP 负责；
间歇回正只脉冲 CoP，不脉冲踝角，也不新增写手；
hip/knee 不做 X 回正；
不要用 hipX 平移力，也不要把基础力当回正力。
```
