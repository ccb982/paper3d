## 1. 先定结论

“髋支撑”不是把髋关节往某个世界坐标推，也不是一个固定的 hip 基础力矩。

基础力就是回正力，不再拆成两个力。

```text
BaseSupport = 支撑 + 回正
回正只修改基础力的输出
不新增 righting torque
不产生 base vs righting 对拉
```

单写手契约：

```text
每根 hip2 / ankle：
  一个基础输出
  一个 qRef / 一个目标
  一个 kp/kd
  一个 PD 执行
```

矢状回正藏在基础力里：

```text
先算基础支撑/CoP
再用 XCoM 误差修改这个基础输出
最后仍然只有一个 PD
```

`hipX` 后移是运动学结果，不是某个 X 写手。当前代码里没有直接写 hipX 的 writer；髋锚点位置由 hip2/knee2/foot2 角度、脚固定、骨盆/CoM 平衡共同决定。

矢状方向的净水平力只能来自地面/踝：

```text
GRF / CoP → 踝基础力（含回正）
hip/knee 只是传力和改变姿势
没有凭空 X 力写手
```

所以：

```text
不要用“推髋/拉髋”的虚拟力解决；
髋只做基础支撑；
矢状回正修改踝/CoP 的基础输出。
```

## 2. 当前实现与证据

### 2.1 已有的基础支撑

- `squatDownCommand.ts`
  - `computeSquatSupport(...)`
  - `squatDynamicSupport(...)`
  - 输出 `tauGravity`
- `squatClean.ts`
  - `baseHipFf`
  - `computeSagittalBase(...)`
  - `hip2` PD + `baseHipFf`
- `Drive`
  - `supportTorque(...)` / passive support

这些是基础支撑，不是髋 X 回正。

### 2.2 实测

踝背屈默认值调整后：

```text
hipX  -31.7cm → -21.9cm
kneeX +10.3cm → +17.8cm
comX  -17.5cm → -3.5cm
```

提高髋基础支撑：

```text
PP_HIP_SUP=2 → hipX -21.0cm，comY 58cm
PP_HIP_SUP=3 → hipX -19.7cm，comY 60cm
```

它会把身体托高、蹲变浅，不能当作“髋 X 回正”。

前向 torso 虚拟力：

```text
10~30N → hipX 反而更后（-22.8 ~ -23.5cm）
```

结论：

```text
基础力可以托高度，但不能替代髋/CoM 回正；
前向平移力也不是正确方向。
```

## 4. BaseSupport

### 4.1 目标

```text
让 hip/knee/ankle 承担身体重量和 GRF，不让骨盆自由下落。
```

### 4.2 输入

```text
质量、CoM、脚位置、CoP、关节角、GRF
```

### 4.3 输出

```text
每轴一个 ffBase 字段：
  hip2 一份
  knee2 一份
  foot2 一份

它不是独立写手；由 HipSupport 同一个 PD 一起执行。
```

### 4.4 约束

```text
不单独出一个“回正力矩”；
回正只修改基础支撑的输出；
不承担“把髋往前推”；
不允许超过关节 tauMax；
左右腿共享支撑预算；
同一轴只能有一个基础输出，不能叠加两个基础力。
```

### 4.5 当前实现

保留：

```text
computeSquatSupport
squatDynamicSupport
baseHipFf
supportTorque
```

但不要用 `PP_HIP_SUP` 大幅放大；它主要改变蹲的深度。

### 4.6 第一阶段：被动刚度（PD 内部）

被动刚度不是新层，不是新写手，也不是 `addPassiveTorque` 通道。

它是同一个 PD 内部的 K/B 分量：

```text
τ = kp·(qRef − q)
    − kd·ω
    + kpPas·(qBase − q)
    − bPas·ω
    + ffBase
```

其中 `kpPas / bPas` 和主动 K/B 一起合成同一份 PD 力矩。  
没有第二个写手，没有第二个 PD。

关键缺口：

```text
squatDown 的 foot2/knee2 PD 里没有这组 passive K/B；
刚蹲下第一拍只有主动 PD 和执行器小阻尼；
→ 容易往后倒。
```

做法：

```text
在 squatDown 的 foot2/knee2 同一个 PD 里加 kpPas / bPas；
qBase 用基础目标，不用主动回正目标；
总力矩仍受同一个 cap/tauMax。
```

不要混淆：

```text
被动刚度 = PD 内部的 K/B
被动组织 = executor.passive（另一条物理并联）
```

被动刚度负责：

```text
刚接触/刚蹲下瞬间
脚踝高频小抖动
外力冲击的第一拍
```

不负责：

```text
慢速 CoM 漂移
髋后坐的几何问题
```

## 5. Ankle 两个策略（最终契约）

### 5.0 只有两个

```text
A. WorldGrip
   脚/踝世界坐标抓地
   FootWorldTarget → AnkleComp → foot0/1/2 qRef
   只负责脚在世界里的位置/姿态

B. LocalSupportRighting
   踝局部支撑 + 回正
   以踝为支点，支撑小腿及以上
   ankle torque / CoP
   不写 foot 世界 qRef
```

所有东西必须归到这两个之一：

```text
被动刚度       → B 内部 K/B
间歇 CoP 脉冲  → B 内部状态
FootPad CoP    → B
踝侧向被动     → B
世界抓地       → A
```

不允许第三个踝策略；不允许 A 和 B 同时写同一个世界目标。

### 5.1 WorldGrip（世界抓地）

```text
输入：脚世界位姿 + 小腿世界位姿
输出：foot0/1/2 qRef
执行：foot PD
边界：不写 CoP，不做支撑/回正
当前：FootWorldTarget / AnkleComp
```

### 5.2 LocalSupportRighting（局部支撑+回正，一个输出）

```text
输入：CoP / XCoM / 踝角 / 小腿姿态
输出：一份 ankle 基础输出（已含回正）
执行：ankle PD
边界：不写 world foot pose，不抢 WorldGrip 的 qRef

回正不是额外加力：
  base = support/CoP
  base = righting_modify(base, XCoM)
  τ = PD(base)
```

### 5.3 目标

```text
CoP 在支撑多边形内，优先用踝把 XCoM 拉回。
```

#### CoP 目标

```text
ω   = sqrt(g / comY)
xco = comX + comVelX / ω
copTarget = clamp(xco, footMin, footMax)
```

#### 执行

```text
τ_ankle = Kp_cop * (copTarget - copNow)
        - Kd_cop * copVel
```

限制：

```text
CoP 不越界；
ankle 不饱和；
不写 hipX。
```

#### 与当前代码

```text
FootPad / ankle CoP / AnkleComp
```

Phase 1 仍然以踝策略为主。

### 5.4 间歇主动踝回正（并入局部策略）

回正范围很小，不再做独立 righting 模块/PD。

最终只有一条命令：

```text
qAnkleRef = qAnkleBase + ΔqPulse
τ_ankle = kp·(qAnkleRef − q) − kd·ω + ffBase
```

`ΔqPulse` 是基础命令内部的短脉冲，最终仍由同一个 ankle PD 执行。  
不新增写手，不新增第二套 PD，不产生对拉。

输入：

```text
xcom = comX + comVX / ω
eX   = comTargetX - xcom
bodyBehind = eX > 0
```

触发：

```text
p > 0.2
且 |eX| > E_TRIG（建议 0.015m）
且持续 HOLD（建议 0.08~0.10s）
且 CoP margin > 0.015m
且未在脉冲/冷却期
```

输出：

```text
CoP_target_pulse = CoP_target_base + sign(eX) * PULSE
（建议 PULSE = 0.015~0.02m）
持续时间 PULSE_T（建议 0.12~0.16s）
冷却 COOL_T（建议 0.10~0.20s）

ΔqPulse 由这个 CoP 目标折算进 qAnkleRef；
仍然只有 ankle PD，不再有独立 righting PD。
```

限制：

```text
CoP_target 必须在脚掌内；
CoP 已经贴边时不再脉冲；
eX 变号立即取消；
掉落/接触丢失立即取消；
仍然是原来的 ankle PD 执行，不新增写手；
不新增独立 righting PD。
```

时序：

```text
IDLE
  → eX 超阈值并保持 HOLD
PULSE
  → 持续 PULSE_T，CoP 目标前移
COOL
  → 持续 COOL_T，不动作
IDLE
```

为什么不是角度脉冲：

```text
踝角已经 28~29°，接近目标上限；
角度脉冲没有增加 CoP 权限，实测 hipX 反而更差；
必须脉冲 CoP/地面反力，不是脉冲关节角。
```

### 5.5 论文里的间歇控制怎么做

论文不是“固定每 0.12s 给一个踝角脉冲”。主流做法是：

```text
1. 倒立摆/LIPM 状态
2. 状态/误差超过阈值才触发
3. 触发后闭环控制一小段（act）
4. 然后等待一段（wait）
5. 等待期靠被动刚度/阻尼，不连续闭环
6. 输出的是力矩/CoP/反馈控制量，不是关节角脉冲
```

代表工作：

```text
Asai et al. 2009, PLoS One
  A model of postural control in quiet standing:
  robust compensation of delay-induced instability using intermittent
  activation of feedback control.
  做法：延迟反馈 + 间歇激活；状态误差超阈值才开反馈。

Gawthrop et al. 2011, Biological Cybernetics
  Intermittent control: a computational theory of human control.
  做法：事件驱动/预测式间歇闭环；开/关区间由状态决定，
  不是固定周期。

Bottaro et al. 2005, Human Movement Science
  Body sway during quiet standing:
  is it the residual chattering of an intermittent stabilization process?
  做法：act-and-wait / 间歇稳定过程；sway 像间歇控制的残余抖动。

Loram et al. 2005, Journal of Physiology
  Human postural sway results from frequent, ballistic bias impulses
  by soleus and gastrocnemius.
  做法：踝肌产生短促、ballistic 的偏置冲量，不是连续弹簧。
```

对应到本架构：

```text
触发：eX / CoP margin / 状态持续
执行：CoP 目标短脉冲
保持：PULSE_T
等待：COOL_T，被动/连续基础继续
输出：ankle PD 的 CoP 目标，不改髋
```

所以论文的关键不是“脉冲角度”，而是：

```text
事件触发的反馈/CoP 脉冲 + act-and-wait
```

### 5.7 论文：蹲下踝主动控制不应很强

结论：**支持降低踝主动增益，但不支持降到 0。**

相关证据：

```text
Dionisio et al. 2008
J Electromyogr Kinesiol 18(1):134-143
DOI: 10.1016/j.jelekin.2006.07.010
向下蹲：
  - 加速段没有可测的肌肉激活
  - 胫骨前肌在启动前先动
  - 减速段主要是股四头肌
  - 踝力矩/EMG 不是主动主力
```

```text
Khorievin et al. 2013
Fiziol Zh 59(1):56-67
踝策略蹲：
  - 踝肌只在关节角变化中轻微参与
  - 大腿肌 EMG 主导
```

```text
Medicina 2023, 59(6):1105
最大蹲深踝背屈约 38.8°
踝背屈力量与最大蹲深无相关（r=-0.006）
被动 ROM / 跟腱刚度才相关
```

```text
Macrum et al. 2012
J Sport Rehabil 21(2):144-151
限制踝背屈 ROM 会改变 soleus 活动和膝轨迹
→ 踝更多是“约束/支撑”，不是主动主控
```

对应到本架构：

```text
ANK_K 20 → 可试 10
ANK_ACT 0.70 → 可试 0.50
主动踝只补慢误差；
被动 ROM/刚度负责深度和第一拍；
不能把 ANK_K 降到 0，纯被动会倒。
```

当前 A/B（squatDown）：

```text
ANK_K=20: comX≈-0.9cm, 稳定
ANK_K=10: comX≈-2.9cm, 稳定
ANK_K=6:  comX≈-5.5cm, 稳定但后坐更多
纯被动:   直接倒
```

所以论文和实验都支持：

```text
降低主动踝增益；
保留最小主动；
大头交给被动刚度和 ROM。
```

## 6. 为什么不做 hip X 回正（边界；11-21 修正见 §6.6）

```text
髋/膝不能凭空产生净水平力。
矢状方向的净水平力只能来自地面反力（踝/CoP/摩擦）。
```

hip2 的力矩可以改变姿势和角动量，但不能直接写 hipX，也不能替代踝/CoP 的水平力。

当前约定：

```text
hip2：基础支撑 + 关节目标 + 同一 PD 内的 CoM ff
ankle：负责矢状 XCoM/CoP
不存在独立 hip X 写手
不存在第二个 hip2 写手
```

> 2026-11-21 修正：上面的“CoM ff”是旧版 `supportClean` 的 CoM 误差分配，
> 只能并进现有 `hip2/knee2/foot2` 的 ff；不是恢复 legacy 写手，也不是 ΔqHip 回正。

之前试过：

```text
hipRightingOffset → ΔqHip     已移除
torso 前向虚拟力              已移除
```

原因：

```text
ΔqHip 只能改变姿势，不能稳定提供净水平力；
前向 torso 力反而让 hipX 更后。
```

所以不做：

```text
不用 hip2 的 Δq 去补矢状 CoM；
不新增 hip X 力矩/外力；
不写 hipX。
```

```text
新 kneeFf  ：hipX -22.53cm，kneeX 17.51cm
```

所以“往后的力”主要来自 `supportWbc.knee` 的静态腿逆动力学 ff，不是 knee2 PD。  
`knee2` PD 是一个命令层写手；Drive td 仍作为执行阻尼保留（SQC_DAMP_IN_PD=0），所以写入计数可为 2。

即：

```text
hip2 仍然一个 qRef
一个 kp/kd
一个 ff/baseHipFf
一个 PD
```

不新增：

```text
hipX 写手
hip 第二套 righting PD
root/torso 平移力
```

### 6.5.5 旧法庭与当前的关键差异

旧 `pd()`：

```text
tau = clamp(pdVal + ff + passive, ±cap)
```

当前：

```text
tau = clamp(pdVal + ff, ±cap)
executor.addPassiveTorque(passive)
```

这个差异会改变 hip2/knee2 的支撑预算。  
如果只治髋后移，可以先只对 `hip2` 做 A/B：

```text
A：当前 passive 独立
B：hip2 的 passive 回到 active tau
```

不要全局改回旧法则。

### 6.5.6 交接后髋后移的最小修法

```text
1. 交接时捕获 hip2 当前目标和 hip 高度
2. hip2 仍用唯一 PD + baseHipFf
3. 只改 hip2 的目标保持 / 阻尼 / baseHipFf
4. 不碰踝 A/B，不加 hipX 约束
5. A/B 只比较 hipX、comX、hip2 饱和
```

一句话：

```text
交接后停 squatDown/FootPad，
启 squatFrame/AnkleComp/base，
只动 hip2 治髋后移。
```

## 6.6 2026-11-21 交接后回读与重构计划

### 6.6.1 回读快照

交接后逐写手审计（`l` 侧，命令层 ext 力矩）：

```text
t≈0.10
  hip2   -50
  knee2  +47
  foot2    0
  upperBase  34 / 18 / 3（spine1/2/3）
  upperRighting 30 / 14 / 3

t≈0.20
  hip2   -51
  knee2  +56
  foot2    0
  hipX  -25.78
  comX   -0.67
```

结论：

```text
foot2 主动矢状力矩为 0
踝不是持续后移的主动来源
后移来自 hip2/knee2 内力矩 + 脚底接触约束
```

上身对照：

```text
upper 主动链关闭（0.41s）
  hipX -24.76 → -16.22
  comX  +2.60 → -4.39
```

说明上身确实在拉/压骨盆，但不能靠“上身穿透”解决；髋/膝链仍需要 CoM 外环。

### 6.6.2 旧版 CoM 分配（保留的公式）

旧版 `supportClean.ts` 的 `tqCom` 不是 hip 独立目标，而是 CoM 误差按关节分配：

```text
tgtC = 双脚位置中点
eX   = tgtC.x - comX

蹲姿权重：
  hip   0.25
  knee  0.30
  foot  0.45

Kx = 2500
hipCom  = 0.25 * Kx * eX = 625  * eX
kneeCom = 0.30 * Kx * eX = 750  * eX
footCom = 0.45 * Kx * eX = 1125 * eX
```

旧版最终脚/髋/膝输出：

```text
tau = sgn0 * (bias + dir) + PD(dev)
```

这段 legacy 在蹲姿被 `SC_SQUAT_LEGS=0` 关闭，原因是它作为**第二写手**和
`pairBase/hip2` 对拉，不是因为 CoM 公式本身错。

### 6.6.3 重构方向

保留当前单写手，恢复 CoM 外环，但只作为**同一 PD 的 ff**：

```text
eX = midfootX - comX
eX = deadband(eX, SQC_COM_DEAD)

hipCom  = wHip  * Kx * eX
kneeCom = wKnee * Kx * eX
footCom = wFoot * Kx * eX

hip2.ff  += hipCom
knee2.ff += kneeCom
foot2 ff/target += footCom
```

约束：

```text
每轴仍只有一个 PD
不新增 src / 不恢复 SC_SQUAT_LEGS=1
不写 hipX
不把 CoM 项塞给上身
上身只做姿态/阻尼，不做 CoM 主动补偿
```

建议参数：

```text
SQC_COM_KX      = 2500    # 旧版值，先保留
SQC_COM_W_HIP   = 0.25
SQC_COM_W_KNEE  = 0.30
SQC_COM_W_FOOT  = 0.45
SQC_COM_DEAD    = 0.005m
SQC_COM_CAP_HIP = 30 N·m
SQC_COM_CAP_KNEE= 40 N·m
SQC_COM_CAP_FOOT= 50 N·m
```

实施顺序：

1. `hip2.ff` 先接 `625*eX`，审计 hipX/comX，不动踝。
2. 再接 `knee2.ff`，确认不把 knee2 顶饱和。
3. 最后接 `foot2`；A（WorldGrip）走 qRef/目标，B 走 ankle torque，不新增写手。
4. 每步用固定随机种子，比较 0/0.1/0.2/0.4s。
5. 任何一步导致 `hip2/knee2` 长期饱和或 `foot2` 变成第二个 X 写手，立即回退。

## 7. 协调

hip 轴不需要仲裁：

```text
hip2 只有 qBase + ffBase
→ 一个 qRef
→ 一个 PD
→ 一个力矩
```

跨关节协调：

```text
踝负责矢状 CoM/CoP；
hip 只做基础支撑；
安全层最后兜底。
```

规则：

```text
同一 hip2 轴只允许一个 hip 写手；
不允许第二个 hip torque；
不允许 hip X 闭环；
髋不回正矢状 X，只托住身体。
```

## 8. 写手边界

```text
HipSupport（唯一 hip 写手）：
  qHipRef = qBase
  ffBase = 一份基础前馈
  同一个 PD 输出最终 hip torque

AnkleStrategy：
  foot/ankle CoP，矢状 X 唯一来源
  间歇 CoP 脉冲只是它的内部状态，不是新写手

Safety：
  HipLateral(Z)
  JointLimit
  KneeGuard（阈值型）
```

禁止：

```text
直接写 hipX
用 torso/root 平移力推髋
用 hip 基础力矩替代矢状回正
两个 hip 闭环目标叠加
```
