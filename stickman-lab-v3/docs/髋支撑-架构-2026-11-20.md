# 髋支撑架构（2026-11-20）

## 1. 先定结论

“髋支撑”不是把髋关节往某个世界坐标推，也不是一个固定的 hip 基础力矩。

它应该拆成两层：

```text
基础支撑（ffBase）
  托住身体，承担重力/GRF 的静态分量
  每轴只输出一份基础前馈

髋回正（ΔqHip）
  只改同一个 hip2 的 qRef
  不产生第二个力矩写手
```

单写手契约：

```text
每根 hip2：
  一个 qRef
  一个 kp/kd
  一个基础前馈 ffBase
  一个 PD 执行

τ_hip = kp·(qHipBase + ΔqHip − q)
        − kd·ω
        + ffBase
```

`HipRighting` 不是新写手，也不是新力矩通道；它只是同一个 hip2 目标的偏移量。  
不允许 base 和 righting 各自出一个 hip 力矩再相加。

`hipX` 后移是运动学结果，不是某个 X 写手。当前代码里没有直接写 hipX 的 writer；髋锚点位置由 hip2/knee2/foot2 角度、脚固定、骨盆/CoM 平衡共同决定。

所以：

```text
不要用“推髋/拉髋”的虚拟力解决；
用同一个 hip2 的 qRef 偏移 + 基础前馈解决。
```

## 2. 当前实现与证据

### 2.1 已有的基础支撑

- `squatDownCommand.ts`
  - `computeSquatSupport(...)`
  - `squatDynamicSupport(...)`
  - 输出 `tauGravity`
- `squatClean.ts`
  - `baseHipFf`
  - `computeSagittalBase(...)`
  - `hip2` PD + `baseHipFf`
- `Drive`
  - `supportTorque(...)` / passive support

这些是基础支撑，不是髋 X 回正。

### 2.2 实测

踝背屈默认值调整后：

```text
hipX  -31.7cm → -21.9cm
kneeX +10.3cm → +17.8cm
comX  -17.5cm → -3.5cm
```

提高髋基础支撑：

```text
PP_HIP_SUP=2 → hipX -21.0cm，comY 58cm
PP_HIP_SUP=3 → hipX -19.7cm，comY 60cm
```

它会把身体托高、蹲变浅，不能当作“髋 X 回正”。

前向 torso 虚拟力：

```text
10~30N → hipX 反而更后（-22.8 ~ -23.5cm）
```

结论：

```text
基础力可以托高度，但不能替代髋/CoM 回正；
前向平移力也不是正确方向。
```

## 3. 新分层

```text
┌─────────────────────────────────────────┐
│ 命令层：qRef / kp / kd / CoM 目标       │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│ HipSupport（唯一 hip 写手）               │
│   qHipRef = qBase + ΔqRight               │
│   ffBase = 重力/GRF 基础前馈              │
│   τ = PD(qHipRef) + ffBase                │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│ AnkleStrategy                            │
│ CoP 目标 ← XCoM                          │
│ ankle torque 调 CoP                      │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│ HipRighting（只改 qRef，不是写手）        │
│ 双倒立摆：CoM/躯干误差 → ΔqHip            │
│ 只在踝策略不足或误差持续时介入            │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│ Safety                                   │
│ HipLateral(Z) / JointLimit / KneeGuard   │
└─────────────────────────────────────────┘
```

## 4. BaseSupport

### 4.1 目标

```text
让 hip/knee/ankle 承担身体重量和 GRF，不让骨盆自由下落。
```

### 4.2 输入

```text
质量、CoM、脚位置、CoP、关节角、GRF
```

### 4.3 输出

```text
每轴一个 ffBase 字段：
  hip2 一份
  knee2 一份
  foot2 一份

它不是独立写手；由 HipSupport 同一个 PD 一起执行。
```

### 4.4 约束

```text
不负责 X 位置回正；
不承担“把髋往前推”；
不允许超过关节 tauMax；
左右腿共享支撑预算；
同一轴只能有一个 ffBase，不能叠加两个基础力。
```

### 4.5 当前实现

保留：

```text
computeSquatSupport
squatDynamicSupport
baseHipFf
supportTorque
```

但不要用 `PP_HIP_SUP` 大幅放大；它主要改变蹲的深度。

## 5. AnkleStrategy

### 5.1 目标

```text
CoP 在支撑多边形内，优先用踝把 XCoM 拉回。
```

### 5.2 目标

```text
ω   = sqrt(g / comY)
xco = comX + comVelX / ω
copTarget = clamp(xco, footMin, footMax)
```

### 5.3 执行

```text
τ_ankle = Kp_cop * (copTarget - copNow)
        - Kd_cop * copVel
```

限制：

```text
CoP 不越界；
ankle 不饱和；
不写 hipX。
```

### 5.4 与当前代码

```text
FootPad / ankle CoP / AnkleComp
```

Phase 1 仍然以踝策略为主。

## 6. HipRighting（目标偏移，不是力矩写手）

### 6.1 目标

```text
用 hip 目标偏移控制躯干/CoM/角动量，不是平移髋。
不产生第二个 hip 力矩写手。
```

### 6.2 模型

双倒立摆：

```text
腿 + 躯干
踝控制全身 CoM
髋目标偏移控制躯干/角动量
```

### 6.3 激活条件

不要常开。满足任一条件才进入：

```text
|CoP margin| < 0.02m
或 |xcomTarget - xcom| > 0.03m 持续 > 0.1s
或 hip 接近目标误差上限
```

退出：

```text
|error| < 0.015m 持续 > 0.2s
```

### 6.4 目标偏移

示意：

```text
eX = xcomTarget - xcom
eV = -comVelX
eT = trunkPitchTarget - trunkPitch

ΔqHip =
  clamp(
    Kx * eX +
    KdX * eV +
    Kt * eT -
    KdT * trunkPitchRate,
    ±qCap
  )

qHipRef = qHipBase + ΔqHip
```

最终仍然只有一个 PD：

```text
τ_hip = kp·(qHipRef − q) − kd·ω + ffBase
```

### 6.5 分配

```text
左右 hip2 各自一个 qHipRef；
基础 ffBase 不变；
ΔqHip 只改同一个 qRef；
不新增 hip torque 通道；
不写 hipX；
不直接加 root impulse。
```

### 6.6 当前代码的落点

```text
squatClean.ts
  hip2 PD + baseHipFf  ← 已经是一个写手
新增 HipRighting
  只计算 ΔqHip
  → 加到 hip2 的 qRef
  → 不新增 ff/ext/torque
```

## 7. 仲裁

hip 轴上不需要仲裁：

```text
基础 ffBase 和回正 ΔqHip
在同一个 HipSupport 内部合成
→ 同一个 qRef
→ 同一个 PD
→ 同一个力矩
```

只有跨关节才需要协调：

```text
踝策略先做；
髋回正只在踝/CoP 不足时开启；
安全层最后兜底。
```

规则：

```text
同一 hip2 轴只允许一个 hip 写手；
不允许 base 和 righting 各自出 torque；
不允许两个 hip 闭环目标；
髋回正只改 qRef，不改 ffBase。
```

## 8. 写手边界

```text
HipSupport（唯一 hip 写手）：
  qHipRef = qBase + ΔqHip
  ffBase = 一份基础前馈
  同一个 PD 输出最终 hip torque

AnkleStrategy：
  foot/ankle CoP，局部踝写手

HipRighting：
  只计算 ΔqHip
  不是 torque writer

Safety：
  HipLateral(Z)
  JointLimit
  KneeGuard（阈值型）
```

禁止：

```text
直接写 hipX
用 torso/root 平移力推髋
用 hip 基础力矩替代髋回正
两个 hip 闭环目标叠加
```

## 9. 实施顺序

### Phase 0：审计

```text
记录 hip2：
  qRef
  baseHipFf / tauGravity
  applied
  tauMax
  saturation
同时记录：
  comX / xcom / CoP margin / trunk pitch
```

先确认基础支撑符号和预算，不做大幅调参。

### Phase 1：基础支撑

```text
保留 computeSquatSupport / baseHipFf
只修符号、分配、饱和
不把 PP_HIP_SUP 当回正旋钮
```

### Phase 2：踝策略

```text
CoP 目标 = clamp(XCoM)
ankle PD 跟踪 CoP
先保证 CoP margin
```

### Phase 3：髋回正

```text
新增 HipRighting 目标偏移
只在 CoP margin 小或误差持续时开启
ΔqHip 加到 hip2 的 qRef
不新增 ff/ext/torque
设置 ramp / deadband / Δq cap
```

### Phase 4：A/B

```text
A：只有踝
B：踝 + 髋回正
比较：
  comX
  CoP margin
  hip torque
  trunk pitch
  fall rate
```

## 10. 验收指标

不要用 hipX 作为唯一目标。看：

```text
comX 跟踪误差
XCoM / CoP margin
hip2 力矩饱和度
躯干 pitch
左右腿 Fz
是否跌倒
```

建议：

```text
|comX - target| < 2cm
CoP margin > 1.5cm
hip2 不长期饱和
躯干 pitch 连续
```

`hipX` 只作为几何诊断：

```text
深蹲时 hipX 本来就会后移；
不要为了把 hipX 拉回 0 而制造新的虚拟力。
```
