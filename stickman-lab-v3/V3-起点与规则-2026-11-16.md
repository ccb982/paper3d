# 机器人仿真 v3：起点与规则（2026-11-16）

## 1. v2 封存

- 目录：`stickman-lab-v2/`，不再修改。
- git tag：`v2-sealed-2026-11-16`。
- 封存原因：QP 姿态控制线一整天没有进展；净室 QP 接管命令层后，蹲姿从约 2s 掉到 0.97–1.44s。不再在 v2 上修 QP。

## 2. v3 起点

- 来源 commit：`44becd51`（2026-10-22，“upper body: add passive deadband and document 7.2s record”）。
- 这是 QP 之前的蹲姿伺服/被动刚度版本，不是净室 QP 版本。
- 原记录：`SQC_BSS_DEAD_Z=4`、`SQC_BSS_DEAD_R=1` 时 fall=7.219s。
- 2026-11-16 复测：`node tools/run.mjs _probe-squat-fall` → `fall=4.073s`（J=2，默认 env）；带网页默认参数 → `fall=3.650s`。
- 结论：v3 先保住“能蹲住”，不再以 QP 为起点。

## 3. v3 规则

物理真实性降级为可选项。目标是游戏里看着稳、能演出、能继续做动作。

允许：

- 关节锁死、轴向锁、硬限位、冻结 DOF。
- 增大腿/足/髋的质量、惯量、摩擦、被动刚度。
- 直接给关节或质心加虚拟回正力/力矩。
- IK/姿态目标优先，不要求和接触力/动力学完全自洽。
- 宁可“凭空发力”，也不让角色软倒。
- 关闭 QP；QP 最多保留 shadow。

禁止：

- QP 接管命令层。
- 同一关节两套基础力互相打架。
- 为了数学自洽牺牲蹲姿稳定。

优先级：视觉稳定 > 姿态可读 > 物理真实。

新增作弊开关统一用 `V3_` 前缀，避免和 v2 的 `SQC_*` 混淆。

## 4. 验证

```bash
node tools/run.mjs _probe-squat-fall
# 基线要求：fall >= 2s
```

改完后至少跑一次 `npm run typecheck`。
