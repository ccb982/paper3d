# 地形表驱动管线 —— 唯一权威架构文档（定稿）

> 状态：**定稿（2026-09-05）**。两遍建表（先单块可定 → 后邻居敏感）→ 检验 →
> 直接创建精修物理 + 渲染（无墙缓冲中间物）。表 = 领导：只把各点/边的属性
> 弄清楚；精确几何（细分、拼弧、坡带、壁顶沿）由创建函数权威产出。
> **本文件取代《地图架构.md》及一切以旧「精修层 + 后处理」管线为权威的文档**
> （归档清单与映射见 §11）。当前几何构建默认走表驱动
> （`ChunkManager.__PP_TABLE_BUILD !== false`）；旧路径代码暂存未拆（§7.3 如实标注）。

---

## 0. 一句话

**每 chunk：Pass1 定块属性（高度/材质/边 kind）→ Pass2 定邻居敏感细节
（topEdgeY/depth/邻接标记）→ 检验 → FaceBuild 直接产出渲染 + 物理（同一份数据）。
顶面与侧壁共享同一张 fine 细分图 → 壁顶沿与顶网格边界折线逐段同位，
weld 坡脚/bevel 弧带处几何完全闭合。**

## 1. 动机与取代对象

旧管线（《地图架构.md》时代的 buildChunkFinal + buildChunkWallBuffers +

| # | 问题 | 后果 |
|---|------|------|
| 1 | 两套后处理并存（PostProcess 新 vs RefinementPostProcess 旧） | 贴地与渲染两套面 |
| 2 | 墙材质/归属靠 UV 反推 + wallRef 链 | 动材质坏索引、补墙反复出错 |

## 2. 全链流程总览

```
RasterMap 数据环（无界确定性生成；heights/blockTypes/groupKey）
   │  chunkSource(cx,cz)：refineChunkSource 应用 per-chunk 意图（裁决 override）
   ▼
① 建表（全区各 chunk 独立两遍；Pass1 全区先完成）
   Pass1（单块可定）：id/role/h/hBase/topTileId + 4 向 kind（hard/weld/bevel）
        + ruling 溯源 + leftKind/rightKind（同块垂直邻边回填）
   Pass2（邻居敏感）：topEdgeY / calcDepth / depth / oppKind / arcNeighbor /
        topWeldDirs（跨界邻居由 src 同公式现算，无需邻表）
   ▼
② 检验 checkTable（不通过不放行；生产默认跳过，回归脚本调用）
   ▼
③ 创建 FaceBuild（读表 + src，直接产出几何缓冲）
   buildTopGeometry  顶面：coarse 1m / fine 0.125m（bevel 弧带 ∪ weld 非线性 cell）
   buildWallGeometry 侧壁：每边恒壁；壁顶沿 = 顶网格边界折线同位节点列
   ▼
④ 装配 ChunkManager.finishStandardChunkTable
   顶面 mesh（TerrainMaterial）＋侧壁 mesh（WallMaterial）＋装饰层
   物理 trimesh = 顶面 + 侧壁同一份缓冲合并（一次产出，无二次合并）
   ▼
⑤ 查询/贴地（现状：仍走旧查询路径 ppSurfaceHeight —— 开放项 P1，§8）
```

烘焙（albedo/lightmap，Worker）与装饰放置发生在②前（与旧管线相同的
异步烘焙节拍），表驱动只替换「像素就绪后的几何装配」；装饰照旧由
`planDecor → buildDecorLayer/createDecorColliders` 消费（§7.2）。

## 3. 表数据模型（与代码逐字段一致）

```ts
// FaceTable.ts
interface FaceTable { cx: number; cz: number; cells: FaceCell[]; }   // 225
interface FaceCell {
  id: number;                       // tileId（0 兜底）
  role: TileGenRole | "";           // tile 语义角色
  h: number;                        // 逻辑高（顶面基准）
  hBase: number;                    // 面板底高（= 壁底埋深参考），缺省 = h
  topTileId: number;                // 顶材质（默认本块 tile）
  top: { materialId: number };      // 可改槽（当前未消费，预留）
  topWeldDirs: number[];            // ★ 语义标注：坡进顶方向（几何经 src 直接
                                    //   采样获得，本字段供推理/查询层，当前无消费）
  sides: [FaceSide, FaceSide, FaceSide, FaceSide]; // 0=+x 1=-x 2=+z 3=-z
  idx: number;                      // 块局部下标 lbz*15+lbx
}
interface FaceSide {
  kind: SideKind;                   // "hard"(默认) | "weld" | "bevel"
  oppKind: SideKind;                // 共享边对侧块朝本块的边属性（成对标注）
  leftKind: SideKind;               // 沿边小端(p0)邻接垂直边属性
  rightKind: SideKind;              // 沿边大端(p1)邻接垂直边属性
  ruling: EdgeRuling;               // 裁决溯源 weld|cliff
  topEdgeY: number;                 // 该边顶面视觉高主值（本块视角，逐段 max）
  calcDepth: number;                // 计算落差量（≥0；平地 = 0）
  depth: number;                    // 恒壁深 = calcDepth + WALL_MIN_DEPTH
  arcNeighbor: boolean;             // 两端邻边任一 bevel（弧带伸入 → 需弧顶墙）
  sideTileId: number;               // 侧壁材质（默认 = topTileId）
}
```

**方向/端点约定**（勿混）：
- dir：0=+x、1=−x、2=+z、3=−z（`DIR4`）；`oppositeDir(dir) = dir^1`（同轴反向）。
- `edgeEndAdjacentDirs(dir)`：dir<2 → [3,2]，否则 [1,0] —— 沿边小端 p0/大端 p1 邻接的
  垂直边方向（p0 = 沿边坐标小端：x 向边 = z 小端，z 向边 = x 小端）。
- 「弧边左右邻边」= 与弧边**垂直**的两条邻边（dir^2 与 (dir^2)^1 语义），用于 bevel 否决。

**kind 语义（三态平起平坐，hard 默认）**：
- `hard`（默认，立墙硬边；含主动声明/显式覆写 forceHard / edgePolicy='hard'）；
- `weld`（坡）：裁决为 weld 的边 —— 低侧块顶面沿坡带爬向高侧 crest；两侧都标 weld；
- `bevel`（弧边）：精修层形态 —— 圆角几何由创建函数统一处理；成立条件含
  「左右邻边均非 weld」否决（防弧带与邻边坡面交角漏洞）。

**常量（FaceTable/FaceBuild 定义）**：
| 常量 | 值 | 含义 |
|---|---|---|
| WALL_EPS | 0.05 | 墙存在/埋深容差 |
| WALL_MIN_DEPTH | 0.3 | 每壁恒有保底深度（防 0 高墙/破面） |
| BEVEL_EPS | 0.05 | bevel 判据高差容差 |
| BEVEL_R | 0.3 | 弧带半径（FaceBuild，精修层形态） |
| WELD_RAMP_CELLS | 4/3（块宽 1/3） | weld 坡带宽度（Refinements，可逐边覆写） |
| FINE_S / FINE_D | 8 / 3 | fine 细分 = 0.125m |
| WELD_FINE_EPS | 0.03 | weld 非线性 cell 判据（1m 网格直线 vs 真坡面） |
| SLIT_EPS | 0.004 | 混合边细缝判据（见 §6.2） |

## 4. 两遍建表

### 4.1 Pass1 —— `pass1Build(src, cx, cz, forceHard?)`

每块四向 `kindOfSide(src, bx, bz, dir, forceHard?)` 判定链：
1. `forceHard?(bx,bz,dir)` 命中 → **hard**（显式覆写通道）；
2. `finalRuling(src,…) === "weld"` → **weld**（插值 = 显式 opt-in：
   edgePolicy smooth/hard、liquid/pit 无条件焊、确定性 30% 大落差产坡 override
   —— 全部收敛在 Refinements.finalRuling 唯一判点）；
3. 本块 role=platform 且邻 ground、邻 `h ≤ 本h − BEVEL_EPS`、ruling=cliff、
   且**左右邻边均非 weld** → **bevel**（弧边）；
4. 其余 → hard。

`leftKind/rightKind`：全部 kind 定完后回填（同块垂直邻边），供 Pass2 与创建用。

### 4.2 Pass2 —— `pass2Build(table, src)`

每块每向，把 4m 边按 **4×1m 段**逐段现算再合成主值：
- `topEdgeY` = 4 段中本视角（`viewTopAt` = surfaceHeightCore 本块视角）顶的最大值；
- `calcDepth` = 有墙段 `max(0, 本侧顶 − (lowBase − WALL_EPS))` 的最大，
  `lowBase = min(邻侧顶, 两侧 hBase)`；
- 有墙段判据：`cell.h > nbH || 本侧顶 > 邻侧顶 + WALL_EPS`；
- `depth = calcDepth + WALL_MIN_DEPTH`（**每边恒壁**，平地也有保底 0.3）；
- `oppKind`：同表直取 `nb.sides[dir^1].kind`；跨界按 src 对邻块对侧判 kind；
- `arcNeighbor = leftKind === "bevel" || rightKind === "bevel"`；
- `topWeldDirs`：`side.kind === "weld" && 邻 h > 本 h` 的方向（坡爬入本块顶）。

跨界邻居：Pass2 内 `cellAt` 只查本表，出界按 `src.blockAt` 同公式现算
（无界共享源 → 无需邻居表；`FaceQuery`/`TableProvider` 为预留的跨 chunk 表查询
接口，当前装配未调用）。

## 5. 检验 —— `checkTable(table)`

| 规则 | 说明 |
|---|---|
| 恒保底 | `|depth − (calcDepth + WALL_MIN_DEPTH)|` 须 ≈ 0 |
| bevel 左右邻非坡 | bevel 边左右邻边（`edgeEndAdjacentDirs`）任一 weld → 报错 |
| 左右端标注一致 | `leftKind/rightKind` 与邻边实际 kind 复核 |
| 材质默认一致 | `sideTileId === topTileId`（可改槽默认值一致） |

输出 `errors[]`（限 24 条）+ `stats`（kind 分布 / calcSides / 两侧组合 pairStats /
bevelCount）。生产装配不强制调用（放行门槛在回归脚本层执行）。

## 6. 创建函数 —— FaceBuild（读表 + src，一次产出渲染/物理）

### 6.1 顶面高度函数

- `surfaceHeightCore(src, 视角块, x, z)`：高度场基源（硬边界基面 hB + 本块 weld 边
  interpEdge max 合成）。**视角块 = 查询点所属块**，必须显式传，不得 floor 自推
  （撕裂角语义：同一格点从不同块视角可不同值）。
- `topYView(table, src, 视角块, x, z)` = surfaceHeightCore + **bevel 弧带内缩**：
  视角块存在 bevel 棱且点到棱的垂直距离 `d < BEVEL_R` 时，
  `y −= BEVEL_R − √(2·BEVEL_R·d − d²)`（圆角剖面向内收）。
- `topYAt` = 视角自推版（查询便利）。

### 6.2 顶面 fine 细分图 —— `topFineCells(table, src)`（顶面与侧壁共用）

1m cell 的网格边是直线；凡真实面在该 cell 内不满足「线性可表」就必须
0.125m 细分，否则网格边与真实面（以及贴它的壁）错位。标记来源两类：

- **bevel 弧带 cell**（`cellBevelFine`：cell 距 bevel 棱 < BEVEL_R）→ 外扩 1 格
  （**写独立数组**；原地扩散会级联传染，已踩坑）；
- **weld 非线性 cell**（`cellWeldCurvFine`）：仅候选「本块有 weld 边 且 cell
  落在某 weld 棱坡带（距棱 < rampWidth）」的 cell，做 5 点检验 —— 中心 + 4 边
  中点的真实高 vs 网格三角形线性预测（对角剖分 01-10），偏差 > WELD_FINE_EPS
  → fine。命中 = 坡脚棱/双坡角脊穿过该 cell；
- 随后 **逐边扩张 `weldOut`**（不是整格外扩）：对每个与 fine 相邻的 coarse cell，
  在其共享边的 8 个 fine 节点上采样真实坡面对 1m 弦求差，偏差 > SLIT_EPS →
  并入 fine，迭代至稳定（≤16 轮）。块边界边跳过（由墙封，见 §6.4）。
  这一步消除「细缝」：fine 侧 0.125 折线与 coarse 侧 1m 弦在弯曲共享边上的
  错位（曾表现为坡面上横/竖细缝，实测残留 ≤ 4mm 不可见）。

结果缓存于 `WeakMap<FaceTable, Uint8Array>`（同一表顶/壁两函数只算一次）。
coarse 1m 与 fine 0.125 的分界不影响水密：两种 cell 的顶点互不共享（index
soup），各自线性 —— 共享边双方都直线时必然重合，弯曲边由上方规则保证
两侧同 cadence。

### 6.3 `buildTopGeometry` —— 顶面

- coarse cell：4 角（`topYView`）一 quad，法线 (0,1,0)，三角形对角
  (0,0)-(0,1)-(1,0)/(0,1)-(1,1)-(1,0)（即 01-10 对角线，与 `sampleSurface`
  插值剖分一致）；
- fine cell：9×9 = 0.125m 顶点，高度 `topYView`，法线中差（2·step 标定）；
- uv 按整 chunk 归一（供 tileId/纹理采样），与旧顶面约定一致；
- `topTriCount` = 顶面三角数（合并物理时区分用途）。

### 6.4 `buildWallGeometry` —— 侧壁（每边恒壁）

每块每向生成壁条，深度语义 = 表 depth：
- **顶沿 = 顶网格边界折线同位节点列**：沿边每 1m span 属于一块本块侧 1m cell
  （`dirEdgeCells` 从 fine 图取该 4 cell 标记）；cell fine → 该 span 8×0.125m
  子节点，coarse → span 两端节点。逐节点 `top = topYView(本块视角)` —— 与
  顶网格边界顶点**同位同值**，故每段壁顶 = 顶网格对应边段（闭合由构造保证）；
- 底沿 = `min(本节点顶, lowBase − WALL_EPS − WALL_MIN_DEPTH)`，
  `lowBase = min(邻视角两节点顶的最大, cell.hBase, nb.hBase)`（埋入低侧基底以下，
  任何视角不见破面）；weld 边壁从 crest 一直挂到低侧基底 → 坡面侧壁完整；
- uv = 所属 tile 中心（侧壁材质默认本块 tile），顶点色/明暗为占位（shader 调）；
- 绕序朝外：dir1(−x)/dir2(+z) 采样方向朝内，索引翻转（2026-09-04 修正）；
- bevel 弧带相关边因 fine 图自动获得 0.125 拼弧（旧 SEG=8/32 双档已废除）。

**闭合论证**：顶面每条边线 = 网格边折线（coarse 直线或 fine 折线）；壁顶沿 = 同
节点列同值 → 逐段重合；壁底埋深不穿帮；块边界线两侧 cell 视角不同造成的撕裂由
各自壁条覆盖（壁 = 高侧从其 crest 挂到低侧基底以下）。回归：
`__weldclosure.ts`（900 边/块壁顶 vs 网格边逐点对差，6 chunk × 3 seed = 0 开口）、
`__mixededge.ts`（混合边错位 >5mm 采样 = 0）。

### 6.5 物理与渲染同一份数据

`finishStandardChunkTable` 把 topG + wallG 顶点合并、索引偏移后直接
`replaceChunk → createGround`（trimesh）—— 渲染 = 物理 = 同一缓冲（碰撞=所见
不变式）；无墙缓冲中间物、无 wallRef、无 UV 反推。

## 7. 装配与生命周期

### 7.1 标准流程（默认启用）

```
requestStandardBake(cx,cz)
  ├─ planDecor（装饰先于烘焙：贴图/装饰物阴影进快照）
  ├─ Worker 烘焙 albedo/lightmap（缓存命中跳过）
  └─ finishStandardChunk
       └─ __PP_TABLE_BUILD !== false → finishStandardChunkTable（表驱动，本架构）
             buildFaceTable(src) → buildTopGeometry + buildWallGeometry
             → TerrainMaterial(顶) + WallMaterial(壁) + buildDecorLayer
             → 物理合并 → replaceChunk → createDecorColliders
```

表随 chunk 构建（buildFaceTable 一次），随 chunk 释放；无跨 chunk 持久状态。

### 7.2 装饰/烘焙（未变，消费同一份 decor 计划）

装饰贴图/装饰物在烘焙前放置（`planDecor`），高度采样经 `postSurfaceHeightAt`
（= 旧查询面，见 §8）；物理装饰碰撞体在 replaceChunk 后补建（顺序约定：先换地形
后建装饰碰撞，防旧体误销毁）。测试地图/地块名标注层照旧。

### 7.3 旧路径代码现状（暂存未拆）

设 `globalThis.__PP_TABLE_BUILD = false` 可回退旧装配：
`buildChunkFinal + buildChunkWallBuffers + BlockFaceIndex bundle +
PostProcess.buildPostChunkTopSurface/buildPostSideWalls`。以下仍被该路径引用：
PostProcess.ts / RefinementPostProcess.ts / ChunkSurface.ts / ChunkWalls.ts /
BlockFaceIndex.ts / Refinements 的 buildChunkFinal・buildChunkWallBuffers・
mergeTerrainPhysics。**退役拆分是开放项（§12），本架构文档以表驱动为权威。**
旧管线对照脚本（surface-regression / postprocess-regression / __tabletest /
__bfintegrate）在旧路径拆完前保留作对照（__p0table 已删：引用的 attachWallQuads
早不存在，2026-09-05）。

## 8. 查询/贴地现状与收敛（开放项 P1）

- 几何（本架构）：顶面/壁均以 `surfaceHeightCore` 解析面 + fine 网格产出；
- 贴地/装饰查询：`RasterMap.surfaceHeightAt` → `RefinementPostProcess.
  ppSurfaceHeight`（四角 cornerCell 三角插值 + `ppHeight` 逐点偏移：旧 bevel 圆角；
  坑/裂已移除；`POST_PROCESS_ENABLED=false` → 退化为纯 cornerCell 面）。
  ★ **坑/裂已弃用并移除（2026-09-05）**：`POST_PROCESS_ENABLED=false` 关停本层，
  surfaceHeightAt 与烘焙高度源同步退化为纯精修层视觉面；坑洞/裂缝代码（ppHeight
  内 pit/crack、PostProcess 的坑裂链、配置常量）已整段删除，待用户基于表驱动重写。
  渲染（表驱动，无坑裂）与查询现存的残余差异 = 表驱动 weld/fine（含 FaceBuild
  bevel 弧带）↔ cornerCell 部分插值，收敛为 P1：统一高度接口（建议 f32 角高场
  全链），旧 pp/查询路径退役后删除。

## 13. 坑洞/裂隙 = 实时地形变形（阶段 E′，2026-09-05）——【已作废 · 仅存档】

> ★ 2026-09-05 晚：用户拍板移除旧坑洞管线。本节整套「实时变形层 / dent 状态表 /
> DeformManager / deformOffset 三端同源」设计**未按其原样落地即被 §14.10 R+P 取代**；
> 代码已删除：`RegionDeform.ts` / `RegionFaceQuery.ts`（及 __regionquery / __regiondeform
> 回归）。运行时破坏 = 子弹 → `ChunkManager.playBulletImpact` → 补丁覆盖（§14.10）。
> 本节仅作历史存档保留。

> 取代旧 pit/crack 后处理（已整段移除，见 §7.3/§12.2）。坑/裂升级为**实时变形
> 系统**：一套变形层、两个触发端——生成期种子装饰（轻量变体）+ **角色攻击命中的
> 运行时下陷**。同一张**变形状态表**驱动几何/查询/烘焙三端同源；不在 FaceTable
> 增字段，阶段 D 纯基础地形保持逐位一致（A/B）。坑为**纯下沉** ⇒ 无需真删面。
> 关键洞察（用户定调）：**「同步更新一下表」** —— 变形是能全局查询的高度附加场，
> 后台重烘焙只需重读同一张变形表即可把坑面光照变准，无需几何耦合。

### 13.1 总体管线（一套变形层，两个触发端）

```
触发端（都写同一张变形状态表，§13.2）：
   T1 生成期装饰（轻量变体）——阶段 D 基础地形生成完成后，以世界种子按 §13.2
       确定性逐块查询 → 就地埋入装饰坑/裂（今随机装饰的替代，同表同机制）。
   T2 攻击命中（运行时）——attackImpact(x,z) 向 dent 表追加一条 → 立即驱动
       受影响 chunk 重建（§13.7 运行时路径）。

取样端（同一 dent 表 → 三端同源）：
   deformOffset(x,z) = Σ各 dent 在 (x,z) 的纯下沉贡献（≤0）
   deformYView(表,src,vbx,vbz,x,z)      = topYView + deformOffset      // 几何（顶+壁顶沿）
   deformSurfaceHeight(src,x,z)         = sampleSurface + deformOffset  // 查询/烘焙
```

阶段 D 产出**纯基础地形**（weld/bevel fine 齐全、与今天逐位一致），变形只加载在
dent 表上；dent 表为空 = 纯基础地形（A/B 保持）。坑为**纯下沉雕刻**：新表面
处处不高于旧表面 ⇒ 无需真删面（§13.5.2），范围只覆盖坑/裂本体口沿圈 → 顶点
预算低一个量级。

### 13.2 变形状态表（内存态 dent 层）与两种注入

- 表 = 全局 `DeformState`（**内存态**，用户拍板不做持久化）：`dent[]`，每条 =
  `{环心 wx/wz, 半径 R, 深度 D, profile(kind: pit|crack 及其方向/长/半宽),
  source: T1|T2}`。纯数据可序列化；chunk 卸载即失。
- **T1 注入（确定性生成期装饰）**：阶段 E 承继原「读表查命中」实体——对
  FaceTable 15×15 地块逐个 `hash32(世界块坐标, worldSeed)` 判定（PATCH_RATE
  ≈0.05），命中则写一条 dent。锚用世界块坐标 ⇒ 同一物理地块任何 chunk/任何
  时刻重算一致，无需跨 chunk 通信。
- **T2 注入（运行时攻击）**：`DeformManager.impact(wx,wz,strength)` 即时追加
  一条 dent（参数按武器/地形滚定，§13.4），并在命中帧驱动受影响 chunk rebuild。
  与 T1 之差只在**参数来源（运行时 vs 种子哈希）与触发时机（命中帧 vs 建块）**；
  数据、几何、查询、烘焙全部同一机制 —— 这就是「随机生成 = 实时系统的
  轻量变体」。

### 13.3 候选资格（纯 src 判定，避开棱/坡敏感带）

T1 以表遍历、T2 以命中点定位，但**资格不得引用表字段**——查询/烘焙在任意 chunk
都可重算同一资格（§12.5 的跨 chunk 查询尚未接入，故此约束是硬性的）。T2 命中点
同样过资格筛（水上/高台边缘等落点直接放弃，不产生 dent）。资格 = 只看 `src`：

- 本块 role ∉ `{liquid, pit, platform}`（水面/低洼/高台不雕）；
- 8 邻块 role ∉ `{liquid, pit, platform}`（水岸/台缘不雕）；
- 四向邻块高度差 |Δh| ≤ `PATCH_SLOPE_EPS`(0.5m)。

前两条保角色语义；第三条的关键作用——**weld 棱/坡带只在高度过渡处成形**
（§4.1/§6.1），禁止陡变邻块（|Δh|>0.5）⇒ **weld 坡带不可能伸过命中块**，从根上
把 §6.2/§6.4 的「两侧同 cadence」闭合论证区域与 deform 场隔离。
bevel 弧带（≤0.3m）只出现在微差边（|Δh|≤0.5，邻块略低）：坑口若压到这类边上，
只需 **dent fine 与 bevel fine 取并集**（§13.5.1 独立数组合并）+ 口沿处 offset=0 且
s'(0)=0（C¹ 平滑）——叠加依旧水密，无专门互斥需求。

### 13.4 参数卷（T1/T2 共用剖面，参数来源不同）

```
PATCH_RATE       ≈ 0.05   T1 每块命中概率（回归带 [0.03, 0.10]）
PATCH_SLOPE_EPS  = 0.5    m，高度陡变邻块禁雕（§13.3，T1/T2 同用）
T1 生成期坑：圆心=块心+哈希偏移 δ∈[0,0.5]m；R=0.9..1.4m；D=0.25..0.5m
   ★ δ+R ≤ 1.9 < 2.0（永不出块、可贴块边触发侧壁同步）
T1 生成期裂：方向=哈希 θ；半长 ≤1.6m；半宽 W=0.15..0.4m；深 0.15..0.3m；
   两端「半宽→0 渐隐」V 收口，端点距块边 ≥0.4m（裂不切壁）
T2 攻击 dent：impact(wx,wz,strength) —— 半径 R=0.6..1.2m·强系数、深 D=0.15..0.4m
   圆心=命中点，**允许跨 cell/跨块**（dent 表全局；rebuild 按影响集处理 ≥1 chunk，
   §13.7）；方向性攻击也可落一条 crack（沿攻击方向、参数同 T1 裂）。
剖面（共用）：平底+陡壁 smoothstep s(t)=3t²−2t³，t=(R−r)/0.35 —— 口沿 r=R
   offset=0（两端 s'=0，C¹）、坑底 r≤R−0.35 均匀平面 −D；陡壁斜率 ≈1.5D/0.35
   （57~65°）。裂同此：中心条带 −D，两侧 W−0.2..W 陡壁带。
堆叠：deformOffset = Σ 各 dent 贡献（每端 C¹ ⇒ 重叠无阶）。
```

深度为世界纵向单位，剖面纯数学（无 cache、无副作用），同参同值。旧 pit/crack
常量名已清空，可安全复用。顶点预算同 §13.5.1 —— **每 dent 仅口沿圈 2~5 fine
cell**，体量净增 <1%（§13.8 锁死）。

### 13.5 挖坑几何（小范围 fine + 删面等价 + 侧壁同步）

#### 13.5.1 范围只到口沿圈（顶点预算见 §13.4）

- **顶面**：不再整块 4×4 精细化。**只有与坑/裂口沿相交的 cell 标 fine**
  （坑：陡壁圈带 r ∈ [R−0.35, R]；裂：槽两陡壁带 + 端收口），且沿 §6.2 写**独立
  数组再合并** `fineE = baseFine | deformFine`（沿用「原地扩张级联传染」教训）。
  陡壁带 = 0.125m 弧面解析取样（smoothstep 剖面，§13.4），坑底/槽底为**均匀平板
   −D** → 内区 coarse 1m 即精确（无曲率可走样），口沿圈外 0 差不偏移、1m 直线
  照旧。命中 ~11 座 × 2~5 fine cell/坑、≤7 条带/裂，**顶面体量净增 <1%**
  （§13.8 体量行锁死）。这就是「范围要小、面数要少」的落实。

#### 13.5.2 「挖坑删面 → 补下部」的等价论证（本实现不真删，数学等价）

目标态 = 把坑覆盖区的地表换成更低的新面。阶段 D 的基础地形（顶面/壁与今天逐位
一致）先生成完毕，变形在其上以「位移」达成同一可见结果（T1/T2 同一机制）：

- 坑/裂是**纯下沉**：deform 后的新表面 `topYView + deformOffset(≤0)` 在全区处处
  不高于基础面 `topYView`。旧面**被覆盖在下面、永不露出** ⇒ 无需物理删除——
  删与不删的渲染/物理结论逐像素一致；不删还免去了「删后补」要焊接两道边界
  的缝隙风险。「原本经过的部分删去、用下部的坑补上」在纯下沉下 === displacement，
  此处明确必须下沉才能成立：**凡剖面只降不升，删/移等价；若未来有洞穿/悬顶类
  上抬特征，需回到真布尔删面，本文档暂排除。**
- 唯一会发生「旧面露出」的现象是坑切过**侧壁**（壁面不是下沉面）→ 处理见
  §13.5.3。

#### 13.5.3 相关侧壁同步（用户要求的核心：坑向下凹一块 ⇒ 壁面必须跟着改）

侧壁**恒壁 quad 的顶沿本来就是「贴顶网格边界折线」**（§6.4，`topYView` 同位采样）。
把它从 `topYView` 换成 **deformed 面（含 deformOffset）**：

- 坑贴近某条块壁时（T1 δ+R→1.9、T2 命中点任位），该壁顶沿在此段**随坑口下凹**
  —— 壁面从「平顶」变「V 形内凹」，坑壁在崖面上形成可见缺口 —— 正是「向下凹
  一块，侧壁同步修改」；
- 壁顶沿节点仍在顶网格边界折线上（同列同位采样），与顶面闭合论证（§6.4）不破坏：
  壁顶沿 = 顶网格边界段（deformed 版），两侧同函数同值；
- 壁面其余（低侧基底、埋深 WALL_MIN_DEPTH）不变，底仍埋入低侧基底以下；
  cavity 内凹只改顶沿路径，不改变「壁 = 覆盖低侧开口」的恒壁语义。
- T1 坑不跨块（δ+R ≤ 1.9 < 2.0）→ 同步壁在本块内；T2 命中若跨 chunk 边，影响
  集重建两个 chunk，各自壁顶沿同源采样同一 dent 表 ⇒ 跨 chunk 无接缝。

> 实现落点：`buildWallGeometry` 顶沿的两处采样（`topYView`，FaceBuild.ts:457）改走
> `deformYView`；`dirEdgeCells` 的 fine 读取不变（口沿圈 fine ⇒ 该壁段自动 0.125 细）。

#### 13.5.4 坑/裂内壁语义（不新增面类别）

坑壁/槽壁的陡坡三角来自**口沿圈 fine + 内区 coarse 过渡**：口沿圈 0.125m 弧面
（法线中差平滑渲染）即真实坑壁，坑底/槽底为内区均匀平板段；无独立坑壁/坑底
子网格、无二次 pass。整个坑 = 顶面一张网格里的一次下沉面（§13.5.2 删面等价）。

### 13.6 高度场统一与收敛（几何 = 查询 = 烘焙 = 同一张变形表）

定义**唯一的变形附加场**与两条同源入口（T1/T2 无差别）：

```
deformOffset(x,z) = Σ dent 贡献        // ≤0，纯下沉；支撑 = 各 dent 圆域
deformYView(表,src,vbx,vbz,x,z)     = topYView + deformOffset      // 几何
deformSurfaceHeight(src, x, z)      = sampleSurface + deformOffset  // 查询/烘焙
```

收敛论证：

1. 几何顶面逐顶点 `deformYView`；`sampleSurface` = cornerCell 四角插值
   （Refinements.cornerCell = surfaceHeightCore，与 topYView 的 base 同源，§8
   已知一致）＋逐点 deformOffset ⇒ 两式同点同值（f64 同函数）。
   ★ coarse/精确之差：**口沿陡壁带必 fine**（0.125m 逐顶点取样，无走样）；坑底/
   槽底为**均匀平面 −D**（1m coarse cell 内线性即精确）⇒ 坑几何 ≡ 查询面，
   偏差 < 1cm（§13.8 收敛行）。
2. dent 本质为局部场：其圆周外 offset=0 且两端 C¹ ⇒ fine/coarse 边界两侧无台阶；
   跨 chunk 的 dent，两侧 chunk 读同一全局 dent 表，边界同值。
3. 查询/烘焙直接用 `deformSurfaceHeight`：

   - `RasterMap.surfaceHeightAt`（:155 现走 ppSurfaceHeight）切到 deformSurfaceHeight；
   - `bakeCompute` 的 surfaceHeightAt 假接口（:662）切成同函数 ⇒ **后台重烘焙 =
     「同步更新表」**：deflect 后重跑 requestStandardBake 只重读 dent 表，高质量
     坑面光照（坑壁 AO/坑底明暗）自动跟上，与几何零耦合。
     —— §8 的 P1 在坑/裂维度一次性收敛（weld/fine 残余差异仍是独立 P1，§12.1）。

   旧 `ppSurfaceHeight` 骨架随之退役，`POST_PROCESS_ENABLED` 总闸可最终摘除
   （进 §12.2 退役清单）。

### 13.7 渲染/物理同源 + 运行时重建与光照

**物理不需要第二份几何**。deformOffset 表现在 topG+wallG 的顶点/索引里，
`finishStandardChunkTable` 照旧合并两缓冲后 `createGround` 建 trimesh（§6.5
不变式）——「渲染和物理都打补丁」= 同缓冲补丁。装饰碰撞体照 §7.2 补建，
高度采样走 deformSurfaceHeight，与坑面齐平。

**建块时序（T1 装饰随建块落定；烘焙先于几何且已含坑面）**：

```
finishStandardChunk(cx,cz)
   ├─ 烘焙已由 requestStandardBake 打完（Worker；surfaceHeightAt=deformSurfaceHeight
   │    ⇒ T1 装饰坑的光照在几何生成前即定型）
   └─ finishStandardChunkTable：阶段D 基础顶/壁（纯）
       → T1：DeformManager 注入 dent 表 → 顶/壁输出
         buildTopGeometry(table,src,deform) / buildWallGeometry(table,src,deform)
       → 材质 → 物理合并 → replaceChunk → 装饰碰撞体
```

**运行时击中路径（T2，主线程，~几 ms）**：

```
DeformManager.impact(wx, wz, strength)
  1. dent 表追加（§13.2）
  2. 影响集 = 与 dent 圆相交的已加载 chunk（可 ≥1，跨 chunk 边各取各）
  3. 逐个 chunk：deform 重建（deformYView / 口沿圈 fine / 壁顶沿）→ replaceChunk

     重建装饰碰撞体（复用缓存 decor 计划，采样 deformSurfaceHeight ⇒ 坑内物落
     到新坑底）
  4. surfaceHeightAt 已走 deformSurfaceHeight ⇒ 脚底/后续命中即时收敛
  5. 光照（用户定调：即时 + 后台重烘焙）：
     - **即时**：重建时局部法线重算 + 坑壁顶点色 AO 压暗（零延迟假 AO）
     - **后台**：若该 chunk 未在重烘焙冷却中（~2s）→ 强制 requestStandardBake
       （读同一 dent 表 = 「同步更新表」）→ 就绪后只换材质光照，不再动几何
```

**阶段 E′ 引入的装配改动**：

1. `finishStandardChunkTable` 在 buildFaceTable 后构造 `deform = buildDeform(T1)`
   （读表择命中 → dent 表）；`impact()` 入口由模式层接攻击回调；
2. `buildTopGeometry(table,src,deform)` / `buildWallGeometry(table,src,deform)`
   （deform 空 = 纯基础地形，A/B）；壁顶沿走 `deformYView`（§13.5.3）；
3. `RasterMap.surfaceHeightAt` 与 bakeCompute 高度假接口换 `deformSurfaceHeight`；

存在（装饰落坑内，占用采样自动取坑底高，见 §13.6.3）。

## 14. FaceQuery —— 区域面查询工具（§12.5 预留实体落地，2026-09-05）——【已作废 · 仅存档】

> ★ 2026-09-05 晚：随旧 deform 管线整段移除（模块 RegionFaceQuery.ts 已删），
> §14.1–§14.9 全部为存档内容。§14.10「剔除+打补丁（R+P）」是现行运行时破坏方案。

> 目标（用户定调）：**划定一块 3D 范围 → 直接得到范围内所有侧壁与顶面；做细节
> 改动时还能告知每个面的什么具体部位在该改动范围内**。一半走表的面查询（FaceTable/
> 纯数据），一半需真实访问实际地形渲染（THREE Mesh）+ 物理（trimesh 合并缓冲）。

### 14.1 用途与两种模式

**模式 A —— 表驱动查询（纯）**：读 FaceTable + src + fine 图，不依赖任何渲染/物理
实例。给定 3D 范围，返回范围内顶 cell 与壁 column 的**逻辑身份**（§14.3 表侧部分）。
chunk 未建也能查 —— 编辑器/规划/bake/路径的通用底座。

**模式 B —— 实装对位（真实读写）**：对**已建 chunk**，在逻辑身份上附加实际缓冲
切片：
- 渲染：顶/壁两个 Mesh 的 BufferGeometry（position/normal/color/index）属性切片；
- 物理：合并 trimesh 数组（`pv/pi`）对应切片 —— 由于渲染与物理**同构同序**
  （§6.5），以 `nVT = topG.vertices.length/3` 与 `topIndexCount` 换算即可对位；
- 未建 chunk 仅返回模式 A 身份（`mesh/phys` 空），状态透明。

两个模式同一套 `FaceRef`，调用方按需取。

### 14.2 输入与两段式（用户定调：一个三维形状，先表后部位）

```
query3D(shape: Shape3D): { faces: FaceRef[], parts: PartInfo[] }
Shape3D = Sphere{中心 wx,wz,y, R}            // dent/坑（§13.4）
        | Box3D{min, max}
        | SlotPolyline{折线,W,D}             // crack 槽（含端收口）
        | 复合（union=min / intersect=max / subtract=− 的 SDF 组合）
```

**形状表达约定（性能/精度两级）**：
- **精确拟合（变形/真删补）**：解析 SDF 复合（盒=6 slab、球=距离−R、折线槽=
  点到折线距离≤W 且 y∈[−D,0]，2.5D 有盖棱柱），union=`min`/intersect=`max`/
  subtract=`−`；边界交点统一用「边上二分求 SDF=0」（每条边 6~10 次采样）。
- **粗略定位（只问哪些面/大概区域，推荐默认）**：把复杂形状**粗分解成 ≤8 个
  盒/薄片/球**原语的 union —— 不要再拆细（大量原语会 O(V×N) 和轮廓碎裂）；
  盒内判定=3 次区间比较，比球还省；不求精确截面，partial 交点整体关闭。
- 两类查询内部都先 cell 包围盒 vs 形状下界做**整格快跳**。查询本体恒为亚毫秒
  级，贵的是改动后的重建/烘焙而非查询。

阶段1 —— 表查询粗筛（先得知涉及哪些面）：
   shape.bounds（含 y 高差的 AABB）→ 与已加载 chunk 包围盒求交 → chunk 集
   → 逐 chunk 读 FaceTable 做块级/格级裁剪：
      顶 cell：1m 足迹 ∩ bounds.xy 非空 且 表面高范围与 bounds.y 重叠；
      壁 column：贴边 4m 竖条带（顶沿 ~ lowBase−DEPTH）与 bounds 相交；
   → InvolvedFaces: FaceRef[]（§14.3）

阶段2 —— 精确部位窄筛（每面哪部分区域在形状内）：
   → classifyParts(faces, shape)，见 §14.4
```

跨 chunk：bounds 与任一已加载 chunk 包围盒相交即纳入；未建 chunk 由模式 A 直查
（读 src/种子，无需实例）。`impact`/编辑器都只传 shape，内部自动两段。

### 14.3 `FaceRef` 结构（表侧身份 + 实装侧切片 + cadence 组）

```
interface FaceRef {
  kind: 'top-cell' | 'wall-column';
  chunk: { cx, cz, key };              // chunk 归属
  // —— 表侧身份（模式 A 恒有；无需渲染）——
  topCell?:  { lx, lz, viewBx, viewBz, isFine };              // 顶 cell（1m 格）
  wallCol?:  { bx, bz, dir, lowBase, topBase };               // 壁 column（抽象块+向）
  // —— 实装侧（模式 B；chunk 已建才有）——
  render?: { meshId:'top'|'wall'; vertexBase; vertexCount;
             indexBase; indexCount; hasColor; hasShade };     // 渲染 BufferGeometry 切片
  phys?:   { vertexBase; vertexCount; indexBase; indexCount }; // 物理合并缓冲切片（同构换算）
  // —— cadence（水密关键）——
  shareEdges: EdgeRef[];   // 本面参与的外边界边：{即与邻 cell/邻壁共享的边；
                           //   shared 端点在 coarse/fine 边界或 chunk 边界}
}
```

- 顶 cell 的 `render` 切片含 coarse（4 顶点/2 三角）或 fine（9×9 顶点/128 三角）
  两种形态 —— 由 `isFine` 区分；
- 壁 column 的切片为沿边节点段（≤4 span × fine 分裂）+ 顶沿/底沿点集；
- `shareEdges`：改动一个面的顶点，若它骑在 coarse/fine 共享边或顶沿↔壁顶沿
  共享点，就必须连带邻面同步 —— 这是 §6.2/§6.4 水密论证在工具层的「责任链」。

### 14.4 `classifyParts` —— 每面哪部分区域在形状内

对阶段 1 的 InvolvedFaces 逐一与 shape 的**体积**做精细求交，输出三类覆盖：

- `fullyInside`：完全在形状内的子三角/子段 —— 直接位移/涂改的原子集；
- `partial`：与 shape 表面相交的子面片 —— **逐边记录与形状边界的交点参数 t**
  （截面轮廓点，是重细分 / 真删补变形（§13.5）的骨架；**粗略模式可整体关闭**）；
- `depthAt`：顶点逐点下沉量（deformOffset 值）。

**采样粒度旋钮 `resolution`**：分类采样不必绑定面的实际细分——
`0.125 / 0.25 / 0.5 / 1m` 可选。`res=1m` 时 coarse cell 只测 4 角、fine cell 退化为
粗抽样，仅需「哪些面/大概区域」时开销压低一个数量级；需要真写回变形/删补时
才用 `res=0.125`（fine 格 81 顶点 + 边界交点）。**旋钮只影响分类精度，不影响表身份
与切片对位的正确性**。

对每类面：

| FaceRef 类型 | 返回的「具体部位」 |
|---|---|
| top-cell **fine** | 9×9 0.125 顶点中落在 shape 内的顶点下标与深度；fullyInside 子三角集合；与形状表面相交的 partial 三角及其边界交点参数 |
| top-cell **coarse** | 4 角点位图 + **`needRefine=true`**（1m 网格只能线性表达，coverage 要被精细切分必须并发升 fine——连锁触发其 shareEdges 邻 cell 一并评估） |
| wall-column | 沿边 **span 位图**（该 1m span 是否与 shape 相交）+ span 内 0.125 节点集；顶沿节点集（与顶网格边界同点 —— 改动时须与对应 top-cell 同值，侧壁同步天然达成）；底沿点集；partial 段与形状边界的交点 |

```ts
classifyParts(refs: FaceRef[], shape: Shape): PartInfo[]
// PartInfo = { ref,
//              inside: { vertices, triSubset, depthAt },   // fullyInside
//              partial: { edges, 交点参数 t[] },            // 截面轮廓
//              needRefine: boolean, syncEdges: EdgeRef[],
//              wallTopNodes?: 同点组 }
```

关键点：classify 输出**最小修改单位** = 顶点/三角粒度 + 截面轮廓交点 +
`needRefine` 升级需求 + `syncEdges` 连带责任 —— 「这个面哪部分区域在形状内」
精确到可执行粒度，且自带的 cadence 信息保证不会改坏邻居。

### 14.5 read / apply —— 真实访问渲染与物理

```ts
// 读（模式 B）：返回去重的顶点/法线/颜色/高度快照，按世界坐标做 key，
//   ⇒ 顶沿节点 与 壁顶沿节点（同位同点）自动合并为同一笔 ⇒ 编辑天然同步两侧
readFaces(refs, partSelect?): FaceSnapshot[]
// 写：
applyFaces(updates, opts?: { physics: 'rebuild' | 'inplace' })
  → 渲染：写 BufferAttribute（position/normal/color）→ .needsUpdate = true
  → 物理：'inplace' 就地写合并 trimesh 数组（引擎支持 update 则直更，
          否则同缓冲 createGround 换入）；'rebuild' = 整 chunk 走 §13.7 重建
  → 标记该 chunk 异步重烘焙（冷却，§13.7.5）
```

- **渲染 = 物理强一致**：写渲染切片的同时按 §14.3 的 `phys` 切片同构写到物理
  数组；两处不同 buff 但同序同值，绝无「看得见踩不实」。
- **改写法线/颜色**：recompute 范围内法线（中差）与坑壁 AO 顶点色（§13.7 即时
  光照路径在此可复用）。
- 顶/壁两个 Mesh 与物理三种缓冲由 `refs` 内的切片直接覆盖，不扫描整个 chunk。

### 14.6 与变形系统/编辑器的配合

- **§13 变形（T2 impact）**：classify 先行 —— 得 needRefine 集 + fine 顶点集 +
  壁顶沿组 → 决定该 dent 走「整 chunk 重建」（含 fine 升级，§13.7 主路径）还是
  「就地哑改」；默认主路径，工具只提供精确性判定与落位。
- **编辑器/判定工具**：`query3D`（模式 A）粗筛 + 阶段 2 classify 定位 + apply 原位
  微调（贴图/细节/测量），不触发重建。
- FaceQuery 就是老 `BlockFaceIndex`（§11 归档）的正确继承者：不靠 UV 反推，全量
  来自表身份 + 合并布局。

### 14.7 边界与未建 chunk

- region 跨 chunk：逐 chunk 分发；邻 chunk 边界侧的面按各自 chunk 返回
  （各自壁条覆盖，§6.4 论证），工具不跨 chunk 缝合顶点，只保证同点同值。
- 未建 chunk：模式 A 直接给身份（读 src/种子确定性求得 isFine/needRefine），
  render/phys 为 null —— 编辑器/规划拿到纯逻辑答案；构建后补齐模式 B。

### 14.8 FaceQuery 回归

- 命中一致性：同一 shape（bounds）下模式 A 与模式 B 的身份完全一致；
- 切片合法性：render/phys 的 vertex/index 范围落在缓冲实际长度内，三角不越界；
- 同点同值：classify 返回的顶沿节点与壁顶沿节点世界坐标一一对应、深度一致；
- 读写往返：apply 后 readFaces 与写入值全等；物理与渲染 arrays 逐位一致；
- needRefine 正确性：coarse↔fine 边界两侧偏差 = 0，升级后无 T 结；
- 性能：单 region 查询 + classify 单 chunk 顶点命中数在预算边界内（实测基线）。

### 14.10 ★ 剔除+打补丁（R+P）——子弹撞地轻量方案（已实现）

- 定调（2026-09-05 用户拍板）：不用 deform 下沉，改为「区域内材质剔除 + 统一补丁」——
  子弹命中区域（垂直投影与水平圆相交的 coarse cell 集）顶面/侧壁统一挖成补丁，
  补丁区域边界即 3D 区域边界，边界外原样。
- 语义落位（含用户两轮修正：坑缘坡面插值 + 坑底不悬空 + 补丁全权负责内部）：
  - **深度场（逐顶点，世界函数）**：`PatchOverlay.depthOf(wx,wz)` = 坑内满 `PATCH_DEPTH`，
    「四方向射线法」：沿 ±x/±z 共边逐个 cell 外走，遇未补丁（含跨 chunk 出界）即坑口线，
    取点到该线距离的最小值，向内 1m smoothstep 坡降 → 坑口线深度 0（与原地面 C⁰ 连续）。
    ★ 只计共边方向：对角仅共享角点的未补丁格不参与距离 → R=0.6 的小十字坑中心可达满深
    （若按任意相邻格取矩形距离，小坑中心最大只有 0.5D，游戏里几乎不可见——已修并加验收）。
    顶面每顶点 y = topYView − depthOf（coarse 四角/fine 全网格采样；
    fine 法线中差重算 → 坑缘坡面法线正确倾斜；coarse 斜坡面暂保持 (0,1,0)）。
  - **坡面即坑的侧壁**：坑不是一个竖直台阶，而是一个平滑凹陷；坡面（含坑内整个顶面）全用
    补丁色 →「坑的侧壁材质依旧属于补丁」。
  - **坑内隔断壁剔除（补丁全权负责内部）**：恒壁只在 4m 块边存在；两侧 cell 都补丁的壁段
    **仅当两侧表面在壁线处数学级同高（|差| < WALL_FLUSH_EPS=0.002m，浮点噪声级）**才整段
    剔除 → 连贯凹陷。★ eps 曾取 0.02 → 毫米~2cm 的微小高台棱被误删（用户实测：微小高差
    地面补丁后侧壁消失）；任何可见高差（≥几毫米）壁段**必须保留并补丁化**——顶沿 = 原顶面
    − 深度场（世界函数两侧同减 → 台阶差保持），否则把崖壁抽掉 = 打出空洞（void，同日实测
    修复）。坑缘壁（补丁↔原样交界）顶沿=原地面（边界线 depth=0 → 坑底经由坡面落地，不悬空），
    并染补丁色。
  - **防 T 结细缝（补丁 cell ∪ 外扩 1 圈强制 fine 细分）**：深度场给原本平坦 coarse 区引入
    smoothstep 曲率——若补丁 cell 保持 coarse（1m 弦线）会与其相邻 fine 格/坑口外侧 coarse
    弦线在曲率处裂开（补丁内部 & 与原面交界缝隙，2026-09-05 用户实测修复）。
    `topFineCellsFor` = 基座 fine ∪ 补丁 cell ∪ 补丁邻格 1 圈 → 坑内坡面与坑口交界全细分
    （0.125m 逐点采样世界函数），粗细分界只落在深度/表面恒直的边上 → 弦=曲线，无缝隙。
  - **壁底保底深度随深度场（预防性侧壁长度）**：墙底参照 = 邻侧**深度场修正后的最终面**
    （两节点同减 depthOf）→ "埋入地下防破面"的 WALL_EPS+WALL_MIN_DEPTH 保底长度相对
    新坑底仍完整保留，坑底接缝不露线（2026-09-05 用户：补丁侧壁也要留预防性长度）。
  - **材质**：顶/壁 ShaderMaterial 增加 `useVertexColor` + `vColor` 通道；**顶点色 =
    乘性焦土染色**：中性白 (1,1,1) = 原样；非中性色（补丁染色乘数）→ `albedo × vColor`，
    保留原 tile 的 base/纹理明暗颗粒 → "地面被烧过"而非换纸。三版演进记录：
    ① 乘数取 [0.16,0.135,0.12] 线性太深 → 全黑（用户：看不到颜色）；
    ② 改整块 albedo/base 替换 → 丢纹理成贴纸（用户：材质变了/均匀色块）；
    ③ 定案：乘性染色 + 乘数提亮到 [0.62,0.52,0.42]（暖褐焦土调，细节保留，不同
    地面烧完深浅自然）。侧壁默认顶点色 = [1,1,1]（此前 0.6 占位在开启顶点色后
    会压暗全世界侧壁，已修正）。无新贴图/无 tile id 扩展。
  - **幂等**：同 cell 二次命中不重复标记、不重建。
- 实现位点：
  - `FaceBuild`：`PATCH_DEPTH=0.2`、`PATCH_COLOR=[0.62,0.52,0.42]`（乘性焦土染色）、
    `PatchOverlay{isPatched, depthOf, color}` 接口、`buildPatchOverlay(patched, cx, cz, depth, color)`
    工厂（深度场含 1m smoothstep 坡面插值；跨 chunk 边界视未补丁 → seam 两侧各自收口 0，封死），
    `buildTopGeometry`/`buildWallGeometry` 增加 patch 参数、顶面几何恒输 `colors`；
    `circleCells(px,pz,r,chunkSize)` 纯函数（AABB 中心最近点判交；角点并入；跨 chunk/负坐标安全）。
  - `ChunkManager`：`patches: Map<chunkKey, Uint8Array(60×60)>` 补丁覆盖（内存态）；
    `finishStandardChunkTable` 读覆盖 → `buildPatchOverlay` 传给两个 builder；装配抽成
    `assembleTableChunk`（几何字节 → 材质/Group/装饰/物理/换装，Worker 与同步共用）；
    **破坏重建走 `terrainPatch` Worker**（§14.10b）：`patchRebuildChunk` 拷掩码 → Worker
    几何 → 装配；同 chunk 并发串行化；Worker 失败/纹理缓存缺失 → `requestStandardBake`
    兜底。`toGeo` 顶面挂 `color` 属性；标准顶/壁材质 `useVertexColor:true`（boss4D 与
    ChunkWalls/PostProcess 保持默认不启用）；`playBulletImpact` R+P 重写（circleCells
    标记 → 有新 cell 才 patchRebuildChunk；未建成 chunk 只登记，将来烘焙自然带补丁）；
    `isPatchedAt(x,z)` 查询。

### 14.10b ★ 破坏几何 Worker 化（2026-09-05）

- 动机：命中重建的最大单帧成本 = 「表 + 双 builder」整 chunk 几何生成（数万顶点，
  主线程数十 ms 级）；决策（circleCells/标记）本就 μs 级留主线程。
- 拆法（输入面收敛于 Refinements 统一输入面，故可整段迁移）：
  - `PatchCompute.computeTableGeometry(readChunk, seed, cx, cz, mask)` = 唯一几何生成
    纯函数：`makeChunkSource → refineChunkSource(seed,cx,cz) → buildFaceTable → 双 builder`
    （与 `RasterMap.chunkSource` 同路径同函数）。文件不 import three → Worker 依赖最小。
  - `terrainPatch.worker.ts`：收 3×3 邻域 heights/blockTypes 拷贝 + 掩码 → 纯计算 →
    回传可转移 typed arrays（零拷贝）。
  - `TerrainPatch.ts`：主线程服务。拷邻域数组（~135KB，不转移活数组所有权）→
    postMessage(transfer)；掩码必须传**拷贝**（transfer 会转移所有权）；Worker 不可用/
    onerror → 主线程同步同函数（字节一致）；再失败由 ChunkManager 走标准烘焙兜底。
- 一致性与正确性：Worker 与主线程同一函数同一输入 → **逐位一致**（验收 ⑧：活闭包
  vs 传输拷贝闭包逐位比对，2 seeds）；并发：同 chunk 在途串行化，命中合并后重算终态
  （掩码只增）；幂等跳过保留。
- 未移出主线程（边界）：BufferGeometry 上传/材质/装饰层与碰撞体/rapier collider 重建——
  three/物理对象只能在主线程；后续若仍需优化，先 profile 这几段的占比再决定。

### 14.10c ★ 玩法高度采样同步（角色脚底/贴地/clamp 三端同源，2026-09-05）

- 根因（用户实测：坑洞没同步物理层——只改了渲染）：rapier trimesh 随 replaceChunk 每
  次破坏重建（子弹落点正确），但**角色/敌人/实体落脚不走物理体**，走
  `RasterMap.surfaceHeightAt`（WorldMode.clampCharacter / EntityBase / CharacterBase）
  —— 不知道补丁 → 角色在坑上"浮空行走"，观感 = 物理层未同步。
- 修法：新增 `PatchState`（全局单一真源：掩码 + depthAtWorld 世界深度查询；渲染几何 /
  Worker / 玩法采样共用同一张掩码）。`RasterMap.surfaceHeightAt` 统一 **减补丁深度场**
  （坑内 = PATCH_DEPTH、坑缘 1m smoothstep 坡降 → 0，与几何同函数）→ 角色/敌人落入坑、
  贴地/悬崖检测同步。ChunkManager 从"自有 map"改为 PatchState 读写者（防双份漂移），
  世界进入时 clearAll（与 raster.clearAll 同生命周期）。
- 验收 ⑨：坑心 surfaceHeightAt 下降 ≈ −D、坑外 Δ=0、isPatchedAt 世界查询正确。
  - `TerrainMaterial`/`WallMaterial`：`useVertexColor` 构造标志 + `varying vColor`、
    fragment `alb = albedoTex * vColor`（顶点色 = 乘性染色；指向 `vertexColors` 让 three
    注入 attribute color）。
- 验收（`scripts/__regionpatch.ts`，2 seeds 全绿）：circleCells 覆盖/角点/跨 chunk/负坐标/幂等；
  深度场坑内满深/边界线 0、补丁区全补丁色（cell 内部顶点判定避开共享边界）、坡面插值连续
  （0→0.5D→D 值域 + 相邻采样差 <0.03 + 法线倾斜）；**真实子弹 footprint（circleCells R=0.6
  十字坑）坑心满深 ≥0.99D + 坑底/坡面顶点齐备（可见性回归）**；  主坑壁补丁色、顶沿 ∈ 原面−[0,D] 无错位；**壁覆写语义（④b）**：搜真实 flush 平面（噪声级
  同高）→ 补丁后整段剔除（36→0）；搜真实微小高台棱（0.0025~0.03m）→ **侧壁保留**（n=120
  全补丁色）；搜真实大台阶平面 → 壁保留且全补丁色 + 顶沿满深下降（n=96）——无空洞；
  **防 T 结细缝（⑦）**：补丁 cell 全 0.125m 细分（内部核 49 顶点）+ 平坦区同点无高度分裂；
  远离区壁多集逐位一致 [1,1,1]；同 overlay 重建逐位一致；seam 两侧深度收口 0 + 双侧壁保留补丁色。
  其余脚本（__weldclosure/__fbuild/__finestats/__mixededge 等）回归保持绿。
- 已知取舍：坑缘坡面宽度 = 1 coarse cell（1m smoothstep）；跨 chunk 的坑在 seam 处各侧深度
  收口为 0（seam 壁保留且补丁色 → 封死不悬空，但坑被 seam 分成两半的浅底形态）；
  补丁染色 = 乘性焦土（无自身法线/粗糙度变化；保留原 tile 细节）；lightmap 不重烘
  （沿用旧图；增量光线本就低频）。
