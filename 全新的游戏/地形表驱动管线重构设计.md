# 地形表驱动管线重构设计 —— 决策与几何分离

> 状态：设计稿 v2（2026-09-04）。针对 09-04 整合后地形管线暴露的混乱（两套后处理、
> UV 反推材质、先算后删补、cornerH 只写不读、裁决重复现算）做架构级重排：
> **数据 → 事实表（一次构建、全算死）→ 面决策（纯表驱动）→ 统一几何生成（物理=渲染同源）**。
> 本稿为**动工版**：含模块划分、签名骨架、规则细节与分阶段验收。
> 配套旧稿：《地图架构.md》《精修层与定型快照架构.md》《后处理地块索引层设计.md》（本文为其演进）。

---

## 0. 一句话

**地形创建不再"边算边改"：每 chunk 先构建一张完整事实表（块/面静态判定全算死），
后处理只把表翻译成生成指令，几何生成器按指令一次产出顶面、侧壁与物理（三者同源）。**

## 1. 动机（现管线问题，2026-09-04 诊断）

| # | 问题 | 后果 |
|---|------|------|
| 1 | 两套后处理并存：`PostProcess.ts`（渲染/物理用）vs `RefinementPostProcess.ts`（surfaceHeightAt→贴地/烘焙用）；开关/常量/哈希/求值位置全不同源 | 贴地与渲染是两座山；角色踩的地形 ≠ 看到的地形 |
| 2 | 墙材质/归属靠 UV 反推（wallRef/quadEdgeDir 假设"uv 块=发射块"） | 动材质即坏索引；反推无兜底静默错 |
| 3 | 侧壁先全量生成 → skip 剔除 → 重建补墙 | 逻辑链长，反复出现缺口/错墙/双墙/材质混 |
| 4 | `cornerH` 角高场只写不读，各处仍逐点现算 `cornerCell` | 白算 + 无统一高度源 |
| 5 | `isBevel` 双实现；回落路径产 dummy 假称逐位一致 | 语义漂移，索引不可全信 |
| 6 | 索引 `materialId` 全 0、缺 visualDrop | 表不可用于侧壁判据 |
| 7 | 死代码/半死代码多（旧薄壳、buildPostRenderTop、无引用配置常量、三份方向表…） | 认知负担、回归面大 |

## 2. 目标架构与模块划分

```
┌─ 数据层（不动）───────────────────────────────────────────────┐
│ generateChunk → ChunkData（RasterMap.chunks 存储）              │
│ chunkSource = refineChunkSource(...)（per-chunk 精修源，缓存）   │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼ 阶段 A：角高场
┌─ cornerH（一次算好）──────────────────────────────────────────┐
│ buildCornerField(src, cx, cz) → Float32Array(60·60·4)          │
│   = 现 buildChunkFinal 的角高部分（米格 cell 四角、cell 视角）   │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼ 阶段 B：事实表（一次构建、全算死）
┌─ FaceTable.ts ────────────────────────────────────────────────┐
│ buildFaceTable(src, cornerH, seed, cx, cz) → FaceTable          │
│   = FaceCell[225]（§3）+ cornerH 引用 + seed                     │
│   输入只需：src + cornerH —— 不再需要墙缓冲                       │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼ 阶段 C：面决策（纯表，零几何）
┌─ FaceDecision.ts ─────────────────────────────────────────────┐
│ decideTop(table)   → TopCmd[3600]（coarse/fine 标记+弧带参数）   │
│ decideWalls(table) → WallCmd[≤900]（flat/arc/none + tileId）     │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼ 阶段 D：统一几何生成（一次成型）
┌─ ChunkGeometry.ts ────────────────────────────────────────────┐
│ buildChunkGeometry(table, topCmds, wallCmds)                    │
│   → { top, walls } 合并顶点/索引（含法线/uv/颜色）                │
│   → mergeTerrainPhysics 语义内建：输出一份 trimesh              │
└──────────────────────────────┬─────────────────────────────────┘
                               ▼
      ChunkManager：建表/决策/生成一次调用链 → mesh + 材质 + 物理挂载
```

新文件（4 个，均在 src/services/map/）：
- `FaceTable.ts` —— 表结构与构建（取代 BlockFaceIndex 大部分职责）
- `FaceDecision.ts` —— 表 → 顶面/侧壁指令
- `ChunkGeometry.ts` —— 统一几何生成（顶面+侧壁+合并）
- `TerrainQuery.ts` —— 统一贴地/烘焙采样（取代两套 height 接口，§6）
其余按 §10 退役/收敛。

旧文件退役映射见 §10。`BlockFaceIndex.ts` 退役（其查询职责并入 FaceTable/TerrainQuery）。

## 3. 事实表数据模型（已定案 2026-09-04）

> 每地块一条记录：**1 顶部 + 4 侧壁（五方向）**。侧壁各自标 弧边/坡面/硬边；
> 墙记录「从顶往下多长」并带保底；顶/侧材质默认同 tile、侧壁可单独改。

```ts
interface FaceTable {
  cells: FaceCell[];        // 225 条
  cornerH: Float32Array;    // 引用阶段 A
  seed: number;
}

interface FaceCell {
  id: number;
  role: TileGenRole | "";
  h: number;                // 逻辑高
  hBase: number;
  topTileId: number;        // 顶部材质（默认本块 tile）

  top: {
    materialId: number;     // 运行时单独覆写槽（默认 = topTileId）
    corners: Float32Array;  // 引用 cornerH 中本块 5×5 角（16 个 1m cell 的角点）
  };

  sides: [FaceSide, FaceSide, FaceSide, FaceSide];  // 0=+x 1=-x 2=+z 3=-z
}

interface FaceSide {
  kind: "bevel" | "weld" | "cliff";   // 弧边 / 坡面(插值) / 硬边
  ruling: "weld" | "cliff";           // kind 溯源
  isBevel: boolean;                   // kind==bevel 的判定输入
  logicalDrop: number;                // max(h-邻h, 0)
  visualDrop: number;                 // 视觉落差（cornerH 判）
  neighbor: FaceCell | null;          // 同 chunk 引用；跨界 null → FaceQuery 兜底
  wall: {
    has: boolean;
    topY: number;                     // 墙顶主值
    depth: number;                    // ★ 从顶往下深 = max(落差, WALL_MIN_DEPTH)
    spans?: number[];                 // [0..1] 沿边分段有无墙（半墙情形，P2 定稿）
  } | null;
  sideTileId: number;                 // 侧壁材质（默认 = topTileId，可单独改）
}

/** 跨界/未建表回落：仅 id/role/h/ruling 现算可信，判定字段恒空 */
interface FaceQueryResult extends FaceCell { resolved: boolean }
```

**规则（全部构建期算死）**：
- `kind`：weld 边 → "weld"；cliff 且 (platform 高 → ground 低, BEVEL_EPS 内) → "bevel"；其余 cliff → "cliff"。
  弧边侧向有 weld 邻边的撤销规则照旧（唯一实现，落在此处）。
- `visualDrop`：用 cornerH 取该边两侧 4m 端点视觉高差（高侧-低侧）；`wall.has = visualDrop > EPS`（或逻辑落差）且该侧是更高侧。
- `wall.depth`：`max(视觉落差, WALL_MIN_DEPTH)`；`topY` = 高侧视觉顶主值。
- `spans`：4m 边内分段（每米 1 段）有无墙；半墙（weld 交叉角）时非整段。

## 4. 面决策规则（FaceDecision）

### 4.1 顶面 TopCmd（每 1m cell）
```ts
interface TopCmd { lx: number; lz: number; fine: boolean }
```
- `fine=true` 判定：该 1m cell 内任一点受 bevel 偏移（距 bevel 边 < BEVEL_R）→ 必细；
  或 pit/crack 命中（role/ruling + seed hash，确定性）→ 按概率细。
- fine cell 外扩 1 格（水密/无 T 结，见 §5.1）。

### 4.2 侧壁 WallCmd（每块每向）
```ts
interface WallCmd {
  cellIdx: number; dir: number;
  shape: "flat" | "arc" | "none";
  tileId: number;
  // arc 附加：弧端在哪、加密采样参数（沿边 t）
  arcEnd: "A" | "B" | "AB" | null;
}
```
规则（全部查表）：
- `shape=none`：`wall.has=false`。
- `shape=flat`：普通 cliff 墙 / weld 坡背后的直壁。直接生成：顶 `topY`、底 `topY-depth`。
- `shape=arc`：该面是 bevel 弧边的**相邻面**且弧带需圆滑到该面（相邻面 `kind∈{bevel,cliff}` 高侧有墙）。
  墙顶沿 4m 边在弧端按 `arcEnd` 加密采样（几何阶段算 yAt）。—— 即旧"rebuild 墙"，现在直接生成。
- 相邻 bevel 块扩散/对边规则：由表 `neighbor` 链与 isBevel 推导，**不需要再查 src**。

### 4.3 输出
`FaceDecision { tops: TopCmd[]; walls: WallCmd[] }` —— 纯数据，供 §5 消费。

## 5. 统一几何生成（ChunkGeometry）

### 5.1 顶面
- coarse cell：4 顶点（角 y = cornerH[cell 四角] + 该角偏移），对角剖分与现网格一致。
- fine cell：S×S 细分（S=8），顶点 y 沿网格采统一高度函数；**外扩 1 格使相邻 coarse/fine 交界无 T 结**（同现方案）。
- 法线：fine 用中差；coarse 朝上。
- uv：`(lx/N, lz/N)`。

### 5.2 侧壁
- flat 墙：沿 4m 边每米 1 quad；顶 y = topY（读取表主值），底 = topY - depth。
- arc 墙：沿边按 arcT（决策给出）分段；每段顶 y = 统一高度函数采样（弧线贴合顶面）；
  底 = topY - depth。两端弧带与相邻面闭环（端三角在此一次生成）。
- 每 quad：法线水平（法向该 dir）；uv = tileId 纹理坐标（tile 中心 + 高度方向比例）。

### 5.3 合并
- 顶面 + 侧壁合并为一份 `vertices/indices`（含法线/uv/颜色属性）→ **同一份数据同时建 mesh 与 trimesh**；
  无二次合并（现 mergeTerrainPhysics 职责内建）。

### 5.4 一致性
- 顶点高度一律来自**统一高度函数**（§6）——保证墙顶、顶面、贴地、烘焙同值。

## 6. 统一高度函数与采样（TerrainQuery）

现两套高度接口必须收敛为**一套**：
- `surfaceHeightAt`（旧 ppSurfaceHeight）与 `postSurfaceHeightAt`（新）→ 统一为
  `TerrainQuery.heightAt(raster, x, z)`（= 现 postSurfaceHeightAt 语义：表判据 + 角高场高度）。
- 消费方全部切换：角色贴地/WorldMode clamp、装饰贴地、烘焙（Worker + 主线程回退）、Minimap。
- 高度取值策略（动工前拍板，见 §12-D）：cornerH 为 f32。若全链统一走 f32 角高场插值，
  则顶面顶点、墙顶、贴地、烘焙全部同值且免现算；若保留 f64 现算，则只用于渲染精确度但
  表决策仍可用 f32（决策不敏感）。**推荐：渲染几何与贴地统一 f32 角高场**（视觉无差、
  速度大幅提升、同源天然成立）。

## 7. 生命周期与缓存

- FaceTable 随 chunk 构建，挂 RasterMap 缓存（替代现 blockIndexCache），随 chunk 释放。
- 装饰/标签/交互查询经 FaceTable/`TerrainQuery`；未建 chunk 回落（诚实空判定）。
- 无任何跨 chunk 几何后写；邻居只读 `cells`（跨界经 FaceQuery）。

## 8. 不变式与回归

| 不变式 | 内容 |
|---|---|
| 渲染=查询 | 任意 (x,z) 贴地采样 ≡ 渲染网格高度（同一高度函数） |
| 渲染=物理 | 合并产物同一顶点/索引 |
| 确定性 | 同 seed/chunk 输出逐位一致（表/决策/几何全纯函数） |
| 材质一致 | 任一立面材质 == sideTileId（校验器遍历断言） |
| 索引诚实 | 回落无假判定 |

回归：A/B 逐位探针（锁顶面→锁侧壁）、9 chunk 冒烟、[WALL-DBG] 类统计可保留到过渡期。

## 10. 新模块签名骨架（动工锚点）

export class FaceQuery {

// FaceDecision.ts
export function decideTop(table: FaceTable): TopCmd[];
export function decideWalls(table: FaceTable): WallCmd[];

// ChunkGeometry.ts
export interface ChunkGeometryOut {
  vertices: Float32Array; normals: Float32Array; uvs: Float32Array;
  colors: Float32Array; shade: Float32Array; indices: Uint32Array;
}
export function buildChunkGeometry(
  table: FaceTable, tops: TopCmd[], walls: WallCmd[], seed: number,

// TerrainQuery.ts
export function terrainHeightAt(raster: RasterMap, x: number, z: number): number;

// ChunkManager.finishStandardChunk 新链（伪代码）

## 12. 动工前必须拍板的开放决策

- D1（§4.2）：arc 面集合精确规则 —— "bevel 弧边相邻且 wall.has"是否覆盖全部旧 rebuild 扩散情形？P2 用探针对齐。
- D2（§3）：`wall.spans` 是否需要（weld 交叉角半墙出现频率）—— P0 统计后定。
- D3（§3.5 数据流）：buildCornerField 与 buildChunkFinal 的关系 —— 后者退役后角高场独立产出（含撕裂语义是否保留）。
- D4（§6，关键）：高度取值 f32 统一 vs f64 保留 —— **倾向 f32 + cornerH 插值全链统一**。
