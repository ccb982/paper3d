# 战斗与掉落管线架构

> 一行定位：**命中 = rapier 物理碰撞｜伤害 = modifier 结算链｜掉落 = 挂载在静态世界命中回调上的独立管线**
> 范围：瞄准 → 发射 → 飞行 → 碰撞分发 → 命中分类 → 伤害 → 反馈 → 掉落。
> 原则：谁拥有谁负责；战斗内部直接调用，表现边界走 EventBus；组合层回调注入世界细节。

---

## 一、击中检测架构（现状，代码即文档）

### 1.1 总览
```
输入(KeyJ/左键) → DesktopBinding.pressed.attack
  → WorldMode.consumeAttack()
  → firePlayerBullet()
        ├─ cameraRay() 直射方向（底）
        └─ aimRaycast() 辅助瞄准（命中目标则把弹道转指向目标落点）★预测用，不负责最终判定
  → executeAttack('projectile') → BulletManager.spawn（池 100）
  → BulletEntity 纯物理：球 r=0.08 / gravityScale=0 直线 / CCD 防隧穿 / restitution0.8 反弹 / 寿命2s
  → rapier 接触 → PhysicsWorld → EntityManager.dispatchCollision（按 userData=实体id）
        ├─ bases 查得到 → 实体命中 → hitFx + DamagePipeline + emit 'damage'
        └─ bases 查不到（地面/装饰=0 或未注册）= 静态世界 → hitFx + onGroundHit(x,y,z)
              └─ WorldMode 组合回调：地形扣除(playBulletImpact) + 水面波动(agitateWaterNear) + 掉落(spawnItemDrops)
  → 反馈：CombatDirector 听 damage/killed → FEEL 表(hitstop/时间缩放/镜头踢/音频钩子)；浮动伤害数字
```

### 1.2 瞄准（Targeting.ts）
- **双射分离**：`cameraRay` 纯相机方向打底；`aimRaycast`（Targeting.ts:37）做辅助瞄准——实体优先（`queryRay` 空间索引粗筛 + `raySphereHit` 3D 精细球判定）+ 物理兜底（`castRay` 落地面/墙），并有**遮挡校验**（墙后目标不算命中）。
- 命中目标是**预测**，决定发射方向；子弹是否真的打中，交给物理碰撞判，二者不互相替代。弹道直线 → 指即中，手感好。

### 1.3 发射（Attack.ts：统一攻击意图）
- `executeAttack` 分派三类意图：`projectile`（子弹池发射）/ `melee`（querySphere 范围瞬时 + 高度过滤±2m）/ `aoe`（落点延迟，预留）。
- 玩家与 AI 共用同一入口（`aiCtx.attack` 也是 executeAttack）——"谁发射都一样"。

### 1.4 飞行 & 碰撞（BulletEntity.ts）
- 纯物理实体（零渲染），绘制由 BulletRenderer 从速度快照完成（数据/视觉解耦）。
- 碰撞体积 = 小球 r=0.08 + CCD（防隧穿）；gravityScale=0 → 直线弹道；restitution=0.8 → **打地面会反弹**。
- 命中实体后**不销毁、继续穿透**（可一路打穿多个敌人，设计如此）。

### 1.5 碰撞分发（EntityManager.dispatchCollision）
- 关键设计：按 `userData = 实体 id`（非 rapier handle）查 `bases` → **杜绝 handle 复用误伤**。
- 地面/装饰物刚体（`kind:'ground'/'decoration'`，fixed）**没有 EntityBase 实例注册** → 落到 `onCollision(null)` 分支 = "命中静态世界"。

### 1.6 命中分类（BulletEntity.onCollision）
- 只在 `started`（接触开始）触发一次；同阵营直接忽略。
- 命中实体：`hitFx?.(other)`（一次性命中特效，实体槽/固定点两种挂法）+ `applyDamage` + emit `'damage'` + 控制台。
- 命中静态世界：`hitFx?.(null)` + `onGroundHit(x,y,z)`。
- ★ **组合层回调注入是本管线核心扩展点**：子弹实体不知道"地形扣除/水波动/掉落"的具体实现，只回抛坐标——掉落管线因此 0 侵入挂载。

### 1.7 伤害（DamagePipeline.ts）
- `resolveDamage` modifier 链：闪避 → 格挡 → 护盾 → 防御 → 暴击 → 下限/取整（顺序即语义，加机制=插链，不改核心）。
- `applyDamage`：未闪避且 final>0 → `target.onTakeDamage` → 扣血 → hp≤0 → emit `'killed'` + onDeath。
- 同层已有 CombatDirector（事件消费者）配 FEEL 规则表统一手感强度。

### 1.8 反馈（表现边界）
- `'damage'`：CombatDirector 按规则表做 hitstop/时间缩放/镜头冲击；WorldMode 投影浮动伤害数字。
- `'killed'`：击杀定格演出。
- 战斗数值逻辑内部直接调用；EventBus 只承载"表现/跨模块听众"——符合《开发说明书》③约定精神。

## 二、物品掉落管线（新增 2026-09-08）

### 2.1 挂点（一颗子弹撞地 → 一次结算）
```
BulletManager.onGroundHit = (x, y, z) => {        // WorldMode 注入的组合回调
  chunks.playBulletImpact(x, y, z);               // 地形扣除（既有）
  agitateWaterNear(x, z);                         // 水面波动（既有）
  spawnItemDrops(x, z);                           // ★ 掉落管线（新增）
};
```

### 2.2 环境探测 → 规则表（ItemDropPipeline.ts：纯函数，零依赖）
```
spawnItemDrops(x, z):
  env = {
    hasGround:  true,                                 // 回调即撞地，恒真
    hasWater:   watersPointWithin(x, z, 0.6) ≠ null,  // 0.6m 内水面（十字采样）
    hasCrystal: chunks.hasPropTypeNear(x, z, 'depleted_crystal', 2.2),  // 耗尽原石晶体
  }
  → rollDrops(env) → [{itemId, count}]
```

| 环境 | 物品 | 概率 | 每次数量 | 堆叠上限 |
|---|---|---|---|---|
| 地面 | `raw_rock` 固原岩 | 0.35 | 1~2 | 99 |
| 水面 0.6m | `ketone` 酮凝集 | 0.40 | 1~2 | 99 |
| 原石晶体 2.2m | `iron_grain` 异铁 | 0.55 | 1~2 | 99 |

### 2.3 "附近有原石晶体"的查询（ChunkManager.hasPropTypeNear）
- 装饰计划是**确定性**的（seed + chunk groupKey/blockTypes + surfaceHeightAt）→ 运行时重算即可还原位置，不必持久化、不建网格。
- 世界坐标换算：`wx = cx*60 + 本地x`（chunk 群中心 +30 / 装饰层 −30 抵消）。
- 对命中点所在 chunk 及邻环重算 → 距离 ≤ r 即判定存在。BOSS 四维空间返回 false。

### 2.4 背包落账 + UI
- `hasSpace` + `addItem('player', …)`：有空间直接直塞，满堆自动叠格（上限 99 由 items.json `maxStack` 约束）。
- `showPickupResult(itemId, ok, count)`：显示**物品名 × 数量**（"拾取了 固原岩 ×2"），背包满提示失败。
- `flashItemAndRefresh(itemId)`：背包打开时该格闪烁 + 面板实时刷新（bullet 掉落与 E 键拾取同走一格闪烁反馈）。

### 2.5 与既有生态的位置
- 掉落**直塞背包** + 提示 + 格子闪烁，与敌人死亡掉落（ItemBase 掉地上拾取，M4 阶段）是两条并行路径；若后续要"爆炸溅出实体掉落物"，把 rollDrops 的产出改走 ItemBase 生成即可，规则层不动。

## 三、架构评价（击中检测层）

### 合理之处（保留不动）
1. **判定分工清晰**：瞄准则（预测）与物理实碰分离，各司其职；辅助瞄准 + 直线弹道给出手感，物理判定兜底真实性。
2. **userData=实体 id 分发**：规避 rapier handle 复用误伤——这是会真实爆炸的坑，已提前防住。
3. **组合层回调注入**（onGroundHit / hitFx）：让子弹实体零认知于世界细节，掉落/水波/地形全是世界层的事——本次掉落管线就是该扩展点的成功验证。
4. **伤害 modifier 链 + FEEL 表**：机制与手感都是"加一行/加一个"，核心不动。

### 隐患与改进（按优先级）
1. **[低] BulletEntity.ts:154 动态 `import('../../core/EventBus')`** —— 每发命中都过一遍 Promise 边界；若未来拆包，首颗命中可能漏发 `'damage'`。EventBus 已是主包稳定模块，应改静态顶层导入（CombatDirector 即静态导入）。
2. **[中] DamagePipeline.resolveDamage("纯计算"契约背离)** —— 头注释写"不修改实体状态，纯计算"，但 `modifierShield`（DamagePipeline.ts:61）直接改了 `ctx.target.shield`。当前调用方每次新建 ctx 所以暂未炸，但契约脆弱（重入/复用会同点双扣盾）。改进：护盾吸收挪到 applyDamage 落账阶段，resolve 只读快照。
3. **[中] "静态世界"分支无类型区分** —— 子弹打中地面、装饰物、柱子全是 `onCollision(null)` → dent + 波动 + 掉落。当前与掉落需求恰好吻合（打晶簇=异铁）；但将来要细分（打墙不 dent、装饰物不吃地形扣除）时没有依据。留扩展位：dispatchCollision 对 userData=id 可反查实体 kind（ground/decoration），勿现在改。
4. **[中] 反弹 vs 命中语义** —— restitution=0.8 导致一发子弹可能多次撞地 → onGroundHit 多次触发 → dent/波动/掉落多次 roll（日志可见多次 [PATCH]）。若"一发=一次结算"是意图，需把结算表做成每发子弹一次性（记录已结算 id）；若"弹跳多次命中"是玩法（朝晶簇扫射刷材料），则属特性并应固化规则。**二选一，别模糊。**
5. **[低] 掩蔽信息**：瞄准的遮挡校验覆盖"预判"，飞行中撞中间物属正常物理——无问题，不必改。

### 结论
**击中检测架构骨架合理、扩展点充分，无需重构。** 三项小修最优先：静态导入 EventBus、修复 DamagePipeline 纯函数契约（护盾落账）、明确每发子弹的 onGroundHit 结算次数语义。掉落管线挂点（静态世界命中回调）与现有判定模型完全自洽。
