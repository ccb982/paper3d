# 地块与装饰架构 —— 更多地块 × 程序化装饰 × 地图装饰物

> 定位：《架构设计.md》8.0 地形管线的**扩展层设计**。不改变既有三域架构
> （数据域→烘焙域→运行时域），在每个域开受控扩展点。
> 原则延续：一切确定性派生自 hash2(seed, …)；重建不漂移；AO/明暗只存一处。
> 状态：2026-08-26 定稿（阶段一已实现并过回归基线）。

## 1. 地块基类 TileDef：属性自足

每个地块自己描述完一切，不依赖外部表解释自己：

```ts
class TileDef {
  id / key / label
  genRole: 'ground' | 'platform' | 'liquid' | 'pit'   // 生成器结构槽位匹配维度
  physics: { height, heightJitter*, walkable, lethal, flattenAtPorts }
  visual:  { baseHsl(唯一颜色真源), jitter, depression, patches?, borderLine?, streaks? }
  groups:  string[]    // 所属风格组（多对多）
}
```

内置清单（阶段一）：

| id | key | genRole | 组 |
|---|---|---|---|
| 0 | flat 平地 | ground | foundation |
| 1 | platform 高台 | platform | foundation |
| 2 | pit 坑洞 | pit | foundation |
| 4 | water 水域 | liquid | foundation |
| 3 | slope 预留 | ground | （无，永不抽中） |
| 10 | ice 冰面 | ground | crystal |
| 11 | ash_field 灰烬地 | ground | ashen |
| 12 | mud 泥沼地 | ground | ashen, overgrown |
| 13 | rock_platform 岩台 | platform | ashen, foundation |
| 14 | ice_platform 冰台 | platform | crystal |
| 15 | mossy_platform 苔台 | platform | overgrown |

⚠️ 装饰地块物理数值与其基础类严格一致（换皮不改结构 → 固定 seed 下
walkable/heights 逐位不变，回归基线成立）。

## 2. 组 = 风格包（多对多，不带契约）

- 一组内混装各种 genRole 的地块；地块可属多个组 → 相邻区域换组过渡自然
- **结构合法性由抽取时按角色过滤保证**，不由组契约保证：
  结构层说此处需要 platform → 只在该组 platform 成员里抽；筛空走回退链
- **回退链**：生效组 → 基石组(foundation，四角色齐装) → 全局默认块
- 选组粒度：每 chunk 一次（60m 一换，已定稿）；权重由 hash 抽，确定性
- 主打加成：本 chunk 各角色的「主打成员」权重 ×5（成片不碎）

内置组（阶段一）：

| key | label | 成员 |
|---|---|---|
| foundation | 基石（兜底） | flat/platform/water/pit |
| crystal | 霜蓝结晶 | ice×3, ice_platform×3, water, pit |
| ashen | 灰烬废土 | ash_field×3, mud, rock_platform×3, pit×2, water×0.5 |
| overgrown | 沃绿蔓生 | mud×2, mossy_platform×3, water×2, pit×0.5 |

## 3. 生成流程：六层管线（阶段一已落地）

```
L0 端口派生        不变（盐锁死，动一个数全世界重洗）
L0.5 特殊布局解析  registerSpecialLayout(seed,cx,cz)→ChunkLayoutPlan
                    replace=整块接管结构层；注册表空=行为同旧版逐位一致
L1 结构层          structureSlots：迷宫 → 角色槽位 PATH/WALL/LIQUID/PIT
                    只认槽位不认地块；输出 = 固定 seed 回归基准
L2 选组层          pickChunkGroup(seed,cx,cz)：每 chunk 加权抽组
L3 抽取层          fillSlots：角色→组内筛同 genRole 成员加权抽（含主打加成）
                    PATH 装饰斑块 pass：vnoise(低频)>τ 且距端口>1块
                    → 组内装饰平面地块成片替换（冰原/灰烬地成坨而非撒芝麻）
L4 行为落地        assignHeights 读地块 physics；梯田带按 platform 角色判定
                    repairConnectivity：端口格不得是不可走角色（对特殊布局兜底）
L5 输出            toChunkData 存最终 TileDef.id（下游零改动）
```

回归不变量（scripts/gen-regression.ts，486 chunk 对照已通过）：
- walkable[] / heights[] 逐位一致
- blockTypes 变化仅允许：平地→装饰平面(0→10/11/12)、高台→高台变体(1→13/14/15)

## 4. 特殊 chunk 与事件：只留接口位

| 接口 | 形态 | 状态 |
|---|---|---|
| 布局接管 | ChunkGenerator.registerSpecialLayout（地形自主设计） | ✅ 已落地（空注册表） |
| chunk 激活回调 | ChunkManager(opts.onChunkActivated)，每个 chunk 仅一次 | ✅ 已落地 |
| 事件状态注册表 | WorldEventRegistry（chunkKey→状态，天级生命周期） | ✅ 已落地（无事件内容） |
| 小地图图标 API | 事件立项时接 Minimap | 预留 |

铁律：
- 事件【选择】确定性（种子派生）；【过程/结果】运行时状态，不随 chunk 视觉陪葬
- 跨天保留与否由事件类型决定（默认天级；一次性剧情写 Session）

## 5. 装饰性纹理贴图（TileDecals，独立列表，阶段二）

- **独立注册表**（不是地块）：DecalDef{ key, groups[], placement{tiles?/hostRole/perChunk/scaleRange}, pattern }
- 与地块同构带组归属 → 组面板决定本 chunk 哪些贴图活跃；placement 决定长在哪
- **顺序**：地形生成完成后、渲染前调用 planChunkDecals(seed,cx,cz,blockTypes,groupKey) 散布（确定性 hash）
- **渲染**：阶段二并入 TerrainMaterial 的 shader 图案层——贴图 = 地块图案函数的叠加层，专属性天然成立
- 阶段一：仅契约 + 空规划（planChunkDecals 返回 []）

## 6. 实体地形装饰（TileProps，独立列表，阶段三）

- **独立注册表**：PropDef{ key, groups[], placement{tiles?/hostRole/perCellProb/scaleRange/sink/keepClear}, render:'instanced'|'billboard' }
- 有实体但属于地图一部分：**不进 EntityManager/空间索引/AI**；随 chunk 生灭
- **顺序**：地形生成完成后、渲染前 planChunkProps(...) 散布，然后渲染
- **渲染**：InstancedMesh（程序化几何优先：变形 icosahedron/棱柱簇…）；v1 无碰撞（挡人=walkable 标记或 host 扩展，显式第二阶段）；影子接 StaticShadows 时一并纳入
- 阶段一：仅契约 + 空规划（planChunkProps 返回 []）

## 7. 表现层：shader 优先，少纹理（阶段二）

```
每 chunk 两张小数据：
├─ 块 id 微纹理 15×15 R8（225 字节，Nearest）——shader 知道每像素站在哪种地块上
└─ 光照图 128² 继续烘焙（阴影/AO 需跨块邻域采样）

TerrainMaterial 片元：
  读 id → uniform 数组取该地块调色板/图案参数 → GLSL 程序化图案函数 → ×光照合成
```

- 现 albedo 256² 烘焙退役，抖动/斑块/描边/拉丝改写为图案函数库条目；Worker 只烘光照图
- 地块专属装饰直接写进各自图案函数
- JS/GLSL 哈希不必一致（纯视觉），但 baseHsl 两端同源（小地图/墙顶点色仍走 JS）

## 8. 分界铁律增补

```
⑥ 装饰只动颜色（albedo 域），零明暗语义——光照永远只来自 lightmap；
   发光类走 lightmap B 通道（预留位），禁止在 albedo 里画亮斑
⑦ 装饰/贴图/装饰物布局全确定性（盐隔离——改 A 层不许漂移 B 层）
⑧ 装饰物 = 静态地图部件：不进 EntityManager/AI；要挡人走显式第二阶段
⑨ Worker 内代码零 three 依赖（规划/图案计算全纯函数）
⑩ 装饰物几何共享（module 级缓存），chunk dispose 只销毁实例矩阵
```
