## 1. 地块基类 TileDef：属性自足

每个地块自己描述完一切，不依赖外部表解释自己：

```ts
class TileDef {
  id / key / label
  genRole: 'ground' | 'platform' | 'liquid' | 'pit'   // 生成器结构槽位匹配维度
  physics: { height, heightJitter*, walkable, lethal, flattenAtPorts }
  visual:  { baseHsl(唯一颜色真源), jitter, depression, patches?, borderLine?, streaks? }
  groups:  string[]    // 所属风格组（多对多）
}
```

内置清单（阶段一）：

| id | key | genRole | 组 |
|---|---|---|---|
| 0 | flat 平地 | ground | foundation |
| 1 | platform 高台 | platform | foundation |
| 2 | pit 坑洞 | pit | foundation |
| 4 | water 水域 | liquid | foundation |
| 3 | slope 预留 | ground | （无，永不抽中） |
| 10 | ice 冰面 | ground | crystal |
| 11 | ash_field 灰烬地 | ground | ashen |
| 12 | mud 泥沼地 | ground | ashen, overgrown |
| 13 | rock_platform 岩台 | platform | ashen, foundation |
| 14 | ice_platform 冰台 | platform | crystal（已挂 rock 材质，见 §7） |
| 15 | mossy_platform 苔台 | platform | overgrown |

| 17 | grass 草地 | ground | foundation, overgrown |
| 18 | wood 木板路 | ground | foundation, overgrown |

## 2. 组 = 风格包（多对多，不带契约）

- 一组内混装各种 genRole 的地块；地块可属多个组 → 相邻区域换组过渡自然
- **结构合法性由抽取时按角色过滤保证**，不由组契约保证：
  结构层说此处需要 platform → 只在该组 platform 成员里抽；筛空走回退链
- **回退链**：生效组 → 基石组(foundation，四角色齐装) → 全局默认块
- 选组粒度：每 chunk 一次（60m 一换，已定稿）；权重由 hash 抽，确定性
- 主打加成：本 chunk 各角色的「主打成员」权重 ×5（成片不碎）

内置组（阶段一）：

| key | label | 成员 |
|---|---|---|
| foundation | 基石（兜底） | flat/platform/water/pit, brick, grass, wood |
| crystal | 霜蓝结晶 | ice×3, ice_platform×3, water, pit |
| ashen | 灰烬废土 | ash_field×3, mud, rock_platform×3, pit×2, water×0.5, brick×2 |
| overgrown | 沃绿蔓生 | mud×2, mossy_platform×3, water×2, pit×0.5, grass×2, wood×2 |

## 3. 生成流程：六层管线（阶段一已落地）

```
L0 端口派生        不变（盐锁死，动一个数全世界重洗）
L0.5 特殊布局解析  registerSpecialLayout(seed,cx,cz)→ChunkLayoutPlan
                    replace=整块接管结构层；注册表空=行为同旧版逐位一致
L1 结构层          structureSlots：迷宫 → 角色槽位 PATH/WALL/LIQUID/PIT
                    只认槽位不认地块；输出 = 固定 seed 回归基准
L2 选组层          pickChunkGroup(seed,cx,cz)：每 chunk 加权抽组
L3 抽取层          fillSlots：角色→组内筛同 genRole 成员加权抽（含主打加成）
                    PATH 装饰斑块 pass：vnoise(低频)>τ 且距端口>1块
                    → 组内装饰平面地块成片替换（冰原/灰烬地成坨而非撒芝麻）
L4 行为落地        assignHeights 读地块 physics；梯田带按 platform 角色判定
                    repairConnectivity：端口格不得是不可走角色（对特殊布局兜底）
L5 输出            toChunkData 存最终 TileDef.id（下游零改动）
```

回归不变量（scripts/gen-regression.ts，486 chunk 对照已通过）：
- walkable[] / heights[] 逐位一致
- blockTypes 变化仅允许：平地→装饰平面(0→10/11/12)、高台→高台变体(1→13/14/15)

## 4. 特殊 chunk 与事件：只留接口位

| 接口 | 形态 | 状态 |
|---|---|---|
| 布局接管 | ChunkGenerator.registerSpecialLayout（地形自主设计） | ✅ 已落地（空注册表） |
| chunk 激活回调 | ChunkManager(opts.onChunkActivated)，每个 chunk 仅一次 | ✅ 已落地 |
| 事件状态注册表 | WorldEventRegistry（chunkKey→状态，天级生命周期） | ✅ 已落地（无事件内容） |
| 小地图图标 API | 事件立项时接 Minimap | 预留 |

铁律：
- 事件【选择】确定性（种子派生）；【过程/结果】运行时状态，不随 chunk 视觉陪葬
- 跨天保留与否由事件类型决定（默认天级；一次性剧情写 Session）

## 4.6 ★ 地图加载全流程（2026-08-27 整理；标准风格）

```
WorldMode.enter
  → raster = new RasterMap(seed)          # 统一空间层（纯数据）
  → entities = EntityManager(physics, raster)
  → chunks = new ChunkManager(scene, raster, groundHost)   # groundHost=EntityManager 适配
  → chunks.bootstrap(出生点)               # 数据环扩张 + 出生 3×3 强制构建

每帧 WorldMode.update → chunks.update(玩家xz, dt)
  ├ syncChunks：RasterMap.updateChunks（数据环扩张）→ 新增块入队 → processQueue（8ms 预算）
  └ sweepChunks：看门狗（0.5s 一拍：在途超时释放 / 空洞补请求）

构建一个 chunk（requestStandardBake）：
  ① planDecor：贴图 + 装饰物【全部放置完成】（确定性）→ 阴影体积打包
  ② 烘焙缓存查询（seed|cx|cz）→ 命中直接装配
  ③ 快照（3×3 原始数组拷贝）→ Worker（携带 propVolumes + decals）
     └ Worker 不可用 → 主线程同步烘焙（同一计算核心，输出逐位一致）
  ④ Worker 回传 RGBA → assembleChunkMaps（albedo装饰叠加层 + 光照图）

装配（finishStandardChunk）：
  ⑤ 位移平面几何 + UV（外观 UV = 块 id 微纹理同约定）
  ⑥ TerrainMaterial(albedo, lightmap, 材质配置)
     └ 材质配置 = buildTileRenderConfig(blockTypes)：
        块 id 微纹理（15×15 R8 Nearest）+ uMatBase/uMatSurface/uMatEmissive/uMatParams
  ⑦ ChunkWalls 断崖侧壁（顶点色）
  ⑧ buildDecorLayer → 装饰物网格层（对齐 chunk 角）→ 挂进 group
  ⑨ replaceChunk：换装（销毁旧视觉+旧物理）+ fixed trimesh 地面刚体 + 激活回调
  ⑩ createDecorColliders：装饰物 fixed cuboid 碰撞体（★ 必须在 replaceChunk 之后）

Boss4D 风格：buildChunkMesh 同步直建，同一装饰管线（贴图印进单纹理烘焙）。

渲染（WorldMode.render → renderer.render(scene, camera)）：
  片元：块 id → 材质函数分发（dirt/rock/moss…）→ ×装饰叠加层 ×光照图
        + 4×4 棋盘描边 + 镜面/菲涅尔/发光（表面属性）
```

**装饰物高度参与预渲染结构** —— 放置顺序：

```
requestStandardBake
  ① planDecor：贴图 + 装饰物全部放置完成（确定性，两份消费同一计划）
  ② 快照携带装饰数据进 Worker：
     - propVolumes（装饰物→球/柱遮挡体积 [x,z,y,r,h]，shadow≠none 才有）
       → 光照图 Pass B1.5 印入软影（沿太阳方向投影，头实尾虚）
     - decals → 印进 albedo（CPU 印章：speckle/blotch 图案）
  ③ 烘焙 → 装配 → finishStandardChunk 消费同一份装饰计划建 props
  缓存命中/同步回退路径：装饰计划确定性重算，结果一致
```

装饰物阴影 = 烘焙域（光照图内印入），不是实时阴影贴图；
参数经验：128² 光照图 0.47m/px，物理尺寸的影子会被双边模糊抹平到不可见——
印章刻意放大底宽 1.7×、压暗 0.7（美术向），并带浮点防御（perp2 微负→NaN 曾致影尾黑块，
已修）。运行时贴地阴影盘（shadow:'disc'）阶段三叠加时注意勿重复压暗。

## 5. 装饰性纹理贴图（TileDecalBase 基类体系，decor/TileDecalBase.ts）

```
TileDecalBase（基类 = 行为）
├─ 声明：groups（多对多）/ placement{tiles?/hostRole/density/scaleRange}
│        / pattern{fnId, params}
├─ ★ 烘焙：stampInto 基类统一实现——按 pattern.fnId 查【图案注册表】执行
├─ 图案注册表：registerDecalPattern(fnId, 印章函数)——加新图案=注册函数
├─ 库：registerDecal(实例)——加新贴图=注册实例

└─ 烘焙入口：applyDecalStamps → 各实例 stampInto → 印进 albedo
```

- **加新贴图 = 注册一个基类实例 +（新图案时）注册一个图案函数**，管线零改动
- 内置图案：speckle（碎屑斑点）/ blotch（污渍）；自定义走图案注册表

## 6. 实体地形装饰（MapEntityDecorBase 基类体系，decor/MapEntityDecorBase.ts）

```
MapEntityDecorBase（基类 = 行为）
├─ 声明：groups / placement / render / shadow / physics{type,radius,height}
│        / geometry
├─ ★ 物理：createColliders 基类统一生成 fixed cuboid
│    （可挡人/挡弹；半径/高度×scale；y=体积中心）
├─ ★ 阴影：toShadowVolumes 基类统一算烘焙体积
│    —— 碰撞与阴影共用同一体积（physics 单一数据源）
├─ 库：registerMapDecor(实例)——加新装饰=注册实例
├─ 规划：planChunkProps（坡度/地块/keepClear 过滤，纯函数）
├─ 渲染：registerPropRenderer + 内置 instanced（程序化岩石几何，共享缓存）
└─ 宿主：ChunkGroundHost 接口（模式层 EntityManager 适配；本层零 entity 依赖）
```

- **不注册实体基类**：不进 EntityManager 的基类体系/空间索引/AI——是"地图的一部分"
- 角色碰撞：kinematic 无物理响应 → CharacterBase.separateFromStatics 用
  PhysicsWorld.queryStaticObstacles（读 rapier 实际半宽）手动弹出
- 生命周期：碰撞体随 chunk 视觉替换/模式退出销毁（ChunkManager 管理）

## 7. 表现层：材质属地块 + 装饰独立叠加（2026-08-27 修正定稿）

```
TileDef.visual.material = { fnId, params }      ← 地块自挂材质
  ↓ 渲染（阶段二）
块 id 微纹理（15×15 R8，Nearest）→ 片元按 id 查材质
  → 调该材质的 GLSL 图案/表面函数 → 输出基色 + 粗糙度/镜面/菲涅尔/发光/动画

TileDecalBase（装饰纹理）                        ← 独立叠加层，不参与材质
  → 裂隙/小石子/污渍 = 表面点缀
```

**分工铁律**：材质决定"这块地是什么"（泥/砖/草/木/冰/水）；
装饰纹理决定"这块地上长了什么"（裂了/有碎石/有苔点）。装饰永远叠在材质之上。

**材质库**（TileMaterials.ts，已落地）：
- `registerTileMaterial({ fnId, label, params模板, surface{粗糙度/镜面/菲涅尔/发光/动画} })`
- 内置：dirt（泥）/ brick（砖）/ grass（草）/ wood（木）/ rock（岩）/ moss（苔）
- 加材质 = 注册定义 + 阶段二补 GLSL 函数；地块引用 fnId + 可覆盖 params（变体）
- 已挂载：flat→dirt、platform→rock、rock_platform→rock(粗粝变体)、ice_platform→rock(冰台变体)、mossy_platform→moss、brick→brick、grass→grass、wood→wood

**已废弃方向**：早期"装饰纹理并入 shader 图案函数"的说法作废——
装饰纹理保持独立层（现在就是独立注册表+印章），材质单独成库。

**每 chunk 两张小数据（阶段二）**：
```
├─ 块 id 微纹理 15×15 R8（225 字节，Nearest）——材质分发依据
└─ 光照图 128² 继续烘焙（阴影/AO 需跨块邻域采样）
```

- 现 albedo 256² 烘焙退役：基色由材质 shader 计算（无限分辨率），
  装饰印章迁入独立的轻量叠加层
- JS/GLSL 哈希不必一致（纯视觉），但 baseHsl 两端同源（小地图/墙顶点色仍走 JS）

## 8. 分界铁律增补

```
⑥ 装饰只动颜色（albedo 域），零明暗语义——光照永远只来自 lightmap；
   发光类走 lightmap B 通道（预留位），禁止在 albedo 里画亮斑
⑦ 装饰/贴图/装饰物布局全确定性（盐隔离——改 A 层不许漂移 B 层）
⑧ 装饰物 = 静态地图部件：不进 EntityManager/AI；要挡人走显式第二阶段
⑨ Worker 内代码零 three 依赖（规划/图案计算全纯函数）
⑩ 装饰物几何共享（module 级缓存），chunk dispose 只销毁实例矩阵
```

### 给地块写材质 shader 的流程（现在就可以做）

```
① TileMaterials.ts：registerTileMaterial({ fnId, label, params模板, surface })
 ② TerrainMaterial.ts：MATERIAL_GLSL 里加 GLSL 材质函数 mat_<fnId>（读 matP(id,i) 参数），
    并在 MAT_FN_INDEX 登记一行（fnId → 索引）；分发由 uMatFn[id] 自动路由，无需手写 id 分支
    ★ 新增地块 id 必须 < MATERIAL_SLOTS（=32）；超出需同步放大该常数与 GLSL 数组尺寸
③ Tiles.ts：地块 visual.material = { fnId, params? }（params 覆盖模板=变体）
④ 参数顺序 = 模板声明顺序（JS 打包与 GLSL 索引同序，勿乱）
⑤ 棋盘描边强度默认 0.16（borderLine=false 的水面为 0）；表面属性自动生效
```
