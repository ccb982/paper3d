# 敌人地形语义与偏好表设计（设计稿 v1 · 2026-09-21 · 代码未动）

> 定位：**敌人 AI 重做的表层权威稿**（L1 语义表 / L2 工件表 / L3 兵种偏好表 / urgency 圈 / 读时合成 / 指令与路径锁定）。
> 将来并入《敌人管线设计.md》总纲，替换其 §1 的语义来源。本文只定设计，不含实施。
> 前置共识（本次对话拍板）：
> - 语义**锚定舰船位置**、落地算一次（换落点才重算）；玩家只影响**工件**，不影响语义。
> - 战壕/掩体/墙**不进语义表**、**不参与寻路**（可走可爬），照常挡子弹。
> - 每个兵种用自己的处理手法把 L1+L2 合成**独属该兵种的攻↔防偏好表**。
> - 路径**锁定**：定下后执行期不重规划，只在白名单事件重算。

## 0. 总览

```
                    高度场（RasterMap / TerrainSampler）
                              │
              ┌───────────────┴────────────────┐
              ▼                                ▼
     L1 语义表（静态·舰船锚）          路径硬口径（坑/陡壁/水；非语义）
     高地/关口/低谷/迎背船坡/走廊/隐蔽…
              │
              │        舰船位置 ──→ urgency(d) 解析圈（不存表·软权重）
              │
              ▼
     L3 兵种偏好表（静态·每兵种一次处理）──┐
     每格：攻分/防分（两个并行，不互抵）    │
                                          ▼
     L2 工件表（动态·唯一持续修改）──→ 读时合成（查询时相加，不落表）
     战壕/掩体/墙：防护方向·防护分        Score(兵种,状态,格)
     （对玩家方向；建/拆/玩家动 → 更新）        │
                                               ▼
                              大队：锚解引用 + 意图 → SquadOrder
                                               ▼
                              队长：区块内按 L3 选格 → 分解 → 锁定路径
                                               ▼
                                       执行层（SteerPick 局部避让）
```

**三条纪律**
1. 玩家移动 → 只刷 L2；L1/L3 一行不动。
2. 工事（战壕/掩体/墙）永不参与寻路、永不触发重规划；爬墙走执行层。
3. 命令只从大队下发；跨队诉求走 `requestSupport/shareContact` → 大队裁决。

## 1. L1 统一地形语义表（静态·舰船锚）

### 1.1 用途
- 敌人 AI 的**唯一地形语义视图**（替代 `genRole` 那套"山谷/山坡"地理标签作为 AI 语义）；
- 消费方：L3 合成、工兵放置优化、偷袭路线、队长的守位/攻位选格；
- **不含人造物**（战壕/掩体/墙 → L2）。

### 1.2 语义类别（初版清单，可增删）

| 语义 | 判据（初值） | 典型价值 |
|---|---|---|
| 高地/制高 | 平滑 h 的局部极大或平台（`isPlateau`）+ 相对邻域高差 ≥1.2m | 观察、俯射、远程 |
| 低谷 | 平滑 h 的局部极小 | 隐蔽推进、低姿态集结 |
| 迎船坡 | 坡度 ≥坡阈 且 `n̂·d̂_ship > 0`（面向舰船） | 偏进攻（可俯射/冲正面） |
| 背船坡 | 坡度 ≥坡阈 且 `n̂·d̂_ship < 0`（背向舰船） | 偏防御（反斜面，被舰船方向地形遮挡） |
| 关口/隘口 | 可站宽度 ≤1 格 + 两侧高差 ≥1.5m（升级现有 W/K） | 卡口、易守 |
| 走廊 | BFS 连通可站带，宽度 2~4 格 | 编队通行、包抄廊道 |
| 开阔地 | 可站宽度 ≥4 格、无掩体特征 | 暴露、冲锋面 |
| 隐蔽接近 | 对舰船方向的高度场 LOS 遮挡连续格 | 偷袭路线 |
| 盲区/死角 | 舰船方向不可见格 | 待机、集结点 |
| 陡壁 | `dh > WALL_DH`（同现有口径） | 不可站（路径硬口径） |
| 水 | `role==='liquid'` | 可走（现状保留） |
| 坑 | `role==='pit'` 或 `h < -1.2` | 不可走（路径硬口径） |

> 方向项统一：`n̂` = 平滑后的下坡方向（`gradientInto` 给）；`d̂_ship` = 指向舰船的水平单位向量。
> 坡向示例（用户定调）：**面向舰船的坡面偏进攻，背对舰船的坡面偏防御**。

### 1.3 区块化（比 4m 格更大的语义块）

```
种子：梯度模 ≈ 0 的点（峰 / 谷 / 平台）
扩张：4 邻域 BFS，同类别 + |Δh| ≤ 0.75m + 坡度连续
收口：区块 < 3 格 → 并入邻块（或标中性）
输出：regionId · 类别 · 朝向(对舰船) · 面积 · 代表点
```

- 数据落 `per-cell`: `classId / regionId / aspect(n̂·d̂_ship) / h / slope / width / choke / losToShip`；
- 区块表：`regionId → {类别, 代表点, 面积, 朝向, 邻接}`（供大队取"目标语义块"）。

### 1.4 更新节拍
- **落地一次**；**换落点（舰船挪窝）→ 全量重算**；
- 地形被挖/建墙**不触发**（人造物走 L2；坑洞只走路径口径）；
- 成本：73×73 ≈ 5.3k 格 + BFS，一次量级 ms，可接受。

## 2. L2 工件表（战壕 / 掩体 / 墙；动态·唯一持续修改）

### 2.1 字段

```
Work = {
  id, kind: 'trench' | 'cover' | 'wall',
  几何: 位置(线/矩形) · yaw · 尺寸,
  防护: 防护向量(对玩家) · 防护分 · 顶面可站(可攀),
  状态: 占用 · hp/存活 · version,
}
```

### 2.2 更新（这是"玩家变化复杂"的唯一落点）
- 建/拆/被毁 → **即时**更新；
- **玩家位置变化 → 重算"防护方向/防护分"**：节流 2~5Hz 或玩家位移 > 3m；
- 只更新**最近小范围内**的工件（空间哈希取邻域，不全表扫）。

### 2.3 与寻路/移动的关系（用户定调）
- **完全不参与**寻路代价与阻挡：战壕、掩体、**墙**一视同仁；
- **允许爬墙**：复用现有 `CharacterBase` 攀爬（顶住可攀工事 `walkableTop`，`CLIMB_HOLD` 后 `beginClimb` 自动翻上）——**执行层的事，不动路径**；
- 工事"不挡路径"≠"不挡子弹"：**照常挡子弹**（掩体存在的意义）；
- 因此"墙挡路/新建筑挡路"**不是**重规划事件（详见 §7）。

## 3. L3 兵种偏好表（静态·每兵种一次处理）

### 3.1 合成公式（形态）——攻/防**两个并行分**

```
L3[兵种][格] = { atk, def }      // 两个独立分，互不抵消
atk = wA·(n̂·d̂_ship)            // 方向主轴：迎船坡 → atk↑
    + Σ_k wA_k · 语义k(格)       // 高地/关口/走廊/隐蔽…
def = wD·(-(n̂·d̂_ship))         // 背船坡 → def↑
    + Σ_k wD_k · 语义k(格)       // 反斜/关口/高地/盲区…
```

- **很多地形两用**：高地、关口、走廊往往 `atk` 与 `def` **同时高**——由状态在读时决定取谁（§5），不在表里二选一；
- 每个兵种一套 `(wA, wD, wA_k, wD_k)` + **专属特殊规则**（"独有的处理手法"）；
- 静态：落地一次算全表；也可**按兵种首次出现懒算**；
- 语义与权重的具体值 → 调参面（后续 RTS 观测器扫参）。

### 3.2 各兵种处理手法（初版矩阵）

| 兵种 | 主取语义 | atk↑ | def↑ | 特殊规则 |
|---|---|---|---|---|
| 盾 | 关口/走廊/迎船坡 | 迎船坡、关口、走廊 | 关口、走廊、掩体后 | 宽度大优先；站前沿；两用地形先攻后守 |
| 突击 | 隐蔽接近/低谷/迎船坡 | 隐蔽接近、低谷、迎船坡 | 背船坡（临时） | 沿推进轴压上；接受低掩体 |
| 远程 | 高地/盲区/背船坡 | 高地、俯射位 | 高地、反斜、盲区 | 俯射 LOS + 距离带 [0.5R,1.05R]；有掩体加成 |
| 工程 | **工事位优化**（见下） | — | — | 不选"蹲位"，选"放工事最优格" |
| 后勤 | 盲区/走廊 | — | 盲区、走廊 | 限制在前线后方；远离接敌 |
| 飞行 | 不读地面 L3 | — | — | 独立空中层，只读目标 |

**工兵放置优化（"工事立在哪里效果最好"）**：
```
工事价值(格) = 地形控制力(关口/高地)
             + 覆盖(俯射推进轴/舰船方向的路段)
             + 隐蔽(对玩家不可见/反斜面)
             - 暴露(玩家火力可达)
按兵种施工规则排序取 Top，且满足推进阶段（逐步向前）
```

### 3.3 攻防的空间锚（回答"啥位置算进攻/防御"）
- **主轴 = 舰船方向**：迎船坡/近船正面 = 进攻位；背船坡/反斜面 = 防御位；
- urgency 圈（§4）只做软偏置，不参与攻防定义。

## 4. 紧急度 urgency（舰船距离圈·不存表·软约束）

```
urgency(x,z) = smoothstep 型：d_ship 越小 → 越高
   （R_inner / R_outer 可调；连续，不分硬档）
```

- **零存储**：舰船位置已知，查询时 `hypot` 现算 O(1)；
- **不强制**：只作权重/偏置（大队节奏、选块加分、推进意愿），不是硬门槛；
- 与态势函数分工：`p`（时间节律+挑衅）= 时间维；`urgency`（舰船距离圈）= 空间维；
- 随舰船锚生灭（换落点自动变），不写进 L1/L2/L3 任何表。

## 5. 读时合成（不重建任何表）

```
// 状态选择"取攻还是取防"：w ∈ [0,1] 由状态/态势 p 给出（0=全防，1=全攻，中间=混合）
Score(兵种, 状态, 格) = lerp(def, atk, w_状态)           // 静态底：两个并行分在此合成
                      + Σ 工件加成(格, 玩家位置, 状态)   // 动态项（空间哈希邻域）
                      + 状态权重(状态, 格)               // urgency 软项等
```

- 两分并行的直接好处：巡逻/集结等**中间状态可同时参考攻防**（如 0.5/0.5），不会被"相减"抹平；

- 玩家满地图跑 → 只有第二项变；L1/L3 零改动；
- 新掩体建成 → 读表自然生效（"AI 施工写回自己的价值地图"成立，且不重建）；
- 消费者：
  - **大队**：选目标语义块（配合 urgency/p）；
  - **队长**：区块内按 Score 选具体格（目的地）；
  - **寻路**：按状态读分做代价项（见 §7：只在**重新寻路**时读，不每帧重算）。

## 6. 决策链与指令格式（定稿形态）

### 6.1 指令
```
SquadOrder = { anchor, intent, ttl }
  anchor = { kind:'区块', regionId } | { kind:'小队', squadId }
  intent = 攻 | 守 | 守卫 | 集结 | 偷袭
  // 紧急度不入令：谁读谁按舰船距离算
```

### 6.2 锚解引用（只在大队层）
- 大队把 `kind:'小队'` 解析为"该小队**当前所在语义区块 + 朝向**"，**下发到队长的永远是位置型目标**；
- 队长**永不查别的队**（避免帧序依赖与跨队耦合）；
- **事件驱动重发**（低频 1~2Hz 或事件，非持续查）：
  - 锚跨区块 / 位移超 N 米；锚小队 并队·换队长·阵亡·失联；意图完成；TTL 到期；
- 解引用时附带**锚精度/是否休眠**（L0~L3 位置精度不同）→ 队长据此收放守圈（贴近守卫 ↔ 区域守卫）。

### 6.3 被保护小队的诉求（防"命令成环"）
- 不开放跨队指挥：保护队**不听**被保护队；
- 被保护队有需求 → `requestSupport / shareContact`（已有黑板）→ **大队裁决** → 由大队加派/改派。

### 6.4 队长分解矩阵（"怎么守卫"由队长回答）

| 意图 | 队长干什么 | 主要载体 |
|---|---|---|
| 攻 | L3 进攻分选推进格；盾前/远程后/突击侧翼；接敌与开火策略 | `UnitDirective` + `taskX/taskZ` |
| 守 | L3 防守分选反斜/关口格；沿区块前沿摊开、面向威胁、控火 | 同上 |
| 守卫 | 环绕区块/锚布岗（护卫弧线、4m 间隔）、指定朝向/警戒/轮换 | `taskX/taskZ`（已有成员位置列） |
| 集结 | 区块内收敛到集结点、整队形 | 编队槽位 |
| 偷袭 | L1"隐蔽接近"格分段走；`fireOnArrival`/禁火；延迟发动 | `roe` + 分段路径 |

## 7. 路径锁定与重规划白名单（治"左右抽风"）

- 一条路**定下即锁**：执行期只做 `SteerPick` 局部避让（保留"禁止向量合成"原则），**不重算整条路**；
- **允许中断（重算）的白名单**：
  1. 目标/意图变更（大队换令）；
  2. 地形被挖断（路径上出现坑/陡壁）；
  3. 长时间无进展（阈值如 2s 位移 < ε）；
  4. TTL 到期；
  5. 攻/守状态切换（读表口径变了）。
- **工事永不触发重规划**（战壕/掩体/墙不挡路；爬墙走执行层）；
- 白名单之外：**零重规划**——这是"路径别改来改去"的硬保证。

## 8. 节拍与性能预算

| 项 | 时机 | 量级 |
|---|---|---|
| L1 全量 | 落地 / 换落点 | 5.3k 格 + BFS，一次 |
| L3 全量 | 落地 / 换落点（或按兵种懒算） | 兵种数 × 5.3k，一次 |
| L2 更新 | 建/拆/毁 + 玩家动（节流 2~5Hz，仅邻域工件） | 稀疏，小 |
| 读分 | 查询时 | O(1) + 邻域工件数 |
| urgency | 查询时 | O(1)（hypot） |
| 寻路 | 仅白名单事件 | 现状口径 |

- 不新增每帧全表扫描；L1/L3 静态是硬边界（"语义一次"的兑现）。

## 10. 待确认与验收

**待确认（本轮未拍）**
1. "守" 与 "守卫" 是否同义？本稿按**不同**处理（守=阵地防守；守卫=保护区块/对象、环绕布岗）。
2. L1 语义清单增删（尤其"开阔地/盲区"是否要）。
3. L1 是否**完全无视**人造地形改动（本稿默认：无视；坑洞只走路径口径）。
4. L1 替换 `TerrainScore` 的语义来源、`genRole` 保持不动——默认通过。

**验收指标（将来实测）**
- 早期：队伍在外圈高地/关口占位，不挤船；工兵逐步向前施工；
- 总攻：压向舰船 6~38m 战壕带（与旧实测口径一致）；
- 坡向正确：迎船坡 atk↑、背船坡 def↑；高地/关口**两分皆高**（抽样可视化）；
- 掩体建成 → 相关格选位即时变化（未重建表）；
- **重规划次数/分钟显著下降**（左右抽风指标）；
- 帧成本 ≤ 现状（L1/L3 不在帧内重算）。
