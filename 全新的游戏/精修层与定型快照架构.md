# 精修层与定型快照架构 —— 统一产出的最终地形真源

> 定位：承接《地块与装饰架构.md》六层管线的 **L6 精修层（定型段）**，把《地形边缘
> 裁决与视觉面架构.md》第五铁律「对外纯净、下行全消费」落实为**统一定型快照**。
> 命题：L0–L5 的地块高度 / 材质 / 属性分配完之后，**所有剩余**（边过渡裁决、角点
> 插值、顶面几何、断崖墙、地形物理、烘焙、贴地）由精修层**统一产出**，下游一律
> 只读精修层产物，各自零现算。
> 状态：2026-08-30 定稿（输入/输出大改方向 + 物理分层产出决策）。

---

## 0. 为什么是大改（双向）

现状（改前）精修层只是 `refine()` 包装的一个**查询接口**（`edgeFinal`/`blockAt`），
几何在每个消费方各自现算：ChunkSurface 用 `cornerHeight` 逐角拼网格、ChunkWalls
自行扫描墙、bakeCompute 本地重构 `sampleSurface`、RasterMap 再包一层贴地采样。

目标（改后）：**输入、输出都要大改**——

| | 现状 | 目标 |
|---|---|---|
| **输入** | 消费方各自建立 BlockSource（17×17 表 / 快照源 / 惰性查询） | 精修层直接收「以 chunk 为单位的原始块数据」（每块 `id`=材质+属性、每块 `heights`=高度），内部统一建源 |
| **输出** | 一个可查询的 BlockSource，几何在消费方各算 | **统一定型快照**（per-chunk 单产物），下游只读这一份 |

## 1. 定位与职责边界

精修层是**最终地形唯一真源**：L4 高度分配之后的那一层，负责把"地块级数据"变成
"定型的地形本体"，并统一产出下流全部消费所需的定型产物。

精修层**是**（职责内）：
- 输入原始块数据，内部建几何源
- 边过渡裁决（weld/cliff）——唯一判点不变式 `edgeFinal`
- 角点插值 / 视觉面高度（weld 坡 / cliff 板）
- 顶面几何 + 断崖墙
- **地形物理数据**（顶面 + 墙合并成一份，可直接建 trimesh）
- 统一产出 **per-chunk 定型快照**

精修层**不是**（职责外）：
- ❌ 实体 / 装饰碰撞——那是下游管理器的事（见 §3 物理分层）
- ❌ 材质渲染 GLSL / 贴图 / 装饰物放置
- ❌ 玩法逻辑

---

## 2. 输入：以 chunk 为单位的原始块数据

精修层的输入不再是消费方各自拼的 BlockSource，而是**直接喂原始块数据**：

- 逐块 `id`（→ TileDef，携带材质 `visual.material` 与属性 `physics`/`walkable`/`edgePolicy`）
- 逐块 `heights`（L4 高度分配结果）
- 本 chunk 生效 `groupKey`（调色板等外观消费）

> 即 `ChunkData`（`blockTypes` + `heights` + `groupKey`）作为精修层的输入面。
> 精修层内部统一建立几何源，替代消费方各自建 `blockAt`/逐角查询。

---

## 3. ★ 物理分层产出（关键决策，2026-08-30）

**物理不是一层，是分两层产出，最后才合并交给物理管理器。**

```
地面地形物理（第一次产出）
  └─ 精修层产出：顶面 trimesh + 断崖墙，合并成一份【地形物理数据】
        （只吃精修层定型快照；不含任何实体/装饰碰撞）

实体 / 装饰碰撞（第二次产出）
  └─ 下游各自的管理器（EntityManager / ChunkGroundHost / 放置逻辑）自行产出
        （防碰撞体、可放置物、装饰物 cuboid 等；★ 不属于精修层）

         ▼ 合并
      最终物理数据
        ▼
      物理管理器（PhysicsWorld，唯一碰 rapier 的地方）
        ▼
      与实体交互
```

- 精修层**只管第一层**（地形物理体）。
- 第二层（实体/装饰碰撞）**不进精修层快照**——它们会随放置/移动变化，由各自的
  物理相关管理器自己维护，绝不经经精修层。
- 精修层一旦定型，地形物理就定岁了；之后实体怎么放、物理怎么交互，是下游的事。

---

## 4. 输出：统一定型快照（per-chunk 单产物）

精修层对**每个 chunk** 产出一份唯一快照，涵盖：

| 产物 | 内容 | 消费者 |
|---|---|---|
| 角点高度场 | 每米格四角高度（weld = 2×2 max，cliff = 自持） | 顶面网格、贴地 |
| 边裁决表 | 每边 weld/cliff（唯一判点 `edgeFinal`） | 墙、可遍历性、烘焙 |
| 顶面几何 | 顶点/索引/UV（剖分与 PlaneGeometry 一致） | 渲染、物理 |
| 断崖墙几何 | 墙三角形 + 顶点色 | 渲染、物理 |
| **地形物理数据** | 顶面 + 墙合并的一份（见 §3） | 物理合并 |
| 材质分发依据 | 块 id → 材质（外部消费） | 渲染、装饰 |

快照为 **per-chunk**（世界无限流式、所有消费者都是 chunk 级）。

**下游全读快照、零自算**：顶面网格 / 墙 / 地形物理 / 烘焙 / 贴地一律只读精修层
快照，不反向摸规则链、不复算边裁决、不复刻几何公式——唯一判点不变式 `edgeFinal`
仍由精修层持有。

- 《地块与装饰架构.md》定 L0–L5（分配层）+ 装饰层；本文件承接 L6 精修层定型。
- 《地形边缘裁决与视觉面架构.md》第五铁律原述"精修层对外只暴露定型产物"；

  下游不再依赖独立默认引擎源文件。
