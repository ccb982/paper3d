# 精修层过渡模型重构设计 —— weld/cliff 过渡与顶点一致性

> 定位：承接《精修层与定型快照架构.md》（L6 定型段）与《地形边缘裁决与视觉面架构.md》
> 的**过渡模型重写**。现状把"硬切换(cliff) + 插值(weld)"做成了"0.35m 硬台阶 +
> 1m 陡坡 + 补缝墙阵"，体感烂完。本文给出新的**几何定义**：顶点一致性不变式、
> 可配斜坡宽度、对角幽灵拉高根除、墙只断崖不发缝。
> 状态：2026-08-30 架构讨论稿（决策已拍板，未动代码）。
> 决策记录：① 坡宽可配、默认 2m；② β 带宽保持 0.35；③ 对角拉高彻底清除；
> ④ 首轮只出本文档。

---

## 0. 现状根因（烂在哪三层）

| # | 根因 | 代码位 | 后果 |
|---|------|--------|------|
| 1 | **角点高度没有一致性不变式**：`cornerHeight(base,V)` 是"以某块为基准"的函数，同一顶点 V 从邻块查回不同值 | Refinements.ts:156 | 顶点存在两个合法高度 → 缝 → 被迫用 SEAM_EPS=0 到处补墙 |
| 2 | **坡宽不可配**：weld 只有"低侧 1 列被 2×2-max 拉高"一种形态 | Refinements.ts:182 | 档差 2.2m 塞进 1m 坡 = 65°，坡内沿还触发补缝墙，"过渡≈没过渡" |
| 3 | **对角幽灵拉高**：2×2 max 把"只对角相接"的高块也计入 | Refinements.ts:182 | 看不见的架空隙 + 墙阵 |
| 4 | **意图层是空壳**：`planRefinements` 恒空、`hBase` 无人喂 | Refinements.ts:276 | 层内一堆"等一个永远等不到的输出"的死接口 |

**结论**：不是常数调得差，是**几何定义理不清**。要根治，必须重定义"过渡"的几何语义。

## 1. 新模型总览：同一张高度场，cliff=撕裂、weld=传导

```
旧：每条 cell 以"自家块"为基准，自己算自己的四个角
   → 共享顶点各算各的 → 必然不一致 → 补墙掩盖

新：地形顶面本质 = 每米格 cell 四角高度 → 三角剖分，你唯一要定的就是角点高度。
   cliff 与 weld 不是两种计算路径，而是同一张高度场上的两个运算符：
     cliff = 撕裂：切断高度场，两侧各持自家高度 → 竖直落差面（墙来补）
     weld = 传导：把一侧高度沿斜坡带传到另一侧，两侧在边界共享同值
   → 共享 weld 边两边的 cell 取到必然相同的值 → 构造上水密（watertight）
   → 补缝墙机制整体退役（仅保留断崖真墙）
```

### 1.1 不变式（本次重构的灵魂，替代旧的"空精修 ≡ 旧世界逐位一致"）

旧式的"与 max-2×2 逐位一致"与"根除对角拉高"**互斥**（旧式的高块对角
必然被 max 计入）——所以本次是**契约变更**，旧回归基线正式作废，换成：

| 不变式 | 含义 | 验证方式 |
|---|---|---|
| **顶点一致性** | 同一世界顶点，任一相邻 cell 读到的值**浮点位相等** | 新回归脚本：遍历共享边两端，断言两侧相等 |
| **无幽灵拉高** | 对角高块不经真 weld 边缓冲，不得抬高此角 | 回归脚本：找"对角高块 + 相邻边皆非 weld"案例，断言角 = 自持 |
| **墙 = 断崖真墙** | 发墙仅由「裁决 cliff 且两侧表面确有落差」触发；weld 永不发补缝墙 | 墙计数回归（墙三角数不再随对角/坡沿膨胀） |
| **空斜坡 ≡ 旧平面** | 恒定高块（全平地）顶面与旧 PlaneGeometry 逐位一致（此条保留） | 现有 surface-regression 的空斜坡用例 |

> ⚠️ 合约变更确认：旧文档《地形边缘裁决与视觉面架构.md》§6 的"weld 与旧公式
> 逐位对照"不再适用；β=-1 恒 weld 的"应急回退"也将**不是**旧世界——它只是
> "全斜坡新几何"。任何依赖逐位一致的旧脚本需按上文新脚本表迁移。

## 2. 裁决（不变）与斜坡（全新）

### 2.1 裁决仍是布尔：`weld | cliff`

规则链、TileDef.edgePolicy、移动层 stepHeight、唯一判点 `finalRuling` **全部不变**。
weld/cliff 只决定过渡方式，不再隐式决定几何形态。

### 2.2 斜坡宽度（本次新增的一维可配）

每条 **weld 边**携带斜坡宽度 `w`：

- **w ∈ {1, 2, 4} 米（离散，= 整 cell 列数）。理由：坡末必须精确落回 hLow，
  且与相邻平地共享的顶点刚好是 hLow → 坡内沿不出墙、不产生小数位缝。**
- **默认 2m**（对 2.2m 档差 ≈ 48°，有坡感又不吞掉方块）；
  低端机/密集地形可全局降为 1；4=整块缓坡（梯田观感）。
- **可配层级**（由粗到细）：
  1. 全局常量 `WELD_RAMP_CELLS = 2`（Refinements；一条线改全画面）
  2. `TileDef.physics.edgePolicy`（'smooth'/'hard'，语义不变；宽暂时只走全局）
  3. `planRefinements` 逐边 `EdgeOverride.rampWidth`（未来加规则时扩，第一版可留接口）
  4. 注释约束：`w` 必须能整除块宽（4 / w ∈ 整数）→ 只允许 1/2/4。

### 2.3 斜坡剖面（沿边常数，垂直边线性）

```
边 E：(低侧块 L, 高侧块 H)，裁决 weld，宽 w 米。
以深入 L 的方向为 x（0 在共享边，w 在坡脚）：
  坡面高 s(x) = hH - (hH - hL) * (x / w)      // 0≤x≤w，线性
  x < 0（H 侧）：恒 hH（crest 沿整条边的 z 方向不变）
  x ≥ w（L 侧深处）：恒 hL
沿边方向（z）恒高 —— crest 是沿整边的一条等高线，端点由顶点规则收口（§3）。
```

- **坡是低侧块顶面的一部分**：L 的多条 weld 边各自在自家坡带上成形，交汇处由
  顶点规则（§3）取一致高度，由 cell 角点插值缝合 → 不打架。
- 斜坡边上 H 侧**不降**：H 的顶面自持 hH，坡的 crest 贴齐 H 顶 → 共享沿边

无缝（这是"weld"唯一的承诺：**共享 weld 边两侧沿整边（含端点）零落差**）。

## 3. 过渡模型核心：撕裂面 + 传导场，两级合成

### 3.1 治法（总纲）

**角点取值不再依赖 cell 归属：所有角点由"层级判定"一手包办。** 三个纯函数
构成完整取值链，`cornerCell` 是唯一消费入口，`vertexHeight/rampProfile` 是它的
两个支撑：

```
rampProfile(w, t)   —— 斜坡剖面采样（低侧块顶面的蒙皮带）
vertexHeight(V)     —— 顶点场缝合值（base 无关，块边界/块角上的"两点合一点"）
cornerCell(C, V)    —— cell 角点取值（唯一消费入口，三层规则合成）
```

### 3.2 硬边界（cliff = 撕裂），怎么做

裁决照旧（`edgeRuling/finalRuling` 一字不改）。几何语义收紧成一条：

```
cliff 边 E（低侧 L，高侧 H）：
  L 侧所有 cell 沿 E 的角  = L.h   （自持，零插值）
  H 侧所有 cell 沿 E 的角  = H.h   （自持）
  → E 上同时存在两个高度，构成竖直落差面 |H.h − L.h|，这就是"墙"本身。
```

- 墙顶 = 各自面高，墙底 = `min(hBase(L), hBase(H)) − WALL_EPS`，法线朝低侧。
  weld 边永不发墙。
- 台阶感保留 β=0.35：小块差判 cliff → 0.3m 干净台阶；移动层 `stepHeight` 同常量
  可当楼梯爬——"方块感"就是这条线，不是几何 bug。
- 退化保护：若 `|H.h − L.h| = 0`（edgePolicy hard 但等高）→ drop=0 → 不发墙，
  结果为纯平面。

### 3.3 插值（weld = 传导），怎么做

**斜坡 = 低侧块顶面的一段"蒙皮"**，不是"拉高一列 cell"。这是与旧 65° 陡坡
一刀两断的关键。

```
weld 边 E：(低侧 L, 高侧 H)，带斜坡宽 w ∈ {1,2,4} 米。
以深入 L 的方向为 t（t=0 在 E 上，t=w 到坡脚）：
  剖面 s(t) = hH − (hH − hL) · t/w      // t∈[0,w]，线性
  沿 E 方向（i 轴，4m）不变 → crest 是等高线
  t ≥ w → 恒 hL（与 L 深处平面对接，无墙无痕）
  坡在 L 内部成形，吃的是 L 自己的顶面；H 侧顶面自持 hH，crest 贴齐 H 顶
```

**坡带内 cell 的角点取「剖面采样」，不取顶点场**——这就是旧版的病根：旧实现
只有"边界那排 cell 被拉到 hH，其余 cell 落回 hL"，cell 内只下沉一次 → 陡。
新实现按 w 排 cell 逐排采样 s(t)，坡度按 w 摊平（默认 2m ≈ 48°）。

> **有意简化声明：斜坡只做线性剖面，不做光滑曲线（余弦/贝塞尔/二阶项均不用）。**
> 理由：① 顶面渲染本就是三角形线性插值，线性剖面在 1m 网格上精确复现，零细分成本；
> ② 保留地形"方块感"，曲线坡反而与整作画风格违和；
> ③ 剖面维数降到一维（只随 t），顶点缝合/回归验证都简单。
> 若未来要"平滑坡面"，改动点只有 `rampProfile` 一处，不牵动 `cornerCell` 判定结构。

### 3.4 合成规则（cornerCell 三层判定，唯一消费入口）

```
cornerCell(cell C ∈ 块 B, 顶点 V):
  1. 若 V 处、属于 B 的任一边段裁决 == cliff
       → 返回 B.h                        ← 撕裂面自持优先，压过一切
  2. 否则若 V 落在 B 的某条 weld 斜坡带内（0 < t < w，B 为其低侧）
       → 返回 max(各重叠带 s_E(t))        ← 剖面采样，重叠带取更高者
  3. 否则（V 在块边界 / 块角 / 坡带外）
       → 返回 vertexHeight(V)             ← 顶点场缝合值
```

```
vertexHeight(V):            // base 无关 —— 谁查都同值，水密的构造基础
  候选集 = ∅
  for 环绕 V 的每块 B (≤4):
    若 B 在 V 处所有入射边段均裁决 weld（corner-open，含"无外部块"角块）
      → 候选集 ∪= { h(B) }
  for V 处每条裁决 weld 的边 E=(a,b):
     候选集 ∪= { crest(E) = max(h(a), h(b)) }    ← E 的端点即 crest 终点
  return max(候选集 ∪ {0})
```

**为什么这三层天然解决全部旧问题：**

| 旧症状 | 新模型里的根因消除 |
|---|---|
| 对角幽灵拉高 | 对角块只有真斜坡传导（corner-open 或经 weld 边 crest）才抬角；否则被自己硬边挡住，进不了候选集 |
| weld 边缝 + 补墙 | cornerCell 走 vertexHeight（规则 3），同一顶点谁查都同值 → 构造上水密，SEAM 补墙退役 |
| 1m 陡坡 | 剖面按 w 排摊平，默认 2m；w=4 更缓 |
| 坡内沿又补墙 | t=w 处 s 精确落回 hL，与平地共享顶点同值 → 无边墙 |
| 坡带端头三角切角 | 端头 cell 的角自动进 vertexHeight 聚合，与周围地块缝合，无需特殊处理 |

### 3.5 斜坡带端面（"坡的侧面"如何收口）

weld 坡带两端（沿边方向）连接 crest(hH) 到坡脚(hL)：
- 端面恰是 **cliff 边**边界 → 端面 = 该 cliff 应有的竖直墙顶随 vertexHeight（两侧
  blockOpen 侧的表面值），与坡带端线吻合 → 自动覆盖，无需斜坡专用侧墙。
- 端面是 **weld / 同高块** → 邻块顶面延展过来同高 → 无墙、无缺口。

→ 结论：**不需要"斜坡专用侧墙"、不需要补缝墙；所有竖立面对 = 断崖墙本身。**

## 4. 墙生成与物理（精修层统一产出，不变量绑定）

### 4.1 发墙条件（重写）

```
旧（2026-08-30 基线）：任何「表面顶 − 低侧 hBase > SEAM_EPS(=0)」都补竖直墙
新：仅当该 cell 边界两侧块的共享边裁决 == 'cliff'，且两侧表面确有落差
    （高侧表面 > 低侧 hBase + EPS）时，才发墙（真断崖）。
weld 边：永不发墙（共享边零落差是 weld 的契约；坡内沿与顶点已保证连续）。
SEAM_EPS 机制整体退役（保留为断言：任何 weld 边触发发墙 = 回归失败）。
```

- 墙顶仍沿边界跟随 `cornerCell`（两侧表面值 = 撕裂面各自自持 / 坡带剖面，§3 一致）。
- 墙底 = 两侧 `baseHeightOf` 较浅者 − WALL_EPS（同现状，堵死不悬空）。
- 法线朝低侧；去重沿用"每边界仅高侧发一次"。

### 4.2 输入输出接口（与《精修层与定型快照架构.md》§3 对齐，不新增层）

```
buildChunkFinal(src, cx, cz, size)        → ChunkFinal         # 角点高度场 + 顶面
buildChunkSideWalls(...) / buildChunkWallBuffers(...) → 墙 raw # + mergeTerrainPhysics
```

- `ChunkFinal` 增加可选 `edgeRulings` 表（每米格边的裁决）或由 cornerH 派生——
  第一版由 cornerH 自动足够（墙判据需要边裁决，WallBuildCtx 已提供裁决路径）。

## 5. hBase 双语义激活（意图层从空壳变实）

新几何下 `hBase` 第一个真实消费方就是斜坡与墙：

| 用途 | 语义 |
|---|---|
| **斜坡的底** | 坡面沿 x 升降时，底恒 `hBase` → 坡带厚度保持、侧面不悬空（`hBase` 缺省 = h 时，浅坡不露出底，天然正确） |
| **墙的底** | 两侧 `hBase` 较浅者 − WALL_EPS（现状，配合新墙判据只出现在真断崖） |
| **意图输出** | `setHeight(bx,bz,h,hBase)`：削顶/垫底造"厚板""薄壳""下沉台"——这是 planRefinements 首批内容 |

`planRefinements(seed)`（全局 Map）→ **`planRefinements(seed, cx, cz)`（per-chunk）**，
签名对齐"输入 = 原始块数据（id/heights/groupKey），输出 = per-chunk 意图"的既定形态。

## 7. 回归与验证（重写最大风险的控制）

1. **现成回归保持**：`walkable/heights/blockTypes`（L4 产出）零改动 →
   `scripts/gen-regression.ts` 应逐位通过（不动 L0-L5，只动 L6 几何）。

6. 阶段性评审：先单 chunk 陈列馆（`?group=crystal` 测试地图）肉眼核查
   台阶/斜坡/断崖三观感，再全量跑回归。

  是斜面，侧面（沿 i 方向的两端）若邻块也是坡/墙，厚度不齐——列为意图层后期内容。
- **cornerCell 规则 2 的"在斜坡带内"判定**：需要查 B 的四邻 weld 边、算 t、再
  决定取剖面 vs 顶点缝合。实现时建议把"带内格点集"预计算进 ChunkFinal（一次算
  好，避免每角每帧重查）；与 §1.1 顶点一致性回归脚本配套。
```
