# 第一部分 地形生成与几何（表驱动）

## 0. 一句话

**每 chunk：Pass1 定块属性（高度/材质/边 kind）→ Pass2 定邻居敏感细节
（topEdgeY/depth/邻接标记）→ 检验 → FaceBuild 直接产出渲染 + 物理（同一份数据）。
顶面与侧壁共享同一张 fine 细分图 → 壁顶沿与顶网格边界折线逐段同位，
weld 坡脚/bevel 弧带处几何完全闭合。**

## 1. 动机与取代对象

旧管线（《地图架构.md》时代的 buildChunkFinal + buildChunkWallBuffers +
PostProcess/RefinementPostProcess 双后处理 + BlockFaceIndex/wallRef 面索引，2026-09-05 已整段删除）问题：

| # | 问题 | 后果 |

| 2 | 墙材质/归属靠 UV 反推 + wallRef 链 | 动材质坏索引、补墙反复出错 |

## 2. 全链流程总览

```
RasterMap 数据环（无界确定性生成；heights/blockTypes/groupKey）
   │  chunkSource(cx,cz)：refineChunkSource 应用 per-chunk 意图（裁决 override）
   ▼
① 建表（全区各 chunk 独立两遍；Pass1 全区先完成）
   Pass1（单块可定）：id/role/h/hBase/topTileId + 4 向 kind（hard/weld/bevel）
        + ruling 溯源 + leftKind/rightKind（同块垂直邻边回填）
   Pass2（邻居敏感）：topEdgeY / calcDepth / depth / oppKind / arcNeighbor /
        topWeldDirs（跨界邻居由 src 同公式现算，无需邻表）
   ▼
② 检验 checkTable（不通过不放行；生产默认跳过，回归脚本调用）
   ▼
③ 创建 FaceBuild（读表 + src，直接产出几何缓冲）
   buildTopGeometry  顶面：coarse 1m / fine 0.125m（bevel 弧带 ∪ weld 非线性 cell）
   buildWallGeometry 侧壁：每边恒壁；壁顶沿 = 顶网格边界折线同位节点列
   ▼
④ 装配 ChunkManager.finishStandardChunkTable
   顶面 mesh（TerrainMaterial）＋侧壁 mesh（WallMaterial）＋装饰层
   物理 trimesh = 顶面 + 侧壁同一份缓冲合并（一次产出，无二次合并）
   ▼
⑤ 查询/贴地（现状：仍走旧查询路径 ppSurfaceHeight —— 开放项 P1，§8）
```

烘焙（albedo/lightmap，Worker）与装饰放置发生在②前（与旧管线相同的
异步烘焙节拍），表驱动只替换「像素就绪后的几何装配」；装饰照旧由
`planDecor → buildDecorLayer/createDecorColliders` 消费（§7.2）。

## 3. 表数据模型（与代码逐字段一致）

```ts
// FaceTable.ts
interface FaceTable { cx: number; cz: number; cells: FaceCell[]; }   // 225
interface FaceCell {
  id: number;                       // tileId（0 兜底）
  role: TileGenRole | "";           // tile 语义角色
  h: number;                        // 逻辑高（顶面基准）
  hBase: number;                    // 面板底高（= 壁底埋深参考），缺省 = h
  topTileId: number;                // 顶材质（默认本块 tile）
  top: { materialId: number };      // 可改槽（当前未消费，预留）
  topWeldDirs: number[];            // ★ 语义标注：坡进顶方向（几何经 src 直接
                                    //   采样获得，本字段供推理/查询层，当前无消费）
  sides: [FaceSide, FaceSide, FaceSide, FaceSide]; // 0=+x 1=-x 2=+z 3=-z
  idx: number;                      // 块局部下标 lbz*15+lbx
}
interface FaceSide {
  kind: SideKind;                   // "hard"(默认) | "weld" | "bevel"
  oppKind: SideKind;                // 共享边对侧块朝本块的边属性（成对标注）
  leftKind: SideKind;               // 沿边小端(p0)邻接垂直边属性
  rightKind: SideKind;              // 沿边大端(p1)邻接垂直边属性
  ruling: EdgeRuling;               // 裁决溯源 weld|cliff
  topEdgeY: number;                 // 该边顶面视觉高主值（本块视角，逐段 max）
  calcDepth: number;                // 计算落差量（≥0；平地 = 0）
  depth: number;                    // 恒壁深 = calcDepth + WALL_MIN_DEPTH
  arcNeighbor: boolean;             // 两端邻边任一 bevel（弧带伸入 → 需弧顶墙）
  sideTileId: number;               // 侧壁材质（默认 = topTileId）
}
```

**方向/端点约定**（勿混）：
- dir：0=+x、1=−x、2=+z、3=−z（`DIR4`）；`oppositeDir(dir) = dir^1`（同轴反向）。
- `edgeEndAdjacentDirs(dir)`：dir<2 → [3,2]，否则 [1,0] —— 沿边小端 p0/大端 p1 邻接的
  垂直边方向（p0 = 沿边坐标小端：x 向边 = z 小端，z 向边 = x 小端）。
- 「弧边左右邻边」= 与弧边**垂直**的两条邻边（dir^2 与 (dir^2)^1 语义），用于 bevel 否决。

**kind 语义（三态平起平坐，hard 默认）**：
- `hard`（默认，立墙硬边；含主动声明/显式覆写 forceHard / edgePolicy='hard'）；
- `weld`（坡）：裁决为 weld 的边 —— 低侧块顶面沿坡带爬向高侧 crest；两侧都标 weld；
- `bevel`（弧边）：精修层形态 —— 圆角几何由创建函数统一处理；成立条件含
  「左右邻边均非 weld」否决（防弧带与邻边坡面交角漏洞）。

**常量（FaceTable/FaceBuild 定义）**：
| 常量 | 值 | 含义 |
|---|---|---|
| WALL_EPS | 0.05 | 墙存在/埋深容差 |
| WALL_MIN_DEPTH | 0.3 | 每壁恒有保底深度（防 0 高墙/破面） |
| BEVEL_EPS | 0.05 | bevel 判据高差容差 |
| BEVEL_R | 0.3 | 弧带半径（FaceBuild，精修层形态） |
| WELD_RAMP_CELLS | 4/3（块宽 1/3） | weld 坡带宽度（Refinements，可逐边覆写） |
| FINE_S / FINE_D | 8 / 3 | fine 细分 = 0.125m |
| WELD_FINE_EPS | 0.03 | weld 非线性 cell 判据（1m 网格直线 vs 真坡面） |
| SLIT_EPS | 0.004 | 混合边细缝判据（见 §6.2） |

## 4. 两遍建表

### 4.1 Pass1 —— `pass1Build(src, cx, cz, forceHard?)`

每块四向 `kindOfSide(src, bx, bz, dir, forceHard?)` 判定链：
1. `forceHard?(bx,bz,dir)` 命中 → **hard**（显式覆写通道）；
2. `finalRuling(src,…) === "weld"` → **weld**（插值 = 显式 opt-in：
   edgePolicy smooth/hard、liquid/pit 无条件焊、确定性 30% 大落差产坡 override
   —— 全部收敛在 Refinements.finalRuling 唯一判点）；
3. 本块 role=platform 且邻 ground、邻 `h ≤ 本h − BEVEL_EPS`、ruling=cliff、
   且**左右邻边均非 weld** → **bevel**（弧边）；
4. 其余 → hard。

`leftKind/rightKind`：全部 kind 定完后回填（同块垂直邻边），供 Pass2 与创建用。

### 4.2 Pass2 —— `pass2Build(table, src)`

每块每向，把 4m 边按 **4×1m 段**逐段现算再合成主值：
- `topEdgeY` = 4 段中本视角（`viewTopAt` = surfaceHeightCore 本块视角）顶的最大值；
- `calcDepth` = 有墙段 `max(0, 本侧顶 − (lowBase − WALL_EPS))` 的最大，
  `lowBase = min(邻侧顶, 两侧 hBase)`；
- 有墙段判据：`cell.h > nbH || 本侧顶 > 邻侧顶 + WALL_EPS`；
- `depth = calcDepth + WALL_MIN_DEPTH`（**每边恒壁**，平地也有保底 0.3）；
- `oppKind`：同表直取 `nb.sides[dir^1].kind`；跨界按 src 对邻块对侧判 kind；
- `arcNeighbor = leftKind === "bevel" || rightKind === "bevel"`；
- `topWeldDirs`：`side.kind === "weld" && 邻 h > 本 h` 的方向（坡爬入本块顶）。

跨界邻居：Pass2 内 `cellAt` 只查本表，出界按 `src.blockAt` 同公式现算
（无界共享源 → 无需邻居表；`FaceQuery`/`TableProvider` 为预留的跨 chunk 表查询
接口，当前装配未调用）。

## 5. 检验 —— `checkTable(table)`

| 规则 | 说明 |
|---|---|
| 恒保底 | `|depth − (calcDepth + WALL_MIN_DEPTH)|` 须 ≈ 0 |
| bevel 左右邻非坡 | bevel 边左右邻边（`edgeEndAdjacentDirs`）任一 weld → 报错 |
| 左右端标注一致 | `leftKind/rightKind` 与邻边实际 kind 复核 |
| 材质默认一致 | `sideTileId === topTileId`（可改槽默认值一致） |

输出 `errors[]`（限 24 条）+ `stats`（kind 分布 / calcSides / 两侧组合 pairStats /
bevelCount）。生产装配不强制调用（放行门槛在回归脚本层执行）。

## 6. 创建函数 —— FaceBuild（读表 + src，一次产出渲染/物理）

### 6.1 顶面高度函数

- `surfaceHeightCore(src, 视角块, x, z)`：高度场基源（硬边界基面 hB + 本块 weld 边
  interpEdge max 合成）。**视角块 = 查询点所属块**，必须显式传，不得 floor 自推
  （撕裂角语义：同一格点从不同块视角可不同值）。
- `topYView(table, src, 视角块, x, z)` = surfaceHeightCore + **bevel 弧带内缩**：
  视角块存在 bevel 棱且点到棱的垂直距离 `d < BEVEL_R` 时，
  `y −= BEVEL_R − √(2·BEVEL_R·d − d²)`（圆角剖面向内收）。
- `topYAt` = 视角自推版（查询便利）。

### 6.2 顶面 fine 细分图 —— `topFineCells(table, src)`（顶面与侧壁共用）

1m cell 的网格边是直线；凡真实面在该 cell 内不满足「线性可表」就必须
0.125m 细分，否则网格边与真实面（以及贴它的壁）错位。标记来源两类：

- **bevel 弧带 cell**（`cellBevelFine`：cell 距 bevel 棱 < BEVEL_R）→ 外扩 1 格
  （**写独立数组**；原地扩散会级联传染，已踩坑）；
- **weld 非线性 cell**（`cellWeldCurvFine`）：仅候选「本块有 weld 边 且 cell
  落在某 weld 棱坡带（距棱 < rampWidth）」的 cell，做 5 点检验 —— 中心 + 4 边
  中点的真实高 vs 网格三角形线性预测（对角剖分 01-10），偏差 > WELD_FINE_EPS
  → fine。命中 = 坡脚棱/双坡角脊穿过该 cell；
- 随后 **逐边扩张 `weldOut`**（不是整格外扩）：对每个与 fine 相邻的 coarse cell，
  在其共享边的 8 个 fine 节点上采样真实坡面对 1m 弦求差，偏差 > SLIT_EPS →
  并入 fine，迭代至稳定（≤16 轮）。块边界边跳过（由墙封，见 §6.4）。
  这一步消除「细缝」：fine 侧 0.125 折线与 coarse 侧 1m 弦在弯曲共享边上的
  错位（曾表现为坡面上横/竖细缝，实测残留 ≤ 4mm 不可见）。

结果缓存于 `WeakMap<FaceTable, Uint8Array>`（同一表顶/壁两函数只算一次）。
coarse 1m 与 fine 0.125 的分界不影响水密：两种 cell 的顶点互不共享（index
soup），各自线性 —— 共享边双方都直线时必然重合，弯曲边由上方规则保证
两侧同 cadence。

### 6.3 `buildTopGeometry` —— 顶面

- coarse cell：4 角（`topYView`）一 quad，法线 (0,1,0)，三角形对角
  (0,0)-(0,1)-(1,0)/(0,1)-(1,1)-(1,0)（即 01-10 对角线，与 `sampleSurface`
  插值剖分一致）；
- fine cell：9×9 = 0.125m 顶点，高度 `topYView`，法线中差（2·step 标定）；
- uv 按整 chunk 归一（供 tileId/纹理采样），与旧顶面约定一致；
- `topTriCount` = 顶面三角数（合并物理时区分用途）。

### 6.4 `buildWallGeometry` —— 侧壁（每边恒壁）

每块每向生成壁条，深度语义 = 表 depth：
- **顶沿 = 顶网格边界折线同位节点列**：沿边每 1m span 属于一块本块侧 1m cell
  （`dirEdgeCells` 从 fine 图取该 4 cell 标记）；cell fine → 该 span 8×0.125m
  子节点，coarse → span 两端节点。逐节点 `top = topYView(本块视角)` —— 与
  顶网格边界顶点**同位同值**，故每段壁顶 = 顶网格对应边段（闭合由构造保证）；
- 底沿 = `min(本节点顶, lowBase − WALL_EPS − WALL_MIN_DEPTH)`，
  `lowBase = min(邻视角两节点顶的最大, cell.hBase, nb.hBase)`（埋入低侧基底以下，
  任何视角不见破面）；weld 边壁从 crest 一直挂到低侧基底 → 坡面侧壁完整；
- uv = 所属 tile 中心（侧壁材质默认本块 tile），顶点色/明暗为占位（shader 调）；
- 绕序朝外：dir1(−x)/dir2(+z) 采样方向朝内，索引翻转（2026-09-04 修正）；
- bevel 弧带相关边因 fine 图自动获得 0.125 拼弧（旧 SEG=8/32 双档已废除）。

**闭合论证**：顶面每条边线 = 网格边折线（coarse 直线或 fine 折线）；壁顶沿 = 同
节点列同值 → 逐段重合；壁底埋深不穿帮；块边界线两侧 cell 视角不同造成的撕裂由
各自壁条覆盖（壁 = 高侧从其 crest 挂到低侧基底以下）。回归：
`__weldclosure.ts`（900 边/块壁顶 vs 网格边逐点对差，6 chunk × 3 seed = 0 开口）、
`__mixededge.ts`（混合边错位 >5mm 采样 = 0）。

### 6.5 物理与渲染同一份数据

`finishStandardChunkTable` 把 topG + wallG 顶点合并、索引偏移后直接
`replaceChunk → createGround`（trimesh）—— 渲染 = 物理 = 同一缓冲（碰撞=所见
不变式）；无墙缓冲中间物、无 wallRef、无 UV 反推。

## 7. 装配与生命周期

### 7.1 标准流程（默认启用）

```
requestStandardBake(cx,cz)
  ├─ planDecor（装饰先于烘焙：贴图/装饰物阴影进快照）
  ├─ Worker 烘焙 albedo/lightmap（缓存命中跳过）
  └─ finishStandardChunk
       └─ finishStandardChunkTable（表驱动，本架构；旧后处理分支已删）
             buildFaceTable(src) → buildTopGeometry + buildWallGeometry
             → TerrainMaterial(顶) + WallMaterial(壁) + buildDecorLayer
             → 物理合并 → replaceChunk → createDecorColliders
```

表随 chunk 构建（buildFaceTable 一次），随 chunk 释放；无跨 chunk 持久状态。

### 7.2 装饰/烘焙（未变，消费同一份 decor 计划）

装饰贴图/装饰物在烘焙前放置（`planDecor`），高度采样经 `postSurfaceHeightAt`
（= 旧查询面，见 §8）；物理装饰碰撞体在 replaceChunk 后补建（顺序约定：先换地形
后建装饰碰撞，防旧体误销毁）。测试地图/地块名标注层照旧。

### 14.10 ★ 剔除+打补丁（R+P）——子弹撞地轻量方案（已实现）

- 定调（2026-09-05 用户拍板）：不用 deform 下沉，改为「区域内材质剔除 + 统一补丁」——
  子弹命中区域（垂直投影与水平圆相交的 coarse cell 集）顶面/侧壁统一挖成补丁，
  补丁区域边界即 3D 区域边界，边界外原样。
- 语义落位（含用户两轮修正：坑缘坡面插值 + 坑底不悬空 + 补丁全权负责内部）：
  - **深度场（逐顶点，世界函数）**：`PatchOverlay.depthOf(wx,wz)` = 坑内满 `PATCH_DEPTH`，
    「四方向射线法」：沿 ±x/±z 共边逐个 cell 外走，遇未补丁（含跨 chunk 出界）即坑口线，
    取点到该线距离的最小值，向内 1m smoothstep 坡降 → 坑口线深度 0（与原地面 C⁰ 连续）。
    ★ 只计共边方向：对角仅共享角点的未补丁格不参与距离 → R=0.6 的小十字坑中心可达满深
    （若按任意相邻格取矩形距离，小坑中心最大只有 0.5D，游戏里几乎不可见——已修并加验收）。
    顶面每顶点 y = topYView − depthOf（coarse 四角/fine 全网格采样；
    fine 法线中差重算 → 坑缘坡面法线正确倾斜；coarse 斜坡面暂保持 (0,1,0)）。
  - **坡面即坑的侧壁**：坑不是一个竖直台阶，而是一个平滑凹陷；坡面（含坑内整个顶面）全用
    补丁色 →「坑的侧壁材质依旧属于补丁」。
  - **坑内隔断壁剔除（补丁全权负责内部）**：恒壁只在 4m 块边存在；两侧 cell 都补丁的壁段
    **仅当两侧表面在壁线处数学级同高（|差| < WALL_FLUSH_EPS=0.002m，浮点噪声级）**才整段
    剔除 → 连贯凹陷。★ eps 曾取 0.02 → 毫米~2cm 的微小高台棱被误删（用户实测：微小高差
    地面补丁后侧壁消失）；任何可见高差（≥几毫米）壁段**必须保留并补丁化**——顶沿 = 原顶面
    − 深度场（世界函数两侧同减 → 台阶差保持），否则把崖壁抽掉 = 打出空洞（void，同日实测
    修复）。坑缘壁（补丁↔原样交界）顶沿=原地面（边界线 depth=0 → 坑底经由坡面落地，不悬空），
    并染补丁色。
  - **防 T 结细缝（补丁 cell ∪ 外扩 1 圈强制 fine 细分）**：深度场给原本平坦 coarse 区引入
    smoothstep 曲率——若补丁 cell 保持 coarse（1m 弦线）会与其相邻 fine 格/坑口外侧 coarse
    弦线在曲率处裂开（补丁内部 & 与原面交界缝隙，2026-09-05 用户实测修复）。
    `topFineCellsFor` = 基座 fine ∪ 补丁 cell ∪ 补丁邻格 1 圈 → 坑内坡面与坑口交界全细分
    （0.125m 逐点采样世界函数），粗细分界只落在深度/表面恒直的边上 → 弦=曲线，无缝隙。
  - **壁底保底深度随深度场（预防性侧壁长度）**：墙底参照 = 邻侧**深度场修正后的最终面**
    （两节点同减 depthOf）→ "埋入地下防破面"的 WALL_EPS+WALL_MIN_DEPTH 保底长度相对
    新坑底仍完整保留，坑底接缝不露线（2026-09-05 用户：补丁侧壁也要留预防性长度）。
  - **材质**：顶/壁 ShaderMaterial 增加 `useVertexColor` + `vColor` 通道；**顶点色 =
    乘性焦土染色**：中性白 (1,1,1) = 原样；非中性色（补丁染色乘数）→ `albedo × vColor`，
    保留原 tile 的 base/纹理明暗颗粒 → "地面被烧过"而非换纸。三版演进记录：
    ① 乘数取 [0.16,0.135,0.12] 线性太深 → 全黑（用户：看不到颜色）；
    ② 改整块 albedo/base 替换 → 丢纹理成贴纸（用户：材质变了/均匀色块）；

    会压暗全世界侧壁，已修正）。无新贴图/无 tile id 扩展。
  - **幂等**：同 cell 二次命中不重复标记、不重建。

### 14.10b ★ 破坏几何 Worker 化（2026-09-05）

- 动机：命中重建的最大单帧成本 = 「表 + 双 builder」整 chunk 几何生成（数万顶点，
  主线程数十 ms 级）；决策（circleCells/标记）本就 μs 级留主线程。
- 拆法（输入面收敛于 Refinements 统一输入面，故可整段迁移）：
  - `PatchCompute.computeTableGeometry(readChunk, seed, cx, cz, mask)` = 唯一几何生成
    纯函数：`makeChunkSource → refineChunkSource(seed,cx,cz) → buildFaceTable → 双 builder`
    （与 `RasterMap.chunkSource` 同路径同函数）。文件不 import three → Worker 依赖最小。
  - `terrainPatch.worker.ts`：收 3×3 邻域 heights/blockTypes 拷贝 + 掩码 → 纯计算 →
    回传可转移 typed arrays（零拷贝）。
  - `TerrainPatch.ts`：主线程服务。拷邻域数组（~135KB，不转移活数组所有权）→
    postMessage(transfer)；掩码必须传**拷贝**（transfer 会转移所有权）；Worker 不可用/
    onerror → 主线程同步同函数（字节一致）；再失败由 ChunkManager 走标准烘焙兜底。
- 一致性与正确性：Worker 与主线程同一函数同一输入 → **逐位一致**（验收 ⑧：活闭包
  vs 传输拷贝闭包逐位比对，2 seeds）；并发：同 chunk 在途串行化，命中合并后重算终态
  （掩码只增）；幂等跳过保留。
- 未移出主线程（边界）：BufferGeometry 上传/材质/装饰层与碰撞体/rapier collider 重建——
  three/物理对象只能在主线程；后续若仍需优化，先 profile 这几段的占比再决定。

  `levels: Uint8Array(60×60)`（0 = 无；N = 该 1m cell 累深 N 层 = N×PATCH_DEPTH）。
  ★ 边界纪律：
  - **生成器不写**（generateChunk 恒产出全 0；levels 由运行时 playBulletImpact 写）→
    种子确定性、烘焙/装饰输出不受影响；
  - **clearAll 清**（天结束/世界重建时与 heights 一起回收）；
  - **快照分流**：几何快照（3×3 heights/blockTypes/**levels**）携带 levels →
    Worker 几何/高度同源；**烘焙快照（bakeCompute）不携带 levels** → lightmap 维持
    "不重烘"取舍（坑光照仍沿用旧图）。
- 为什么挂 chunk 而不是独立注册表/PatchState：三端（渲染几何、rapier trimesh、
  玩法高度采样）消费的是"地形数据"，把它做成数据的一个维度即天然同源——本轮修复
  "物理不同步"的根因就是独立注册表需要每个消费端记得去查（§14.10c 血泪史）。
- 为什么不上 FaceTable：表是每次重建现建、Worker 局部的重建产物，运行态塞进重建
  输入 = 生命周期错位（§13 时代已明确"不在 FaceTable 增字段"）。
- 迁移路径：PatchState（boolean mask）语义 = levels 的 {0,1} 特例。先把数据迁移到
  chunk levels、行为保持今天（每枪新 cell=1 层）回归全绿，再叠加"同点 +1"。
- 命中规则（待定最小项）：本枪 footprint ∩ chunk 的每个 cell 层数 +1（Uint8；饱和
  层即"够深"，需不需要显式顶另议）；只重算受影响 chunk（幂等守卫 = 层数有变化）。

### 14.11.2 连续包络场（方案 a）—— 水密的数学核心（原型已锁 2026-09-05）

- 逐 cell 计数允许相邻 cell 层数不同；而 4m 块内部 1m 格之间没有墙（基础地形靠共享
  边同高保证 C⁰）。**唯一能容忍任意层数分布且不开裂的出路 = 深度场处处连续**：
  顶面高度 = 基面 − D·u(p)，u 连续 ⇒ 无内部台阶 ⇒ 无需为 1m 级差补墙。
- **定稿公式**（`scripts/__patchstack.ts` 数值原型验证）：
  `u(p) = min over 4 卡氏射线 r of  min_{k≥0}[ N[j+k] + d_k(p) / W ]`
  - j = p 所在 cell；k=0 项 = N_p（自身 cell 常数地板）；d_k = p 到第 k 个 cell
    最近边的轴距（+x = k−frac；−x = frac+(k−1)；z 同理）；对角 cell 不上射线
    （不泄压，验证 ✓）；★ 跨 chunk（2026-09-10）：出本 chunk 后经 `levelAt` 继续读
    邻 chunk 层数（未加载 = 0），seam 两侧共享顶点同路径求值 → 同值连续；
    `levelAt` 缺省 = 旧语义（出界视作层 0 收口）。
  - W = 每层过渡宽度（m/层），默认 **W=0.5**；剪枝：`(k−frac)/W ≥ 当前 best` 即停。
- **原型锁定的数值行为**（验收基准）：
  - 层差跃变 L|L+1：过渡在较深 cell 的前 0.5m 内完成，斜率 ≤ 1/W=2 层/m，无跳变；
  - 十字坑(5格) 中心可达深度 = min(层数, 到地面距离/W)：W=0.5 → L1~L3 满层，L4+ 饱和
    3 层（更深处须向外扩挖 → 挖坑自然越挖越宽）；
  - 单格孤立 cell 最大 ~2 层（W=0.25）/1 层（W=0.5）——无内墙几何的硬约束；
  - L1 坑心仍满层 1.0（与现行观感一致），坑缘坡宽 = W。
- 观感权衡：W 越大坡越缓、堆叠越早饱和；W 越小越陡、堆叠越久。默认 0.5（二/三枪
  明显加深，之后自然扩挖）。若后续想"同点越打越深不饱和"→ 自动扩印（每 L 层向外
  补 1 圈）或上真墙几何，另行评估。

### 14.11.5 已知取舍与开放项

- **同点连打深度的几何上限**：无内墙的连续顶面约束下，深度 ≤ 坑半径 × (1/W)；

  玩法上"坑越挖越宽再越挖越深"。若想要"原地无限下钻"观感，备选：随层数自动外扩
  1 圈（每 L 层扩印）或引入真墙几何（大改）。
- lightmap 不重烘（沿用旧图）；levels 不进烘焙快照（自动隔离）。
- 每帧多枪合并未做（现为 per-chunk 在途串行）；高频连发需时再加帧末合并。
- **深坑死亡规则（2026-09-05）**：WorldMode.clampCharacter 原以 `surfaceHeightAt < −1.5`
  一刀切判"深坑死亡"→ 补丁把普通地块挖深也误触发。现加**脚下地块复核**：
  仅当 `tileDefAt(x,z).isDepression`（坑洞地块）且低于 −1.5 才沉落死亡；普通地块的
  深补丁坑只正常贴地站立（不判死）。足够深 = 沿用 −1.5 地表门限。

### 14.11.7 ★ 跨 chunk 破坏 + 插值（2026-09-10 落地）

- 背景：旧语义"出 chunk 界 = 虚拟层 0"把跨 seam 的坑切成两半（§14.10 已知取舍）；
  破坏本就该跨 chunk 连续（用户 2026-09-10 定调"这个功能本来就是应该实现的"）。
- 核心：`LevelAtWorld = (wx,wz) => number`（世界 1m cell 下标 → 层数；未加载 = 0）。
  - `envelopeLevelAt(..., W, levelAt)`：射线出本 chunk 后经 provider 继续走，坑口线
    /坡面跨 seam 连续；查询点落在邻 chunk（含恰在 seam 平面）时以邻 cell 为
    "自身地板"求值 → A/B 两侧共享边界顶点同值（不再一侧 0 一侧非 0 撕裂）。
  - `buildLevelOverlay(..., levelAt)` 追加 `isPatchedAtWorld(wx,wz)`：侧壁"两侧都补丁
    + flush → 整段剔除"跨 seam 生效（各 chunk 自带状态，两侧对称剔除内部隔断壁）。
  - 运行时 `RasterMap.levelDepthAt/digCells` 同用 provider → 角色脚底/物理 clamp
    与几何逐点同源连续。
- 数据流：`terrainPatch.compute` 的 3×3 邻域 payload 追加 `levels` 拷贝（3.6KB/chunk，
  随消息 transfer）；Worker 与主线程回退各自构造同构 provider（字节一致纪律不变）。
- 重建联动：`ChunkManager.markNeighborsForDug`——挖动 cell 到邻块边界距离 ≤
  邻块贴 seam 边界线最大层数 × W 时，把邻 chunk 压入 pendingPatches（数据早已同步
  落库；未建成 chunk 由后续标准构建自然读到新层数）。邻块边界无补丁（层数 0）→
  其几何不依赖本块，跳过。邻块重建无直接挖点 → dirty=null → 水体走全量重解
  （避免空增量列表漏更新）。
- 兼容：`levelAt` 缺省时 `envelopeLevelAt`/`buildLevelOverlay` 保持旧 seam 收口语义
  （`__regionpatch` 等无 provider 路径回归不变）。
- 数值自检（2026-09-10，跨 seam 3×3 深坑）：seam 顶点两侧深度逐位相等（0.4 vs 0.4）、
  坑内满深、单侧补丁 seam=0 且坑缘平滑、`isPatchedAtWorld` 双向正确、
  单格坑满深/对角不泄压/旧兼容收口全部回归（12/12）。
- 观察项（非阻塞）：坑水（WaterSurface 连通分量/水帘）跨 seam 的池连通目前主要经
  `patch.depthOf` 联动；若实战中 seam 处水面/水帘出现不连续，再补 probe 级联动。

## 15. 双 Worker 流式构建 + 预算化装配（2026-09-05，消除地形创建卡顿）

- 问题：普通新建/重建 chunk 的几何生成（表 + 双 builder，数万顶点）一直在主线程
  （烘焙 worker 只负责贴图）→ 跨 chunk 时单帧尖峰。
- 方案（用户点题"两个 webworker"）：
  1. **几何 worker = terrainPatch**（原本只服务破坏重建）现在承担**全部**标准 chunk
     几何：`finishStandardChunk` 缓存命中/烘焙完成后一律 `terrainPatch.compute`
     （快照拷贝→worker→零拷贝回传）。bake（贴图）与 geometry（几何）两个 Worker
     **并行流水**：烘焙[i+1] 与几何[i] 同帧进行，主线程只装配。
  2. **预算化装配**：几何就绪只进 `assembleQueue`，`update()` 每帧最多装配
     `ASSEMBLE_PER_FRAME=2` 个（BufferGeometry 上传 + rapier collider 重建分散到帧）。
  3. **换代作废**：`geoInflight`/`assembleQueue` 随 setStyle/dispose 清空，装配前
     校验 bakeGen（换风格/退出不留旧装配）。
  4. 兜底链：Worker 故障 → 主线程同步同函数（PatchCompute 同源字节）→ 异常交
     看门狗重试；看门狗跳过 geoInflight 中的 chunk（不重复派发）。
- 首次创建除外（用户确认可接受）：出生 3×3 会在一两秒内按预算逐帧装配完毕。
- 常量可调：`ChunkManager.ASSEMBLE_PER_FRAME`。若需更平，可再加"预取环+1"或
  "装配时间预算（ms）"代替个数预算。

## 17. 地形修改 = 原地更新 + 物理分块（2026-09-09 落地）

> 目标：挖坑帧耗 10~15ms → <0.5ms 级。核心思想：**物理体"块级拆分"，视觉几何
> "原地复用"，计算与 GPU 分配彻底解耦**。

### 17.1 现状盘点（重构前每挖一坑的主线程开销）

计算侧本就增量（`IncrementalGeometry`：基座缓存 + 逐 cell/逐边前缀偏移
`topVPre/topIPre/wallVPre/wallIPre` + 受影响掩码，Worker 内"受影响重发、其余
字节级复用"）——设计稿里的 `cellVertexOffsets` 早已存在。大头全在主线程装配：

| 开销 | 旧路径 | 新路径 |
|------|--------|--------|
| BufferGeometry | 每次新建 ×2~3（6~8 属性全量） | Mesh/Geometry 常驻，`attr.array.set` 原地写 |
| 材质 | 每次新建 TerrainMaterial+WallMaterial+tileIds 纹理 | 常驻不重建 |
| 物理 trimesh | 整 chunk 销毁重建（O(全 chunk) BVH） | 每 4m 块一个 collider，只换受影响 slot（O(块)） |
| GPU 上传 | 全量（换新 buffer） | 全量 set（同 buffer；分块上传留待后续） |
| 装饰 | 销毁重挂（不变） | 销毁重挂（不变，预算化） |

### 17.2 物理分块

- **数据**：`partitionGroundTiles`（IncrementalGeometry 导出）把整 chunk 顶面+侧壁
  字节切成 **225 个 4m 块 trimesh**（slot=bz*15+bx；块 = 自有 16 个 1m cell + 4 条
  壁边；索引重定基块局部）。**布局按输出 fine 掩码推导**（受影响 cell 恒 fine、
  基座可能 coarse → 增量输出偏移整体后移，绝不能拿基座布局切）。
- **产出**：`computeTableGeometry` 返回 `tiles[]`——全量构建 = 全部 225 块；
  增量构建 = dirty 块 **±1 环**（顶点焊接跨界 + 壁边 owner 均被覆盖）。Worker
  transfer 传输（terrainPatch.worker transferOf）。
- **物理侧**：每 chunk 一个 fixed 地面刚体 + N 个 trimesh collider。
  - `PhysicsWorld.setTileCollider(bodyId, slot, v, i)`：同刚体移除旧 slot collider
    → 建新（记账 key = bodyId*1024+slot）；`removeBody` 清名下全部 tile 记账。
  - `ChunkGroundHost.createGroundTiled(cx,cz,tiles)`（首块随实体创建并登记
    tileSlot，其余挂同刚体）/ `updateGroundTile(id, slot, v, i)`；WorldMode 实现。
  - 首块走 `BodyOptions.tileSlot`（EntityManager→addFixed 透传，创建即记账）。
- **兜底**：宿主未实现 / tiles 缺失 → 合并 trimesh 旧路径原样可用。

### 17.3 视觉原地更新（ChunkManager.applyTerrainPatchInPlace）

前置：`terrainVisuals` 登记（buildTerrainMeshes 统一登记 top/wall/water mesh 引用）
+ chunk 已分块 + 宿主支持；任一不满足 → 回退全量换装（replaceChunk）。

顺序（有讲究）：**②视觉 → ④装饰拆 → ③水换 → ①物理**：
- ②视觉失败即 return false（物理未动，回退全量无状态污染）。
- ④装饰先于 ③水：水换会 append 新网格到末尾，先拆装饰才能保住
  `terrainCount` 索引裁剪语义（不误伤新水网格）。
- ①物理最后（collider 原位换，视觉/装饰已就位）。

- **attr 原地写**（applyGeoInPlace）：逐属性长度一致 → `(a.array as Float32Array).set`
  + needsUpdate（零分配）；长度不一致（fine 区扩张致布局漂移）→ 换 attribute
  （Mesh/材质仍保留）。位置/索引长度是布局漂移主判据。
- **包围球**：建网格时 computeBoundingSphere 后 radius+6m——挖坑只降不高，
  原地更新免重算，视锥剔除不误裁坑底。
- **水**：拓扑可变（干块摘除/拆池）→ 整体换 mesh（小网格，廉价）。
- **装饰**：语义不变（销毁旧层+prop/apron/plinth 刚体 → pendingDecorJobs
  预算化重贴地重造；InstancedMesh 分桶使逐 prop 重贴复杂，留待后续）。

### 17.4 消费链路（全部现有入口不动）

`playBulletImpact` → `flushPatchRebuilds`（120ms 节流 + 帧合并，不变）→

### 17.5 验收与开放项

- ✅ tsc + build 通过；字节一致验收 ⑧（增量==全量）继续覆盖 tiles 切分前提。
- ⏳ 进游戏验收：连射挖坑帧耗时（目标 <0.5ms 级）、坑边碰撞连续性（分块接缝）、
  挖坑后 props 重贴地表现不回归。

  ③ tiles 与顶/壁字节共享底层 buffer（省 Worker 一次拷贝与传输）。

### 17.6 创建侧预算化（2026-09-09 二批：地形创建不卡帧）

> 几何计算早已 Worker 化（terrainPatch ×3）；创建卡顿大头在主线程装配：
> ① rapier trimesh 225 块一次全建（WASM 同世界，挪不进 worker）；② 包围球
> O(n) 主线程扫描。对策：

- **分块 collider 创建时间预算**：首建时首块随实体同步建（tileSlot），其余块进
  `pendingTileJobs` 队列，`update()` 每帧按 **≤1.5ms 时间预算**消费
  （`drainTileJobs`；bodyId 不匹配 = chunk 已销毁/重建 → 条目丢弃）。
  挖坑增量更新（受影响几块）不走队列，仍同步原位换。
- **包围球 Worker 化**：`computeTableGeometry` 单遍扫出 top/wall y 范围
  （`topBounds/wallBounds`）→ 主线程 `setPaddedSphere` 解析构造
  （center=(0,yMid,0)，r=√((S/2)²×2+dy²)+6m 挖深余量），创建与原地更新共用，
  不再主线程 `computeBoundingSphere`。
- 玩家无 fall-through 风险：角色 y 由 CPU 高度钳制（RasterMap），不读 trimesh；
  受影响的只是子弹/掉落物（chunk 生成于加载环远端，到达前 collider 已建完）。

### 17.7 修复：回退路径吞碰撞体（2026-09-09）

> 症状：地图创建后打几枪，之后子弹穿地、无法破坏地面。

- **根因**：首次挖坑时增量输出因 fine 扩张布局漂移 → 原地更新失败 → 回退
  `replaceChunk`，但把 **patch tiles（只有受影响 ~9 块）** 传了进去 →
  `createChunkGround` 只建了这 9 块 collider，**其余 ~216 块碰撞体全部消失**
  → 之后子弹在该 chunk 大部分区域直接穿地。
- **修复**：① 回退路径一律合并 trimesh（**绝不传 patch tiles**——tiles 只有
  全量构建（225 块）才能当整块地面用）；② `applyGeoInPlace` 升级两档：
  Tier A 布局一致 → `array.set` 零分配；Tier B 布局漂移 → **整体换 geometry**
  （Mesh/材质/分块物理全保留，旧 GPU 缓冲 dispose）——chunk 保持分块态，
  原地路径不再因首次挖坑就永久失效。

### 17.8 ★ 分块物理实测失败 → 回退合并 trimesh（2026-09-09 定论）

> **结论：225 个 4m 块级物理分块 + 预算队列得不偿失，已回退；后以 grid×grid
> 空间分区 + 同步创建 + 受影响分区提前返回重做（§17.9）。** 上轮删除的分块物理代码
> 教训：单块 trimesh 建造成本 = 三角面数 × BVH，225 小块总开销反而更高；
> 「排队预算分帧」在单块 ~0.1ms 假设下成立，fine 地形单块 ~1-3ms 时吞吐不足 →
> 队列堆积、期间地面缺 collider 子弹穿地 + 主线程挤占致烘焙超时。

**失败链条（实测日志锁定）**：
1. fine 高密度地形单块（16 fine cell ≈ 2048 tri）rapier trimesh 建 **~1-3ms**；
2. 225 块/ chunk × 1.5ms 预算/帧 → **每帧只建 1 块** → 数千块排队 **~70s** 才铺完
   （日志实证 `[TILE-DRAIN] pending=4256 …每帧 1 块`）；
3. 期间 chunk 只有首块 collider（`tiles=1`）→ **子弹穿地、无法挖坑**；
4. 近圈门（≤45m 当帧建齐）把一堆 chunk 误判近圈 → **当帧同步建数千 collider →
   主线程卡死数秒 → 烘焙 worker 饿死超时**（日志实证大量「烘焙超时」）。

**回退收益（用户实测）**：`TILED_GROUND=false` 后 → 每 chunk 单个合并 trimesh
（5~15ms/次，ASSEMBLE_PER_FRAME=2 摊销）→ 流式创建平滑、物理立即完整、
子弹命中与挖坑全部恢复、「几乎不卡」。

**教训**：
- 单块 collider 建造成本 = 三角面数 × BVH，分块把 1 次大 BVH 换成 225 次小 BVH，
  总开销反而更高（多次 wasm 分配 + 每块独立 BVH）。
- 「排队预算分帧」在单块成本 ~0.1ms 的假设下成立；fine 地形单块 ~1-3ms 时
  预算吞吐不足以跟上流式创建 → 队列无限堆积。
- 挖坑性能的**正确方向**是「计算进 worker + 主线程原地换 buffer/GPU 缓冲」，
  物理维持**整 chunk 合并 trimesh 重建**（挖坑时一次性重建可接受）；若要省物理
  重建，改走 rapier **heightfield**（单块可改高度、无 per-collider 开销），
  而不是「每 4m 一块 trimesh」。

### 17.9 ★ 物理分区 = grid×grid 空间分区 + 受影响分区提前返回（2026-09-09 落地）

> 用户定调：物理上做「提前返回」——x 轴三分、y 轴三分（3×3=9 分区），用受影响
> 顶点掩码**精确找出需改动的分区**，合并后只重建这些分区，其余不动。

**设计（规避 §17.8 失败链）**：
- **粒度**：每 chunk 一个地面刚体 + `PHYS_GRID×PHYS_GRID` 个 trimesh 分区
  collider（`PHYS_GRID=3`，可调）。每分区 ≈ 整 chunk 的 1/9 三角面。
- **创建全同步**（无队列、无预算、无近圈门）：首分区随实体创建（tileSlot 登记），
  其余 8 分区 setTileCollider 挂同刚体——一次成本 ≈ 原合并 trimesh，物理立即完整。
- **挖坑增量（提前返回核心）**：Worker 用受影响 1m cell 掩码（`masks.top`，已含
  补丁∪1 圈）→ `deriveAffectedCells` 映射到所属分区（cell = floor(bx*grid/BPS)）
  → `partitionGroundCells` **只切受影响分区**（其余不生成）→ 主线程 `applyTerrainPatchInPlace`
  只 `updateGroundCell` 换这些分区的 collider（同步，O(受影响分区)）。单坑通常命中
  1~4 分区 → 物理重建从整 chunk（10~15ms）降到 1/9~4/9 chunk（~1~3ms）。
- **一致性**：分区布局按**输出** fine 掩码推导（受影响 cell 恒 fine、基座可能 coarse，
  增量输出偏移后移——不能拿基座布局切，沿用 §17.4 的教训）；分区字节 = 块字节
  拼接 + 索引重定基分区局部（与上轮探针逐字节验证的切分同构）。
- **兜底**：宿主不支持分区 / cells 缺失 → 整 chunk 合并 trimesh（旧路径原样可用）。

### 17.10 ★ 挖坑带宽优化 = 每 chunk 静态数据缓存 + 受影响区间局部上传（2026-09-10 落地）

> 用户定调：只加速"正在被打的 chunk"，其他 chunk 走常规路线；瓶颈是**上传带宽 +
> 同步 collider**，不是 CPU 算力。原有缓存：烘焙纹理（`bakeCache`）与无补丁基座
> 几何（`baseCache`）；缺口在"每枪仍全量输出/上传"。

- **① 每 chunk 静态数据缓存**（`PatchCompute.dropPatchSourceCache`）：
  refined src（3×3 heights/blockTypes → 精修源）与 FaceTable 只依赖 heights/blockTypes、
  与 levels 无关 → 同一 chunk 连打复用，省掉每枪 `planRefinements`（225 块×4 向）
  与 `buildFaceTable`（Pass1+Pass2）。LRU=16；3×3 邻域缺块时不入缓存（防固化缺块快照）。
  换代清空：`TerrainPatch.clearCaches` / Worker `clearCache` 与基座缓存一并清。
- **② `baseCache` LRU 16 → 36**：覆盖加载环（radius 2 → 5×5=25）+ 余量；小于环会在
  跑动/多坑连打时来回逐出，退化成全量构建。
- **③ 受影响区间局部上传**（增量重发新增 `updateRanges`）：
  - 布局基准 = **上一次输出布局**（`ChunkBase.outTop/outWall`，随每枪更新），而不是
    无补丁基座（补丁必把 cell 升 fine → 对基座必然"漂移"）；
  - 缓存 miss 首枪 `prev=undefined` → 不带区间、整块上传兜底；之后各枪产出
    `{ vertex, index }` 下标区间（消费端按 attribute.itemSize 换算元素偏移，
    对接 three `addUpdateRange`，上传后自动清空）；
  - 主线程 `applyGeoInPlace` 区间齐全时只 `subarray.set` + `addUpdateRange`（每属性
    几 KB~几十 KB），替代整块（示例 chunk 顶点位置 ~940KB）CPU 拷贝 + GPU 重传；
    区间缺失（任何布局漂移/属性异常）自动回退整块 `.set`，Tier B 仍整体换 geometry。
- **验收**：`__incremental_check` 全绿（miss/hit 与全量逐位一致；现场计时全量
  420ms vs 基座命中增量 14.12ms，29.8×）；`__regionpatch` 输出与优化前基线逐项一致；
  区间覆盖自检 18/18（顶/壁各属性 + 索引：以上一版缓冲 + 区间覆盖 == 整块输出）；
  布局漂移（远处新增坑）自动放弃区间走整块。
- **④ 当前 chunk 低节流（2026-09-10）**：`ChunkManager` 每帧 `markHotChunk` 标记玩家
  所在 chunk；`flushPatchRebuilds` 对热点 chunk 使用 `PATCH_REBUILD_MIN_MS_HOT=40ms`
  （常规 chunk 仍 120ms），连射当前坑更跟手。其他 chunk 的节流/装配顺序完全不变。
- **未做/后续**：物理 collider 重建仍是每枪同步 cooking（可再预算化）；水体小网格
  整体换；装饰重贴地预算化。先实测，不够再拆。

### 1. 地块基类 TileDef：属性自足

#### 1.0 ★ 铁律：类型封闭，材质自由（2026-08-28 定稿，地块最高设计原则）

地块的两层属性地位不对等，扩展时必须分清自己在动哪一层：

| 层 | 承载字段 | 性质 |
|---|---|---|
| **类型**（结构层） | `genRole` + `physics` | **封闭集合，必须确定**：平地/高台/水/坑洞 四基础类型 + 装饰性平地/装饰性高台 两变体类。生成器/连通性/碰撞/寻路只认类型 |
| **材质**（表现层） | `visual.material` + `baseHsl` + `key/label` | **完全自由**：名字任意、材质任意、颜色任意。表现层只消费 |

推论：
- 装饰变体只是"换皮"：变体 `physics` 必须 ≙ 基础类型（逐项一致）——
  固定 seed 下 walkable/heights 逐位不变，回归基线成立
- **加类型 = 体系级决策**（要通盘考虑生成器槽位/高度分配/碰撞，慎）；
  **加材质皮 = 日常内容工作**（registerTile 注册即生效，管线零改动）
- 组（TileGroups）按【类型】过滤抽取（rolePool→genRole）；组内装什么材质的地块是自由内容
- 水/坑**没有**装饰变体是有意设计：语义色（警示红/深蓝）是玩法可读性的一部分，全局唯一

每个地块自己描述完一切，不依赖外部表解释自己：

```ts
class TileDef {
  id / key / label
  genRole: 'ground' | 'platform' | 'liquid' | 'pit'   // 生成器结构槽位匹配维度
  physics: { height, heightJitter*, walkable, lethal, flattenAtPorts }
  visual:  { baseHsl(唯一颜色真源), jitter, depression, patches?, borderLine?, streaks? }
  groups:  string[]    // 所属风格组（多对多）
}
```

### 2. 组 = 生物群系（材质组唯一概念；2026-08-28 融合原 RegionTheme）

- **组现在是生物群系的唯一载体**：一个组 = 成员地块 + 调色板(palette) + 生成偏置(gen)
  - `palette {hueShift/satMul/lightMul}`：本组地块的色调倾向（烘进 albedo +
    调制材质 uMatBase + 墙顶点色同源；水/坑语义色只吃 45% 保读性）
  - `gen {densityBias/waterMul/pitMul}`：本组的迷宫密度/水体/坑洞比例偏置
  - 旧 RegionTheme 的空间插值层已删除——**每 chunk 按其组恒定（硬边界）**，
    肉鸽风格友好；⚠️ 同 seed 地形与融合前不同，旧回归基线需重生成
- **组归属唯一权威 = GroupDef.members**：`TileDef.groups` 是声明性数据（表达意图，
  运行时不消费——与装饰实体/贴图不同）；首次选组时 `validateTileGroupSync`
  自动校验两者同步，漂移即 warn（2026-08-28 定稿，防双记账静默失效）
- 一组内混装各种 genRole 的地块；地块可属多个组 → 相邻区域换组过渡自然
- **结构合法性由抽取时按角色过滤保证**，不由组契约保证：
  结构层说此处需要 platform → 只在该组 platform 成员里抽；筛空走回退链
- **回退链**：生效组 → 基石组(foundation，四角色齐装) → 全局默认块

### 4.6 ★ 地图加载全流程（2026-08-27 整理；标准风格）

```
WorldMode.enter
  → raster = new RasterMap(seed)          # 统一空间层（纯数据）
  → entities = EntityManager(physics, raster)
  → chunks = new ChunkManager(scene, raster, groundHost)   # groundHost=EntityManager 适配
  → chunks.bootstrap(出生点)               # 数据环扩张 + 出生 3×3 强制构建

每帧 WorldMode.update → chunks.update(玩家xz, dt)
  ├ syncChunks：RasterMap.updateChunks（数据环扩张）→ 新增块入队 → processQueue（8ms 预算）
  └ sweepChunks：看门狗（0.5s 一拍：在途超时释放 / 空洞补请求）

构建一个 chunk（requestStandardBake）：
  ① planDecor：贴图 + 装饰物【全部放置完成】（确定性）→ 阴影体积打包
  ② 烘焙缓存查询（seed|cx|cz）→ 命中直接装配
  ③ 快照（3×3 原始数组拷贝）→ Worker（携带 propVolumes + decals）
     └ Worker 不可用 → 主线程同步烘焙（同一计算核心，输出逐位一致）
  ④ Worker 回传 RGBA → assembleChunkMaps（albedo装饰叠加层 + 光照图）

装配（finishStandardChunk）：
  ⑤ 位移平面几何 + UV（外观 UV = 块 id 微纹理同约定）
  ⑥ TerrainMaterial(albedo, lightmap, 材质配置)
     └ 材质配置 = buildTileRenderConfig(blockTypes)：
        块 id 微纹理（15×15 R8 Nearest）+ uMatBase/uMatSurface/uMatEmissive/uMatParams
  ⑦ ChunkWalls 断崖侧壁（顶点色）
  ⑧ buildDecorLayer → 装饰物网格层（对齐 chunk 角）→ 挂进 group
  ⑨ replaceChunk：换装（销毁旧视觉+旧物理）+ fixed trimesh 地面刚体 + 激活回调
  ⑩ createDecorColliders：装饰物 fixed cuboid 碰撞体（★ 必须在 replaceChunk 之后）

Boss4D 风格：buildChunkMesh 同步直建，同一装饰管线（贴图印进单纹理烘焙）。

渲染（WorldMode.render → renderer.render(scene, camera)）：
  片元：块 id → 材质函数分发（dirt/rock/moss…）→ ×装饰叠加层 ×光照图
        + 4×4 棋盘描边 + 镜面/菲涅尔/发光（表面属性）
```

**装饰物高度参与预渲染结构** —— 放置顺序：

```
requestStandardBake
  ① planDecor：贴图 + 装饰物全部放置完成（确定性，两份消费同一计划）
  ② 快照携带装饰数据进 Worker：
     - propVolumes（装饰物→球/柱遮挡体积 [x,z,y,r,h]，shadow≠none 才有）
```

装饰物阴影 = 烘焙域（光照图内印入），不是实时阴影贴图；

## 水体管线 —— 独立于地形管线的平行管线（设计稿 2026-09-07）

> 状态：**设计稿**。水体升格为**独立管线**：不再是地块，不给 TILE_WATER 的 tile
> 材质（现有 pebble 水底是水体模块开工前的**静态占位**，开工后水面上移，
> pebble 成为「浅水透底可见的河床」底色来源）。与地形管线**单向联动**（水读
> 地形，地形不读水），拥有独立渲染管线入口。
>
> **用户定调（原话）**：只有 **LOD 范围内**的水才启用 **FFT 位移纹理的播放**；
> 只有**非常近**的水才启用**运行时计算**。
>
> 血缘：借鉴 natural-disasters（Tessendorf FFT 海洋）的渲染技法（位移→法线、
> 泡沫速率积分、微波纹旋转采样、背光体散射），但**不做逐帧 FFT、不做千米大面**。

---

### 0. 一句话

**水 = 一套独立管线：烘焙基准面（水位/水深，CPU 可查）+ 三层 LOD（极近=运行时
计算 / LOD 圈=FFT 位移纹理播放 / 圈外=静态）+ 独立渲染 pass；范围与水位从地形
管线取，装配与生命周期并入地形双 worker 流式。**

### 1. 三层 LOD（用户定调，参数暂定）

| 档 | 距离 | 水做什么 | 波形来源 | 成本 |
|----|------|---------|---------|------|
| **运行时层** | ≤ R0（建议 12m，覆盖游泳交互圈） | 实时波形仿真；游泳/涟漪/浮力物理采样**只在这一层** | Gerstner 4~8 层（ω 预采样）或 fbm 时间演化，逐帧算 | 近处片元/顶点一次波形求值 |
| **播放层** | R0~R1（建议 60m ≈ chunk 见距盘） | 循环位移纹理**播放**（预烘 FFT 位移纹理按 uTime 采样，外观≈仿真、零逐帧 FFT） | 烘焙期 FFT 烘**循环位移纹理**，运行期 `texture(uDispLoop, w/scale + f(t))` | 1~2 次纹理采样 |
| **静态层** | > R1 | 只画基准面 + 平价简色，无起伏（渐隐出） | 无 | 近零 |

- **圈界渐变带**：两档之间用空间 alpha 渐变（默认 8m）过渡，禁止硬切（位移与
  法线同时渐变，防跳出）。
- R0/R1 为常量可调（`WaterLOD` 参数卷）；R0 跟随相机/玩家中心，随移动环带滚动。
- **实现状态（2026-09-09）**：播放层/静态层已在共享 WaterMaterial 内以**距离 uniform
  环**落地（uLodNear/uLodFar，12m/55m；顶点 L1/L2 采样+波高衰减、片元法线级联/泡沫/
  高光衰减，纯 shader、无边跳变）。运行时层（真实波形仿真 + 游泳采样）未实现。

### 2. 预烘焙资产（一次性内容）

#### 2.1 静止基准面（CPU 可查 —— 物理免费的关键）
- **水位恒定 y = 0**（用户定调，2026-09-07）：不做邻岸推导、不做连通域水位带，
  全局统一。0 以上是岸/干地，0 以下是水。
- 水深场 = 0 − 水底地形高（`surfaceHeightAt`/FaceCell `h`，water 块底 -0.5
  类）→ 浅水（近 0）透出 pebble，深水不透明。
- 产物：低分网格（如 1m 格）水深场（水位 0 已知，存深度即可）。
- **消费**：游泳浮力/吃水/岸泡沫/浅水变色的 CPU 与 shader 公共源。

#### 2.2 播放层位移纹理（「FFT 位移纹理的播放」物化）
- 烘焙期（非运行期）：144~256² 级 FFT/Gerstner 谱烘成**时间循环位移纹理**
  （时间编码进纹理，如 3D 纹理或 1D 序列打包），含位移 + 导数。
- 运行期：播放层网格顶点/法线只做 `texture(…) + uTime` 采样，**无逐帧 FFT、
  无仿真状态**——这正是"LOD 圈内启用播放"的含义。

### 3. 与地形管线联动（契约，单向：水读地形）

```
地形管线（RasterMap 数据环 + FaceBuild）
   ├─ 水域布局   chunkSource cell id==4（ROLE_LIQUID 簇）→ 水网格范围（mask 收缩）
   ├─ 岸线       水全向 weld（edgeRuling rule1）→ 岸→水过渡由地形 weld 完成；
   │              水面网格沿 weld 岸线贴合，岸边水色/泡沫带取 weld 边位置
   ├─ 水位       恒定 y=0（用户定调），不读邻岸；水深 = 0 − 水底地形高
   │              （surfaceHeightAt/FaceCell h）→ 烘焙水深场（§2.1）
   ├─ 侧壁       id==4 水墙独立路径保留（WALL_BRIGHTNESS×0.32 深暗）
   │              水面网格与该墙顶**标高对齐基准面**，防水面穿墙/墙顶出头
   └─ 生命周期   水网格装配并入同一双 worker 流式（terrainPatch + assembleQueue
                  预算化，ASSEMBLE_PER_FRAME 节拍）；setStyle/dispose 与地形
                  同步清空水队列；chunk 卸载即弃水面
```

- **地形不读水**：水只消费地形已定型数据（表驱动 FaceTable 的 id/高度/岸，
  `surfaceHeightAt`），不反向改地形。
- **水底与水面分离**：水底仍是地形块（pebble 河床材质照走 oklchShade）；水面是
  水体管线的独立网格，两层面间留水深间隙 → 浅水区水面透出 pebble，深水区不透明。

#### 3.1 坑 / 水交界 —— 下落过渡带（2026-09-07）

水相邻坑洞（`ROLE_PIT`/pit 邻格，坑深 -3.0、lethal）处，水面不再在坑壁上做岸线
收边，改为沿坑壁**下落过渡**：水帘从潮位倾泻到坑底。

- **判定**：水 meta 派生时找「水 cell 的共享边，邻 cell 为 pit」→ 记 `dropEdge[]`
  （边 + 潮位(=0) + 坑底高）。
- **几何**：沿 `dropEdge` 生成贴墙**水帘网格**（宽=边，从潮位 → 坑底），与
  侧壁墙顶**标高对齐潮位**，帘底落在坑底。水帘属于水面同一 water mesh 的附属
  片，随 chunk 生命周期一体装配。
- **着色（分层细部）**：
  - 帘体：UV 滚动条纹/噪声 → 流动感；瀑布常见"白-透-暗"竖向渐变；
  - 唇沿（潮位）：泡沫积分白线（借鉴 natural-disasters 泡沫速率，持久白沫）；
  - 坑底溅落点：受击泡沫 + 落点涟漪（极近层可带粒子水花；播放/静态层仅受击
    环状噪声，不动粒子）；
  - 帘底段 alpha 渐隐，融入坑内暗部（坑 lethal 深暗，不做强光）。
- **LOD**：极近层 = 全动画（帘流 + 泡沫闪 + 溅环）；播放层 = UV 滚动保持动感
  （下落是整体定向运动，`uv+uTime` 零额外纹理开销）；静态层 = 静态帘（无动画，
  仅竖向渐变亮片贴墙，让边界不消失）。
- **物理**：坑 lethal，跌落带无物理交互；坑底默认**无积水**（保住 lethal 深坑
  语义）。若要"坑底受击处一层薄水"作为溅落目标 → 开放项（§7 待定）。

### 4. 独立渲染管线

- **水网格**：每 chunk 一片独立 `BufferGeometry`（按水域 mask 收缩、贴岸），
  独立 `RawShaderMaterial`——**不进入** `MAT_FN_INDEX`/`oklchShade` 材质分发。
- **渲染次序**：地形（不透明）之后、半透明杂物之前；水可半透明（透底/透光）。
- **分层细分**：近 chunk 水网格细分高，远低——细分与 LOD 档联动（播放层用
  coarse，运行时层 near 细分）。
- **着色**：基面色 + 水深色（浅=透出 pebble 底色，深=偏深水体色）+ Fresnel/
  reflect（复用 TerrainMaterial 的反射通道思路）+ 法线（近=运行时波形，LOD 圈=
  播放纹理导数）+ 岸泡沫 + 涟漪 + 背光体散射（借鉴 natural-disasters 技法）。
- **共享**：太阳光源 uniforms（uSunDir/uSunDay 等照 feed 链）、ACES/colorspace
  输出管线、RenderManager 调度。半透明合成走独立水 pass（贴 waterRenderOrder）。

#### 4.1 局部扰动注入（涟漪/浪涌 · 2026-09-08 落地）

交互涟漪走**纯 shader 注入**，不建 CPU 波形、不加粒子片：向共享材质写入「落点」，
水面网格就地叠加一段约 2s 的剧烈起伏。因材质全水面共享一份 → 对任意 chunk 水面
即时生效；不新增网格/pass，不改角色与碰撞。

- **数据通路**：uniform `uImpact[6]`（vec4：`.xy`=落点世界 xz、`.z`=强度(米)、
  `.w`=起始时刻；空槽 w<0）+ 环形槽位（槽满覆盖最旧）。时钟 = 全局 uTime
  （performance.now × 0.001），与 wallRegistry 昼夜喂值同源。
- **注入 API**：`sharedWaterMaterial.addImpact(x, z, strength)`（WaterMaterial.ts）。
  强度 = 波幅米数：步行入水 ~0.8；坠入/炮弹 ~1.4~1.6；水中移动 0.3~0.55。
- **波形**（`impactAgitation`，顶点/片元共用同函数）：
  - 中心回弹涌浪：`exp(−d²·3) · (0.35+0.65·sin(age·11)) · fade`
  - 外扩环带：`exp(−((d−age·2.2)·2.2)²) · sin(d·9−age·30) · fade · 0.8`
    （以 ~2.2 m/s 外扩的波阵）
  - 时间衰减 `fade = exp(−age·1.7)`；age>2s 整槽退出
- **装配点**（WaterMaterial vert/frag，仅水面顶 deep=0、非 border 分支）：
  - 顶点：`wp.y += impactAgitation(...)` → 真实抬升/凹陷；坑水帘/幕布/屋顶不参与
  - 片元：0.08m 中心差分求扰动斜率，×0.5 并入表面法线 → 波动区反光/波光随浪晃动
- **语义**：涟漪是纯表面表现，物理/碰撞不读它；落点外衰减数米内归零（局部圈，
  不污染全图）。

### 5. 交互 / 物理（只在极近运行时层）

- **游泳**：CPU 查基准面（§2.1）+ 极近运行时波形（同一波形函数 CPU 侧可求值）
  → 吃水/浮力/阻力；涟漪经解析注入极近圈（抄 natural-disasters 雨滴 ring 思路）。
- **水深**：水深 = 基准面(=0) − 水底地形高 → 岸泡沫带/浅水变色/深水色，一行共用。
- 播放层/静态层**无物理**：物理采样永远回到 CPU 基准面 + 极近波形，不读播放纹理。

#### 5.1 落水 / 炮弹触发（2026-09-08 落地，WorldMode）

触发侧与 §4.1 解耦——WorldMode 只做「事件 → addImpact」转发，不识波形；当前
实现未按 LOD 分档，涟漪注入共享材质后靠距离衰减自然局限在落点圈。

- **角色入水**（`updateWaterEntry`，player/enemy 各维护一帧状态 `waterPrev`）：
  - 走进水面（脚下方块 非水→水，且脚底 < 水面下 0.5m）：强度 0.8
  - 高处坠入 / 跳水（本帧穿过 y=0）：强度 `0.7 + 0.15×坠落速度`，上限 1.6
  - 水中移动（`moveSpeed > 0.3`）：周期泛波——间隔 `340 − 28×速度` ms
    （慢走 ~0.34s / 快跑 ~0.2s），强度 `0.28 + 0.06×速度`（≤0.55）；
    站立不动不泛波
- **炮弹/子弹落点**（撞地回调 `agitateWaterNear` + `waterPointWithin`）：落点及其
  **0.6m 半径十字采样**（`tileDefAt(...).genRole === 'liquid'`）命中水面 → 强度 1.4
- **不变量**：触发只调 `addImpact`；角色位置/速度/碰撞**零改动**——水中是否能
  站立/淹死仍由地形坑洞规则原样决定（无游泳浮力层、无吸附手感）。

### 12. 材质伪造渲染（OKLab 实时域，2026-08-31 定版）

GPU 逐像素程序化渲染：每个地块只声明一个 sRGB-HSL 基色（作者侧），
丰富渐变/明暗/反光全由 shader 产生——空间非均匀多尺度，非整体统一调色。

#### 12.1 颜色空间链路（边界定死，杜绝双转换）

```
作者侧  Tiles.baseHsl（sRGB-HSL）× 组调色 applyGroupTintHsl（HSL 域）
JS 一次  colorLab.srgbHslToOklch → OKLCH(L,C,H)，存 uMatBaseLCH[id]（每 chunk 构建期）
GPU     oklchShade：LCH + 逐像素偏移 → oklab2linear（输出线性 RGB）
管线     ×albedo ×光照图 → ACES → three linearToOutputTexel（sRGB 屏幕）
```

- 旧实现把 sRGB 值直接喂 linear 管线（二次 ACES 压缩偏暗偏脏）——已根除。
- 无材质地块（水/坑/冰）走 albedo 白底+CPU 色路径不变；`uMatBaseLCH=白(L1,C0,H0)`。

#### 12.2 渲染层（每像素，全部复用单一噪声场）

```
shadeField(w) → (patch, mid, grain)    三尺度：大斑块 0.04 / 中频 0.18 / 颗粒 30
              （世界坐标先 mod SHADE_FIELD 折回防精度损失）

① materialShade(f,w,id) → vec4(dL, dC, dH, reflect)   每材质各自配方
   xyz = OKLab 加法偏移（明暗/饱和/色相）；w = 反光层乘数
② oklchShade：LCH = base + (dL,dC,dH) + 每地块 jitter(OKLab 幅度)
   → clamp L/C、fract H → oklab2linear → × reflect（多尺度亮度层次，乘法）
③ 伪 PBR（零额外噪声采样）：
   伪法线 pseudoNormal = grain 有限差分（2 次 h21）→ 微阴影/高光
   伪 AO = patch 谷地压暗；伪粗糙度 = 材质基础 + grain 调制（高光功率 mix(48,8,rough)）
④ LOD 发光（实时域，增强版 2026-09-01，RenderManager 每帧喂太阳）：
   lit += base · uMatLODEmissive[id] · 18.0 · distBand · glance · sunLayer · idJit
   distBand = 距离带状呼吸（俯瞰时邻近区块出现明暗环带，随相机移动分层可见）：
     ring1 = smoothstep(60,12,dist)         主发光带（远→近亮起）
     ring2 = smoothstep(40,28,dist)·0.6     次带叠加
     ring3 = smoothstep(22,14,dist)·0.4     近距微带
     distBand = clamp(ring1+ring2+ring3, 0, 1.6)
   glance = 0.45+0.55·(水平距/总距)      镜头掠射强、垂直俯视弱（纯几何，无法线）
   sunLayer = clamp(0.5+0.9·dot(地块→相机, uSunSide)·uSunDay, 0, 1)  朝阳侧亮、夜晚消退
   idJit = 0.75+0.5·h21(floor(vWorld·0.25))   地块级空间抖动 → 相邻平台发光不一致
   uSunSide = 水平太阳方向（JS 每帧一次；uSunDir 同时修为真实 sun.dir）
   目标：相机平移/俯瞰/转身时地块间发光层次差异明显（自 2026-09-01 增强）
```

#### 12.3 数据流与扩展点

| 层 | 文件 | 职责 |
|---|---|---|
| 材质注册表 | `TileMaterials.ts` | params 模板 + surface + `lodEmissive` |
| 色彩工具 | `colorLab.ts` | sRGB-HSL↔OKLab 纯函数（矩阵经数值求逆校验） |
| uniform 打包 | `ChunkManager.buildTileRenderConfig` | baseLCH/jitter/surface/lodEmissive/fn 按 tile id 槽位 |
| GLSL 库+分发 | `TerrainMaterial.ts` | MAT_FN_INDEX 数据驱动 dispatch；加材质 = 注册 + 登记一行 |

加材质三步：`registerTileMaterial` → `MAT_FN_INDEX` 登记 → 写 `mat_<fnId>` GLSL（返回
`vec4(dL,dC,dH,reflect)`）。橙红系压灰原则：基色 s ≤ 0.3、材质 dC 幅度 ≤ 0.004
（灰底上色相残留极易刺眼，2026-08-31 用户定调）。

#### 12.4 性能契约

- 伪 PBR / 反光层 / LOD 发光 **零额外噪声采样**（全部复用 shadeField 与材质内噪声）；
  增强版 LOD 增量 = 3 smoothstep + 1 clamp + 1 floor + 1 h21 + 1 dot + 若干 mad
  （多环带 distBand 由 3 次 smoothstep 求值；idJit 复用 h21，无新增 per-pixel 纹理采样）。
- 所有逐像素工作在 GPU；JS 只在 chunk 构建期转一次 LCH、每帧喂一次太阳 uniform。
- **伪法线不回读**：`pseudoNormal` 由 grain 高度场做有限差分（2 次 h21）在 GPU 内
  实时派生，不经法线贴图/顶点法线回读、无额外缓冲/CPU 同步 → 开销小（§12.2 ③）。

#### 12.5 日光渲染职责分工（太阳参与、月亮不参与地块光照）

实时渲染域，只有**太阳**驱动地块（顶面 + 侧壁）光照；**月亮不参与地块光照**，
只用于天空/月光平行光：

```
地块顶面  TerrainMaterial → uSunDir/uSunSide/uSunDay/uSunColor/uSunIntensity
          （updateTerrainLighting 每帧喂；方向→影子朝向、色温→晨昏、daylight→昼夜）
地块侧壁  WallMaterial / Boss4DWallMaterial → uAmbientColor/uSunColor/uSunDay/uWallEmissive
          （updateWallMaterialsLighting 每帧喂；标准墙=顶面同光照公式，Boss4D 墙≈顶面近似）
月亮      queryMoon() 数据只进 SkyDome（MoonEffect 离屏渲染圆盘，§14）与月光平行光
```

**侧壁昼夜光照模型（2026-09-02 定版）**：竖直墙面法线水平，上方来光 N·L≈0
→ 光照公式直射项对墙天然失效，夜晚只剩 ambient×AO ≈ 全黑。三层保底（只作用于
`WallMaterial`，见 `TerrainMaterial.ts`）：

1. **昼夜直射保底**：`d = mix(max(lm.r, WALL_NIGHT_DIRECT_FLOOR=0.30), max(lm.r, WALL_DIRECT_DAY_FLOOR=0.45), uSunDay)`
   ——夜晚钳到 ≥0.30（月光级暗度）、白天 ≥0.45（坡脚/影区墙保亮）。
   ★ 2026-09-07 用户验收："夜间侧壁非常亮"→ 夜档从 0.85 降为 0.30。
   根因：墙面 vUvC 塌缩成光图上一个点，烘焙阴影区（lm.r≈0）时墙会黑，
   但 0.85 月光全开级无差别加亮把整面墙顶得比顶面亮太多。
2. **侧壁自发光**（WALL_EMISSIVE=0.15，2026-09-07 从 0.55 降档）：`lit += base×alb×uWallEmissive`，
   与光照解耦（不受 AO/直射遮挡），材质本色直接发光兜底防纯黑；
   `(1-daylight)×0.15` 夜淡入。原 0.55 近乎半个底色自发光，夜晚壁面
   大幅亮于顶面（顶面无此项）——用户验收降档。
3. **水体侧壁独立路径**（id==4 water）：不享受自发光/增亮——直射用烘焙
   原值 lm.r、增益压到 WALL_BRIGHTNESS×0.32。水坑内壁深暗即可，亮蓝+全额自发光
   会发白刺眼（0.4 仍偏亮 → 0.32 用户定稿）。

增益链：`lit = base×alb×(ambient×lm.g×ao + sun×d) × wallGain`，非水墙
`wallGain=1.0`（已与顶面同源采样 uVw，不再补偿墙脚塌缩）、水墙
`WALL_BRIGHTNESS(2.9)×0.32`。

**侧壁纹理沿革（2026-09-01 定稿）**：标准世界侧壁已修复"竖条纹"与"纹理随相机水平
漂移"两个 bug——竖直墙面用墙面切平面坐标（沿墙水平距离 × 墙高），法线只见世界方向
（`mat3(modelMatrix)`）。Boss4D 四维空间**刻意反向保留**漂移特效：侧壁改用
`Boss4DWallMaterial`（`Boss4DArena.ts`）采样顶面同款 mapTex，采样坐标轴由
`normalMatrix * normal`（视角相关法线）驱动，相机转动时墙面纹理水平平移——这是
正常世界已修掉的那个变体，只在四维空间保留作主题手感。该材质同享 wallRegistry
昼夜喂值；共享 mapTex 仅以 uniform 引用（不设 `.map`），避免 disposeVisual 双重释放。

#### 12.6 天空穹顶色彩空间（与 clearColor 同管线，2026-09-01 修复）

- 背景清屏色经 `renderer.setClearColor(horizon)` 走 sRGB 输出管线，屏幕显示 = 配置值。
- 天空穹顶（SkyDome ShaderMaterial）自定义片段着色器，**必须**在末尾
  `#include <colorspace_fragment>`——否则穹顶地平线色被 sRGB→线性暗化，
  与背景/雾在交界处出现色差（曾验证：87ceeb 被暗化为 62,157,212，与背景 135,206,235 不符）。
- 教训：自定义 ShaderMaterial 的 toneMapped/colorSpace 属性**不会**自动注入
  tonemapping/colorspace 块——需在 GLSL 里显式 `#include`（与 §12 地形材质一致）。

#### 12.7 白天渲染性能评估（2026-09-01 定论）

白天渲染开销整体不大，无非显著瓶颈项：
- 环境层：约 4 个 draw calls（穹顶 1 + 太阳圆盘 1 + 半球光 + 平行光）；
  白天月亮 `uVisible=0` 直接 fragment discard，成本≈0。
- 地形逐像素光照是**最大固定成本**（白天/夜晚相同），但伪法线零回读、光照
  uniform 每帧一次喂值、无逐像素 CPU 计算——属 GPU 内轻量派生。
- 结论：不必为性能移除日月圆盘；优化重心在地形逐像素着色器而非天空层。

### 13. 天空云朵（GPU 流体附着穹顶，2026-09-01 落地）

实时渲染域新增"云朵"环境子系统，**复用特效播放器同一套 FluidSolver**（GPU
半拉格朗日平流 + 红黑 SOR 压力投影），归 RenderManager 协调。

#### 13.1 归属与接线
- `src/services/render/CloudSolver.ts`：轻量封装——持有独立 `FluidSolver`（512×512），
  产出云场合成纹理；RenderManager.update 每帧推进，进入 world 时 reset。
- `src/services/render/SkyDome.ts`：SKY_FRAG 新增云层采样——按穹顶半球世界方向
  （绕 Y 水平角 → U，竖直条带 → V）映射云纹理，用 alpha 把云白 soft 叠加到天空渐变；
  云只在白昼可见（`uCloudDay = sun.daylight` 渐变隐没）。
- `src/main.ts`：`renderManager.setup(scene, renderer)` 传入 renderer 供求解器构造。

#### 13.2 求解参数（用户定稿）
| 项 | 值 |
|---|---|
| resolution | 512 × 512 |
| enableAdvection | ON（半拉格朗日，CFL 子步） |
| enablePressure | ON（pressureIterations≈10, omega≈1.7, warmStart） |
| maxVelocity | 600 px/s（限速） |
| step 节奏 | 每秒 2 帧（累积 dt，每帧 dt=0.5s），CFL≈1 稳定 |
| 模式 | vector（colorGrid alpha = 云遮盖度，RGB 携带 HSLA 自由流动） |
| 注入 | 周期（每 ~3s）随机小半径（radius 0.04~0.08）+ 柔和漂移速度，云色随 time 变 |
| viscosity | 0、gravity 0（云靠 advection 漂移 + pressure 内聚成团） |
| 云色随时刻 | `setHour(hour)` 喂纯时间（非太阳采样）；距日出(6)/日落(18) ±1.5h 渐变到暖橙/粉，其余近白；夜晚压低 alpha |

#### 13.3 关键实现细节
- 云纹理是 **HSLA-编码**（colorGrid RGBA=R:H/G:S/B:L/A:alpha）。穹顶着色器内置
  `hsl2rgb` 把采样 HSL 还原成云色，再用 alpha 作密度叠加；`uCloudDay=sun.daylight`
  做白昼渐变隐没。
- 云色由 **CloudSolver 按 hour（纯时间）调注入色**（晨昏暖、白天白），穹顶消费
  该颜色 → 云随时间染上晨昏色，与太阳采样解耦。
- ★ **双缓冲 crossfade（消除 2fps 跳变）**：求解器内核本身是乒乓纹理（texA/texB +
  swap）。输出之上再叠一层过渡：每次真实结算时把当前合成帧冻结进 `prevRT`，
  之后每帧在 `prev→cur` 间按过渡进度插值（`uCloudBlend`），把 2 帧/秒的台阶
  平滑成连续形变；穹顶一次采样 prev/cur 两纹理 `mix` 叠加。
- **穹顶贴图 = 极坐标圆盘（纹理中心正对天顶）**：方位角 `phi=atan(dir.x,dir.z)` →
  环向，`theta=acos(dir.y)` → 径向 `r`（0=天顶，1=地平线）；`cuv = 0.5 + 0.5·(cosφ, -sinφ)·r`。
  纹理中心永远正对天空中心，云从中心向四周铺开；纹理边缘落在地平线（天空边界），
  由 `cloudV = 1 - smoothstep(0.55, 0.85, r)` 淡出 → 天空内部无接缝/断层，
  断层只可能出现在地平线（且被淡出掩盖）。纹理四角在 r≤1 时永远不会被采到。
- 数据流向：CloudSolver.getPrevTexture / getCurrentTexture / getBlend →
  RenderManager.follow 每帧喂 SkyDome.setCloudTextures(prev, cur, blend)。
- 水流合成仅在有 step 结算时执行（2 帧/秒配色），copy prev 为一帧内一次全屏 pass。
- 穹顶映射为**世界方向**（`vWorldDir`）而非相机方向 → 云固定在天空，转头不漂。
- 空云兜底用 1×1 全透明 DataTexture，未启用云时无云。

#### 13.4 待调优（未做，预留）
- 低粘度扩散 → 更蓬松 billowy；云遮挡太阳/月亮的投影关系。

### 14. 月亮 = 特效播放器离屏渲染（MoonEffect，2026-09-02 落地）

月亮圆盘从"程序化月相着色器"整体替换为**特效播放器真实资产渲染**——复用
`.scene.zip` 特效包的 base/residual 纹理 + regionEntity 几何 + VAT 顶点动画
（大猫哥的月亮.scene.zip），支持包内全部表现能力（VAT 呼吸/脉动、区域实体、
扭曲）。

#### 14.1 数据流（单向）

```
main.ts: Asset.load("大猫哥的月亮.scene.zip")
  ├─ 检测 regionEntities.length > 0 → 走 MoonEffect（VAT 路径）
  └─ 否则回退旧静态纹理路径（setMoonTexture）
MoonEffect（src/vendor/player/MoonEffect.ts）
  ├─ Asset + FramePlaybackController（帧推进）
  ├─ 共享主渲染器（RenderManager.setup 注入；★不是独立 WebGLRenderer
  │   ——跨上下文纹理不可采样，独立渲染器产出的 RT 在主上下文全透明）
  ├─ renderFrameData → WebGLRenderTarget（bbox 尺寸离屏渲染）
  └─ 渲染前后 setClearColor(0x000000,0) 透明清屏 / 恢复场景背景色
       （★不透明清屏会让月亮 quad 采出方形边缘）
SkyDome
  ├─ setMoonEffect(effect)：保存 _renderer，后到注入（setup 早于 MoonEffect
  │   创建 → 时序上 renderer 先存、setMoonEffect 时补注入）
  ├─ MOON_TEX_FRAG：采样 effect.getMoonTexture()（RT.texture），
  │   alpha=贴图自身（★无光晕/disco 圆盘——曾因整帧空白+光晕出现大白圆）
  ├─ 表面浅色层：贴图色 × 混月白 0xc8d8f0，uTint=moonVisible×0.28（夜显日隐）
  ├─ 外发光光晕 moonGlowMesh：独立 quad（月亮 1.6×），径向渐变 AdditiveBlending，
  │   pow 2.2 衰减，强度 moonVisible×0.55，每帧与月亮同步位置/朝向/宽高比
  └─ ★ 地平线淡出：horizFade = clamp(sin(仰角)×6, 0, 1)——月落与日出同现于
      地平线时，未淡完的月亮不再遮挡太阳（depthTest:false 的天空层无深度仲裁）
```

#### 14.2 内容裁剪（只显示月亮本体）

资产帧内月亮内容只占小部分、四周大量空白 → 整帧渲染会显得月亮很小：

- MoonEffect 构造时遍历**所有帧所有 region boundary 顶点**（标注空间 0..1）取
  包围盒，外扩 5% 余量防 VAT 呼吸位移裁边；**相机只覆盖该包围盒** → 月亮本体
  填满 RT，无空白。
- `getContentScale()`：内容宽高比（最长边归一 1）→ SkyDome quad 按 scale.x/y
  缩放，圆形月亮不被拉成椭圆；最长边 = MOON_RADIUS×2 = 36 世界单位（与旧
  程序化月亮同尺寸）。

#### 14.3 坐标系契约

- 顶点/标注坐标 **Y 向下**（(0,0) 左上）→ 正交相机必须是
  `OrthographicCamera(0, 1, 0, 1, -1, 1)`（top=0 < bottom=1 反直觉但正确）；
  曾用 `(0,1,1,0)` 整月亮翻出视口全透明。
- 消费链：RenderManager.follow(target) → skyDome.updateMoonEffect(scaledDt)
  （推进 VAT 时间 + 离屏渲染）→ skyDome.update（采样 RT 显示）。

#### 14.4 昼夜可见度

`moonVisible = smoothstep` 日落/日出窗口（§12.5 月亮不参与地块光照不变）；
月贴图浅色层/外发光强度统一乘 `moonVisible × horizFade`。
