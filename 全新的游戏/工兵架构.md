## 0. 本次重构定调（2026-09-21）

1. **总攻（assault）= 工兵掩护射手**：停止挖战壕；继续造掩体；向本军**远程小队**靠拢、在其威胁侧充当掩体/盾。
2. **取消"施工方向随危机度调整"**：防线方向只在落地/换落点时确定（扫描走廊轴），此后**不随玩家位置/危机度重排**；删除 `refaceDefense` 整条机构。
3. **成员任务唯一写入口 = 引擎施工指挥层**（现状事实，文档纠偏；队长层不写 taskX/Z）。
4. **战壕深度以"可走入"为硬约束**：坑底不得低于危险阈值（-1.2m），标称 5 遍 ≈ 1.0m（§6）。

## 2. 阶段机 ✅

```
S0 勘察（落地/换落点）──planDefense──▶ S1 施工（掩体+战壕，环序推进）
                                          │ 施工表清空
                                          ▼
                                       S2 防线就绪（一般任务）
总攻(assault) 叠加：SA ── 停挖壕 / 续掩体 / 掩护射手（✅）
```

- `stage: 'S0'|'S1'|'S2'` 目前只由施工表驱动：`S1 → S2` 在 `buildPieces` 清空那一拍（✅）；
- SA 是**叠加态**（由 `battlePosture === 'assault'` 驱动），不覆盖 stage；
- assault 不回退 → "停挖壕"即**本局不再挖**。

## 3. 防线与方向（落地定死）✅

- 防线环/弦的**展开轴** = 落地时 `analyzeLandingTerrain` 的扫描走廊轴 `approachX/Z`；写入 plan 后恒定；

## 4. 施工目标表 buildPieces ✅

生成函数 `regenerateBuildPieces(plan)`：

- 环序 `2→1→0`（外 80m → 中 60m → 内 40m）；
- 每环顺序：
  1. **掩体先行**——每掩位 3 块（沿切线 ±4m），按 `plan.posts` 评分降序；
  2. **战壕直线弦**——4m 步进；半长 内 20 / 中 24 / 外 30m；
  3. **每战壕点朝舰船（落点中心）方向 +5m 一线掩体**（pit/liquid/低于 -1.2m 跳过）——掩体在前、战壕脚底下；
- 空表兜底：沿来向弧线自造掩体（±2 档，40/60/80m）；
- 元素：`{ kind:'cover'|'trench', x, z, ring }`；掩体 1 遍建成，战壕 5 遍；
- ✅ `pri` 施工优先级（2026-09-21）：**0 = 前线掩体（战壕前方 5m，最先部署）→ 1 = 战壕 → 2 = 环上掩体**；
  施工顺序 = 先掩体、再掩体后面挖战壕、最后补环掩体（用户定调："先造掩体，然后掩体后面持续挖战壕"）。

## 5. 调度与施工（2s 决策拍）✅

**冷却**：`buildCds` **每帧递减**（真秒；掩体 3s / 战壕 4s），动作只在 2s 拍上发起。

**队级分派 `assignBuild`**（2026-09-22 修复，`000ebc5`）：保持当前未建块；否则**两段挑**——
① 先只看**本队质心 50m 内**按 pri 挑未认领块（防"全局最低 pri=63m 外前线件"任务瞬移 → 半路折返转圈）；
② 50m 内无件才全局按 pri 兜底。`claimed` 去重（掩体班先铺掩体、战壕班专人持续挖壕）。

**成员分派 `spreadBuilders`**：
1. 本队已派块是**未成战壕** → 全员**静态环列**（整组围挖到成）；
2. 本队 `buildFocus` 未成 → 全员静态环列；
3. 否则每成员就近未认领候选（≤40m，`lineBlocked` 直行遇墙剔除，≥90m 不吃），
   `keepsTask`：目标仍有效就不重写（到达即静立，杜绝转圈）。

**施工循环**（`buildCds ≤ 0` 的施工队）：
- ① **焦点续挖**：焦点块未成且成员 ≤6m → 必须继续；
- ② **就近动工**：成员 ≤5m；**pri 小者先**（前线掩体 > 战壕 > 环掩体）→ 挖痕多者优先 > 近者；
- 掩体：`buildCover` + `markTerrainDirty`，一次建成，cd=3s；
- 战壕：`digTrench`（7×7 面，+1 层 ≈0.2m）逐遍加深，cd=4s；满 `TRENCH_PASSES=5` 记 `builtSlots`。

## 6. 深度与可走入口径 ✅（审计 B1 裁定）

- 标称：5 遍 ≈ 1.0m（实测 1.0–1.2m）；
- **硬约束：坑底高度不得低于 -1.2m**（移动危险判据 `role==='pit' && h < -1.2`）；否则战壕变成硬阻挡，
  远程无法入壕（与总纲 §9 验收冲突）；
- ✅ 已实施：每遍挖前检查坑底高度，低于阈值即封顶（该块记建成，不再深挖）；
- 战壕是**真地形**（`RasterMap.levelDepthAt`），与"工事不阻路"纪律的边界：
  挖掘改变地形属总纲 §5 重规划白名单第 2 条；掩体/墙不参与阻挡。

## 8. 态势联动（新语义）⏳

| 态势 | 工兵行为 |
|---|---|
| fortify / patrol / advance / mass | S1 照常：掩体 + 战壕（环序推进）；方向恒定 |
| **assault（总攻）** | ① **暂停开挖战壕**：只停派活/停挖，**战壕件保留**（从不清空）；② **继续造掩体**：掩体件照常派、照常建（含未建的前线掩体排）；③ **掩护射手**：`ctx.buildSite` 锚定最近**远程小队**质心（施工期与护卫期都生效）；掩体清空（S2）→ 大任务转 `guard`，成员在射手威胁侧护栏弧展开 |
| withdraw | 工兵清任务随撤（⏳ 接线检查） |

**保护动作（✅ 已接线）**：保护对象由引擎配置（`protectAssign`/`ctx.protect`），工兵的动作是 `PROTECT_ACTION = build`——处于 `guard`/`patrol` 任务时，
成员分派优先走 `spreadBuilders`（在保护锚附近找未建掩体施工）；附近无工件才退回站岗扇区。
配合 S1 的 build 任务（锚=射手）即"工兵的保护手段 = 造工事"。

**实现（✅ 已接线）**：assault 时**引擎把工兵的保护对象配为射手**（`protectAssign` source='shooter'，
锚 = 最近远程小队质心，`ctx.protect` 下发）——
掩体未清空时大任务仍为 `build`（成员继续分块造掩体）；清空后 `engineMissionFor` 给 builders `guard`，
`spreadGuards` 以射手为锚写护栏弧。实测：锚与射手质心 0.2–0.4m；护栏期工程队质心距射手 ≈15m
（护栏弧 6m + 2s 决策拍滞后）。
"掩护射手"是**作战定位**（可读玩家方向），与"施工方向恒定"（§3）互不冲突：**规划方向固定，战斗站位动态**。

### 8.1 掩体驻守（远程；引擎命令）✅（2026-09-21）

- **选点（引擎 `updateCoverHolders`，每帧）**：给远程队选"掩体后有战壕"的**配对掩体**（距离带 8~75m）；
- **站位 = 掩体朝外（远离舰船/落点中心）5m = 战壕位**；"掩体在 站位→舰船 连线"上（掩体在前、战壕脚底下）；
- **命令**：`kind='garrison'`（target = 战壕位、threat = 玩家位置；1Hz 无条件重发）→ 队长直接执行站位
  （不再按玩家绕掩体）；玩家换侧站位不变（驻壕而非冲掩体前）；
- 验收（probe-cover）：① 引擎选配对掩体 ② 命令带玩家位置 ③ 站位在掩体后（outward 5m、segD 0）④ 玩家换侧站位不变。
