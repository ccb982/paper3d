## 0. 一句话架构

**水体是地图里的独立实体；所有水体共用一张"公用水纹理"；每个水体独立存储自己的几何与状态。**

```
公用水纹理（静态 clipmap，全局共用）      每个水体（独立存储）              涟漪（世界坐标解析场）
  R=水深 G=到岸距离 B=掩码 A=泡沫/湿边  →  几何：规则网格（body 包围盒内）   →  CPU 池 + 16 槽叠加
        │                                        │                              │
        └──────────── 采样同一 uv / 同一 mip ─────┘                              │
                     ⇒ 岸线只有一处定义 ⇒ 不会有缝                              │
```

**不变的东西**：求解算法（探针/安定/增量 dig）· 水位语义 · 玩法查询接口 · 挖坑联动流程 · worker 协议。

## 3. ★ 定稿架构

### 3.1 三个角色（互不重叠）

| 角色 | 是什么 | 生命周期 | 归属 |
|---|---|---|---|
| **公用水纹理** | 一张**静态**的、覆盖大范围的水体属性图（clipmap 多级） | 随地形（静态，只在新区进入时增量烘） | **全局共用**，所有 body 引用 |
| **WaterBody** | 一片连续水域（跨 chunk 算一片）：成员块集合、**唯一水位 L**、包围盒、几何、uv 变换 | 随世界 | **独立存储**（不挂 chunk group） |
| **涟漪场** | 世界坐标的解析涟漪（CPU 池 + 16 槽叠加） | 瞬态（2 秒） | 全局材质侧 |

> ★ **为什么只有一张新图**：波场（FFT）现状已有且跨 chunk 无缝；属性（图 B）新增；涟漪**不做图**。

### 3.2 公用水纹理（静态 clipmap）

```
通道：R = 水深     G = 到岸距离     B = 掩码(0=水, 1=岸)     A = 泡沫/湿边强度
覆盖：多级 clipmap，每级 512²，按相机位置滚动（每级偏移对齐到 texel）

  级别   覆盖边长   texel      用途
  L0     64 m      0.125 m    近景（岸线精度、涟漪边界）
  L1    256 m      0.5 m      中景
  L2   1024 m      2 m        远景
  L3   4096 m      8 m        极远景

★ 静态：地形不变 ⇒ 内容不变 ⇒ **只在新区进入视野时增量烘**（不是每帧重烘）
★ 增量烘焙的输入现成：settleComp 已算出唇位/干块/水深（WaterSurface.ts:359-432）
```

### 3.3 WaterBody（独立存储）

```ts
interface WaterBody {
  id: number;                 // union-find union-by-min ⇒ 与加载顺序无关，稳定
  blocks: Set<number>;        // 世界块坐标（4m 块）
  level: number;              // ★ 唯一水位 L = min(各分量 L)（水往低处流）
  bounds: { minX, minZ, maxX, maxZ };   // 包围盒（= clipmap 采样与几何的范围）
  chunks: Set<number>;        // 成员 chunk（chunk 卸载时减引用，不销毁 body）
  geo: BodyGeometry | null;   // 规则网格（按 LOD 档重建）
  uvTransform: ...            // body 局部 ↔ 世界 ↔ clipmap uv
}
```

**归属合并**：union-find，**union-by-min**（块坐标字典序小的当 root ⇒ 最终 root 与 union 顺序无关 ⇒ id 稳定可复现）。
表按 chunk 分桶（`blockOwner` / `bodyOfChunk` / `bodies`），随 chunk 卸载可回收。

### 3.4 数据流

```
① 生成（不动）
   TerrainPresets → blockTypes[TILE_WATER]
② 求解（不动）
   ChunkManager → terrainPatch worker → buildWaterSurface(table, src, patch)
                    └─► WaterSurfaceRaw（per-chunk，含 deep/border/level）
③ ★ 新增：归并 + 烘属性图
   raw → ① 块归属 union-find  ② body.L = min(各分量 L)  ③ 块数据 → 公用水纹理（增量烘）
④ ★ 新增：独立渲染
   body → 规则网格（body 包围盒内）→ 挂 WaterStore 的独立 group
         顶点：y = body.L + FFT 位移（世界空间）+ 涟漪场
         片元：alpha = 掩码（clipmap 采样）+ 泡沫/湿边 + 水体着色
⑤ 挖坑（不动）
   dig → waterSolve worker → 新 raw → 回到 ③
```

### 3.5 ★★ 岸线与缝隙（核心问题）

#### 问题的精确表述

「公用水纹理内部的掩码」与「外部靠近岸边单独算的部分」之间可能有缝。

#### 三个根因

| # | 根因 | 为什么会错位 |
|---|---|---|
| **① 精度不同** | 纹理掩码边缘 0.125m 级；水面几何边缘 1m/4m 级 | 同一条岸线被两种精度各描述一遍 ⇒ 错位 |
| **② 采样不同** | 水面层与近岸层取到不同 mip / 不同 uv 变换 | 同一世界点采到不同掩码值 ⇒ 错位 |
| **③ 语义不同** | 水面用「掩码=0」，近岸用「到岸距离<阈值」 | 两个判定标准各判各的 ⇒ 错位 |
| **④ ★ 位移不受岸线约束**（现状已存在） | FFT 位移有 `border < 0.5` 约束（`WaterMaterial.ts:273`），**涟漪 shake 没有**（`:270-271`，注释明说「不再受 border 静止约束」）；片元涟漪法线也没有（`:448-457`） | 涟漪把**岸边顶点抬起来**、岸线像素法线被打乱 ⇒ 岸线抖动/锯齿 ⇒ 看起来就是「岸线有缝」 |

> ★ **根因 ① 是致命的**：只要在 **CPU 侧按掩码裁几何**，边缘精度就等于几何精度，**永远对不上纹理边缘** ⇒ 必然有缝。

#### 解法（五条，一起才成立）

| # | 解法 | 消灭哪个根因 |
|---|---|---|
| **A. 单一岸线真源** | 岸线**只由公用水纹理的掩码定义**。所有层（水面/近岸/水帘）采样**同一 uv、同一 mip 级** | ② ③ |
| **B. 几何不裁、像素裁** | 水面几何 = 规则网格**全覆盖** body 包围盒，**不做 CPU 侧掩码裁剪**；片元里 `alpha = mask`（`discard` 或 blend） | **①（致命项）** |
| **C. 近岸是叠加层，不是拼接层** | 近岸**不另起几何与水面拼**，而是**同一张网格上多画一层**（泡沫/湿边/亮边），由同一掩码的「近岸带」（G 通道 < 阈值）驱动 | ③ |
| **D. 边界处重叠 + 交叉淡化** | 若确有必须分离的几何（如竖直的水帘），在分界处让两层**重叠一小段**，并用**同一掩码值**做 alpha 交叉（一层淡出、另一层淡入）⇒ 数学上连续 | ① ③ |
| **E. ★ 所有几何位移都服从掩码** | **FFT 位移与涟漪位移用同一把尺子**：用 G 通道「到岸距离」调制 ⇒ 离岸近时位移衰减到 0 ⇒ 岸线顶点完全不动 | **④** |

#### ★ 涟漪与公用水纹理的关系（不是「替代」，是「叠加」）

```
公用水纹理（静态空间属性）：水深 / 到岸距离 / 岸掩码 / 泡沫   ⇒ 决定「水在哪儿、多深、离岸多远」
涟漪场（动态扰动）：      波高 / 法线                        ⇒ 决定「水此刻怎么动」
FFT 海况（现状已有）：     波高 / 法线                        ⇒ 大尺度海况
```

**原则：涟漪只改「水怎么动」，绝不改「水在哪儿」。**
- 岸线（alpha）**只**由公用水纹理决定 ⇒ 涟漪再猛也撕不开岸线
- 涟漪在采样层面与公用水纹理**同源**（同一个世界坐标 → 同一个 clipmap uv）⇒ 天然无缝
- ⇒ **不需要**把涟漪塞进公用水纹理（那会把「静态增量烘的 clipmap」变成「每帧要写的动态图」+ ping-pong，更贵）

#### 判据（可测，不是"看着像"）

| 判据 | 做法 |
|---|---|
| **掩码一致性断言** | 探针：对同一世界点，水面层与近岸层采样到的掩码值必须**逐位相等**（同 uv、同 mip）⇒ 不等即 FAIL |
| **岸线零位移断言** | 探针：在掩码=岸 的像素上，涟漪位移与 FFT 位移之和必须 **= 0**（岸线顶点完全不动）⇒ 不等即 FAIL（现状会 FAIL） |
| **边缘连续性** | 岸线处放大 4 倍截图，检查有无 1px 亮/暗缝 |
| **无 CPU 侧裁剪** | 代码审查：`WaterSurface` 侧不得再出现「按掩码决定三角形取舍」的逻辑（现有 `filled` 标记要退化为「只发水块」而不是「决定边缘」） |

> ★ **一句话**：**只要"裁剪"发生在片元 alpha，而不是几何取舍，缝就不可能存在** —— 因为那时边缘的分辨率是像素，与掩码完全同源。

### 3.6 LOD

| 档 | 距离 | 几何 | clipmap 级 | 波场 | 涟漪 |
|---|---|---|---|---|---|
| L0 近 | < 80m | 1m 网格（body 内按 16m tile 分片） | L0 | 三层全量 | 采 |
| L1 中 | 80~250m | 4m 网格（整 body 合并） | L1 | L0+L1 | 采 |
| L2 远 | > 250m | 整 body 一个 quad | L2/L3 | 静态基准面 | 不采（远处看不见） |

- 切换：滞回带（对齐地形 60/70m 做法）+ **分帧预算**（每帧最多重建 N 个 body）
- ★ **离屏图 = 内容，LOD = 采样精度**，两者正交（比"raw 后处理降采样"干净）

### 3.7 生命周期与 chunk 解耦

| 事件 | 现状 | 目标 |
|---|---|---|
| chunk `park`（>4 块） | 水 mesh 随 group 离场 | **水不动** |
| chunk `destroy`（>6 块） | 水几何被 dispose | **不动水**；只从 `body.chunks` 减引用 |
| chunk 重建 | 水重算 | 不变 |
| 挖坑 | 水重解该 chunk | 不变（worker 协议不动） |
| 模式退出 | 水随 chunk dispose | `WaterStore.dispose()` 一次性释放 |

### 3.8 涟漪（不做图，世界坐标解析场）

```
CPU 侧 RipplePool（容量 64~128）：{ x, z, t0, strength, kind }   ← 世界坐标
每帧：① 淘汰 age > 2s  ② 按到相机距离排序  ③ 取最近 K=16 写 uniform
Shader：for (i < K) h += impactRing(worldXZ, slot[i])   ← 线性叠加 = 天然干涉
        ★ 距离早退：|d| > 4.4m 跳过 ⇒ 实际进入循环的顶点极少
        ★★ 岸线约束（E）：用 clipmap 的到岸距离 G 通道调制 ⇒ 离岸近 → 位移衰减到 0
           （★ 现状涟漪**没有**这个约束 → 岸边顶点被抬起 → 岸线看起来有缝；见 §3.5 根因④）
「更真实」三件事：
  ① 叠加干涉（不再是「槽满覆盖」）
  ② 岸反射/吸收（用 clipmap 的到岸距离 G 通道调制）
  ③ 浅水减速（波速 ∝ √(gh)，用 R 通道水深调制）
```

> ★ 涟漪与公用水纹理是**叠加**关系，不是替代：公用水纹理决定「水在哪儿」，涟漪决定「水怎么动」；
> 岸线（alpha）**只**由公用水纹理决定 ⇒ 涟漪再猛也撕不开岸线。

## 5. 风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| **岸线外观回归** | 规则网格 + alpha 裁剪 ⇒ 岸线从 4m 块状变 0.125m 平滑 | 必然发生（P2 的目的就是变好看）；离屏截图对比闸门 |
| **公用水纹理内存** | 每级 512²×4B = 1MB，L0~L3 = 4MB + 每 body 引用 | 静态共享 ⇒ 总量固定；clipmap 只需 4 级 |
| **增量烘焙成本** | 新区进入视野时烘 | 静态 ⇒ 只在新区发生；可分帧摊销 |
| **涟漪槽位着色开销** | K=16 × 每顶点循环 | 距离早退 ⇒ 实际 1~2 次；微信小游戏端实测 |
| **涟漪池淘汰策略** | 池满丢哪条 | 按「age 过期 + 距离最远」；强度高的（子弹 1.4）加权保留 |
| **微信小游戏端 RT 限制** | 多 RT 带宽/内存 | 只新增 1 类 clipmap RT（4 级 512²）；涟漪不占 RT |
| **求解态仍分裂在两个 worker** | 首建在 terrainPatch 池、破坏在 WaterSolve | 本期不动（其他不变）；独立存储后挪主线程很容易 |
| **uTime 基准** | 涟漪年龄 = `uTime − 起始时刻` | ✔ 已确认一致（都是 `performance.now()*0.001`，`TerrainMaterial.ts:1254`） |
