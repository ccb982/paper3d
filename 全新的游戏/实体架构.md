# 实体架构 —— 类树重构 + 蜂群适配（2026-09-18 设计稿，待实施）

> 本文是实体层（entity/）类树与生命周期的唯一设计权威。
> 关联：《蜂群架构.md》（敌人系统 / LOD / v2 编队与寻路唯一权威）、
> 《开发说明书.md》（总体分层 / 实体管线 / 战斗与掉落管线）、
> 《地形与渲染管线架构.md》（地形查询 / 空间索引 / 渲染管线）。
>
> **决策记录（2026-09-18 用户拍板）**
> - **类树形态**：`EntityBase → CharacterBase → { EnemyBase / AllyBase / Player }`
>   —— 保留 CharacterBase 中间层（角色运动/地形/受击表现是三方共用的真公共代码）。
>   ★ 实施修正（E2）：见 §6.2/§6.6。
> - **文档载体**：新建本文档，不把玩家/友军塞进《蜂群架构.md》；
>   蜂群 v2 只负责"逻辑归属与寻路"，实体侧负责"载体与骨架"，两边正交。
> - **重构纪律**：E0~E2 阶段是**纯搬运**（行为零变化，只拆文件/拆职责）；
>   **E3 起才允许动行为**（引入蜂群接口/编队移动来源）。
> - ★ **管线设计（2026-09-18 追加拍板）**：实体管线改**显式六相**（输入→大脑→模拟→战斗→
>   升降格桥接→表现），生命周期改**状态机 + 退役原因**，销毁与业务事件解耦；
>   所有"会改实体集合"的操作集中到**唯一桥接相位**，为蜂群 v2 的
>   升格/降格/编队下发留好标准接口（见 §9）。
> - ★ **字段预留（2026-09-18 追加拍板）**：敌实体先落**非可选**字段——编队层次
>   （battalionId/squadId/formSlot/corridorIdx）、载体（carrier）、飞天（isAir/altitude）、
>   移动位置（moveTarget）、攻击类型（attackType）与 role；默认值、行为零变化，
>   v2 由 `SwarmTierPort` 填值（见 §5.3）。
> - ★ **实施顺序（2026-09-18 四次拍板）**：**先重做玩家与友军基类**——
>   友军分**飞天 / 陆地跟随 / 陆地站桩**三类；玩家要求**架构独立**（不与敌友耦合）。
>   **敌人基类（EnemyBase）本轮不动**：它后续要接蜂群 v2 的大量内容，
>   等 v2 启动时与 E3/P4 一起做。**装备/弹药类实体不在重做范围**。
> - ★ **敌人基类 v2 定稿（2026-09-19 拍板）**：**单一单位模型**——代理与实体是同一
>   `SwarmUnit` 的 `dormant/active` 两态（代理具备全部能力、只是被门控）；
>   `EnemyBase` = 表现载体（血条/影子/受击染料/死亡动画/帧）+ 基础行动/攻击 +
>   **常开感知**，行为归蜂群引擎；小队**同质**（一队一兵种 4~12）、Boss/高威胁**单例**；
>   指挥权 `leaderUid` 只挂 active、Phase 4 原子转移、代理被击可升格接管；
>   情报**个体→小队→大队**（战略级全知仅用于寻路目标）。详见 §5。
>
> **一句话**：把"上帝基类"拆成三段——EntityBase 只做载体骨架、
> CharacterBase 只做角色运动与表现、三个阵营基类各自管自己的驱动方式；
> 管线改"显式相位 + 幂等退役"，让 L3 敌人成为蜂群引擎可随时接管/交还的
> **标准载体**（steer / 快照 / 编队字段 / 退役原因），
> v2 编队引擎落地时**不需要再动实体类树和管线顺序**。

## 1. 现状瓶颈

### 1.1 代码证据（2026-09-18）

| 类 | 行数 | 混了哪些职责 |
|---|---|---|
| `EntityBase` | 542 | 骨架 + 贴地剪影影子（≈128 行）+ 附属特效槽 + **完整战斗属性**（hp/攻防/暴击/闪避/格挡/效果列表——子弹/物品也背）+ 流体钩子 + 生命周期 |
| `CharacterBase` | 568 | 移动控制器 + 地形立面/空中层 + 角色间/装饰物推挤 + **受击染料流体（≈157 行）** + 死亡动画 + 影子声明 |
| `EnemyBase` | 426 | AI 状态机驱动 + **危害地形扫描（≈90 行，与代理层重复）** + 相机帧/朝向/扭曲 + 眩晕 + 击杀统计 |

### 1.2 真正的病灶（不是"EntityBase 一个类太大"）

| 症状 | 证据 | 后果 |
|---|---|---|
| **载体骨架 / 角色运动 / 阵营驱动 三段混在一起** | `EnemyBase.moveBy` 既做 AI 移动、又做地形危害探测、又做贴片朝向；`WorldMode` 还要帮友军注入回调 | 加一个兵种/友军要动 3 个类 |
| **双轨行为分叉** | 代理层（`SwarmSystem`/`AgentPool`）与 L3（`EnemyBase` + `AISystem`）各有一套危害探测/游走/追击 | 改一处忘一处；升降格后行为漂移 |
| **友军无基类** | `DroneEntity` 里 6 个回调 + `stationary` 布尔分叉 | 第二种友军只能复制整个类 |
| **蜂群 v2 字段无家可归** | `squadId/uid/formSlot/corridorIdx/role` 在 `AgentPool` 侧已设计（《蜂群架构.md》§16.2），实体侧没有对应物 | 升格丢编队 → 队伍散架（v2 铁律 1） |
| **公共表现代码不可复用** | 受击染料/死亡动画/影子都写死在两个基类里 | 友军/NPC 想用只能复制 |
| **`AISystem` 只收 `EnemyBase`** | `AISystem.ts:11` | 与"敌人/友军共用行为库"的文档口径不符，友军只能另写 |

### 1.3 重构目标（验收口径）

- 三个阵营基类各自只回答一个问题：**"谁在驱动我"**（AI / 世界端口 / 输入）。
- L3 敌人 = 蜂群引擎的**表现载体**，不是独立 AI 权威；v2 编队字段跨 LOD 无损。
- 行为零变化地完成 E0~E2；E3~E4 的改动全部有降级链兜底、可逐阶段回滚。
- `npx tsc --noEmit` 零报错、`npm run guard` 通过；每阶段"能玩、能看、能测"。

## 2. 目标类树与职责边界

### 2.1 类树

```
EntityBase（载体骨架：你是谁、在哪、怎么显示、怎么销毁）
 ├─ ItemBase / BulletEntity / ShipEntity / NpcEntity / DecorEntity   ← 装备/弹药不动
 ├─ StructureEntity（★ 新增，v2 §22 工事：固定刚体 + 可 applyDamage + 不进 AI/编队）
 ├─ AllyBase（友 · ★ 本轮重做：三种骨架；直连 EntityBase，见 §6.6）
 │    ├─ AirAlly（飞天）────────► DroneAlly（原无人机）
 │    ├─ GroundFollowAlly（陆地跟随）
 │    └─ GroundStationaryAlly（陆地站桩）──► SentinelAlly（原祖宗）
 └─ CharacterBase（角色运动层：怎么走、怎么被地形挡住、挨打怎么演）
     ├─ EnemyBase（敌：个体战斗 AI + 蜂群代理投影 + 编队字段）★ 本轮不动，随 v2 做
     │    └─ 飞行兵不单开子类：`airborne + role:'flyer'` 标记（v2 §25）
     ├─ Player（★ 本轮架构独立：entity/player/ + systems/player/PlayerPipeline）
     └─ VisitorNpcBase（非战斗角色：访客/事件 NPC，沿用 CharacterBase 管线）
```

### 2.2 职责边界（写代码时对照这张表）

| 层 | 只管 | 绝不管 |
|---|---|---|
| **EntityBase** | Entity 容器/位置/camp、物理同步模式（none/kinematic/read）、动画管线（anim/state）、渲染器生命周期、特效槽、LOD/视锥/影子**调度**、`dispose/onDeath` 骨架、`hitAnchorY/minimapInfo` | 角色移动、输入、AI、地形规则、战斗结算、具体渲染实现 |
| **CharacterBase** | `CharacterController`、碰撞体积/kinematic、贴地与立面规则（`blockCliffClimb`/`airborne`）、角色间/静态物推挤、受击表现（染料/死亡动画）、贴片缩放与影子声明 | 阵营、索敌、攻击意图、输入语义、蜂群编队 |
| **EnemyBase** | 个体战斗 AI（状态机/攻击节奏/眩晕）、敌人显示帧与朝向、击杀统计、蜂群代理投影（快照出入） | 全局寻路（HPA/流场）、编队决策、地形危害全局探测 |
| **AllyBase**（EntityBase 直连） | 世界端口（索敌实体+代理双通道/攻击结算/挖矿）、攻击节奏、跟随锚点/基座、槽位与存活、光束/影子表现、三种运动骨架（§6） | 玩家输入、蜂群编队（远期可选才接）、地面角色规则（陆地骨架接入时再定，§6.6） |
| **Player** | 输入驱动、载具、死亡/复活、操作锁 | 任何 AI/编队逻辑 |
| **systems/swarm** | 编队/寻路/攻击槽/导演/代理池 | 实体类内部状态（只经标准接口：snapshot / steer / combat 字段） |

### 2.3 依赖方向（保持既有分层不破坏）

```
modes（WorldMode）
  → spawn（WorldSpawner：创建/升格/降格实体）
  → entity（类树；不 import systems/swarm 的运行时代码）
systems/swarm → hooks（promote/demote 回调，由 modes 装配）→ spawn → entity
services ← entity（渲染/物理/战斗/特效；entity 不反向引 modes/ui/swarm）
```

★ **铁律**：`entity/` 永远不 import `systems/swarm/`。
蜂群要的东西通过 `hooks.promote/demote` 与数据接口进入；实体的状态通过快照/公共字段出去。

## 4. CharacterBase 收口

保留角色公共能力（三方真正共用的部分）：

1. **运动**：`CharacterController`（移动/跳跃/朝向/攻击动作）+ `moveDir` 速度驱动。
2. **地形**：`climbAnyTerrain` / `blockCliffClimb`（只走插值坡）/ `airborne`（空中层，v2 §25 已就绪）。

不再往 CharacterBase 加任何阵营/玩法语义。

## 5. EnemyBase（敌人）

> ★ **2026-09-19 定稿：单一单位模型 + 载体定位**（E3b/E4/E5 分步实施；实施前保持现状）
> 敌人不是"代理 or 实体"两种兵，而是同一个 `SwarmUnit` 的两种**激活态**；
> `EnemyBase` = 该单位在 L3 的**载体**（表现 + 基础行动/攻击 + 常开感知），
> **行为归蜂群引擎**（去哪、编队、集火、姿态、情报汇聚）。

### 5.1 定位与能力门控（activation）

| 能力 | dormant（代理 L1/L2） | active（L3 实体） |
|---|---|---|
| 跟随指挥 / 消费 steer | ✅ | ✅ |
| 被击感知 / 听警报 / 短距直觉（`PROXY_INSTINCT_R` ≤5m） | ✅ | ✅ |
| 长距索敌 / 主动 LOS | ❌ 关 | ✅ |
| 完整 AI 状态机 | ❌ 关（只跑极简 follow + 到期攻击） | ✅ |
| 指挥资格（`leaderUid` 可指向） | ❌ 关 | ✅ |
| 高保真战斗（攻击槽/令牌/真弹道） | 简化（到期结算） | ✅ |
| 表现（血条/影子/受击染料/死亡动画/帧/扭曲） | ❌ | ✅ |

- **状态属于逻辑单位**（血量/属性/感知/AI/编队/意图），跨 LOD 全程保留：
  降格不失忆、升格不重置。
- **EnemyBase 的三块职责**：
  1. **表现载体**：`HealthBar` / `SilhouetteShadow` / `CharacterHitDye` / `CharacterDeathFx` /
     帧与扭曲 / 小地图 / LOD 档位（§5.6）；
  2. **基础能力**（swarm 失联也不停摆）：游走/巡逻、直线追击、近战挥击/远程射击
     （节奏+冷却）、受击/眩晕/死亡、贴地、**2m 局部避障**；
  3. **常开感知**：自身索敌半径 + 事件感知（被击/听警报），写入小队情报（§5.4）。
- **内部结构（E5 组合件拆分，纯搬运）**：`EnemyBrain`（战斗决策，只产意图）/
  `EnemyLocomotion`（消费 steer 或本地兜底）/ `EnemyPresentation`（按 viewLod 的表现档）。

### 5.2 移动来源三态（★ v2 适配核心）

现状：`EnemyBase.moveBy` 自己探测坑/水/立面（`isDangerAhead`，≈90 行），与代理层重复。
目标：**移动决策上移，实体只消费 steer**。

```ts
// CharacterBase 统一移动入口（E3）
export interface SteerIntent {
  dirX: number; dirZ: number;   // 单位方向（0,0 = 停）
  speed: number;                // m/s（0 = 停）
  /** formation=编队槽位 / flow=流场 / local=本地 AI / none=停 */
  source: 'formation' | 'flow' | 'local' | 'none';
}
```

| 来源 | 谁下发 | 实体做什么 |
|---|---|---|
| `formation`（v2 F1+） | `SwarmSystem`：编队槽位目标 / corridor 车道 | 转向 + 速度积分 + **最后 2m 局部避障** |
| `flow`（现状降级链） | `FlowField` 梯度 | 同上 |
| `local`（AI 兜底） | `EnemyBase` 自身（游走/直扑 + 极近避障） | 同上 |
| `none` | 眩晕/死亡/ROE 停火补位 | 不位移（但仍允许转向/索敌） |

- 危害地形探测（坑/深水/立面）**统一收进 swarm 层**（流场代价 + HPA 代价已编码），
  实体侧只保留 **2m 级局部避障**（防贴墙抖动，属于运动层）。
- `EnemyBase.moveBy` 保留为兼容入口（E3 内部转发到 `applySteer`），E4 后删除。
- 降级链（v2 §15.6）在 swarm 层：HPA corridor → 流场 → 直线；**任何一层都不能让敌人停摆**。

### 5.3 蜂群字段（★ 在 EnemyBase 上先预留，v2 填值）

> ★ **E3a 已落地（2026-09-18）**：`entity/SwarmUnit.ts`（`UnitRole/UnitAttackType/
> SteerIntent/SwarmUnit/SwarmSnapshot/SwarmCarrier`）+ `EnemyBase implements SwarmCarrier`
> （字段默认值 + `applySteer/hasFreshSteer/hydrate/drain`；`isAir/altitude` 转发
> `airborne/airAltitude` 单一事实源）；`AgentSnapshot extends SwarmSnapshot`；
> `WorldSpawner` 升格 `hydrate(snap)`、降格 `...e.drain()`；`MobDef.role/attackType` 透传。
> **E3b（AgentPool 新增列 + 快照感知/AI 连续性 + 指挥权 + 被击升格 + `SwarmTierPort`）随 v2 一起做**（详见 §5.7）。

**预留策略**：E3 先落字段并给默认值（散兵 / 未编队 / 地面），**行为零变化**；
F0/F1 起由 `SwarmTierPort` 在升格 `hydrate` / 降格 `drain` 时统一写入。
实体永远**不主动查询 swarm**（依赖方向铁律），所有值随快照进出。

```ts
// ★ 兵种角色 / 攻击类型：实体侧用可读联合类型；AgentPool SoA 用 Uint8 常量
```

### 5.4 感知与情报（个体 → 小队 → 大队）

```

```

- **成本红线**：不做逐个体 LOS；小队级 LOS 预算 + 事件驱动；合并 O(n) 零分配。

### 5.5 指挥权（`Squad.leaderUid`）

- 指挥权**只挂 active 单位**（dormant 无资格）；单例小队 `leaderUid` = 自身。

1. **实体集合只在 Phase 4 变**：Phase 1~3 只允许标记 `pendingRetire / pendingPromote`，

2. **Brain 与 Simulate 分离**：决策频率（10/5/2Hz）与执行频率（60Hz）解耦；
   `SteerIntent` 是 **hold 语义**——swarm 下发后实体每帧保持执行，直到被覆盖 / 超时 / `clearSteer()`。

### 9.3 生命周期：状态机 + 退役原因（✅ P2 已实施）

```ts
// entity/EntityBase.ts
export type EntityLifeState = 'active' | 'retiring' | 'disposed';

/** ★ 退役原因 = 业务语义的唯一来源（取代 killedByCombat/deathReported） */
export type RetireReason =
  | 'killed'        // 战斗致死：emit killed / 掉落 / 死亡动画 / 击杀统计
  | 'demoted'       // 降格回代理池：先 drain 快照，再释放（不算击杀、不掉落）
  | 'recycled'      // 远距/超时回收：不算击杀、不掉落
  | 'despawned'     // 主动移除（导演收手 / 登船收友军）
  | 'mode_cleanup'; // 模式切换 / 场景卸载

retire(reason: RetireReason): void {
  if (this._life !== 'active') return;   // ★ 幂等：任何路径重复调用都安全
  this._life = 'retiring';
  this.retireReason = reason;
  this.onRetire(reason);                 // 子类业务钩子（emit 统计/槽位联动）
  this.dispose();                        // 资源释放（幂等；不再发业务事件）
}
```

**实施记录（P2）**：
- `dispose()` → 幂等纯资源释放；`onDeath` 默认走 `retire('killed')`（Player 覆写不调 super = 不死）。
- `EnemyBase.onRetire('killed')` 发 `enemy_killed`；降格/回收/清场 reason 不同 → **天然不计击杀**。
- `WorldSpawner` 降格改 `retire('demoted')`、无定义清理 `retire('recycled')`；
  `EntityManager.clear` → `retire('mode_cleanup')`；`AllySystem.disposeAll(reason)`。
- `killedByCombat / deathReported` 双布尔**已删除**。
- ⏳ `pendingRetire` 延迟队列与 Phase 4 统一 flush 属 **P3 相位切分**（当前 retire 同步执行，
  行为与旧路径一致；相位化不改业务口径）。

### 9.4 ★ 蜂群桥接接口（`SwarmCarrier` / `SwarmTierPort`）

> §10 定义**字段与快照内容**；本节定义**管线怎么把它们接起来**。
> `SwarmCarrier` 的字段面 = §5.3 `SwarmUnit`（`swarmUid / carrier / activation / isLeader /
> battalionId / squadId / formSlot / corridorIdx / role / isAir / altitude / moveTarget / attackType`），
> **全部非可选、有默认值**。

```ts
// entity/SwarmCarrier.ts —— L3 实体实现（EnemyBase；友军远期可选）
export interface SwarmCarrier extends SwarmUnit {
  controlSource: 'swarm' | 'local';             // ★ 唯一控制权切换点
  applySteer(intent: SteerIntent | null): void; // Phase 1→2：swarm 下发（hold 语义）
  hydrate(snap: AgentSnapshot): void;           // Phase 4 升格：快照灌入实体
  drain(): AgentSnapshot;                       // Phase 4 降格：实体抽干为快照
  retire(reason: RetireReason): void;           // 统一退役入口（§9.3）
}

// systems/swarm/SwarmTierPort —— 唯一桥接点（WorldSpawner 实现，modes 装配）
export interface SwarmTierPort {
  promote(snap: AgentSnapshot): SwarmCarrier | null;  // 建实体 + hydrate
  demote(carrier: SwarmCarrier): void;                // drain + AgentPool 回池 + retire('demoted')
  entityCount(): number;                              // 升格预算 / L3 上限判定
  canPromote(): boolean;                              // PROMOTE_PER_FRAME / L3_CAP
}
```

**控制权铁律**：

| controlSource | 移动来源 | 本地 AI 保留 |
|---|---|---|
| `'swarm'`（v2 F1+） | `applySteer` 下发的 `SteerIntent`（编队槽位 / 走廊车道） | **只保留战斗决策**（攻击节奏/眩晕/ROE），不再自己选路 |
| `'local'`（现状 / 降级） | `EnemyBase` 自身 AI（流场/直线 + 2m 局部避障） | 全部（现状行为） |

- 控制权切换**只允许在 Phase 4（Bridge）发生**；Phase 1~3 内切换 = 未定义行为。
- `steer` 超时（`STEER_TTL`，默认 0.3~0.5s 未刷新）自动回落 `'local'`
  —— **任何情况下不停摆**（对齐 v2 §15.6 降级链）。
- 升格预算 / L3 上限由 `SwarmTierPort.canPromote()` 判定，
  **不在 SwarmSystem 里直接数实体数组**（消灭 `enemies.length` 与 `bases` 双账本）。

## 10. ★ 蜂群适配（与《蜂群架构.md》v2 的接口契约）

### 10.1 正交性（v2 §12 铁律的实体侧表述）

```
表现载体（L1 代理 / L2 代理 / L3 实体）  ×  逻辑归属（Battalion / Squad / 个体）  ×  阵营
```

- 一只敌从 L1 走上 L3，**编队归属不变**（`squadId/formSlot` 跨升降格无损）。
- 实体类树**不因 LOD 分层**（不存在 L1Enemy/L3Enemy 两个类），只存在"同一实体 + 代理快照"。

### 10.2 跨 LOD 快照必须无损（v2 §16.3 的实体侧责任）

```ts
// systems/swarm/AgentPool.ts —— ★ E3a 起 extends SwarmSnapshot（entity/SwarmUnit.ts，单一事实源）
export interface AgentSnapshot extends SwarmSnapshot {
  // …现有字段（位置/血量/属性/意图/空中层）…
  /** ★ v2：编队字段（升格 hydrate 灌入实体；降格 drain 从实体读回。缺省 = 散兵） */
  uid?: number;
  /** ★ 大编队副本（权威在 Squad.battalion；仅搬运，不反推） */
  battalionId?: number;
  squadId?: number;
  formSlot?: number;
  corridorIdx?: number;
  /** ★ v2：现有缺失项也要补齐（否则降格靠模式层猜） */
  intent?: number;
  bias?: number;
  aggro?: number;
  wanderSpeed?: number;
  /** ★ 兵种角色（也可经 mobIndex → MobDef.role 取，随 v2 定） */
  role?: UnitRole;
  /** ★ 移动位置（编队/走廊下发并保持的目标点；缺省 = 无目标） */
  moveTargetX?: number;
  moveTargetY?: number;
  moveTargetZ?: number;
  /** ★ 攻击类型（none/melee/ranged/bombard；缺省 = 从 MobDef 推导） */
  attackType?: UnitAttackType;
  // ---- ★ 2026-09-19：单一单位模型（指挥/感知/AI 连续性） ----
  /** 是否本队队长（指挥权标记；dormant 恒 false） */
  isLeader?: boolean;
  /** 感知（逻辑单位状态，跨 LOD 保留） */
  lastSeenX?: number;
  lastSeenZ?: number;
  lastSeenAt?: number;
  aggroFrom?: number;
  /** 休眠 AI 状态（降格抽干 / 升格回灌 → 不失忆、不重置巡逻） */
  aiStateIdx?: number;
  aiTimer?: number;
}
```

**实体侧义务**：
1. `EnemyBase.hydrate(snap)`：构造/升格时灌入全部字段（含编队/意图/感知/AI 状态），一个不漏；
2. `EnemyBase.drain()`：降格时抽干全部字段 → `AgentSnapshot`；
3. 升降格唯一桥接：`SwarmTierPort`（现由 `WorldSpawner` 实现，见 §9.4）；
4. **禁止**在实体上另存一套与 `AgentPool` 冲突的运行时状态（单一事实源）；
5. **激活态不存快照**：`activation` 由载体派生（池=dormant / 实体=active）。

### 10.3 战斗与寻路的分界（v2 铁律 5）

| 事项 | 归属 |
|---|---|
| 编队去哪 / 从哪包抄 / 阵型槽位 | swarm（Battalion/Squad/corridor） |
| 攻击槽 / 攻击令牌 / 集火 | swarm（`AttackSlots`，L3 与代理共用同一套协调） |
| 近战挥击 / 远程弹道 / 攻击节奏 | entity（`executeAttack` + `AIStateMachine`） |
| 伤害结算 | `applyDamage` / `killed`（不变） |

★ `attackType` 只决定走哪条**攻击结算分支**（melee/ranged/bombard）与攻击槽分圈（近战内圈/远程外圈）；
**打谁**仍由攻击槽/编队/警戒场决定，实体不自己选目标类别。
L3 实体**不做全局寻路**（不跑 A*/流场采样）；需要移动时读 swarm 下发的 `SteerIntent`/`moveTarget`。

### 10.4 空中层（v2 §25）

- 基础设施已就绪：`CharacterBase.airborne/airAltitude`、`AgentPool.isAir/altitude`、名册 `isAir`。
- 飞行兵 = `EnemyBase + isAir + role:'flyer'`；**不进地面 corridor / 车道 / 工事代价 / 陷阱**。
- 导航 = 直线 + 避障（高于飞行高度的地形/建筑），由 swarm 空中层负责；实体只执行。

### 10.5 友军与蜂群

- 蜂群引擎本阶段**只服务敌人**；友军编队化（护送、协同包抄）是远期玩法，**不在本次重构范围**。
- `AllyBase` 预留 `SwarmUnit` 兼容位，未来若要友军编队，只加一个友军版 coordinator，不改类树。

### 10.6 性能口径（沿用《性能评估报告》与 v2 预算）

- L3 上限 30、升格预算 ≤2/帧、降格滞回 30/40m —— 实体侧不新增每帧全量遍历。
- `entityPerf` 分项继续统计行为/物理/动画/渲染/影子；E1 搬运不得改变计时口径。

## 11. 冻结契约（不得破坏）

1. `applyDamage` / `killed` / `damage` 事件、`sameTeam` 阵营过滤（player/ally 互免）。
2. `EntityManager.update/renderAll` 是实体管线唯一入口；`inFrustum/lodExempt` 语义不变。
3. `RasterMap` 统一空间层（实体索引/查询）；`querySphere/queryRay` 行为不变。
4. `hitAnchorY()`（受击锚点）、`minimapInfo`（含 `hideOnMap`）、`visible` 语义不变。
5. 升格/降格桥接点唯一：`SwarmTierPort`（现由 `WorldSpawner.promoteAgent/demoteFarEnemies` 实现）。
6. 击杀统计口径：远距回收**不算击杀**（P9）；`enemy_killed` 只在真死亡发一次。
   统一读 `retireReason`（P2 已落地，§9.3）。
7. 存档不存任何运行时实体状态/代理/编队（v2 铁律 7）。
8. AI 行为库（`behaviorTable/conditionTable`）敌友共用，加内容=改配置。
9. 玩家 `lodExempt`、无人机 `lodExempt`（动画时钟不得冻结）。
10. 重构期间：E0~E2 只允许"搬运 + 转发"，禁止顺手改数值/时序。
11. ★ 生命周期唯一入口 `retire(reason)`（§9.3）：`dispose` 只释放资源、不发业务事件；
    任何路径不得绕过 / 重复执行。
12. ★ 管线六相顺序（§9.2）为硬契约；**实体集合只在 Phase 4 变动**（Phase 1~3 只标记）。
13. ★ 控制权（`controlSource`）只在 Phase 4 切换；steer 断开自动回 `local`
    —— **任何情况下不能让敌人停摆**（v2 铁律 3）。
14. Phase 4 桥接唯一走 `SwarmTierPort`；禁止在其他相位 create/dispose 敌人实体。

## 13. 风险与取舍

- **重构期行为漂移**：E0~E2 强制"纯搬运"，禁止顺手改逻辑；每步跑行为对照。
  → 一旦发现差异，先回滚再定位，不"边修边重构"。
- **AllyBase 抽象过度**：飞天 / 陆地跟随 / 陆地站桩三者差异大，先抽"能共享的"
  （世界端口 / 索敌 / 代理目标 / 攻击节奏 / 槽位），移动与站位留在三个子类里，不强行统一状态机。
- **玩家独立后变"孤岛"**：`PlayerPipeline` 收口时容易把装备/载具逻辑切断。
  → `PlayerServices` 接口先冻结（输入/相机/装备查询 + 事件订阅），只搬家不改语义。
- **AISystem 泛化误注册**：类型放宽到 `CharacterBase` 后，玩家/访客可能被注册。
  → 注册只由 `EnemyBase`/`AllyBase` 构造发起；玩家永不注册。
- **E3 快照丢字段**：swap-remove + 升降格是踩过的坑（v2 §16.2/§16.3）。
  → 快照字段清单写进验收用例：升格→改状态→降格→再升格，逐字段断言。
- **不做 ECS**：项目是微信小游戏 + 手写管线，ECS 的包体/心智/改动面都不划算；
  用"继承 + 组合模块"解决 90% 问题，剩下 10% 用接口（`SwarmUnit/AllyWorldPort`）。
- **不动子弹/物品的战斗字段（E5 可选）**：收益小、改动面大；文档标记即可，不为了"干净"而冒险。
- **不引入友军编队**：蜂群是敌人系统；友军协同是另一个玩法课题，等敌人 v2 稳定后再议。
