## 0. 一句话

**探路的只管"哪里能过、哪条最省"；跟路的只管"沿这条线稳稳走"。** 坡度是一等公民，
寻路与执行同用一套坡度口径——路径给出的线，执行层必须能走完；走不完的线，根本不该被搜出来。

## 1. 设计目标（用户可感知，逐条可探针化）

| # | 目标 | 反例（现状病灶） |
|---|---|---|
| G1 | **爬山找坡**：有缓坡必走缓坡，绝不正面硬啃陡壁 | A* 把 >0.6m/4m（≈8.5°）的坡全判墙 → 找不到坡 → 直线硬爬 |
| G2 | **不墨迹**：行军速度连续、方向稳定，不原地抽风/画圈 | 锚点跳点+阵型槽硬凑；"到位静止"4m 判定抖动；转圈比 1.2~3.6 波动 |
| G3 | **不穿墙**：路径段 = 可执行线（坡度/硬边双重校验同源） | 寻路 0.6/4m、HPA 拉直 0.8/4m、执行 1.0/1.6m —— 三套口径 |
| G4 | **不发疯**：一条路定下即锁；重规划走白名单 + 预算 | 走廊共享缓存互相重解（~1400 次/分钟风暴）；A* 失败率 ~55% |
| G5 | **不掉队**：全队沿同一走廊，编队槽位可站 | 槽位无可行性校验；坡面上横向排开 → 卡进崖壁 |

## 3. 第一性原理：地形通行模型（坡度一等公民）

### 3.1 坡度定义与采样契约

```
grade(seg) = (h(终点) − h(起点)) / 段长        // 有符号；负 = 下坡（放行，轻微加价）
```

- **一切通行判定必须按"线段采样"**：沿段每 `SAMPLE_DS = 1.6m` 取 `surfaceHeightAt`（连续面），
  算滚动窗坡度；**禁止**用 4m 格心高差直接当坡度（那是离散台阶，不是坡）。
- 4m 格只用于：表（`TerrainScore`：cls/掩体/宽度/隘口）、簇图缓存、采样缓存（`TerrainSampler`）。
- 高度真源 = `RasterMap.surfaceHeightAt`（执行层同源）；采样缓存只做加速，不改变语义。

### 3.2 三类阈值（单源：`SwarmDanger.ts`）

| 常量 | 值（默认） | 语义 | 消费方 |
|---|---|---|---|
| `STEP_MAX` | 0.6m | 单步**瞬时坎**上限（角色 clamp 能力；≤0.6 自动踏过） | CharacterBase / 段采样细分（0.8m 窗） |
| `GRADE_MAX` | 0.625（≈32°） | **可持续爬升上限**（`PROBE_RISE/ PROBE_R = 1.0/1.6`） | 全部寻路边校验 + 执行危险探测 |
| `GRADE_COMFORT` | 0.36（≈20°） | 舒适坡（此坡度以下不减速、不加价） | 代价函数 / 速度函数 |
| `CELL_RISE_MAX` | 2.5m/4m | `GRADE_MAX` 的 4m 折算（过渡期兼容旧格图） | 格图边校验 |

**段有效性判定（唯一实现，所有层调用）**：

```
canTraverse(a, b):
  沿 a→b 每 0.8m 采样 h：
    ① 任一 0.8m 窗升 > STEP_MAX(0.6)  → false（离散坎/陡壁）
    ② 任一 1.6m 窗升 > GRADE_MAX×1.6 → false（持续陡坡）
    ③ 命中表硬边界（blockedAt/cls≥2）→ false
  下坡一律放行；水域放行（涉水代价另计）
```

> 决策点 D1：`GRADE_MAX` 取 32°（现执行层口径）或放宽到 40°（0.84/1.6）？放宽=能爬更陡的坡但
> 执行层需同步改 `PROBE_RISE`，否则又脱节。**推荐 32° 不动执行层**。

### 3.3 代价函数（寻路用）

```
segCost(a,b) = dist × (1 + W_SLOPE × max(0, grade − GRADE_COMFORT)² )   // 凸惩罚：缓坡免费、陡坡急贵
             × coverMul(a,b)                                            // 掩体/战壕折扣 0.6~1（已落地）
             + dropPenalty(下坡轻微加价，防之字下冲)
```

- 凸惩罚使"缓线"自然胜出——**不需要显式之字规则**，A* 自己会沿等高线找缓坡（决策点 D2：是否显式 switchback，默认否）。
- 未知区（chunk 未载）保留 `COST_UNKNOWN` 兜底。

### 3.4 速度函数（执行层用，治"墨迹"的点睛）

```
speedMul(grade) = 1                                     , grade ≤ GRADE_COMFORT
                = 1 − K_SLOW × (grade − COMFORT)/(MAX−COMFORT) , COMFORT < grade ≤ MAX   // K_SLOW 默认 0.5
                = 0（拒绝）                                , grade > MAX
```

- 代理：在 `SwarmSystem.move` 的限速里乘 `speedMul`（按**前方 1.6m 的局部坡度**算）。
- 实体：在 `EnemyLocomotion` 输出时乘同函数。
- 效果：上陡坡肉眼可见地变慢但**方向稳定**——比"速度不变、方向抽风"观感好得多。

> 决策点 D3：上坡减速强度 `K_SLOW`（0.5 = 陡坡半速）。默认 0.5。

### 3.5 兵种差异表达：一套算法 + 参数表（不要"每兵种专属寻路函数"）

**结论**：搜索与跟随算法（A* / HPA / 校验器 / PathFollower）**只有一套代码**；兵种差异全部落在数据面。

| 差异类型 | 例子 | 表达方式 | 现状 |
|---|---|---|---|
| **能力**（能不能过） | 飞行不进地面层；两栖涉水；攀爬者坎上限更高；大体型要更宽走廊 | `NavProfile` 参数/旗标（同一 `canTraverse` 组合器消费） | 散落特判（flyer/水域） |
| **偏好**（先走哪） | 盾走隘口、远程上高地、突击贴掩体、后勤绕远 | 权重乘子表 | 已有：`UnitStrategy.MUL` / `pathMulFor(兵种)` |
| **结构**（不同空间） | 空中层完全不走地面寻路 | 独立层 | 已有：flyer 走空中层 |

**为什么不"每兵种一套寻路函数"**：

1. **bug 面 ×N**：单个口径错（如"把坡当墙"）要在 N 套函数里各修一遍，必然改漏 → 行为分裂；
2. **跨 LOD 换载体**：同一个兵会升格/降格（代理 ⇄ 实体），函数分裂后两条路的路径必须"接得上"，本身成为新 bug 源；
3. **探针/验收 ×N**：每个指标要按兵种分别断言，成本指数上升。

**唯一扩展点**：`NavProfile` 表（放 `UnitStrategy.ts` 旁，与 `MUL` 并列，单源）：

```ts
export interface NavProfile {
  stepMax: number;      // 瞬时坎上限（默认 STEP_MAX=0.6；攀爬者 1.0）
  gradeMax: number;     // 持续坡上限（默认 GRADE_MAX≈0.625 / 32°）
  slopeWeight: number;  // 凸惩罚权重（后勤大、突击小）
  kSlow: number;        // 上坡减速强度（默认 0.5）
  width: number;        // 走廊净宽需求（大体型 >1；默认 1 = 单人宽）
  swim: boolean;        // true=可涉水（水只加价）；false=水域视为绕行
  edgeOk?: (h: (x: number, z: number) => number,
            blockedAt: (x: number, z: number) => boolean,
            ax: number, az: number, bx: number, bz: number) => boolean;
                        // 极特例钩子（挖洞/跳崖）——默认不提供
}

const D: NavProfile = { stepMax: 0.6, gradeMax: 0.625, slopeWeight: 1, kSlow: 0.5, width: 1, swim: true };

export const NAV_PROFILE: Record<SquadType, NavProfile> = {
  defense:   { ...D, width: 1.2 },           // 盾：略宽，隘口偏好由 MUL 负责
  assault:   { ...D, slopeWeight: 0.8 },     // 突：不怵坡
  ranged:    { ...D },                       // 远：中性（高地偏好由 MUL 负责）
  logistics: { ...D, slopeWeight: 1.6 },     // 后：最怕陡
  flyer:     { ...D },                       // 空：由空中层直通，本表仅占位
  mixed:     { ...D },
};
```

**纪律**：

1. **算法一行不改，差异全部数据化**——新增兵种只加一行 `NAV_PROFILE`；
2. 只有"算法结构不同"才允许独立层（如空中层），且**不允许复制搜索代码**；
3. `edgeOk` 钩子的实现也必须在 `canTraverse` 组合器**内部**调用（保证口径同源、探针可覆盖）。

> 决策点 D6：首批差异化范围——推荐先只落 `flyer`（空中层豁免）+ 大体型 `width`，其余全默认；观察探针再逐兵种开参数。

## 4. 四层职责与数据流

```
命令轨（大队）── SquadOrder{anchor,intent,coarse,ttl} ──┐
                                                      ▼
L2 小队走廊 SquadPath（有界 A* + canTraverse 拉直）── waypoints[] ──┐
     ▲ 粗图兜底/长距：L1 HpaPath（簇图，边=canTraverse）             ▼
L3 跟随器 PathFollower（★新）── 小队锚点 + 朝向 + speedMul ── 编队槽位（可行性校验）
                                                      │
                                    个体指令/steer（代理 SoA / 实体 applySteer）
                                                      ▼
L4 局部避障 SteerPick（16 向：硬否决 + 表分 + 坡度代价 + hysteresis）
                                                      ▼
                                        移动积分（SwarmSystem.move / CharacterBase）
```

| 层 | 模块 | 只回答 | 不做 |
|---|---|---|---|
| L0 事实 | `RasterMap / TerrainSampler / TerrainScore / SwarmDanger` | 高度、可站、掩体、坡度阈值 | 不搜路 |
| L1 粗图 | `HpaPath` | 远距（>70m）大概怎么绕 | 不出细路径、不锁定 |
| L2 走廊 | `SquadPath` | 精确 waypoint 走廊（全段可执行） | 不做跟随、不碰命令 |
| L3 跟随 | `PathFollower` ★新 | 沿走廊稳稳走、到点/卡住申报 | 不改走廊、不改命令 |
| L4 局部 | `SteerPick` | 本拍方向（避障/贴坡选择） | 不做全局规划 |
| 任务走廊 | `MemberTaskNav` | 成员点级走廊（复用 L2 校验/L3 跟随语义） | 不做小队级规划 |
| 流场 | `FlowField` | **仅交战直扑**（玩家/舰船源） | 不用于行军（决策点 D4：默认保持） |

**车道纪律**：流场只服务"接敌最后的直扑段"；行军段一律走 L2/L3。

## 5. 路径表示与不变量（Path Contract）

```
Corridor {
  pts: {x,z}[]          // waypoint 串（首点≈当前位置，末点=目标）
  segOk: boolean[]      // 每段 canTraverse 校验结果（生成时算一次，锁定）
  stamp: number         // 生成戳（地形代次 + 目标位）
  lockedAt: number      // 锁定时刻（白名单外的重规划一律拒绝）
}
```

| # | 不变量 | 违反后果 |
|---|---|---|
| I1 | **段有效性**：每段 `canTraverse` 为真（含坎/坡/硬边） | 路径不可执行 → 墨迹 |
| I2 | **跟随不出走廊**：横向偏差 > `CORRIDOR_W=6m` → 归位；归位失败按"无进展"申报 | 抄近路卡崖 |
| I3 | **定下即锁**：白名单外零重规划（白名单见 §8） | 左右抽风 |
| I4 | **覆盖式更新**：目标变 → 新走廊整体覆盖旧走廊；同命令 keep-alive 不清走廊 | 旧路半截误导 |
| I5 | **同源口径**：寻路/执行同用 §3.2 一套阈值（`SwarmDanger`） | 穿墙/拒走 |
| I6 | **命令不含细路径**：命令只带 `anchor/intent/coarse(≤8 路点软参考)`；细路径归小队 | 大队越权 |

## 6. 跟随器 PathFollower（★新部件，治 G2/G5）

### 6.1 状态

```
PerSquad {
  corridor: Corridor | null
  idx: number            // 当前段
  s: number              // 段内投影里程
  lateral: number        // 横向偏差（有符号）
  stuck: { t0: number, x: number, z: number, lastD: number } | null
}
PerUnitSlot { rank, lateralOffset, status }   // 编队槽位
```

### 6.2 每拍（小队级 10Hz；代理 20Hz 复用同一函数）

```
update(squad, corridor, now):
  ① 投影：在当前段 ±1 段窗口内求最近点 → s, lateral
  ② 段推进：到当前段末端 < R_ADV(6m) → idx++（可连跳）
  ③ 横向归位：|lateral| > E_SOFT(3m) → 输出归位速度分量 k·(目标−投影)（不触发重规划）
  ④ 卡住检测：T_STUCK(2.5s) 内段内里程增量 < 1m 且 目标距未减小 → status='stuck'
       └→ 只申报一次（走白名单第 3 条：无进展）；不自行重解
  ⑤ 终点：到末点 ≤ R_ARR(4m) → status='arrived'，减速停
  输出：{ anchor(沿段前瞻点), dir(段切向), speedMul(§3.4), status }
```

### 6.3 与命令轨/队长拆步的关系

- 队长拆步（P4-1）产出的"步令"**就是短走廊**（1~3 段），PathFollower 同一套跟随；步令覆盖=新走廊覆盖，不改 `order`。
- 大队命令 keep-alive（重发同目标）**不清走廊**（`stamp` 未变即沿用）。
- 拆步与走廊**同一目标时合并**：带 `coarse` 的令直接作为首段参考，拆步只做局部补正（避免两套目标并跑）。

### 6.4 到位口径（治"到位静止"抖动）

- "到位"以**小队锚点**判定（质心距离），不以个体 4m 判定；
- 个体停步 = `|投影点 − 个体位| < R_SLOT(2m)` 且方向切换 < 阈值；槽位不可站时向法向内收（§7）。

## 7. 编队与坡度变形（治 G5）

- 槽位生成不变（uid rank → `formationOffset`），但输出前过**可行性校验**：
  - 槽位点 `pass` 且局部坡度 ≤ `GRADE_MAX`（用 `canTraverse(锚点, 槽位)` 快速判定）；
  - 失败 → 该槽沿**法向内收**（offset×0.6/0.3/0）→ 再失败退化为**纵队**（沿切向单列）；
- 坡面上禁止大横向偏移（横向偏移量 × max(0.4, 1−grade)）；
- 窄走廊（宽度 < 队形宽）自动纵队化——用 `TerrainScore.widthAt` 已有字段。

## 8. 重规划白名单与预算（汇总 + 增补）

**允许重规划（重解走廊）的事件**（其余一律锁定）：

1. 目标/意图变更（大队换令；含撤销/回撤）；
2. 路况变（路径段被挖/新建硬边界 → `segOk` 失效）；
3. **无进展**（PathFollower 申报：2.5s 位移 <1m 且距目标未近）；
4. TTL 到期（走廊软寿命 12s；地形代次戳变化）；
5. 攻/守状态切换（读表权重代次变化）；
6. 收/放队形导致走廊宽窄不匹配（仅重解一次）。

**预算**：每队 ≤ `REPLAN_BUDGET = 6 次/分钟`（超预算 → 只上报不重解，等 TTL）。
**计数探针**：已有「重规划(白名单P4)」行；新增「按事件分类计数」（target/dig/noprogress/ttl/stance）。

> 说明：P4-3 已把 `MemberTaskNav` 两类重解与失败冷却归口进白名单，本文件把它们升级为**全寻路轨统一口径**。

## 9. 接口契约（模块级，TypeScript 签名）

```ts
// L0：唯一通行判定（新）
function canTraverse(h: (x: number, z: number) => number,
  blockedAt: (x: number, z: number) => boolean,
  ax: number, az: number, bx: number, bz: number): boolean;

// L1：粗图（保留现接口；边校验换 canTraverse）
hpa.find(raster, sx, sz, gx, gz, out): boolean;
hpa.coarseReachable(raster, sx, sz, gx, gz, out): 'ok' | 'blocked' | 'unknown';

// L2：走廊（find 内部拉直改用 canTraverse + 凸坡度代价）
squadPath.find(raster, sx, sz, gx, gz, out, costMul?): boolean;

// L3：跟随器（新）
class PathFollower {
  setCorridor(squadId: number, c: Corridor): void;
  clear(squadId: number): void;
  update(squadId: number, cx: number, cz: number, now: number):
    { anchor: {x,z}; dirX: number; dirZ: number; speedMul: number; status: 'ok'|'arrived'|'stuck' };
}
```

**明确禁止**：4m 格心差直接当坡度（必须段采样）；执行/寻路两套阈值；命令对象携带细路径。

## 10. LOD 一致性

| 载体 | 移动实现 | 跟随 | 坡度上限 |
|---|---|---|---|
| 代理（L1/L2 远群） | `SwarmSystem.move`（pickSteer + 原子） | 同一 `PathFollower`（20Hz） | `STEP_MAX/GRADE_MAX` |
| L3 实体 | `CharacterBase`（clamp + isWall）+ `EnemyLocomotion` | 同一 `PathFollower`（10Hz，经 `steerEntities`） | 同上 |
| 空中层 | 直线（不受地面危险） | 无 | 豁免（不改） |

- 兵种差异一律经 `NAV_PROFILE`（§3.5）注入，两个载体读**同一张表**；升格/降格不得改变寻路行为；
- 流场（`FlowField`）仅用于**接敌直扑**与警戒；行军禁用，防止"绕过坡直接从流场爬"。
