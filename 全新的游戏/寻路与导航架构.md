## 0. 一句话

**探路的只管"哪里能过、哪条最省"；跟路的只管"沿这条线稳稳走"。** 坡度是一等公民，
寻路与执行同用一套坡度口径——路径给出的线，执行层必须能走完；走不完的线，根本不该被搜出来。

## 1. 设计目标（用户可感知，逐条可探针化）

| # | 目标 | 反例（现状病灶） |
|---|---|---|
| G1 | **爬山找坡**：有缓坡必走缓坡，绝不正面硬啃陡壁 | A* 把 >0.6m/4m（≈8.5°）的坡全判墙 → 找不到坡 → 直线硬爬 |
| G2 | **不墨迹**：行军速度连续、方向稳定，不原地抽风/画圈 | 锚点跳点+阵型槽硬凑；"到位静止"4m 判定抖动；转圈比 1.2~3.6 波动 |
| G3 | **不穿墙**：路径段 = 可执行线（坡度/硬边双重校验同源） | 寻路 0.6/4m、HPA 拉直 0.8/4m、执行 1.0/1.6m —— 三套口径 |
| G4 | **不发疯**：一条路定下即锁；重规划走白名单 + 预算 | 走廊共享缓存互相重解（~1400 次/分钟风暴）；A* 失败率 ~55% |

| 层 | 表示 | 坡度口径 | 病根 |
|---|---|---|---|
| `HpaPath` 簇图 | 32m 簇 + 4m 格 pass + 端口 | 建簇 4 邻域差 > `WALL_DH=3.0` 判硬边；拉直 `clearLine` 升 >0.8/4m 拒 | 建簇过松、拉直过紧；与执行层两套数 |

## 3. 第一性原理：地形通行模型（坡度一等公民）

### 3.0 可行性表（迷宫抽象）：唯一通行真源，建一次永不变

**结论**：把所有不可通行的边抽象成迷宫墙，落成**一张静态边墙表**——此后一切寻路
（HPA / SquadPath / 任务走廊 / 命令核验 / 流场）都**读这张表**，不再各自采样判墙。

- **建表时机**：落点/换图时**一次构建**（按活动窗口或逐 chunk 懒建）；**挖坑、挖战壕、建工事都不改表**。
- **与现有表的关系（就是同一张表）**：数据结构等价——每格 = 自身高度 + 4 条边属性（外加可选 SCC 标签）。
  差别只在纪律：① 边属性（含方向 `ABS/DOWN/COAST/OPEN`）是一等公民，不再由各消费者临时算 `dh`；
  ② 建表时用唯一判据（§3.1）烙一次，此后全体只读；③ 表随地图**静态**（工事/挖掘不重建），
  而 `TerrainScore`（评分权重/掩体/宽度）仍按自身需要重建——**同网格同源数据，两条生命周期**。
  实现上**不新建平行网格**：从 chunk 高度数组顺产紧凑位图（2bit 边型 + int8 落差）。
- **预计算（纯函数）**：表 = 地形高度（+ 水/角色位）的**纯函数**——与运行时状态（权重/玩家位/工事）无关，
  故可在 **chunk 生成时顺产**并随 chunk 缓存；同 seed 必然同表（可离线校验 / 单元测试）；SCC/定向标签同批预计算。
- **每条边存"边型 + 量化落差"**（每格两条边 E/S，W/N 复用邻格，标准迷宫编码；**边型方向感知**）：

  | 边型 | 判据（0.8m 采样窗最大 |落差|） | 通行规则 |
  |---|---|---|
  | **绝对墙**（悬崖 / 摔死坑） | 落差 > `CLIFF_DH`(3.0m)；或**深坑**（role=pit 且 h < `PIT_H`=-1.2） | **双向禁止**（路径绝不跨越） |
  | **特殊墙**（硬边） | 0.6m < 落差 ≤ 3.0m | **只可下落、不可上升**（单向边） |
  | **半通行**（水岸） | 水域 / 水陆交界 | 双向可走：软代价 + **催促上岸**（执行层引导力） |
  | 开放 | 其余（含**浅坑/战壕**） | 自由通行 |

  - **每格五值（用户定）**：`自身高度 + 四向边（E/W/S/N）各记"可走 0/1 + 净落差（米，带符号）"`——读表即得，运行时不现算；

  - 读取时按本兵种 `stepMax`（默认 0.6）比较：攀爬者可放宽"特殊墙"的上升禁令（§3.5）；
  - 表 = 边型位（2bit）+ 量化落差（int8）→ 一张表支持兵种差异，不建多张表。
- **坑与战壕都可通行**，不进表（不影响墙）；只作为**软代价 / 掩体加成**从 `HoleTable` 另读
  ——即"工事永不触发重规划"（《敌人管线设计.md》§5）的落地方式。
- **水可通行 + 催促上岸**：不判墙、不判死；寻路只加软代价（允许过河），执行层叠加
  "最近岸方向"引导力——在水中尽快上岸；在岸上贴水则略偏岸内（除非路径要求过河）。
- **分辨率**：默认 **4m**（与现表/HPA 同网格，零改造成本）；若"贴崖绕行"观感不足再上 2m。
  **不下到像素**：像素(0.25m) 格数 ×256，建表与 A* 成本爆炸，收益仅是视觉贴合。
- **内存**（400×400m 窗口）：4m 格 ≈ 1 万格 → 边坡度+断崖位 ≈ 40KB；2m 也仅 ≈ 160KB。零头。
- **有向可达标签（必要修正）**：单向边使可达性**不对称**——`component` 升级为 **SCC / 定向可达**
  （命令门问的是"从 A 能到 B 吗"）；建表顺产，`coarseCheck` 仍是 O(1)（查有向标签）。
- **表不变的三条推论**：
  1. 挖断/新建**永不触发重规划**（§8 白名单第 2 条删除）；
  2. 搜索失败 = 真不可达（不再因抖动反复重试）；
  3. `component` 静态 → 命令门/探针直接读。

> 决策点 D7：分辨率默认 4m（可选 2m）。
> 决策点 D8：**坑可通过**需执行层同步——现行"代理掉坑即死 / 危险探测把坑判墙"与表冲突
> （表说能走、执行判死 = 老病根的翻版）；应改为"坑=低地可走"（可保留爬出减速/落坑伤，但不判墙不判死）。
> 决策点 D9：落崖单位处置——墙为双向后，被击退/生成到崖对侧的单位无法自行返回；
> 走"卡死回收"兜底还是"单向下崖豁免"，需定（**推荐：回收兜底，不加例外**）。

### 3.1 边型判定（方向感知）与采样契约

```
edgeKind(a → b):        // 同一条边两个方向通行性可不同
  沿 a→b 每 0.4m 采样 h：
    最大单步 |Δ| > CLIFF_DH(3.0)                    → ABS   （悬崖：双向禁）
    最大单步 |Δ| > 0.6 且 > 3×中位单步 + 0.15        → DOWN  （离散硬边：只可下）
    其余（含一切连续坡、水/坑/战壕）                  → OPEN
  （坡是正常通路，不做特殊处理；水岸的"半通行"只体现为软代价 + 催促上岸，不判墙）
```

- **采样判定只在建表时执行一次**（§3.0）；运行时不采样、只读表位。
- 建表每 0.8m 取 `surfaceHeightAt`（连续面）算相邻落差；**禁止**用 4m 格心高差直接当落差。
- 4m 格只用于：表（`TerrainScore`：cls/掩体/宽度/隘口）、可行性表、簇图缓存、采样缓存（`TerrainSampler`）。
- 高度真源 = `RasterMap.surfaceHeightAt`（执行层同源）；采样缓存只做加速，不改变语义。

### 3.2 阈值（单源：`SwarmDanger.ts`）

| 常量 | 值（默认） | 语义 | 消费方 |
|---|---|---|---|
| `STEP_MAX` | 0.6m | **特殊墙下限**：0.6 < 落差 ≤ `CLIFF_DH` → 单向边（可下不可上） | 建表判据 + 执行危险探测（同源） |
| `CLIFF_DH` | 3.0m | **绝对墙下限**：落差 > 此值 → 悬崖（双向禁；沿用表口径 `WALL_DH`） | 建表判据 + 执行（防走落） |
| `GRADE_COMFORT` | 0.36（≈20°） | 舒适坡（此坡度以下不减速、不加价） | 代价函数 / 速度函数 |
| `GRADE_MAX` | 0.625（≈32°） | 陡坡减速参考上限（**不参与通行判定**） | 速度函数 |
| `CELL_RISE_MAX` | 2.5m/4m | 过渡期兼容旧格图（N0 表落地后废弃） | 格图边校验（WIP） |

**边型判定（唯一实现；建表时跑一次）**：

```
edgeKind(a → b)：见 §3.1
  - ABS：双向不可通行
  - DOWN：h(b) < h(a) 方向可走；反向不可
  - COAST：可走（软代价 + 催促上岸）
  - OPEN：可走
（水/坑/战壕不判墙；平面陡坡不判墙，只减速/加价）
```

> 该判定是**建表判据**（§3.0）：建表时每条边过一次；运行时所有层读边型位，方向语义一致。
> 推论：**搜索图是有向图**——A*/HPA/拉直/连通域全部按有向边处理（HPA 端口边带方向）。

### 3.3 代价函数（寻路用）

```
segCost(a,b) = dist × (1 + W_SLOPE × max(0, grade − GRADE_COMFORT)² )   // 凸惩罚：缓坡免费、陡坡急贵
             × coverMul(a,b)                                            // 掩体/战壕折扣 0.6~1（已落地）
             + dropPenalty(下坡轻微加价，防之字下冲)
```

- 凸惩罚使"缓线"自然胜出——**不需要显式之字规则**，A* 自己会沿等高线找缓坡（决策点 D2：是否显式 switchback，默认否）。
- 坑/战壕**可通行**（§3.0）：不进墙表；涉坑/涉水只作软代价（`HoleTable`/水域），**不触发重规划**。
- 未知区（chunk 未载）保留 `COST_UNKNOWN` 兜底。

### 3.4 速度函数（执行层用，治"墨迹"的点睛）

```
speedMul(slope) = 1                                            , slope ≤ GRADE_COMFORT
                = max(0.5, 1 − K_SLOW × (slope−COMFORT)/(MAX−COMFORT)) , 更陡渐慢   // K_SLOW 默认 0.5
                （通行由"断崖位"判死：墙不走；平滑陡坡只是慢，不拒走）
```

- 代理：在 `SwarmSystem.move` 的限速里乘 `speedMul`（按**前方 1.6m 的局部坡度**算）。
- 实体：在 `EnemyLocomotion` 输出时乘同函数。
- 效果：上陡坡肉眼可见地变慢但**方向稳定**——比"速度不变、方向抽风"观感好得多。

> 决策点 D3：上坡减速强度 `K_SLOW`（0.5 = 陡坡半速）。默认 0.5。

### 3.5 兵种差异表达：一套算法 + 参数表（不要"每兵种专属寻路函数"）

**结论**：搜索与跟随算法（A* / HPA / 校验器 / PathFollower）**只有一套代码**；兵种差异全部落在数据面。

| 差异类型 | 例子 | 表达方式 | 现状 |
|---|---|---|---|
| **能力**（能不能过） | 飞行不进地面层；两栖涉水；攀爬者坎上限更高；大体型要更宽走廊 | `NavProfile` 参数/旗标（同一 `edgeKind` 判定消费） | 散落特判（flyer/水域） |
| **偏好**（先走哪） | 盾走隘口、远程上高地、突击贴掩体、后勤绕远 | 权重乘子表 | 已有：`UnitStrategy.MUL` / `pathMulFor(兵种)` |
| **结构**（不同空间） | 空中层完全不走地面寻路 | 独立层 | 已有：flyer 走空中层 |

**为什么不"每兵种一套寻路函数"**：

1. **bug 面 ×N**：单个口径错（如"把坡当墙"）要在 N 套函数里各修一遍，必然改漏 → 行为分裂；
2. **跨 LOD 换载体**：同一个兵会升格/降格（代理 ⇄ 实体），函数分裂后两条路的路径必须"接得上"，本身成为新 bug 源；
3. **探针/验收 ×N**：每个指标要按兵种分别断言，成本指数上升。

**唯一扩展点**：`NavProfile` 表（放 `UnitStrategy.ts` 旁，与 `MUL` 并列，单源）：

```ts
export interface NavProfile {
  stepMax: number;      // 墙判据：能上的最大单步落差（默认 0.6；攀爬者 1.0）
  gradeMax: number;     // 陡坡减速参考上限（默认 ≈0.625 / 32°；**不判通行**）
  slopeWeight: number;  // 凸惩罚权重（后勤大、突击小）
  kSlow: number;        // 上坡减速强度（默认 0.5）
  width: number;        // 走廊净宽需求（大体型 >1；默认 1 = 单人宽）
  swim: boolean;        // true=可涉水（水只加价）；false=水域视为绕行
  edgeOk?: (h: (x: number, z: number) => number,
            blockedAt: (x: number, z: number) => boolean,
            ax: number, az: number, bx: number, bz: number) => boolean;
                        // 极特例钩子（挖洞/跳崖）——默认不提供
}

const D: NavProfile = { stepMax: 0.6, gradeMax: 0.625, slopeWeight: 1, kSlow: 0.5, width: 1, swim: true };

export const NAV_PROFILE: Record<SquadType, NavProfile> = {
  defense:   { ...D, width: 1.2 },           // 盾：略宽，隘口偏好由 MUL 负责
  assault:   { ...D, slopeWeight: 0.8 },     // 突：不怵坡
  ranged:    { ...D },                       // 远：中性（高地偏好由 MUL 负责）
  logistics: { ...D, slopeWeight: 1.6 },     // 后：最怕陡
  flyer:     { ...D },                       // 空：由空中层直通，本表仅占位
  mixed:     { ...D },
};
```

**纪律**：

1. **算法一行不改，差异全部数据化**——新增兵种只加一行 `NAV_PROFILE`；
2. 只有"算法结构不同"才允许独立层（如空中层），且**不允许复制搜索代码**；
3. `edgeOk` 钩子的实现也必须在 `edgeKind` 组合器**内部**调用（保证口径同源、探针可覆盖）。

> 决策点 D6：首批差异化范围——推荐先只落 `flyer`（空中层豁免）+ 大体型 `width`，其余全默认；观察探针再逐兵种开参数。

## 4. 四层职责与数据流

```
L0 可行性表 PassTable（§3.0；一次构建，永不重建）── 边墙/坡度/连通域
        │（唯一通行真源：以下各层只读表，不自行判墙）
命令轨（大队）── SquadOrder{anchor,intent,coarse,ttl} ──┐
                                                      ▼
L2 小队走廊 SquadPath（有界 A* + 读表拉直）── waypoints[] ──┐
     ▲ 粗图兜底/长距：L1 HpaPath（簇图，边读表）             ▼
L3 跟随器 PathFollower（★新）── 小队锚点 + 朝向 + speedMul ── 编队槽位（可行性校验）
                                                      │
                                    个体指令/steer（代理 SoA / 实体 applySteer）
                                                      ▼
L4 局部避障 SteerPick（16 向：硬否决 + 表分 + 坡度代价 + hysteresis）
                                                      ▼
                                        移动积分（SwarmSystem.move / CharacterBase）
```

| 层 | 模块 | 只回答 | 不做 |
|---|---|---|---|
| L0 真源 | **`PassTable` 可行性表（§3.0）** | 唯一通行判定（边墙/坡度/连通域） | 不搜路；**一次构建，挖建不改** |
| L0 事实 | `RasterMap / TerrainSampler / TerrainScore / SwarmDanger` | 高度、可站、掩体、坡度阈值（建表输入） | 不搜路 |
| L1 粗图 | `HpaPath` | 远距（>70m）大概怎么绕 | 不出细路径、不锁定 |
| L2 走廊 | `SquadPath` | 精确 waypoint 走廊（全段读表校验） | 不做跟随、不碰命令 |
| L3 跟随 | `PathFollower` ★新 | 沿走廊稳稳走、到点/卡住申报 | 不改走廊、不改命令 |
| L4 局部 | `SteerPick` | 本拍方向（避障/贴坡选择） | 不做全局规划 |
| 任务走廊 | `MemberTaskNav` | 成员点级走廊（复用 L2 校验/L3 跟随语义） | 不做小队级规划 |
| 流场 | `FlowField` | **仅交战直扑**（玩家/舰船源） | 不用于行军（决策点 D4：默认保持） |

**车道纪律**：流场只服务"接敌最后的直扑段"；行军段一律走 L2/L3。

**分工纪律（2026-09-23 定；两套寻路**直接分开**，不做"一个函数可开关权重"）**：

- **两套寻路（模块分家）**：
  - `FeasibilityPath`（可行性寻路；共用）：只读表边的走/不走（有向），**代价恒 1**；输出"可达性"与"可行走廊"；
  - `WeightedPath`（加权寻路；**仅小队**）：以可行性为底座，再按权重择优（掩体折扣 / 兵种亲和 / 坡度凸惩罚 / 远程高地）。
- **大队 = 可行性寻路 + 另一套战术逻辑**：指挥/闸门/配额/使命/改派等（战术逻辑不是寻路；不读权重）；
- **小队 = 可行性寻路 + 加权寻路**：先保证路能走，再保证路更优；
- **禁止**：把权重塞进大队；把两套寻路合成一个"带权重开关"的函数（接线、探针、回滚都按两个模块分别做）。

## 5. 路径表示与不变量（Path Contract）

```
Corridor {
  pts: {x,z}[]          // waypoint 串（首点≈当前位置，末点=目标）
  segOk: boolean[]      // 每段读表校验结果（生成时算一次，锁定）
  stamp: number         // 生成戳（命令代次 + 目标位；**不含地形代次**——表不变，§3.0）
  lockedAt: number      // 锁定时刻（白名单外的重规划一律拒绝）
}
```

| # | 不变量 | 违反后果 |
|---|---|---|
| I1 | **段有效性**：每段按**有向边型**校验（ABS 禁 / DOWN 仅下坡向 / COAST 半通行） | 路径不可执行 → 墨迹 |
| I2 | **跟随不出走廊**：横向偏差 > `CORRIDOR_W=6m` → 归位；归位失败按"无进展"申报 | 抄近路卡崖 |
| I3 | **定下即锁**：白名单外零重规划（白名单见 §8） | 左右抽风 |
| I4 | **覆盖式更新**：目标变 → 新走廊整体覆盖旧走廊；同命令 keep-alive 不清走廊 | 旧路半截误导 |
| I5 | **同源口径**：寻路/执行同用 §3.0 表 + §3.2 阈值（`SwarmDanger`） | 穿墙/拒走 |
| I6 | **命令不含细路径**：命令只带 `anchor/intent/coarse(≤8 路点软参考)`；细路径归小队 | 大队越权 |
| I7 | **工事不动路**：挖坑/战壕/建工事不使 `segOk` 失效、不触发**硬**重规划（表不变量）；**加权路**另有"代价代次"：掩体增删 → 代价场变 → 触发**一次**偏好重算（覆盖式，节流，不占硬白名单预算） | 挖一下全队重规划 / 掩体变了永远不优化 |

## 6. 跟随器 PathFollower（★新部件，治 G2/G5）

### 6.1 状态

```
PerSquad {
  corridor: Corridor | null
  idx: number            // 当前段
  s: number              // 段内投影里程
  lateral: number        // 横向偏差（有符号）
  stuck: { t0: number, x: number, z: number, lastD: number } | null
}
PerUnitSlot { rank, lateralOffset, status }   // 编队槽位
```

### 6.2 每拍（小队级 10Hz；代理 20Hz 复用同一函数）

```
update(squad, corridor, now):
  ① 投影：在当前段 ±1 段窗口内求最近点 → s, lateral
  ② 段推进：到当前段末端 < R_ADV(6m) → idx++（可连跳）
  ③ 横向归位：|lateral| > E_SOFT(3m) → 输出归位速度分量 k·(目标−投影)（不触发重规划）
  ④ 卡住检测：T_STUCK(2.5s) 内段内里程增量 < 1m 且 目标距未减小 → status='stuck'
       └→ 只申报一次（走白名单第 3 条：无进展）；不自行重解
  ⑤ 终点：到末点 ≤ R_ARR(4m) → status='arrived'，减速停
  输出：{ anchor(沿段前瞻点), dir(段切向), speedMul(§3.4), status }
```

### 6.3 与命令轨/队长拆步的关系

- 队长拆步（P4-1）产出的"步令"**就是短走廊**（1~3 段），PathFollower 同一套跟随；步令覆盖=新走廊覆盖，不改 `order`。
- 大队命令 keep-alive（重发同目标）**不清走廊**（`stamp` 未变即沿用）。
- 拆步与走廊**同一目标时合并**：带 `coarse` 的令直接作为首段参考，拆步只做局部补正（避免两套目标并跑）。

### 6.4 到位口径（治"到位静止"抖动）

- "到位"以**小队锚点**判定（质心距离），不以个体 4m 判定；
- 个体停步 = `|投影点 − 个体位| < R_SLOT(2m)` 且方向切换 < 阈值；槽位不可站时向法向内收（§7）。

## 7. 编队与坡度变形（治 G5）

- 槽位生成不变（uid rank → `formationOffset`），但输出前过**可行性校验**：
  - 槽位点 `pass` 且局部边型 ≤ DOWN/OPEN（用 `edgeKind(锚点, 槽位)` 快速判定）；
  - 失败 → 该槽沿**法向内收**（offset×0.6/0.3/0）→ 再失败退化为**纵队**（沿切向单列）；
- 坡面上禁止大横向偏移（横向偏移量 × max(0.4, 1−grade)）；
- 窄走廊（宽度 < 队形宽）自动纵队化——用 `TerrainScore.widthAt` 已有字段。

## 8. 重规划白名单与预算（汇总 + 增补）

**允许重规划（重解走廊）的事件**（其余一律锁定）：

1. 目标/意图变更（大队换令；含撤销/回撤）；
2. ~~路况变（路径段被挖/新建硬边界 → `segOk` 失效）~~ **删除**——挖/建不改表（§3.0），工事永不触发重规划；
3. **无进展**（PathFollower 申报：2.5s 位移 <1m 且距目标未近）；
4. TTL 到期（走廊软寿命 12s；命令代次戳变化）；
5. 攻/守状态切换（读表权重代次变化）；
6. 收/放队形导致走廊宽窄不匹配（仅重解一次）。

**预算**：每队 ≤ `REPLAN_BUDGET = 6 次/分钟`（超预算 → 只上报不重解，等 TTL）。
**计数探针**：已有「重规划(白名单P4)」行；新增「按事件分类计数」（target/noprogress/ttl/stance）。

> 说明：P4-3 已把 `MemberTaskNav` 两类重解与失败冷却归口进白名单，本文件把它们升级为**全寻路轨统一口径**。

## 9. 接口契约（模块级，TypeScript 签名）

```ts

type EdgeKind = 'open' | 'down' | 'coast' | 'abs';

// L1：粗图（接口保留；端口边带方向）
hpa.find(raster, sx, sz, gx, gz, out): boolean;
hpa.coarseReachable(raster, sx, sz, gx, gz, out): 'ok' | 'blocked' | 'unknown';

// L2：走廊（有向搜索 + 读表拉直 + 凸坡度代价）
squadPath.find(raster, sx, sz, gx, gz, out, costMul?): boolean;

// L3：跟随器（新）
class PathFollower {
  setCorridor(squadId: number, c: Corridor): void;
  clear(squadId: number): void;
  update(squadId: number, cx: number, cz: number, now: number):
    { anchor: {x,z}; dirX: number; dirZ: number; speedMul: number; status: 'ok'|'arrived'|'stuck' };
}
```

**明确禁止**：4m 格心差直接当落差（必须 0.8m 段采样）；把 DOWN 边当无向边处理；执行/寻路两套阈值；命令对象携带细路径。
