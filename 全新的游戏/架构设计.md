## 0. 架构总览

```
┌─────────────────────────────────────────────────────────────────────┐
│                       应用层（Game Modes）                            │
│   BOOT → SHIP(日常) → WORLD(战斗) → BOSS(决战) → RESULT              │
│   （模式切换走 ModeManager，各自独立场景容器）                        │
├─────────────────────────────────────────────────────────────────────┤
│                       系统层（Systems）                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│  │ 实体系统  │ │ 战斗系统  │ │ 地图系统   │ │ 抽卡系统  │ │ 背包系统   │  │
│  │ Entity   │ │ Combat   │ │ Map      │ │ Gacha    │ │Inventory │  │
│  │ Manager  │ │ 伤害/子弹 │ │ chunk    │ │ 卡池/保底 │ │ 物品/合成 │  │
│  │ +组件     │ │ AI      │ │ 生成/迷雾  │ │          │ │          │  │

│  │  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌─────────┐   │     │
│  │  │ 物理    │ │ 渲染   │ │ 相机    │ │ 资源    │ │ 特效     │   │     │
│  │  │ rapier │ │ Render │ │ Camera │ │ Asset  │ │ 播放器   │   │     │
│  │  │ 固定步长 │ │ 场景组织 │ │ 跟随/避障│ │ 加载/缓存│ │ FX挂接  │   │     │
│  │  └────────┘ └────────┘ └────────┘ └────────┘ └─────────┘   │     │

├───────────────────────────┼─────────────────────────────────────────┤

│  └────────────────────────┬────────────────────────────────────┘     │
├───────────────────────────┼─────────────────────────────────────────┤
│                           ▼                                          │
│  ┌────────────────────────────────────────────────────────────┐     │
│  │             平台实现（Platforms）                           │     │
│  │  Web（开发默认）│ 微信小游戏 │ 抖音小游戏 │ 其他（按需）      │     │
│  └────────────────────────────────────────────────────────────┘     │
└─────────────────────────────────────────────────────────────────────┘

数据流（纵向）：
 配置 JSON（内容）→ 系统层读取 → 核心运行时调度 → 服务层执行 → 平台层输出
 事件（横向）：系统间通过 EventBus 解耦通信
 状态（Session）：纯数据，贯穿模式切换，可序列化存档
```

**架构分层原则**
```
① 上层依赖下层，下层不依赖上层（单向依赖）
② 应用层/系统层只消费抽象（InputActions/Services 接口），不碰平台 API
③ 平台层 = 唯一接触 wx./tt./浏览器 API 的地方
④ 内容配置只被系统层读取，不进核心运行时
⑤ 换平台/换设备 = 只改平台层；加内容 = 只改配置
```

## 1. 核心运行时

### 1.1 游戏循环（GameLoop）
```
rAF 驱动（浏览器/小游戏统一）
 ├ fixedUpdate(dt=1/60)   # 物理/战斗/逻辑（固定步长，可多次追赶）
 ├ update(dt)            # 渲染同步/特效/相机/UI（可变步长）
 └ render()              # three.js render + Canvas UI
```
- 物理固定步长 + 累积器（rapier 需要稳定步长，如 60Hz）
- `dt 限幅`（切后台恢复时防爆炸，如 max 0.1s）
- 暂停时只跑 render（UI 动画继续），物理/逻辑冻结

```
类结构（GameLoop.ts）：
 GameLoop
  ├ start() / stop() / setPaused(bool)
  ├ fixedUpdate(dt) / update(dt) / render()
  └ subscribers: fixedSet/updateSet（注册回调）
```

### 1.2 状态机（StateMachine）
```
状态：BOOT → SHIP(日常) → WORLD(战斗) → BOSS(决战) → RESULT → BOOT
 ├ 每个状态 = 独立场景容器（scene + 实体集 + 更新逻辑）
 ├ 切换 = 卸载旧场景（可保留数据）→ 加载新场景
 └ 状态栈支持：暂停菜单（WORLD → MENU → WORLD）

★ 模式切换保留规则（SHIP ↔ WORLD 往返）：
 ├ 保留（Session/跨场景）：舰船上的东西、科技树、主角物品、
 │   友军列表、遗物、卡池计数、day、背包/仓库
 ├ 丢弃（随场景卸载）：当天地图、地图实体（敌人/资源点/箱子）、
 │   战斗中的子弹/粒子/特效、技能 CD 等运行时状态
 └ 恢复：回舰船后，保留数据从 Session 重建（地图明天重新生成）
```
- 模式切换统一走 `ModeManager`，禁止散落的条件切换。

```
类结构（ModeManager.ts）：
 ModeManager
  ├ switchMode(next: ModeId)          # 卸载旧 → 加载新
  ├ pushMode(mode) / popMode()        # 暂停菜单栈
  ├ register(modeId, Mode)            # 注册模式
  └ 每个 Mode：onEnter(ctx) / onExit() / update(dt)

 Session
  ├ get/set 各字段（纯数据存取）
  ├ serialize() → string / deserialize(json)
  └ reset()                            # 开新局
```

### 1.3 事件总线（EventBus）
```
类型安全的事件（enum 键 + 泛型负载）
 ├ 拾取事件：PickupEvent{item, position}
 ├ 守卫警报：ShipAlertEvent{wave, direction}
 ├ 抽卡结果：GachaResultEvent{result}
 ├ 对话/事件：DialogueEvent / StoryEvent
 ├ 死亡/结算：DeathEvent / RunEndEvent
 └ ...
```

★ 事件总线使用规则（谁走总线，谁直接调用）：
```
判断标准 = "有没有非战斗系统要听这个事件"，不是频率

走总线（跨系统解耦）：
 ├ UI 需要监听：拾取/抽卡/警报/对话/死亡/结算
 └ 跨模块通知：背包变动/遗物获得/科技树解锁

不走总线（模块内部直接调用）：
 ├ 战斗内部一切：伤害/子弹命中/受击/死亡判定
 │   - 战斗 = 专门模块（combat/），所有战斗逻辑集中处理
 │   - 战斗模块内部直接调用（StatsCalculator/BulletSystem/AIStateMachine）
 │   - 不 emit 到总线，其他系统也不需要听
 └ 每帧高频路径（移动/特效/相机）直接调用

战斗模块（combat/）职责边界：
 ├ 集中处理：伤害结算/子弹/受击/无敌帧/死亡判定/掉落产出
 ├ 对外输出（总线）：死亡事件（供结算）、掉落事件（供拾取）
 ├ 对外提供：combatAPI（其他系统调用的入口）
 └ 不散落：任何战斗逻辑不得写在 combat 外（UI 只读状态/听事件）
```

### 1.4 Session（一局数据）
```
纯数据对象（可序列化，供自动存档）
 ├ 无 class 实例引用、无函数、无 THREE 对象 —— 保证 JSON.stringify 可用

完整字段清单：
 ├ meta:        { seed, day, version }          # 局标识 + 地图重建种子
 ├ player:      { pos, hp, mp, stats, 黑冠层数 } # 玩家状态（本舰存档点=舰船坐标）
 ├ inventory:   { 背包网格, 仓库网格, 堆叠 }      # 物品（含弹药/食物堆）
 ├ relics:      { 槽位[], 持有集合 }              # 遗物（槽 ∪ 背包）
 ├ allies:      { 友军列表[干员id] }               # 抽到的友军（不存部署位置）
 ├ gacha:       { pityCounter, 已抽次数 }
 ├ ship:        { hp, armor, shield, 科技树, 炮塔[] }
 ├ dayProgress: { 今日是否已出击, 当天地图seed }
 └ 排除：战斗中的物理/粒子/特效/弹幕（永不序列化）

序列化规则：
 ├ 背包/仓库 = 物品 id + 坐标 + 堆叠数（紧凑数组，非完整对象）
 ├ 遗物 = id 列表（效果由配置表重建）
 ├ 友军 = 干员 id 列表（实体由配置表重建）
 └ 全部由 id 引用配置 → 序列化只有 id/数字/小数组 → 保持 < 10KB
```

### 1.5 自动存档（SaveSystem）
```
SaveSystem（本舰安全点，单档位）：
 ├ 序列化：Session → JSON（< 10KB）→ PlatformAdapter.storage.set
 ├ 触发：返回本舰 / 抽卡后（安全点才存）
 ├ 删除：死亡 / 舰船被毁 / 通关 → storage.remove
 ├ 恢复：启动时 storage.get → 有局 → 重建 Session → 回本舰
 ├ 地图重建：seed 确定性生成（ChunkData 不存档，重新生成）
 ├ 排除：战斗中状态（物理/粒子/特效）永不存档
 └ 平台差异：微信 setStorageSync / 抖音 / Web localStorage（Adapter 统一）
```

## 2. 实体系统

### 2.1 实体定义（组合式，非继承）
```
Entity = { id, kind, transform, components[] }
组件（每个都是纯数据 + 可选 Update）：
 ├ Transform    # 位置/旋转/缩放
 ├ RigidBody    # rapier 刚体引用 + 物理参数
 ├ Billboard    # 2D 贴片渲染组件（动画/翻转/阴影）
 ├ Weapon       # 攻击/开火逻辑
 ├ Health       # 血量/受击/死亡
 ├ AI           # 状态机（敌人用）
 ├ Inventory    # 可拾取物品
 └ EffectSlot   # 特效挂点（播放器）
```
- **组合优于继承**：角色/敌人/子弹/箱子都是 Entity + 组件组合
- 组件可持有运行时引用（rapier handle / THREE mesh / 播放器 controller）——正常

★ 物理实体判定（按 kind 自动挂 RigidBody）：
```
不是"所有物体都有 rapier 刚体"——按 kind 配置决定：
├ 需要物理（自动挂 RigidBody 组件）：
│   - 角色/敌人/友军：移动碰撞、被击退
│   - 子弹：飞行 + 命中判定
│   - 掉落物：落地、被爆炸推飞
│   - 可破坏物（箱子/栅栏）：被攻击、被打飞
│   - 地形/墙/舰船/炮塔：固定刚体（碰撞拦截/目标）
├ 不需要物理（不挂 RigidBody）：
│   - 特效/粒子/拖尾（播放器视觉）
│   - 布料（GPU verlet 独立模拟）
│   - 水（Gerstner shader，只采样高度做浮力）
│   - 资源点/采集点（逻辑交互判定）
│   - 装饰物（纯贴图）
└ 判断标准："会不会被撞/撞别人/被力推"——需要才建

 实现（EntityManager.create）：
  实体配置表（entities.json）每条目带 physics 标记：
   { "kind": "enemy", "physics": "dynamic-capsule" }
   { "kind": "bullet", "physics": "dynamic-sphere" }
   { "kind": "wall", "physics": "fixed-box" }
   { "kind": "resource_spot", "physics": null }   # 无物理
  创建时按配置：有 physics → 调 PhysicsWorld.addBody 挂 RigidBody
  无 → 只创建渲染/逻辑组件
```

### 2.2 实体基类体系（管线驱动 + 继承扩展）
```
★ 实体管线 = EntityManager（创建/遍历）+ PhysicsWorld（物理）+ 基类体系（行为骨架）
  组合式数据（2.1）负责"有什么"；基类负责"怎么活"（生命周期/管线联动）。

★ 组合 vs 继承的边界（2.1 与 2.2 并存）：
  ├ 继承（基类体系）= 公共骨架：生命周期 / 管线联动 / 更新顺序
  │   —— EntityBase → CharacterBase/BulletBase/ItemBase → 具体实体
  ├ 组合（组件）= 能力细节：Health/AI/Weapon/Inventory 等
  │   —— 挂在基类实例的组件集合上（data 字段/组件表）
  ├ 规则：行为骨架走继承（每类实体骨架不同），
  │        能力复用走组合（多类实体共享同一组件）
  └ 例：Player 继承 CharacterBase（骨架），挂 Health/Ammo（组件）；
       Enemy 继承 CharacterBase（骨架），挂 Health/AI（组件）
```
 ├ 数据：Entity（id/kind/position）+ 可选 RigidBodyRef（handle 由 PhysicsWorld 分配）
 ├ ★ 动画管线联动（宿主角色）：
 │    assetRef（FtxAsset/Asset）+ FrameAnimator（时间轴/状态/朝向/翻转）
 │    FrameState（frameIndex/facing/flipX/lodLevel，见 3.3.3）
 ├ ★ 渲染管线联动（宿主角色）：
 │    FXRenderer（FTXQuad 纯纹理 / 特效网格）
 │    读 FrameState → 取纹理 → 贴片 → 挂场景（见 3.3.2）
 ├ 生命周期：
 │    spawn(pos, asset) → 建动画/渲染/物理 → update(dt) 每帧 →
 │    死亡 → dispose()（动画/渲染/物理资源全释放）
 ├ 更新骨架（update 模板方法）：
 │    ① 子类行为逻辑（覆写 onUpdate）
 │    ② 物理同步（玩家：位置→刚体；敌人：刚体→位置）
 │    ③ 动画推进（anim.update(dt) → FrameState.frameIndex）
 │    ④ 渲染同步（renderer 位置/朝向/翻转 → render）
 ├ 事件：onDeath / onTakeDamage（子类覆写；跨系统走 EventBus）
 └ 注册：EntityManager.create() 返回 EntityBase 实例（进管线统一驱动）

### 2.2.1 子类体系（细分基类）
```
EntityBase
 ├── CharacterBase（角色基类）
 │     ├ 控制：CharacterController（相机相对移动/跳跃/朝向——已有）
 │     ├ 属性组件：Health / Ammo / Skill（后续）
 │     ├ 挂接：EffectSlot（技能特效挂点）
 │     └ 子类：

 │     ├ 物理：dynamic 球体 + 初速（直线/追踪/重力）

       ├ 无物理（纯视觉）
       └ 播放器资产 + 生命周期（一次/循环/受击触发）
```

### 2.2.2 实体管线的完整数据流（与动画/渲染/物理联动）
```
EntityManager.create(kind, pos, physics?, asset?) → EntityBase
  ├ 物理：collisionVolume 属性（基类声明）→ PhysicsWorld.addBody（y = 脚底+bodyOffsetY）
  ├ 动画：asset → FrameAnimator（FrameState 衔接层）
  ├ 渲染：FXRenderer（FTXQuad/特效网格）
  ├ 碰撞分发：bodyMap（handle → 实体）注册
  └ 空间索引：SpatialGrid 注册（4.1a）

每帧（EntityManager.update(dt) 遍历）：
  entity.update(dt)：
    ① 行为逻辑（子类 onUpdate：AI/控制/子弹飞行/拾取判定）
       ★ CharacterBase：moveDir×speed → moveVelocity（期望速度）
       ★ EnemyBase：super.onUpdate 必须先调（速度驱动链路）
    ② 物理同步（velocity：setVelocityXZ + 位置读回；read：纯读回）
    ③ 动画推进（FrameAnimator.update → 写 FrameState）
    ④ 渲染同步（renderer 位置/朝向/翻转 → 读 FrameState 画）
    ⑤ 空间索引移块（onEntityMoved，hash 比较静止零成本）

销毁（entity.dispose()）：
  anim.dispose / renderer.dispose（mesh+几何+材质）
  / em.unregister（grid+bodyMap 注销）
  / em.destroy → physics.removeBody（★ 刚体释放，防物理世界泄漏）
  → 资源全释放（模式切换/场景卸载时 EntityManager.clear() 批量）

★ 解耦原则（已落实）：
  ├ EntityBase 不碰 rapier（唯一封装 PhysicsWorld）
  ├ EntityBase 不碰具体渲染器（FTXQuad 只在子类构造）
  ├ 动画/渲染只依赖 FrameAssetSource 统一接口（FtxAsset/Asset 一视同仁）
  ├ 碰撞体积 = 基类声明属性（EntityBase.collisionVolume），
  │   物理创建/刚体偏移/碰撞处理统一从属性取
  └ 碰撞事件 = 管线分发（EntityManager → onCollision 钩子），游戏层只管处理

★ 已知限制与后续方案（当前实现边界）：
  ├ 子弹回池：当前超时销毁；池化（复用内存/刚体）后续补
  ├ 资产释放：FtxAsset/Asset 全局常驻（无引用计数）；模式切换手动释放
  │   （架构 9.3 计划：引用计数归零 → dispose）
  └ 事件（onDeath 等）：当前基类回调；EventBus（1.3）就绪后走总线
```

★ 序列化边界（实体与存档）：
```
游戏运行：全部内存数据（组件带引用，无约束）
存档 = 安全点时把内存"写一下"：只提取描述字段
 ├ 存：kind + configId + 位置 + 可存数值（hp/ammo/堆叠…）
 ├ 不存：handle/mesh/controller 等运行时引用
 └ 背包/遗物 = id 列表（配置重建）
读档 = 仅启动时一次：JSON → 按描述重建实体 → 重新分配引用
之后运行：全内存，存档不再参与
```

### 2.2 实体管理（EntityManager）
```
├ 池化：子弹/粒子类高频实体用对象池（预分配，复用）
├ 遍历：按组件类型分组索引（需要 AI 的组 / 需要物理的组…）
├ 创建/销毁：统一入口，销毁时回收组件资源（物理体/网格/特效）
└ 数量上限：同时活跃实体数预算（见性能预算）
```

### 2.3 物理与渲染同步
```
RigidBody 持有 rapier 句柄（userData = entityId）
每 fixedUpdate 后：物理步进 → 把刚体 transform 写回 Entity.transform
渲染层只读 Entity.transform（billboard 面相机/网格变换）
 ├ 被动跟随：物理体写回 → 渲染体跟随（角色/子弹）
 └ 主动驱动：渲染体写回 → 物理体（摄像机/不参与碰撞的装饰）
```

## 3. 渲染架构

### 3.1 场景组织
```
一个主场景（three.Scene）+ 按需子容器：
 ├ RenderScene  # 地形/装饰（静态合并）
 ├ EntityLayer  # 所有实体（billboard/网格）
 ├ FXLayer      # 特效（播放器实例/粒子）
 └ SkyLayer     # 天空/远景
```
- 静态地形合并网格（每 chunk 一个 merged mesh，减少 draw call）
- 实体渲染：billboard 用 InstancedMesh 或合并批次（同类精灵合并）

### 3.2 Billboard 精灵系统
```
BillboardComponent（角色/道具/敌人的世界贴片）
 ├ ★ 动画源 = 播放器资产（ftx3 纹理包，见 3.3.1 动画管线）
 │   - assetRef（FtxAsset）+ controller（帧播放）+ resolver（帧名→索引）
 │   - 不再使用"精灵图集"（textureAtlas）——帧内容全部来自 ftx 包
 ├ currentFrame   # 当前帧（动画状态机驱动）
 ├ facing         # 朝向（前/后/左/右 → 帧组选择，帧名带朝向前缀如 前0/后0）
 ├ flipX          # 移动方向翻转
 ├ facingMode     # always-camera（永久面相机）
 ├ shadow         # 假阴影贴片（地面锚点，与精灵分离）
 └ sortLayer      # 排序层（y-sort：角色/子弹/特效前后遮挡）
```
- **y-sort**：2D 贴片在 3D 场景的遮挡用「y 值排序」模拟（类八方旅人）
- 渲染排序：每帧按 transform.y 排序批次（数量可控，性能可接受）
- Billboard = 贴片容器（位置/朝向/阴影/排序）；帧内容由播放器提供，二者解耦

### 3.3 特效挂接（播放器桥接）
```
EffectSlot 组件：
 ├ assetId     # 资产引用：.ftx3.gz（纹理包）或 .scene.zip（特效包）
 ├ controller  # FramePlaybackController（播放器实例）
 ├ attachPoint # 挂点（头顶/手部/胸口——相对 transform 偏移）
 ├ loopMode    # 循环/一次/受击触发
 ├ physics     # ★ 当前注入的物理参数（公共库引用或内嵌覆盖，见 9.4）
 └ 生命周期：生成时创建 → 播放 → 结束销毁（或跟随实体）
- 播放器输出直接进 FXLayer
- 特效不参与物理，纯视觉（内容设计已确认：实体 vs 特效分离）
- ★ 所有美术 = 播放器格式（ftx3 / .scene.zip），游戏内可函数编辑：
   注入/取消物理参数、修改扭动（distort）、换皮（见 9.4 运行时编辑）
```
- 播放器输出直接进 FXLayer
- 特效不参与物理，纯视觉（内容设计已确认：实体 vs 特效分离）

### 3.3.1 动画管线（角色/道具帧动画，播放器驱动）
```
FrameAnimator（动画状态机组件，驱动 Billboard 帧内容）
 ├ 输入：动画配置 anims.json（角色/道具的动画表）
 │   { "protagonist": {
 │       "facing": { "前": ["前0","前1"], "后": ["后0","后1","后2"] },
 │       "states": {
 │         "idle":   { "facing": "前", "loop": true,  "fps": 3 },
 │         "walk":   { "facing": "auto", "loop": true, "fps": 6 },
 │         "attack": { "facing": "auto", "loop": false, "fps": 10 }
 │       } } }
 ├ 状态切换（实体行为驱动）：
 │   - 移动 → walk / 静止 → idle / 攻击 → attack（播一次回 idle）
 │   - 朝向：facing 决定帧组（前0/后0...）——帧名 = 朝向前缀 + 帧号
 ├ 播放驱动：state → 帧名列表 → resolver 查索引 → controller.goto 逐帧
 │   - 循环：controller loop；单次：播完回调切回 idle
 ├ 帧内容：FtxAsset（纯纹理包）→ Billboard 贴片纹理
 └ 换皮/形态：切换 asset 或 setFrameTextures（见 9.4）

 动画数据流：
  实体行为(移动/攻击) → FrameAnimator.setState('walk')
  → 查 anims.json 帧名列表 → resolver.resolve('前1')
  → controller.goto(index) → Billboard 显示该帧纹理

★ 时间轴与帧播放控制（复用播放器内核 core/time.ts + core/controller.ts）：
 ├ 三层分工：
 │   ├ 语义层（FrameAnimator）："播什么" —— 状态机 → 帧名列表
 │   ├ 时间层（Controller/TimeState）："播到哪了" —— 时间 → 帧索引
 │   └ 显示层（FrameState）："显示啥" —— 帧索引 → 纹理 → 画面
 ├ 时间轴（TimeState，每动画实例私有一份）：
 │   ├ localTime / frameIndex / fps / state / loopCount / order
 │   ├ order：loop / linear / reverse / pingpong
 │   └ 推进：advance(dt) —— 游戏循环每帧调用，唯一时间入口
 ├ 帧播放控制（Controller）：
 │   ├ play/pause/stop/hold(冻结帧)/goto/gotoTime/stepForward/stepBackward
 │   ├ 回调：onFrameChange / onComplete / onStateChange
 │   └ 单次动画：onComplete → 状态机自动切回 idle（闭环）
 ├ 每帧流程：
 │   GameLoop.update(dt) → FrameAnimator.update(dt)
 │     → 状态转移检查（行为层 setState）
 │     → controller.advance(dt)（★ 时间轴推进）
 │     → frameIndex 写入 FrameState
 │   → 渲染管线读 FrameState.frameIndex → 取纹理 → 画
 ├ LOD 与时间轴（不打断时间轴，只调速率/暂停）：
 │   ├ LOD 0：advance 正常（全速）
 │   ├ LOD 1：fps 减半（时间轴变慢，不跳帧）
 │   └ LOD 2：controller 暂停（时间轴冻结，保持当前帧画面）
 └ 原则：每个动画实例独立时间轴，互不干扰；advance 唯一时间入口；
     暂停/冻结/跳转改状态不改 time；LOD 降级不 reset 时间轴
```

### 3.3.2 渲染管线（播放器输出 → 画面）
```
两层渲染输出，统一进 FXLayer：

① 纯纹理帧（FtxAsset / ftx3 包）—— FTXQuad 渲染器
   ├ quad + 合成 shader：base(HSL) + residual(残差) → RGB（GPU 每帧合成）
   ├ bbox 区域映射到贴片（帧内容只占 bbox 区域，透明外延）
   ├ ★ 纹理反转（渲染层应用，读 FrameState.flipX/flipY）：
   │    ├ flipX：quad.scale.x = -1（左右反转——脸朝右的帧朝左走时用）
   │    └ flipY：quad.scale.y = -1（上下反转，预留）
   ├ 流体注入：uFluidTex 分支（注入物理参数时直接采样流体合成结果）
   └ 纹理数据 row0=顶部 + shader 内翻转 v（防上下颠倒，统一约定）

② 特效包（Asset / .scene.zip）—— 实体网格渲染（已有）
   ├ VAT 位移（扭动/变形）+ 模板裁剪 + 每帧变换 + distort
   └ 输出同 FXLayer

FXLayer 集成（世界空间）：
 ├ 实例化：播放器实例输出 → FXLayer 子容器
 ├ 世界变换：实体 transform → 贴片位置/缩放（billboard 面相机）
 ├ 排序：与实体统一 y-sort（批次级，见 3.7）
 ├ LOD：距离 → 减帧（4→2 帧）/ 停流体 / 单帧静态（见 3.6）
 └ 剔除：视锥外不更新/不渲染（见 3.5）

渲染数据流（每帧）：
  FrameAnimator 驱动帧索引 → 播放器输出纹理/网格 → FXLayer
  → RenderManager：剔除 → LOD → 分组 → 批次 y-sort → draw
```

### 3.3.2a 朝向与翻转决策（控制解耦）
```
★ 帧名语义约定：
 ├ "前"帧 = 脸朝相机（正面）→ 游戏里"向下移动"时使用
 ├ "后"帧 = 背对相机 → "向上移动"时使用
 └ 左右移动 → 延续当前 facing 帧组 + flipX 反转

★ 输入完全解耦（双端：桌面/触屏走同一抽象）：
 输入层：InputActions.moveAxis（抽象方向，WASD / 虚拟摇杆 → 同一语义）
   ↓ 游戏控制层不碰具体按键
 角色移动系统：消费 moveAxis → 移动
   ↓
 朝向逻辑（FrameAnimator.setFacing）：
   moveAxis.y > 0 → facing = 前（"前"帧组）
   moveAxis.y < 0 → facing = 后（"后"帧组）
   moveAxis.x < 0 → flipX = true（脸朝左）
   moveAxis.x > 0 → flipX = false（脸朝右）
   ↓
 FrameState 写入 { facing, flipX }
   ↓
 渲染管线：facing 已由动画管线转成 frameIndex（帧组选择）；
           flipX 应用 quad.scale.x = ±1（反转在渲染层）

★ 翻转状态延续（切换动画不重置）：
 动画状态切换（idle→walk）时 flipX 保持上一帧的值，
 只由新输入方向修改——状态切换不碰 flipX。

★ 分层归属：
 flipX 决定 = 控制/动画层（moveAxis 派生，逻辑）
 flipX 应用 = 渲染层（quad.scale.x，表现）
 FrameState 为传递者 —— 决策与表现解耦，与输入解耦一致
```

### 3.3.3 动画管线与渲染管线的关系（FrameState 衔接）
```
★ 两条管线解耦，通过每帧更新的"帧状态 FrameState"衔接：
   动画管线（逻辑侧）写，渲染管线（表现侧）读，单向数据流。

职责划分：
 ├ 动画管线（逻辑侧）："现在该播哪一帧"
 │   FrameAnimator(状态机) → resolver(帧名→索引) → controller(时间轴推进)
 │   驱动者 = 行为层（移动/攻击/状态）
 ├ 渲染管线（表现侧）："这一帧怎么画出来"
 │   FTXQuad / 实体网格 → 合成 shader → FXLayer → y-sort → draw
 │   被动消费（只画"当前帧"，不关心时间）

FrameState（每实体一份，动画写 / 渲染读）：
 ├ assetRef     # FtxAsset 或 Asset（纹理/网格数据源）
 ├ frameIndex   # 当前帧（动画管线每帧写入）
 ├ facing/flipX # 朝向（贴片翻转/帧组）
 ├ lodLevel     # 渲染侧下发（反向控制）
 └ 渲染句柄     # quad/mesh/纹理缓存（渲染侧持有）

每帧数据流（单向）：
 行为层(移动/攻击/中毒)
   → 动画管线：setState → resolveFrame('前1') → controller.advance(dt)
   → 写 FrameState.frameIndex
   → 渲染管线：读 FrameState → 取纹理/网格 → 合成 → FXLayer → 排序 → draw

LOD 反向控制（唯一反向通道）：
 RenderManager（渲染侧）每帧评估距离 → LOD 等级 0/1/2
   → setLodLevel 下发：
      动画管线：降帧率 / 减帧 / 停流体步进
      渲染管线：减细节 / 静态单帧
 其余全部单向（渲染不驱动动画）

解耦收益：
 ├ 改动画实现（换状态机/配置）不影响渲染
 ├ 改渲染实现（换 shader/合批）不影响动画
 └ LOD 逻辑集中：渲染侧评估 → 等级下发 → 双侧响应
```

### 3.4 渲染性能预算
```
目标：稳定 60fps（低端机 30fps 保底）
 ├ draw call：< 200（静态合并 + InstancedMesh + 特效合批）
 ├ 活跃实体：< 100（池化 + 上限）
 ├ 特效实例：< 30（LOD 降采样）
 ├ 阴影：仅玩家 + 近处实体（假阴影贴片兜底）
 └ 粒子：< 5000（距离降采样）
```

### 3.5 视锥剔除（Frustum Culling）
```
三层剔除（每帧在 render 前执行）：
 ├ ① Chunk 级：相机视锥 vs chunk AABB → 视锥外的 chunk 整块跳过
 │   - 每个 chunk 维护一个粗 AABB（地形 + Actors 范围）
 │   - 视锥外 chunk：不更新 Actors、不渲染网格（省 CPU + GPU）
 ├ ② 实体级：three.js 自带 frustumCulled（per-mesh AABB）
 │   - 实体超出视锥 → 跳过渲染（省 draw call）
 │   - billboard 用自身 AABB（贴片矩形包围盒）
 └ ③ 特效级：特效实例位置 vs 视锥 → 视锥外不实例化/不渲染
```

### 3.6 LOD 系统（与剔除联动）
```
LODManager（每帧或每 N 帧评估一次）：
 ├ 评估：实体/地形到相机的距离 → 确定 LOD 等级
 ├ 地形：chunk 按距离选网格精度（近/中/远三级）
 │   - 近：全精度（贴图+法线+细节装饰）
 │   - 中：简化块（合并网格，去法线）
 │   - 远：低面数 + 贴片蒙版
 ├ 实体（billboard）：按距离切换表现
 │   - 近：全帧动画 + 阴影 + 特效挂点
 │   - 中：减帧动画（4→2 帧）+ 停特效
 │   - 远：静态单帧 + 无阴影 + 假阴影贴片
 ├ 切换策略：异步换（延迟一帧，避免瞬间 pop）/ 渐变（可选）
 └ 与剔除协同：视锥外的直接跳过 LOD 评估（省计算）
```
- 视锥剔除 = 每帧"看不见的别渲染"；LOD = "看得见的按距离降成本"
- 两者在 `RenderManager` 统一入口执行：`updateVisible() → 剔除 → LOD → 排序 → draw`

### 3.7 排序与合批（方案 B：批次间 y-sort + 实例合并）
```
★ 取舍决策：y-sort（逐实例遮挡）与 InstancedMesh（少 draw call）互斥
   采用方案 B —— 粗排序（批次级）+ 细合并（实例级）：

渲染流程（RenderManager 统一入口）：
 updateVisible() 每帧：
  ① 视锥剔除：相机视锥 vs chunk/实体 AABB → 剔除不可见（见 3.5）
  ② LOD 评估：仅对"可见"实体评估距离 → 定 LOD 等级（见 3.6）
  ③ 分组：按「图集 × LOD 等级」分组
     - 同图集 + 同 LOD → 合并批次（InstancedMesh 一次绘制）
     - 不同 LOD 的同一图集 → 分到不同批次（近远不同细节）
  ④ 批次排序：批次之间按「代表 y 值」排序（粗遮挡）
     - 每个批次取一个代表 y（如平均 y）
     - 批次间正确遮挡（地面批次 < 角色批次 < 空中特效批次）
  ⑤ 绘制：按排序后的批次依次 draw（同批次内不细排遮挡）

方案 B 的效果：
 ├ draw call：批次数 = 图集数 × LOD 级数（个位数~十位数，可接受）
 ├ 遮挡：批次间正确，批次内小误差（角色/敌人数量少，视觉可接受）
 └ 与 LOD/剔除协同：剔除在前（省 LOD 计算）→ LOD → 分组 → 排序 → draw

静态合批：地形/装饰 chunk 内合并为单 mesh（构建时做一次）
```

### 3.8 地形生成架构（chunk 流式）
```
生成流水线（异步队列，避免卡顿）：
 chunk 请求 → 生成器(seed, chunkX, chunkZ, 主题) → 网格/碰撞/布点 → 激活
 ├ ① 高度场：噪声函数叠加（Perlin/Simplex，多倍频 octaves）
 │   - 主题参数化：龙门外环=平台地形 / 迷宫=走廊骨架
 │   - 噪声输入 = (seed, chunkX, chunkZ) 确定性 → 可复现
 ├ ② 网格构建：高度场 → BufferGeometry（顶点/UV/法线）
 │   - 近处全精度 / 远处低细分（LOD 联动，见 3.6）
 ├ ③ 碰撞：rapier 碰撞体
 │   - 地形用 trimesh（合并进 chunk）或 heightfield（高度场直接转）
 │   - 静态刚体，只建一次，chunk 卸载时释放
 ├ ④ 布点（Actors）：资源点/敌人/箱子/装饰
 │   - 由 (seed, chunk, 主题, day) 确定性采样
 │   - chunk 激活时才实例化，卸载时回收
 └ ⑤ 衔接：chunk 边界用连接点（门/坡道/路径）对齐

生成队列：
 ├ 优先级：近 chunk（玩家周围）> 远 chunk
 ├ 预算：每帧最多生成 N 个 chunk（如 1~2 个），防止卡帧
 └ 内存：只保留视距内 chunk 的 Mesh/Actors，ChunkData 可保留
```

### 3.9 水体生成架构（Gerstner 波）
```
大世界水面 = 网格 + Gerstner 顶点波（shader 计算，非 CPU）
 ├ ① 水面网格：大型平面（随 chunk 生成/跟随玩家），细分可控
 │   - 近处高细分（波浪细节）/ 远处低细分（LOD）
 │   - 或全屏 quad + 顶点置换（相机空间，视距无关）
 ├ ② 波形（顶点着色器，每顶点算）：
 │   y = Σ A_i · sin(k_i·(x,z) + ω_i·t + φ_i)   （多层叠加，如 6 层）
 │   法线 = 解析导数（cos 组合），不额外差分
 ├ ③ 着色：
 │   - 基色（深/浅水区参数化）
 │   - 高光（Blinn-Phong，法线来自波形导数）
 │   - 泡沫（浪尖：高度/曲率阈值 + 噪声）
 │   - 反射/折射：SSR（屏幕空间）或 cube map 近似
 ├ ④ 交互：
 │   - 浮力：采样水面高度 → 浮力公式（阿基米德）驱动实体
 │   - 涟漪：实体入水/攻击 → 叠加局部波形（衰减）
 ├ ⑤ 性能：
 │   - 波形全在 vertex shader（GPU），CPU 零开销
 │   - 近处 512 细分 / 远处降采样
 │   - 水仅在有水的主题区启用（如龙门外环有河，实验室无）
 └ 实现位置：services/render/WaterSystem.ts（独立模块，可插拔）
```

### 4.1a 实体空间索引（SpatialGrid，分块遍历）
```
★ 动机（在子弹系统之前落地，子弹/技能/AI 索敌全部依赖）：
  EntityManager 每帧 O(n) 全量遍历的三类开销随实体增长失控：
  ① 渲染：视野外实体也走 billboard + 绘制管线
  ② AI 索敌：将来"找最近目标/范围内敌人"需全量距离计算
  ③ 交互查询：子弹命中、掉落拾取、范围技能
  物理碰撞已由 rapier 承担，不重复做。

★ 算法选型：均匀网格（Uniform Grid），不用四叉树/八叉树
  ├ 运动实体多（子弹/敌人每帧变位置）→ 换块 O(1) 哈希移动，
  │   树结构要频繁更新节点（分裂/合并），重
  ├ 地面玩法为主 → xz 平面 2D 网格足够（y 影响小）
  └ 实现简单、查询半径/矩形/视野覆盖一致

★ 结构（src/services/space/SpatialGrid.ts）：
  blockSize = 8（地图 64×64 → 8×8 块，共 64 块；块大小可配，实测调优：
   太大=接近全量遍历，太小=换块频繁）
  blocks: Map<blockKey, Set<EntityBase>>   # key = (cx,cz) 编码（负数安全）
  cellOf:  Map<EntityBase, blockKey>       # 实体当前块缓存（移块判定用）

★ 更新策略（集中刷新点，最稳的钩子方案）：
  ├ EntityBase 位置有多个写入方（输入驱动/物理 read/AI moveBy）
  │   → 在 EntityBase.update 末尾（syncRender 后）统一调
  │     em.onEntityMoved(base)：算新块 key，与缓存比较，变化才移块
  ├ 每实体每帧成本 = 一次哈希 + 一次比较（O(1) 均摊）
  └ 静止实体（站桩敌人/落地道具）零移块成本

★ 查询 API（分块的核心价值）：
  querySphere(x, z, r) → EntityBase[]      # 覆盖圆的所有块 → 块内距离过滤
  queryRect(x0,z0,x1,z1) → EntityBase[]    # 区域/扫掠
  queryVisible(camera) → EntityBase[]      # 视锥 8 角点投影到 y=0 平面 →
                                            AABB → 覆盖块集合（保守不误剔除）
    ⚠ 实现注意（已踩坑）：
      ① queryVisible 开头必须 camera.updateMatrixWorld()——
         renderAll 在 renderer.render 之前调用，矩阵未更新 = 用上一帧
         姿态裁剪 → 快速转头时边缘实体闪没
      ② 角点射线向上（仰视/平视）时钳制到 maxQueryRange（默认 128），
         不能把 far 平面上的点直接当投影点（AABB 失控 → 裁剪失效）
      ③ 已知项：每帧 Vector3 分配（GC 压力，中期对象复用）；
         同步时序：aiSystem 必须跑在实体管线之前（移动零滞后，见 4.9）

★ 接入点：
  ├ 渲染：EntityManager.renderAll(camera) → grid.queryVisible(camera)
  │   （视野外实体完全跳过；与 3.5 三层剔除联动：网格 = 遍历裁剪层，
  │     three.js frustumCulled = per-mesh 层）
  ├ AI 索敌：seePlayer/findTarget 改为从 grid 按 camp 查询（泛化索敌）
  ├ 子弹/技能/拾取：querySphere
  └ 物理：不动（rapier 已有）

★ 收益与阈值：
  ├ 实体 < 200 时纯遍历无压力——分块为渲染裁剪 + 索敌查询而做
  ├ 视野覆盖 64×64 地图约 1/4~1/3 → 渲染实体数直接 -60%+
  └ AI 索敌从 O(n) → O(块内数量)，敌人 30 个几乎免费
```

### 4.3 AI 架构（共用行为库 + 阵营标签）
```
AIStateMachine（每实体一个实例，配置驱动）
 ├ 读配置：状态机结构（状态/转移/行为名/条件名）
 ├ 执行：当前状态的行为（查行为表取函数）→ 每帧检查转移条件
 └ 切换：条件满足 → 切状态（通用解释器，敌人/友军同一套）

配置 = 状态机结构（数据，可加敌人不改代码，参数全可调）：
 "grunt": { ai: {
   states: {
     "patrol": { behaviors:["wander(speed:2,targetBias:0.04,biasCamp:player)"],
                 transitions:[{"cond":"seePlayer(radius:8,camp:player)","to":"chase"}],
                 minStay:3 },   // ★ 最短停留：保证脱离战斗后真的游走
     "chase":  { behaviors:["moveToTarget(speed:2.5)"],
                 transitions:[{"cond":"inRange(radius:1.5)","to":"attack"}] },
     "attack": { behaviors:["meleeSwing(duration:0.6)"],
                 transitions:[{"cond":"attackFinished","to":"patrol"},  // ★ 挥完一次回游走
                              {"cond":"outOfRange(radius:2)","to":"patrol"}] }
   }, initial:"patrol" } }

代码 = 行为注册表 + 条件注册表（名字 → 函数）：
 behaviorTable = { wander, moveToTarget, meleeSwing, shootBurst, rangedShot,
                   charge, suicideBoom, knockback, shieldBlock, heal, summon,
                   deployGuard, followFormation, death ... }
 conditionTable = { seePlayer, inRange, outOfRange, hpLow30, hitEnd ... }

★ 共用行为库（敌人/友军同一套函数）：
 移动类：wander / patrol / moveToTarget / follow / flee
 攻击类：meleeSwing / shootBurst / rangedShot / charge / suicideBoom
 受击类：knockback / stagger / shieldBlock
 辅助类：heal / buff / summon
 状态类：deployGuard（站桩守点）/ followFormation（阵型跟随）

★ 阵营标签（camp）决定"对谁反应"：
 ├ camp: 'player' → 玩家（维什戴尔）
 ├ camp: 'ally'   → 友军（部署/跟随）
 ├ camp: 'enemy'  → 敌人
 ├ 行为执行时按阵营查目标：
 │   - 索敌：敌对阵营（enemy 索敌 player/ally；ally 索敌 enemy）
 │   - 伤害：碰撞时同阵营不伤（过滤在碰撞层）
 └ 同一个行为，不同阵营反应不同：
     - 例：shootBurst → 敌人朝玩家射 / 友军朝敌人射（同一函数，目标选择按阵营）

 加新敌人/友军：
 ├ 复用行为 → 只改配置（组合已有行为/参数）
 ├ 全新行为 → 写一个函数注册进行为表（少量）
 └ 阵营差异 → 不改代码，靠 camp 标签（行为内查目标）
```

### 4.3a AI 模块落地设计（可实现级）
```
★ 目的：给 EnemyBase/Ally 提供自主行为（巡逻/索敌/攻击），
   替代当前"相机决定朝向"的占位逻辑（修复"敌人盯着玩家"）。

文件结构（src/systems/ai/）：
 ├ AISystem.ts        # 管理器：维护所有 AI 实体，每帧驱动 update
 ├ AIStateMachine.ts  # 状态机解释器（读配置 → 执行行为 → 查条件 → 转移）
 ├ behaviors.ts       # 行为注册表（名字 → 函数）
 ├ conditions.ts      # 条件注册表（名字 → 函数）
 └ aiconfig.ts        # AI 配置类型 + 敌人默认状态机表

★ 完全数据驱动 / 敌人-队友共用：
  ├ 行为/条件 = 查表函数（behaviorTable / conditionTable），新增 = 注册函数
  ├ 敌人/队友共用同一套注册表 + 同一 AIStateMachine 解释器
  │   - 敌人：巡逻/索敌/攻击（见下）
  │   - 友军：守卫/跟随（后续配新状态表即可，不改框架）
  └ 一切参数在配置里调整（每个实体可覆盖，见示例注释）：
      行为参数（wander：speed/turnRate/turnInterval/targetBias/biasCamp；
               moveToTarget：speed；meleeSwing：duration）
      条件参数（seePlayer：radius/camp；inRange/outOfRange/loseTarget：radius）
      状态参数（minStay：最短停留秒数）

接口设计：
  AIComponent（挂在 EnemyBase/Ally）：
    { configId, stateMachine, camp, targetId, lastMoveDir, update(dt, ctx) }
  BehaviorContext（行为/条件统一上下文，模式层每帧注入）：
    { dt, time(累计), target(索敌目标), findTarget(camp → 位置) }
    └ 索敌完全解耦：findTarget 由 WorldMode 注入（camp='player' 查玩家），
      行为/条件只按阵营查，不依赖具体实体 → 敌人找玩家、友军找敌人
      只需换注入实现
  行为签名：behavior(entity, ctx, params) → void（移动/攻击 = 调实体公开方法）
  条件签名：condition(entity, ctx, params) → boolean

★ 关键机制（已实现并验证）：

  ① 状态流转（基准敌人普瑞赛斯，HUD/日志可观察）：
       patrol(游走) ──seePlayer(radius:8)──▶ chase(追击)
          ▲                                  │ inRange(1.5)
          │                                  ▼
          └──── attackFinished(挥完0.6s) ◀── attack(一次性挥击)
              or outOfRange(2) 或 loseTarget(12)

  ② minStay（防状态抖动）：
      AIStateMachine 记录进入状态的停留时间；未满 minStay 不转移。
      例：patrol.minStay=3 → 脱离战斗后至少真实游走 3 秒才重新索敌，
      否则 patrol 会被 seePlayer 一帧拉回 chase（"追击后不游走"的根因修复）。

  ③ 一次性攻击：
      meleeSwing 播完（duration 秒）标记 aiSwingDone → attackFinished 条件
      自动退出 attack 回游走。不再无限循环挥击（"永远卡 attack"的根因修复）。
      重新进入 attack 自动重开一轮挥击（自愈）。

  ④ 游走轻微偏向目标（targetBias/biasCamp）：
      Reynolds Wander 转向时刻，把随机转向角向指定阵营目标拉回 targetBias 比例
      （0=纯随机，0.04≈轻微）→ 巡逻路径整体缓慢倾向目标，但仍随机弯绕。
      注意：不能逐帧混合（每帧 8% 在 60fps 下也会秒级转向 = 直追玩家），
      只在周期转向时偏置才自然。biasCamp='' → 完全纯随机。

  ⑤ 状态播报（调试用）：
      WorldMode 左上角 HUD（0.2s 刷新）实时显示每个 AI 实体当前状态；
      EnemyBase 每秒 [AI] 日志（状态/坐标/刚体/显示帧/yaw）。

★ 与实体管线集成（EnemyBase）：
  ├ 构造：opts.aiConfig 传入 → 建 AIStateMachine + 注册 aiSystem（无配置 → 无 AI 静止）
  ├ updateAI：AISystem 每帧驱动（行为 → minStay 检查 → 条件 → 转移）
  ├ 移动：行为调 moveBy → CharacterController.moveToward（与玩家同一套位置逻辑）
  └ ★ 朝向由移动方向决定（非相机）：
      moveDir 与当前朝向夹角 → facing（前/后帧组）+ setYaw（0/π）
      静止 → 保留最后移动朝向（不面相机）→ 玩家绕背仍可看后帧

★ 与相机解耦（关键）：
  AI 实体朝向 = 移动方向（自主）
  玩家相机 = 纯观察者（facing 判定不再依赖相机位置）
  → 敌人巡逻时自然转身，玩家绕背看后帧（AI 不动时朝向固定）

性能：AI 实体 < 30（预算内）；每帧行为/条件 = 查表函数调用（轻量）
```

### 4.8 rapier 使用总览（特效 vs 物理分工）
```
★ 分工原则：特效（视觉）= 编辑器/播放器做；物理交互（力/碰撞/运动）= rapier 做

哪里用 rapier（物理交互）：
 ├ 移动碰撞：角色/敌人走路不穿墙、不穿地形
 │   - 动态刚体 + 地形固定刚体 → 碰撞拦截
 ├ 子弹：动态刚体 + 速度（物理推动飞行 + 碰撞命中判定）
 ├ 爆炸冲击：querySphere 找范围刚体 → applyImpulse（被炸飞）
 ├ 重力：世界重力 + 每刚体 gravityScale（Boss 局部重力场）
 ├ 击退/受击：命中时 applyImpulse（敌人被击退/击飞）
 ├ 掉落物：物品实体动态刚体（掉地上、物理堆叠）
 ├ 浮力：水面上实体 → 施加浮力（Gerstner 高度采样）
 ├ 拾取/交互：碰撞触发（走近箱子触发拾取）
 └ 移动平台/机关：运动学刚体（自己控制移动）

哪里不用 rapier（纯特效/表现）：
 ├ 特效：粒子/光/拖尾/爆炸视觉（编辑器 .scene.zip + 播放器）
 ├ 布料：GPU verlet（ClothSystem，独立模拟）
 ├ 水：Gerstner 顶点波（shader，不是物理流体）
 ├ 2D 贴片形变：软体形变（7.3，不是刚体动画）
 └ 动画：帧动画/位移（billboard 动画，非物理）

典型组合（爆炸 = 特效 + 物理）：
 ├ 特效层（编辑器/播放器）：爆炸火球/冲击波视觉
 ├ 物理层（rapier）：范围刚体被冲击力推飞
 └ 伤害层（游戏代码）：范围伤害结算
```

### 4.9 PhysicsWorld 封装（接口级）
```
PhysicsWorld（services/physics，唯一接触 rapier API 的地方）：
 ├ init()                      # 创建 world，设置重力（全局 -9.8；子弹 gravityScale=0）
 ├ addBody(entity, opts)       # 创建刚体+碰撞体（userData=entity.id）
 ├ removeBody(id)              # ★ 移除刚体（实体销毁联动，防止物理世界泄漏膨胀）
 ├ step(dt)                    # 固定步长物理步进（1/60，main.ts 每帧驱动）
 ├ setLinvel(id, vel)          # 设速度（子弹发射）
 ├ setVelocityXZ(id, x,z)      # ★ 只覆盖 x/z 速度（保留 y → 重力下落不被清零）
 ├ applyImpulse(id, force)     # 施力（击退/爆炸/被击飞）
 ├ setGravityScale(entity, s)  # 每刚体重力缩放（Boss 局部重力/子弹 0）
 ├ querySphere(pos, radius)    # 球体查询 → 命中实体 id 列表（userData）
 ├ castRay(ray, maxToi, excl)  # 射线查询（摄像机→准星落点；返回 userData+落点）
 ├ onCollision(handler)        # 碰撞事件（实体管线订阅并分发）
 └ getPosition / setPosition   # 位置读写（velocity 模式读回/钳制同步）

★ 刚体身份（踩坑总结，最重要的决策）：
  ├ ⚠ rapier 0.14.0 wasm 绑定缺陷：createRigidBody 返回的 handle 是错读值——
  │   早期创建碰巧读到小整数（≈索引）才"能玩"，后续创建读到递增垃圾值
  │   （栈内数据）→ Coarena 索引越界 → 刚体"找不到"
  │   ★ 处理：PhysicsWorld 内部自管 id → RigidBody 映射（id 从 1 递增不复用），
  │     对外接口不变（仍返回 number）；绝不信任/归一化 body.handle
  ├ 碰撞事件身份 = userData（entity.id，desc 注入 RigidBody）——
  │   handle 会被 rapier 复用，旧事件按 handle 查会误伤新实体
  └ 查询类（castRay/querySphere/intersects）返回 userData 而非 handle

★ 碰撞事件处理（两大约束，都踩过坑）：
  ├ ① drainCollisionEvents 回调中禁止修改物理世界（add/remove 刚体）——
  │    破坏 narrow-phase 迭代 → wasm 内存损坏 → 后续创建刚体返回垃圾
  │    → 回调只收集事件（userData 对），step 返回后统一派发
  └ ② 派发后"良性残余访问"：事件批次内先销毁后查 / 上一帧遗留 →
     getBody 判空静默返回（不告警；正常销毁流程的防御）

★ 刚体生命周期（实体管线联动，防泄漏）：
  EntityBase 构造（em.create）→ 建刚体（y = 脚底 + bodyOffsetY）
  EntityBase.dispose → em.destroy → physics.removeBody（自管 id 回收）
  ⚠ 漏掉 removeBody = 每颗子弹/每次销毁泄漏一个刚体（物理世界膨胀）

★ 角色碰撞统一方案（已实现，替换早期"位置强制覆盖+手动探测回退"）：
  ├ 全部物理实体 = dynamic 刚体 + 速度驱动 + 位置读回（PhysicsMode: velocity/read）
  ├ 角色：每帧 setVelocityXZ(moveDir×speed) → step 推进 → 读回位置
  │   碰撞完全由 rapier 处理（vs fixed 被挡 / vs dynamic 互推）
  ├ 碰撞体声明 = 实例基类属性（EntityBase.collisionVolume，CharacterBase 覆写胶囊/
  │   BulletBase 覆写球体）；刚体 y 偏移（bodyOffsetY）统一从属性取
  ├ 重力：全局 -9.8 → 被顶起会被拉回地面；顶飞钳制在模式层
  │   （clampCharacter：y > 地形+0.4 拉回+刚体同步，防"骑头"）
  └ 碰撞事件：EntityManager 订阅 onCollision → 按 userData=entity.id 查 bases
      → EntityBase.onCollision(other|null, started) 钩子（null=静态世界）

★ 主循环时序（main.ts → WorldMode.update）：
  ① AI 驱动（aiSystem.updateAll：索敌/行为 → 本帧移动方向）
  ② 实体管线（entities.update：onUpdate 速度目标 → syncPhysics → 动画 → 渲染 → 空间索引）
  ③ 角色钳制（clampCharacter：贴地/边界，实体+刚体同步）
  ④ 物理步进（physics.step 固定 1/60）
  ⑤ 渲染（renderAll 视野块裁剪 → renderer.render）
  ⚠ AI 必须在实体管线之前：否则移动方向滞后 1 帧
```

## 5. 背包系统（三角洲式网格背包）

### 5.1 数据结构
```
InventoryGrid = 网格（如 6×8 格），每格可空/占位
ItemInstance（物品实例，运行时）：
 ├ itemId        # 配置表引用（尺寸/图标/可堆叠数）
 ├ gridSize      # 占格尺寸（w×h，如 1×2 / 2×2 / 3×1）
 ├ rotation      # 0° / 90°（是否旋转，占格交换 w/h）
 ├ stackSize     # 当前堆叠数（可堆叠物品用）
 └ slots[]       # 占用的网格坐标（由 gridSize+rotation+anchor 计算）

物品类型（内容设计）：
 ├ 不可堆叠：武器/装备/遗物（各占一格或多格）
 ├ 可堆叠：弹药（60 个一组）/ 食物（可叠放）/
 │        材料（合成用）
 └ 堆叠上限：按物品类型配置（stackable.maxStack）
```

### 5.2 拖动交互状态机（鼠标/触屏通用）
```
状态：IDLE → HOLDING(暂存) → DRAGGING(移动) → DROPPING(旋转检测) → IDLE
 ├ IDLE → 点击物品 → HOLDING
 │   - 物品进入"暂存区"（视觉上跟随指针）
 │   - ★ 原位置被"清空"（记录原位置 backRef，网格该处变空）
 ├ HOLDING → 移动指针 → DRAGGING（物品跟随指针，可旋转）
 │   - 旋转：按键 R（桌面）/ 双击或按钮（触屏）→ rotation 切换 0°/90°
 │   - 拖到目标网格：实时高亮"可放置区域"（绿=能放，红=不能）
 ├ DRAGGING → 松开 → 放置检测
 │   - 检测：目标锚点 + 旋转后占格 全部在网格内 且 全部为空
 │   - 能放 → 放入该位置（占用格子，记录新位置）
 │   - 不能放 → ★ 返回原位置（backRef 恢复）
 └ 任意状态 → 取消（ESC/右击）→ 返回原位置

检测算法：
 canPlace(grid, item, anchor, rotation):
   for each 占格(由 size+rotation 算出的相对偏移):
     if 越界 → false
     if 该格被占用 → false   （或：目标是堆叠同物品 → 走堆叠逻辑）
   return true
```

### 5.3 堆叠逻辑
```
拖到"同物品 + 已存在堆"时：
 ├ 若目标堆 stackSize < maxStack → 合并（目标堆 + 拖拽堆）
 │   - 超出部分：留在原位置（或剩余量继续拖）
 │   - 例：拖 30 弹药到已有 40 的堆（上限60）→ 合并到 60，剩 10 回原位
 ├ 若目标堆已满 → 按普通放置处理（不能叠就找空位）
 └ 快捷操作：双击堆 → 拆分（如 60 → 30+30，拆一半到相邻空位）
```

### 5.4 交互事件流（与输入抽象解耦）
```
触屏/鼠标 → InputActions（抽象）→ InventorySystem
 ├ 触屏：长按物品 = 拾取（进入 HOLDING）/ 拖动 = DRAGGING
 │      双击 = 旋转 / 双击堆 = 拆分
 └ 桌面：左键拾取 / 移动 / R 旋转 / 右键或 ESC 取消
- 具体映射在 InputBindings，背包逻辑只消费语义（pickup/drop/rotate/cancel）
```

### 5.5 与携带限额/舰船仓库联动
```
两个网格容器：
 ├ 随身背包（外出携带，体积有限 → 每日带出/带回限额）
 └ 舰船仓库（本舰，容量大 → 囤积）
- 转移：背包 ↔ 仓库 拖动（同一套拖动系统，跨容器放置）
- 战利品拾取：找到空位放入
- ★ 放不下 → 留在原地（箱子/地上原样保留），不销毁不丢弃
- 数据都在 Session（可序列化，存档兼容）
```

### 5.6 遗物专属栏（即时生效的被动位）
```
遗物有专属装备栏（类似防具槽），但只是"组织方式"：
 ├ 专属栏：遗物槽（如 3~5 格，独立于背包网格）
 │   - 拖动放入 = 装备上（有图标展示，视觉上"穿戴着"）
 │   - 从槽位拖出 = 卸下（可放回背包）
 ├ 放不下 → 塞背包：背包里的遗物同样生效（无差别）
 │   - 遗物 = 即时生效的被动物品（持有即生效）
 │   - 装备栏 vs 背包 = 只有"整理"区别，无效果区别
 ├ 效果：持有即生效（无需"激活"操作）
 │   - 黑王冠（非携带型）：开局即在，永不占槽
 │   - 携带型遗物（能天使/塞雷娅等）：槽位 or 背包都生效
 └ 设计含义：
 │   - 遗物槽 = 快速查看/美观（"穿戴着谁的遗物"）
 │   - 背包 = 仓库（多拿几个遗物，全部生效，但占背包空间）
 │   - 取舍在"背包空间"而非"装备选择"——多带遗物 = 少带物资
- 数据：relicSlots[]（槽位引用）+ 背包内的遗物实例（都算持有）
- 生效判定：Session 里"持有遗物集合" = 槽位 ∪ 背包内遗物

★ 遗物效果结算（局外永久 / 局内生效 两类）：
 ├ 局外永久（每天开始时结算）：
 │   - 黑冠：每天开始时全属性 ×1.01（叠乘，day 层数=黑冠层数）
 │   - 结算时机：新的一天开始（舰船醒来）→ 应用到 player.stats
 │   - 存档保存：属性已并入 stats（Session 存最终值）
 │   - 例：day 10 的黑冠 = 属性 ×1.01^10 ≈ ×1.105
 ├ 局内生效（外出时处理）：
 │   - 能天使→攻速+ / 塞雷娅→护盾 / 银灰→CD- 等
 │   - 外出（进入 WORLD 模式）时应用修饰器到战斗 stats
 │   - 回舰船（模式切换）→ 修饰器移除（下一轮外出重新应用）

 │   - 结算点：每天开始（黑冠）+ 进入战斗模式（局内遗物）
 │   - 效果 = 属性修饰器表（relics.json 配置：效果类型+数值）
 │   - player.stats 存"基础值"，效果以修饰器叠加（不污染基础）
 └ 与 Session：黑冠层数存 Session；基础值存 Session；
     局内效果不存（每次外出重新应用）

## 6. 对话系统

### 6.1 对话数据结构
```

```

 ├ 条件：选项 condition 检查（context 查 Session/持有/天数）
 ├ 效果：节点/选项 effects 执行（EventBus 发出：给物品/扣血…）
 ├ 结束：到达终端节点 → 对话完成 → 触发后续（事件结算/剧情）

### 6.3 对话 UI（Canvas 自绘）
```

### 6.4 事件系统（对话的容器）
```

 │   - 遭遇幸存者：对话 → 选项（给物资/收留/无视）→ 结果效果

## 9. 资源管线

### 9.1 资源加载（AssetManager）
```
├ 同步加载：包内核心资源（启动即用）
├ 异步加载：分包/远程资源（主题区/抽卡演出，按需）
├ 缓存：已加载资源引用计数（chunk 卸载时释放）
└ 资源类型：.scene.zip / 纹理 / 音频 / 字体 / 配置 JSON
```
- 所有资源通过 AssetManager，禁止散落直接 new

### 9.2 美术资产统一（全部 = 播放器格式）
```
★ 原则：所有美术素材（角色/道具/特效/环境）统一两种格式，无 webp/jpg：

① ftx3 纹理包（.ftx3.gz，FtxAsset 播放）
   = 像素结构容器：基础色 + 量化残差 + 区域 bbox + 帧动画序列
   ├ 纯显示：角色帧动画/道具图标/世界贴片
   ├ 可再编辑：支持游戏内注入流体物理参数（全图平流）
   └ 体积小：5 帧主角包约 240KB（压缩后）

② 特效包（.scene.zip，Asset 播放器）
   = 像素结构 + 实体数据：区域实体边界 + 位移纹理（VAT 扭动/变形）
     + 每帧变换（offset/scale/rotation）+ 可挂流体
   ├ 带边界帧：扭动/变形/位移类效果（布料、旗帜、爆炸、水流）
   ├ 每实体独立：边界光栅化障碍物 + 顶点动画
   └ 渲染：模板裁剪 + 位移 + 变换 + 流体合成（GPU）

为什么 webp/jpg 做不到：
  ├ 像素格式只能存"样子"，不能存"结构"（边界/残差/量化元数据）
  ├ 无法在游戏内解耦注入物理参数（流体作用在残差数据上）
  └ 无法运行时编辑扭动/变形（实体边界 + 位移纹理是数据，不是像素）

加载管线（AssetManager 统一）：
  ftx3 → FtxAsset.load → 帧纹理对（base+residual）
  .scene.zip → Asset.load → 帧纹理 + 实体网格 + 播放控制器
  .phys.json → 公共参数库（JSON 解析 + 缓存，可注入任意资产）
```

### 9.2a 素材体积预算（硬约束）
```
★ 目标：首发整包 ≤ 1.5MB（当前实测：代码 gzip 37KB + 素材 528KB）
  当前占位资产：主角 244KB（5 帧）+ 普瑞赛斯 284KB → 需按预算重做/裁剪

按角色/系统分配（制作素材时卡死上限）：
  ├ 主角（维维美）纹理 + 技能特效      ≤ 1MB
  │    ├ 纹理包（帧动画，纯显示）       预算大头留给特效
  │    └ 技能特效（.scene.zip，多实体+VAT）≤ 500KB
  ├ 最终 Boss 纹理 + 特效（合计）      ≤ 1MB
  ├ 普通敌人/友军/道具/场景贴片         各 ≤ 几十 KB
  │    ├ 敌人：基础帧 2~4 帧，无特效或极简
  │    ├ 道具图标：单帧小尺寸
  │    └ 环境/贴片：纯显示帧，无实体数据
  └ 公共物理参数（.phys.json）          ≤ 10KB（JSON，已含预算内）

省体积的手段（能省则省，按顺序）：
  1. 帧数精简：动画 2~4 帧优先（循环动画帧间过渡由播放器插值）
  2. 残差量化：残差数据是体积大头 → 降量化位数/稀疏区域
  3. 特效降实体数：边界实体只保留必要部分（减 VAT 位移纹理分辨率）
  4. 避免重复：共用纹理帧（同造型不同角色复用 base 帧）
  5. 尺寸限制：主角/Boss 全画幅，其他角色缩小画幅（bbox 越小越省）

审核：每次导出素材后记录体积，超预算 → 按上述手段裁剪（写进导出手册）
```

### 9.3 特效包（.scene.zip）管线
```
编辑器导出 → 游戏包内（或分包/远程）→ AssetManager.load
 ├ 加载即解析（播放器 decodeMultiFrame + 实体网格构建）
 ├ 实例化：每实体一个 controller（挂到 EffectSlot）
 └ 卸载：引用计数归零 → dispose（释放纹理/几何/流体解算器）
```

### 9.4 美术资产运行时编辑（可编程）
```
★ 核心：美术资产 = 播放器实例（Asset/FtxAsset），游戏内通过函数编辑，
   支持动态注入与取消，公共参数库复用于任意资产。

① 物理参数注入/取消（状态效果驱动）
   injectPhysics(config | .phys.json id)
     - 纯纹理包（FtxAsset）：注入 → 全图流体平流（无实体障碍物）
     - 特效包（Asset）：注入 → 覆盖该帧内嵌参数（实体边界仍作障碍物）
   clearPhysics()
     - 取消注入 → 恢复原样（无物理 或 恢复原内嵌参数）
   例：主角中毒
     StatusSystem 挂中毒 → fx.injectPhysics(公共库 poison 参数)
       → 播放器流体解算器重建 → 纹理出现毒雾扩散/色相偏移
     中毒解除 → fx.clearPhysics() → 恢复正常纹理
   ★ 公共参数库复用：同一份 poison.phys.json 可注入任意实体纹理

② 实体/扭动编辑（特效包专属，EffectSlot 持有）
   setDistort({ enabled, amplitude, frequency, speed, rotation })
     - 修改实体区域呼吸式扭曲（与编辑器参数一致，运行时可调）
     - 例：旗帜风速增强 → 提高 amplitude/frequency；风暴停 → 关闭
   setTextureTransform({ offset, scale, rotation })  # 底图变换
   后续扩展：替换实体边界/位移纹理（区域形变重塑）

③ 播放层编辑（控制器已有 + 扩展）
   setFps / setOrder / loop / goto / hold 等
   setFrameTextures(base, residual)  # 换皮（受伤/形态切换）

★ 与状态系统联动（EffectSlot 生命周期）：
   ├ 生成：AssetManager 加载 → 创建控制器 → 挂到实体
   ├ 状态注入：StatusSystem(中毒/着火/冰冻) → injectPhysics/clearPhysics
   ├ 环境编辑：WindSystem → setDistort（风速/风向）
   └ 销毁：实体销毁 → dispose（释放全部运行时资源）

④ 流体状态转移（跨资产，视觉/物理彻底解耦）
   需求：敌人被击杀（有血液流体效果）→ 血液"转移"到地面纹理
        → 地面继续流体解算（血泊扩散/渗入），敌人实体销毁
   技术：
   ├ FluidSolver 加状态转移 API：
   │    exportState() → 快照（colorGrid/velocityGrid/densityGrid）
   │    importState(state) → 写入/叠加到目标解算器
   ├ 或简化注入：groundFluid.injectAt(死亡点, {color: 血红, density})
   │    → 目标解算器自行演化（血液自然散开，不保形）
   ├ 决策：推荐"注入"（更符合血液落地扩散的物理直觉，实现简单）
   │       保形转移（transferFrom）作为后续增强
   流程：
   ├ combat 击杀判定 → EventBus 死亡事件 { position, bloodState? }
   ├ GroundFxService（services/fx 地面特效管理）：
   │    击杀点 → 地面 FtxAsset 按需激活流体（注入 blood.phys.json）
   │    → transferFrom(敌人流体) 或 injectAt(死亡点, 血液参数)
   └ 地面继续 step() → 血泊在地面解算/扩散
   性能/持久性：
   ├ 地面流体"按需启用"：有血液注入才激活解算器，平时零开销
   ├ 血泊属于战斗运行时状态：随地图卸载/每日新 seed 消失，不存档
   └ 地面 = FtxAsset + 可注入流体（与角色同一套管线，无特殊实现）
```

### 11.2 输入传递结构（InputFrame，避免参数蔓延）
```
★ 模式/实体统一消费一个 InputFrame（每帧打包一次，替代多参数传递）：
InputFrame = {
  moveAxis,      # 移动轴向（语义）
  lookAxis,      # 视角增量（鼠标/触屏拖拽）
  zoomAxis,      # 滚轮/捏合缩放增量
  held,          # 按住状态（★ attack=左键长按持续发射；跳跃=连跳等长按语义）
  pressed,       # 消费式按键（攻击/闪避/技能/交互）
  interactions,  # 交互事件队列（tap/hold/drag）
  cameraFrame,   # 相机坐标系（forward/right，角色移动/朝向用）
}
数据流：Binding(设备) → InputActions(语义) → 模式组包 InputFrame → 实体管线
好处：加新输入（跳跃/技能）不改方法签名，只扩字段
```

### 11.1 第三人称标准相机（已实现 CameraController）
```
★ 行业标准参数（原神/塞尔达/古墓丽影共识）：
 距离：3.5~5（角色高度的 2~4 倍）
 俯仰：20°~30°（0.35~0.52 rad）——默认 0.5（28.6°）
 lookAt：角色肩部~头顶（0.8~1.0 × 身高）——默认 0.9
 相机高度：角色半高 + 距离·sin(俯仰)
 角色位置：画面下 1/3（相机高于角色 + 俯视自然形成，非 lookAt 硬顶）
 准星：屏幕中心 = 前方远处地面（角色在下方不挡）

① 输入 → 目标角度（鼠标/触屏拖拽 → lookAxis 增量）：
   targetYaw（水平环绕）/ targetPitch（俯仰，clamp 0.2~1.1 rad）
   相机实际角度 = lerp(当前, 目标, 阻尼) —— 跟手但不瞬跳
   （鼠标控制的是"期望视角"，不是直接转相机）
   滚轮缩放：zoomAxis（增量）→ distance = clamp(distance + zoom·sens, 2.5, 12)
   —— 标准第三人称：滚轮 = 相机距离（视觉上高低/远近），非改俯仰角

② 球坐标定位（相机在角色后上方）：
   相机位置 = target + (sin(yaw)·D·cos(pitch),
                        角色半高 + D·sin(pitch),
                        cos(yaw)·D·cos(pitch))
   相机高度 = 角色半高 + 距离·sin(pitch)  ← 含角色半高，避免贴地被身体挡

③ 注视点（准星基准）：
   lookAt = target + (forward·lookAhead, 角色身高×1.1, forward·lookAhead)
   - lookAt 在角色头顶之上 → 角色落在画面下方，准星不被角色遮挡
   - lookAhead（前方视野偏移）与 pitch 共同决定"准星射线与地面的
     交点距离"：交点 ≈ 角色前方 2~3 世界单位（可打近处地面）

④ 相机坐标系（角色移动/朝向用）：
   forward（画面深处）= (-sin(yaw), 0, -cos(yaw))
   right（画面右侧）  = (cos(yaw), 0, -sin(yaw))
   角色移动 = right·左右轴 + forward·前后轴（相机相对移动，
   W 永远朝画面深处，视角转了也一样）
   角色朝向 = 移动方向与 forward/right 的夹角判定（前/后帧组 + flipX）

⑤ 准星（交互基准，与设备解耦）：
   准星固定屏幕中心（UI 层 Crosshair 组件）
   交互/攻击射线 = 从屏幕中心发出（NDC (0,0)）与地形求交
   —— 鼠标只控视角，瞄准始终以准星为准（触屏/手柄天然支持）

⑥ 与模式的关系：相机是独立服务（services/camera/），
   模式切换时 reset(yaw, pitch) 复用，不重建

### 11.1a 相机绑定角色（平滑聚焦点 + 脚步抖动）
```
★ 标准 TPS 跟随机制（参考 three.js OrbitControls 的 target 模式）：
 聚焦点 target = 角色位置 + 肩部高度 + 跳跃偏移（模式层传入 height）
  ├ smoothedTarget.lerp(期望点, dt × targetDamp)   # 平滑聚焦点
  │   → 角色跳跃：聚焦点上移 → 相机跟着升（跟跳）
  │   → 角色高频抖动：lerp 过滤 → 相机稳定（抖动过滤）
  ├ 相机位置 = smoothedTarget + 球坐标偏移（yaw/pitch/distance 不变）
  └ targetDamp 可调：大=更跟手 / 小=更稳

★ 第一人称脚步抖动（移动时，随机化）：
  ├ 触发：第一人称（distance ≤ 阈值）且角色在移动
  ├ 机制：每 beat（0.12~0.28s 随机节拍）重新随机
  │    幅度（基础值 × 0.5~1.5）/ 相位 → 不规则走路感
  ├ 原则：完全一致的 sin 抖动 = 机械感，不如不抖
  │    → 随机节拍 + 随机幅度 + 随机相位
  └ 参数：footstepShake { enabled, baseAmplitude, beatMin, beatMax }
```
