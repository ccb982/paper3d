# 明日方舟主题肉鸽 —— 架构设计（v2）

> 背景：普瑞塞斯团灭泰拉大陆大多数角色，仅剩死魂灵形态的博士与维什戴尔抵抗。
> 世界观：**超新星世界观**——维什戴尔为了解决失控的源石踏足未知空间（太空），罗德岛本舰漂在太空中。
> 玩法：每日舰船抽卡（决定进程，抽到 Boss 直接 Boss 战）→ 大世界探索/采集/战斗 → 敌人每日增益。
> 形态：**3D 大世界 RPG**，角色用 **2D 贴片（billboard）**，美术贴近明日方舟。
> 性质：**纯肉鸽，无存档**，一局一局打。

**世界观要点（超新星/太空，源自官方皮肤设定）**
- 皮肤设定原文：*"维什戴尔为了解决失控的源石而踏足未知空间时的装扮。按本人的说法，既然是来清理垃圾的，那就要有相应的仪式感。"*
- 皮肤台词原文：*"终于上来了，博士，这艘漂在太空里的船算是你的老家？心疼了吗？不过也由不得你了。'维什戴尔'，来摧毁你们疯狂的源石计划了。"*
- 核心冲突：**源石计划失控** → 维什戴尔踏足太空（未知空间）→ 博士的罗德岛漂在太空中
- **罗德岛干员已基本团灭**：
  - 普瑞塞斯/源石失控吞没了泰拉与罗德岛干员
  - 只有博士（死魂灵形态）+ 维什戴尔还在抵抗
  - → 解释"为什么只有维什戴尔一个可操纵角色"
  - → 解释"为什么抽卡才能获得助战"（幸存者/英魂/残响）
  - 抽卡抽到的干员 = 幸存者 / 死魂灵残响 / 源石拟态（叙事自洽）
- 游戏融合设定：
  - 罗德岛本舰 = 漂在太空中的船（博士/死魂灵的家）
  - 维什戴尔登船/降落地表 = "清理失控的源石"
  - 泰拉地表 = 被源石失控侵蚀的探索战场（chunk 生成的主题区）
  - 敌人 = 源石失控产物 / 普瑞塞斯残党（每日增益的叙事解释）
  - 太空 ↔ 地表切换 = 出击/返回（降落/回收动画）
- 美术基调：太空舰船（冷灰/舷窗/星空）+ 泰拉地表（方舟风块状地形）
- 情感基调：空旷的舰船 + 团灭后的孤独感（只有两人的抵抗）

## 0. 核心形态决策（已拍板）

| 项 | 决策 | 说明 |
|----|------|------|
| 平台 | **轻量化游戏平台（多平台）** | 微信小游戏 / 抖音小游戏 / Web / H5 等，核心逻辑平台无关 |
| 包体 | **总包 ≤ 20MB**（主包 4MB + 分包） | 资源体积是硬约束，见"包体预算"章节 |
| 世界观呈现 | **3D 大世界** | three.js 全 3D 场景/地形/相机 |
| 角色 | **2D 贴片（billboard）** | 角色永远是面朝相机的 2D 立绘/小人片，类《八方旅人》纸片人 RPG 质感 |
| 战斗 | **单角色实时操控** | 只有维什戴尔可操纵，动作式实时战斗（移动/闪避/攻击/技能） |
| 地图 | **迷宫 + 块状开放结合** | 不同主题地区用不同生成风格，或同一地区混合 |
| 存档 | **无** | 肉鸽一局制，死亡/通关即结束，SessionData 只在内存 |
| 抽卡 | **后期打磨** | 先做逻辑（卡池/概率/结果），演出最后做 |
| UI | **Canvas 自绘 UI**（无 DOM 依赖） | 平台无关：所有平台都能跑 Canvas（见"UI 系统"章节） |

### 平台无关架构（核心原则）
```
┌─────────────────────────────────────┐
│ 游戏核心（平台无关）                 │
│  Core/Entity/Map/Combat/UI引擎      │
│  └ 只依赖：Canvas + WebGL + WASM    │
├─────────────────────────────────────┤
│  PlatformAdapter（平台适配层）       │
│  ├ 微信小游戏：canvas桥接/存储/音频  │
│  ├ 抖音小游戏：同上（API 不同）      │
│  ├ Web/H5：直接浏览器 API            │
│  └ 其他：按需接入                   │
└─────────────────────────────────────┘
```
- **核心逻辑零平台 API**：不 import 任何 `wx.` / `tt.`，只通过 Adapter 接口调用。
- Adapter 接口（最小集）：`Canvas/GL上下文`、`Storage`、`Audio`、`Touch事件`、`包内资源加载`。
- 换平台 = 写一个新 Adapter，核心零改动。
- 开发用 Web 环境（浏览器最快迭代），发布时接目标平台 Adapter。
- 包体 20MB 约束按"最严平台"（微信主包 4MB）执行，天然满足其他平台。

### 微信小游戏环境差异（作为"最严基准"）
```
❌ 无 DOM API → UI 全 Canvas 自绘（平台无关方案）
❌ 无 navigator.clipboard / fetch 部分能力受限
✅ WebGL 1/2 可用 → three.js 可跑（需适配层）
✅ WASM 可用 → rapier 可跑（体积 1~2MB）
✅ 文件系统：包内资源 + 远程资源缓存（wx.env）
音频用 wx.createInnerAudioContext（非 WebAudio）
```

## 1. 技术栈

| 项 | 选择 | 说明 |
|----|------|------|
| 语言 | TypeScript | |
| 渲染 | three.js | 平台适配层桥接（微信/抖音 canvas） |
| 物理 | rapier（WASM） | 体积 ~1.5MB，可接受 |
| UI | **Canvas 2D 自绘** | 平台无关，所有平台都能跑 |
| 特效 | 编辑器(.scene.zip) → 播放器 | 已打通的管线 |
| 地图 | 程序化生成（seed 驱动） | 省包体（不塞预置地形资源） |
| 音频 | 平台 Adapter 封装 | Web=WebAudio / 微信=InnerAudioContext / 抖音=tt API |

### PlatformAdapter（平台适配层，核心架构）
```
游戏核心绝不 import wx./tt./浏览器 API，只依赖 Adapter 接口：
┌─────────────────────────────────────────────┐
│ PlatformAdapter 接口（最小集）               │
│  ├ createCanvas()      → Canvas + GL 上下文 │
│  ├ loadAsset(path)     → 包内/远程资源      │
│  ├ storage.get/set     → 本地存储（若平台有）│
│  ├ audio.play(bgm/fx)  → 音频统一入口       │
│  ├ input.touch         → 触摸/鼠标事件      │
│  └ platform info       → 尺寸/DPR/能力探测  │
├─────────────────────────────────────────────┤
│ 实现：                                          │
│  ├ WebAdapter（开发默认，浏览器直跑）          │
│  ├ WeChatAdapter（微信小游戏）                 │
│  └ DouyinAdapter / 其他（按需）                │
└─────────────────────────────────────────────┘
```
- 开发流程：浏览器里开发调试（WebAdapter）→ 发布时切换目标平台 Adapter。
- 换平台 = 写一个 Adapter 文件，核心零改动。

### UI 系统（Canvas 自绘，平台无关）
```
UI 层 = 自绘 Canvas 2D 组件系统（不依赖 DOM，任何平台可跑）
 ├ UIEngine：组件树（Panel/Button/List/Slider/Toast…）
 ├ 样式：矩形/圆角/阴影/文字（Canvas 2D API）
 ├ 事件：触摸坐标 → 命中测试 → 组件回调
 ├ 每帧 draw（或脏标记重绘）
 └ 与游戏 3D 场景分离：一个全屏 Canvas 2D 覆盖层（或同 canvas 分层）
```
- 自绘 UI 的代码量可控（几百行核心），不需要引入 DOM 模拟库。
- 字体：包内字体子集（注意体积）/ 平台系统字体。
- **同一套 UI 引擎在 Web 和所有小游戏平台通用**（都是 Canvas）。

### 为什么不用 React（v2 结论）
- 轻量化平台（微信/抖音小游戏）**没有 DOM**，React 无法运行。
- UI 用 Canvas 自绘，跨平台一致，逻辑独立于渲染，与编辑器（React）完全无关。

### 2D 角色方案（billboard）
```
BillboardSprite
 ├ texture      # 2D 立绘/小人贴图（方舟风格，多朝向可选）
 ├ mesh         # 始终面对相机的四边形（facing camera）
 ├ flip         # 左右翻转（移动方向）
 ├ animation    # 帧动画（走/攻/受击/死亡，纹理集）
 └ shadow       # 脚下的假阴影贴片（地面锚点）
```
- 角色挂点（头顶/手部/胸口）用于挂特效（播放器）。
- 敌人同方案。Boss 可放大贴片或半 3D。

## 2. 包体预算（总包 ≤ 20MB）

```
按"最严平台"执行：微信小游戏主包 4MB、总包（含分包）≤ 20MB
满足微信即天然满足其他平台（抖音/Web 限制更宽松）
预算分配（约 18MB 预留 2MB 余量）：
├ 代码（JS）             ~3MB    three.js(600K) + rapier-wasm(1.5M) + 播放器 + 游戏代码
│   └ 播放器实测：raw 200KB / gzip 54KB（仅占代码预算 ~2%）
├ 音频                   ~4MB    BGM 2~3 首(每首~1MB mp3) + 音效集(~1MB)
├ 立绘/干员图鉴          ~3MB    WebP 压缩，每张 100~200KB
├ 特效 .scene.zip 包     ~2MB    子弹/技能/爆炸/抽卡特效（编辑器导出，体积受控）
├ 地形/纹理素材          ~3MB    WebP + 程序化生成减少贴图需求
├ 字体                   ~1MB    中文字体子集（仅用到的字）
└ 剩余                   ~2MB    余量
```

### 包体控制策略（贯穿全项目）
```
① 程序化生成优先：地形/装饰/粒子纹理用 shader/噪声生成，不存贴图
② 纹理压缩：全部 WebP（微信支持），PNG 仅用于需要透明边缘的 UI 图标
③ 音频压缩：BGM 用 96kbps mp3，音效用短片段（<2s），复用同一音效
④ 立绘分级：卡池立绘（高） vs 战斗小人贴片（低），两套分辨率
⑤ 特效包瘦身：编辑器导出时限制分辨率/粒子数/时长（播放器已有此能力）
⑥ 分包策略：核心玩法(主包) + 各主题区素材(分包，按需加载)
⑦ 远程资源：非核心资源（抽卡演出素材）走远程 CDN 缓存，不进包
```

### 与编辑器/播放器的衔接（包体角度）
- 特效编辑器导出的 .scene.zip 需按 20MB 预算约束制作（不是无限精度）。
- 播放器已有分辨率控制 → 导出时可选低分辨率档位。
- 纹理统一走 WebP 压缩管线。

## 3. LOD（3D 大世界重点）

### 地形 LOD
| 距离 | 方案 |
|------|------|
| 近（< 20m） | 全精度块状地形（贴图+法线+细节装饰） |
| 中（20~60m） | 简化块（合并网格，去掉法线细节） |
| 远（> 60m） | 低面数大平面 + 远景贴片（贴图蒙版） |

### 实体 LOD
| 距离 | 角色/物体 |
|------|-----------|
| 近 | 2D 贴片全细节（帧动画+阴影+特效挂点） |
| 中 | 贴片减帧（4 帧→2 帧，特效挂点停止发射） |
| 远 | 贴片换静态单帧（不播动画），无阴影 |

### 特效 LOD
- 粒子按距离降采样/停止发射。
- 爆炸/技能特效：距离 > 阈值直接不实例化（或播放简化版）。
- 子弹特效（拖尾）：只对玩家和近处敌人开全特效。

### 阴影 LOD
- 近处实体开 shadowMap，远处贴片用假阴影（地面圆形贴片）。
- 级联阴影（CSM）或简化：单张全场景阴影贴图，近处 512 近切。

### 实现：VisibilityManager
```
每 N 帧遍历实体 → 按相机距离分级（近/中/远）
 → 切换贴片细节 / 停特效 / 停动画 / 开关阴影
```

## 5. 游戏流程（一局肉鸽，无存档）

```
┌────────────────────────────────────────────┐
│ 开新局（随机 seed 初始化）                  │
├────────────────────────────────────────────┤
│  舰船(日常·固定地图·角色自由走动)          │
│  ├ 抽卡（单一卡池：外出前至少1次，可多次）   │
│  │   ├ 抽到大Boss → 直接进大Boss战          │
│  │   ├ 抽到角色 → 助战/增益                │
│  │   └ 抽到道具 → 进背包                   │
│  ├ 部署 / 商店 / 整理背包                   │
│  └ 出发 ──────────────────────────────────┤
│                                            │
│  ┌──────────────────────────────────────┐  │
│  │ 大世界探索（战斗模式·舰船被守卫）     │  │
│  │  ├ 采集 / 战斗 / 开箱 / 事件          │  │
│  │  ├ ★ 舰船是守卫目标：敌人会袭击舰船    │  │
│  │  │    需在探索与回防之间权衡          │  │
│  │  ├ 完成目标 或 撤退                    │  │
│  │  └ 返回舰船 ─────────────────────────┘  │
│  └──────────────────────────────────────┘  │
│                                            │
│  每日结束 → 敌人增益（日期推进）            │
│  死亡 / 舰船被毁 / 通关 → 局结束 → 结算     │
└────────────────────────────────────────────┘
```

**舰船（固定地图，Hub + 守卫目标）**：
- 独立固定地图，角色可自由走动（非静态 UI 界面）。
- 含：抽卡机、仓库/背包、商店、部署区、NPC、剧情触发点。
- 与其他地区共用 3D 场景/相机/角色操控（只是无战斗敌人）。
- **进入大地图后，舰船是守卫目标**（见战斗章节"舰船守卫"）。

**肉鸽一局制**：
- 无跨局存档；Session 只存当前局（seed、day、背包、卡池进度）。
- 死亡 = 局结束（可结算展示本局数据）。
- 每日增益贯穿本局，日期越往后越难，逼玩家推进。

**每日增益（数值 + 敌人种类）**
```
数值增益：enemyMultiplier = 1 + (day-1)*0.12 + floor((day-1)/7)*0.5
种类解锁：按日期阈值引入新敌人种类（可配置表）
 ├ day 1~3   ：基础兵（近战/远程）
 ├ day 4~7   ：+精英兵、袭扰兵（优先袭击舰船）
 ├ day 8~14  ：+装甲兵、自爆兵
 ├ day 15+   ：+重装精英、特殊机制敌人（召唤/冲刺/范围攻击）
 └ 每阶段在生成器布点表中加入新种类（与主题地区绑定）
```
- 数值曲线 + 种类表都做成配置，日期推进时敌人池动态扩展。
- 新种类由 `ChunkActorGenerator` 按 (day, 主题) 从激活的敌人表中采样。

## 6. 抽卡模块（逻辑先行，演出后补）

### 单一卡池（核心规则）
```
只有一个卡池：Boss / 角色 / 道具 都在里面
 ├ 每次外出前：必须至少抽 1 次
 ├ 可抽任意多次（自主决定抽多少 → 自主决定本局进程）
 ├ 抽到大Boss → 直接进大Boss战（玩家可主动"抽到 Boss 为止"）
 ├ 抽到角色 → 助战/增益
 ├ 抽到道具 → 进背包
 └ 抽得越多：保底计数前进，也更可能触发 Boss 战（赌注）
```

**免费抽卡 + 恶搞方舟本体（设计意图）**
```
★ 抽卡完全免费，无货币/资源消耗
 ├ 风险不在"资源"，在"进程"：抽得越多 → 离 Boss 越近
 ├ 上限 50~60 抽（保底机制保证）→ 每局 Boss 战迟早会来
 ├ 抽卡 = 玩家自选的"进度快慢调节器"：
 │   - 想多探索积累（遗物/装备）→ 少抽，远离 Boss
 │   - 想推 Boss → 狂抽，自找的
 ├ 恶搞方舟本体：把"氪金抽卡"的痛点反转成免费机制
 │   - 方舟：抽不到想要的就氪 → 你的游戏：抽到 Boss 是自找的
 │   - 二次元仪式感保留（至少1抽/日），但经济负担为零
 └ 平衡点：抽卡推进 vs 探索积累的时间竞争（纯意志力游戏）

★ 抽到 Boss = 立即迎战（刻意的残忍，无缓冲）
 ├ 不给"延迟备战"选择：抽到就是 Boss 战，直接传送
 ├ 运气不好带着弱装备进 Boss 战 → 死 → 局结束（肉鸽常态）
 ├ 设计意图：强化"每次抽卡都是赌命"的紧张感
 │   - 多抽 = 更早面对超越自己准备的 Boss（自食其果）
 │   - 玩家必须权衡：装备够了没？敢不敢再抽？
 ├ 与肉鸽精神一致：运气差死掉是常态，重开一局即可
 └ 叙事自洽：普瑞塞斯不会等你准备好

★ 稀有度恐惧（对抽卡文化的彻底反转）
 ├ 常规二次元：渴望抽到稀有角色（6★ = 惊喜）
 ├ 本游戏：稀有档 = 大Boss = 死亡倒计时 → 玩家害怕稀有
 │   - 出金光效 = 心跳加速（不是惊喜，是恐惧）
 │   - 抽到 6★ 时第一反应是"完了"而不是"好耶"
 ├ 反转的戏剧性：
 │   - 卡池里"角色"也是 6★，但可能同时被 Boss 挤掉
 │   - 玩家从"盼 6★"变成"求求你出个 3★ 吧"
 │   - 低稀有度（道具/角色）反而安全、有价值
 └ 情感曲线：每抽都是"希望-恐惧"的赌博，抽卡不再是奖励而是赌局
```

### 明日方舟同款概率与保底（P0 核心）
```
★ 6★ 基础概率 2%（方舟数值）
 ├ 前 50 抽：概率保持 2%
 ├ 第 50 抽未出 6★ 后：每抽 +2%（50抽后第1抽=4%，第2抽=6%…）
 ├ 极限情况：50~60 抽左右基本必出 6★（因 +2%/抽 快速累加）
 ├ 抽到 6★：在【角色 / 大Boss】间按权重二选一
 │   （大Boss 是 6★ 档里的"最稀有档"）
 ├ 保底：10 抽内必有 5★ 或以上（方舟同款）
 ├ 井：累计抽数达到阈值可自选/必定触发（数值待定）
 └ 保底/井计数记录在 Session（一局内有效，局结束重置——肉鸽特性）
```

**大 Boss 战的可及性（玩家主动选择）**
```
抽到大Boss = 直接进大Boss战
 ├ 概率路线：50~60 抽极限触发（6★ 递增 + 权重）
 ├ 主动路线：玩家可不断十连"硬抽 Boss"——赌/求 Boss 战
 │   - 想挑战/想拿 Boss 掉落 → 主动抽到 Boss 为止
 │   - 不想打 Boss → 见好就收，停止抽卡直接出发
 └ 抽卡 = 玩家完全自主的进程开关（不是被动的随机惩罚）
```
- 玩家可以主动选择结束抽卡（见好就收），或不停十连把 Boss 抽出来。
- 抽卡 = 玩家对进程的"赌注"：想强 → 多抽（也更可能抽到 Boss）。
- 每日至少 1 抽的约束保证"每天都有抽卡"这个二次元仪式感。

## 7. 地图系统（片状加载 + 迷宫/块状开放结合）

### 主题地区（多主题包）
| 主题 | 生成风格 | 特色 |
|------|----------|------|
| 龙门外环 | 块状开放 | 高低差平台、城墙、市场 |
| 卡西米尔竞技场 | 块状开放 | 开阔、观众席、角斗区 |
| 哥伦比亚实验室 | 迷宫 | 走廊+房间、试管/灯光、Boss房 |
| 乌萨斯废墟 | 迷宫 | 黑暗、窄道、伏击 |
| 罗德岛舰船 | 固定 | 基地（非随机，固定 chunk 集） |

### 片状加载（Chunk Streaming）
```
大世界 = 若干 Chunk（如 64m × 64m 一块）拼接
 ├ 角色进入新 chunk 边界（如距边界 < 1.5 chunk）→ 请求生成该 chunk
 ├ 生成的 chunk 由 (seed, chunkX, chunkZ, 主题) 确定性派生 → 可复现
 ├ 只加载/渲染当前视距内的 chunk（远 chunk 卸载网格，保留数据/或全卸载）
 └ 探索越多，地图自动向外扩大（无固定地图尺寸）
```
- **数据分层**：
  - `ChunkData`（纯数据：地形高度/方块类型/资源点/刷怪点）——轻量，可保留
  - `ChunkMesh`（生成的网格/贴片）——按视距加载/卸载（LOD 联动）
  - `ChunkActors`（实体的摆放：敌人/箱子/装饰）——chunk 激活时才实例化
- **生成流水线**：`chunk 请求 → 生成器(seed派生) → 网格/碰撞/布点 → 激活`，放入队列异步处理，避免卡顿。
- 舰船（固定地图）用同一套 chunk 系统，只是 chunk 数据来自预置而非生成器。

### 两种生成器（可组合）
```
MapGenerator (按主题选风格)
 ├ BlockOpenGenerator    # 块状开放：矩形块拼接、平台、路径
 └ MazeGenerator         # 迷宫：房间+走廊（BSP/回溯法）、关卡门

每 chunk 按主题风格独立生成，chunk 边界用连接点（门/坡道）衔接
地图内容 = 骨架 + 主题素材(贴图/装饰) + 资源点 + 敌人布点 + 宝箱
```
- seed 驱动全程 → 可复现，可查看本局种子。
- 大世界：主题区可以跨界连续（龙门外环 chunk 邻接哥伦比亚实验室 chunk 时风格渐变），探索自由，boss 区单独。

### 探索进度（肉鸽目标）
- 大 Boss 有专属地图生成机制（见 Boss 系统），探索到触发条件即进入 Boss 区。
- 探索越深，敌人增益与稀有度提升（与每日增益联动）。

### 迷雾 / 视野系统（信息 = 资源）
```
右上角小地图：默认大面积迷雾
 ├ 留痕（记忆信息）：探索过的地形/资源点永久留痕
 │   - 只显示地形（走过的路/地形结构/资源点位置）
 │   - ★ 不显示怪物——怪物只在"持续视野"内才实时显示
 ├ 持续视野（实时信息）：角色周边 + 舰船周边
 │   - 显示当前范围内的怪物/袭扰波次/动态目标
 │   - 离开视野 → 怪物从地图消失（只能靠记忆/警觉）
 └ 设计含义：地形是"记忆"，怪物是"实时"——信息分层

开图道具 = 【可露希尔的无人机】（大型道具，非遗物）
 ├ 背景：可露希尔是罗德岛工程主管，无人机是她的标志
 │   - 团灭后，她留下的无人机仍在天上飞 → 她的遗产
 ├ 分类：大型道具（占背包容量大，携带数量有限）
 │   - 体积大 → 不能带很多（载重/格子占用高）
 │   - 例：带 1~2 台已是上限（具体数值待定）
 ├ 效果：在角色位置展开一片"持续视野"（如半径翻倍/大范围）
 ├ 价值：信息优势 = 探索效率（实时看到周围怪物/资源/袭扰方向）
 ├ 敌人不攻击它 → 不会被拆，属于"永久型信息道具"
 ├ 局限：只开"当前所在区域"的视野，走远了视野消失（但留痕保留）
 └ ★ 获取途径：
 │   - 卡池道具池（抽到 = 纯赚的安全奖励档）
 │   - 合成台制作（消耗采集物资，配方表）
 │   - 即：即使脸黑抽不到，也能靠探索积累合成获得

与舰船守卫联动：开图道具让你提前看见袭扰波次动向
 └ 迷雾下舰船遇袭只能靠警报 → 开图后能提前规划回防路线（决策更从容）
```

### Boss 系统（两层级）
```
┌─────────────────────────────────────────────────┐
│ ① 常规小 Boss（地图随机刷新）                    │
│   - 随机出现在已生成 chunk 的某些节点（精英房/特殊地形）│
│   - 使用常规战斗系统 + 专属 AI/技能（无专属地图）  │
│   - 掉落稀有奖励，推动探索                        │
├─────────────────────────────────────────────────┤
│ ② 大 Boss（专属地图生成 + 专属机制 + 独立战斗模式）│
│   - 大Boss 在卡池中（方舟同款概率/保底/井）       │
│   - 抽到 → 直接传送/切换到专属 Boss 竞技场         │
│   - BossArenaGenerator：独立生成（非 chunk 流式）  │
│   - 自定义物理机制：局部重力/重力方向变化/时间缩放  │
│   - 最终 Boss 战 = 独立战斗模式（单独设计规则）     │
└─────────────────────────────────────────────────┘
```

**大 Boss 专属地图（BossArenaGenerator）**
```
独立竞技场地图（非 chunk 流式，固定规模 or 阶段变化）
 ├ 按 Boss 定制的场地布局（平台/坑/障碍/阶段破坏物）
 ├ 场地可随阶段演变化形（进入阶段2 塌陷/升平台）
 └ 与主题美术一致（实验室 Boss → 试管装置场地）
```

**自定义物理机制（大 Boss 战）**
```
rapier 扩展能力：
 ├ 局部重力场：Boss 周围区域重力方向/大小变化（反转、拉向中心）
 ├ 每实体 gravityScale：特定敌人/子弹重力倍增
 ├ 时间缩放（子弹时间）：战斗节奏控制
 └ 绑定特效：重力异常时的粒子/光线扭曲表现
```
- rapier 支持世界级重力 + 每刚体 `gravityScale` → 局部场用"区域查询 + 施加额外力"实现。

**最终 Boss 战斗模式（独立）**
```
BossRaidMode：与常规战斗模式并列的独立模式
 ├ 多阶段 Boss（血条分段，阶段切换 = 场地+AI+机制变化）
 ├ 专属机制（自定义重力/地形破坏/召唤物等，按 Boss 定制）
 ├ 专属 HUD（Boss 血条/阶段提示/机制预警）
 └ 战斗结束 → 结算 → 回舰船（本局接近终局）
```

**最终 Boss：四维空间主题机制（玩家未见过的设计）**
```
叙事根基：普瑞塞斯是拥有强大力量的科学研究者
 ├ 源石计划失控 ≈ 她对四维空间实验的直接后果
 ├ 四维技术是她力量的来源 → Boss 战自然使用四维机制
 ├ 玩家对抗的不是怪物，是"超越三维认知的存在"
 └ 世界观与机制咬合：打赢 = 用三维认知击穿四维造物

核心思路：把 4D 几何概念降维呈现为 3D 可玩机制（不需要真做 4D 渲染）
 ├ ① 超立方体竞技场（Tesseract 投影）
 │   - 竞技场 = 4D 超立方体的 3D 投影
 │   - 阶段切换时"投影旋转"→ 平台/房间位置重组，空间在眼前变形
 ├ ② 第四维切片（Hyperplane Slice）
 │   - Boss 可在不同"切片层"间移动，玩家用"维度目镜"切换可见切片
 │   - 同位置不同切片 = 不同敌人/陷阱/Boss 部位
 │   - 玩法：切换切片才能命中弱点，或躲开只存在于某切片的弹幕
 ├ ③ 投影战斗（Shadow Projection）
 │   - 玩家攻击的是 Boss 在 3D 的"投影"
 │   - 击破投影 → Boss 沿第四维轴旋转 → 投影换形态（新弱点/新攻击）
 │   - 叙事："你只看到了它的一个面"
 ├ ④ 内外倒转（3D 无内外之分）
 │   - 4D 视角下 3D 物体没有内部/外部区别
 │   - 机制：Boss 把核心弱点"转出"3D 面外 → 玩家可直击平时藏体内的弱点
 │   - 反制：Boss 也能从玩家"被皮肤包裹的 4D 部分"发动无法预判的攻击
 └ ⑤ 维度坍缩/展开（可选进阶）
     - 局部空间压成 2D：玩家进入平面层（横版视角）平面移动躲弹幕
     - 展开 4D：两个分离房间在第四维连通，"走东墙出现在西房"
```
- 实现：全部用 3D 引擎的变换/相机/空间扭曲做"投影/切片"视觉，无需真 4D。
- 每个机制对应一个 Boss 阶段，阶段推进 = 维度理论逐步揭示。
- 这是最终 Boss 的"招牌"，抽到 Boss 战值得专门做这套演出。

**四维机制设计原则（确保"新奇体验"）**
```
① 规则先立后破（认知颠覆的核心）
   - 战斗前段先让玩家"学会"一个稳定规则（如：墙不可穿过）
   - 阶段切换时打破它（如：Boss 让墙在第四维"失效"，可穿墙攻击）
   - 玩家必须重构认知 → 这就是"从来没见过"的体验来源

② 递进揭示，不一次砸完
   - 阶段1：单一维度现象（空间重组）
   - 阶段2：切片交互（看不见的层）
   - 阶段3：规则反转（内外/上下/前后倒转）
   - 每阶段只引入一个新概念，玩家消化后再给下一个

③ 机制内嵌教学（不弹窗说教）
   - 每个新机制用"安全演示"开场：Boss 先表演一次，玩家看明白再应对
   - 例：切片机制出现前，先让一个无害投影"切"过场地让玩家看到层

④ 视觉 + 操作双重反直觉
   - 不只在画面做炫技，操作本身也要违背直觉
   - 例：投影形态切换时，玩家攻击方向也需要"换轴"
   - 例：内外倒转阶段，玩家躲进"墙里"反而安全（3D 无内外）

⑤ 保留"可学会"的底线
   - 每个机制有明确规律（时间/节奏/空间提示），玩家能读懂
   - 反直觉 ≠ 无规律：给足提示（颜色/音效/轨迹），让"懂了"的时刻有成就感

⑥ 情绪弧线
   - 首遇震撼（WOW）→ 困惑（这是什么？）→ 观察（原来如此）→ 掌控（我打过了！）
   - 打完最终 Boss 的瞬间，玩家会记住这场战斗，而不是"又一个多阶段怪"
```

## 8. 战斗系统（单角色实时动作）

### 操控（维什戴尔）
```
WASD 移动 / Shift 闪避 / 鼠标瞄准 / 左键攻击 / 技能(1~4) / 交互(E)
```
- 动作式：攻击连段、闪避无敌帧、技能 CD。
- 敌人：近战兵/远程兵/精英/Boss，AI 状态机（巡逻/索敌/攻击/技能/死亡）。

### 相机（第三人称越肩跟随）
```
肩后跟随（over-shoulder）：相机悬于角色右肩后方，随移动/转向平滑跟随
 ├ 基础跟随：位置 = 角色 + 右偏移(肩) + 后偏移 + 高度
 ├ 瞄准时：相机拉近到肩部齐平，准星对准鼠标射线
 ├ 闪避/受击：相机轻微震动/偏移
 └ 碰撞规避：相机与墙/地形碰撞时自动拉近（sphere cast）
```
- 舰船（日常）与战斗模式共用同一套相机系统（无战斗时只是不锁敌）。
- 鼠标控制视角旋转，角色面向与移动分离（类越肩射击/ARPG）。

### 实体阵营
```
角色：主角(维什戴尔) / 友方(助战) / 敌方
物体：可交互(箱子/机关) / 静态(墙/地形)
子弹：友方 / 敌方
```

**友军两种形态（部署型 / 跟随型）**
```
友方(助战)分两类：
 ├ ① 部署站桩型（Deployable）
 │   - 放下后固定驻守某处（如守舰船、守路口）
 │   - 自动索敌战斗（类似炮塔，但有角色形态/技能）
 │   - 玩家离开后继续战斗 → 天然契合"舰船守卫"
 │   - 可回收/换位置（或部署后固定，按设定）
 │   - 例：盾卫站桩守船、狙击干员守高台
 └ ② 跟随型（Follower）
     - 始终跟随玩家移动（保持阵型/距离）
     - 协同攻击玩家锁定的目标（或自动索敌）
     - 玩家撤退时一起撤
     - 例：维什戴尔的老搭档、召唤物

抽卡抽到的角色 → 玩家决定部署 or 跟随（或角色本身有类型）
```

**弹药机制（主角/炮塔 vs 友军不对称）**
```
├ 主角（维什戴尔）：无弹药机制（无限弹药，技能只看 CD/蓝）
├ 舰船炮塔：无弹药机制（自动无限射击）
└ 友军：有弹药机制
    ├ 弹药 = 友军使用强力技能的消耗品
    ├ 有弹药：能放强力技能（爆发伤害/范围/辅助）
    ├ 无弹药：切"扛盾"近战模式
    │   ├ 扛盾防御：高减伤/嘲讽，站桩抗线
    │   └ 近战攻击：盾击/近战挥击（持续造成近战伤害）
    └ 弹药消耗按技能强度分级（普通技 1 发 / 大招 3 发…）
```
- 不对称设计制造决策：**弹药给谁？**（友军技能 or 留作别的用途）
- 无弹药的友军依然有用（扛盾 + 近战输出），不拖累体验。

**友军辅助功能**

**物品分类体系（遗物 / 道具）**
```
┌─────────────────────────────────────────────────────┐
│ ① 遗物（干员意志的传承，永久增益）                  │
│   ├ 携带型遗物：占遗物栏位（3~5 格，需"装备"生效）  │
│   │   - 例：能天使遗物→攻速+（装了才有）             │
│   ├ 非携带型遗物：不占栏位，被动永久生效            │
│   │   - 例：魔王的黑王冠（开局即得，每日+1%）       │

```

**携带限额（双向：带出去有限 / 带回来有限）**
```
舰船仓库：可大量囤积（物资随便存）
每天外出：
 ├ 带出去有限：出发时按背包容量/载重选装备（武器/弹药/无人机/补给）
 ├ 带回来有限：返回时只能带回 X 件（探索收获要取舍）
 │   - 物资 vs 遗物 vs 战利品 vs 捡到的材料 → 抉择
 │   - 带不下的 → 留在原地（下次再来？还是放弃？）
 └ 决策链：
 │   - 出发：什么值得带出去？
 │   - 探索：什么值得捡？
 │   - 返回：什么值得带回来？
 └ 让"物资多"不等于"战力强"——带得出去/带得回来才算数
```

**无人机回收机制（放出去要收回来）**
```
可露希尔的无人机是"外放型"道具：
 ├ 放出去：展开持续视野（开图）
 ├ 返回时：必须先回收回舰船再离开
 │   - 回收操作：回到无人机位置 / 或远程召回（限时/耗操作）
 │   - 忘了回收 / 来不及 → 无人机就没了（永久损失，本局）
 ├ 设计意图：
 │   - 无人机"放出去"是投资，"收回来"是责任
 │   - 开图爽 → 但记住要收回来 → 探索到远处时多一层顾虑
 │   - 与"抽卡/守卫"一致的哲学：风险来自玩家自己的选择
 │   - 不是被敌人打掉（敌人不攻击它），而是自己丢的
 └ 叙事：可露希尔留下的无人机，弄丢了就真的没了
```

**最终决战：物资全部解禁（囤积的兑现）**
```
抽到 Boss → 立即进最终决战（罗德岛本舰参战）
 ├ 平时：带出去/带回来有限（每日限额，战略储备）
 ├ 决战：全部物资解禁——仓库里的所有囤积都用得上
 │   - 弹药/食物/材料/无人机/所有道具全量可用
 │   - 之前"带不出去"的物资在决战全部兑现
 ├ 设计含义：
 │   - 囤积不是无意义 → 每一份物资都是决战储备
 │   - 平时省吃俭用 = 为决战攒家底（肉鸽的"蓄力"感）
 │   - 抽到 Boss 时强弱取决于"你囤了多少"——
 │     与"抽到 Boss = 立即迎战"联动：仓里有粮，心里不慌
 └ 叙事：罗德岛本舰是终极堡垒，倾巢而出的一战
```

**初始遗物：【魔王的黑王冠】（阿米娅传承，开局即得）**
```
类型：非携带型遗物（不占遗物栏位，被动永久生效）
背景：黑冠是"魔王"传承的象征，阿米娅持有
 ├ 团灭时阿米娅将黑冠传给维什戴尔 → 魔王意志的继承
 ├ 开局自动生效，无需携带/装备（一直在）

 │   - 数值示例：day 10 → +10%，day 21 → +21%
 ├ 意义：随时间增长的"保底成长"——
 │   - 弥补每日增益（敌人变强）的压力，玩家有底
 │   - 黑冠在 → 维什戴尔会越来越强，魔王之名当之无愧
```

**舰船科技树（简短版，不拖长流程）**
```

 ├ 主线程示例：船体强化 → 装甲 → 护盾 / 炮塔解锁 → 炮塔强化
```

- 袭击波次与每日增益联动（日期越后，袭扰越猛）。

## 9. 物理 / 爆炸 / 布料 / 水

### rapier 封装
```
PhysicsWorld
 ├ step(dt)            # 固定步长
 ├ add/remove RigidBody
 ├ collisionCallbacks  # 阵营分发
 └ explosion(pos, r, force)  # 爆炸冲击
```

### 爆炸库
- 特效层（粒子/光/烟，播放器或自研）+ 物理层（explosion 冲量）分离。

### 布料（GPU verlet）
- 位置/速度纹理 + 数值积分 shader，纯视觉。
- 博士袍、披风、旗帜。

### 水（GPU Gerstner 波）
```
大世界水面 = Gerstner 波（4~8 层正弦叠加），无需数值 PDE 求解
 ├ 波形：y = Σ A_i · sin(k_i·(x,z) − ω_i·t + φ_i)（多层叠加，深浅区参数不同）
 ├ 法线：由波形解析导数计算（tan/cos 组合），做光照细节
 ├ 泡沫：浪尖曲率/高度阈值 + 噪声贴图 → 白沫
 ├ 反射/折射：屏幕空间反射（SSR）或 cube map + 深度折射近似
 ├ 浮力/交互：从波形高度采样 → 浮力公式（阿基米德），物体漂浮
 └ 性能：波形在顶点着色器计算，只对近处网格细分（远处降细分/LOD）
```
- 数学只是三角函数叠加（高中水平），不需要手写微积分。
- 与流体编辑器的"平流/压力"不同：那是小面积特效流体，大世界用 Gerstner 性价比最高。
- 深水区（太空/深色海）与浅水区（龙门外环的河/滩）参数分开配置。

## 12. 与特效编辑器/播放器的衔接

```
特效编辑器 ──导出──► .scene.zip ──加载──► 播放器（无头模式）
                                              ├ 子弹拖尾/技能特效
                                              ├ 爆炸/水/布料
                                              ├ 抽卡演出特效（后做）
                                              └ 环境特效
```

### 播放器无头模式（headless runtime）
```
播放器进游戏 = 去掉 demo UI，只保留核心运行时
 ├ 移除：demo 控制面板/文件选择/滑块（纯开发调试用）
 ├ 保留：Asset 加载 / FramePlaybackController / renderFrameData / FluidEffect
 ├ 由游戏通过参数控制：
 │   ├ 特效包路径（Asset.load(sceneZipUrl)）
 │   ├ 播放控制（play/pause/goto/loop/速度）
 │   ├ 渲染参数（transform：位置/缩放/旋转）
 │   ├ 材质参数（底图变换/扭曲强度/颜色参数）
 │   └ 流体参数（手动注入 injectAt / 解算器配置）
 └ 输出：纹理/网格直接挂到游戏实体上（子弹挂拖尾、技能挂光效）
```

```ts
// 游戏内用法（无头模式示例）
const asset = await Asset.load(sceneZipUrl);       // 特效包
const ctrl = asset.createController({ fps: 30, order: 'loop' });
// 每帧：游戏更新实体 → 播放器渲染特效
renderFrameData(data, time, 30, transform, renderer, scene, camera, fluidTex);
// 交互：游戏中点击/命中 → 注入或触发
fluidEff?.injectAt(uv);
```

**播放器体积（实测）**：raw 200KB / gzip 54KB
- 仅占代码预算 3MB 的 ~2%
- 平台无关（纯 three.js + 数据解析），轻量化平台零改动
- 去掉 UI 后体积还会进一步缩小（demo 面板代码不进游戏包）
