数据流（纵向）：
 配置 JSON（内容）→ 系统层读取 → 核心运行时调度 → 服务层执行 → 平台层输出
 事件（横向）：系统间通过 EventBus 解耦通信
 状态（Session）：纯数据，贯穿模式切换，可序列化存档
```

**架构分层原则**
```
① 上层依赖下层，下层不依赖上层（单向依赖）
② 应用层/系统层只消费抽象（InputActions/Services 接口），不碰平台 API
③ 平台层 = 唯一接触 wx./tt./浏览器 API 的地方
④ 内容配置只被系统层读取，不进核心运行时
⑤ 换平台/换设备 = 只改平台层；加内容 = 只改配置
```

## 1. 核心运行时

### 1.1 游戏循环（GameLoop）
```
rAF 驱动（浏览器/小游戏统一）
 ├ fixedUpdate(dt=1/60)   # 物理/战斗/逻辑（固定步长，可多次追赶）
 ├ update(dt)            # 渲染同步/特效/相机/UI（可变步长）
 └ render()              # three.js render + Canvas UI
```
- 物理固定步长 + 累积器（rapier 需要稳定步长，如 60Hz）
- `dt 限幅`（切后台恢复时防爆炸，如 max 0.1s）
- 暂停时只跑 render（UI 动画继续），物理/逻辑冻结

### 1.2 状态机（StateMachine）
```
状态：BOOT → SHIP(日常) → WORLD(战斗) → BOSS(决战) → RESULT → BOOT
 ├ 每个状态 = 独立场景容器（scene + 实体集 + 更新逻辑）
 ├ 切换 = 卸载旧场景（可保留数据）→ 加载新场景
 └ 状态栈支持：暂停菜单（WORLD → MENU → WORLD）

★ 模式切换保留规则（SHIP ↔ WORLD 往返）：
 ├ 保留（Session/跨场景）：舰船上的东西、科技树、主角物品、
 │   友军列表、遗物、卡池计数、day、背包/仓库
 ├ 丢弃（随场景卸载）：当天地图、地图实体（敌人/资源点/箱子）、
 │   战斗中的子弹/粒子/特效、技能 CD 等运行时状态
 └ 恢复：回舰船后，保留数据从 Session 重建（地图明天重新生成）
```
- 模式切换统一走 `ModeManager`，禁止散落的条件切换。

### 1.3 事件总线（EventBus）
```
类型安全的事件（enum 键 + 泛型负载）
 ├ 伤害事件：DamageEvent{target, source, amount, type}
 ├ 拾取事件：PickupEvent{item, position}
 ├ 守卫警报：ShipAlertEvent{wave, direction}
 ├ 抽卡结果：GachaResultEvent{result}
 └ ...
```
- 用于**解耦**（UI 监听战斗事件，战斗不直接碰 UI）
- 高频路径（每帧/每实体）不走事件总线，直接引用（性能）

### 1.4 Session（一局数据）
```
纯数据对象（可序列化，供自动存档）
 ├ 无 class 实例引用、无函数、无 THREE 对象 —— 保证 JSON.stringify 可用

完整字段清单：
 ├ meta:        { seed, day, version }          # 局标识 + 地图重建种子
 ├ player:      { pos, hp, mp, stats, 黑冠层数 } # 玩家状态（本舰存档点=舰船坐标）
 ├ inventory:   { 背包网格, 仓库网格, 堆叠 }      # 物品（含弹药/食物堆）
 ├ relics:      { 槽位[], 持有集合 }              # 遗物（槽 ∪ 背包）
 ├ allies:      { 友军列表[干员id] }               # 抽到的友军（不存部署位置）
 ├ gacha:       { pityCounter, 已抽次数 }
 ├ ship:        { hp, armor, shield, 科技树, 炮塔[] }
 ├ dayProgress: { 今日是否已出击, 当天地图seed }
 └ 排除：战斗中的物理/粒子/特效/弹幕（永不序列化）

序列化规则：
 ├ 背包/仓库 = 物品 id + 坐标 + 堆叠数（紧凑数组，非完整对象）
 ├ 遗物 = id 列表（效果由配置表重建）
 ├ 友军 = 干员 id 列表（实体由配置表重建）
 └ 全部由 id 引用配置 → 序列化只有 id/数字/小数组 → 保持 < 10KB
```

### 1.5 自动存档（SaveSystem）
```
SaveSystem（本舰安全点，单档位）：
 ├ 序列化：Session → JSON（< 10KB）→ PlatformAdapter.storage.set
 ├ 触发：返回本舰 / 抽卡后（安全点才存）
 ├ 删除：死亡 / 舰船被毁 / 通关 → storage.remove
 ├ 恢复：启动时 storage.get → 有局 → 重建 Session → 回本舰
 ├ 地图重建：seed 确定性生成（ChunkData 不存档，重新生成）
 ├ 排除：战斗中状态（物理/粒子/特效）永不存档
 └ 平台差异：微信 setStorageSync / 抖音 / Web localStorage（Adapter 统一）
```

## 2. 实体系统

### 2.1 实体定义（组合式，非继承）
```
Entity = { id, kind, transform, components[] }
组件（每个都是纯数据 + 可选 Update）：
 ├ Transform    # 位置/旋转/缩放
 ├ RigidBody    # rapier 刚体引用 + 物理参数
 ├ Billboard    # 2D 贴片渲染组件（动画/翻转/阴影）
 ├ Weapon       # 攻击/开火逻辑
 ├ Health       # 血量/受击/死亡
 ├ AI           # 状态机（敌人用）
 ├ Inventory    # 可拾取物品
 └ EffectSlot   # 特效挂点（播放器）
```
- **组合优于继承**：角色/敌人/子弹/箱子都是 Entity + 组件组合
- 组件纯数据 → 可序列化、可配置化（内容加实体 = 加配置）

### 2.2 实体管理（EntityManager）
```
├ 池化：子弹/粒子类高频实体用对象池（预分配，复用）
├ 遍历：按组件类型分组索引（需要 AI 的组 / 需要物理的组…）
├ 创建/销毁：统一入口，销毁时回收组件资源（物理体/网格/特效）
└ 数量上限：同时活跃实体数预算（见性能预算）
```

### 2.3 物理与渲染同步
```
RigidBody 持有 rapier 句柄（userData = entityId）
每 fixedUpdate 后：物理步进 → 把刚体 transform 写回 Entity.transform
渲染层只读 Entity.transform（billboard 面相机/网格变换）
 ├ 被动跟随：物理体写回 → 渲染体跟随（角色/子弹）
 └ 主动驱动：渲染体写回 → 物理体（摄像机/不参与碰撞的装饰）
```

## 3. 渲染架构

### 3.1 场景组织
```
一个主场景（three.Scene）+ 按需子容器：
 ├ RenderScene  # 地形/装饰（静态合并）
 ├ EntityLayer  # 所有实体（billboard/网格）
 ├ FXLayer      # 特效（播放器实例/粒子）
 └ SkyLayer     # 天空/远景
```
- 静态地形合并网格（每 chunk 一个 merged mesh，减少 draw call）
- 实体渲染：billboard 用 InstancedMesh 或合并批次（同类精灵合并）

### 3.2 Billboard 精灵系统
```
BillboardComponent
 ├ textureAtlas   # 帧动画纹理集（精灵图）
 ├ currentFrame   # 当前帧（动画状态机驱动）
 ├ flipX          # 移动方向翻转
 ├ facingMode     # always-camera（永久面相机）
 ├ shadow         # 假阴影贴片（地面锚点，与精灵分离）
 └ sortLayer      # 排序层（y-sort：角色/子弹/特效前后遮挡）
```
- **y-sort**：2D 贴片在 3D 场景的遮挡用「y 值排序」模拟（类八方旅人）
- 渲染排序：每帧按 transform.y 排序批次（数量可控，性能可接受）

### 3.3 特效挂接（播放器桥接）
```
EffectSlot 组件：
 ├ assetId     # .scene.zip 资源
 ├ controller  # FramePlaybackController（播放器实例）
 ├ attachPoint # 挂点（头顶/手部/胸口——相对 transform 偏移）
 ├ loopMode    # 循环/一次/受击触发
 └ 生命周期：生成时创建 → 播放 → 结束销毁（或跟随实体）
```
- 播放器输出直接进 FXLayer
- 特效不参与物理，纯视觉（内容设计已确认：实体 vs 特效分离）

### 3.4 渲染性能预算
```
目标：稳定 60fps（低端机 30fps 保底）
 ├ draw call：< 200（静态合并 + InstancedMesh + 特效合批）
 ├ 活跃实体：< 100（池化 + 上限）
 ├ 特效实例：< 30（LOD 降采样）
 ├ 阴影：仅玩家 + 近处实体（假阴影贴片兜底）
 └ 粒子：< 5000（距离降采样）
```

### 3.5 视锥剔除（Frustum Culling）
```
三层剔除（每帧在 render 前执行）：
 ├ ① Chunk 级：相机视锥 vs chunk AABB → 视锥外的 chunk 整块跳过
 │   - 每个 chunk 维护一个粗 AABB（地形 + Actors 范围）
 │   - 视锥外 chunk：不更新 Actors、不渲染网格（省 CPU + GPU）
 ├ ② 实体级：three.js 自带 frustumCulled（per-mesh AABB）
 │   - 实体超出视锥 → 跳过渲染（省 draw call）
 │   - billboard 用自身 AABB（贴片矩形包围盒）
 └ ③ 特效级：特效实例位置 vs 视锥 → 视锥外不实例化/不渲染
```

### 3.6 LOD 系统（与剔除联动）
```
LODManager（每帧或每 N 帧评估一次）：
 ├ 评估：实体/地形到相机的距离 → 确定 LOD 等级
 ├ 地形：chunk 按距离选网格精度（近/中/远三级）
 │   - 近：全精度（贴图+法线+细节装饰）
 │   - 中：简化块（合并网格，去法线）
 │   - 远：低面数 + 贴片蒙版
 ├ 实体（billboard）：按距离切换表现
 │   - 近：全帧动画 + 阴影 + 特效挂点
 │   - 中：减帧动画（4→2 帧）+ 停特效
 │   - 远：静态单帧 + 无阴影 + 假阴影贴片
 ├ 切换策略：异步换（延迟一帧，避免瞬间 pop）/ 渐变（可选）
 └ 与剔除协同：视锥外的直接跳过 LOD 评估（省计算）
```
- 视锥剔除 = 每帧"看不见的别渲染"；LOD = "看得见的按距离降成本"
- 两者在 `RenderManager` 统一入口执行：`updateVisible() → 剔除 → LOD → 排序 → draw`

### 3.7 排序与合批
```
├ y-sort：实体按 transform.y 排序（billboard 遮挡正确性）
├ 合批：同图集/同材质的 billboard 合并批次
│   - 同精灵图集 → 一个批次（InstancedMesh）
│   - 不同图集 → 分批次（按图集分组渲染）
└ 静态合批：地形/装饰 chunk 内合并为单 mesh（构建时做一次）
```

### 3.8 地形生成架构（chunk 流式）
```
生成流水线（异步队列，避免卡顿）：
 chunk 请求 → 生成器(seed, chunkX, chunkZ, 主题) → 网格/碰撞/布点 → 激活
 ├ ① 高度场：噪声函数叠加（Perlin/Simplex，多倍频 octaves）
 │   - 主题参数化：龙门外环=平台地形 / 迷宫=走廊骨架
 │   - 噪声输入 = (seed, chunkX, chunkZ) 确定性 → 可复现
 ├ ② 网格构建：高度场 → BufferGeometry（顶点/UV/法线）
 │   - 近处全精度 / 远处低细分（LOD 联动，见 3.6）
 ├ ③ 碰撞：rapier 碰撞体
 │   - 地形用 trimesh（合并进 chunk）或 heightfield（高度场直接转）
 │   - 静态刚体，只建一次，chunk 卸载时释放
 ├ ④ 布点（Actors）：资源点/敌人/箱子/装饰
 │   - 由 (seed, chunk, 主题, day) 确定性采样
 │   - chunk 激活时才实例化，卸载时回收
 └ ⑤ 衔接：chunk 边界用连接点（门/坡道/路径）对齐

生成队列：
 ├ 优先级：近 chunk（玩家周围）> 远 chunk
 ├ 预算：每帧最多生成 N 个 chunk（如 1~2 个），防止卡帧
 └ 内存：只保留视距内 chunk 的 Mesh/Actors，ChunkData 可保留
```

### 3.9 水体生成架构（Gerstner 波）
```
大世界水面 = 网格 + Gerstner 顶点波（shader 计算，非 CPU）
 ├ ① 水面网格：大型平面（随 chunk 生成/跟随玩家），细分可控
 │   - 近处高细分（波浪细节）/ 远处低细分（LOD）
 │   - 或全屏 quad + 顶点置换（相机空间，视距无关）
 ├ ② 波形（顶点着色器，每顶点算）：
 │   y = Σ A_i · sin(k_i·(x,z) + ω_i·t + φ_i)   （多层叠加，如 6 层）
 │   法线 = 解析导数（cos 组合），不额外差分
 ├ ③ 着色：
 │   - 基色（深/浅水区参数化）
 │   - 高光（Blinn-Phong，法线来自波形导数）
 │   - 泡沫（浪尖：高度/曲率阈值 + 噪声）
 │   - 反射/折射：SSR（屏幕空间）或 cube map 近似
 ├ ④ 交互：
 │   - 浮力：采样水面高度 → 浮力公式（阿基米德）驱动实体
 │   - 涟漪：实体入水/攻击 → 叠加局部波形（衰减）
 ├ ⑤ 性能：
 │   - 波形全在 vertex shader（GPU），CPU 零开销
 │   - 近处 512 细分 / 远处降采样
 │   - 水仅在有水的主题区启用（如龙门外环有河，实验室无）
 └ 实现位置：services/render/WaterSystem.ts（独立模块，可插拔）
```

## 4. 战斗系统架构

### 4.1 伤害结算流程
```
命中（碰撞回调/射线判定）
 → DamageEvent（emit 到总线）
 → 目标 Health 组件处理：减血/无敌帧/受击动画/受击特效
 → 死亡判定 → 死亡流程（掉落/清实体/结算）
```
- 碰撞回调解耦：rapier 碰撞 → 转发为逻辑事件（阵营过滤在此层）
- 伤害类型/元素/暴击 → 纯数值层（配置驱动）

### 4.2 子弹系统
```
Bullet = Entity + RigidBody + Weapon + EffectSlot
 ├ 发射：Weapon 组件创建子弹（从对象池取）→ 物理体赋速度
 ├ 飞行：物理驱动（无重力/重力/追踪 由组件参数控制）
 ├ 命中：碰撞回调 → 伤害 → 命中特效 → 回池
 └ 生命周期：超时/超距自动回池
```
- 阵营（友/敌）在子弹创建时锁定，碰撞时按阵营过滤

### 4.3 敌人 AI 架构
```
AIStateMachine（每实体一个实例，配置驱动）
 ├ 状态：巡逻/索敌/攻击/技能/受击/死亡
 ├ 转移条件：距离/视野/血量/时间（配置表）
 └ 行动：移动/攻击（都走统一接口，方便加新敌人类型）
```
- AI 是配置表（状态+条件+行为），加新敌人 = 加配置，不写代码
- ★ **AI 框架通用：角色/敌人/友军共享同一套 AIStateMachine**
  - 敌人用：巡逻/索敌/攻击/技能/死亡
  - 友军用：守卫模式（站桩索敌）/ 跟随模式（阵型跟随）
  - 玩家用：无 AI（输入驱动），但受击/死亡状态复用
  - 差异全在状态表配置，不是不同实现

### 4.4 每日增益系统（敌人池扩展）
```
DayScalingSystem（每日结算时执行）：
 ├ 数值增益：enemyMultiplier = f(day)（内容设计曲线，配置化）
 │   - 所有伤害/血量计算引用 multiplier（全局缩放）
 ├ 种类解锁：按 day 阈值从敌人池解锁新种类
 │   - enemies.json 每条目带 unlockDay
 │   - ChunkActorGenerator 布点表 = 已解锁种类 ∩ 主题敌人池
 ├ 实现：
 │   - 全局 difficultyScale（int）+ enemyPool 过滤器
 │   - 计算时统一走 StatsCalculator（乘 multiplier）
 └ 存储：Session.day（存档包含，恢复时重算）
```

### 4.5 友军系统（部署/跟随/弹药）
```
AllyEntity = Entity + Billboard + AI + Weapon + Ammo
 ├ 部署型：放下后 AI=守卫模式（站桩索敌，守点）
 │   - 部署 = 玩家主动操作（从背包/友军列表拖出放置）
 │   - 回收 = 玩家主动操作（手动收回背包/友军列表）
 │   - 纯玩家决策，无自动回收机制
 │   - 守卫模式 = 通用 AIStateMachine 的"deploy"状态（见 4.3）
 ├ 跟随型：AI=跟随模式（保持阵型距离，跟随玩家）
 │   - 目标=玩家位置 + 阵型偏移（插值跟随）
 │   - 协同攻击：优先攻击玩家锁定目标
 │   - 跟随模式 = 通用 AIStateMachine 的"follow"状态（见 4.3）
 ├ 弹药（Ammo 组件）：
 │   - ammo 计数 / maxStack（60）
 │   - 有弹药 → 技能可用（消耗弹药）
 │   - 无弹药 → 切"扛盾近战"模式（AI 状态切换）
 ├ 辅助功能（挂件）：
 │   - 移动背包：携带上限 +N（Inventory 上限引用）
 │   - 自动拾取：半径内采集物自动入包
 └ 数据：友军在 Session（友军列表），部署位置不存（回船重新部署）
```
- ★ 友军的守卫/跟随 = 通用 AIStateMachine 的状态表配置（与 4.3 同一框架）
- 部署/回收都是玩家主动操作（拖放），与游戏机制无关，无自动逻辑

### 4.6 爆炸系统
```
ExplosionSystem（services/physics）：
 ├ 触发：explosion(position, radius, force, damage)
 ├ 物理层：半径内所有刚体施加冲量（距离衰减）
 │   - rapier query（球体查询）→ 逐个 applyImpulse
 ├ 伤害层：半径内实体按距离结算伤害（DamageEvent）
 ├ 特效层：播放器爆炸特效（EffectSlot 挂到爆炸点）
  ├ 可破坏物：独立实体（箱子/栅栏），不在地形 mesh 内
 │   - 销毁 = 从 EntityManager 移除 + 物理体移除
 │   - 地形静态 mesh 不受影响（不重建 chunk）
 ├ 2D 贴片形变：被打飞的敌人/物品启用软体形变（见 7.3）
 └ 参数：爆炸配置表（半径/威力/伤害衰减曲线）
```

### 4.7 主角技能资源（无弹药，纯 CD）
```
主角（维什戴尔）攻击/技能：
 ├ 无弹药机制：普通攻击/技能不消耗弹药（内容设计已定）
 ├ 纯 CD 系统：每个技能独立冷却（技能 CD 配置）
 │   - 普通攻击：内置攻速（攻击间隔 CD）
 │   - 技能 1/2/3：各自 CD（配置，可被遗物/科技树缩短）
 ├ 实现：
 │   - SkillComponent：{ skillId, cdRemaining, cooldown }
 │   - 释放 → cdRemaining = cooldown → 每帧递减 → 0 可再用
 │   - 无蓝条/无弹药（对比友军 4.5：有弹药机制）
 ├ 与友军差异：主角=CD 驱动；友军=弹药驱动（不对称设计）
 └ 数据：技能 CD 不进 Session（战斗中状态，存档点=舰船已重置）
```

## 5. 背包系统（三角洲式网格背包）

### 5.1 数据结构
```
InventoryGrid = 网格（如 6×8 格），每格可空/占位
ItemInstance（物品实例，运行时）：
 ├ itemId        # 配置表引用（尺寸/图标/可堆叠数）
 ├ gridSize      # 占格尺寸（w×h，如 1×2 / 2×2 / 3×1）
 ├ rotation      # 0° / 90°（是否旋转，占格交换 w/h）
 ├ stackSize     # 当前堆叠数（可堆叠物品用）
 └ slots[]       # 占用的网格坐标（由 gridSize+rotation+anchor 计算）

物品类型（内容设计）：
 ├ 不可堆叠：武器/装备/遗物（各占一格或多格）
 ├ 可堆叠：弹药（60 个一组）/ 食物（可叠放）/
 │        材料（合成用）
 └ 堆叠上限：按物品类型配置（stackable.maxStack）
```

### 5.2 拖动交互状态机（鼠标/触屏通用）
```
状态：IDLE → HOLDING(暂存) → DRAGGING(移动) → DROPPING(旋转检测) → IDLE
 ├ IDLE → 点击物品 → HOLDING
 │   - 物品进入"暂存区"（视觉上跟随指针）
 │   - ★ 原位置被"清空"（记录原位置 backRef，网格该处变空）
 ├ HOLDING → 移动指针 → DRAGGING（物品跟随指针，可旋转）
 │   - 旋转：按键 R（桌面）/ 双击或按钮（触屏）→ rotation 切换 0°/90°
 │   - 拖到目标网格：实时高亮"可放置区域"（绿=能放，红=不能）
 ├ DRAGGING → 松开 → 放置检测
 │   - 检测：目标锚点 + 旋转后占格 全部在网格内 且 全部为空
 │   - 能放 → 放入该位置（占用格子，记录新位置）
 │   - 不能放 → ★ 返回原位置（backRef 恢复）
 └ 任意状态 → 取消（ESC/右击）→ 返回原位置

检测算法：
 canPlace(grid, item, anchor, rotation):
   for each 占格(由 size+rotation 算出的相对偏移):
     if 越界 → false
     if 该格被占用 → false   （或：目标是堆叠同物品 → 走堆叠逻辑）
   return true
```

### 5.3 堆叠逻辑
```
拖到"同物品 + 已存在堆"时：
 ├ 若目标堆 stackSize < maxStack → 合并（目标堆 + 拖拽堆）
 │   - 超出部分：留在原位置（或剩余量继续拖）
 │   - 例：拖 30 弹药到已有 40 的堆（上限60）→ 合并到 60，剩 10 回原位
 ├ 若目标堆已满 → 按普通放置处理（不能叠就找空位）
 └ 快捷操作：双击堆 → 拆分（如 60 → 30+30，拆一半到相邻空位）
```

### 5.4 交互事件流（与输入抽象解耦）
```
触屏/鼠标 → InputActions（抽象）→ InventorySystem
 ├ 触屏：长按物品 = 拾取（进入 HOLDING）/ 拖动 = DRAGGING
 │      双击 = 旋转 / 双击堆 = 拆分
 └ 桌面：左键拾取 / 移动 / R 旋转 / 右键或 ESC 取消
- 具体映射在 InputBindings，背包逻辑只消费语义（pickup/drop/rotate/cancel）
```

### 5.5 与携带限额/舰船仓库联动
```
两个网格容器：
 ├ 随身背包（外出携带，体积有限 → 每日带出/带回限额）
 └ 舰船仓库（本舰，容量大 → 囤积）
- 转移：背包 ↔ 仓库 拖动（同一套拖动系统，跨容器放置）
- 战利品拾取：找到空位放入；满了 → 留在原地或丢弃
- 数据都在 Session（可序列化，存档兼容）
```

### 5.6 遗物专属栏（即时生效的被动位）
```
遗物有专属装备栏（类似防具槽），但只是"组织方式"：
 ├ 专属栏：遗物槽（如 3~5 格，独立于背包网格）
 │   - 拖动放入 = 装备上（有图标展示，视觉上"穿戴着"）
 │   - 从槽位拖出 = 卸下（可放回背包）
 ├ 放不下 → 塞背包：背包里的遗物同样生效（无差别）
 │   - 遗物 = 即时生效的被动物品（持有即生效）
 │   - 装备栏 vs 背包 = 只有"整理"区别，无效果区别
 ├ 效果：持有即生效（无需"激活"操作）
 │   - 黑王冠（非携带型）：开局即在，永不占槽
 │   - 携带型遗物（能天使/塞雷娅等）：槽位 or 背包都生效
 └ 设计含义：
 │   - 遗物槽 = 快速查看/美观（"穿戴着谁的遗物"）
 │   - 背包 = 仓库（多拿几个遗物，全部生效，但占背包空间）
 │   - 取舍在"背包空间"而非"装备选择"——多带遗物 = 少带物资
- 数据：relicSlots[]（槽位引用）+ 背包内的遗物实例（都算持有）
- 生效判定：Session 里"持有遗物集合" = 槽位 ∪ 背包内遗物

### 5.7 合成系统（两套合成台）
```
CraftingSystem（统一逻辑，两套配方表）：
 ├ 配方：craftRecipes.json
 │   - 输入材料（物品+数量）→ 输出物品（+数量）
 │   - 配方分级：shipOnly（本舰）/ portable（前哨舰）
 ├ 合成台：
 │   - 本舰完整台：所有配方可用（含 shipOnly 增益/装备）
 │   - 前哨舰简易台：仅 portable（弹药/食物/应急）
 ├ 流程：打开合成台 → 选配方（检查材料）→ 确认 → 扣材料 → 产出
 │   - 材料不足 → 灰显/提示缺什么
 │   - 产出进背包（满 → 提示/失败）
  ├ 弹药合成：材料 → 弹药堆（60/组，直接进背包可叠放）
  ├ 食物合成：材料 → 食物堆
  └ 实现位置：systems/inventory/CraftingSystem.ts
```

### 5.8 采集系统（常规地图交互）
```
GatheringSystem（走近 → 交互 → 入包）：
 ├ 资源点 = 独立实体（带 Gathering 组件：产出表/采集耗时）
 │   - 布点：ChunkActorGenerator 按 (seed, chunk, 主题) 放置
 │   - 类型：矿物/植物/废料（产出材料不同）
 ├ 交互：玩家走近 → 按交互键（interact）→ 采集中（进度条）
 │   - 采集耗时（如 1~2s，可被打断）
 │   - 完成后：材料入背包（找空位，满则留在原地）
 ├ 产出表：gathering.json（资源点类型 → 产出材料 + 数量）
 ├ 资源点刷新：每天新地图（新 seed）→ 资源点重新生成
 └ 与合成联动：采集的材料 = 合成台输入（见 5.7）
- 实现位置：systems/inventory/GatheringSystem.ts
```

## 6. 抽卡系统

### 6.1 卡池结构
```
GachaPool（单一卡池，配置驱动）：
 ├ gachaPool.json：条目 { id, rarity(1~6), type(角色/Boss/道具), weight }
 ├ 概率计算：稀有度权重 → 类型内权重
 │   - 6★：基础 2%，50 抽后每抽 +2%（递增）

抽卡请求 → 概率计算（含保底）→ 结果 → 分发

## 7. 地图系统

### 7.1 迷雾/视野系统
```
FogOfWar（数据层 + 渲染层）：
 ├ 数据：当天地图迷雾网格（每个 chunk 一个 bitmask）
 │   - revealed（地形留痕）/ visible（持续视野=有怪物显示）
 ├ 更新：每帧玩家/无人机位置 → 圆半径标记
 │   - revealed：走过的永久留痕（只显示地形）
 │   - visible：当前视野（怪物实时显示）
 │   - 离开视野 → visible 清除，revealed 保留
 ├ 渲染：小地图 Canvas 2D
 │   - 黑色迷雾 + revealed 区域显示地形（灰度地形图）
 │   - visible 区域叠加怪物图标（实时）
 ├ 无人机：放出去 = 增加一个"视野源"（第二半径）
 │   - 回收/丢失 → 视野源移除（revealed 保留）
 └ 数据作用域：仅当天地图有效（见"每日新地图"）

★ 每日新地图（地图生命周期）：
 ├ 每天出击 = 新生成一张当天地图（新 seed）
 │   - 出击时生成（以舰船为中心展开，chunk 流式）
 │   - 玩家一天实际活动范围有限 → 地图规模 = "当天够走"
 │   - ★ 前哨舰 = 当天地图的固定锚点（生成原点）
 │       - 地图以舰船坐标为原点生成，舰船永远在入口区
 │       - 守卫系统（7.2）的舰船位置 = 已知常量
 ├ 当天结束/回舰船 → 当天地图废弃
 │   - 留痕/迷雾/已探索区域 → 全部丢弃（不存档）
 │   - 第二天出击 → 全新地图（新 seed，重新生成）
 ├ 存档不存地图：Session 只存 day（存档恢复 → 重新生成当天地图）
 │   - 但"当天已探索的留痕"会丢 → 恢复后当天迷雾重置
 │   - 可接受：存档点在舰船，玩家还没出发（当天地图还没生成）
 └ 设计含义：
     - 无"无限持久世界"负担（存档小、内存小）
     - 每天新鲜感（新地形/新资源点/新敌人布局）
     - chunk 流式保留（当天地图也按需生成），但语义=有界一天

迷雾渲染性能：
 ├ 迷雾画到离屏 canvas（低分辨率，如 1/4 尺寸）
 ├ 只更新变化的区域（脏区矩形），不全屏重绘
 └ 放大显示（模糊可接受，迷雾本来就该柔和）
```

### 7.2 舰船守卫系统
```
ShipGuardSystem：
 ├ 袭击波次生成：按"出击时长"间隔生成（内容设计：时间驱动非距离）
 │   - 每 N 分钟一波 → 生成器从敌人池取袭扰兵
 │   - 波次强度 = f(day)（每日增益联动）
 ├ 敌人目标分级：AI 目标选择（玩家 or 舰船）
 │   - 袭扰兵：无视玩家直奔舰船（目标=舰船坐标）
 │   - 普通兵：就近攻击（玩家 or 舰船）
 ├ 舰船本体：HP/装甲/护盾（Session）
 │   - 受击 → ShipAlertEvent（HUD 警报 + 小地图红点）
 │   - HP 归零 → 局结束（删除存档）
 ├ 炮塔：自动索敌（每个炮塔一个简单 AI）
 │   - 槽位配置：固定位点，放置后自动攻击范围敌人
 ├ 科技树：节点配置表（等级 → 效果：船体/炮塔/护盾）
 │   - 科技点来源：探索/战斗/卡池
 └ 实现位置：systems/ship/
```

### 7.3 布料系统
```
ClothSystem（GPU verlet，独立于物理）：
 ├ 数据：位置/速度纹理（每根线 2D 纹理）
 ├ 积分：GPU shader（verlet 数值积分，约束求解）
 ├ 网格：角色挂件（披风/袍子/旗帜）
 ├ 交互：风场/玩家移动扰动（参数注入）
 └ 碰撞：无（纯视觉，或胶囊近似）
- 实现位置：services/render/ClothSystem.ts

★ 2D 贴片的受力形变（物品/敌人被打飞）：
 ├ 本系统也负责"2D 贴片受力的软体形变"——不是 3D 网格挂披风
 ├ 物品/敌人是 2D 贴片（billboard），被打飞时：
 │   - 贴片网格做 verlet 形变（顶点扰动，模拟软体翻滚/挤压）
 │   - 形变参数：受力方向/强度/物体硬度（配置）
 │   - 翻滚：贴片跟随物理速度旋转 + 形变（比刚体动画更生动）
 ├ 实现：
 │   - 贴片 geometry 顶点可形变（verlet 约束到外形）
 │   - 或简化为"贴片 UV 扭曲/缩放模拟受力"（低端机降级）
 ├ 适用：被打飞的敌人 / 抛掷的物品 / 掉落物
 └ 与 3D 布料的关系：同一个 ClothSystem
     - 场景旗帜/飘带 = 3D verlet 网格
     - 2D 实体形变 = 贴片 verlet（同积分器，不同网格形态）
```
- 2D 角色平时保持平面贴片（不形变），仅在受击/打飞瞬间启用形变
- 形变结束后恢复平面（避免持续 GPU 开销）

## 8. 资源管线

### 8.1 资源加载（AssetManager）
```
├ 同步加载：包内核心资源（启动即用）
├ 异步加载：分包/远程资源（主题区/抽卡演出，按需）
├ 缓存：已加载资源引用计数（chunk 卸载时释放）
└ 资源类型：.scene.zip / 纹理 / 音频 / 字体 / 配置 JSON
```
- 所有资源通过 AssetManager，禁止散落直接 new

### 8.2 特效包（.scene.zip）管线
```
编辑器导出 → 游戏包内（或分包/远程）→ AssetManager.load
 ├ 加载即解析（播放器 decodeMultiFrame）
 ├ 实例化：每实体一个 controller（挂到 EffectSlot）
 └ 卸载：引用计数归零 → dispose（释放纹理/几何）
```

### 8.3 分包策略
```
主包（4MB）：核心代码 + 舰船 + 基础敌人 + 基础特效
分包1：主题区A（龙门外环素材）
分包2：主题区B（卡西米尔）
分包3：大Boss 专属（四维竞技场 + 演出）
└ 按需加载：进主题区时加载对应分包
```
