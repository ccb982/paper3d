## 1. 一句话 + 现状瓶颈

**一句话**：把敌人从"每只全保真"改为"**分层保真 + 时间片调度 + 全局协调**"——近处是个体、
远处是代理、更远只有流动感；"聪明"来自攻击槽 / 警戒场 / 导演这类全局机制，不靠堆个体算力。

## 2. 目标与验收指标

- **玩法**：屏上 50 / 全图 200 稳定 60fps（低端目标：无掉帧尖刺，最低 30fps 可玩）。
- **预算**（60fps = 16.6ms 总预算内，蜂群占比）：总计 **≤ 4ms**
  - 决策（脑）：≤ 1.5ms
  - 移动 / 分离 / 贴地：≤ 1ms
  - 渲染提交：≤ 1ms（实例化后 draw call ≤ 3）
  - 其余（感知 / 攻击 / 杂项）：≤ 0.5ms
- **行为**：反应有随机差异（不再整齐划一）；围杀有槽位感、不叠人堆；远处有洪流流动感。
- **兼容**：伤害管线 / 事件总线 / 掉落 / 遗物击杀结算 / 舰船索敌契约**全程不变**。

## 4. 模块划分（新建 `src/systems/swarm/`）

```
SwarmSystem.ts    调度器：分桶 tick + 时间片预算 + 升降级桥接（唯一对外入口）
AgentPool.ts      SoA 定长池（256）：pos/hp/state/target/timers/flags，swap-remove，零 GC
CrowdGrid.ts      分桶：邻居分离 / 密度 / 警戒场 / 子弹段圆命中
FlowField.ts      4m 网格多源 Dijkstra（玩家+舰船），坑/水/崖编码为高代价，3Hz 增量
AttackSlots.ts    攻击槽协调器：环形占位 + 近战攻击令牌 + 远程距离环
Director.ts       威胁预算 / 节奏 / intent 分配（打谁、包抄方向、集结）
render/SwarmBatch.ts  图集 + InstancedMesh（L2/L1）；L3 仍走现有 FTXQuad
```

依赖方向：`modes` 驱动 `SwarmSystem`（单向）；`swarm` 只消费 `services`（map/render/combat）
与 `core`（EventBus/Session），**不引 ui**；行为库（`systems/ai/aiconfig` + behaviors/conditions）
被 L2/L3 共用（同一份配置，不同 tick 频率）。

## 5. 关键机制

### 5.1 调度器（SwarmSystem）

- 分桶 tick：`bucket = (frame + agentPhase) % K`，各层 K = 6 / 12 / 30（对应 10/5/2Hz）。
- 预算门：每帧决策耗时超过预算 → 本帧剩余分桶顺延到下一帧（不补课）。
- 计数器：`entityPerf` 扩展 swarm 分项（brain / move / sep / grid / render），P0 建立的基线持续对照。

### 5.2 流场（FlowField）—— 导航 + 危险代价

- 网格 = RasterMap 4m 块（对齐现有 `blockAt`），窗口以玩家为中心 96×96 块（384m）。
- 多源 Dijkstra：目标集合 = 玩家 + 舰船停靠点（可扩展集结锚点）；重建 3Hz，或目标移动 > 1 格触发。
- 代价：坑 / 深水（水代价 8）编码为高代价，上坡按米加价；**本地 hazard 探测保留并扩展**
  （坑 / 深水 / 高台立面 → 转向绕行；"陡升且不延续=墙，插值坡放行"，见顶部决策记录）
- 消费：代理取邻格梯度 + 分离修正；窗口外走直线逼近，入窗自动接上流场。
- worker 化（可选，P2 之后再评估：16k 节点 Dijkstra 主线程 3Hz 亦可接受）。

### 5.3 人群网格（CrowdGrid）

- 2m 分桶（随玩家窗口滑动），查询半径 = 自身碰撞半径 + 邻居半径。
- 分离：每代理每移动 tick 查 4~8 邻居，O(n) 无排序。
- 警戒场：发现玩家/被击中的单位向网格刷"警戒半径"；范围内同伴按**个体随机延迟 0.2~1.5s**
  转入追击（消灭整齐划一感）；不做逐敌 LOS 射线。
- 玩家子弹打 L2/L1：线段 vs 网格圆判定（子弹本来就少），命中即结算，不给远处建刚体。

### 5.4 攻击槽（AttackSlots）—— "聪明"的最大来源

- 目标周围预计算**环形槽**（近战内圈 / 远程外圈），按角度扇区分配；槽容量有限。
- 近战**攻击令牌**：同一目标同时挥击数上限 N（默认 3~4），其余单位绕行 / 游走 / 等待；
  挥击有起手预警帧 + 后摇 + 受击打断（可读性）。
- 远程占距离环 + 集火（共享优先目标）；槽位 1~2Hz 重分配，目标移动不抖。

### 5.5 升降级（实体 ⇄ 代理）

- `agentId` 稳定：池内 id 与实体一一对应；升格 = 建 `EnemyBase` 并灌入代理数据；
  降格 = 拆实体、数据回池（位置 / 血量 / 状态机状态保留）。
- 切换点滞回（30/40m）+ 升格预算（≤2/帧）；死亡统一走 `applyDamage` / `killed` 事件。
- **单一事实源**：任何时刻一只敌要么是实体要么是代理，桥接层封装在 SwarmSystem，外部不可见。

### 5.6 战斗抽象（L2/L1 到期结算）

- L2/L1 在攻距内按各自 cadence 排"到期事件"：预警（视觉闪烁/曳光）→ 结算伤害；
  伤害走与 `applyDamage` 等价的代理入口（`AgentHandle` 实现伤害管线所需最小面：hp/defense/camp/position）。
- 不生成子弹实体；远处敌人远程攻击 = 曳光 + 到期扣血。
- 玩家/友军子弹命中原生支持代理（5.3 段圆判定）；近处仍走 rapier。

### 5.7 批渲染（SwarmBatch）

- 每兵种一张**图集**：帧序列打平（base 色烘焙进图集；residual/fluid 放弃），构建期生成。
- `InstancedMesh` 容量 256/兵种，实例属性：pos / yaw（帧）/ flip / frameIndex / 受击染色 / fade。
- 刷新策略：仅在有变化（移动/换帧/染色）时写脏区间；L2 30fps 换帧、L1 冻结帧。
- 影子 / residual 特效**仅 L3**；L2/L1 无影子（或仅大单位投影，按预算定）。
- **血条（2026-09-15 修订）**：L3 仍用 `services/fx/HealthBar`（个体 Effect，含构造期
  maxHp 兜底）；**L2/L1 在 `≤LOD_MAX_DIST(90m)` 内用实例化血条**——实例属性 `aRatio`，
  片元 `filled = step(vUv.x, vRatio)` 实现左锚收缩（血量从右往左退），实例位置
  `(x, 地面高 + h + 0.4, z)`、朝向复制相机四元数（billboard）。
  代价：+1 个 draw call + 每帧 ≤256 次实例写入，无逐敌 Effect / 无分配。

### 5.8 导演（Director，P4）

- 威胁预算：按玩家血量 / 弹药 / 与舰船距离调节生成与压力，不再纯随机刷。
- 节奏：静 → 试探 → 突涌 → 间歇（波次是导演节拍，不是独立 timer）。
- intent 分配：一部分压舰船 / 无人机 / 祖宗，一部分包抄玩家（扇区分配），形成分工洪流。

## 10. 风险与取舍

- **双轨期复杂度**（实体 + 代理并存）：用单一 `agentId` + 桥接层收口，禁止两套行为逻辑分叉。
- **图集构建成本**（帧数 × 尺寸）：按兵种拆图、构建期生成，运行时零重建。
- **视觉差异**：L2/L1 无 residual/fluid / 无影子（已确认接受）；L3 保持全效果。
- **流场窗口边界**：窗口外直线逼近，入窗接管，避免边界抖动。
- **近处 rapier 仍是事件开销大头**：L3 上限 30 是硬约束，不再扩大。
- **不要做**：逐个体 A* / 逐个体 LOS / 逐帧创建销毁实体 / 视距外全保真。

# v2：编队层次与分层寻路（2026-09-18 设计稿）

> **决策记录（2026-09-18 用户定调）**
> 现状的"聪明"来自攻击槽 / 警戒场 / 导演这类**扁平机制** —— 200 只代理各算各的，
> 没有"部队"概念：不会分兵、不会按兵种配合、不会绕远路（出流场窗口就直线撞墙）。
> **v2 引入三级编队**，核心是**一次昂贵寻路、全队复用、逐级下发**：
>
> > 大编队决定战术 → 小编队执行并修正 → 逐步分配到每个真实敌人和代理
>
> - **大编队**：战术层。决定打谁 / 从哪压 / 什么阵型；**执行一次复杂寻路**
> - **小编队**：执行层。**复用**大编队的寻路结果，按自身情况（兵种/伤亡/位置）修正
> - **个体**：代理 + L3 实体。跟随分配到的槽位
> - 兵种现状：**杂兵 / 盾兵 / 突击兵**（已足够做大编队战术部署）；**后续加远程**
> - 硬要求：**寻路必须强** —— 确保真的能迅速找到玩家或舰船
>
> v2 与原章的关系：§3 的 L1/L2/L3 是**表现载体分层**，v2 的编队是**逻辑归属分层**，
> **两者正交**（一只敌人可以是"任何编队 + 任何 LOD 层"）。原 §5.2 流场降级为
> "局部微调"，全局导航交给 v2 的 HPA*。

## 11. 一句话

**编队是"战术单位"，LOD 是"表现精度"；一次 HPA\* 全队复用，逐级下发到个体。**

## 14. 小编队（Squad）—— 执行层

### 14.1 职责

- **认领车道**：在 corridor 的横向带内认领一条 lane（`laneOffset`），避免全队挤在中心线上
- **复用主干**：沿 corridor waypoints 推进，**不自行寻路**
- **局部修正**（这是"根据自身情况做修正"）：
  1. **避障**：本地 hazard 探测（坑 / 深水 / 陡崖立面），走不通就横向挪车道
  2. **分离**：与其它小编队、自身成员分离（复用 `CrowdGrid`）
  3. **交战接管**：目标进入视野（`< SLOT_COMMIT 25m`）→ 本小队**脱离走廊**直接扑目标（攻击槽接管）
  4. **兵种微调**：盾兵前压、远程后拉、突击兵加速
- **质心与朝向**：小编队有局部坐标系（质心 + 前进方向），个体按**阵型槽位**相对定位

### 14.2 车道分配（避免全队一条线）

```
corridor 主干（带宽 W）
  ════════════════════════════════════════════  ← 上边界（可走宽度上限）
      ╲  Squad A（lane -0.35W）
  ─────╲──────────────────────────────────────  ← 主干中心线
        ╲     Squad B（lane 0.0 = 中心）
  ───────╲────────────────────────────────────  ← 主干中心线
              Squad C（lane +0.35W）
  ════════════════════════════════════════════  ← 下边界
```

- `W` = corridor 逐点的**可走横向半宽**（由 HPA* 输出，见 §15.4）
- lane 分配按兵种优先：**盾兵占中前**（承受正面），**突击兵占外侧**（便于展开包抄）
- 车道在走廊变窄（`W` 缩小）时**自动收拢**，避免挤进不可通行区

### 14.3 阵型定义

```ts
type UnitRole = 'shield' | 'assault' | 'grunt' | 'ranged';

interface FormationSlot {
  /** 编队本地坐标：+x 前、+z 右（与小编队朝向对齐） */
  fx: number; fz: number;
  /** 该槽位偏好角色（软约束：没有对应兵种就让给其他角色） */
  prefer?: UnitRole;
}

interface FormationDef {
  id: 'wedge' | 'line' | 'column' | 'encircle';
  slots: FormationSlot[];
}

/** 楔形：盾兵顶点 → 突破 */
const WEDGE: FormationDef = {
  id: 'wedge',
  slots: [
    { fx:  2.0, fz:  0.0, prefer: 'shield' },   // 顶点
    { fx:  1.0, fz: -1.6, prefer: 'grunt'  },
    { fx:  1.0, fz:  1.6, prefer: 'grunt'  },
    { fx: -0.5, fz: -2.6, prefer: 'assault' },  // 两翼外扩
    { fx: -0.5, fz:  2.6, prefer: 'assault' },
    { fx: -1.5, fz: -0.9, prefer: 'ranged' },   // 后排火力
    { fx: -1.5, fz:  0.9, prefer: 'ranged' },
  ],
};

/** 纵队：窄道行军（走廊变窄时自动切换） */
const COLUMN: FormationDef = { id: 'column', slots: [/* 单列纵向排列 */] };
```

- **阵型选择**：大编队按 `走廊宽度 / 目标类型 / 兵种配比` 选；走廊窄 → 纵队；开阔 + 攻玩家 → 楔形；攻舰船 → 横列展开。
- **槽位是软约束**：兵种不齐时按顺序填，不空槽。

## 15. ★★ 寻路：HPA\* + 走廊带（v2 的"强"在哪）

### 15.1 为什么现有 FlowField 不够

| 问题 | 现有实现 | 后果 |
|---|---|---|
| **窗口只有 324m** | `FLOW_SIZE=81` × `FLOW_CELL=4m` | 出窗口**直线逼近** → 撞山/撞水/卡住（用户说的"找不到玩家"） |
| **只有距离场** | 多源 Dijkstra 的负梯度 | 只知道"往哪边走离目标近"，**不知道路有多宽** → 大队挤成一坨 |
| **无路可走时不退让** | 梯度可能指向不可通行方向 | 代理贴墙抖动 |
| **单一目标集合** | 源 = 玩家 + 舰船 | 无法表达"从东北包抄"这种带方向的战术 |

**FlowField 不删，降级为"局部微调层"**（最后一公里 + 动态人流），全局导航交给 HPA*。

### 15.2 HPA\* 结构（一次昂贵、全队复用）

```
① 粗层：Cluster（32m 簇 = 8×8 个 4m 格）
   ┌────┬────┬────┐
   │ C00│ C01│ C02│   每个 cluster 预计算：
   ├────┼────┼────┤   · portals：与 4 邻簇边界上的可通行段
   │ C10│ C11│ C12│   · 内部图：portal ↔ portal 的最短距离（缓存！）
   ├────┼────┼────┤
   │ C20│ C21│ C22│   ★ 地形不变 → 内部图永久有效（玩家挖坑才失效）
   └────┴────┴────┘

② 细层：A* 跑在「portal 图」上
   起点所在簇的 portal → … → 终点所在簇的 portal
   节点数 = portal 数（远小于格数）→ 毫秒级

③ 拼接：按 cluster 序列，用缓存好的「portal 间内部路径」拼出完整折线

④ 平滑：funnel（string pulling）→ 最少 waypoint 的可走折线
```

**为什么强**：
- **全图可达**（不受窗口限制）—— 这是"迅速找到玩家/舰船"的根本
- **簇内路径可缓存** → 目标移动时**只重算 A* 那步**（毫秒级），缓存复用
- **只算一次，全编队复用** → 成本与敌人数无关

### 15.3 代价模型（复用现有口径 + 扩展）

| 因素 | 代价 | 来源 |
|---|---|---|
| 坑 | `COST_PIT = 8` | 现有 FlowField 同口径 |
| 深水（水深 > 0.8m） | `COST_LIQUID = 8` | 现有（敌人不涉水） |
| 上坡 / 爬坡 | `+ dh × COST_CLIMB(1.5)` | 现有 |
| **陡崖立面（不延续的陡升）** | **不可通行** | 现有 `MOVE_STEP_MAX` 判定 |
| **★ 通行宽度** | 窄于大队宽度 → **高代价**（不是封死） | v2 新增 |
| ★ **工事（§22）** | 玩家：阻挡 / 高代价；**敌人己方：高代价但可通行** | v2 新增 |
| ★ **飞行单位（§25）** | **完全不参与本代价模型** | 独立空中层：直线 + 避障 |
| ★ 暴露度（远期） | 靠近玩家火力 → 加价 | 可选，先不做 |

★ **通行宽度**是大编队特有的：一个 2m 宽的缝，单体过得去、大队过不去。
做法：对每个格预计算**到最近不可通行格的横向距离**（距离变换，一次性），
HPA* 按"编队宽度"决定加价倍率 → 自然偏好大路。

### 15.4 走廊带（Corridor）—— 小编队能"分车道"的前提

HPA* 只给出一条折线，**不够**。还要给**带宽**：

```ts
interface CorridorNode {
  x: number; z: number;
  /** ★ 该点的可走横向半宽（米；由宽度距离变换沿法线采样得出） */
  halfWidth: number;
  /** 该点的地形高度（贴地用） */
  y: number;
}

interface Corridor {
  nodes: CorridorNode[];
  /** 总长度（米；用于估算行军时间与"是否绕远"） */
  length: number;
  /** 生成时间戳（失效判断） */
  builtAt: number;
}
```

小编队据此：`laneOffset ∈ [-halfWidth × 0.7, +halfWidth × 0.7]`，并在 `halfWidth` 收窄时自动收拢。

### 15.5 重算与增量

| 触发 | 动作 | 成本 |
|---|---|---|
| 目标位移 > `RETARGET_DIST`（默认 24m） | 重跑 ②（A* on portal graph），**缓存 ③④** | 毫秒级 |
| 目标跨 cluster | 同上 | 毫秒级 |
| 编队出发 cluster 变化 | 同上 | 毫秒级 |
| 地形变化（玩家挖坑 / **敌人造工事** §22） | 标记脏 cluster → 失效该簇内部图 | 仅受影响的簇 |
| 走廊被堵（小队长时间无进展） | 局部重算（从当前位置到目标的后半段） | 毫秒级 |
| 兵力损失 > 40% / 换姿态 | 重排阵型分区（不重算路径） | 微秒级 |

**失效判定不做逐帧比较**，只在 `RETARGET_DIST` 或事件（挖坑 / 受损）时触发。

### 15.6 降级链（绝不能"找不到路就不动"）

```
HPA* corridor 可用？
  ├─ 是 → 沿走廊 + 流场微调 + 分离
  └─ 否（Worker 未回 / 无解 / 超时）
       ├─ FlowField 窗口内？ → 用流场梯度（现有行为）
       └─ 窗口外 → 直线逼近 + 本地 hazard 绕行（现有兜底）
```

**超时保护**：HPA* 单次上限 `HPA_BUDGET_MS`（默认 8ms），超时返回已探索的最优近似解。

### 15.7 Worker 化

- HPA* 丢 `Worker`（项目已有 `terrainBake.worker` 等 Worker 基建可参照），
  主线程只做"下发查询 + 收结果"。
- 地形数据（高度 / 通行性 / 宽度）**只读**，可 `SharedArrayBuffer` 共享（避免每次拷贝）。
- 结果回传：corridor waypoints（几十个点）→ 结构化拷贝成本可忽略。
- ★ **Worker 未就绪时走降级链**，绝不让编队停摆。

### 15.8 「迅速找到玩家/舰船」的另一半：情报（感知 vs 全知）

寻路强 ≠ 知道目标在哪。这里要做**明确的玩法选择**：

| 方案 | 感受 | 建议 |
|---|---|---|
| **大编队全知**（直接拿玩家/舰船真位置） | 敌人总能找上门，压力稳定 | ★ **采用**：玩法上"大举进攻"本就该找到你 |
| 全知 + 个体全知 | 无处可藏，搜索感为零 | 不采用 |
| 大编队全知 / 个体有限感知 | 队伍朝你来，但个体仍需"察觉"才追击 | ★ **采用**：保留现有警戒场与个体反应延迟 |

→ **大编队全知寻路，个体仍受警戒场约束**。这样"迅速找到"和"有搜索感"两者兼得。

★★ **绝对不能拿 `index` 当编队成员引用**：
`AgentPool.removeAt()` 是 **swap-remove**（尾元素填坑，所有数组同步搬移）→
**一次死亡就让所有 index 位移**。方案二选一：
1. **每帧按 `squadId` 分桶重建成员表**（O(n)=256，极廉价）—— ★ 推荐，无同步风险
2. `uid` + `uidToIndex` 映射（要维护 push/removeAt 同步，容易出错）

**推荐 1**：编队不持有成员列表，只持有 `squadId`；`SwarmSystem` 每帧扫一遍池分桶。

## 20. 风险与取舍（v2）

- **过度设计风险**：编队是最容易"很优雅但看不到效果"的系统。
  → **F0 先做可视化**，每阶段用画面验收；不达标就停在该阶段，不继续往上堆。
- **一次寻路全队复用 = 全队同时犯错**：走廊被堵时全员卡住。
  → 全靠 §14.1 的"小队局部修正" + §15.6 降级链；小队长时间无进展要能**自己重算局部**。
- **共享 corridor 与"整齐划一"的矛盾**：用户明确讨厌整齐划一（§1 现状瓶颈）。
  → 车道偏移 + 个体相位抖动 + 个体反应延迟（现有机制）**必须保留**，编队只给"大致方向"。
- **swap-remove 与编队引用**：★ 已踩过的坑（index 不可跨帧缓存）。
  → 每帧分桶重建，不维护 uid→index 映射。
- **Worker 通信成本**：地形大数组别每次拷贝。
  → `SharedArrayBuffer`；结果只回传 waypoints。
- **据守会退化成"卡关"**：高地 + 山脚守点 + 不开火，搞不好就是玩家打不动的死结。
  → ★ 红线：据点**必须给解**（范围/间接火力、载具、引蛇出洞、绕后）；且据守**不是永久态**
  （`TERRAIN_TIMEOUT` + 玩家远离 → 转 advance）。宁可少恶心一点，也不要变成堵路。
- **"不开火"被误读成"停摆"**：ROE=hold 期间单位仍在补位/换岗/索敌。
  → 复用既有警戒场与反应延迟；**任何情况下都不允许它违反铁律 3**。
- **高地选点抖动**：每帧重打分会让编队反复改主意。
  → 选点**只在 scout 阶段算一次 + 换姿态时重算**，中途保持（除非高地失守或玩家离开窗口）。
- **工事改导航 = 可能把 AI 自己关在门外**（§22 最容易翻车的一处）。
  → ★ 己方工事对自己必须是"高代价但可通行"，且**不得**封死唯一通路。
- **工事性能**：数量一多就是 draw call 灾难。
  → 同类工事实例化批渲染 + `MAX_STRUCT_PER_BN` + 离玩家太远的不建。
- **工事变成"永久墙"**：若跨局残留，地图会越玩越堵。
  → 随波次清理（运行时态，不入存档，同铁律 7）。
- **偷袭变成"无提示背刺"**：玩家只会认为 AI 作弊，不是"聪明"。
  → ★ 必须给可察觉线索（声音/阴影/短暂轮廓）；且过于靠近会提前暴露（§23.5）。
- **偷袭分队潜伏过久 = 变相"敌人不动"**：抽调走 1~2 组后正面变弱，后方又迟迟不动。
  → `AMBUSH_TIMEOUT` 兜底，到点就并回正面；`MAIN_FORCE_MIN` 保证正面不被抽空。
- **"打不到的高危火力点" = 死结**：藏在工事后 + LOS 遮挡，最容易做成玩家无解。
  → 必须给到**侧面/绕后、间接火力、拆外层**三条解（§22.9）；偷袭分队就是为此存在的。
- **陷阱 = 无提示踩雷的挫败感**（和"无提示背刺"同一类问题）。
  → 可察觉线索 + 可侦察显形 + 可提前引爆（§24.5）；且 AI 自己不踩（`passFaction`）。
- **飞行兵最容易做成"持续空中输出"= 恶心**（★ 用户原话就是这个担心）。
  → 只保留轰炸 + 冷却 + 单组上限（铁律 24），投完就走。
- **无预警空袭 = 挫败**：→ 落点指示 + 延迟引信，玩家必须有躲的窗口（铁律 25）。
- **飞行兵"无视一切" → 万能解**：飞越工事、不踩陷阱、无视地形，很容易变成无解单位。
  → 必须有防空威慑（火力点兼对空）+ 投弹航段脆弱（§25.5）。
- **不要做**：
  - 逐个体 HPA*（只大编队算一次）
  - 逐个体 A*（沿用 §10）
  - 编队成员用裸 index 长期持有（swap-remove 会毁掉它）
  - 让编队接管"个体战斗行为"（攻击槽 / 令牌仍是 §5.4 的职责，编队只管"去哪")

## 21. 地形战术：抢占高地 · 据守 · 收缩包围（2026-09-18 新增）

> **用户定调**：「占领高地可以试一试，远程兵在山顶，山脚下其他兵种守着，恶心死玩家。
> 开局先不打玩家，而是寻找舰船附近的有利地形，占领并防守；然后发起总攻的时候收缩包围圈。」

### 21.1 一句话

把**地形**变成编队的第一个战术资源：序盘不接敌，先抢高地/隘口据守，把玩家逼进仰攻劣势；
总攻阶段以**收缩包围圈**收网。远程兵靠高地放大射程与视野，近战兵守山脚隘口。

### 21.2 为什么可行（复用 v2 既有结构，不新增"地形分析子系统"）

| 需要的东西 | 从哪来 |
|---|---|
| 高度 / 坡度 / 可站面积 | 现有导航网格的**高度场**（HPA\* 代价模型已在用 climb / elevation） |
| ★ 山脚守点（隘口） | **HPA\* 的 portal 图**：高地簇与邻簇之间的 portal 就是「上山必经之路」，前移 2~4m 即守点 |
| 通往据点的路径 | 同一个 HPA\* corridor，不用第二套寻路 |
| 站位分配（山顶/山脚/侧翼） | 现有 §14.3 `FormationDef` + `prefer: UnitRole` 软槽位 |
| 包围圈 | 现有 `encircle` 阵型**升格**为大编队级"环绕目标"（槽位摆到目标周围的环上） |

★ 关键洞察：**寻路用的 portal 图，同时就是据守点的来源** —— 一处结构、两种用途。

### 21.3 序盘状态机（接在 §13.2 的姿态机之前）

```
[spawn] 波次生成
   │  开局：不开火（ROE = hold）
   ▼
  scout ──► seize ──► fortify ──► encircle ──► assault
 侦察/选点   抢占高地    据守布防     收缩包围圈     总攻
   │          │           │            │            │
   │          │           │            │      目标清空 / 玩家逃逸 → withdraw
   └── 超时(找不到高地) ──┴────────────┴──► 降级为 §13.2 的 advance 直接进攻
```

| 姿态 | 行为 | 交战规则 (ROE) |
|---|---|---|
| `scout` | 在**舰船/玩家**周边 `TERRAIN_SEARCH_R`(60~120m) 内打分选点 | **不开火** |
| `seize` | 大编队跑一次 HPA\* → corridor 直达选定高地 | **不开火**（除非被玩家先打） |
| `fortify` | 远程上顶、近战占山脚 portal、**突击兵预置侧翼（= §23 偷袭分队）** | **不开火**，仅反击 / 驱离 |
| `encircle` | 环绕目标收缩半径（§21.5） | 进入射程即开火 |
| `assault` | 收缩到 `R_MIN` 后总攻 | 全力交战 |

★★ **ROE=hold 是"不开火"，不是"停摆"**：据守期间单位仍在**补位 / 调整朝向 / 索敌 / 换岗**，
绝不违反铁律 3「任何一层都不能让敌人停摆」。这里的"不动"是**站位稳定**，不是 AI 冻结。

### 21.4 高地选点（打分，而不是"随便找个高的地方"）

候选 = 导航网格上的**局部高点**（高度 > 邻域均值 + 顶部可站面积 ≥ 一个小编队所需）。打分：

```
score =  w1 · 高度优势（相对目标/通路的俯视高度）
       + w2 · 顶部可站面积（能摆开远程兵）
       + w3 · 视野覆盖率（顶部对目标 / 接近路线的视线比例）
       + w4 · 距目标距离窗口（落在 HIGH_GROUND_WINDOW 内才给分）
       - w5 · 被反打风险（离玩家出生点/载具太近、无遮蔽）
```

- ★ **距离窗口 `HIGH_GROUND_WINDOW`(25~60m) 是硬约束**：太近 → 玩家一波冲掉；太远 → 打不到、白占。
- **山顶 → `ranged`**：站位在**朝向接近路线的那侧边缘**（站正中间反而没视野）；
  射程需同时覆盖 `山脚守点 + 目标`。
- **山脚 → `shield`/`grunt`**：占高地簇的**入边 portal**（每 portal 一个守点，前移 `GARRISON_PORTAL_AHEAD`），
  把上山路变成"仰攻 + 堵口"的劣势地形。
- **`assault` = 机动预备队**：藏在山侧 / 反斜面，专门反打试图绕后的玩家。

### 21.5 收缩包围圈（encircle → assault）

- 环上切 `N` 个扇区，各小编队认领一个（按 `BATTALION_MAX_SQUADS` 均分角度）。
- 半径按号令收缩：`R(t): ENCI_R0 → R_MIN`（默认 45m → 8m，历时 `ENCI_CONTRACT`≈30s）。
- ★ 环上槽位**优先吸附高地/掩体**（容差内就近取有利地形），但**必须保持环闭合** ——
  留缺口 = 玩家从缺口溜掉，等于包围失败。
- **总攻号令（任一触发）**：
  1. 所有大编队到达 `fortify`；2. `ENCI_CONTRACT` 计时到期；3. **玩家先开火 / 摧毁据守点**；
  4. 玩家进入内圈 `R_INNER_TRIGGER`；5. 舰船开始移动（玩家想跑）。

### 21.6 兵种分工小结

| 兵种 | 位置 | 任务 |
|---|---|---|
| `ranged`（普通远程兵） | 高地**顶部边缘** | 居高临下输出，覆盖山脚与通路 |
| **高危火力点**（固定工事） | ★ **高位 + 藏在工事之后** | 高威胁压制；正面打不到，需绕后/拆外层（§22.9） |
| `shield` | 山脚 **portal 守点** | 堵住上山唯一路径，硬吃正面 |
| `grunt` | 守点两侧 / 斜坡 | 填缝、防绕后 |
| `assault` | 反斜面 / 侧翼（机动） | 预备队，抓绕后 / 追逃逸；★ **总攻时即 §23 的偷袭分队主体**；★ 也是**端掉高位火力点**（§22.9）的手段 |

### 21.7 必须有"上钩"的兜底（否则从战术变成堵路）

★★ 玩家完全可以选择**不上钩**（远远绕开、或干脆回基地）。所以：
- `scout` 超时（`TERRAIN_TIMEOUT`）→ 找不到合适高地就**降级为直接 advance**，绝不允许原地空转。
- 玩家持续远离 → 放弃据守，转 `advance` 追击（据守**不是永久状态**）。
- ★ **平衡红线**：高地据点**必须给玩家解法**（范围/间接火力、载具、引蛇出洞、绕后），
  否则就是"卡关"而不是"战术"（§20 风险里同步记了一笔）。
- ★ 选点**只在 `scout` 算一次 + 换姿态时重算**，中途保持 —— 否则每帧重打分 = 编队反复改主意。

## 22. 防御工事：敌人会施工（2026-09-18 新增）

> **用户定调**：「我还要让敌人会造防御工事。」

### 22.1 一句话

`fortify` 姿态不再只是"站住"，而是**建**：**杂兵兼任施工**，在隘口、高地、接近路上修掩体、路障、火力点，
把"占住的地形"变成"玩家的难题"。★ 工事**改变通行代价**，所以和 §15 寻路强耦合 ——
这是本节最容易翻车的地方，见 §22.3。

### 22.2 工事种类（先少后多，第一版只做前三种）

| 工事 | 位置 | 作用 |
|---|---|---|
| **掩体 / 沙袋** | 山脚 portal、正面 | 挡子弹、给守军 cover（伤害减免） |
| **路障 / 铁丝网** | 接近路线 | **抬高通行代价**（不硬堵）、逼玩家绕行或拆 |
| **普通火力点**（弩炮 / 机枪塔） | 高地顶部 / 工事后 | 自动射击，覆盖隘口与通路（轻） |
| ★★ **高危火力点** | **高位 + 藏在工事之后** | 重装高威胁：高 HP、高 DPS，正面几乎打不到（§22.9） |
| 诡雷 / 雷区（后续） | 隘口前 | 区域拒止，踩上去炸 |
| 观察哨（后续） | 高地 | 扩大警戒视野，提前预警 / 呼叫增援 |

### 22.3 ★★ 与寻路的耦合（本节的成败点）

- 工事落在导航网格上 → **必须标脏 cluster**（§15.5 的脏集），下次寻路重算。
  ★ **绝不能**在已缓存的 corridor 上悄悄插障碍，否则整队照着旧路撞墙。
- ★★ **两阵营通行掩码（`passFaction`）**：
  - **玩家侧**：工事 = 阻挡 / 高代价（要打，或要绕）；
  - **敌人侧**：**己方工事 = 高代价但可通行**（`STRUCT_COST_ENEMY`）。
    这样敌人会**自然走"留的门"**，万一路被堵死也能慢慢挤过去 —— **不会把自己关在门外**。
  ★ 这条是刚需：若工事对敌人也是硬阻挡，AI 会自锁在工事群里。
- 工事**不改变 HPA\* 的粗层结构**（cluster 划分不动），只改"簇内代价 + portal 通断"
  → 重建成本被限制在受影响的少数簇内。

### 22.4 谁建 / 怎么建

- **角色**：★ **由 `grunt`（杂兵）兼任施工 —— 不新增兵种**（用户 2026-09-18 裁定）。
  好处是零新增角色；代价是施工的杂兵本身就是普通单位，被抽去打杂的兵力不再输出。
- **点位从哪来**：★ `scout` 阶段**就把工事点位和地形点位一起算出来**（同一张 portal 图）——
  隘口 = portal 守点，火力点 = 高地顶，路障 = 接近路线的**收窄处**。
- **流程**：`scout`（选点）→ `seize`（占位）→ `fortify`（被指派的杂兵按点位顺序施工，每件 `BUILD_TIME`）。
- ★ **施工中脆、可打断**：施工的杂兵无武装、移速降；**杀掉施工中的杂兵 = 该工事作废**。
  这是玩家最重要的一条反制手段。
- **预算**：每个大编队一份 `BUILD_BUDGET` 点数，每件工事扣点 → **不会变成地毯式工事墙**。

### 22.5 可摧毁 + 必须留路（红线，与 §21.7 同源）

- 所有工事有 `STRUCT_HP`，走既有 `applyDamage` 口径 → 玩家可以打掉。
- ★★ **工事不得封死玩家唯一通路**：要么本身可摧毁，要么强制留 `STRUCT_GAP_MIN`(4m) 缺口。
- **玩家反制手段**（必须至少给到这几条）：拆、绕、范围伤害、**先杀施工中的杂兵**、引蛇出洞。
- 这一条和"据点必须给玩家解法"是同一条红线的两种形态：**不能从"战术"变成"卡关"**。

### 22.6 生命周期

| 时机 | 行为 |
|---|---|
| `fortify` 期间 | 施工中（ROE 仍 hold；被玩家打则提前 `assault` 护工事） |
| 转 `encircle` / `assault` | **停工**，已建工事**保留为静态威胁** |
| 大编队被歼灭 / 换日（玩家回基地） | **随波次一起清**（不跨局残留，否则地图越玩越堵） |
| 存档 | ★ **不存**（纯运行时态，同铁律 7） |

- 离玩家太远的工事**不建**（省性能）；同时存在数上限 `MAX_STRUCT_PER_BN`。

### 22.7 表现与性能

- 低模 + **同类实例化批渲染**（同 §5.7 SwarmBatch 思路）。
- ★ 建造过程要**看得见**：先出地基轮廓 → 逐渐长高（进度条 / 顶点位移）。
  否则玩家只会觉得"突然冒出来一堵墙"，还以为是 bug。
- 破坏复用现有受击反馈 + 碎块。

### 22.8 与序盘状态机的接线（§21.3）

```
scout（选点：地形点 + 工事点）
  → seize（占位）
  → fortify（★ 工事施工中，ROE 仍 hold）
  → 关键工事完成 → 具备 encircle 条件
       └─ 施工期被玩家打 → 提前 assault（护工事 + 转守为攻）
```

### 22.9 高危火力点：藏在工事之后的纵深布置

> **用户定调**：「还要有普通远程兵与高危火力点；高位火力点藏在工事后面。」

- **两级火力（不要混为一谈）**：

| 档 | 形态 | 特点 |
|---|---|---|
| **普通远程兵** | **机动单位**（`ranged`，§16.4，F5） | 弱、能动、可被冲脸 |
| **高危火力点** | **固定工事** | 高 HP / 高 DPS / 覆盖广，**正面几乎打不到** |

- ★★ **纵深两层布防**（这才是"恶心"的核心）：

```
玩家火力 ──► [ 外层：工事线（可拆、吃伤害、挡视线） ] ──► [ 内层：高位火力点（高危） ]
```

  外层工事**替火力点吃伤害、遮视线**；火力点躲在后面俯射**缺口与接近路**。
  → 玩家想打火力点，**必须先破外层**（或者用别的手段）。

- **LOS 规则**：工事对玩家火力**提供遮挡**（`FP_LOS_BLOCK`：正面伤害大幅衰减 / 不命中）；
  但工事一旦被拆出缺口，火力点即暴露。

- ★★ **反制红线（必须有解，同铁律 10 / 14）** —— 至少给到这几条：
  1. **侧面 / 绕后**：LOS 断开的方向能打到 → ★ **正好是 §23 偷袭分队的活**（从背向端掉火力点）；
  2. **范围 / 间接火力**：越过工事砸到后方；
  3. **先拆外层**：拆出缺口 → 火力点暴露；
  4. ★ 绝不允许"**看不见、打不到、还一直在输出**"的死角。

- ★ **与 §23 咬合**：高位火力点是**正面主力啃不动的点**，由偷袭分队从背后解决 ——
  这正是"正面 + 绕后"组合拳存在的意义。

## 23. 绕后与偷袭（总攻必须有 1~2 组偷袭）（2026-09-18 新增）

> **用户定调**：「还有绕后+偷袭，总攻的时候必须有 1~2 组偷袭的。」
> （同一条消息里裁定：**施工由杂兵兼任**，见 §22.4）

### 23.1 一句话

大编队进入总攻阶段时，**固定抽出 1~2 个小编队作为偷袭分队**：不走正面走廊，
从侧翼 / 反斜面 / 隐蔽路径绕到玩家（或舰船）**背后**，**正面先接火、背后再捅刀**。

★ "总攻时**必须**有偷袭组"是硬要求 —— 不是可选战术，而是总攻的标准构成。

### 23.2 编制与兵力底线

- 偷袭分队**优先 `assault`**（快、适合快速突入），可掺 1~2 个 `grunt` 做肉盾。
- 组数 `AMBUSH_SQUADS = 1~2`，★ **硬上限 2**。
- ★ **正面兵力底线 `MAIN_FORCE_MIN`(60%)**：抽走偷袭分队后若正面低于此比例 → **取消偷袭**
  （防止"绕后绕到自己正面崩了"）。

### 23.3 路径：第二条走廊（不能共用正面走廊）

- 除了大编队的**正面 corridor**，为偷袭分队再跑**一条侧翼 corridor**
  （同一套 HPA\*，但代价模型加**侧向偏置 + 可见度惩罚**）。
- ★ **可见度代价**：优先走**反斜面 / 掩体 / 高地背面**（被玩家看到的概率低）。
  实现：用高度场算出"相对玩家视点的暴露度"作为附加代价 → 路径会**自然选隐蔽路线**。
- **绕后终点**：目标**背向侧**（`AMBUSH_ARC` = 背向 ±90° 扇区）。
- ★ **绕后路径必须避开正面火力覆盖区**，否则"绕后"等于正面再冲一次，白搭。

### 23.4 潜伏与发动（ROE）

| 阶段 | 偷袭分队行为 | ROE |
|---|---|---|
| `fortify` | 预置到侧翼 / 反斜面隐蔽位 | **隐蔽：不开火、不暴露** |
| `encircle` | 沿侧翼 corridor 缓慢逼近后方 | **仍隐蔽** |
| `assault` 号令 | **延迟 `AMBUSH_DELAY`(1~2s) 后**从背后同时发动 | 全力交战 |

- ★ **正面先接火、背后晚一步** —— 这个时间差就是"偷袭"手感的全部来源。
- ★★ **潜伏 ≠ 停摆**：潜伏期间仍在**缓慢侧移找位 / 贴掩体 / 观察**，不违反铁律 3。
- ★ 侧翼 corridor 与正面 corridor 一样走 §15.5 的增量重算与降级链（**绝不能因为绕后就卡住**）。

### 23.5 暴露与兜底（否则玩家会觉得被作弊）

- ★★ **必须给可察觉的线索**：偷袭分队接近时要有**视觉/音效提示**
  （后方脚步声 / 阴影 / 短暂轮廓）。让"被偷袭"是**可归因**的，而不是凭空挨打。
- `AMBUSH_EXPOSE_DIST`：过于靠近玩家（< 12m）→ **隐蔽失效**，直接转入冲锋（不等号令）。
- `AMBUSH_TIMEOUT`(20s)：超时没到位 / 没发动 → ★ **放弃偷袭，并入正面进攻**。
  ★★ 绝不允许偷袭分队长期潜伏导致"敌人不动"（这会同时违反铁律 3 和用户定的
  "不许敌人不动 + 时间照常流逝"那条）。
- **玩家反制**：反侦察 / 巡逻后方 / 听声辨位 / 范围技能扫出阴影 / 提前打掉侧翼通路。

### 23.6 与既有设计的关系（不是新系统，是既有件的重组）

| 既有件 | 在偷袭里的角色 |
|---|---|
| §21.6「反斜面的 `assault` = 机动预备队」 | ★ **就是偷袭分队的预置形态**（同一批人，两个阶段的说法） |
| §15 HPA\* corridor | 再跑一条侧翼 corridor（同一套算法，换代价权重） |
| §14 `Squad` | 偷袭分队就是普通小编队，只是挂了个 `ambush` 标记 |
| §22 工事 | 可选：出发的侧翼路径上由杂兵**顺手修一段路障**掩护出发点 |
| §22.9 高危火力点 | ★ 正面主力啃不动的点，**由偷袭分队从背向端掉**（组合拳的落点） |
| §25 飞行兵 | 轰炸正面/吸引注意力，为偷袭分队创造切入窗口（总攻时的天然组合） |
| §13.2 姿态机 | `assault` 姿态的一个**并行分支**（正面主力 + 偷袭分队两条线） |

### 23.7 调试可视化（§17 追加）

- 侧翼 corridor 与正面 corridor **用不同颜色**画出来。
- 偷袭分队画**待机计时 / 隐蔽状态 / 暴露状态**。
- ★ 看不到"它在绕后"就调不出手感 —— 这条必须进 F0 的可视化清单。

## 24. 陷阱（敌人也会布置）（2026-09-18 新增）

> **用户定调**：「敌人也可以布置陷阱。」

### 24.1 一句话

★ **工事是"挡住你"，陷阱是"等你来踩"**。陷阱**不是障碍**（不改变通行代价），
而是**触发式的一次性危害**，铺在接近路、隘口、以及 **§22 工事缺口（那道"门"）** 上。

### 24.2 陷阱种类（第一版三种）

| 陷阱 | 作用 | 触发方式 |
|---|---|---|
| **诡雷 / 地雷** | 直接伤害（可带减速） | 踩踏 |
| **绊线 / 拉发** | **警报**：暴露玩家位置 + 呼叫就近编队 | 跨越 |
| **陷坑 / 减速带** | 限制机动，把玩家**钉在火力区里** | 踩踏 |
| 诱饵（后续） | 假补给 / 假遗物，骗玩家走进火力覆盖 | 拾取 |

### 24.3 布置位置（复用既有结构，不新建系统）

- 接近路线 / 隘口：**同一张 portal 图**（§21.2 / §22.4 早就在算这些点）。
- ★★ **工事缺口就是最好的陷阱位**：玩家被 §22.3 的两阵营掩码逼着从"门"过，
  **门里埋雷** = 纵深布防的最后一环。（§22 那张示意图里的"门"从此有了第二重含义。）
- 仰攻坡、反斜面的必经点。

### 24.4 己方无害（沿用掩码思路）

- 陷阱带 `passFaction`：**敌人自己踩不响**（同 §22.3 的通行掩码逻辑）。
- ★ 否则 AI 会自己踩自己的雷 → **自锁**（同铁律 13 的教训）。

### 24.5 可见性与可察觉（红线，同铁律 17）

- 陷阱**默认不显形**，但 ★ **必须有线索**：地面异常纹理 / 微弱提示音 / 
  **敌人自己不走的"绕开轨迹"**（这条最优雅：AI 的行为本身就是提示）。
- 提供**侦察手段**显形（现有侦察能力 / 范围技能扫出）。
- **反制**：侦察 / 绕行 / **用范围攻击提前引爆** / 载具或召唤物趟雷 / 跟着敌人踩出来的路走。

### 24.6 与寻路、生命周期的关系

- ★ **陷阱不参与 HPA\***：它是 trigger，**不是障碍** → **不进代价模型、不标脏 cluster**
  （★ 与工事相反，别混：工事要标脏，陷阱不要）。
- **一次性**：触发或拆除后消失。
- 上限 `MAX_TRAPS_PER_BN`；`TRAP_ARM_TIME`（布置后多久进入待发，之前可安全拆除）。
- ★ 随波次清理、**不入存档**（同铁律 15）。

### 24.7 参数（并入 §19）

`MAX_TRAPS_PER_BN` 6 / `TRAP_ARM_TIME` 4s / `TRAP_DAMAGE` 按类型 / `TRAP_REVEAL_R` 8m

## 25. 飞行兵种（只做轰炸，不缠斗）（2026-09-18 新增）

> **用户定调**：「还要有飞行兵种，但是我就不指望飞行兵种持续攻击了，怪恶心的，
> 就只起个轰炸作用即可。」

### 25.1 一句话

飞行兵是**一次性的轰炸投送手段**，不是"会飞的持续输出"。
它们**不缠斗、不盘旋输出**：飞进来 → **投一次弹** → 撤出去 → 冷却 → 再来一趟。

★ 这条是用户明确要的**减法**：持续空中攻击"怪恶心"，所以**只保留轰炸**这一个作用。

### 25.2 出击循环（sortie，不是缠斗 AI）

```
待机（编队后方 / 机场）
  → approach 进场（按预定航线飞向目标点）
  → ★ bomb run 投弹（一次投放；落点带指示 + 延迟引信）
  → egress 撤离（★ 投完立刻走，不回头）
  → cooldown 冷却（FLYER_SORTIE_COOLDOWN）
  → 回到待机
```

- ★★ **不追击、不缠斗、不持续开火** —— 投完就走，这是**硬性行为约束**。
- 同时在场 `MAX_AIR_SQUADS = 1`（就一组，别搞成"满天空都是"）。
- ★ 呼应 §23：总攻时 **轰炸正面 + 偷袭绕后** 是天然组合
  （轰炸吸引注意力，正好给偷袭分队创造窗口）。

### 25.3 ★★ 导航：飞行兵**不参与地面寻路**

- 飞在天上 → 无视坑 / 深水 / 陡崖 / 通行宽度 / **工事** / **陷阱**。
- ★ 所以 **不要**把飞行兵塞进 §15 的地面 corridor：它们走**独立空中层**，
  导航 = **直线 + 避障**（只需绕开高于飞行高度的地形/建筑），比 HPA\* 廉价得多。
- ★ 也不进 §14 的车道分配与阵型槽位（没有"编队横排"这回事）。
- 编队层次上仍挂在大编队下（有 `squadId`），但**只由大编队决定"何时投 / 投哪"**，飞行过程自治。

### 25.4 投弹（唯一的攻击方式）

- 落点 = 大编队指定的**区域**（玩家当前位置 / 舰船 / 正面主力要突破的点）。
- ★★ **落点指示 + 延迟引信**（`BOMB_FUSE_TIME`）：落地前有可见标记与短暂延迟
  → **玩家有反应窗口**。这是"轰炸"套路的标准公平性设计，也是避免
  "从天而降的伤害"挫败感的关键（同铁律 17 / 20 的可察觉红线）。
- 伤害作用于**区域**（对己方是否减伤按手感定）。
- ★ 投弹航段是飞行兵**最脆弱**的时候（可被击落）。

### 25.5 与既有设计的交互

| 既有件 | 与飞行兵的关系 |
|---|---|
| §15 HPA\* / corridor | ★ **不参与**（独立空中层：直线 + 避障） |
| §22 工事 | **直接飞越**（工事挡不住它）；★ 但火力点**可选兼作防空威慑**，限制活动空域 |
| §24 陷阱 | ★ **不触发**（空中不踩雷） |
| §21 地形战术 | 无视高地 / 隘口 —— 它是"地形管不着"的那一类 |
| §23 偷袭 | 轰炸正面吸引注意力，为偷袭分队创造窗口 |
| LOD（§3） | 空中单位同样可降级为代理（空中代理路径更简单：直线 + 高度） |

★★ **防空威慑是必要的平衡**：否则飞行兵会变成"地形 / 工事 / 陷阱全无视"的**万能解**。
建议让**高危火力点兼有对空能力**（一个工事、两种威胁）—— 这样 §22 与 §25 正好互相咬合。

### 25.6 参数（并入 §19）

`MAX_AIR_SQUADS` 1 / `FLYER_SORTIE_COOLDOWN` 12~20s / `FLYER_ALTITUDE` 按地形高 /
`BOMB_FUSE_TIME` 1.5s（落点延迟）/ `BOMB_RADIUS` 6m

## 26. 铁律汇总（v2 完成后仍不得破坏）

1. **编队归属跨 LOD 升降格保持**（`squadId` 必须进 `AgentSnapshot`）
2. **编队成员引用不存裸 index**（swap-remove；每帧分桶）
3. **寻路有降级链**：HPA* → 流场 → 直线；**任何一层都不能让敌人停摆**
4. **大编队全知、个体有限感知**（保留警戒场与反应延迟）
5. **编队只管"去哪"，不管"怎么打"**（战斗仍走 `applyDamage` / 攻击槽 / 令牌）
6. **对外单向依赖**：`modes` → `SwarmSystem`；模式层不碰编队内部
7. **存档不存编队**（纯运行时态，可随时重建）
8. **可视化走 URL 开关，关闭时零开销**
9. **序盘"不开火"≠"停摆"**：ROE=hold 期间仍索敌/补位/换岗；且**任何姿态都必须有超时兜底**能收敛到进攻
10. **据点必须给玩家解法**（范围火力/载具/引蛇出洞/绕后）—— 不许做成无解堵路
11. **地形选点一次算定**（`scout` 一次 + 换姿态重算），**不得每帧重打分**（防编队反复改主意）
12. **工事改变导航必须标脏 cluster**（不得悄悄改缓存走廊）
13. **敌人己方工事对自己"高代价但可通行"**（★ 绝不自锁在工事群里）
14. **工事必须可摧毁，且不许封死玩家唯一通路**
15. **工事是运行时态**：随波次清理，不入存档，不跨局残留
16. ★ **总攻必须有 1~2 组偷袭分队**；抽调后正面兵力不得低于 `MAIN_FORCE_MIN`(60%)
17. ★ **偷袭必须有可察觉线索**（声音/阴影/轮廓）—— 不许无提示背刺
18. ★ **潜伏 ≠ 停摆**；偷袭必须有 `AMBUSH_TIMEOUT` 兜底（到不了位就并回正面）
19. ★ **高危火力点必须有解**（侧面/绕后 · 间接火力 · 拆外层）—— 不许出现"看不见又打不到"的死角
20. ★ **陷阱必须可察觉 / 可侦察**（不许纯隐形踩雷）—— 与铁律 17 同源
21. **陷阱对己方无害**（`passFaction`，绝不自触）
22. **陷阱不参与寻路代价**（是 trigger 不是障碍；★ 不得标脏 cluster —— 与工事相反）
23. ★ **飞行兵不参与地面导航**（不进 corridor / 车道 / 工事代价 / 陷阱触发）—— 走独立空中层
24. ★ **飞行兵只做轰炸**：不缠斗、不持续攻击；必须有冷却 + 单组上限（`MAX_AIR_SQUADS`）
25. ★ **轰炸必须有落点预警 + 可躲的反应窗口**（同铁律 17 / 20 的可察觉红线）
26. **防空威慑必须存在**（工事/火力点可对空）—— 否则飞行兵成了无视地形/工事/陷阱的万能解
