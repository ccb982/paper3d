## 1. 一句话 + 现状瓶颈

**一句话**：把敌人从"每只全保真"改为"**分层保真 + 时间片调度 + 全局协调**"——近处是个体、
远处是代理、更远只有流动感；"聪明"来自攻击槽 / 警戒场 / 导演这类全局机制，不靠堆个体算力。

现状瓶颈（2026-09-13 代码证据）：

| 症状 | 位置 | 说明 |
|---|---|---|
| 每敌全保真 | `entity/EnemyBase.ts` | 各自 FTXQuad + 帧动画 + rapier kinematic + 血条 Effect + 影子 |
| 逐帧全量 AI | `systems/ai/AISystem.ts:24` | 单例 Set 全量跑状态机，无时间片 / 无调度 |
| 逐敌地形开销 | `EnemyBase.moveBy`（hazard 扫描，最多 8×2 方向）、`WorldMode.clampCharacter`、`updateWaterEntry` | 每敌每帧多次 raster 采样 |
| 逐敌推挤 | `CharacterBase.separateFromOthers / separateFromStatics` | raster 查询 + 静态障碍索引 |
| 逐敌 draw call | `EntityManager.renderAll` → 每敌一个 FTXQuad | 目前 50 上限首先卡在这里 |
| 硬上限补丁 | `WorldMode.MAX_ENEMIES=50`、`ENEMY_CULL_RADIUS=120`、影子强 LOD、波次拆两处 | 打补丁式省算力，不是架构 |
| 索敌重复 | `WorldMode.enemyTargetCandidates` 逐敌排序 | 无共享感知 / 无目标分配 |

## 2. 目标与验收指标

- **玩法**：屏上 50 / 全图 200 稳定 60fps（低端目标：无掉帧尖刺，最低 30fps 可玩）。
- **预算**（60fps = 16.6ms 总预算内，蜂群占比）：总计 **≤ 4ms**
  - 决策（脑）：≤ 1.5ms
  - 移动 / 分离 / 贴地：≤ 1ms
  - 渲染提交：≤ 1ms（实例化后 draw call ≤ 3）
  - 其余（感知 / 攻击 / 杂项）：≤ 0.5ms
- **行为**：反应有随机差异（不再整齐划一）；围杀有槽位感、不叠人堆；远处有洪流流动感。
- **兼容**：伤害管线 / 事件总线 / 掉落 / 遗物击杀结算 / 舰船索敌契约**全程不变**。

## 4. 模块划分（新建 `src/systems/swarm/`）

```
SwarmSystem.ts    调度器：分桶 tick + 时间片预算 + 升降级桥接（唯一对外入口）
AgentPool.ts      SoA 定长池（256）：pos/hp/state/target/timers/flags，swap-remove，零 GC
CrowdGrid.ts      分桶：邻居分离 / 密度 / 警戒场 / 子弹段圆命中
FlowField.ts      4m 网格多源 Dijkstra（玩家+舰船），坑/水/崖编码为高代价，3Hz 增量
AttackSlots.ts    攻击槽协调器：环形占位 + 近战攻击令牌 + 远程距离环
Director.ts       威胁预算 / 节奏 / intent 分配（打谁、包抄方向、集结）
render/SwarmBatch.ts  图集 + InstancedMesh（L2/L1）；L3 仍走现有 FTXQuad
```

依赖方向：`modes` 驱动 `SwarmSystem`（单向）；`swarm` 只消费 `services`（map/render/combat）
与 `core`（EventBus/Session），**不引 ui**；行为库（`systems/ai/aiconfig` + behaviors/conditions）
被 L2/L3 共用（同一份配置，不同 tick 频率）。

## 5. 关键机制

### 5.1 调度器（SwarmSystem）

- 分桶 tick：`bucket = (frame + agentPhase) % K`，各层 K = 6 / 12 / 30（对应 10/5/2Hz）。
- 预算门：每帧决策耗时超过预算 → 本帧剩余分桶顺延到下一帧（不补课）。
- 计数器：`entityPerf` 扩展 swarm 分项（brain / move / sep / grid / render），P0 建立的基线持续对照。

### 5.2 流场（FlowField）—— 导航 + 危险代价

- 网格 = RasterMap 4m 块（对齐现有 `blockAt`），窗口以玩家为中心 96×96 块（384m）。
- 多源 Dijkstra：目标集合 = 玩家 + 舰船停靠点（可扩展集结锚点）；重建 3Hz，或目标移动 > 1 格触发。
- 代价：坑 / 水 / 悬崖（落差 > 阈值）编码为高代价或不可通行 → **删掉现有 hazard 方向扫描**。
- 消费：代理取邻格梯度 + 分离修正；窗口外走直线逼近，入窗自动接上流场。
- worker 化（可选，P2 之后再评估：16k 节点 Dijkstra 主线程 3Hz 亦可接受）。

### 5.3 人群网格（CrowdGrid）

- 2m 分桶（随玩家窗口滑动），查询半径 = 自身碰撞半径 + 邻居半径。
- 分离：每代理每移动 tick 查 4~8 邻居，O(n) 无排序。
- 警戒场：发现玩家/被击中的单位向网格刷"警戒半径"；范围内同伴按**个体随机延迟 0.2~1.5s**
  转入追击（消灭整齐划一感）；不做逐敌 LOS 射线。
- 玩家子弹打 L2/L1：线段 vs 网格圆判定（子弹本来就少），命中即结算，不给远处建刚体。

### 5.4 攻击槽（AttackSlots）—— "聪明"的最大来源

- 目标周围预计算**环形槽**（近战内圈 / 远程外圈），按角度扇区分配；槽容量有限。
- 近战**攻击令牌**：同一目标同时挥击数上限 N（默认 3~4），其余单位绕行 / 游走 / 等待；
  挥击有起手预警帧 + 后摇 + 受击打断（可读性）。
- 远程占距离环 + 集火（共享优先目标）；槽位 1~2Hz 重分配，目标移动不抖。

### 5.5 升降级（实体 ⇄ 代理）

- `agentId` 稳定：池内 id 与实体一一对应；升格 = 建 `EnemyBase` 并灌入代理数据；
  降格 = 拆实体、数据回池（位置 / 血量 / 状态机状态保留）。
- 切换点滞回（30/40m）+ 升格预算（≤2/帧）；死亡统一走 `applyDamage` / `killed` 事件。
- **单一事实源**：任何时刻一只敌要么是实体要么是代理，桥接层封装在 SwarmSystem，外部不可见。

### 5.6 战斗抽象（L2/L1 到期结算）

- L2/L1 在攻距内按各自 cadence 排"到期事件"：预警（视觉闪烁/曳光）→ 结算伤害；
  伤害走与 `applyDamage` 等价的代理入口（`AgentHandle` 实现伤害管线所需最小面：hp/defense/camp/position）。
- 不生成子弹实体；远处敌人远程攻击 = 曳光 + 到期扣血。
- 玩家/友军子弹命中原生支持代理（5.3 段圆判定）；近处仍走 rapier。

### 5.7 批渲染（SwarmBatch）

- 每兵种一张**图集**：帧序列打平（base 色烘焙进图集；residual/fluid 放弃），构建期生成。
- `InstancedMesh` 容量 256/兵种，实例属性：pos / yaw（帧）/ flip / frameIndex / 受击染色 / fade。
- 刷新策略：仅在有变化（移动/换帧/染色）时写脏区间；L2 30fps 换帧、L1 冻结帧。
- 血条 / 影子 / residual 特效**仅 L3**；L2/L1 无影子（或仅大单位投影，按预算定）。

### 5.8 导演（Director，P4）

- 威胁预算：按玩家血量 / 弹药 / 与舰船距离调节生成与压力，不再纯随机刷。
- 节奏：静 → 试探 → 突涌 → 间歇（波次是导演节拍，不是独立 timer）。
- intent 分配：一部分压舰船 / 无人机 / 祖宗，一部分包抄玩家（扇区分配），形成分工洪流。

## 6. 群体智能清单（战术层，P2 起逐步上线）

## 7. 冻结契约（不得破坏）

- `applyDamage` / 事件总线（`damage` / `killed`）/ `MobDef.drops` / 遗物击杀统计。
- 舰船索敌优先级（祖宗 > 舰船 > 玩家 > 友军）与舰船守卫结算。
- RasterMap 空间索引升级为"实体 + 代理"统一查询面（小地图 / 索敌 / 掉宝查询都要能看见代理）。
- 存档：不存代理（纯运行时态，可随时重建）。

## 10. 风险与取舍

- **双轨期复杂度**（实体 + 代理并存）：用单一 `agentId` + 桥接层收口，禁止两套行为逻辑分叉。
- **图集构建成本**（帧数 × 尺寸）：按兵种拆图、构建期生成，运行时零重建。
- **视觉差异**：L2/L1 无 residual/fluid / 无影子（已确认接受）；L3 保持全效果。
- **流场窗口边界**：窗口外直线逼近，入窗接管，避免边界抖动。
- **近处 rapier 仍是事件开销大头**：L3 上限 30 是硬约束，不再扩大。
- **不要做**：逐个体 A* / 逐个体 LOS / 逐帧创建销毁实体 / 视距外全保真。
