## 架构速览（开发前必读，一页记住整个系统）

### 分层（单向依赖，禁止反向）★ 2026-08-25 按代码现实修订
```
main（入口：路由 + 主循环 + boot 装配；时间经 RenderManager 分发）
  ↓
modes（应用层：ShipMode/WorldMode/[Boss]）
  ↓
entity（实体骨架：EntityBase 统一管线）  systems（玩法：ai/inventory/interaction…）  ui（ship/world 两套）
   三大业务层平级、少横向。已知例外：entity→systems/player（角色控制器）、
   ui→systems/inventory（舰船背包网格展示直读 session；★ 计数/落账/合成全走
   ItemManager/CraftingManager，加工台与背包共享同一图标服务）
  ↓
core（EventBus/Session/SaveSystem/ItemArchetype）←─ services（render/camera/combat/fx/map/physics…）
   并列基础设施层，均可被上方任意层消费；services→core 合法（如 CombatDirector 订阅事件）
  ↓
platform（输入/平台适配：Web/WeChat/Douyin）  vendor（自研 FTX 播放器，仅 main/services 消费）
```
- 上层依赖下层；platform 是唯一碰 wx./tt. 的地方
- ⚠️ entity 层是核心层（旧图漏画）；services 不引 modes/ui/entity 的运行时代码
  （type-only import 例外）；加内容 = 改配置；换平台 = 改 platform

### 核心约定（写代码时始终记住）
```
① 游戏循环：fixedUpdate(物理/战斗) → update(渲染/特效/相机/UI) → render
② 实体：Entity + 组件（Transform/RigidBody/Billboard/Health/AI/...）
   - 需要物理的实体挂 RigidBody（按 kind 配置，非全部）
   - 序列化只存描述（kind/位置/数值），运行时引用（handle/mesh）不存
③ 事件总线：只有"UI/跨模块要听"的才走总线（拾取/抽卡/警报/对话/死亡）
   - 战斗内部（伤害/命中）直接调用，不 emit；只在"表现边界" emit（damage→伤害数字/导演反馈、killed→击杀演出）
④ AI：AIStateMachine 通用解释器 + 行为注册表 + 阵营标签(camp)
   - 敌人/友军共用行为库；玩家单独 PlayerController（输入驱动）
   - 子弹管线统一：谁发射都一样，阵营过滤在碰撞层
   - ☞ 敌人群体（分层保真/流场/攻击槽/批渲染）重置进行中，见《蜂群架构.md》（2026-09-13 设计定稿）
⑤ 存档：安全点（本舰）写 Session → storage；读档仅启动一次
⑥ 配置化：内容全在 config/*.json（敌人/遗物/卡池/合成/对话/事件）
⑦ 渲染管线：视锥剔除 → LOD → 分组(图集×LOD) → 批次y排序 → draw
   - 特效=播放器（.scene.zip）；物理=rapier；水/布料=独立 shader/verlet
```

### 模式状态机
```
BOOT → SHIP(日常) → WORLD(战斗) → BOSS(决战) → RESULT → BOOT
保留：舰船上的东西/科技树/主角物品/友军/遗物/卡池计数/day/背包
丢弃：当天地图/地图实体/战斗运行时状态
```

### 物理使用（rapier 分工）
```
游戏代码 → PhysicsWorld 封装（唯一碰 rapier 的地方）→ rapier
 ├ addBody(entity, kind)   # 按配置自动挂刚体
 ├ step(dt)                # 固定 1/60
 ├ applyImpulse            # 爆炸/击退/击飞
 ├ querySphere             # 爆炸范围
 ├ castRay                 # 瞄准/直线判定
 └ onCollision             # 阵营过滤后转伤害事件
特效/布料/水 = 不走物理（播放器/verlet/Gerstner）
```

### 开发时三问（拿不准时自检）
```
Q1: 这个新内容能不能放配置里？→ 能就放 config/，不硬编码
Q2: 这个调用跨模块了吗？→ 跨了就走 EventBus，没跨就直接调
Q3: 这个实体需要物理吗？→ 会被撞/会撞人/被力推才挂 RigidBody
```

### 已实现的多图层复合特效渲染（★ 2026-09-09 按代码现实）
```
背景：特效包（.scene.zip）一帧可以有区域实体（region/maskEffect → VAT 顶点动画）；
      一个包的"多帧"有时不是动画，而是多图层（共享同一画布，如可露希尔的无人机：
      frame_0 主体 / frame_1 左翼 / frame_2 右翼）。播放器正常渲染只画单帧，
      多图层必须拆开各自摆位再同时显示。

复合渲染器（services/render/DroneCompositeRender）：
  - 主体（无区域实体帧）→ FTXQuad 静态贴片
  - 双翼（带区域实体+maskEffect 帧）→ ★ 独立重走播放器单帧渲染管线：
      ① 网格重建：按整块美术 bbox 矩形 ring（标注空间、首尾闭合）重建，
        作者画的小区域多边形常只罩住翅膀下部 → 直接渲染会裁掉大半；
        重建后顶点走 buildDisplacementTextureData + buildEntityMesh（maskEffect
        原样驱动顶点呼吸，矩形随位移自然扑扇）。
      ② 恒等 uv：播放器 base/residual 纹理本身已按 bbox 裁剪（尺度=bbox.w×bbox.h），
        0..1 即整幅翅膀。帧映射须设 offset=(art.x/canvasW, 1-(art.y+art.h)/canvasH)、
        scale=(art.w/canvasW, art.h/canvasH)，得到的 vUv=(x,1-y) 归一化 0..1，
        与直接绘制 FTX 像素级一致。⚠️ 绝不能沿用 Asset 的整画布基准
        texBbox/frameSize 映射，否则采样区间推到纹理边缘 → 翅膀跑到画布顶部/偏移。
      ③ renderFrameData → 离屏 WebGLRenderTarget → 世界 billboard quad 采样
        （与 MoonEffect→SkyDome 同范式；RT 采样 quad 用 ShaderMaterial 原样输出
        sRGB 并翻转 v：RT row0=底，直接采样上下颠倒）。
  - VAT 连续时间 = 实体基类动画播放器（FrameAnimatorBase.localTime，默认一直 play、
    loopMax 无上限 → 连续不封顶），绝不另造控制器/计时器。
  - 主渲染器注入：★ 无人机是悬浮召唤物，由其所在模式（WorldMode）注入 THREE.WebGLRenderer，
    离屏 RT 与主渲染器共享 GL 上下文（WorldMode.render 里 entities.renderAll 在
    renderer.render(scene) 之前执行，实体内可安全做离屏 RT）。
  - ★ 关键实体 LOD/视锥豁免（EntityBase.lodExempt，主角/无人机/子弹为 true）：
    renderAll 对豁免实体绕过 2D 梯形视锥裁剪 + 距离 LOD，始终 applyViewDistance(0)。
    原因：FrameAnimatorBase.update 在 LOD≥2 时冻结动画时间轴（含 VAT 连续时钟
    localTime）——主角/无人机必须全程满档播放，不受距离/视野影响。
  - 兜底：无区域实体数据（纯 ftx3 纹理包）时双翼回退 FTXQuad + 老式 UV 扭曲；
    三图层按 frame 顺序渲染同一帧号（此包必需，勿按动画循环切帧）。
```

## 阶段 P：播放器集成（★ 首要任务，其他一切的前提）

### 为什么是首要任务
```
所有美术素材 = 播放器格式（ftx3 纹理包 / .scene.zip 特效包）：
 ├ 角色（主角/友军/敌人）动画 = ftx3
 ├ 技能/命中/环境特效 = .scene.zip
 ├ 道具图标/世界贴片 = ftx3 单帧/帧动画
 └ 物理参数 = 公共库 .phys.json（可注入任意资产）
播放器不集成 → 没有角色、没有特效、游戏无法开始做。
```

### 现状与目标
```
现状：
 ├ 播放器内核已验证（effects-player 原型成熟）
 ├ 已无头移植到 src/vendor/player/（解码/实体渲染/流体/播放）
 └ 但游戏内零调用：没有加载入口、没有特效管理、没有渲染集成

目标（本阶段结束时）：
 ├ 游戏内能加载并播放任何 ftx3 / .scene.zip
 ├ 特效实例可挂到实体、可编辑（物理注入/扭动/换皮）
 ├ 有性能管理（池化/LOD/剔除/实例上限）
 └ 有验证场景：主角模型 + 一个技能特效 + 中毒注入演示
```

### 子任务

**P1 播放器内核入驻（半天）**
```
1. vendor/player 整理为唯一源码：
   - FtxAsset.ts 归位到 core/ftxAsset.ts（与 effects-player 结构一致）
   - 补缺失文件：gl/ftxRenderer.ts（纯纹理 quad 渲染）

**P3 特效实例管理器（2 天）—— services/fx/EffectFx**
```

 ├ spawn(assetRef, opts) → EffectInstance     # 创建播放实例
 ├ despawn(instance)                           # 销毁（池化回收）
 ├ 实例上限：同时活跃 < 30（超限按 LOD 降级/停最远）

 ├ 生命周期回调：onComplete/onFrameChange/onStateChange
 └ 销毁：实体销毁自动回收

★ FrameState 衔接层（动画管线写 / 渲染管线读，见架构 3.3.3）：
 ├ 每实体一份：{ assetRef, frameIndex, facing/flipX, lodLevel, 渲染句柄 }
 ├ 动画管线（FrameAnimator）每帧写 frameIndex

 └ 本阶段实现基础字段；lodLevel 字段预留（P7 用）

★ 时间轴 = 复用播放器内核（core/time.ts + core/controller.ts，不重写）：

 ├ FrameAnimator 只做语义层：状态 → 帧名列表 → 配置 controller
 ├ 推进：FrameAnimator.update(dt) → controller.advance(dt) → 写 FrameState
 ├ 单次动画回 idle：controller onComplete 回调驱动状态机
 └ LOD 降级：调 fps / 暂停 controller（不 reset 时间轴，见 P7）

★ 朝向与翻转（控制解耦，见架构 3.3.2a）：
 ├ 帧名语义：前=脸朝相机（向下移动用）/ 后=背对相机（向上移动用）
 ├ 输入解耦：InputActions.moveAxis（抽象）→ 移动系统 → 朝向逻辑

 ├ FrameState 携带 facing+flipX → 渲染层应用（quad.scale.x=±1）
 └ ★ flipX 状态延续：动画状态切换不重置，只由新输入方向修改

## 战斗与掉落管线架构

> 一行定位：**命中 = rapier 物理碰撞｜伤害 = modifier 结算链｜掉落 = 挂载在静态世界命中回调上的独立管线**
> 范围：瞄准 → 发射 → 飞行 → 碰撞分发 → 命中分类 → 伤害 → 反馈 → 掉落。
> 原则：谁拥有谁负责；战斗内部直接调用，表现边界走 EventBus；组合层回调注入世界细节。

### 一、击中检测架构（现状，代码即文档）

#### 1.1 总览
```
输入(KeyJ/左键) → DesktopBinding.pressed.attack
  → WorldMode.consumeAttack()
  → firePlayerBullet()
        └─ cameraRay() → crosshairPoint() 准星落点（代理锁敌 → 敌人实体 → 地形 → 虚拟远点）★预测用，不负责最终判定
              → aimDirectionFromMuzzle() 枪口 → 落点（经典 TPS 弹道收敛；普通弹/祖宗弹同口径）
  → executeAttack('projectile') → BulletManager.spawn（池 100）
  → BulletEntity 纯物理：球 r=0.9（出膛 0.12 → 飞 4m 恢复，见 §1.4）/ gravityScale=0 直线 / CCD 防隧穿 / restitution0.8 反弹 / 寿命2s（零世界认知——不判伤害不判地形）
  → rapier 接触 → PhysicsWorld → EntityManager.dispatchCollision（按 userData=实体id）
        └─ BulletEntity.onCollision → 过滤(仅started/同阵营跳过) + hitFx → onHit(payload)  ★唯一出口
              └─ ★★命中解析层 resolveBulletHit（WorldMode 唯一入口，敌人/装饰物/地块全归口）
                    ├─ other=敌人实体 → applyDamage + emit 'damage' + 反弹
                    └─ other=null（地块/装饰物）→ chunks.resolveImpact → ImpactReport（一次权威判定；跳弹每次反弹各自解算）
                          ├─ playBulletImpact(report)  ◆ 地形扣除（还原老版：任意落点必出坑；报告供坐标）
                          ├─ agitateWaterNear(x, z)    ◆ 水面波动（报告 tile/water）
                          └─ spawnItemDrops(report)    ◆ 掉落：ground/water/prop 全来自报告
  → 反馈：CombatDirector 听 damage/killed → FEEL 表(hitstop/时间缩放/镜头踢/音频钩子)；浮动伤害数字
```

#### 1.2 瞄准（经典 TPS 枪口→准星收敛；2026-09-14 重做）
- **准星落点 `crosshairPoint()`**（WorldMode）：相机沿准星发线 →
  ① **蜂群代理优先**（主力杂兵无物理体：`raySphereHit` 3D 圆柱近似，垂距 ≤ `BULLET_HIT_RADIUS` 视为对准；比地形/实体落点近才锁）
  ② 敌人实体 / 地形静态物兜底（`aimRaycast` 实体优先 + 物理兜底 + 遮挡校验；`skipPhysics` 越过自家舰船/友军/飞行弹体）
  ③ 全无命中（对天/虚空）→ 相机射线上 `CROSSHAIR_CONVERGE_DIST=200m` 虚拟远点。
- **发射方向 = 枪口 → 准星落点**（`aimDirectionFromMuzzle`）：无论落点是代理/敌人/地面/远点，弹道都经过准星所指处——不会再出现「枪口与相机平行的两条线各飞各的」。
- 命中目标是**预测**，决定发射方向；子弹是否真的打中，交给物理碰撞判，二者不互相替代。弹道直线 → 指即中，手感好。
- **友军不劫持准星**（`AimOptions.skipPhysics`）：物理射线命中舰船/友军/飞行弹体不算落点，越过继续投——同时修掉了"连发时准星被上一发飞行子弹顶住"的问题。

#### 1.3 发射（Attack.ts：统一攻击意图）
- `executeAttack` 分派三类意图：`projectile`（子弹池发射）/ `melee`（querySphere 范围瞬时 + 高度过滤±2m）/ `aoe`（落点延迟，预留）。
- 玩家与 AI 共用同一入口（`aiCtx.attack` 也是 executeAttack）——"谁发射都一样"。

#### 1.4 飞行 & 碰撞（BulletEntity.ts）
- 纯物理实体（零渲染），绘制由 BulletRenderer 从速度快照完成（数据/视觉解耦）。
- 碰撞体积 = 小球 r=`BULLET_HIT_RADIUS`(0.9) + CCD（防隧穿）；gravityScale=0 → 直线弹道；restitution=0.8 → **打地面会反弹**。
- ★ **子弹体积模型（2026-09-14 定调；`PhysicsWorld.setBallRadius` 运行时改球体）**：
  1) **常规物理半径极小 = `BULLET_BODY_RADIUS`(0.05)**：飞行全程不误触地形/装饰物/自军（用户定：0.9 → 0.05）；
  2) **近点小弹**（用户定：15m 内都是近点）：投射落点距出生点 ≤ `BULLET_CLOSE_DIST`(15m) → **全程 0.05 不放大**——近战/贴墙/舰边射击最干净；
  3) **命中窗口放大**：>15m 的远点弹临近投射落点 5m 内（`BULLET_BULGE_DIST`）→ 放大到 `BULLET_BULGE_RADIUS`(1.5)，过点/远离立即缩回 0.05（补偿目标移动/弹道与准星的偏差）。
  **逻辑命中与物理体积解耦**：蜂群代理的 2D 线段判定用 `b.hitRadius`（常规 `BULLET_HIT_RADIUS` 0.9 / 放大 1.5），近身敌人照常命中；子弹对物理实体（Boss 等）的命中由临近落点放大保证。
- 命中实体后**不销毁、继续穿透**（可一路打穿多个敌人，设计如此）。

#### 1.5 碰撞分发（EntityManager.dispatchCollision）
- 关键设计：按 `userData = 实体 id`（非 rapier handle）查 `bases` → **杜绝 handle 复用误伤**。
- 地面/装饰物刚体（`kind:'ground'/'decoration'`，fixed）**没有 EntityBase 实例注册** → 落到 `onCollision(null)` 分支 = "命中静态世界"。

#### 1.6 命中分类（BulletEntity.onCollision → 命中解析层）
- 只在 `started`（接触开始）触发一次；命中过滤唯一真源 = `services/combat/teams.ts sameTeam`（`player`/`ally` 互免：玩家不误伤无人机，友军不互殴；`enemy` 对一切非同阵营生效）。
- **子弹实体零世界认知**：不做伤害、不判地形、不判装饰物——只过滤 + `hitFx` + 回抛载荷 `onHit({self, other, point, damage})`，分类结算全部由解析层（WorldMode.resolveBulletHit）负责。
- 敌人实体（`other≠null`）：解析层 `applyDamage + emit 'damage' + 控制台`（伤害结算归 combat，入口归解析层）。
- 静态世界（`other=null`）：解析层 `resolveImpact(point)` → 细分地块/装饰物 → 地形扣除/水波/掉落。
- ★ **组合层回调注入是本管线核心扩展点**：统一出口 `onHit` 一颗入口吃所有命中，解析层内部再细分——掉落/水波/地形/伤害全在解析层归口。
- ★ **跳弹分别解算（2026-09-08 定调）**：restitution=0.8 反弹 → 每次接触开始（`started`）独立触发一次解析 → 每次反弹各自结算（独立挖坑 / 水波 / 掉落 / 敌人伤害），不做每发合并。

#### 1.7 伤害（DamagePipeline.ts）
- `resolveDamage` modifier 链：闪避 → 格挡 → 护盾 → 防御 → 暴击 → 下限/取整（顺序即语义，加机制=插链，不改核心）。
- `applyDamage`：未闪避且 final>0 → `target.onTakeDamage` → 扣血 → hp≤0 → emit `'killed'` + onDeath。
- 同层已有 CombatDirector（事件消费者）配 FEEL 规则表统一手感强度。

#### 1.8 反馈（表现边界）
- `'damage'`：CombatDirector 按规则表做 hitstop/时间缩放/镜头冲击；WorldMode 投影浮动伤害数字。
- `'killed'`：击杀定格演出。
- 战斗数值逻辑内部直接调用；EventBus 只承载"表现/跨模块听众"——符合《开发说明书》③约定精神。

### 二、命中解析层 + 物品掉落管线（重写 2026-09-08）

> 一行定位：**所有子弹命中（敌人 / 装饰物 / 地块）都进唯一入口 `resolveBulletHit`；静态世界再走 `resolveImpact` 一次权威判定产出 ImpactReport，地形修改 / 水面波动 / 掉落全部消费同一份**——敌人伤害结算归 combat、世界细节归解析层，子弹实体零认知。此前"敌人伤害内嵌在 BulletEntity、静态世界各端重复探测"的旧架构整体废除。

#### 2.1 挂点（每次碰撞开始一次；敌人 / 装饰物 / 地块全走这里）
```
BulletEntity.onCollision → onHit(payload)             // ★唯一的出口（跳弹每次反弹各触发一次）
  → WorldMode.resolveBulletHit({ self, other, point, damage })
      ├─ other = 敌人 → applyDamage + emit 'damage'   （伤害归 combat）
      └─ other = null → chunks.resolveImpact(point)   ★命中解析层：一次权威判定
            ├─ chunks.playBulletImpact(impact)         // 地形扣除（还原老版：任意落点必出坑，报告供坐标）
            ├─ agitateWaterNear(x, z)                  // 水面波动（既有，十字采样保留）
            └─ spawnItemDrops(impact)                  // 掉落管线：三键全来自报告
```

#### 2.2 命中解析层（ChunkManager.resolveImpact → ImpactReport）
```
ImpactReport {
  x, y, z;                       // 命中点（世界）
  tile:  { cx,cz, bx,bz, id, role, h }   // ★ 命中地块：blockTypes→ Tiles 表 id + genRole + 4m 面高
  water: 'hit' | 'edge' | 'none'         // 命中块本身是 liquid / 4 邻块是 liquid / 无
  prop:  { key,x,y,z,r,h } | null        // ★ 命中点 ~2.2m 内最近的可碰撞装饰实体（无则 null）
}
```
- **地块属性来自表**（`tileById(id).genRole`）：`blockAt`（4m 世界块）→ `ChunkData.blockTypes[15×15]` → `Tiles 注册表`；高度取 blocks 内 1m cell 的 `heights`（4×4 平整）。无 chunk 数据 → id=0/role=''/h=0（视为不可挖）。
- **水判定**：命中块 role=='liquid' → `hit`；否则查 4 邻块任一 liquid → `edge`；否则 `none`。（水判定随"命中地块"表属性，不再十字采样。）
- **装饰实体**：`queryPropsNear` 查**运行时权威索引** `propRegistry`（见 2.5），返回最近者。

#### 2.3 地形修改（playBulletImpact(impact)）
- **还原老版行为（2026-09-08 回退）**：第一版资格门（role + 陡变带 PATCH_SLOPE_EPS=0.5）导致大片地形打不出坑、worker 空转，体验"远不如之前"。回退后：
- 每次静态命中都出坑——水平圆与 coarse cell AABB 判交 → digCells 逐格 +1（不封顶；同点连打持续加深）→ patchRebuildChunk 重建链路不变。
- 报告 `impact` 仍为**坐标源**（复用 resolveImpact 的命中点），地形修改与掉落/水波共用同一入口，维持"接入解析层"的归口；不做单独的地块资格收敛（后续若要"防水底/陡变带不挖"，须以玩家认可的手感再调，勿一步砍死）。

#### 2.4 环境探测 → 规则表（ItemDropPipeline.ts：纯函数，零依赖）
```
spawnItemDrops(impact):
  env = {
    hasGround:  impact.tile.role ∈ {ground, platform},   // 命中地块是可站地形
    hasWater:   impact.water !== 'none',                 // 命中块或贴邻一格水面
    hasCrystal: impact.prop?.key === 'depleted_crystal', // 2.2m 内耗尽原石晶体
  }
  → rollDrops(env) → [{itemId, count}]
```

| 环境 | 物品 | 概率 | 每次数量 | 堆叠上限 |
|---|---|---|---|---|
| 地面地块 | `raw_rock` 固原岩 | 0.35 | 1~2 | 99 |
| 命中水/贴水 | `ketone` 酮凝集 | 0.40 | 1~2 | 99 |
| 原石晶体 2.2m | `iron_grain` 异铁 | 0.55 | 1~2 | 99 |

#### 2.5 装饰实体权威索引（propRegistry）
- 旧 `hasPropTypeNear` 是"确定性重放规划"——每发命中重算 9 片 chunk 的 `planChunkProps`，是**推演**不是**查实际**。
- **新方案**：`createDecorColliders` 创建碰撞体时把实体登记进 `propRegistry`（key → `{key,cx,cz,x,y,z,r,h}[]`，世界坐标），chunk 视觉替换销毁时同步 `propRegistry.delete(key)`，`disposeAll` 全清——**只索引实际存在的碰撞体**（与 propBodies 同生命周期）。`queryPropsNear(x,z,r)` 查命中片 + 8 邻环取最近；`hasPropTypeNear` 降级为委托。BOSS 四维空间无装饰回归 false。

#### 2.6 背包落账 + UI
- `hasSpace` + `addItem('player', …)`：有空间直接直塞（★ 2026-09-10 起同层合并语义：一格一类、数量无上限，直塞即并入唯一格；不再有 maxStack 分堆）。
- `showPickupResult(itemId, ok, count)`：右上角"获得物品"**播报栈**（用户手绘 JSON《页面布局/获得物品.json》换算：灰黑半透明、左图标右文字；x 0.8766~0.9984 / y 0.8093~0.9103；**面板先放大 2× 再缩小 1/3（净 ≈1.33×）**，2026-09-10 用户定调）——每次拾取生成一条向下堆叠（同屏最多 5 条），单条 1.8s 后**向下滑动 + 淡出**移除；文案"获得了 固原岩 ×2"，背包满同格式红字"背包已满，无法拾取 …"（图标淡化）。
- `flashItemAndRefresh(itemId)`：背包打开时该格闪烁 + 面板实时刷新（bullet 掉落与 E 键拾取同走一格闪烁反馈）。
- 跳弹多次命中 → 每次反弹独立走本管线（各自掷概率 / 落账 / 提示），属特性。

#### 2.7 与既有生态的位置
- 掉落**直塞背包** + 提示 + 格子闪烁，与敌人死亡掉落（ItemBase 掉地上拾取，M4 阶段）是两条并行路径；若后续要"爆炸溅出实体掉落物"，把 rollDrops 的产出改走 ItemBase 生成即可，规则层不动。

### 三、架构评价（击中检测层）

#### 合理之处（保留不动）
1. **判定分工清晰**：瞄准则（预测）与物理实碰分离，各司其职；辅助瞄准 + 直线弹道给出手感，物理判定兜底真实性。
2. **userData=实体 id 分发**：规避 rapier handle 复用误伤——这是会真实爆炸的坑，已提前防住。
3. **组合层回调注入（onHit / hitFx）**：子弹实体零认知于世界细节——伤害、地形、装饰物、掉落全是解析层（WorldMode.resolveBulletHit）的事。
4. **伤害 modifier 链 + FEEL 表**：机制与手感都是"加一行/加一个"，核心不动。

#### 隐患与改进（按优先级）
1. **[已修 ✅] 动态 `import('../../core/EventBus')`** —— EventBus 改静态顶层导入（WorldMode.resolveBulletHit 里 emit 'damage'），每发命中不再过 Promise 边界。
2. **[中] DamagePipeline.resolveDamage("纯计算"契约背离)** —— 头注释写"不修改实体状态，纯计算"，但 `modifierShield`（DamagePipeline.ts:61）直接改了 `ctx.target.shield`。当前调用方每次新建 ctx 所以暂未炸，但契约脆弱（重入/复用会同点双扣盾）。改进：护盾吸收挪到 applyDamage 落账阶段，resolve 只读快照。

# 附：背包与加工台架构（★ 2026-09-10 模块化落地）

> 一行定位：**背包 = 同层合并（一格一类、数量无上限、跨层可拆分）；计数与落账的唯一入口是 ItemManager（countItem / countTotal）；加工台 = 每个配方一个 CraftModule 模块（内部自管 UI 与数量窗），数据查询 / 消耗 / 新增全部走 ItemManager / CraftingManager，图标与背包共享同一 ItemIconRegistry。**
> 范围：session.inventories 数据模型 → 计数/落账 → 合成 → 图标 → 模块化 UI。
> 原则：UI 不碰 session 网格做业务判断；配置 → 业务（ItemManager/CraftingManager）→ 表现（图标服务/模块）；舰船与战斗两套 UI 体系各自装配。

---

### 一、数据模型：同层合并归一（★ 2026-09-10 重构）

```
旧：同层存在同 itemId 多堆（maxStack 裂格）→ 新增/移动按 maxStack 分堆
新：一格一类、数量无上限；同层插入即合并；跨层允许拆分（同 itemId 可同时在基地/飞船/玩家）
```
- `addItemToGrid`（Session.ts）：已有同类格 → 数量累加；无则占空格；无空格则失败。格子数 = 可容纳的**不同物品类型数**（容量语义保留：player 4×6 / ship 8×10 / base 30×30）。
- `moveItemBetweenGrids`：源拿取 → 目标合并；格子不足回滚。
- ★ `swapGridCells` / `ItemManager.swapCells`（2026-09-10）：**网格内自由整理**——同层拖拽两格交换；目标空 = 移动、两格同类 = 数量合并到目标（维持一格一类）。UI：`InventoryGridRenderer` 所有有物品的格子可拖（`text/x-grid`），目标格 drop 回调 `onCellDrop`（跨层仍走详情面板"转移"）。
- `hasSpace` 语义：该层已有该物品 → **恒有空间**；否则需空格。
- `mergeDuplicatesInGrid`（Session.ts）：旧存档迁移，加载时对三层各做一次重复堆合并求和（合并只会减少占用，安全）。

### 二、计数唯一入口（ItemManager）
```
countItem(layer, itemId)          // 单层数量
countTotal(itemId)                // ★ 基地＋飞船＋玩家 总数（加工台显示用）
hasItem(layer,itemId,count)       // = countItem ≥ count
hasSpace(layer,itemId,count)      // 已有同类 → 恒真；否则需空格
```
- 业务层（CraftingManager）与 UI（CraftingOverlay / CraftModule）一律经 ItemManager 计数，**不再直接遍历 session 网格**。
- 消耗 / 新增 / 跨层移动全部走 `ItemManager.addItem / removeItem / moveItem`（唯一碰网格的地方）。

### 三、合成：跨层扣料 + 模块化
```
canCraft(recipeId)         → 各材料 countTotal ≥ 需求
craft(recipeId, src, dst)  → 扣料顺序：基地 → 飞船 → 玩家；产出 addItem(dst)
maxCraftable(recipeId)     → min(⌊countTotal / count⌋)   （UI 不再自己算）
```
- 数量确认窗的"拥有 / 需要"均取**所有背包层总数**。
- 产出目标层已有同类 → 恒有空间；否则需空格，否则不扣料（不破坏数据）。

### 四、图标路径唯一化（★ 2026-09-10）
- `ItemIconRegistry.createIconElement(itemId)`：**唯一挂载出口**——静态（六兄弟/色块兜底）→ 独立 `<img>`(dataURL)；无人机 → 活动画布（翅膀动画经 DroneIconAnimator 播放，断连画布自动回收）。
- 背包与加工台 = 同一 UI 体系：**同一个** `ItemIconRegistry` 实例注入 InventoryGridRenderer 与 CraftModule。
- 战斗 = 另一套 UI 体系：WorldMode 不注入，背包网格内部自建注册表，互不干扰。
- 旧的"加工台 cloneIcon / 背包 toDataURL"双路径废除（`InventoryGridRenderer` 构造改可注入，缺省自建）。
- ★ 部署槽池图标同走该出口（2026-09-10）：无人机在出击槽里也是活动画布（翅膀持续抖动），不再是 `toDataURL` 随机帧快照。

### 五、加工模块 CraftModule（配方的基本单位 ★ 2026-09-10）
```
new CraftModule(recipe, deps: { craftingManager, itemManager, iconRegistry, host, onRequestOpen })
  mount(btn)      // 底图 + 输出图标/名字 + 材料图标(iconRegistry) + 拥有/需求(countTotal)
  refresh()       // 重查各材料拥有量，不足标红
  openQuantity()  // 本模块自管数量确认窗（挂 host；单开由宿主仲裁）
  dispose()       // 拆数量窗 + 清槽位 DOM
```
- **一个模块 = 一个配方**；UI 播放（图标、数量、点击、加工）全部封装在模块内部。
- CraftingOverlay 只做编排：6 槽位装配模块 / 单开仲裁（点 A 先关 B 窗）/ 背景 THREE + resize / 显隐销毁。

### 六、装配
```
ShipMode: 一个 ItemIconRegistry（★ 两处共用）
  ├→ ShipUIManager → InventoryPanel → InventoryGridRenderer(注入)
  └→ CraftingOverlay → CraftModule(注入)
WorldMode: 另一套 UI 体系，InventoryPanel 不注入 → 网格内部自建注册表
```

### 架构评价（现状）
- 合理：计数/落账单一入口；加工台零 session 依赖；图标一条路径；模块内聚、可增删配方即增删模块。
- 已知边界：`InventoryPanel` 网格**展示**仍直读 `session.inventories`（视图层，不做业务判断）；`countTotal` 每次全层遍历（网格小、调用频率低，无需优化）。

  - 每贴片独立素材（.ftx3），帧映射按 bbox 对齐；锚点 offsetX/offsetY / scale 按装备位配置定义；帧时间独立 loop。
  - ★ 子贴片**继承父贴片 billboard 朝向与翻转镜像**（父 scale 取反 → 子局部位置/缩放自动同步镜像），无需自转/手动翻转——不侵入播放器管线。
  - ★ 贴地剪影影子（2026-09-10）：每贴片惰性挂 `SilhouetteShadow`（与实体同款）——太阳解析投影 + 逐顶点贴地爬坡 + LOD/昼夜浓度；剪影随当前动画帧（按 data 引用去重）；世界宽/高按贴片世界缩放 + `rotateZ` 平面内旋转合成；宽轴取屏幕面内 X 轴的地面投影（含翻转镜像）。
- **出击槽池**：`session.player.slots: (string|null)[12]`（通用混用池，2×6 展示；友军/装备任意格里混放）。装备在槽即视为已穿戴（**同部位多件全量叠加**贴片）；可部署在槽即出队。旧存档自动迁移：`equips`(3) + `deployedAllies`(旧4) 并入前 7 格，旧字段删除。
- 放入/取出 = 背包拖入/拖出出击槽（`ItemManager.putIntoSlot / removeFromSlot`；一格一个，违规拒绝）；也可背包"使用"装备道具 → `effect 'equip'` → 自动放入首个空槽。
- 装配：`CombatItemController.syncLoadout()` 进入战场时 + 每 0.5s 定期 diff 同步（槽位变更 → 贴片及时刷新，未变零开销；无装备图素材时自动跳过）。

# 附：地图与 HUD 叠加层架构（★ 2026-09-15）

> 一行定位：**UI 层不持有实体、不遍历场景** —— 模式层每帧把需要的世界数据塞进
> `core/WorldUIState`，各叠加层只读这一份快照；图标形状与配色统一出自
> `services/ui/mapIcons.ts`，杜绝"小地图和大地图长得不一样"。

## 一、数据通道（唯一入口：WorldUIState）

- `WorldMode` 每帧构造 `WorldUIState` 喂给 `WorldUIManager.update(ctx)`；
  UI 层**不 import entity / scene**，只消费纯数据。现有字段：
  `playerPosition` / `cameraYaw` / `entities` / `playerStats` / `ammoEntries` /
  `allies` / `nearbyItem` / **`swarm`** / **`shipPosition`**。
- ★ **`swarm` = `SwarmSystem.pool` 的只读视图**（`{x, z, count}`），把 L2/L1 代理暴露给 UI。
  **铁律**：>35m 的敌人在代理池里，**不在 `EntityManager.bases`**。
  任何"显示敌人"的新 UI 必须**同时吃 `entities`（L3 实体）与 `swarm`（L2/L1 代理）** ——
  只吃前者就会出现"敌人一过 35m 就从地图上消失"（本次真实 bug，用户 2026-09-15 反馈）。
- `shipPosition`：舰船世界坐标；**不在当前场景时传 `null`**，消费方跳过绘制（不画错位图标）。
  2026-09-15 起还驱动**舰船独立开雾**与**舰船雷达敌情**（小地图/大地图消费），见 §六。
- 传引用不传副本：`swarm` 直接引池本体、`shipPosition` 直接引 `ShipEntity.position`
  → **零每帧分配**；起止一律以 `count` 为准（池是 swap-remove，尾部不代表有效）。

## 二、共享图标库 `services/ui/mapIcons.ts`（改图标只改这里）

四个纯函数元件（无状态、每帧直接调；同屏 ≤ 十几处，开销可忽略）：

| 元件 | 形态 |
|---|---|
| `drawPlayerArrow` | 白箭头 + 深色描边（`rot = π − yaw`） |
| `drawShipIcon` | 脉冲光环 + 双层菱形舰体 + 舰桥亮点（需求原话"要很显眼"） |
| `drawMarkerIcon` | 菱形 + 深描边，**颜色由调用方传** |
| `drawOffscreenIndicator` | 出窗贴到矩形边框的方位三角 + 距离数字 |

- 配色约束（用户 2026-09-15 定调）：`SHIP_COLOR='#66e0ff'` 青蓝**舰船独占**；
  `MARKER_PALETTE` 6 色（橙 / 亮黄 / 绿 / 品红 / 紫 / 朱橘）**禁蓝、禁灰白**
  （蓝给舰船、灰白留给玩家箭头与 UI），并避开敌人红 `#ff4444` / NPC 黄 `#ffd75e` 的主色相。
- ★ 发光**不用 `ctx.shadowBlur`** —— canvas 阴影是 per-draw 高开销路径（标记层每帧重画），
  改用"外圈半透明大图形 + 内圈实心"两层叠加：视觉等价、成本恒定。

## 三、三处消费（同一套形状、同一条方位公式）

| 消费方 | 文件 | 形态 |
|---|---|---|
| 小地图 | `services/ui/Minimap.ts` | 左上角方形画布：窗内画图标；出窗 → 贴到**内缩 6px** 的方框边 |
| 大地图 | `ui/world/MapPanel.ts` | M 键全屏面板：滚轮缩放 / 拖拽平移 / 回到玩家 / 标记点编辑 |
| 场景提示 | `services/ui/NavHints.ts` | 屏幕上的"方向箭头 + 名称 + 距离"文字行（DOM，行节点池化） |

- **方位角统一为一条公式**：世界角 θ → 画布旋转角 `rot = π − θ`（字形 0rad 指屏幕上方）。
  小地图 / 大地图 / 场景提示**共用这一条**，禁止各处再推导一次（三处各错一个方向是经典坑）。
- **出窗贴边算法**：`t = min(halfW/|dx|, halfH/|dz|)` → 三角放在射线与内框的交点；
  距离数字沿"指向中心"的反方向内缩 `t − 13/n`（**不是** `t×(n−13)/n`，后者在 t≈1 时才等价）。
- **滞回防闪**：舰船 >30m 才出场景提示、<24m 隐藏；标记 <6m 隐藏（贴着目标时不糊屏）。

## 四、标记点（`services/ui/MapMarkers.ts`）

- **单一实例**由 `WorldUIManager` 持有：`MapPanel` 写，`Minimap` / `NavHints` 读
  → 遍历 `readonly items`，不复制、不 map、不建临时对象。
- 颜色**存在数据项上**（`MapMarker.color`），不是画的时候现查 → 小地图 / 大地图 / 场景提示
  三处同色，一眼对得上。
- 上限 = **int max（永不顶掉旧标记）**；`add()` 满员返回 `null` 由调用方提示，
  **绝不静默丢弃**。沿革：初版 8 且满了 `shift()` 顶掉最早的 → 用户"标记太多之前的会直接消失"
  → 先改"满了不删、弹提示" → 再定调 int max。
- **单击 vs 拖拽平移**：按下→松手位移 < `DRAG_SLOP_PX(4px)` 才算单击（放置/删除），否则算平移。
  单击反算世界坐标必须用**上一帧 render 存下的** `lastX0/lastZ0/scale` ——
  用"实时中心"会因重绘节流（~8Hz）而漂移，出现"点这儿标那儿"。
- 删除 = 点中已有标记（屏幕半径 `MARKER_HIT_PX=16px` 换算成米）；
  「清除标记」走"再点一次确认"（一发误点删掉二十几个点，比多点一次难受得多）。

## 五、性能约定（都是踩过的）
