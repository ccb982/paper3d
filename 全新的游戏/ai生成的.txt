这套架构的核心是：每个 Chunk 内部是一个独立的“迷宫房间”，房间的出口（端口）位置由种子确定性决定，相邻房间通过端口自动拼接，形成无限延展的全局迷宫。

地图生成模块详细架构设计（分块迷宫版）
0. 核心设计哲学
局部生成，全局连通：每个 Chunk 只负责自己 15×15 格，但通过边界端口协议保证跨块连通。

确定性（Deterministic）：给定 (seed, chunkX, chunkZ)，永远生成同一迷宫。无需存储邻块数据。

迷宫优先：先用生成树画“路”，剩余区域再填水/坑/高台。路一定是连通的。

1. 数据模型（每个 Chunk 的内存表示）
typescript
// 地块基础数据（15x15）
enum TileType {
  ROAD = 0,      // 平地/路（可通行）
  WATER = 1,     // 水域（不可通行，阻挡）
  PIT = 2,       // 坑洞（不可通行，掉落死亡）
  PLATFORM = 3,  // 高台（可通行，但比路高）
}

interface Tile {
  type: TileType;
  height: number;  // 绝对高度（米）
  isWalkable: boolean; // 由 type 派生
}

// Chunk 完整数据
interface ChunkMazeData {
  tiles: Tile[][];      // [row][col]
  ports: {
    top: number[];      // 上边界出口的列索引（如 [3, 10]）
    bottom: number[];
    left: number[];
    right: number[];
  };
  seed: number;
  chunkX: number;
  chunkZ: number;
}
2. 生成流水线（5 个阶段）
阶段 0：种子与端口派生（边界协议）
目标：为当前 Chunk 确定 4 条边上的出口位置，这些位置必须与相邻 Chunk 严格对齐。

算法（确定性哈希）：

text
对每条边（上/下/左/右），取派生种子：
  边种子 = hash(全局种子, chunkX, chunkZ, 边方向)

在该边上生成 2 个出口位置（1~13 之间，不能贴角 0 或 14）：
  出口1 = (hash(边种子, 0) % 11) + 2
  出口2 = (hash(边种子, 1) % 11) + 2
  确保出口1 != 出口2，且间隔 ≥ 3（防止两个出口黏连）
关键对称性保证：

Chunk (cx, cz) 的 右边界 出口列表，与 Chunk (cx+1, cz) 的 左边界 出口列表，必须完全相同。

这通过让 右边界种子 = hash(cx, cz, 'right') 与 左边界种子 = hash(cx+1, cz, 'left') 使用同一套哈希逻辑实现（实际编码时，直接用 (cx+1, cz, 'left') 的派生值作为当前块的 right 值）。

结果：跨块时，路是“无缝”的，玩家不会遇到断头路。

阶段 1：生成树（迷宫骨架）—— Wilson 随机游走
目标：在 15×15 网格上生成一棵 连通所有格子的生成树，且所有边界出口都是树的节点（强制在树中）。

数据准备：

将 15×15 网格看作 225 个顶点。

将 4 条边上的 8 个出口格子（每条边 2 个）标记为 “根节点集合”。

Wilson 算法步骤（保证均匀随机生成树）：

从所有根节点集合中随机选一个作为“已访问集合”。

随机选一个未访问节点，开始做 随机游走（上下左右随机走，不走回头路），直到撞到已访问集合。

将这条游走路径加入已访问集合（路径上的边成为树的边）。

重复，直到所有 225 个节点都被访问。

结果：225 个节点通过 224 条边连成树。

为什么不用 DFS 递归回溯？ Wilson 生成的树更随机，分支更均匀，不会出现“长直走廊”和“贴着墙的单一主干道”，更接近自然迷宫。

阶段 2：走廊加宽（可选，增加战斗空间）
目标：将部分“窄路”（1 格宽）拓宽为“宽路”（2 格宽），提升战斗体验，同时保持迷宫感。

策略：

遍历所有度数 ≤ 2 的节点（即纯通道节点），以 20% 概率 将其相邻的某个非树格子（墙）征用为平地。

征用时确保不破坏树结构（不切断路径）。

最多额外增加 10%~15% 的平地面积。

阶段 3：地形分类（墙区分配）
此时：网格中约有 50%~55% 的格子是树（平地/路），其余 45%~50% 是“墙区”（未选入树的格子）。

将墙区按比例分配为水域/坑洞/高台/死路平地：

地形	目标占比（占全 Chunk）	放置策略
水域（WATER）	30%	在墙区中随机选取 连通块，用 BFS 生长成片（3~8 格连续），形成湖泊。
坑洞（PIT）	30%	在剩余墙区中随机撒点（单个或双格），不相连，像陷阱。
高台（PLATFORM）	20%	选取紧挨着树（路）的墙区格子，将其拔高。每个高台 1~2 格，分散放置。
死路平地（ROAD）	20%	剩余的墙区格子直接降级为平地（ROAD），但不与主树相连（作为视觉死胡同）。
分配约束：

水域和坑洞绝不能占用边界出口格子（边界出口强制为 ROAD）。

高台不能放在坑洞/水上。

阶段 4：局部连通性快检（兜底修复）
虽然生成树保证了“树内所有格子连通”，但阶段 3 加宽走廊时，可能不小心把某个边界出口或关键节点给覆盖成了水域/坑洞。

修复方案（极快）：

从所有 8 个边界出口格子开始 BFS。

只走 isWalkable = true 的格子（ROAD + PLATFORM）。

如果有任何一个 树节点（原本属于生成树的格子） 未被访问，说明它被意外堵死了。

将该节点强制恢复为 ROAD（如果上面有高台则降级，有水/坑则填平）。

重复 1~2 次即可收敛（最多改动 1~2 格）。

阶段 5：高度分配（绝对平整）
地块内绝对平坦，地块间有台阶差。

类型	基准高度（米）	随机扰动
边界出口（ROAD）	0.0	无扰动（保证跨块顺滑）
内部普通路（ROAD）	0.0	-0.1 ~ +0.3
死路平地（ROAD）	0.0	-0.1 ~ +0.3
高台（PLATFORM）	1.8	0.0 ~ +0.4
水域（WATER）	-0.5	无扰动
坑洞（PIT）	-3.0	无扰动
3. 跨 Chunk 全局连通性证明（数学保证）
块内：生成树连接了所有 ROAD 和 PLATFORM，且至少连接到 8 个边界出口。

块间：

Chunk A 的右边界出口 (14, y) 与 Chunk B 的左边界出口 (0, y) 坐标严格一致（由阶段 0 的对称哈希保证）。

因为两边都是 ROAD，且都连通到各自的生成树，所以 A 内任意点 → A 树 → A 右出口 → B 左出口 → B 树 → B 内任意点 路径恒成立。

归纳：无限网格上的所有 Chunk 通过这种“端口握手”形成一个无限连通图。

4. 确定性详解（保证复现）
全局种子：day（来自 Session）。

每个 Chunk 的种子：chunkSeed = hash(globalSeed, chunkX, chunkZ)。

所有随机选择（出口位置、Wilson 游走方向、水域放置点、坑洞位置）全部基于该种子。

因此：(day, cx, cz) → 唯一结果，无需存储地形数据。
