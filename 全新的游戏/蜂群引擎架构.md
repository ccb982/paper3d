## 1. 全流程（数据流）

```
① 落地扫描 S0          地形特征 → 逐格特征向量（LandingTerrain）
② 态势函数             时间曲线 + 挑衅加成(衰减) → 攻势强度 p → 权重向量 w
③ 地块评分表           每格分 = w · 特征（TerrainScore；动态重建）
④ 大队（战术层）        从表取目标/集结/包抄走廊/偷袭位/工事点（SwarmCommander）
⑤ 小队（执行层）        同表不同解读（兵种投影）；命令分解（SquadTactics）
⑥ 个体（执行）          趋近高分格 + 命令原子（两层掷）+ 射击/掩体校验
⑦ 反馈闭环             击杀/被击/受阻 → 挑衅值/评级 → 回到 ②③
```

**四层正交**：编队归属（逻辑） × LOD 载体（表现） × 激活态（dormant/active） × 兵种角色。

## 2. 数据底座

### 2.1 地形特征（逐格；`LandingTerrain` 扫描产出）✅

| 特征 | 来源 | 用途 |
|---|---|---|
| `h` 绝对高度 | `raster.surfaceHeightAt` | 制高（高地分/远程射界） |
| `d_ship` 距玩家舰船 | 扫描中心 | 态势距离项（权重随 p 变化） |
| `walkable` 可站性 | 坑/深水/过低/陡升（只挡爬升） | 阻挡/软代价 |
| `width` 通行宽度 | 多源 BFS 距离变换 | 大队 vs 单体通行 |
| `post` 掩体/制高 | coverSlots（贴真实遮挡）+ highGround | 驻守/施工优先 |
| `choke` 隘口 | 宽度 ≤8m 收缩段 | 盾兵守点 |

### 2.2 评分表 `TerrainScore`（★ 4m 格、半径 144m ≈ 5.3k 格）✅

- 网格与**地形块/挖掘同源**（1 格 = 1 块），寻路可直接消费格级代价。
- 每格分 = `w.h×h + w.dist×d_ship + w.cover×post加成 − 近舰负分`，不可站格 = −∞。
- **更新策略**：换落点/态势 → 全量重建（触发戳 = 落点版本 + 态势代次）；
  **建成掩体 / 挖掘（战壕/坑）→ 局部重算** `invalidateArea(x,z,r)`（脏窗 + 邻环，
  因坡面/墙面/战壕都依赖邻格高差）。
- 消费 API：`scoreAt`、`bestNear`、`isReady`、`clsAt/blockedAt/costAt`、`isTrenchAt`。

---

**总纲（表即战场）**：`TerrainScore` 表是全敌共享的**唯一战场视图**——态势函数（`p`）驱动表的权重，
蜂群引擎在表上选集结点/进攻轴/阵地，敌人个体读**同一张表**落位与决策。
任何新战术都必须表达为"对表的读法"（过滤+重加权投影），**不允许**另开一套平行逻辑。

### 2.3 平滑与梯度 ∇S̃（局部微调 / 选点辅助 / 可视化）⏳ M3

- **平滑**：`S̃ = 1~2 次 3×3 均值滤波(S)`；**原始 S 保留**给 argmax/阈值（防掩体跳变被抹平）。
- **梯度**：`gradAt(x,z)` = 中心差分并归一化；带**死区 + 迟滞 + 限步长**，2~5Hz 或表重建时同算。
- **分工（硬约束）**：
  | 用途 | 用谁 |
  |---|---|
  | 长距找玩家/舰船、绕大障碍 | HPA\* / corridor（全局，**不准用梯度**） |
  | 队形槽位落位 | `bestNear`（非局部 argmax，不怕局部极值） |
  | 站位/施工点微调、集结点漂移 | **∇S̃**（小步长） |
  | 集结点与平台区（\|∇S̃\| 小 + S 高） | ∇S̃ 派生量 |
  | 换位触发线 / 掩体边缘（\|∇S̃\| 大） | ∇S̃ 派生量 |
  | 调试 | 热力图 + 箭头（`?swarmdbg`） |
- 成本 O(N)（≈5.3k 格；全量一次性，局部重算只算脏窗），与评分表同触发重建。

### 2.4 ★ 统一地形采样缓存（联动省开销）⏳ M3

**问题**：同一片地形被采样多次——`LandingTerrain` 扫描、HPA 簇构建、评分表、流场窗口
（实测瓶颈就是 `surfaceHeightAt/tileDefAt` 采样，HPA 单簇 ~0.7ms）。

**方案**：一层 `TerrainSampler`（`services/map/`，全局唯一），按**世界格坐标**记忆化：

```
sample(gx, gz) -> { h, role, pass }        // 首次真采样，之后命中缓存
version(chunkKey)                          // 挖坑/地形重建 → 该 chunk 版本 +1，相关格失效
```

- **HPA 簇**：簇的 `h/pass` 数组改为从 sampler 填（不再直接打 raster）。
- **评分表 TerrainScore**：4m 格 = 与 sampler **同网格（1:1，零聚合）**，高度/role 直接读缓存。
- **LandingTerrain 扫描 / 流场窗口**：逐步切到同一缓存（流场自带的窗口缓存后续合并）。
- **失效纪律**：以 chunk 版本戳为准（挖坑/重建/卸载）；LRU 控制容量。
- 收益：同域一次采样多处复用；HPA 冷启动与换落点重扫的主要成本直接砍掉。

---


- 成本：全量 O(5.3k 格)（一次性，换落点/态势）；局部重算只算脏窗（挖掘/掩体每块 ~几百格）。

### 2.5 ★ 通行分类 / 战壕 / 动态障碍分层 ✅（表侧已实现）

| 层 | 内容 | 归属 |
|---|---|---|
| **静态地形（进表）** | 高度、可站、**坡面(cls1 减速)**、**墙面(cls2 硬边界)**、**坑洞水域(cls3 硬边界)** | `TerrainScore` ✅ |
| **战壕（进表）** | **显式挖掘标记格直接算**（`digRect` 一次 +1 层 ≈0.2m）；未标记的自然低洼（低于邻域 ≥0.6m）也算；给掩体加成 | `TerrainScore` ✅ |
| **挖掘（写表）** | 战后/施工挖改 → `invalidateArea` 局部重算；模式层任意挖改调 `commander.markTerrainDirty(x,z,r)` | ⏳ 模式层接线 |
| **动态障碍（不进表）** | 实体/掩体/单位占位 → 独立模块 `BlockerLayer`，寻路/移动查询时叠加 | ⏳ M4 |

- cls 阈值（4m 邻格）：坡面高差 >1.5m、墙面 >3.0m；`costAt` 坡面 ×1.6、硬边界 = ∞。
- 寻路消费（⏳ M3）：SquadPath/HPA 把「硬边界」当不可进、坡面当代价倍率；**8m/4m 粒度争议已消**——表就是 4m。
- **战壕偏好（✅ 已接）**：① 远程——在「理想站位 ±6m」射程环带内取最高分战壕，直接入壕（`rangedPost` 早退）；
  ② 全兵种——驻守/集结类目标（`protect/regroup`）≤8m 内自动吸附到战壕格；
  ③ 驻守点清单（`garrisonCovers`）把前线附近战壕并入候选；④ 远程候选普遍 +2.0 战壕基础分。
- 动态障碍不进表的理由：表是低频事件重建的静态真源；单位/掩体每帧变，混进来会逼表高频重算。

## 3. 态势函数（v3 核心）

### 3.1 攻势强度

```
p = clamp( schedule(t) + provocation(t), 0, 1 )
```

- **时间强影响（主导）**：`schedule(t)` = 当日节律曲线 × 天数档位（可预测、好调）。
- **玩家进攻附加影响（次要，自然衰减）**：
  ```
  P += 事件权重（我方被击杀/被击/工事被拆/核心区被侦察）
  P *= exp(-dt/τ)          // τ = 半衰衰减时间常数（60~120s）
  provocation = min(PMAX, P) × K   // 额外推进 ≤ 0.35
  ```
- **迟滞**：上升快、回落慢（不同时间常数），避免一枪全场变阵。
- ✅ 现状：`Posture` 是离散档位 + 固定转移条件（contact/builtRatio/aliveRatio）；
  ⏳ M2 改为连续 p（`schedule + provocation` 衰减）+ 档位仅作日志。

### 3.2 时间曲线（建议默认，可调）

| 时段 | p | 行为 |
|---|---|---|
| 出击 0~25% | 0.05~0.2 | 施工 + 巡逻（近舰负分，往外展开） |
| 25~50% | 0.2~0.45 | 试探推进 |
| 50~75% | 0.45~0.7 | 集结、火力压制 |
| 75~100% | 0.7~1.0 | 总攻（一旦进入**锁定**，只受 withdraw 安全阀影响） |
| 换日 | 档位整体上移 | 天数 = 强度基线 |

### 3.3 姿态与权重

- 档位：`fortify / patrol / advance / mass / assault / withdraw`（withdraw 独立安全阀，伤亡比触发）。
- 权重表 `PHASE_WEIGHTS`（h/dist/cover/near）✅：前期 `dist` 小 + 近舰负分；
  **总攻 `dist=-0.35` 猛加（越近越高分 → 压向舰船）**；撤退 `dist=+0.25`。
- ⏳ 相邻档位权重**线性插值**（姿态切换不再跳变）。

## 3.4 ★ 权重系数怎么算（全部归一化到 0~1，量纲统一）

**特征（逐格；扫描时一次算好）**

| 特征 | 公式 | 说明 |
|---|---|---|
| `H` 高度 | `(h − h_min) / max(1, h_max − h_min)`（扫描域内极值；域内高差 <1m → 0.5） | 绝对高度归一 |
| `D` 舰距 | `d_ship / R`（R=144） | 越远越大 |
| `T` 威胁距 | `d_player / R` | 到玩家（威胁）的距离归一 |
| `C` 掩体/制高 | `min(1, 1.0·已建掩体 + 0.6·规划掩体位 + 0.4·高地)` | 造好掩体即吃满 |
| `W` 通行宽度 | `min(1, width_cells / 4)`（到最近阻挡格距离变换） | 大队通行能力 |
| `K` 隘口 | `1`（宽度 ≤1 格且前后变宽）/ 否则 0 | 盾兵守点 |
| `N` 近舰 | `clamp((30 − d_ship)/30, 0, 1)` | 只在前期惩罚 |
| 阻挡格 | `S = −∞`（坑/深水/过低） | 一律不可选 |

**总评分（逐格）**

```
S = wh·H + wd·D + wt·T + wc·C + ww·W + wk·K − wn·N
```

**权重 = 态势强度 p 的分段线性插值**（锚点见下表；`wd/wt` 正 = 偏好远）：

| p | 姿态 | wh | wd(舰距) | wt(威胁距) | wc | ww | wk | wn(近舰) |
|---|---|---|---|---|---|---|---|---|
| 0.05 | fortify | 0.50 | **+0.10** | 0.00 | 0.80 | 0.05 | 0.20 | **0.80** |
| 0.25 | patrol | 0.50 | **+0.12** | 0.00 | 0.80 | 0.10 | 0.30 | **0.60** |
| 0.45 | advance | 0.45 | +0.02 | −0.05 | 0.70 | 0.25 | 0.20 | 0 |
| 0.65 | mass | 0.35 | −0.10 | −0.10 | 0.60 | 0.35 | 0.10 | 0 |
| 0.90 | assault | 0.30 | **−0.40** | −0.15 | 0.50 | 0.40 | 0.05 | 0 |
| withdraw | 安全阀 | 0.45 | +0.30 | **+0.60** | 0.90 | 0.20 | 0.10 | 0 |

- 相邻锚点线性插值（p 变 → 权重连续变，姿态不跳变）。
- 量级口径：H/D/T/C/W/K ∈ [0,1]，权重 ≤0.8 → 单项贡献 ≤0.8；总 S 约 [−1.2, +2.5]。
- `wd` 的符号就是**阶段语义**：前期正（往外展开）+ 近舰惩罚；**总攻转负且猛加（压向舰船）**；
  `wt` 总攻小幅负（压向玩家）、撤退大幅正（远离玩家）。

## 3.5 ★ 单日节律 schedule(t)（每天 1~2 波 + 总攻）

`t = 当日进度 0~1`（T_day 内流逝）；**schedule(t) 是态势的主导输入**，挑衅只是提前量：

| 时段 | 进度 | 增兵 | 行为（姿态） |
|---|---|---|---|
| 扎根 | 0~0.15 | **少量**（~10-15% 基数：后勤 + 2~3 近战） | 后勤修工事、近战守线、飞行待命（fortify） |
| 集结 | 0.15~0.40 | 渐进补兵 → **补齐一个基数** | 工事前推、巡逻侦察（fortify→patrol） |
| **第一波** | 0.40~0.55 | **大量增兵**（+~50% 基数） | advance→mass 主动进攻；**打残（损 25%）→ withdraw 回防** |
| 再集结 | 0.55~0.75 | 持续增兵 + 工事继续前推 | 防御修复 → patrol 再试探（provocation 累计） |
| **总攻** | 0.75~1.0 | **大量增兵**（满编/额外额度） | assault：全力以赴、施工停、盾也压上（schedule≥0.8） |
| **入夜** | 1.0（时间独立） | 停增（不再补充） | 总攻持续到被清完 |

> **时间独立走势**：当日结束只看**时钟**，与歼灭数量无关；临近晚上（schedule→0.80）总攻，
> 到点入夜仍未肃清 → **惩罚**（⏳ 夜晚惩罚 M5+，模式层施加：强制白天活动、入夜必须撤离）。
> 无"收尾"档：入夜后敌群保持 assault，打到被清完为止；肃清与否只结算当日战绩。

**schedule(t) 锚点**：0.10 @0.10 · 0.25 @0.30 · **0.45 @0.45（第一波）** · 0.60 @0.65 · **0.90 @0.80（总攻）** · 1.0 @1.0（分段线性）。

**姿态判定**（取代纯时间兜底）：
```
p = clamp(schedule(t) + provocation, 0, 1)
assault ⟸ p ≥ 0.80 或 累计损失 ≥ 25%
```

**与账本/闸门的接线**（每天重置）：
- `baseQuota` = 当天基数（难度系数 × 上限基数）；`ledger.total` 每天按 **两次波峰**扩容：
  曲线 = `baseQuota × (0.15 → 1.0 渐增 → 波峰1 ×1.5 @0.45 → 回落 → 波峰2/满编 @0.80)`。
- 生成闸门沿用 `spawned − recalled − removed < total`（引擎直管账本，不新增计数）。
- **参数口径（拍板）**：`T_day` = **沿用现有昼夜时长**（WorldMode 日程，M2 直接读现有 day 配置）；
  `baseQuota` = **≈30 人（一个排的抽象，非硬性；允许 ±浮动）**，兵种/火力配比**沿用既有大队编制**（11 兵种分配表）；
  **可附加精英/Boss**（Boss `swarmUid=0` 不入账本，属附加单位，不占基数）；
  第一波 ×1.5 ≈ **45**、总攻按**满编基数**扩容。
- **撤退安全阀**（波内）：loss ≥25% → withdraw 30s → 防御修复 → patrol 再集结；
  总攻内 loss ≥60% → withdraw（已实现的 `aliveRatio<0.4` 基准在进总攻时重置）。

**实现落点**（✅ M2 已接线）：`SwarmCommander` 读 `dayT01`（WorldMode 从太阳钟 `renderManager.querySun().hour` 换算：
6:00=0 / 18:00=1）；**节奏口径 = 从落地起算、黄昏到 1**（落地即黄昏/夜晚 → 直接满节奏）；
挑衅 = 被击（`recentHits` 差分 ×0.01）+ 击杀（账本差分 ×0.03/人），指数衰减在 `PostureFn` 内；
增兵 = 开局班底 8（后勤/盾/突击/远程）+ 基数大队滴灌 + 第一波（t01≥0.45）与总攻（t01≥0.80）各增一个大队；
**兵力放行** = 账本 `releaseCap = total × releaseAt(t01)`（0.20→0.50→0.75→0.95→1.00，早间只放少量；
`canSpawn/remaining` 取 `min(total, releaseCap)`，导演补怪/环境怪同受闸门约束）；
`?swarmdbg` 面板显示 `态势 / p / 日程 / 挑衅`；调试可用 `commander.debugDayT01 = 0~1` 拨动日程。

**进攻队列（BattleLine）定调（2026-09-21 用户）**：线位只是"刚整队那一拍"的**短暂队形调整命令**
（TTL 3s，`update` 返回是否刚整队），且**只对非攻击（chase=false）小队生效**——
正在攻击的队始终执行攻击目标（追玩家/推进），**队列调整不得影响攻击**（此前每拍强推线位 → 敌人排队不总攻）。
**队列成员（2026-09-21 用户）**：只整**近战进攻队**（盾/突击/混编）；**施工队、后勤、远程不整队**（各有工位/射界位）。



## 4.1 ★ 兵种怎么消费这张表（同一张 S，不同投影）

每个兵种 = **一次过滤 + 重加权**（都在 `bestNear/argmax` 之上，扫描半径/带位不同）：

| 兵种 | 投影公式（在 S 上再加权） | 选择范围 |
|---|---|---|
| 盾 | `S_shield = S + 0.6K + 0.3W − 0.2·|d_front|/R` | 前线 40m 内（正面/隘口） |
| 突击 | `S_assault = S + 0.5·(1−T)` | 沿推进轴走廊，接受低掩体 |
| 远程 | `S_ranged = S + 0.8C − 0.5·|d_player − 0.8R|/R`（另做 LOS 真挡弹校验） | 玩家射程带 [0.5R,1.05R] |
| 工程 | `S_eng = 0.6S + 0.4C − 0.3·|d_ship − 60|/60` | 施工环带 ≈60m |
| 后勤 | `S_log = S − 0.8·(1 − D_front)`（`D_front`=到前线归一距） | 前线后方 ≥20m |
| 飞行 | 不读表（独立空中层，只读目标） | — |

- 投影是**纯函数**（同一张 S，可各自调系数）；远程的 kite 换位 = 在 `S_ranged` 里取"更远+掩体"的次优极点。
- 施工是**写表**：工程兵在 `S_eng` 高位造掩体 → `C` 提升 → 表重建 → 远程/盾/后勤立刻"看见"新有利位置。

## 4.2 ★ 大队 / 小队也读表

**大队（引擎，2s 决策拍 + 态势变化即拍）**
| 决策 | 读表方式 |
|---|---|
| 集结点（mass） | `argmax S` 于环带 [60,90]m × 来向 ±60° |
| 主攻轴 / 走廊 | 对每条 HPA corridor 取 ±20m 带内 `mean(S_assault)`，取最大 |
| 包抄/偷袭出发位 | 侧向走廊（±60°~±90°）内 `argmax S`（低 T、高 C） |
| 隘口分配 | `argmax K`（配 `S_shield` 排序）→ 盾队一一对应 |
| 施工清单 | `top-N S_eng` 沿环排序 → `buildPieces` 顺序 |
| 撤退点 | `argmax (0.5H + 0.6T + 0.9C)`（远离玩家） |
| 兵力配比 | 各兵种投影的**最优格评分均值** → 该方向值不值得派（低分方向减兵） |

**小队（执行层，5~10Hz）**
- 小队的部署 mode（screen/flank/garrison/build/regroup/press）→ 选对应投影；
- 队长把**队形槽位锚点**微调：每个槽位取其 3m 邻域内最高分格（`bestNear(slot, 3)`），
  实现"阵型不变但每个兵踩在更有利的位置"；
- 交战中持续校验：站位分下降（玩家逼近/掩体被拆）→ 触发换位（局部重取投影极点）。

## 10. 验收清单（M4 实机）

1. 前期不挤船、往外施工/巡逻；玩家不进攻时节奏只随时间走。
2. 玩家猛攻 → 攻势显著提前（≤2 档 / p +0.35），停手 1~2 分钟回落到时间基线。
3. 总攻压向舰船；进入总攻后不因挑衅衰减退出（只 withdraw 安全阀）。
4. 各兵种站位可区分（盾前 / 突击两翼 / 远程掩体后射程环 / 工程高分格施工 / 后勤后置）。
5. 远程不追打：掩体真挡弹校验通过后持续射击，玩家逼近先换更优位再打。
6. 帧率：`?enemies=200` 下蜂群预算 ≤4ms，无尖刺（HPA 预热摊帧）。
