## 0. 一句话

**精修层定型后，per-chunk 一次性构建 BlockFaceIndex（块级面信息 + cornerH + 原墙缓冲），
挂在 RasterMap 缓存；后处理四路（顶面、侧壁、调试、贴地单点）全从同一索引取数据——
构建只跑一次，各处 O(1) 复读，重复查询归零。**

---

## 1. 数据流（目标）

```
RasterMap（per-chunk 缓存主人）
  chunkSourceCache（已有，BlockSource）
  blockIndexCache（新增，BlockFaceIndexBundle）      ← 一次构建
       │  buildBlockFaceIndex(src, cx, cz, cornerH, wallBuffers)
       │  = BlockFaceIndex{ cells(225), cornerH(ref), wallBuffers(ref) }
       ▼
ChunkManager.finishStandardChunk(cx, cz)
  │  idx = raster.blockFaceIndex(cx, cz)      ← 惰性构建 / 命中缓存
  ├── buildPostChunkTopSurface(raster, cx, cz, idx)
  │       用 idx.cornerH（不再自己 buildChunkFinal）
  │       用 idx 判 bevel/pit/crack（不再逐点 blockAt/finalRuling）
  ├── buildPostSideWalls(raster, cx, cz, ..., idx)
  │       用 idx.wallRef（不再遍历全量 quad 反推）
  │       用 idx 判 isBevelEdge/侧壁扩散（不再逐边 blockAt）
  │       重建结果为新的 wallBuffers（写回 idx.wallBuffers 给物理/渲染）
  └── buildBevelWallDebug(raster, cx, cz, idx)   ← 同用

运行期（任意坐标）
  postSurfaceHeightAt(raster, x, z)
  │  ccx,ccz → raster.blockFaceIndex(ccx,ccz)   ← 命中缓存（构建过的 chunk）
  │  → idx.cornerHAt(x,z) + ppOffset            （后续可全面走索引）
```

## 2. 缓存结构（RasterMap 新增）

```ts
class RasterMap {
  /** 新增：per-chunk 地块面索引缓存（chunkKey → Bundle） */
  private blockIndexCache = new Map<number, BlockFaceIndexBundle>();

  /** 惰性构建 / 取索引。一次构建，顶面/侧壁/调试/单点全复用。 */
  blockFaceIndex(cx: number, cz: number): BlockFaceIndexBundle {
    const key = chunkKeyOf(cx, cz);
    let b = this.blockIndexCache.get(key);
    if (!b) {
      b = buildBundle(this, cx, cz);       // 见下
      this.blockIndexCache.set(key, b);
    }
    return b;
  }
}

// Bundle：一个 chunk 的地块面索引 + 精修层产物引用
interface BlockFaceIndexBundle {
  index: BlockFaceIndex;       // §1 的数据结构
  cornerH: Float32Array;       // 引用 buildChunkFinal 产物（顶面/贴地基底）
  wallBuffers: ChunkWallBuffers; // 原墙缓冲（侧壁重建后写回同一引用）
  src: BlockSource;            // 精修源（跨 chunk 邻居下钻用）
}
```

**构建一次省一次**：原来 buildPostChunkTopSurface 与 buildPostSideWalls 各跑
一次 `buildChunkFinal` / `buildChunkWallBuffers`；现在 Bundle 构建时只跑一次，
顶面/侧壁/调试都复用同一产物。

## 3. 各函数改写点

### 3.1 buildPostChunkTopSurface（顶面）

| 现在 | 改后 |
|---|---|
| `const finalTerrain = buildChunkFinal(src,cx,cz,N)` | 用 `idx.cornerH`（引用，不重算） |
| `cellViewBlock` + `cornerCell` 逐角 | 用 `idx.cornerHAt`（米格 4 角 O(1)） |
| `bevelOffset` 逐点扫 4 边 `blockAt`+`finalRuling` | 用 `idx` （`sides[dir].ruling/.drop/.isBevel` 预存） |
| `nearInterpOrPlatform` 逐点查 8 邻 | 用 `idx`（邻块 `role`+`sides[dir].ruling` 预存） |
| `crackOffset` 5×5 扫锚块 | 用 `idx` 预建裂隙表（待做，见 §5） |
| `buildChunkFinal` 的 finalTerrain 透传 | indexBundle 已含 cornerH；透传路径保留 |

**改动本质**：把"每采样点判定块属性"换成"读 idx 已算好的块属性 + 高度"。采样点仍要做
连续距离计算（dMin/along/perp），但**块属性查询归零**。

### 3.2 buildPostSideWalls（侧壁）

| 现在 | 改后 |
|---|---|
| `buildChunkWallBuffers(src,...)` | 用 `idx.wallBuffers`（引用，不重算） |
| 收集弧边侧壁 `src.blockAt`+`isBevelEdge` | 用 `idx.at().sides[dir].isBevel` |
| 识别被剔除 quad 用 `buffers.uvs` 反推 | 用 `idx.at().sides[dir].wallRef` 定位 |
| 侧壁扩散（邻居高台判定）`src.blockAt(nb).role` | 用 `idx.at(nbLocal)`（跨界走 bundle 邻居下钻） |
| 重建写回 `buffers.vertices` 等 | 同一 `idx.wallBuffers` 引用，物理/渲染取同源 |

### 3.3 postSurfaceHeightAt（贴地单点）

- 命中 `raster.blockFaceIndex(ccx,ccz)` 缓存 → 若构建过，用 `idx.cornerHAt`；
- 未构建（单点先于 chunk 网格）→ 回落当前 `src.chunkSource` + cornerCell 现查（兜底）。
- 保持不变式：渲染=查询同源（都是同一 cornerH + 同一 ppOffset）。

### 3.4 buildBevelWallDebug

- 用 `idx` 的 `sides[dir].isBevel` 画弧边记号，不再独立 `isBevelEdge` 现查。

## 4. 跨 chunk 邻居查询协议

BlockFaceIndex 只覆盖本 chunk 15×15。后处理需要研究邻居块（bevel 判定、侧壁扩散、
裂缝锚块）时：

```
idxNeighbor(wbx, wbz, dir):
  目标块世界 (nbx,nbz) = 本块 + dir 偏移
  → 算其所在 chunk (ccx,ccz)
  → raster.blockFaceIndex(ccx,ccz)   // 惰性构建邻居（或 chained cache）
  → 其 atWorld(nbx,nbz) / sideAt
```

- 构建期的邻居下钻：邻居 chunk 若已构建（同批新增）→ 直接；否则可惰性构建（成本同
  一个纯 buildBundle，可能触发邻居精修产物——可接受，因为本来就要加载）。
- **为避免构建期连锁下钻太深**：只下钻 1 层邻居的块元数据（role/ruling/drop）即可，
  墙缓冲只读本 chunk。bevel/侧壁扩散只需邻居的块属性，不需要邻居墙缓冲。

## 9. 风险 / 注意

- **cross-chunk 下钻**成本：只下钻邻居块元数据（1 层），不下钻墙缓冲。
- **buffers 共享写**：侧壁重建写回 idx.wallBuffers，物理/渲染同取——需保证单点查询
  不依赖被改的 buffers（单点用 cornerH，安全）。
- **clearAll / chunk 卸载**：blockIndexCache 与 chunkSourceCache 同步清理。
