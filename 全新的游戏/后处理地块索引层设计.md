# 地块面索引层（BlockFaceIndex）设计

> 状态：设计稿（2026-09-04）。精修层输出时构建 per-chunk 的**地块面级粗信息数组**，
> 供后处理(bevel/crack/pit/侧壁)与运行时(地面交互/材质替换)统一查询。
> 索引不存几何顶点，只存面级元信息（角色/高度/裁决/落差/材质）。

---

## 0. 一句话

**精修层定型后，为每个 chunk 构建一份「地块面数据库」——每个地块的顶面 + 四侧面 + 底面的
粗信息（角色、高度、裁决、落差、材质 ID）+ 面索引（定位对应的墙 quad 区间 / 顶面格坐标），
后处理从库里读取而不现查现算；运行时对地面交互时通过索引定位面，替换材质 ID 为
流体残差纹理，持久化存盘。**

---

## 1. 为什么是平铺数组而非八叉树

地块是**规则 4m×4m 网格**，chunk 是**固定 60m×60m**，空间均匀、坐标整数、密度固定：
- 八叉树为不规则 / 可变密度设计，这里多一层无用的树寻址。
- **平铺数组 + 直接下标**：块坐标 → 数组偏移 O(1)，邻居 = ±1 偏移。

> 结论：不用八叉树。用平铺 `BlockFaceEntry[]`（BPS×BPS = 15×15）。

---

## 2. 数据结构

### 2.1 单个地块面信息

```ts
/**
 * 一个地块的 6 个面的粗信息。
 * 索引存在 `BlockFaceEntry` 数组中，按块局部坐标平铺。
 */
interface BlockFaceEntry {
  // ---- 块本体 ----
  id: number;                  // TileDef.id（材质/类型判别）
  h: number;                   // 块逻辑高（裁决/邻块判定用）
  hBase: number;               // 实体面板底高（补墙/悬空/侵蚀用）
  role: TileGenRole | "";       // genRole 缓存（免每次 tileById）

  // ---- 顶面 ----
  top: {
    /** 顶面 4 角的视觉面高度（= cornerCell，后处理 yAt 基底） */
    cornerH: [number, number, number, number]; // c00, c10, c11, c01
    /** 顶面当前材质 ID（默认 = 地块原始材质；运行时可替换为流体残差等） */
    materialId: number;
  };

  // ---- 四侧面 (dir: 0=+x, 1=-x, 2=+z, 3=-z) ----
  sides: [FaceSide, FaceSide, FaceSide, FaceSide];

  // ---- 底面 ----
  bottom: { hBase: number; materialId: number };
}

/**
 * 单侧面信息
 */
interface FaceSide {
  /** 裁决：cliff(硬边界) / weld(插值坡) */
  ruling: EdgeRuling;
  /** 与邻居块的落差（高侧 - 低侧，≥ 0） */
  drop: number;
  /** 邻居块在数组中的索引（用于快速邻块查询） */
  neighborIdx: number | null; // null = 边界（无邻居）或缺块
  /** 该面当前材质 ID（默认 = 地块侧面材质；运行时可替换） */
  materialId: number;
  /** 原墙 quad 的索引区间（用于后处理侧壁剔除/重建） */
  wallRef: { idxStart: number; quadCount: number } | null;
}
```

### 2.2 per-chunk 索引容器

```ts
/**
 * 一个 chunk 的完整地块面索引。
 * 构建一次，后处理和运行时统一读取。
 */
class BlockFaceIndex {
  /** 块数/边 = 15（60m / 4m） */
  readonly BPS: number;
  /** 平铺数组：BPS×BPS，下标 = lbz*BPS + lbx */
  readonly cells: BlockFaceEntry[];
  /** 世界块坐标 → 本 chunk 局部下标（ccx/cz 已知时 O(1)） */
  private indexOf(lbx: number, lbz: number): number {
    return lbz * this.BPS + lbx;
  }
  /** 按局部坐标查询 */
  at(lbx: number, lbz: number): BlockFaceEntry | undefined {
    if (lbx < 0 || lbz < 0 || lbx >= this.BPS || lbz >= this.BPS) return undefined;
    return this.cells[this.indexOf(lbx, lbz)];
  }
  /** 按世界块坐标查询（跨界返回 undefined，后处理可做兜底） */
  atWorld(wbx: number, wbz: number, cx: number, cz: number): BlockFaceEntry | undefined {
    const lbx = wbx - cx * this.BPS;
    const lbz = wbz - cz * this.BPS;
    return this.at(lbx, lbz);
  }
  /** 按世界块坐标 + 方向查邻居面信息（跨 chunk 边界返回 undefined） */
  sideAt(wbx: number, wbz: number, dir: 0|1|2|3, cx: number, cz: number): FaceSide | undefined {
    const e = this.atWorld(wbx, wbz, cx, cz);
    if (!e) return undefined;
    return e.sides[dir];
  }
}
```

## 3. 构建时机与流水线

```
精修层产出（per-chunk 确定性产物）
  │  buildChunkFinal        → cornerH (60×60×4, 视觉面高度)
  │  buildChunkWallBuffers  → 原墙 quad (顶点/uv/索引)
  │  finalRuling / edgeOf   → 四边裁决
  ▼
BlockFaceIndex 构建（新增，per-chunk 一次）
  │  ① 遍历 15×15 块，填充 id/h/hBase/role
  │  ② 四边：finalRuling → ruling, edgeOf → drop, 邻块索引 → neighborIdx
  │  ③ 原墙 quad 按 uv 反推发射块 → wallRef 登记
  │  ④ 顶面 4 角：从 cornerH 复制 → top.cornerH
  │  ⑤ 侧面/顶面/底面 materialId 初始化为地块原始材质
  ▼
BlockFaceIndex 挂载到 per-chunk 缓存（惰性，chunk 卸载时释放）
  │
  ├──→ 后处理（只读）：
  │      bevelEdge    → 读 sides[dir].ruling + drop 判定
  │      crack 扫描   → 读 role + neighborIdx（预计算裂隙表）
  │      侧壁重建    → 读 wallRef（剔除原墙 quad）+ sides[dir].drop
  │      yAt 基底     → 读 top.cornerH（= cornerCell）
  │
  └──→ 运行时（读/写）：
         地面交互（角色死亡/技能特效）→ 读 top.materialId → 替换为流体残差材质 → 持久化
         墙面交互                       → 读 sides[dir].materialId → 替换 → 持久化
```

## 4. 各消费方如何用索引

### 4.1 后处理（bevel / crack / pit / 侧壁重建）

| 现在（散乱查询） | 用索引后 |
| --- | --- |
| `src.blockAt(bx, bz)` 取 role/h | `index.at(lbx, lbz).role / .h` |
| `finalRuling(src, bx, bz, dir)` 取裁决 | `index.at(lbx, lbz).sides[dir].ruling` |
| `src.blockAt(bx+dx, bz+dz)` 查邻居 | `index.at(lbx+dx, lbz+dz)` 或 `sides[dir].neighborIdx` |
| 侧壁 quad 反推 `quadEdgeDir` | `wallRef.idxStart` 直接定位 |
| `bevelOffset` 每点扫 4 边 | 预计算 `bevelEdge[dir]` + `drop[dir]`，O(1) |
| `crackOffset` 扫 5×5 锚块 | 预建 `crackTable`，只查经过本块的裂隙 |

### 4.2 运行时地面交互

角色死亡 / 技能特效 → 需要"把地面材质替换为流体残差纹理，保存（不是附着动画）"：

```
事件发生 → 命中坐标 (x,z)
  → 算出所在块 (bx,bz) + 面方向（顶面 or 侧面）
  → index.at(bx,bz).top.materialId = FLUID_RESIDUAL_MATERIAL_ID   // 替换
  → index.at(bx,bz).top.cornerH[k] ... // 高度不变，只换材质
  → 标记 dirty → 持久化存盘（写入存档 / 增量 diff）
```

**持久化方案**：索引的 `materialId` 字段支持覆写。存档时只需序列化 dirty 块的
`{bx, bz, face, materialId}`（增量极小）。加载时恢复，重建索引时读 override。

## 5. 索引的生命周期

```
构建：精修层快照后 → BlockFaceIndex.build(src, cornerH, wallBuffers) → 确定性
  ↓
挂载：ChunkManager 缓存（惰性，chunk 进入构建范围时）
  ↓
读（后处理）：构建网格/侧壁时只读
  ↓
读/写（运行时）：游戏事件触发时覆写 materialId → 持久化
  ↓
卸载：chunk 离开构建范围时释放（materialId 已持久化）
  ↓
重建：chunk 重新进入时，从存档恢复 dirty materialId override
```

---

## 6. 不改精修层的保证

- 索引构建**只读** `buildChunkFinal` / `buildChunkWallBuffers` / `finalRuling` / `tileById`
  的产物——精修层源码零改动。
- `materialId` 覆写由运行时层发起，不经过精修层。
- 后处理层只读不写索引（保持"只读复用精修层"铁律）。

---

## 7. 落地顺序

1. **Phase 1**：`BlockFaceIndex` 数据结构 + 构建函数（从精修层产物填充）
2. **Phase 2**：`PostProcess.ts` 各热点改走索引（替代 `src.blockAt` / `finalRuling` 现查）
3. **Phase 3**：运行时材质替换接口 + 持久化 diff 格式

---

## 8. 开放项

- **cross-chunk 邻居**：`neighborIdx` 只在本 chunk 内有效（null = 跨界）。跨 chunk
  查询需要走 RasterMap 拿邻 chunk 索引（惰性）。是否缓存 1 块裙边？
- **侧面 materialId 替换频率**：如果运行时只改顶面材质（坑/裂视觉），侧面不改
  → 侧面 `materialId` 可省略，简化结构。
- **cornerH vs h 的双高度**：顶面用 `top.cornerH`（视觉面），裁决/邻块用 `h`（逻辑高）——
  两者不同源，索引分开存，消费方按需取。
