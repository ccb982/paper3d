## 0. 总览：四层正交 × 一条执行链

```
                高度场 RasterMap / TerrainSampler（✅ 缓存）
                          │
        ┌─────────────────┴──────────────────┐
        ▼                                    ▼
 L1 语义表（📐 静态·舰船锚）           路径硬口径（✅ 坑/陡壁/水）
 高地/关口/低谷/迎背船坡/走廊/隐蔽…
        │
        │      舰船位置 ──→ urgency(d) 解析圈（📐 不存表·软权重）
        ▼
 L3 兵种偏好表（📐 静态·每兵种一次处理）
 每格：atk / def 两个并行分
        │
        │   L2 工事表（📐 动态·唯一持续修改；坑洞/掩体/墙，对玩家向）
        ▼
 读时合成 Score(兵种, 状态, 格) = lerp(def, atk, w_状态) + 工件加成 + urgency软项
        │
        ▼
 大队（✅ 引擎：锚解引用 + SquadOrder{anchor, intent, TTL}）
        │
        ▼
 队长（⏳ 多步拆解 + 区块内选格 + 锁定路径 + 可申报回撤）
        │
        ▼
 个体（✅ 唯一执行层：SteerPick 候选选择 + AtomExecutor 原子掷）
```

**四层正交**：编队归属（谁） × LOD 载体（多远） × 激活态（代理/实体） × 兵种角色（干什么）。
**一条执行链**：所有战术最终都变成"执行层的候选打分"；**禁止向量合成**（§4）。
**三条纪律**：
1. 玩家移动 → 只刷 L2；L1/L3 一行不动；
2. 工事（战壕/掩体/墙）**永不参与寻路、永不触发重规划**；爬墙走执行层；
3. 命令只从大队下发；跨队诉求走 `requestSupport / shareContact` → 大队裁决。

## 1. 敌人表层（L1 / L2 / L3 + urgency）📐

| 层 | 内容 | 更新时机 | 玩家相关？ |
|---|---|---|---|
| **L1 语义表** | 高地 / 关口 / 低谷 / 迎背船坡 / 走廊 / 开阔 / 隐蔽接近 / 盲区 / 陡壁 / 水 / 坑 | 落地一次；**换落点重算** | 否（只锚舰船） |
| **L2 工事表** | 坑洞 / 掩体 / 墙（位置·深/朝向·遮蔽/防护分·占用） | **唯一持续修改**：建/拆/毁 + 玩家动（2Hz 重排） | 是（深×近 / 遮蔽×近，对玩家） |
| **L3 兵种偏好表** | 每格 `{atk, def}` 两个并行分（"很多地形两用"） | 落地一次；按兵种懒算 | 否（锚舰船方向） |
| **urgency** | 舰船距离圈：越近越高；**不存表**，查询现算；软约束 | 无需更新（随舰船锚） | 否 |

### 1.1 L1 语义类别（判据初值，可增删）

| 语义 | 判据（初值） | 典型价值 |
|---|---|---|
| 高地/制高 | 平滑 h 的局部极大或平台（`isPlateau`）+ 相对邻域高差 ≥1.2m | 观察、俯射、远程 |
| 低谷 | 平滑 h 的局部极小 | 隐蔽推进、低姿态集结 |
| 迎船坡 | 坡度 ≥坡阈 且 `n̂·d̂_ship > 0`（面向舰船） | 偏进攻（可俯射/冲正面） |
| 背船坡 | 坡度 ≥坡阈 且 `n̂·d̂_ship < 0`（背向舰船） | 偏防御（反斜面，被舰船方向地形遮挡） |
| 关口/隘口 | 可站宽度 ≤1 格 + 两侧高差 ≥1.5m（升级现有 W/K） | 卡口、易守 |
| 走廊 | BFS 连通可站带，宽度 2~4 格 | 编队通行、包抄廊道 |
| 开阔地 | 可站宽度 ≥4 格、无掩体特征 | 暴露、冲锋面 |
| 隐蔽接近 | 对舰船方向的高度场 LOS 遮挡连续格 | 偷袭路线 |
| 盲区/死角 | 舰船方向不可见格 | 待机、集结点 |
| 陡壁 | `dh > WALL_DH`（同现有口径） | 不可站（路径硬口径） |
| 水 | `role==='liquid'` | 可走（现状保留，上岸权重） |
| 坑 | `role==='pit'` 或 `h < -1.2` | 不可走（路径硬口径） |

> 方向项统一：`n̂` = 平滑后的下坡方向（`gradientInto` 给）；`d̂_ship` = 指向舰船的水平单位向量。
> 坡向主轴（用户定调）：**面向舰船的坡面偏进攻，背对舰船的坡面偏防御**。

### 1.2 区块化（比 4m 格更大的语义块）

```
种子：语义类别格（高地/低谷 = 平滑梯度小 + 外环(12m)高差 ±1.2m 判出）
扩张：4 邻域 BFS，同类 + 邻步高差 ≤ 0.75m（面积类）/ ≤1.5m（窄类：坡/关口/走廊）
收口：面积 < 3 格降中性（关口 ≥1、走廊 ≥2——窄特征不误杀）
输出：regionId · 类别 · 朝向(对舰船) · 面积 · 代表点
```

**实现口径（✅ 2026-09-21，`swarm/TerrainSemantics.ts`）**
- **几何量用原始高度**（LOS / 可攀宽度 / 夹持高差）；**坡向用 3×3 平滑高度**（抗噪）；
- 关口 = 可攀宽度 ≤1 格 且 **窄轴两侧都被抬高 ≥1.5m**（单侧墙不算）；走廊 = 宽 2~4 格 + 单侧夹持；
- 陡壁/坑 = 硬类（不可站）；水 = 可站；迎/背坡要求坡度 ≥1.5m/4m 且 |坡向| ≥0.25；
- LOS：舰船眼高 +1.6m → 目标 +0.4m，2m 步长，净空 0.2m；被挡 = 隐蔽（偷袭/接近用；坡类/高地保留原类，隐蔽是正交标记）。

- 数据落 `per-cell`：`classId / regionId / aspect(n̂·d̂_ship) / h / slope / width / choke / losToShip`；
- 区块表：`regionId → {类别, 代表点, 面积, 朝向, 邻接}`（供大队取"目标语义块"）；
- ★ **L1 = 纯初始地形（2026-09-21 定稿）**：`classAt` 只读创建时高度场——任何挖掘/破坏/构造**都不改变语义类**（战壕类已废除）。
- ★ **地形破坏 = 独立掩码模块 `HoleMask`**：真源 = `RasterMap.levelDepthAt`（挖掘深度叠加层，天然凹陷=0 不误判）；
  阈值 ≥0.15m（`digCells` 一层=0.2m）；收集路径 = **`ChunkManager.applyDigGroups` 中央钩子 `onTerrainDig`**
  （子弹/战壕/任何 digCells 都过）→ `SwarmCommander.noteTerrainDig`（标脏）→ 本 tick 全表重扫（`holeMask.refresh(±160m)`）；
  构建时首扫一次接管"落地前已存在的初始破坏"。
- ★ **敌人读的是另一个动态坑洞公式表 `HoleTable`**（见 §1.3）：掩码 → 逐格打分（深×近）→ 连通块合并成坑洞条目。
- 成本：73×73 ≈ 5.3k 格 + BFS，一次量级 ms；掩码重扫 ~5k 采样（levelDepth）仅破坏后 1 tick。

### 1.3 L2 工事表（坑洞 + 构造掩体；动态·唯一持续修改）

- **坑洞（`HoleMask` → `HoleTable`）**（✅ 已实现 2026-09-21）：
  - `HoleMask`（独立模块）= 4m 格挖掘深度掩码，同锚窗口；`depthAt/isDug` 读原始数据，不参与任何语义类；
  - `HoleTable`（敌用动态表，2Hz 重排）= 逐格打分 + 连通块合并出坑洞条目：
    - 坑洞分 = **深度因子 × 距离因子**——深 <0.3m 归零、≥1.0m 满分；玩家 ≤40m 满分、≥90m 归零；
      **只有够深且够近**才是有效高分坑洞（成分取积，浅/远其一为零 → 分塌 0）；
    - 条目 `Hole{ 代表点(块内最高分格), 质心, 格数, 最深, 平均深, 分, 距玩家 }`，按分降序；
    - "动态不断修改"：玩家移动→距离分变；新挖坑→新条目；坑被填/塌→条目消失。
- **构造掩体（同拍动态计算）**（✅ 已实现 2026-09-21）：
  - 真源 = `CoverEntity._coverRegistry` 活注册表（`snapshotCovers('enemy')` 快照）——新增/被毁即时反映，
    **不存手工列表**（`builtCovers` 已废除）；
  - 掩体分 = **遮蔽因子（挡玩家射界 1 / 暴露 0.35）× 距离因子**；`hidden` 随玩家移动/墙倒实时变；
  - 掩体集合指纹变化 → `scoreStamp++` → `TerrainScore` 全量重评（掩体加成 ±2.5 随真源，不上陈旧数据）。
- **与寻路/移动**：**完全不参与**寻路代价与阻挡（坑洞、掩体、**墙**一视同仁）；
  **允许爬墙**——复用 `CharacterBase` 攀爬（顶住可攀工事 `walkableTop`，`CLIMB_HOLD` 后 `beginClimb`）✅；
- 工事"不挡路径"≠"不挡子弹"：**照常挡子弹**（掩体存在的意义）；
- 因此"墙挡路/新建筑挡路"**不是**重规划事件（§5）。

### 1.4 L3 兵种偏好表（静态·每兵种一次处理）——攻/防**两个并行分**

```
L3[兵种][格] = { atk, def }      // 两个独立分，互不抵消
atk = wA·(n̂·d̂_ship)            // 方向主轴：迎船坡 → atk↑
    + Σ_k wA_k · 语义k(格)
def = wD·(-(n̂·d̂_ship))         // 背船坡 → def↑
    + Σ_k wD_k · 语义k(格)
```

- **很多地形两用**：高地、关口、走廊往往 `atk` 与 `def` **同时高**——由状态在读时决定取谁（§1.6）；
- 每个兵种一套 `(wA, wD, wA_k, wD_k)` + **专属特殊规则**；按兵种首次出现懒算；
- **各兵种处理手法（初版矩阵）**：

| 兵种 | 主取语义 | atk↑ | def↑ | 特殊规则 |
|---|---|---|---|---|
| 盾 | 关口/走廊/迎船坡 | 迎船坡、关口、走廊 | 关口、走廊、掩体后 | 宽度大优先；站前沿；两用地形先攻后守 |
| 突击 | 隐蔽接近/低谷/迎船坡 | 隐蔽接近、低谷、迎船坡 | 背船坡（临时） | 沿推进轴压上；接受低掩体 |
| 远程 | 高地/盲区/背船坡 | 高地、俯射位 | 高地、反斜、盲区 | 俯射 LOS + 距离带 [0.5R,1.05R]；有掩体加成 |
| 工程 | **工事位优化**（见下） | — | — | 不选"蹲位"，选"放工事最优格" |
| 后勤 | 盲区/走廊 | — | 盲区、走廊 | 限制在前线后方；远离接敌 |
| 飞行 | 不读地面 L3 | — | — | 独立空中层，只读目标 |

**工兵放置优化（"工事立在哪里效果最好"）**
```
工事价值(格) = 地形控制力(关口/高地)
             + 覆盖(俯射推进轴/舰船方向的路段)
             + 隐蔽(对玩家不可见/反斜面)
             - 暴露(玩家火力可达)
按兵种施工规则排序取 Top，且满足推进阶段（逐步向前）
```

- **攻防的空间锚**：主轴 = 舰船方向（迎船坡/近船正面 = 进攻位；背船坡/反斜面 = 防御位）；
  urgency 圈只做软偏置，不参与攻防定义。

### 1.5 urgency（舰船距离圈·不存表·软约束）

```
urgency(x,z) = smoothstep 型：d_ship 越小 → 越高（R_inner / R_outer 可调；连续）
```

- **零存储**：查询时 `hypot` 现算 O(1)；**不强制**：只作权重/偏置，不是硬门槛；
- 与态势函数分工：`p`（时间节律+挑衅）= 时间维；`urgency` = 空间维；随舰船锚生灭。

### 1.6 读时合成（不重建任何表）

```
Score(兵种, 状态, 格) = lerp(def, atk, w_状态)           // w 由状态/态势 p 给（0=全防，1=全攻）
                      + Σ 工件加成(格, 玩家位置, 状态)   // 动态项：空间哈希邻域，稀疏
                      + urgency 软项
```

- 两分并行：巡逻/集结等**中间状态可同时参考攻防**（如 0.5/0.5），不会被"相减"抹平；
- 玩家满地图跑 → 只有第二项变；L1/L3 零改动；新掩体建成 → 读表自然生效（不重建）；
- 消费者：**大队**选目标语义块；**队长**区块内 `argmax Score`（目的地/多步选格）；
  **寻路**按状态读分做代价项（只在**重新寻路**时读，不每帧重算）。

### 1.7 与现有代码/表的关系（边界）

- L1 **替换 `TerrainScore` 的语义来源**；`TerrainScore` 保留：4m 网格、`cls/blockedAt/costAt`
  通行口径与环境查询 API（寻路继续消费）、`gradientInto/isPlateau/smoothAt` 作 L1 数学工具；
- **语义/工件/兵种偏好不在 `TerrainScore` 内重建**；战壕/掩体不再是表分来源（移 L2）；
- `TileDef.genRole` 继续服务水/坑等硬判定（非 AI 语义，勿动）；
- 复用：`RasterMap` / `TerrainSampler`（高度缓存）、`LandingTerrain`（采样入口）。

## 2. 态势与节律 ✅

```
p = clamp( schedule(t) + provocation, 0, 1 )        // 时间维（引擎）
urgency(d_ship)                                     // 空间维（📐 解析圈，不入令）
schedule(t)：单日节律锚点（0.45 第一波 / 0.80 总攻 / 1.0 入夜），节奏从落地起算、黄昏到 1
provocation：被击 ×0.01 + 击杀 ×0.03，指数衰减 τ=90s，上限 +0.35
态势映射：p<0.22 fortify / <0.30 patrol / <0.55 advance / <0.80 mass / ≥0.80 assault
锁定：进入 assault 后不回退（只有撤损 60% 的 withdraw 安全阀）；升级立即、降级要过 DWELL
```

**单日节律（schedule 锚点，✅ 已接线）**

| 时段 | 进度 | 增兵 | 行为（姿态） |
|---|---|---|---|
| 扎根 | 0~0.15 | 少量（后勤 + 2~3 近战） | 修工事、守线、飞行待命（fortify） |
| 集结 | 0.15~0.40 | 渐进补兵 → 补齐基数 | 工事前推、巡逻侦察（fortify→patrol） |
| **第一波** | 0.40~0.55 | 大量（+~50% 基数） | advance→mass；打残（损 25%）→ withdraw 回防 |
| 再集结 | 0.55~0.75 | 持续增兵 + 工事前推 | 防御修复 → patrol 再试探 |
| **总攻** | 0.75~1.0 | 满编/额外额度 | assault：全力以赴、施工停、盾也压上 |
| 入夜 | 1.0 | 停增 | 总攻持续到被清完（只结算战绩） |

`schedule(t)` 分段线性锚点：0.10@0.10 · 0.25@0.30 · **0.45@0.45（第一波）** · 0.60@0.65 · **0.90@0.80（总攻）** · 1.0@1.0。

- **兵力放行**：`ledger.releaseCap = ceil(total × releaseAt(t01))`（0.20→0.50→0.75→0.95→1.00）；
  `canSpawn/remaining = min(total, releaseCap)` —— 早间只放少量，第一波/总攻两个波峰放宽；
  基数 ≈30（±浮动），第一波 ×1.5 ≈45、总攻满编；可附加精英/Boss（`swarmUid=0` 不入账）。
- **撤退安全阀**（波内）：loss ≥25% → withdraw 30s → 防御修复 → patrol 再集结；
  总攻内 loss ≥60% → withdraw（`aliveRatio<0.4` 基准在进总攻时重置）。
- **UI 播报**：`Director` 已退化为播报器（mass→预警 / assault→开战 / 回落→清除），**不再产兵**。
- 实现落点：`SwarmCommander` 读 `dayT01`（太阳钟 6:00=0 / 18:00=1）；挑衅在 `PostureFn` 内衰减；
  `?swarmdbg` 显示 `态势 / p / 日程 / 挑衅`；调试可用 `commander.debugDayT01` 拨日程。

## 3. 决策链：大队 → 队长 → 个体

### 3.1 战术能力表 `UnitTactics`（唯一来源）✅
```
TYPE_KIND     角色分类：melee / ranged / support / air / mixed
TYPE_MISSIONS 可接任务：盾[护卫,突进] 突击[护卫,突进,侧击] 远程[驻守,风筝]
              后勤[后置]（不能施工） 飞行[突进] 混编[护卫,突进]
UNIT_TACTICS  共用参数：护卫距离 / 接敌距离 / 可施工
MISSION_EXEC  任务→队内执行：build=禁火+1.05速 / guard=自由+0.9 / hold=0.85 / rear=到位才开火
```
- **任务分派两段**：① 引擎（大队）`engineMissionFor` → 大任务（粘性：只在落点/态势代次/施工阶段切换时重派）；
  ② 队长 `assignTasks` → 成员级任务（施工分块、护卫扇区）——走 `AgentPool.taskX/taskZ`（✅ 成员位置列）；
- **大任务粘性 / 稳定岗位 / 施工块**：`missionAssign / postAssign / buildAssign`（✅）；
- 开局班底：**3 工程（`spawnBuilder`）+ 2 盾 + 2 突击 + 1 远程**，锚点就近生成。

### 3.2 大队 = 锚 + 意图（📐 指令格式定稿）
```
SquadOrder = { anchor, intent, ttl }
  anchor = { kind:'区块', regionId } | { kind:'小队', squadId }
  intent = 攻 | 守 | 守卫 | 集结 | 偷袭 | 撤退
  // 紧急度不入令：谁读谁按舰船距离算（§1.5 urgency 圈）
```
- **锚解引用只在大队层**：`kind:'小队'` → 解析成"该小队当前所在语义区块 + 朝向"，
  下发到队长的**永远是位置型目标**；队长**永不查别的队**（防帧序依赖/跨队耦合）；
- **事件驱动重发**（低频 1~2Hz 或事件，非持续查）：锚跨区块 / 位移超 N 米；
  锚小队并队·换队长·阵亡·失联；意图完成；TTL 到期；
- 解引用附**锚精度/是否休眠**（L0~L3 位置精度不同）→ 队长据此收放守圈（贴近守卫 ↔ 区域守卫）。

### 3.3 队长 = 多步拆解 + 选格 + 分解（⏳ 自主性增强）
- 大队给**大目标（区块 + 意图）**；队长拆成**步骤序列**（每步一格/一个语义小区块），
  逐步取 `argmax Score(兵种, 意图, 格)`；**推进不问大队**，只在整任务完成/失败上报 `progress(k/N)`；
- 步骤可在**同区块内替换**（地形/敌情），大目标不变 → 不触发大队重发；
- **分解矩阵**：

| 意图 | 队长干什么 | 主要载体 |
|---|---|---|
| 攻 | atk 高分选推进格；盾前/远程后/突击侧翼；接敌与开火策略 | `UnitDirective` + `taskX/taskZ` |
| 守 | def 高分选反斜/关口格；沿区块前沿摊开、面向威胁、控火 | 同上 |
| 守卫 | 环绕区块/锚布岗（护卫弧线、4m 间隔）、朝向/警戒/轮换 | `taskX/taskZ`（成员位置列 ✅） |
| 集结 | 区块内收敛到集结点、整队形 | 编队槽位 |
| 偷袭 | L1"隐蔽接近"格分段走；`fireOnArrival`/禁火；延迟发动 | `roe` + 分段路径 |
| 撤退 | 收拢残部沿低风险走廊后撤；伤兵先行、断后交替掩护 | `fallback/boundBack` + `taskX/taskZ` |

### 3.4 回撤与任务取消（📐 两通路）
- **触发（队长侧）**：伤亡比超阈（沿用 withdraw 60% 口径）、目标不可达、长时间无进展、弹药/血量见底；
- 通路①**队长申报**：`requestRetreat(原因/伤亡/位置)` → 黑板 → **大队裁决**（批准/驳回/改派）；
- 通路②**大队自主**：按小队评级直接下发撤退令，取消在途任务；
- 效果：`SquadOrder` 立即失效（seq 作废）→ 转 `撤退`/就地守；撤退途**不追打**（`holdFire`/`fireOnArrival`）。
- 防成环铁律：**保护队不听被保护队**；被保护队诉求走 `requestSupport/shareContact` → 大队。

### 3.5 情报与共享 ✅
个体接触 → `lastSeenX/Z/At`、被击 `aggroFrom`；小队 4Hz 汇总（评级）→ 大队；
`requestSupport / shareContact`（黑板）→ **大队裁决**；📐 `requestRetreat` 同通道；
⏳ contactMap 大队级聚合、感知预算（小队级 LOS）、dormant 半盲规则细化。

## 4. 唯一执行层（`SteerPick` + `AtomExecutor`）✅

```
每决策拍：16 向 + hold 候选
① 硬否决（不是低概率）：表 blockedAt（墙/坑水）、>40° 陡坡
② 打分：W_PATH(1.6)·cos(期望) + W_TABLE(0.8)·表分 + W_TURN(0.7)·上次方向
        − W_AVOID·人群同向 − 水反向 +（禁区逃离/上岸权重）
③ softmax(温度 0.18) 抽样 → 选一个 → 承诺 0.5s；换向迟滞 1.12×
④ 已在硬边界内：不否决、优先逃离；分离只做惩罚 + 移动后物理外推（不合成方向）
原子：移动原子（forward/back/strafe/hold）× 开火（fireProfile：>20m 散射 / <20m 精准）
```

**移动方向纪律（禁止向量合成）**
1. 不做"流场 + 分离 + 编队 + 避障"相加；对候选方向**逐个打分 → softmax → 选一个**；
2. 路径只提供"下一个 waypoint"；方向 = 最接近该 waypoint 的 16 向候选（不插值）；
3. 分离/避障**不产生方向**：只做否决/降权；承诺窗内只做视觉平滑；
4. 决策频率：移动选择 10Hz、开火独立冷却；L1/L2 低频。

**命令 → 权重（层只写权重，执行层只算一次）**

| 命令/指令 | 改动的权重（示意） |
|---|---|
| advance / press | forward↑、fire↑ |
| retreat / fallback | back↑、awayFromThreat↑、fire↓ |
| holdFire | fire→0（权重归零的硬态） |
| focusFire(target) | 对该目标 targetWeight↑（其余↓） |
| flank / bound | lateral↑（侧移）、pathBias 旁路↑ |
| regroup / guardWard | cohesion↑（靠队长/工位）、forward↓ |
| suppress | fireRate↑、forward↓（原地） |
| build（施工） | buildWeight↑、forward↓ |

- 两载体共用：代理 `SwarmSystem` 与实体 `EnemyBrain/EnemyLocomotion` **同一份 `SteerPick`**
  （实体经"表桥"`setSteerTable` 读表）——"两载体同内核" ✅；
- 分层决策评分（📐 读分后统一）：`S_table(L1/L3/L2 合成)` + 各层增量（engine ≤6 / leader ≤5 / unit ≤4 项），
  概率 = softmax(决策分/T)；主力行动 ≥0.6、兜底 ≥0.05（防抖、防摆烂）；每层输出 breakdown 供调试。

## 5. 寻路与路径锁定

| 层 | 实现 | 读表 |
|---|---|---|
| 全局 | `HpaPath`（32m 簇 + 端口图 + 预热 3 簇/10Hz；TTL 20s） | 簇 pass 已按同口径排墙 ✅ |
| 小队 | `SquadPath`（4m 有界 A* + 拉绳；失败 → 直线降级） | 已读 cls：墙=不可进、坡×1.6 ✅ |
| 局部 | `SteerPick`（候选选择） | 硬否决 + 表分打分（📐 读合成分） |
| 危险口径 | 坑 / h<-1.2 / 连续陡坡(1.2m 内升>1.0m，≈40°)；**水可走** | 与表同源常量 |

**路径锁定（📐 治"左右抽风"的硬纪律）**
- 队长选目的地与**分段寻路**读**合成分**（L3+工件+urgency）；工件**只加软分**，不阻挡；
- 一条路**定下即锁**：执行期只做 `SteerPick` 局部避让，**不重算整条路**；
- **允许中断（重算）的白名单**：
  1. 目标/意图变更（大队换令，含回撤/取消任务 §3.4）；
  2. 地形被挖断（路径上出现坑/陡壁）；
  3. 长时间无进展（阈值如 2s 位移 < ε）；
  4. TTL 到期；
  5. 攻/守状态切换（读表口径变了）。
- **工事永不触发重规划**（战壕/掩体/墙不挡路；**爬墙**走执行层）；
- 白名单之外：**零重规划**。

## 12. 管线自评（2026-09-21 · 诚实版）

**结论一句话**：**架构已经"理论正确、单源可调"，但"好玩/聪明"完全没被证明**——
问题不在结构，在**参数、观感与验证缺失**；本轮表层设计（L1/L2/L3）是补课，不是翻新。

- **真正验证过的**：旧表权重方向（前期外围高地 / 总攻舰旁战壕，meanTopD 108→22）；
  节律链路（p/挑衅/releaseCap 两波峰）；任务/岗位稳定（无 8m 跳变、0 kind 翻转）；
  代理执行层卡住 0~2/59、误入硬边界显著下降。
- **设计已定、完全没有实测的（当前最大风险）**：L1/L2/L3 表层 + 指令链新格式（anchor/intent）
  + 多步自主 + 回撤申报 + 路径锁定白名单。
- **价值**：单源（语义表 + 工件表 + 兵种表 + 一条执行链）让"加战术"= 加权重/加意图；
- **代价**：状态面继续变多（anchor/意图/步骤/回退申报）——必须配"状态可观测"（`?swarmdbg`/RTS）；
- **边界**：聪明感还依赖动画前摇/预警/音效与节奏，AI 结构只决定"不犯蠢"。

**下一步只做三件事（先量化，再谈聪明）**
1. **施工速率**：`builtSlots` 每分钟增量（工程队并行是否真生效）；
2. **卡住/回收率**：`reapLost` 次数/分钟 + 硬边界内单位占比；
3. **决策稳定性**：每队 mission/目标变化次数/分钟 + **路径重规划次数/分钟**（本轮新增）。
> 三个指标达标后，再进 RTS 项目做参数搜索；在此之前不再加新战术功能。
