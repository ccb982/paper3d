## 0. 总览：三输入 → 合成 → 兵种战术策略函数 → 一条执行链

```
                高度场 RasterMap / TerrainSampler（✅ 缓存）
                          │
         ┌────────────────┴─────────────────────────────────┐
         ▼                                                  ▼
  输入① L1 地形语义表（✅ 静态·舰船锚）            路径硬口径（坑/陡壁/水）
  输入② L2 工事表（✅ 动态·唯一持续修改；挖壕/掩体/墙，对玩家向）
  输入③ 事态函数（✅ p / posture / frontP —— **合成与定位的双重参数**）
         │
         ▼
  合成层 score(x,z)（✅ TerrainScore；事态 = 权重参数 weightsFor(p,posture)）
        score = h·w.h + dist·w.dist + threat·w.threat + cover·w.cover
              + width·w.width + choke·w.choke + near·w.near
         │
         ▼
  L3 兵种战术策略函数（✅ scoreFor(兵种,x,z) = 合成层 ⊗ 兵种专属特征权重；2026-09-22 P1 落地）
  盾=隘口/掩体 · 突=隐蔽接近/迎船坡 · 远程=高地+射程带+掩体 · 后勤=后区
         │
         ├──→ 寻路拆解（✅ 掩体/战壕成本折扣 0.6~1；仅重规划读，不每帧）
         ▼
  战术选点/命令：大队（✅ 锚+命令）→ 队长（⏳ 区块多步拆解+选格）
         ▼
  个体（✅ 唯一执行层：SteerPick 候选选择 + AtomExecutor 原子掷）
```

**四层正交**：编队归属（谁） × LOD 载体（多远） × 激活态（代理/实体） × 兵种角色（干什么）。
**一条执行链**：所有战术最终都变成"执行层的候选打分"；**禁止向量合成**（§4）。
**三条纪律**：
1. 玩家移动 → 只刷 L2；L1/L3 一行不动；
2. 工事（战壕/掩体）作为**寻路代价项**（折扣 0.6~1，仅重规划时读、不每帧）；**不是硬边界、不触发重规划**；爬墙走执行层；
3. 命令只从大队下发；跨队诉求走 `requestSupport / shareContact` → 大队裁决。

**★★ 命令轨 × 寻路轨（双轨，2026-09-22 用户定稿）：命令是命令，寻路是寻路**
```
命令轨（大队独占）：事态函数 ──→ 大队（doctrine/任务/撤销）──→ SquadOrder{anchor, intent, coarse, ttl}
   · 命令三件套 = 【目标地点/队伍锚】+【大致路径 coarse】+【战术意图】（打/守/撤等）
   · 大致路径 = 发令前【初级寻路】的副产物（走廊级/少量路点）：只作小队参考，不锁定
   · **命令不可变总律**：发出即冻结；后继只有【覆盖】（发新令 seq++ 整体替换）与【中断】（作废/撤销）；
     **原地修改一律禁止**（不改字段、不半旧半新）
   · 覆盖权分层：大队命令的覆盖权**只在大队**（自主修改 = 大队发新令覆盖）；
     小队无覆盖权——仅自身严重（伤亡超阈等）时【申报】请求，经大队裁决**由大队覆盖**；否则等大队自主修改
   · 撤销权只在大队；小队只【上报状态】（progress/伤亡/contact），不能自行撤销、不能改派

寻路轨（小队自治）：寻路决策 = f(L1 地形语义 ⊗ L2 工事 ⊗ 事态函数)          ← 就这三个参数
   · 合成层 → L3 兵种战术策略函数 → 路径代价（§5）
   · 小队在命令给的【区块/意图】scope 内**自主拆分路径**（步进选格/替换步骤），
     可参考随令附带的大致路径（coarse 是软参考，随时可按合成分换掉）；
     不向大队请示、不产生大队级命令；推进只上报 progress(k/N)
   · **小队级寻路命令同样不可变**：执行中调整 = 发**新的寻路命令覆盖上一个**（覆盖权在小队自己）；
     后继只有【覆盖】与【中断】（停）——同样**不允许原地修改**
   · 执行期【时刻读】动态参照（不入合成表、不触发重规划）：
     ① 玩家位置（推进轴/风筝/朝向） ② 被保护对象位置（护卫跟随锚点）
     ③ 掩体位置+LOS——防守站位复核"自己真的被掩体挡住了"，没挡住就挪（§4 执行层）
```
- **两级寻路分工**（2026-09-22 用户定稿）：
  - **大队·初级寻路（粗）**：发令前核验"命令可执行"（簇级连通/直线走廊/绕障粗判：目标不被硬边界封死），
    不可达 → 改派/缩近目标；**核验顺产【大致路径 coarse】随令附带**（走廊级参考，不是逐格路径）；
    低成本、不缓存精细路径；
  - **小队·主寻路（细）+ 执行**：真正的主寻路、路径拆分、步进选格、替换、执行止损全在小队；
    参考 coarse 但**以三参数合成分为准**，coarse 不合适随时换。
- **唯一交叉点**：命令给"目标语义块 + 意图 + 大致路径"（scope）；coarse 是软参考、不是逐格路径；寻路在 scope 内自治；
- **事态两轨都注入**：寻路轨 = 合成权重 `weightsFor(p,posture)` + `frontP` 允许离舰半径；
  命令轨 = doctrine 强度、任务带宽、withdraw 安全阀（§2 / §3.4）；
- **职责隔离**：命令层（大队）只知道"派谁去哪、何时撤、命令能不能落地"；寻路层（小队）只知道"在 scope 内怎么走最划算"。

### 1.1 L1 语义类别（判据初值，可增删）

| 语义 | 判据（初值） | 典型价值 |
|---|---|---|
| 高地/制高 | 平滑 h 的局部极大或平台（`isPlateau`）+ 相对邻域高差 ≥1.2m | 观察、俯射、远程 |
| 低谷 | 平滑 h 的局部极小 | 隐蔽推进、低姿态集结 |
| 迎船坡 | 坡度 ≥坡阈 且 `n̂·d̂_ship > 0`（面向舰船） | 偏进攻（可俯射/冲正面） |
| 背船坡 | 坡度 ≥坡阈 且 `n̂·d̂_ship < 0`（背向舰船） | 偏防御（反斜面，被舰船方向地形遮挡） |
| 关口/隘口 | 可站宽度 ≤1 格 + 两侧高差 ≥1.5m（升级现有 W/K） | 卡口、易守 |
| 走廊 | BFS 连通可站带，宽度 2~4 格 | 编队通行、包抄廊道 |
| 开阔地 | 可站宽度 ≥4 格、无掩体特征 | 暴露、冲锋面 |
| 隐蔽接近 | 对舰船方向的高度场 LOS 遮挡连续格 | 偷袭路线 |
| 盲区/死角 | 舰船方向不可见格 | 待机、集结点 |
| 陡壁 | `dh > WALL_DH`（同现有口径） | 不可站（路径硬口径） |
| 水 | `role==='liquid'` | 可走（现状保留，上岸权重） |
| 坑 | `role==='pit'` 或 `h < -1.2` | 不可走（路径硬口径） |

> 方向项统一：`n̂` = 平滑后的下坡方向（`gradientInto` 给）；`d̂_ship` = 指向舰船的水平单位向量。
> 坡向主轴（用户定调）：**面向舰船的坡面偏进攻，背对舰船的坡面偏防御**。

### 1.2 区块化（比 4m 格更大的语义块）

```
种子：语义类别格（高地/低谷 = 平滑梯度小 + 外环(12m)高差 ±1.2m 判出）
扩张：4 邻域 BFS，同类 + 邻步高差 ≤ 0.75m（面积类）/ ≤1.5m（窄类：坡/关口/走廊）
收口：面积 < 3 格降中性（关口 ≥1、走廊 ≥2——窄特征不误杀）
输出：regionId · 类别 · 朝向(对舰船) · 面积 · 代表点
```

**实现口径（✅ 2026-09-21，`swarm/TerrainSemantics.ts`）**
- **几何量用原始高度**（LOS / 可攀宽度 / 夹持高差）；**坡向用 3×3 平滑高度**（抗噪）；
- 关口 = 可攀宽度 ≤1 格 且 **窄轴两侧都被抬高 ≥1.5m**（单侧墙不算）；走廊 = 宽 2~4 格 + 单侧夹持；
- 陡壁/坑 = 硬类（不可站）；水 = 可站；迎/背坡要求坡度 ≥1.5m/4m 且 |坡向| ≥0.25；
- LOS：舰船眼高 +1.6m → 目标 +0.4m，2m 步长，净空 0.2m；被挡 = 隐蔽（偷袭/接近用；坡类/高地保留原类，隐蔽是正交标记）。

- 数据落 `per-cell`：`classId / regionId / aspect(n̂·d̂_ship) / h / slope / width / choke / losToShip`；
- 区块表：`regionId → {类别, 代表点, 面积, 朝向, 邻接}`（供大队取"目标语义块"）；
- ★ **L1 = 纯初始地形（2026-09-21 定稿）**：`classAt` 只读创建时高度场——任何挖掘/破坏/构造**都不改变语义类**（战壕类已废除）。
- ★ **地形破坏 = 独立掩码模块 `HoleMask`**：真源 = `RasterMap.levelDepthAt`（挖掘深度叠加层，天然凹陷=0 不误判）；
  阈值 ≥0.15m（`digCells` 一层=0.2m）；收集路径 = **`ChunkManager.applyDigGroups` 中央钩子 `onTerrainDig`**
  （子弹/战壕/任何 digCells 都过）→ `SwarmCommander.noteTerrainDig`（标脏）→ 本 tick 全表重扫（`holeMask.refresh(±160m)`）；
  构建时首扫一次接管"落地前已存在的初始破坏"。
- ★ **敌人读的是另一个动态坑洞公式表 `HoleTable`**（见 §1.3）：掩码 → 逐格打分（深×近）→ 连通块合并成坑洞条目。
- 成本：73×73 ≈ 5.3k 格 + BFS，一次量级 ms；掩码重扫 ~5k 采样（levelDepth）仅破坏后 1 tick。

### 1.3 L2 工事表（坑洞 + 构造掩体；动态·唯一持续修改）

- **坑洞（`HoleMask` → `HoleTable`）**（✅ 已实现 2026-09-21）：
  - `HoleMask`（独立模块）= 4m 格挖掘深度掩码，同锚窗口；`depthAt/isDug` 读原始数据，不参与任何语义类；
  - `HoleTable`（敌用动态表，2Hz 重排）= 逐格打分 + 连通块合并出坑洞条目：
    - 坑洞分 = **深度因子 × 距离因子**——深 <0.3m 归零、≥1.0m 满分；玩家 ≤40m 满分、≥90m 归零；
      **只有够深且够近**才是有效高分坑洞（成分取积，浅/远其一为零 → 分塌 0）；
    - 条目 `Hole{ 代表点(块内最高分格), 质心, 格数, 最深, 平均深, 分, 距玩家 }`，按分降序；
    - "动态不断修改"：玩家移动→距离分变；新挖坑→新条目；坑被填/塌→条目消失。
- **构造掩体（同拍动态计算）**（✅ 已实现 2026-09-21）：
  - 真源 = `CoverEntity._coverRegistry` 活注册表（`snapshotCovers('enemy')` 快照）——新增/被毁即时反映，
    **不存手工列表**（`builtCovers` 已废除）；
  - 掩体分 = **遮蔽因子（挡玩家射界 1 / 暴露 0.35）× 距离因子**；`hidden` 随玩家移动/墙倒实时变；
  - 掩体集合指纹变化 → `scoreStamp++` → `TerrainScore` 全量重评（掩体加成 ±2.5 随真源，不上陈旧数据）。
- **与寻路/移动**：**完全不参与**寻路代价与阻挡（坑洞、掩体、**墙**一视同仁）；
  **允许爬墙**——复用 `CharacterBase` 攀爬（顶住可攀工事 `walkableTop`，`CLIMB_HOLD` 后 `beginClimb`）✅；
- 工事"不挡路径"≠"不挡子弹"：**照常挡子弹**（掩体存在的意义）；
- 因此"墙挡路/新建筑挡路"**不是**重规划事件（§5）。

### 1.4 L3 兵种战术策略函数（每兵种独有·读时合成）——攻/防两个并行分

> 管线第 4 环：**入参 =（L1 语义 ⊗ L2 工事 ⊗ 事态 p/posture）合成层 + 兵种特征权重**。
> 只产"读时偏好"，不落表——队长选点/寻路拆解在读时调 `scoreFor(兵种,x,z)`。

```
L3[兵种][格] = { atk, def }      // 两个独立分，互不抵消
atk = wA·(n̂·d̂_ship)            // 方向主轴：迎船坡 → atk↑
    + Σ_k wA_k · 语义k(格)
def = wD·(-(n̂·d̂_ship))         // 背船坡 → def↑
    + Σ_k wD_k · 语义k(格)
```

- **很多地形两用**：高地、关口、走廊往往 `atk` 与 `def` **同时高**——由状态在读时决定取谁（§1.6）；
- 每个兵种一套 `(wA, wD, wA_k, wD_k)` + **专属特殊规则**；按兵种首次出现懒算；
- **各兵种处理手法（初版矩阵）**：

| 兵种 | 主取语义 | atk↑ | def↑ | 特殊规则 |
|---|---|---|---|---|
| 盾 | 关口/走廊/迎船坡 | 迎船坡、关口、走廊 | 关口、走廊、掩体后 | 宽度大优先；站前沿；两用地形先攻后守 |
| 突击 | 隐蔽接近/低谷/迎船坡 | 隐蔽接近、低谷、迎船坡 | 背船坡（临时） | 沿推进轴压上；接受低掩体 |
| 远程 | 高地/盲区/背船坡 | 高地、俯射位 | 高地、反斜、盲区 | 俯射 LOS + 距离带 [0.5R,1.05R]；有掩体加成 |
| 工程 | **工事位优化**（见下） | — | — | 不选"蹲位"，选"放工事最优格"；现行实现（环带/直线弦/总攻掩护）见《工兵架构.md》§4/§8 |
| 后勤 | 盲区/走廊 | — | 盲区、走廊 | 限制在前线后方；远离接敌 |
| 飞行 | 不读地面 L3 | — | — | 独立空中层，只读目标 |

**工兵放置优化（"工事立在哪里效果最好"）**
```
工事价值(格) = 地形控制力(关口/高地)
             + 覆盖(俯射推进轴/舰船方向的路段)
             + 隐蔽(对玩家不可见/反斜面)
             - 暴露(玩家火力可达)
按兵种施工规则排序取 Top，且满足推进阶段（逐步向前）
```

- **攻防的空间锚**：主轴 = 舰船方向（迎船坡/近船正面 = 进攻位；背船坡/反斜面 = 防御位）；
  urgency 圈只做软偏置，不参与攻防定义。

### 1.5 urgency（舰船距离圈·不存表·软约束）

```
urgency(x,z) = smoothstep 型：d_ship 越小 → 越高（R_inner / R_outer 可调；连续）
```

- **零存储**：查询时 `hypot` 现算 O(1)；**不强制**：只作权重/偏置，不是硬门槛；
- 与态势函数分工：`p`（时间节律+挑衅）= 时间维；`urgency` = 空间维；随舰船锚生灭。

### 1.6 读时合成（不重建任何表）——事态函数是**显式参数**

```
scoreFor(兵种, 状态, 格) = 合成层(格) ⊗ 兵种战术策略函数(兵种, 格) ⊗ 事态攻防混比 w_状态
合成层(格) = h·w.h(p) + dist·w.dist(p) + threat·w.threat(p) + cover·w.cover(p)
           + width·w.width(p) + choke·w.choke(p) + near·w.near(p)        // ✅ 已实现
兵种战术策略函数 = Σ_特征 兵种特征权重(type, 特征) × 合成字段          // ✅ scoreFor（UnitStrategy.ts，2026-09-22 P1）
w_状态 = lerp(def, atk, w_状态)  由态势 p 给（0=全防，1=全攻）
总式：_score(兵种,格) = lerp(def, atk, w_状态) + Σ 工件加成(格,玩家,状态) + urgency 软项
  （⚠️ 实现现状：`scoreForUnit = weightsFor × 兵种MUL × 字段`；**urgency 软项未接** 📐）
```

- **事态在合成里的两处**：① 合成层权重 `weightsFor(p,posture)`（`P_ANCHORS` 分段线性，withdraw 独立档）；
  ② 兵种函数的攻防混比 `w_状态`（0=全防，1=全攻）。外加**第三步**：`frontP` 推到**允许离舰半径**（§3.8），
  管"能到多近"，与"怎么加分"正交。
- 两分并行：巡逻/集结等**中间状态可同时参考攻防**（如 0.5/0.5），不会被"相减"抹平；
- 玩家满地图跑 → 只有工件加成/距离项变；L1/L3 零改动；新掩体建成 → 读表自然生效（不重建）；
- 消费者：**大队**选目标语义块；**队长**区块内 `argmax scoreFor`（目的地/多步选格）；
  **寻路**按状态读分做代价项（只在**重新寻路**时读，不每帧重算）。

## 2. 态势与节律 ✅

```
p = clamp( schedule(t) + provocation, 0, 1 )        // 时间维（引擎）
urgency(d_ship)                                     // 空间维（📐 解析圈，不入令）
schedule(t)：单日节律锚点（0.45 第一波 / 0.80 总攻 / 1.0 入夜），节奏从落地起算、黄昏到 1
provocation：被击 ×0.01 + 击杀 ×0.03，指数衰减 τ=90s，上限 +0.35
态势映射：p<0.22 fortify / <0.30 patrol / <0.55 advance / <0.80 mass / ≥0.80 assault
锁定：进入 assault 后不回退（只有撤损 60% 的 withdraw 安全阀）；升级立即、降级要过 DWELL
```

**事态函数的三个输出面（同一事态、三处消费）**：
1. **合成层权重参数**（§1.6 ①）：`weightsFor(p,posture)` → `score` 的七项权重（h/dist/threat/cover/width/choke/near）；
2. **兵种攻防混比**（§1.6 ②）：`w_状态 = lerp(def, atk, p)`（0=全防，1=全攻）；
3. **允许离舰半径**（§3.8）：`frontP`（单调只进不退，τ≈40s）→ `frontMinD`，管"能到多近"——与"怎么加分"正交，专防"一上来就冲家"。

**单日节律（schedule 锚点，✅ 已接线）**

| 时段 | 进度 | 增兵 | 行为（姿态） |
|---|---|---|---|
| 扎根 | 0~0.15 | 少量（后勤 + 2~3 近战） | 修工事、守线、飞行待命（fortify） |
| 集结 | 0.15~0.40 | 渐进补兵 → 补齐基数 | 工事前推、巡逻侦察（fortify→patrol） |
| **第一波** | 0.40~0.55 | 大量（+~50% 基数） | advance→mass；打残（损 25%）→ withdraw 回防 |
| 再集结 | 0.55~0.75 | 持续增兵 + 工事前推 | 防御修复 → patrol 再试探 |
| **总攻** | 0.75~1.0 | 满编/额外额度 | assault：全力以赴、盾也压上；**工兵停挖壕、续掩体、掩护射手**（《工兵架构.md》§8） |
| 入夜 | 1.0 | 停增 | 总攻持续到被清完（只结算战绩） |

`schedule(t)` 分段线性锚点：0.10@0.10 · 0.25@0.30 · **0.45@0.45（第一波）** · 0.60@0.65 · **0.90@0.80（总攻）** · 1.0@1.0。

- **兵力放行**：`ledger.releaseCap = ceil(total × releaseAt(t01))`（0.20→0.50→0.75→0.95→1.00）；
  `canSpawn/remaining = min(total, releaseCap)` —— 早间只放少量，第一波/总攻两个波峰放宽；
  基数 ≈30（±浮动），第一波 ×1.5 ≈45、总攻满编；可附加精英/Boss（`swarmUid=0` 不入账）。
- **撤退安全阀**（波内）：loss ≥25% → withdraw 30s → 防御修复 → patrol 再集结；
  总攻内 loss ≥60% → withdraw（`aliveRatio<0.4` 基准在进总攻时重置）。
- **UI 播报**：`Director` 已退化为播报器（mass→预警 / assault→开战 / 回落→清除），**不再产兵**。
- 实现落点：`SwarmCommander` 读 `dayT01`（太阳钟 6:00=0 / 18:00=1）；挑衅在 `PostureFn` 内衰减；
  `?swarmdbg` 显示 `态势 / p / 日程 / 挑衅`；调试可用 `commander.debugDayT01` 拨日程。
- **进攻队列（BattleLine）**：线位只是"刚整队那一拍"的**短暂队形调整**（TTL 3s），
  **只对非攻击小队生效**（攻击中的队始终执行攻击目标）；只整**近战进攻队**（盾/突击/混编）。

## 3. 决策链：大队（命令轨）→ 队长/小队（寻路轨）→ 个体（执行）

> **命令是命令，寻路是寻路（§0 双轨）**：本节是命令轨；寻路轨 §5。大队只管发令/撤销，

### 3.1 战术能力表 `UnitTactics`（唯一来源）✅

- **任务分派两段**：① 引擎（大队）`engineMissionFor` → 大任务（粘性：只在落点/态势代次/施工阶段切换时重派）；

### 3.2 大队 = 锚 + 意图（📐 指令格式定稿）
``` 
SquadOrder = { anchor, intent, coarse, ttl }
  anchor = { kind:'区块', regionId } | { kind:'小队', squadId }   // 目标地点/目标队伍
  intent = 攻 | 守 | 守卫 | 集结 | 偷袭 | 撤退                    // 战术命令
  coarse = 走廊级大致路径（少量路点；初级寻路副产物）             // 小队参考，可换
  // 紧急度不入令：谁读谁按舰船距离算（§1.5 urgency 圈）
```
- **发令三件套**：目标（地点/队伍锚）+ 大致路径（coarse）+ 战术意图（intent）；三者缺一不可达核验不放行；
- **命令不可变（2026-09-22 定稿）**：`SquadOrder` 发出即冻结——**覆盖**（大队发新令，seq++ 整体替换）
  或 **中断**（撤销/作废）是仅有的两种后继；**原地修改一律禁止**；
  小队对大队命令**无覆盖权**：只能申报请求（§3.4），批准后**由大队发新令覆盖**；否则等大队自主修改
  （自主修改本身 = 覆盖新令，不是改旧令）；
- **coarse 是软参考**：只约束"大方向别离谱"，选格仍以 `scoreFor` 三参数合成为准；小队可随时弃用换更优走廊；
- **发令前 · 初级寻路核验（📐 大队侧粗查）**：目标区块/小队锚做**粗可达性检查**
  （簇级图可达、直线走廊未被硬边界封死）；不可达 → 就近缩目标 / 换目标 / 撤令；
  只算"命令能不能落地"，顺产**大致路径 coarse**（走廊级软参考）随令附带——细路径仍归小队（§5）。
- **锚解引用只在大队层**：`kind:'小队'` → 解析成"该小队当前所在语义区块 + 朝向"，
  下发到队长的**永远是位置型目标**；队长**永不查别的队**（防帧序依赖/跨队耦合）；
- **事件驱动重发**（低频 1~2Hz 或事件，非持续查）：锚跨区块 / 位移超 N 米；
  锚小队并队·换队长·阵亡·失联；意图完成；TTL 到期；
- 解引用附**锚精度/是否休眠**（L0~L3 位置精度不同）→ 队长据此收放守圈（贴近守卫 ↔ 区域守卫）。

### 3.3 队长/小队 = 寻路自治 + 状态上报（✅ P4-1：拆步 + progress(k/N) 落地）

> **⚠️ rts 现状（2026-09-24）**：拆步/progress **未接线（休眠）**——`issuePath/stepK/noteProgress/scoreStep` 全库无调用点；成员调遣实际在 `SquadDispatch`（寻路=ensurePath+锚点，非队长 argmax 拆步）。分解矩阵里的 `taskX/taskZ` 也已收编：**只有工兵**（`EngineerDispatch`）写成员任务，见 §14。

- **上报自身状态**：progress、伤亡比、接触情报（`shareContact`）→ 大队据此裁决（批准升级/等/撤）；
- 步骤可在**同区块内替换**（地形/敌情），大目标不变 → 不触发大队重发；

### 3.4 回撤与任务取消（📐 两通路）——撤销权只在大队
- **触发（小队上报，大队裁决）**：伤亡比超阈（沿用 withdraw 60% 口径）、目标不可达、长时间无进展、弹药/血量见底；
- **命令是命令**：小队**没有覆盖/撤销权**——只有上报状态，撤不撤由大队定；
  仅自身严重（伤亡超阈等）时可**申报请求**，批准后**由大队发新令覆盖**（不可变律下只有覆盖、没有修改），
  否则等大队自主修改（同样以覆盖新令形式发生）；
- 通路①**队长申报**：`requestRetreat(原因/伤亡/位置)` → 黑板 → **大队裁决**（批准/驳回/改派）；
- 通路②**大队自主**：按小队评级直接下发撤退令，取消在途任务；
- 效果：`SquadOrder` 立即失效（seq 作废）→ 转 `撤退`/就地守；撤退途**不追打**（`holdFire`/`fireOnArrival`）。
- 防成环铁律：**保护队不听被保护队**；被保护队诉求走 `requestSupport/shareContact` → 大队。

## 4. 唯一执行层（`SteerPick` + `AtomExecutor`）✅

```
每决策拍：16 向 + hold 候选
① 硬否决（不是低概率）：表 blockedAt（墙/坑水）、>40° 陡坡
② 打分：W_PATH(1.6)·cos(期望) + W_TABLE(0.8)·表分 + W_TURN(0.7)·上次方向
        − W_AVOID·人群同向 − 水反向 +（禁区逃离/上岸权重）
③ softmax(温度 0.18) 抽样 → 选一个 → 承诺 0.5s；换向迟滞 1.12×
④ 已在硬边界内：不否决、优先逃离；分离只做惩罚 + 移动后物理外推（不合成方向）
原子：移动原子（forward/back/strafe/hold）× 开火（fireProfile：>20m 散射 / <20m 精准）
```

**移动方向纪律（禁止向量合成）**
1. 不做"流场 + 分离 + 编队 + 避障"相加；对候选方向**逐个打分 → softmax → 选一个**；
2. 路径只提供"下一个 waypoint"；方向 = 最接近该 waypoint 的 16 向候选（不插值）；
3. 分离/避障**不产生方向**：只做否决/降权；承诺窗内只做视觉平滑；
4. 决策频率：移动选择 10Hz、开火独立冷却；L1/L2 低频。

**命令 → 权重（层只写权重，执行层只算一次）**

| 命令/指令 | 改动的权重（示意） |
|---|---|
| advance / press | forward↑、fire↑ |
| retreat / fallback | back↑、awayFromThreat↑、fire↓ |
| holdFire | fire→0（权重归零的硬态） |
| focusFire(target) | 对该目标 targetWeight↑（其余↓） |

| suppress | fireRate↑、forward↓（原地） |

## 12. 管线自评（2026-09-21 · 诚实版）

**结论一句话**：**架构已经"理论正确、单源可调"，但"好玩/聪明"完全没被证明**——
问题不在结构，在**参数、观感与验证缺失**；本轮表层设计（L1/L2/L3）是补课，不是翻新。

- **真正验证过的**：旧表权重方向（前期外围高地 / 总攻舰旁战壕，meanTopD 108→22）；
  节律链路（p/挑衅/releaseCap 两波峰）；任务/岗位稳定（无 8m 跳变、0 kind 翻转）；
  代理执行层卡住 0~2/59、误入硬边界显著下降。
- **设计已定、完全没有实测的（当前最大风险）**：L1/L2/L3 表层 + 指令链新格式（anchor/intent）
  + 多步自主 + 回撤申报 + 路径锁定白名单。
- **价值**：单源（语义表 + 工件表 + 兵种表 + 一条执行链）让"加战术"= 加权重/加意图；
- **代价**：状态面继续变多（anchor/意图/步骤/回退申报）——必须配"状态可观测"（`?swarmdbg`/RTS）；
- **边界**：聪明感还依赖动画前摇/预警/音效与节奏，AI 结构只决定"不犯蠢"。

**下一步只做三件事（先量化，再谈聪明）**
1. **施工速率**：`builtSlots` 每分钟增量（工程队并行是否真生效）；
2. **卡住/回收率**：`stuck` 回收次数/分钟（§3.6；旧 `reapLost`/远距回收已废除）+ 硬边界内单位占比；
3. **决策稳定性**：每队 mission/目标变化次数/分钟 + **路径重规划次数/分钟**（本轮新增）。
> 三个指标达标后，再进 RTS 项目做参数搜索；在此之前不再加新战术功能。

## 13. 大队战术层：编制比例 + 工事规划（2026-09-23 设计定稿）

### 13.1 编制按比例（动态补充）
- **目标占比表**：按角色（盾/突/远/后勤/工兵）定理想比例；**场上实际占比低了就补**、超了停补。
- 每评级拍统计占比 → 缺口最大兵种优先补（走 `CommanderSpawn`/回收名单通道）；受大队上限/刷兵预算约束。
- 探针：占比表 + 缺口 + 补充计数。

### 13.2 直接读评分（不另做需求图）
- 工事需求 = **`TerrainScore` 的低分位置**（平坦宽阔、无掩体、裸露隘口）——"**工兵补评分**"：
  在低分处修 cover/wall/trench，把该处评分抬起来（不新造需求图，复用既有评分系统）。
- ★ **同源闭环**：评分系统与贪心寻路同源——`pathMulFor(兵种)=掩体折扣×兵种权重` 直接作贪心段"安全项"，
  `scoreForUnit` 供 Decide 选位。**工兵补评分 = 直接改善寻路安全项与选位分**（一条链，无重复口径）。
- 既有工事（`HoleTable`）会改变 cover 分/寻路折扣 → 评分自然反映"还差哪里"，形成闭环。

### 13.3 重要位置 + 分兵施工（分区多线程）
- 取**评分最差的 top-K 格**（聚类去重）为重要位置；按位置选型：隘口→wall/cover；平坦→cover；进路线→trench。
- ★ **环状固定分区（包围舰船；性能纪律）**：围绕**舰船**的环带（内 24m / 外 90m）切成**固定 8 扇区**；
  每扇区一个**安全值**（区内最低评分）+ 最危险点；**摊销刷新**（每次只重算 1 个扇区，全区 ~4s 一轮）；
  **优先派安全值最低的扇区**；环带随舰船移动（换落点重置）。**不再每队手扫全环**。
- ★ **工兵专属目标函数**（不上升为通用导航设施）：`FortifyPlanner.targetOf/spotFor`——
  扇区**未达标 → 最危险点**（补评分）；**已达标 → 扇区内随机位置**（继续干）；所有调用方共用此函数。
- **分区制（多线程）**：**一队一扇区、不得重合**（认领制，`claims`）；
  **粘性：一直干到引擎调走**——达标不换区、持续在本区补评分；仅当**别的未认领扇区明显更危险（低 ≥1.0）**时抢占换区；
  **一队管一大片**；**每队 3 工兵足够**（小队规模约束）。
- ★ **分区分配受事态函数影响**（`PostureFn`：frontP / 态势 / 日程）：
  fortify 期只分近段分区；frontP 提升 → 逐段开放更前分区；assault → 停止扩张、只补线；withdraw → 分区回撤。
- **选址优先级（工兵）**：**越靠前、越空旷/评分越差 → 优先级越高**
  （`priority ≈ 前进度 × 空旷度 × 缺掩体度`）。
- **前推纪律**：**不能一上来就推进**——先修完本分区（评分达阈）才进下一阶段。
- 打断：前沿越过工地 / 威胁临近 → 撤。

### 13.4 连通与推进（阈值驱动；**与"等新任务"并行**）
- **并行语义**：判**执行轨**（修最危险区 → 到阈值 → 扩大范围修 / 连通战壕）与**监测轨**（持续找新任务）**同时运行**——
  不串行等待；监测到明显更危险的新区（低 0.5 分以上）→ **抢占换区**，否则粘滞防抖动。
- 关键位修完（该片**评分抬到阈值**）→ **连通阶段**：相邻关键点 <16m 串 trench，连成一片防线（**全区连通后才谈前推**）。
- 连通完成 **或** `frontP` 闸门允许 → **前推**：取下一带低分格，回到 13.3。
- 阶段机：S1 施工 → **S1b 连通** → S2 就绪/前推。

### 13.5 与现有件关系
- `EngineerCorps` 扩 `FortifyPlanner`（低分位选择/优先级/连通阶段，**直接读 TerrainScore**）；`CommanderSpawn` 加 `RosterController`（占比缺口驱动）。
- 命令铁律不变：大队只发**区块级**命令、命令对象只读、每令过**可行性门 + 事态闸门**、同锚 ≤2 队。
- 探针：低分格 top-K、工兵队↔工地绑定、连通进度、占比缺口。

### 13.6 指挥链闭合：引擎 → 队长 → 代理（2026-09-23 定稿）
- **结构**：引擎给**区**（8 片、最危险优先逐个分配、一队一区、粘性+抢占调走）；队长是**干活的**，两名代理是**辅助**。
- **位置函数（工兵专属）**：`FortifyPlanner.targetOf/spotFor`——未达标→最危险点；达标→区内随机；
  **选点必须过道路可行性**（`walkableLine` 校验，起点=**队长位置**；队长缺失才退质心）。
- **三点一致**：引擎发令目标 = 位置函数输出点 = 注入件点——"工兵得到区之后，对着这个函数用寻路"。
- **代理移动大简化**：非队长成员**只认队长**（朝队长走 + 局部 steer；双阈值滞回 5/8m 防挤圈）；
  成员任务（taskX/Z）**不再驱动移动**；成员级走廊/复杂寻路（MemberTaskNav）退场。
- **队长移动**：>15m 走队级指令目标（走廊锚点+阵型）；≤15m 直走件点；≤2m 停。
  队级走廊 = **LOS 10m 短路 + 贪心校验**（一次一跳、滚动重算；无推进才回落可行性 BFS）。
- **卡死链**：朝队长仍卡 → 传送队长旁（可行格）→ 失败销毁回收（严格回收不变）。
- **待收尾**：个别队长长腿不推进（探针定位：订单目标/走廊点/队长指令/位移 四样并打）。

### 13.8 事态环形活动区 + 区域任务 + 快车道（2026-09-25 实施定稿）

**A. 事态函数 = 环形活动区（硬约束）**
- 语义：**上限 `frontMaxD`=最远允许**、**下限 `frontMinD`=最近允许**（距舰半径）。
- **一日推进（2026-09-25 定稿）**：`ringBounds(t)` 直接给 (下限, 上限)，间距保底（≥120m）：
  **宽环 → 第一波大圆 → 甜甜圈 → 点**
  - `0.00-0.20` 初始宽环 `(ffrontD−80, ffrontD+80)`
  - `0.20-0.45` 收成**大圆** `(0, 90)`；`0.45-0.62` 大圆驻留（第一波：可到舰、不许跑远）

  - `0.82-0.90` 收拢为**点** `(0, 0)`；`0.90-1.00` 点驻留（总攻）
- **初始宽环**（2026-09-25 用户定）：以原前沿距离 `ffrontD` 为中心、**±80m** 的宽环（中心回原位，不是整体外推）。
- **发令冷却（替代时效）**（2026-09-25 用户定）：命令发出去一次后，**短时期内（8s）不再给同一队发**；
  引擎令 TTL 拉长存活（≥60s），**不靠命令时效续命**。例外：事态变动（stage/posture/环/波次签名变）或队重伤（血比<0.5）→ 允许立即重发。
- **磨蹭兜底（§13.10 已实施）**：30s 窗口净<3m 且路径>15m 或反转≥6 → 沿队令方向**向前 20m**；
  无令 → **兵力最稀处**（20m 格计数，<60m）；同队 30s 冷却。
- **层级符合度（已实施）**：后排（远程）比前排（盾/突）更靠敌 >15m → 越位，把后排队目标**拉后 15m**（`rank_fix`）。
- **切向为主 + 朝向舰船 + 环内落点**（2026-09-25 用户定）：
  1. **判断依据以"舰船半径的切向位置"为主**：选位/评分看**环上的角度位**（扇区/切向槽位），径向距离作为约束（在环内）而非主要偏好；
  2. **移动指令主要朝向舰船方向**：推进类命令的目标角保持（切向），径向**向内**收——即"沿环走位、朝舰推进"；
  3. **落点强约束**：引擎移动令、队长自主令、以及**锚点/站位计算结果**（resolveAnchor 的护卫点/掩体位/游弋点）都必须**夹在事态环内**（`clampToRing` 全链覆盖）。
- **切向检测 = 同种兵扎堆分离**（2026-09-25 用户定）：同 `mobKind` 小队互相距离 <50m（扎堆）→
  **横向拉开 + 向舰船方向内收**（笛卡尔分解：横向 20/35/50m × 向舰 20/10/0m，离邻居更远的一侧优先）
  ——**散开且压上**；候选逐个过"环内 + 可站 + 直线可走 + 有向可达"校验，不行换下一个。
- **收拢态**（上限<下限）→ **上限主导**：全员必须收进舰旁。
- 硬约束两条：
  1. 夹环：`SwarmCommander.clampToRing` 单源——`issueChecked`（引擎令）+ `SquadTactics.issue` 的 `ringClamp`（**队长自主令**）同门；`retreat`/`rear` 豁免；计数 `cmdLogRingClamps`；
  2. 每拍巡检各队质心，越界（太近/太远）连续 2s → **强制长寻路令**回环内（`lastDecision=force_in/force_out`）。
- 单源：`SwarmCommander.fortifyBand{rLo,rHi,minD,maxD,frontP,pushM}`（引擎 tick/小地图/时间轴共用）；施工带 `rHi ≤ 上限`。
- 第一波时段起**停止新增施工**（既有件收尾 → S1→S2），避免施工期闸门钳制挡住进攻。

**B. 工兵 = 区域任务（引擎只派区）**
- 引擎把**区（扇区）**派给队；区内活由队自循环（`spot` 粘性：本区未建件还在且可达就不重取）。
- `buildIssued`（队→派件下标）：**只在无令/玩家令/件变化/将到期时换令**（不再反复下"前进"）。
- 第一波抵舰驻留：进攻队进舰 70m → 转「驻守」45s；血比<0.45 → 撤退；到期回正常决策。

**C. 升格判据 = 视野（2026-09-25 用户定）**
- `SwarmHooks.inView?(x,z)`：给了就用它判升格；未给回退原口径（离焦点 < L3_RADIUS）。
- 原游戏 = **玩家视野内变实体**；视野外友军攻击走快车道（直接扣血，不做复杂判断）。
- RTS = 相机视锥（±15% 且 <220m）；降格 `spawner.tickDemote(dt, 相机焦点)`。

**D. 快车道（代理级直接结算）**

### 13.9 评分动态化 + 长短寻路分工（2026-09-25 定稿）

**A. 动态分数（不固定相加）**
- `score = Σ w_i(事态) · feat_i`：系数随 posture/frontP/闸门阶段**动态**重算，不做"地形分+距离分"的固定和。
- **距离混合（距舰）**：`k = clamp01(1 − shipD / D_FAR)`：
  - 近舰：**距离权重 > 地形权重**（守家）；远舰：**地形权重 > 距离权重**（野战）。
  - 公式：`w_dist_eff = w_dist·(1 + (RN−1)·k)`，`w_terrain_eff = w_terrain·(1 − (1−RF)·k)`。
- 系数变化（事态/掩体代次）→ 评分表**按新系数重算**（单源 TerrainScore；parity 断言改"同系数一致"）。
- **距离系数时间增益**（2026-09-25 用户定）：`distGain = 1 + 24·t01`——随时事推进距离权重不断增大，**日终 ×25 彻底碾压地形**（总攻只看"离舰多远"）。

**B. 长短寻路分工**
- **长行军**（换区/集结/抵舰）→ **长寻路**（FeasibilityPath 全走廊；表图 BFS + LOS 拉直）。
- **短程**（交战/巡逻/驻守/换位）→ **短寻路**（LOS 10m 贪心短跳，滚动重算）。
- **工兵就近施工** → 短寻路（目标近，自然短跳）；换区远行 → 长寻路。
- 判据：目标距离 > `LONG_PATH_DIST`（默认 40m）→ 长；否则短（`SquadNavigator.ensurePath` 分流）。

### 13.10 战术层级 + 队形识别 + 磨蹭兜底（✅ 已实施：rts R17/R21——`BattleLine` 角色纵深 + `fallbackTick` 磨蹭/扎堆/层级）

> **架构原则（用户定 2026-09-25，总纲）**：
> **宏观有序、微观无序——"能在无序中稳步朝舰船方向推进，就是最理想的架构"。**
> - **宏观有序（引擎统一设定）**：目标（朝舰推进）、边界（事态环）、分布（切向均匀）、序位（前排/后排层级）。
> - **微观无序（队自决）**：各队自主寻路/走位/队形，不要求步调一致；允许绕、散、慢。
> - **引擎只在四类时刻介入**：① 事态变动（环/姿态/波次）② 队重伤（血比<0.5）③ 扎堆（同种兵<50m）
>   ④ 磨蹭（30s 净<3m 且路径>15m / 反转≥6）。其余时间**少发令**（8s 冷却），命令靠长 TTL 存活。
> - **验收看宏观**：全队**净推进量**（离舰距离均值）单调下降；局部乱不扣分。

**A. 战术层级（引擎掌握全局）**
- 引擎战术逻辑分四层（自上而下）：
  1. **战略层**：事态函数/环形活动区/波次节奏（已有）
  2. **战术层（新）**：按**兵种角色**定位纵深——盾/突击=**前排**（顶线、掩护）、远程=**后排**（掩体输出/驻守）、
     后勤/工兵=**中后**（施工/护卫）、飞行=**空中层**；`BattleLine`（前/中/后排+横向车道）升级为**角色序位**：
     `frontRank(role)` 决定各队纵深槽位；同槽冲突 → 横向车道分散。
  3. **队级层**：队长拆步/走廊（已有）
  4. **个体层**：队长→成员指令（已有）
- 目标：盾兵往前冲、射手在后排——**队与队之间**不抢位、纵深有序。

**B. 队形识别 = 层级符合度判定（2026-09-25 用户定）**
- 队形好不好，**只看符不符合层级**（角色纵深序）——不做复杂几何预设。
- 判定（2s 采样）：把成员位置**沿队前进方向投影**得到实际纵深序；应有序 = `frontRank(role)`：
  **盾/突击（前排） < 远程（后排） < 后勤/工兵（中后）**（投影值越小=越靠前）。
- 指标：**逆序对数**（实际序中前后颠倒的角色对数量）+ **前缘占用率**（前缘是否由前排角色占）。
- 不符合（逆序对 ≥2 或前缘被后排角色占）→ 引擎下发**局部调整令**：只把错位成员/小队挪到对应纵深槽位
  （复用 `formationOffset` + 锚点），**不全队重排**（少发令）。

**C. 磨蹭兜底（反复磨蹭 → 强制动作）**
- 检测（1Hz/队）：`净位移 <3m 且 路径长 >15m`（原地磨蹭）或 `方向反转 ≥6 次/30s`。
- 兜底动作（按优先级，走 `issueChecked` 同一门）：
  1. **向前移动**：沿当前队令方向推进 20m（`advance`，短 TTL）；
  2. **向兵力空虚位置部署**：查 8 扇区/战场格**己方兵力密度**，选最稀处（距当前 <60m）→ `advance`（mission `regroup`）。
- 与**少发令闸门**关系：兜底令计入"事态变动"签名；同一队 30s 内不重复触发（防兜底刷屏）。

**D. 数据来源（全部现成）**
- 队形/磨蹭：`swarm.squads`（成员位置/血量）、`tactics.board`（命令/走廊）、`cmdLog`（台账）
- 纵深槽位：`BattleLine` / `SquadDoctrine` / `formationOffset`
- 兵力密度：`fortify`（8 扇区）/ 战场格计数（按 20m 格统计敌我数量）
