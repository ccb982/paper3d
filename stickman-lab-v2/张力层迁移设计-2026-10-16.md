# 架构文档 —— 四层 + 提案制（2026-10-16 定稿）

## 〇、最终定稿（2026-10-17，用户："我是真的讨厌架构不可控"）

### 层结构

```
┌ 直控层（手动，PRI 100）——用户拖拽
├ 动作层（手动写动作，PRI 40）——walk/bow/idle/singleLeg
└ 伺服层（自动，不可手动写）:
    ├ 预测（PRI 60）——反射 + fallProtect（预判坠落写保护动作）
    └ 保持（PRI 20）——基础力 + 张力 + 回正力 + 柔性足
```

### 保持层的三个机制（正交、不重叠）

| 层 | 机制 | 管 | 参数 |
|---|---|---|---|
| **基础力** | 常值力矩 | 静态载荷（重力/支撑） | **力矩表**（每关节每轴） |
| **回正力** | 弹簧 + 方向项 | 姿势形状 + 平衡 | **目标角表** + kp + K + 权重表 |
| **张力** | 单向阻尼 | 动态耗散（防振） | kd |

- **柔性足 = 独立**（抓地；一般无动作，直控）
- 每层**一个机制、一组参数、一张表**——改哪层动哪层，完全可控
- 基础力/回正力/张力的**写手各一个**（不许分散到多处）
- gcomp：**只作标定工具**（量出表值），不进运行时

### 合并清单（从现状到定稿）

1. 回正力：supportClean（腿）+ trunkClean（脊柱）→ **合并成一个写手**（全身统一弹簧+方向项）
2. 张力：drive 被动 + 伺服弹簧 + stability 单向阻尼 → **统一成一个**（单向阻尼）
3. 基础力：gcomp 运行时 → **删**（表就是基础力；gcomp 留探针标定）
4. 权重表/目标角表/力矩表：**唯一来源**（baseTable）

**三层总览（用户定稿 2026-10-16）**：
```
直控层（手动，100）
动作层（手动写动作，40）
伺服层（自动，不可手动写）:
  ├ 预测（反射+fallProtect，60）——预判坠落写保护动作
  └ 保持（基础力+张力+回正力+柔性足，20）——维持标准态/当前姿态
```
- 预测层**不能手动写**（自动）；手动写动作的=动作层
- 默认预测(60) > 动作(40)（保护优先）；`ACT_OVER_PRED=1` 翻转（动作 65 + 预测整段让位）

**伺服层=保持**（维持标准态/当前姿态，不产生主动轨迹）；
**动作参数可手动指定**（用户："很多动作人类就是预先知道要发多少力"）——动作调伺服**参数**（偏置/增益/目标），不写关节；
**默认预测层>动作层**（保护优先）；**可手动声明翻转**（动作优先，甚至该部分只动作层——预测层整段让位）。

## 一.5、★ 回正层 v2 设计（2026-10-16，论文依据 + 用户定调）

> 用户定调："**回正其实是需要完整力链的，而不是仅仅是被动算一个力**——给回正也加一个控制层。"

### 背景（振动专项发现）

- 当前回正力 = 高增益单点弹簧 → **19Hz 极限环**（实验证明这是当前唯一的稳定机制：低通滤掉它 → 0.95s 倒）
- 低频模式不稳（5-6Hz 倒下）——**单点弹簧结构在低频无相位裕度**
- 能量耗散链路分析（见《能量耗散链路分析.md》）：振动与稳定同源

### 论文依据

| 论文 | 结论 | 对我们的含义 |
|---|---|---|
| **Peterka 2002**（J Neurophysiol 88:1097） | 神经控制器=**PID**（T_a=K_P·e+K_D·ė+K_I·∫e）；**K_P 总是抵抗重力所需的 1.33 倍**；延迟 ~150ms 约束增益 | 我们的 K_P 要按 **1.33×mgh** 重标（当前是拍脑袋的高增益） |
| **双回路结构**（Peterka 2003；人-机器人对比 PMC2767299） | Loop1=角度 PD；**Loop2=低通滤波的力矩反馈（正反馈）**——PID 解释不了 <0.05Hz 数据，加 Loop2 才行 | **Loop2 是低频稳定的缺失环节**（直接对应我们的低频不稳） |
| **特征运动模型**（Alexandrov 2005, PMC1430400） | A 特征运动（踝主导、大惯性）管**慢扰动**；H 特征运动（髋主导、惯性 1/5）管**快扰动**；独立回路 | 回正层分**踝通道（慢）+ 髋通道（快）** |
| **Kiemel 2011**（J Neurosci） | 反馈含加速度项（相位超前 >90°，不只是 PD）；目标=**最小肌肉激活**（不是最小摇摆） | 超前项方向正确；控制目标定成"省力稳定" |

### v2 结构

```
回正层 = Loop1（PD：kp·e + kd·ė）
        + Loop2（低通滤波的 τ/CoP 反馈——正反馈）
        + I 项（低频误差消除）
        分通道：踝通道（慢，A 特征运动）+ 髋通道（快，H 特征运动）

标定基准：K_P ≥ 1.33 × mgh（mgh = 重力 destabilizing 力矩）
目标函数：最小肌肉激活（省力稳定），不追求零摇摆
```

### 实施顺序（每步独立验证）

1. **Loop 2**（低通力矩正反馈）——低频稳定的关键
2. **K_P 重标**（1.33×mgh）
3. **通道分离**（踝/髋）
4. **每关节每轴参数重做**（角色表见下）
5. 验收：19Hz 消失且站住 + 长时（5-10min）

# 张力层迁移设计（2026-10-16）——三层职责分离


> 用户定调："姿势保持弹簧放在回正力一部分，回正力不才是姿势保持的；张力=纯单向阻尼。"
> 本设计**先定职责与迁移映射**，代码按此实施。

## 一、三层职责（互不混淆，检验方法各不相同）

| 层 | 唯一职责 | 写手/通道 | 检验方法 |
|---|---|---|---|
| **基础力** | **只精确抵消重力**（逐关节，无自由参数） | gcomp（`antiG` 叠加通道） | 对账：重力=实际（6/6） |
| **回正力** | **把姿势拉回标准态 + 方向修正**（弹簧+方向项+预算） | supportClean（PRI.action） | 漂移收敛（std−θ→0）、判死时间 |
| **张力** | **耗散**（只压速度，不定义平衡点） | tension（PRI.servo） | 振荡衰减、对账不变（不产生新力） |

**关键区分**：
- 基础力是**无参数**的（对账可验证）；
- 回正力**有 kp/方向项参数**（"回正"的定义：弹簧把偏差拉回标准）；
- 张力**只有阻尼**（不可能顶住错误平衡点 → 天然不打架）。

## 二、旧张力层拆分映射

| 旧张力层组件 | 去向 | 具体实现 |
|---|---|---|
| `kp·(rest−θ)` 弹簧（保持） | **→ 回正力** | supportClean 的回标准弹簧（`_ref`=标准捕获）——**已存在，就是回正力** |
| `kd·(−ω)` 阻尼 | **→ 张力层（重做）** | 单向阻尼：`dev·vel>0`（往外偏）才写 `τ=−kd·vel`，回程零写入 |
| `rest=0`（骨架 rest） | **废弃** | 骨架 rest 0 ≠ 标准站姿（差 ~9°）→ 旧张力出 +104 抵基础力的根源 |
| 让位守卫（直控/pin/动作/踝） | 保留语义 | 各层共用 |
| 目标捕获 | 保留 | 首帧捕获标准站姿（`legRest` Map，与 supportClean 的 `_ref` 同源同刻） |

## 三、为什么弹簧必须归回正力（而不是基础力）

1. **基础力=精确抵消重力**——如果基础力里带弹簧，对账就永远对不平（弹簧在标准态=0 才不干扰；一旦偏了就出"非重力"的力，污染对账口径）
2. **回正力=姿势保持**——弹簧的目标（标准态）、kp、方向项都是"回正"参数，天然属于回正层
3. **旧张力层的错误**：它的弹簧目标=骨架 rest 0（不是标准站姿）→ 等于"回正到错误的位姿" → 与 gcomp/回正弹簧三向打架
4. **重复计数**：旧张力弹簧与 supportClean 回标准弹簧**同时在拉**（kp607 vs kp500）→ 总刚度~1100，且目标不同 → 系统性偏移

## 四、实施顺序（每步独立验证，验证过才进下一步）

```
步骤 1：基础力（已完成，见《基础力修复存档-2026-10-16.md》）
   gcomp 符号（髋'+'）+ 膝惯量下限 3.0 + 载荷混合 + 站立套偏置清零
   → 对账 6/6 精确互补 ✓

步骤 2：张力层 → 纯单向阻尼
   stability ⓪ 块：删除 kp 弹簧（setAngle PD 也一并清），只留 dev·vel>0 的阻尼
   验证：对账不变（张力不产生新力）；无新的振荡

步骤 3：回正力接管姿势保持
   supportClean 的回标准弹簧（已存在）→ 确保启用且目标=标准（_ref 首帧捕获 ✓）
   + app 每帧调用 supportClean（正常站立也走它）
   验证：漂移收敛（std−θ 有界）；对账保持 6/6（回正力在标准态=0，不污染基础力）

步骤 4：回正力方向项（§4.2 逐个）
   foot0/foot2（CoP）→ hip0/hip2（CoM）→ knee2（高度）
   每个单独验符号/增益，回读判死时间

步骤 5：摆动腿持位（回正力的一部分）
   抬腿结束后摆动腿=回正弹簧保持标准位（当前自由折叠 hip2 168°=四足爬行根因之一）
```

## 五、当前代码状态与缺口

- **已有**：supportClean 的回标准弹簧（`_ref` 标准捕获 ✓）、gcomp（符号/下限/混合，存档补丁）、法庭/探针
- **缺口 1**：stability ⓪ 的旧张力 PD 还在（kp607 弹簧 + 骨架 rest 0）→ 步骤 2 拆
- **缺口 2**：app 正常站立不调用 supportClean（只动作时走）→ 步骤 3 接
- **缺口 3**：摆动腿持位档未标定 → 步骤 5
- **注意**：步骤 2+3 必须**成组**上（只删张力弹簧不上回正弹簧 = 姿势无保持 = "四足爬行"；这是 2026-10-16 的实测教训）

## 六、验收标准（法庭）

1. 对账：6/6 关节 重力=实际（基础力精确）
2. 放开后：|roll|、|pitch| 不增长（回正力把姿势钉住）→ 12s 存活
3. 无振荡/无爬行（张力阻尼+回正弹簧配合）

# 深蹲（设计定稿 2026-10-17 用户）

## 分工（用户定调）

- **蹲下的状态（hold）= 三层架构**：基础力 / 回正力 / 张力 在蹲姿态下的版本（先做）
- **下蹲 / 起立 过程 = 动作层**：动作层负责运动（慢速）

## 蹲下的状态（先做，三层）

1. **蹲姿态角表**：髋/膝/踝协调（不是单膝）。
   探针实测几何可行档：`hip=+1.0 / knee=-1.0 / foot=-0.3` → 头高 79cm（SQUAT=1）
2. **蹲底基础力表**：静态维持力矩（探针实测——注意避开崩坏时的假饱和值）
3. **回正力目标角**：supportClean 的 baseAng 表切到蹲姿态
4. **张力层**：照常（单向阻尼）

## 下蹲 / 起立（后做，动作层）

- **慢速**：下降 2-3s（论文标准，控制式离心）
- **CoM 轨迹**：下降全程 CoM 投影压脚中线（论文 mid-foot）——这是核心难点
- **躯干前倾 30-40°** 配 CoM 不动（否则骨盆后移带 60% 体重往后 → 后倒）
- **起身**：蹬伸增量（论文：≈下降力矩 + 加速度项，自重蹲两者几乎相等）

## 论文数据（存档）

| 项 | 值 |
|---|---|
| 膝伸肌峰值力矩 | 100-300 N·m（负重杠铃）；归一化 5.5-6.5%（身高×系统重） |
| 髋伸肌/踝跖屈 | 同量级 / 50-300 N·m |
| 峰值位置 | 三关节都在蹲底（~55% 周期） |
| 时间 | 下降 2-3s 控制式；自由速度全程 ~1.9s |
| 踝背屈 | 全蹲保脚跟需 ~38.5° |
| 下降 vs 上升 | 自重蹲几乎相等（差几个百分点）；负重则上升略大 |

## 已知坑（2026-10-17 实测）

- 旧 squatPhases：髋目标只来自俯仰反馈（起始≈0）→ 膝盖弯了髋没屈 → 往后坐 → 倒
- 新 squatDeepMotion（固定姿态角）：躯干前倾 0.35 不够 + 无 CoM 轨迹 → 后倒（x -185）
- **结论：必须 CoM 轨迹 + 躯干前倾协同（论文的 mid-foot 控制），单给姿态角必倒**
