# 蹲姿稳定架构 v16：两段 PD/ID 命令层

日期：2026-11-14  
状态：**定稿方向**。正式命令层是两段 PD/ID；QP 仅为实验分支，默认关闭。

---

## 0. 结论

用户的设计分层是正确的：

```text
命令层
  ├─ CoM 段  solveSquatHipDynamics   → hip2 + knee2 基础力
  └─ CoP 段  solveSquatShankDynamics → foot2 基础力

执行层
  muscle(): τ = 基础力 + (−b·qd) + (−k·softzone)
  drive.td = −B·ω，Bmax = 0.8·I_low/dt
```

- **两段命令层是正式控制器，不是 fallback。**
- **基础力由命令层控制**；CoM 由大腿段控制，CoP 由小腿段控制。
- **QP 不是命令层的必需品。** QP 只是完整逆动力学/带约束力分配的一种求解方式。
- **QP 默认 off。** 当前 QP 原型未通过 5-seed、接触力、脚滑验收，不能接管基础力。
- **一个关节只能有一个基础力来源。** QP 模式不得同时叠加两段命令层、`supportKd`、hip guard。

## 1. 为什么废弃 v15 的“QP 命令层”

v15 假设：

```text
QP 命令层 → 全部 18 轴基础力 → muscle 执行
```

实测问题：

1. **竖直接触力模型错误**
   - QP `fz 和 = mg`，实际地面力到 1.5–2 倍体重；
   - 去掉后 QP 选 `f=0`；
   - 说明 QP 没有真正的 base 竖直动力学 + 接触力模型。

2. **基础力来源不唯一**
   - QP τ、两段 IK/ID 基础力、`supportKd`、被动 K、hip guard 同时存在；
   - 实测 QP τ=115，执行层 `cmd=231`；
   - 关节被两套基础力同时拉。

3. **任务/约束体系混乱**
   - CoM/base 在 soft / hard / motion-slack 之间反复；
   - posture 被用于支撑腿；
   - `qdd` 顶 100；
   - motion slack 让 QP 宁可松任务，也不给接触力。

4. **接触状态不统一**
   - `Jc` 的接触点、CoP、`footContactForce` 不是同一套点；
   - QP 的 `f` 和实际 GRF 对不上；
   - 脚先侧滑，再被顶飞。

5. **执行层放大**
   - `supportKd=10` 时 `10*qd≈116N`，把 QP 115 放大到 231；
   - 即使 QP 对，执行层也会把基础力改掉。

结论：**不是 QP 本身错，而是拿一个未完成的 QP 直接替换了两段命令层。**

## 2. 正式命令层

### 2.1 CoM 段：`solveSquatHipDynamics`

输入：

- `com`：CoM 位置，顺序 x/z/y
- `comTarget`：期望 CoM
- `comVel`：CoM 速度
- `jCom`：3×2，CoM 对 hip2/knee2 的雅可比
- `h`：hip2/knee2 静态载荷（重力/科氏，同执行层符号）
- `tauMin/tauMax`：关节力矩范围
- `kpF/kdF`：CoM 空间 PD

控制律：

```text
F = [KpF·(comTarget − com) − KdF·comVel]        （x/z/y 三行）
τ_hip2/knee2 = h + J_comᵀ · F
```

然后：

```text
τ = clamp(τ, tauMin, tauMax)
```

这是 **CoM 空间虚拟力 + Jᵀ + 静态动力学前馈**。它不是完整逆动力学，但对慢蹲/准静态足够。

### 2.2 CoP 段：`solveSquatShankDynamics`

输入：

- `cop`：实测/估计 CoP
- `copTarget`：期望 CoP
- `copMin/copMax`：支撑域
- `fz`：足底法向力
- `h`：foot2 静态载荷
- `kpCop`：CoP P 增益（本项目 foot2 力矩正方向与 CoP 正方向相反，默认 `-3`）
- `copCap`：相对 `h` 的附加力矩上限

控制律：

```text
τ_ankle = h + kpCop·(copTarget − cop)·fz
```

用支撑域和 `copCap` 钳位：

```text
τ_lo = h + (loCop − cop)·fz·kpCop
τ_hi = h + (hiCop − cop)·fz·kpCop
τ = clamp(τ_ankle, max(tauMin, min(τ_lo,τ_hi), h−cap),
                    min(tauMax, max(τ_lo,τ_hi), h+cap))
```

这是 **CoP 位置 P → 踝力矩**。论文（Feng 2014）明确：支撑踝用**纯力矩模式**控制 CoP，支撑踝的 IK 不参与。

### 2.3 执行层

```text
muscle: τ = τ_base − b·qd − k·softzone
drive.td = −B·ω
```

- `τ_base` 只来自命令层。
- 阻尼/被动刚度是执行层，不得再被当成第二套基础力。
- QP 模式若启用，必须关闭 `supportKd`、hip guard、两段基础力叠加；当前代码已按 `wbcApply` 分离，但 QP 本身仍未验收。

## 3. 论文里的 CoM / CoP 回正

### 3.1 CoM

Feng 2014 / Koolen 2016 的共同结构：

```text
a_com* = Kp·(com* − com) + Kd·(vel* − vel)
F_com  = m·a_com* + 重力/扰动补偿
τ      = J_comᵀ·F_com + h        （准静态）
```

完整动态版本：

```text
τ = M(q)·q̈ + h(q,q̇) − Jcᵀ·f
```

- 论文用完整 ID/QP；
- 两段命令层是它的降阶版：`h + JᵀF`，不含 `M·q̈`；
- 对慢蹲、双脚支撑，降阶版可以工作；
- 要做快速动作/接触力分配，才升到完整 ID。

**当前关键缺失：**

- `comTarget` 目前是 `[supportX, supportZ, st.y0]`；
- 论文的 `com*` 来自规划/捕获点，不是写死初始高度；
- 应改为规划 CoM 或捕获点目标。

### 3.2 CoP

Feng 2014 的 CoP 公式：

```text
CoP = ( −M_y/F_z , M_x/F_z )
```

支撑踝：

```text
τ_ankle = h + Kp_cop·(CoP* − CoP)·F_z
```

期望 CoP：

```text
CoP* = clamp(com + comVel/ω, supportPolygon)
ω = sqrt(g / h_com)
```

或用支撑中心/规划 CoP。

**当前关键缺失：**

- `copTarget` 目前是 `copXFiltered − eCopX`，本质是“跟着滤波 CoP 走”；
- 论文用**期望 CoP**（捕获点/支撑中心），不是滤波 CoP；
- 应先改成期望 CoP，再做 CoP P。

### 3.3 论文引用

- Feng et al., *Optimization Based Full Body Control for the Atlas Robot*, 2014  
  - 支撑踝纯力矩控制 CoP；软约束高惩罚；CoP tracking；重量分配。
- Koolen et al., *Design of a Momentum-Based Control Framework and Application to the Humanoid Robot Atlas*, 2016  
  - 浮动基 QP；CoM/躯干/摆动脚 motion tasks；接触/friction/CoP 约束；QP 输出 q̈ + GRW，再 ID 出力矩。
- Kuindersma et al., *Optimization-based locomotion planning, estimation, and control design for the Atlas humanoid robot*, 2016  
  - 接触约束带 slack；避免不可行；硬动力学/力矩。
- Kim et al., *Computationally-Robust and Efficient Prioritized Whole-Body Controller with Contact Constraints*, 2018  
  - 任务松弛/优先级；接触约束。

## 4. 逆动力学：需要多少

### 4.1 两段命令层（当前）

```text
τ = h + Jᵀ·F
```

- 有重力/科氏前馈 `h`；
- 有任务空间力 `F`；
- **没有** `M(q)·q̈`，**没有**显式接触力 `Jcᵀ·f`；
- 属于 **quasi-static / reduced inverse dynamics**；
- 对慢蹲、双脚支撑、CoM/CoP 修正足够；
- 不需要完整 `M` 求解。

### 4.2 完整逆动力学（论文级/QP）

```text
M(q)·q̈ + h(q,q̇) = Sᵀ·τ + Jcᵀ·f
```

- 由任务求 `q̈`；
- 由接触约束/摩擦/CoP 求 `f`；
- 反解 `τ`；
- QP 只是求解这个带约束的 ID；
- 如果要动态/全身/多接触，才需要。

**结论：**

- 控制基础力 **不一定** 要 QP；
- 两段命令层已经是基础力控制器；
- 需要完整 ID 时，先补 `M(q)q̈` 和 `Jcᵀf`，再决定是否用 QP 求解；
- 不要用 QP 覆盖两段基础力，再让执行层加阻尼。

## 5. QP 的定位（实验分支）

QP 保留为实验分支，默认：

```text
SQC_WBC=off
```

可用：

```text
SQC_WBC=shadow   # 只算不施加，看 WBC HUD
SQC_WBC=apply    # 实验施加
```

### 5.1 当前 QP 的已知缺陷

- `fz=mg` 静态等式导致法向力低估；
- 去掉后 `f=0`；
- motion hard/slack 反复；
- `qdd` 顶 100；
- 接触点、CoP、footContactForce 不统一；
- 执行层曾把 QP τ 放大一倍；
- 脚先侧滑再被顶飞。

### 5.2 QP 若要转正，最低验收

1. 一个 QP：base 6D 动力学 + 接触力 + CWC/摩擦 + 力矩约束；
2. 不加 `fz=mg` 静态等式；`f` 由 base 竖直动力学决定；
3. CoM/base 任务用论文级 slack，不允许 `f=0` 成为最优；
4. 支撑腿不做 posture；posture 只给摆动腿或零空间；
5. QP 输出 τ 直接进 muscle，不再叠加两段基础力/supportKd/guard；
6. 5 seeds 保持时间 > 两段命令层，且脚不滑、CoP 在支撑域；
7. 通过后再切默认。

## 9. 姿态约束（补充）

两段 `solve` **不能单独约束姿态**：CoM/CoP 是任务空间，解不唯一；符合蹲姿还需要姿态任务。

- `solveSquatHipDynamics` 是 3 行 CoM × 2 关节，本身无零空间可放姿态；直接叠加 posture PD 会和 CoM 抢。
- 实测：`SQC_CMD_POST_W=0.2` 时 5 seeds 保持时间 `0.856–1.096s`，比不加姿态的 `0.902–1.894s` 更差。
- 因此 posture 不能作为加法项硬塞；必须：
  1. 作为**低优先级任务**：加权 QP / 层次 QP，或
  2. 用 **IK/规划**先选蹲姿，再让 CoM/CoP 作为可行性约束，或
  3. 在完整 ID 中把 posture 放零空间。
- 当前 `SQC_CMD_POST_W` 默认 0，避免姿态项破坏 CoM/CoP；姿态解算器单独设计后再启用。

## 10. 姿态优先 QP 方案（讨论，未实施）

### 10.1 用户目标

QP 不应只让 CoM/CoP “随便有解”，而应把 CoM/CoP 引导到 **IK 目标姿态** 上：

- IK/规划给出符合蹲姿的 `q_ik`（hip/knee/ankle/侧向）；
- QP 以 `q_ik` 为姿态任务；
- CoM/CoP 任务由同一个 `q_ik` 生成，并作为回正目标；
- 这样 CoM/CoP 的“解”才是蹲姿有效的解。

### 10.2 优先级

用户希望：

```text
1. 动力学 / 接触 / 力矩（硬约束）
2. 姿态 IK 任务（高优先级）
3. CoM / CoP 回正（次优先级）
4. 正则化
```

这可以作为“保持蹲姿”的设计，但必须满足：

- IK 姿态本身必须是**动力学可行**的（CoM 在支撑域内、关节力矩可达）；
- CoM/CoP 目标必须从同一个 IK 姿态计算，不能互相矛盾；
- 否则姿态优先级高于平衡时，机器人会为了追 IK 而牺牲 CoM/CoP，直接倒。

论文（Feng/Koolen/Atlas）的常见顺序是：

```text
动力学/接触硬约束 → CoM/质心/接触力（高）→ 摆动脚/姿态（低/零空间）
```

即 **posture 通常是低优先级**，不是高于 CoM。若本项目要“姿态优先”，应明确这是产品选择，并加可行性检查/任务松弛，而不是照搬论文。

### 10.3 QP 如何引导 CoM/CoP 到 IK 姿态

建议流程：

```text
IK/规划：q_ik, com_ik, cop_ik, 支撑域
  → QP：
      hard: 浮动基动力学、接触、摩擦/CoP、力矩
      task 1: posture  q → q_ik（高）
      task 2: CoM      com → com_ik（次）
      task 3: CoP      cop → cop_ik（次）
      slack: 任务不可行时松弛，不松动力学/接触
  → ID：τ = M q̈ + h − Jcᵀ f
```

关键：**CoM/CoP 的目标不是独立给定，而是由 `q_ik` 前向计算**。这样姿态和平衡在同一个目标上，优先级高才不会打架。

### 10.4 需要逆动力学吗

需要区分两种 QP：

1. **QP 输出 q̈ + 接触力 f，再算 τ**
   - 必须逆动力学：`τ = M(q)q̈ + h(q,q̇) − Jcᵀ f`；
   - 这是论文 WBC 的标准形式；
   - 当前 `wbcHard` 已经有 `M/h/Jc` 和 τ 行，属于这一类，但接触力/任务/优先级还不对。

2. **QP 只输出关节力矩修正**
   - 可以用 reduced ID：`τ = h + JᵀF`；
   - 两段命令层就是这一类；
   - 不适合做完整接触力分配和姿态优先。

结论：**要做姿态优先 + CoM/CoP + 接触力分配，QP 需要完整 ID；两段命令层不需要。**

### 10.5 当前 QP 的问题（与优先级无关）

- `fz=mg` / `f=0` / motion slack：接触力模型错；
- `qdd` 顶 100；
- 接触点/CoP/footContactForce 不统一；
- 执行层曾把 QP τ 放大；
- 所以现在不是“优先级调反了”，而是 QP 本身还没有正确的动力学/接触解。

**在修正接触力和 ID 之前，不要谈 posture 优先级。**

## 11. QP 参考设计（论文核对）

### 11.1 首选骨架：Sovukluk et al. 2025, ID-WBC

- 论文：*Experimental Comparison of Whole-Body Control Formulations for Humanoid Robots in Task Acceleration and Task Force Spaces*，arXiv:2507.18502。
- 这是目前最贴合“蹲姿 + 全身 + 接触”的 QP 骨架，实验里直接做了 20cm 蹲起。

QP 形式：

```text
变量：ν̇（浮动基 6 + 关节 18）、τ、f_c
成本：Σ_i || ẍ_i,d − ẍ_i ||²_Wi
约束：
  M ν̇ + C ν + τ_g = τ_cont
  J_c ν̇ + J̇_c ν = 0
  |f_x| ≤ μ f_z/√2, |f_y| ≤ μ f_z/√2, f_z ≥ 0
  τ_min ≤ τ ≤ τ_max
```

特点：

- 完整浮动基动力学；接触 6D 硬约束；
- 摩擦锥 + 力矩上下界；
- **没有 `fz 总和=mg`**；
- 任务用软权重（CoM、躯干、脚、姿态/手臂）；
- 蹲姿实验证明 ID-WBC 可用。

### 11.2 CoP / 姿态补充

- **CoP**：Feng 2014 的 CoP 任务/约束 + 支撑踝纯力矩控制；  
  `CoP = (−M_y/F_z, M_x/F_z)`，`τ_ankle = h + Kp_cop(CoP*−CoP)F_z`。
- **姿态优先级**：论文通常把 posture 放低优先级/零空间；若要把 posture 放到 CoM/CoP 之上，必须用**层次 QP**（Kim 2018 / Sentis 2006）并保证 IK 目标可行；否则姿态会牺牲平衡。
- **任务松弛**：Kim 2018 的“松弛任务加速度以满足接触/摩擦”适合接触切换。

### 11.3 推荐组合

```text
骨架：Sovukluk ID-WBC（完整动力学 + 接触 + 摩擦 + τ 限制）
CoP：Feng 2014（CoP task/约束 + 踝纯力矩）
优先级：若 posture 高，采用 Kim 2018 的层次/松弛；否则 posture 低、CoM 高
```

**不推荐**：继续在当前 `wbcHard` 上修 `fz=mg`/`f=0`/motion slack；应新建 clean QP，按上面的骨架实现。

## 12. 现状 QP / solve 与目标 ID-WBC 对照

### 12.1 当前 QP（`wbcHard.ts`，实验，默认 off）

```text
变量：q̈(24) + fL/fR(12) + sContact(12) + sCwc(32) + sMotion(6) = 86
等式：base 6 + CoM/base 6（带 signed motion slack）= 12
约束：接触加速度软、CWC 逐行软、τ 硬、q̈ 边界
无：fz 总和=mg（已删）
任务：CoP 任务 weight=0、posture weight=0、tauFF=10（软）
```

问题：接触/CWC 是软约束且 slack 可被选；CoM/base 用 slack；没有完整 24 行动力学；τ 由 qdd/f 消元；不是论文 ID-WBC。

### 12.2 当前 solve（正式命令层，默认）

```text
CoM: τ_hip2/knee2 = h + J_comᵀ·[Kp e + Kd ev + F_feed]
CoP: τ_foot2 = h + Kp_cop(CoP*−CoP)Fz (+D/feed)
执行: τ = base − b qd − k softzone
posture: 可选，默认权重 0
```

- 5 seeds：`0.902–1.894s`（settle 后）；
- 是 reduced ID，不含 `M q̈` 和接触力；
- 不约束姿态；姿态要单独 IK/层次 QP。

### 12.3 目标 ID-WBC（Sovukluk 2025 骨架）

```text
变量：ν̇(24) + τ(18) + f(12)（可选 task slack）
成本：Σ || ẍ_i,d − ẍ_i ||²_Wi
等式：完整动力学 24 行
约束：Jc ν̇ + J̇c ν = 0（接触硬）
      friction cone / CoP 硬（或高惩罚）
      τ_min ≤ τ ≤ τ_max
      q̈ / f 边界
任务：posture/IK、CoM、CoP、base；权重/层次
```

### 12.4 重做清单

1. 冻结 `wbcHard.ts`，新文件 `wbcId.ts`；
2. 复用 `floatingModel` 的 `M/h/Jcom/Jbase/Jc/Jdot`；
3. 变量 `q̈ + τ + f`，完整 24 行动力学等式；
4. 接触 12 行硬约束；摩擦/CoP 硬；力矩 box；
5. 任务：IK posture、CoM、CoP、base；权重先按论文；若 posture 高，用层次 QP；
6. 无 `fz=mg`、无 motion slack、无接触/CWC slack；
7. 输出 τ 直接进 muscle；执行层只做低阻尼/被动；
8. shadow + 5 seeds，超过两段 `0.902–1.894s` 才默认。

## 14. 简化版 QP（3 关节，不做全身）

### 14.1 变量

只优化矢状 3 关节力矩：

```text
x = [ τ_hip2 , τ_knee2 , τ_foot2 ]
```

或等价的 `q̈3`。不做 18/24 维全身 ID。

### 14.2 任务

1. **CoM 力任务**（hip2/knee2）：

```text
F_com* = Kp·(com* − com) + Kd·(vel* − vel) + F_feed
J_hkᵀ·(τ_hk − h_hk) = F_com*
```

`J_hk` 是 3×2 CoM 雅可比；`h_hk` 是 hip2/knee2 静态载荷。

2. **CoP 任务/约束**（foot2）：

```text
CoP = ankle + (τ_foot − h_foot)/(Fz·k)
CoP_min ≤ CoP ≤ CoP_max
τ_foot* = h_foot + kpCop·(CoP* − CoP)·Fz
```

3. **姿态任务**（可选，按你的优先级）：

```text
τ_i ≈ τ_i,ik
```

`τ_ik` 由 IK/`baseSag` 的关节目标经 PD 得到。

### 14.3 权重

```text
min  w_post·||τ − τ_ik||²
   + w_com ·||J_hkᵀ(τ_hk − h_hk) − F_com*||²
   + w_cop ·||τ_foot − τ_foot*||²
s.t. τ_min ≤ τ ≤ τ_max
     CoP_min ≤ CoP(τ_foot) ≤ CoP_max
     Fz > 0（接触）
```

- 若 posture 高，`w_post` 大；CoM/CoP 必须在同一 IK 目标下可行；
- 若 balance 优先，`w_com/w_cop` 大；posture 小；
- 这是 **静态力分配 QP**，不需要 `M(q)`，不是全身 ID-WBC。

### 14.4 与两个 solve 的关系

- `solveSquatHipDynamics` = CoM 力任务的**闭式加权解** `h + JᵀF`；
- `solveSquatShankDynamics` = CoP 任务的**闭式 P 控制**；
- 3 关节 QP = 同样的任务，但能显式加**姿态权重、CoP 硬约束、力矩耦合**；
- 所以 solve 是 reduced ID 的解析版，QP 是同一简化模型的优化版；两者不是两套物理。

### 14.5 solve 对不对

结构上对，但有边界：

- CoM：`JᵀF + h` 正确；但 `kpF=600/kdF=60` 对 70kg 偏欠阻尼，建议按质量缩放：`kp=m·ω²`、`kd=2mζω`。
- CoP：`τ = h + kpCop(CoP*−CoP)Fz` 正确；`kpCop=-3` 是本项目符号；必须用实测 CoP/支撑域验证。
- `posture` 是加法项时会和 CoM/CoP 抢；默认 0 是对的；要做姿态优先，用上面的 3 关节 QP 权重，而不是直接加 PD。
- `h` 是静态载荷；两段都是 reduced ID，不含 `M q̈` 和接触力；动态蹲起需升级。

## 15. 静态蹲姿伺服（实际任务）

实际任务不是“蹲起轨迹”，而是**蹲下后的静态姿态保持伺服**：

```text
保持 q_ik（髋2/膝2/踝2）
保持 CoM 位置
保持 CoP 在支撑域内
双脚接触、不滑
```

### 15.1 任务优先级

静态保持时：

```text
1. 接触/CoP/关节力矩（安全约束）
2. posture：q → q_ik（主任务）
3. CoM/CoP：漂移修正（次任务）
```

这和动态蹲起不同；静态时姿态是主任务，CoM/CoP 是稳定约束。

### 15.2 两个 solve 单独不够

- `solveSquatHipDynamics` 只控 CoM，不控 `q_ik`；
- `solveSquatShankDynamics` 只控 CoP，不控踝角；
- 单独运行会漂姿态，必须加 posture。

最小正确结构：

```text
τ_post = Kp(q_ik − q) − Kd·qd
τ_hk   = h_hk + J_hkᵀF_com + w_post·τ_post,hk
τ_ank  = h_ank + Kp_cop(CoP*−CoP)Fz + w_post·τ_post,ank
```

其中 `q_ik` 来自蹲姿 IK/`baseSag`。

### 15.3 或 3 关节静态 QP

```text
变量：τ_hip2, τ_knee2, τ_foot2
min  w_post‖τ−τ_ik‖² + w_com‖J_hkᵀ(τ_hk−h_hk)−F_com‖²
   + w_cop‖τ_foot−τ_cop‖²
s.t. τ_min ≤ τ ≤ τ_max
     CoP_min ≤ CoP ≤ CoP_max
```

- 静态保持：`comVel≈0`、`qd≈0`；
- `F_com` 主要消漂移，不需要大增益；
- `CoP*` 用支撑中心/CoM 投影；
- 不需要 `M q̈`；不需要全身 QP。

### 15.4 验收

1. 固定 `q_ik`，10s 静态：关节角漂移、CoM 漂移、CoP 余量、脚不滑；
2. 加轻微扰动，CoM/CoP 能回；
3. 5 seeds；
4. 通过后再做慢速蹲起轨迹。

## 16. 静态蹲姿保持的论文依据

### 16.1 有没有论文

有，但**没有论文保证任意保持时间**；论文给的是实验时长/重复次数。和“静态蹲姿保持”最接近的是：

1. **Galdeano et al. 2014**
   - *Task-based whole-body control of humanoid robots with ZMP regulation, real-time application to a squat-like motion*
   - 静态场景：CoM 参考恒定、双脚相对位姿恒定、ZMP 调节；
   - 任务优先级：脚相对位姿最高 → CoM/ZMP → 关节限位/姿态；
   - 直接对应“站着不动 + 扰动回正 + 蹲姿”。

2. **RH5 WBC 2023**
   - *Experimental Investigations into Using Motion Capture State Feedback for Real-Time Control of a Humanoid Robot*
   - 速度型 WBC QP：变量是关节速度；任务 CoM/root；接触约束；
   - 蹲起 14cm，五次重复；慢速：一次蹲 16s / 10s；
   - 适合“慢速、长时间保持”的 QP 结构。

3. **TALOS WBC benchmark 2022**
   - *Benchmarking Whole-Body Controllers on the TALOS Humanoid Robot*
   - 静态 postural task 用 QP；posture 增益要降低，否则不稳；
   - 接触被破坏时 QP 约束失效会倒。

4. **HuB 2025/2026（RL，不是 QP）**
   - 包含 deep squat、长时间极端平衡；
   - 但是学习策略，不是 QP，不能直接拿来保证 QP。

### 16.2 静态保持的 QP 要求

静态保持比蹲起轨迹更看重：

- **稳态误差**：CoM/CoP/关节角不能慢慢漂；
- **posture 保持**：`q → q_ik` 是主任务；
- **CoP 余量**：不是“刚好在边界”，要留安全区；
- **接触持续**：双脚 fz 不能掉；
- **力矩/热**：长时间保持不能持续饱和。

不需要：

- 不需要全身 `M q̈`；
- 不需要高维 QP；
- 不需要动态接触切换。

### 16.3 推荐静态 QP

```text
变量：τ_hip2, τ_knee2, τ_foot2（或 q̇ 3 个）
任务：
  posture  q → q_ik（高）
  CoM      com → com_ik（中）
  CoP      cop → cop_safe（中）
约束：
  τ_min ≤ τ ≤ τ_max
  CoP_safe_min ≤ CoP ≤ CoP_safe_max
  双脚 fz > 0
```

- 速度型（RH5）或力矩型（Galdeano）都可以；
- 关键是 **posture 高、CoP 留余量、稳态积分/前馈**；
- 论文验证的是“能保持/能重复”，不是“任意时长保证”；时长最终由摩擦、CoP 余量、执行器和模型误差决定。

## 17. 静态保持与慢速蹲统一

慢速蹲（一次 10–16s）是**准静态**，和静态姿态保持可以共用同一套 3 关节 QP：

```text
静态保持：q_ik 恒定，com_ik 恒定，cop_ik 恒定
慢速蹲：  q_ik(t) 慢变，com_ik(t) 慢变，cop_ik(t) 慢变
```

本质区别只是目标在慢变；`q̇`、`q̈` 很小，不需要完整 `M q̈` 全身 ID。

### 17.1 参考

RH5 WBC 2023（PMC9783769）：

- 速度型 WBC QP；
- CoM/root 任务 + 接触约束；
- 蹲起 14cm，五次重复，一次蹲 16s / 10s；
- 适合静态保持和慢速蹲。

### 17.2 统一 QP

```text
变量：τ_hip2, τ_knee2, τ_foot2（或 q̇ 3 个）
任务：
  posture：q → q_ik(t)         高
  CoM：    com → com_ik(t)     中
  CoP：    cop → cop_safe(t)   中
约束：
  τ_min ≤ τ ≤ τ_max
  CoP_safe_min ≤ CoP ≤ CoP_safe_max
  双脚 fz > 0
```

- 静态：目标恒定；
- 慢速蹲：目标慢变，可加很小的 `q̇_ff`、`comVel_ff` 前馈；
- 不需要全身 QP；
- 关键是硬接触/CoP、一个 τ 来源、posture 主任务、稳态积分。

### 17.3 验收

- 10s 静态保持；
- 16s 一次慢速蹲，重复 5 次；
- 记录 CoM 漂移、CoP 余量、脚滑、τ 饱和；
- 通过后再考虑更快的蹲起。

## 18. 简化版论文映射（定稿）

不做全身 ID-WBC。只把 Sovukluk 的 QP 结构**降维到 3 个矢状关节**：

```text
关节：hip2, knee2, foot2
状态：q3, qd3
变量：τ3（准静态）或 qdd3 + τ3 + f（完整降维版）
模型：3 连杆矢状模型；静态时 qdd3=0
任务：posture(q3→q3_ik)、CoM、CoP
约束：接触/CoP、τ 上下限、摩擦
```

### 18.1 静态度量

静态保持时：

```text
qd3 ≈ 0, qdd3 ≈ 0
τ3 = h3 − Jc3ᵀ f
```

所以 3 变量 τ QP 是论文 ID-WBC 的静态特例：

```text
min w_post‖τ−τ_ik‖² + w_com‖J_hkᵀ(τ_hk−h_hk)−F_com‖²
  + w_cop‖τ_foot−τ_cop‖²
s.t. τ_min ≤ τ ≤ τ_max
     CoP_min ≤ CoP ≤ CoP_max
```

### 18.2 慢速蹲

- `q3_ik(t)`、`com_ik(t)`、`cop_ik(t)` 慢变；
- 仍用同一个 3 变量 QP；
- 可加很小的 `qd_ff`、`comVel_ff`；
- 不需要 `M(24)`、不需要 18 轴、不需要全身接触。

### 18.3 边界

- 全身 Sovukluk 只作为公式参考；
- 正式实现是 `squatQp3` 的 3 关节版本；
- 当前 `squatQp3` 的 `qIk` 固定、posture/CoM/CoP 权重仍需调试；
- 两段 solve 继续作为默认/闭式 baseline；
- 只有 3 关节 QP 先通过 10s 静态 + 16s 慢蹲，才能替换两段 solve。
