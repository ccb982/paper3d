# 蹲姿回正力架构定稿（2026-10-28）

> 本文是**蹲姿回正力的架构文档**。目标：先把架构定干净，再慢慢补窟窿。
> 所有结论均有物理级实测支撑（探针名标在各处）。

## 0. 一句话架构

> **回正力 = 「目标」与「当前」的差 → 位置空间反解 → 力矩 → 写回唯一的关节轴。**
> 目标由**脚落点**决定（闭链几何），不随每次蹲下变。

## 1. 用户的力链设计（2026-10-28 原话，不可改动）

```text
「膝盖竖直，髋水平」
「力链畅通，脚发力别动小腿」
「膝关节也要做大腿旋转的限位」
「发力的是膝盖和大腿，小腿支撑就行了」
```

### 1.1 拆解成可实现的职责

| 用户表述 | 物理含义 | 实现落点 |
|---|---|---|
| 膝盖竖直 | 膝锚点在踝锚点**正上方**（不内扣不外撇） | 膝**额状轴**出力 |
| 髋水平 | 骨盆不侧移、不侧倾 | 髋**额状轴**出力 |
| 脚发力别动小腿 | 小腿只被动支撑，不主动出力 | 力链由髋/膝发起 |
| 膝关节也要做大腿旋转的限位 | 大腿绕小腿拧过头时拉住 | 膝**扭转轴**单向弹簧 |
| 发力的是膝盖和大腿 | 主动力矩只给髋、膝 | 踝/小腿零主动力矩 |

### 1.2 力链（畅通版）

```text
      ┌─────────── 地面 ───────────┐
      │                              │
   [地面反力] ──→ [骨盆] ←── [髋力矩]
                      ↑              ↑
                 [大腿] ←── [膝力矩]
                      ↑              ↑
                   [小腿] ←─（被动支撑，不主动出力）
                      │
                    [脚] ──→ CoP 偏移 ──→ [地面反力]
```

**关键**：髋力矩本身不移动骨盆（髋锚点在骨盆上，动不了），
它通过**改变脚上的压力分布（CoP）** → 地面反力 → 把骨盆推回中心。
这正是用户设计的「脚发力传给髋，髋回正的力传到脚上抵消」。

论文依据：Mirshams Shahshahani & Ashton-Miller 2020（PLoS One 15(11):e0242454）
—— *"the stance limb hip is the most effective joint in creating larger instantaneous
shear forces under the stance foot"*（hip strategy）。

## 2. ★ 写手归属表（架构的核心：每个轴只有一个写手）

### 2.1 蹲姿腿链的写手归属（定稿）

| 关节·轴 | 物理平面 | 唯一写手 | 通道 | 职责 |
|---|---|---|---|---|
| **hip 额状轴** | 额状 | `squat.hipStrategy`(active) + `squat.legTension`(passive) | ext/active + ext/passive | 髋水平（主动）+ 下限刚度（被动） |
| **knee 额状轴** | 额状 | `squat.hipStrategy`(active) + `squat.legTension`(passive) | 同上 | 膝竖直（主动）+ 下限刚度（被动） |
| **knee 扭转轴** | 扭转 | `squat.hipStrategy`(active) + `squat.legTension`(passive) | 同上 | 膝扭转限位（主动）+ 被动刹车（被动） |
| **hip 扭转轴** | 扭转 | `squat.legTension`(passive) | ext/passive | 髋轴转的被动刚度 + 解剖软限位 |
| foot 额状轴 | 额状 | `squat.frontalPassive` | ext/passive | 踝 roll 被动刚度 |
| hip/膝/踝 矢状轴 | 矢状 | `squatPairBase` | pair | 矢状回正（肌肉对） |
| 踝 矢状轴 | 矢状 | `squat.ankleFeedforward` | ext/support | 踝矢状前馈（**待补 PD**） |
| spine 各轴 | — | `squat.spinePassive` / `squat.upperRighting` | ext/passive | 上身 |

★ **active / passive 双写不是「同轴两套定律」**：提案总线按 `dof|kind|channel` 仲裁，
  **不同通道各自保留**，在 `executor.applyAll` 里
  `applied = clamp(cmd, ±τmax) + clamp(passive, ±τmax)`（`executor.ts:204,236`）
  ⇒ **物理叠加**，语义上就是论文里的「主动肌肉 + 被动组织」两条并联承载路径。
  ⚠ 同**通道**内才互斥（后提交覆盖先提交）⇒ passive 通道每轴只能有一个写手
  （原 `squatHipSoftLimit` 已并入 `squat.legTension`，见 §7.0.2）。

### 2.2 「同轴两套定律 = 对拉」的病根

[supportClean.ts:268-276](file:///c:/Users/22641/Desktop/架构重置/stickman-lab-v2/src/core/servo/supportClean.ts#L268-L276) 记录的历史病根：
同一根轴上挂两个写手（一个是 pair 肌肉对、一个是 ext 主动），在 `applyAll` 里相加 ⇒ 互相对拉。

**即使通道不同（passive vs active）也会互相干扰** —— 实测：
膝额状轴同时挂被动弹簧（拉向机械中性角 0）+ 主动策略时，被动弹簧在**维持外撇**
（因为「读数归零」≠「几何竖直」）。⇒ 2026-10-28 把 knee 从 `squatFrontalPassive` 摘除。

## 4. 模块结构

```text
src/core/servo/
├── jointPlane.ts     ← 物理平面查询（无状态，纯函数）
├── closedChain.ts    ← 闭链目标求解（从脚落点推膝/髋/骨盆的位置基准）
└── hipStrategy.ts    ← ★ 蹲姿回正力唯一写手
```

### 4.1 closedChain.ts —— 目标层

```text
输入：脚落点（捕获一次，之后不变）+ 当前姿态（每帧）
输出：闭链目标角（每帧重解）
```

- 约束（额状）：膝z = 踝z、髋z = 膝z ⇒ 最小范数最小二乘反解 Δθ
- 残差每帧更新（骨盆只被地面反力推动，必须运行时读）
- **只管额状** —— 矢状归 `squatPairBase`（见 §5.2 清理记录）

### 4.2 hipStrategy.ts —— 力矩层

```text
残差（位置空间，m）
  ├─ 骨盆侧移 = 目标(双脚中点z) − 骨盆z
  ├─ 髋侧倾   = 髋L.y − 髋R.y
  └─ 膝竖直×2 = 膝.z − 踝.z（逐侧）
      ↓ 死区(1cm) → 渐入渐出 → PD → CoP预算钳位
力矩（N·m）
  ├─ 膝额状轴  ← 逐侧独立（左右权限不同：1.36 / 0.88 cm/(N·m)）
  ├─ 髋额状轴  ← 同向（骨盆侧移 + 侧倾）
  └─ 膝扭转轴  ← 单向弹簧，死区 12°
```

## 6. ★★ 核心修复：目标角表被覆盖（回正力一直没生效的根因）

### 6.1 问题

[court.ts:705](file:///c:/Users/22641/Desktop/架构重置/stickman-lab-v2/src/core/court.ts#L704-L719) 在释放瞬间执行：

```ts
captureAngFrom(w.body.dofs);   // 目标角 = 实测释放姿势
```

`baseTable.squat.ang` 里明确写着回正目标 `hip0:0 / knee0:0 / foot0:0`
（= **髋水平、膝竖直、脚竖直**），但这行把它**整张覆盖成实测值**：

```text
释放前实测角: hip_l/0= 0.13  knee_l/1=14.50  foot_l/0=12.09
释放后实测角: hip_l/0=-8.94  knee_l/1= 4.82  foot_l/0=14.53   ← 已经是歪的了
```

⇒ 回正力的目标从"竖直"变成"别动" ⇒ **「膝竖直髋水平」从来没生效过**。

### 6.2 修复

`SQC_KEEP_ANG_TABLE` 默认改为 `'2'`（只覆盖非轴 0 的 DoF，保留轴 0 的几何零）。

```text
keepMode: '0'=全覆盖（旧行为） | '1'=完全不覆盖 | '2'=只覆盖非轴0（★默认）
```

为什么分轴：整张表是 K=2.1 姿势标定的（`hip2:2.09 / knee2:-2.08`），
法庭是 K=1.8，整表照抄会把矢状面往回猛拉（实测 fall 5.47→4.57s）。
而轴 0 那三个 0 是**几何目标**、与蹲深无关。

### 6.3 效果实测

```text
KEEP=0 旧行为:  kneeL/1 读数 =  8.51°   （膝还是歪的）
KEEP=2 新默认:  kneeL/1 读数 =  2.12°   ★ 膝竖直生效
```

### 6.4 ⚠ 但 KEEP=2 会把 CoP 余量用尽（必须知道）

KEEP=2 让**目标**从"歪 8°"变成"零"，于是髋策略开始全力纠偏，
`hip_l/0` 出力被顶到 **−20 N·m**（CoP 预算钳位生效）：

```text
KEEP=2 髋策略开:
  t    | 膝L(膝z−踝z) 膝R    | kneeL/1τ kneeR/1τ | hipL/0τ | comX  comZ
 2.02 |       1.70    0.42 |       4.9       1.5 |     0.1 |   2.3   0.1
 2.22 |       0.72    2.31 |       0.0       6.7 |   −20.9 |   2.0  −0.2
 2.42 |      −0.22    2.95 |       0.9       7.8 |   −19.2 |   1.5  −0.7
 3.02 |      −1.24    3.59 |      −4.8       2.8 |   −16.9 |  −2.5  −1.8
fall=3.04s offX=5.0cm
```

⇒ **左膝残差从 1.70 收敛到 −1.34**（膝竖直真的在纠正），
⇒ 但 **CoP 余量已用尽** ⇒ 骨盆侧移压不下去（maxShift 8.43，KEEP=0 时是 2.77）。

这正是论文的硬约束：**髋策略的权限由 CoP 侧向余量决定，不是 τmax。**
⇒ 要让 KEEP=2 的收益兑现，**必须同时扩 CoP 余量**（见 §10 待办 #5：踝 roll 顶死限位）。

**⇒ 因此 KEEP=2 定为默认值（架构正确），但要等 CoP 余量的问题解决才见净收益。**
用 `SQC_KEEP_ANG_TABLE=0` 可临时回退到旧行为。

## 7. ★ 已知局限（诚实记录 —— 要慢慢补的窟窿）

### 7.0 ★★ 膝盖内收（用户 2026-10-28 指出）：已定位并修复（2026-10-28 晚）

**★ 度量方式的坑（先看这个，否则量错）**：

1. **不能用读数**：`body.ts:841-854` 的 `mirrorSymmetric` 会把左右读数**强制镜像**
   （`avg=(angle_l+sgn·angle_r)/2; angle_l=avg; angle_r=sgn·avg`），
   所以读数永远对称、看不出内收。
2. **不能用「膝间距 vs 踝间距」**：它只测**腿的开合**（位置），
   而本例的「内收」是**朝向拧**——大腿绕自身纵轴拧，膝盖面转向中线。位置几乎没变。
3. **正确度量**：读刚体世界变换（绕开一切读数镜像）：
   ```text
   大腿扭转 = yaw(大腿刚体局部+X) − yaw(小腿刚体局部+X)
               （yaw = atan2(worldX, worldZ)，左腿在 +Z 侧 ⇒ yaw 增大 = 正面转向中线）
   ```

**实测（tools/_tmp-freeze-pose2.ts / _tmp-freeze-dof.ts，蹲下法庭冻结期 0→2s）**：

```text

大腿相对小腿拧转                      +55.2°       +9.3°
膝位置（膝z−踝z，正=外撇）      +1.5cm(外)  +1.2cm(外)
膝偏「髋—踝连线」                    +4.5cm       +4.1cm
```

⇒ **是「朝向拧」不是「位置塌」**：膝相对踝只内移 1.6cm，但大腿拧了 47.6°，
   肉眼看过去就是「膝盖朝内收」。

#### 7.0.1 根因一：摆姿**出生就越限**（限位写错了，不是姿势错）

用户 2026-10-28 原话：「**姿势一点毛病没有，人完全做得出来，是限位写错了**」——完全正确。

```text
摆姿刚成形时（t=0）：
  knee_l/1  角=+14.50°   限位=−8..8   ← 超限 6.5°
  knee_r/1  角=−14.50°   限位=−8..8   ← 超限 6.5°
```

`squatCourtSetup` 的运动学摆姿（绕双膝连线共轴折 1.8rad）把膝的额状轴摆到了 ±14.5°，
而骨架默认限位（`JOINT_LIMITS_XY_DEG.knee_* = [6, 8]`）只有 ±8° ⇒ **摆姿一出生就违约**。

⇒ 限位通道（`drive.ts:537-551`）每帧给越限轴施加限位冲量，
   **反作用力矩拧大腿**（膝是大腿的子体）⇒ 冻结期大腿持续被拧。

**A/B 决定性验证（tools/_tmp-freeze-limitfix.ts）**：

```text
配置                                    Δ大腿yaw
① 现状                                  +48.2°
② LIMITS_OFF=1（限位通道全关）           +1.2°   ★
③ 只放宽膝轴1 → ±20°                    −1.4°   ★
④ 膝轴0/1 都放宽 → ±20°                  +1.5°
```

⇒ **元凶确认：膝逻辑轴1 的 ±8° 限位太窄**（不是任何回正写手的问题）。

**修复**（[baseTable.ts](file:///c:/Users/22641/Desktop/架构重置/stickman-lab-v2/src/core/servo/baseTable.ts) 的 `squat.joints.limits`）：

```ts
['^knee_', 1, -20, 20],   // 膝额状轴（内/外翻）：蹲姿摆姿需 ±14.5° → 留到 ±20°
['^knee_', 0, -12, 12],   // 膝扭转轴：冻结期实测漂到 −9.5° → 留到 ±12°
```

★ **与架构的一致性（重要）**：`squatHipStrategy` 把**膝额状轴**判给了自己（§2.1），
  但那个轴的限位只有 ±8° 时，**限位通道就是同轴第二个写手** ⇒ 策略力矩永远被限位顶回来。
  放宽限位后，主动/被动两条路径才真正能各司其职。
★ 站立状态仍用骨架默认的 6/8°（不变），只蹲姿放宽。

#### 7.0.2 根因二：矢状大力矩经链几何耦合出额状/扭转漂移（大腿上没有任何东西钉住它）

修完限位后仍剩 **+23.6°**。归因（tools/_tmp-freeze-left.ts）：

```text
① 现状                                  +23.6°
② 关矢状基础力 SQC_PAIR_OFF=1            +5.9°
③ 关踝前馈 SQC_ANKLE_FF=0                −5.4°
④ 关髋软限位 SQC_HIP_SOFT=0              +3.2°
⑤ 关回正写手 SQC_HIP_STRATEGY=0          +23.7°   ← 无关
⑥ 关踝被动 SQC_FRONTAL_PASSIVE=0         +3.0°
```

⇒ 关掉**任意一个**矢状向写手都能消掉 ⇒ 不是某一方单独干的，
   而是**矢状大力矩经链几何耦合**出额状/扭转方向的漂移；
   而大腿的额状/扭转轴上**施加力矩全程 = 0 N·m** ⇒ 纯自由漂移。

**⇒ 用户诊断正确：「感觉大腿没被动张力一样」。**

**修复：新增蹲姿腿部被动张力写手**（`squat.ts` 的 `squatLegPassiveTension`）：

- 轴：`hip/0`(额状) `hip/1`(扭转) `knee/0`(扭转) `knee/1`(额状)
- 通道：`ext/passive`（与 `squatHipStrategy` 的 active 通道**叠加而非对拉**——
  `executor.ledger.passive` 与 `cmd` 分开记账，各自封顶 = τmax）
- 目标角：**标准姿势角快照**（新建 [squatPose.ts](file:///c:/Users/22641/Desktop/架构重置/stickman-lab-v2/src/core/servo/squatPose.ts)）
  - ★ 不能用 `baseTable.ang`：释放瞬间的 `captureAngFrom` 会用「已漂歪的姿势」覆盖它
    ⇒ 被动张力会变成「把歪姿势当目标」
  - 快照在**摆姿完成时**捕获一次（`court.ts` 的 `squatCourtSetup` 与 `captureSquatCourt` 都调）
- 形态：弹簧 + 阻尼 + 死区 + 封顶；超解剖软边界 ⇒ 刚度/封顶加大
  （**吸收**原 `squatHipSoftLimit` 的职责——同一轴只能有一个 passive 写手，
  否则提案总线按 `dof|kind|channel` 仲裁会互相顶掉）

**效果**：

```text
Δ大腿yaw：+23.6° → +4.3°
```

#### 7.0.3 修复后的完整状态

```text
                          offX=5cm     offX=5cm（**同一倒法，没变差**）
```

⇒ 额状面（膝盖内收）这一块**已解决**。
⇒ 判死仍是**矢状面前栽**（offX=5cm），根因是踝矢状撑不住（§7.3/§7.4），与本次无关。

#### 7.0.4 论文依据

- **被动张力作为姿势稳定的下限刚度**：非收缩成分（titin/结缔组织）提供被动力，
  随肌肉拉长单调增长；titin 被动模量可实测且疲劳会降低它
  （Privett et al. 2024, *Exp Physiol*）
- **被动不足（passive insufficiency）**：跨双关节肌被两端同时拉长到极限时
  被动张力飙升 ⇒ 天然限制 ROM ⇒「别让大腿拧过头」的物理依据
- **主动/被动是并联的两条承载路径**（不是二选一）⇒ 通道分离、叠加而非对拉
- **Dynamic knee valgus**（=本例现象的正式名字）：股骨内旋 + 髋内收 + 胫骨外展 + 踝外翻
  （Joseph et al. 2008；Claiborne et al. 2006；Hole 2013 综述）
  —— 纠正它靠**主动**控制；被动张力只提供下限刚度

### 7.1 髋额向漂移的真正来源：矢状基础力经链几何的耦合

实测（tools/_tmp-final2.ts）：

```text
 t      | hipL/0     hipL/0τ  | kneeL/1    kneeL/1τ | hipL/2    hipL/2τ  | fz
0.02    |  −0.17°      0.0    |  14.20°      0.0    | 102.4°     −8.9    | 334/331
0.30    |  −8.52°      0.0    |   6.90°      2.0    | 101.2°    −65.2    | 640/657
1.00    |  −9.55°      0.0    |   4.21°      2.7    | 100.6°    −61.2    | 607/602
1.98    |  −9.04°      0.0    |   4.61°      2.6    | 100.1°    −58.2    | 561/563
```

**髋额状轴的力矩全程是 0.0，髋角却从 0.13° 漂到 −9°。**

对照实验坐实因果：
- 关驱动（纯重力+碰撞）→ 髋只漂 **−1.03°**
- 关 pair（矢状肌肉对全关）→ 髋漂 **−17.39°**（失去矢状稳定，更歪）

⇒ 漂移是**矢状基础力（hip/2 = −65 N·m）通过链几何耦合**出来的。
⇒ 根因在基础力侧（额状轴零基础力：`stability.ts:374` 的 `if (d.axis !== 2) continue;`），
额状回正力只能部分抵消。

### 7.2 静置期的"稳"是假的

`SQC_ZERO=1` **每帧清零速度** + `SQC_LIVE=1` 预载 ⇒ 静置期 fz = 1123N（1.64W，超载）。
释放后回到真实 736N（1.07W），**支撑力掉 35%**。

⇒ 静置期的稳不代表释放后能站住。

### 7.3 判死方向不是侧向

```text
 t    | comX    comZ    comY   | |ΔX|  |ΔZ|  |ΔY|
3.05 |    0.1   -2.2   52.7  |  2.19   2.18   3.38
3.30 |   -1.8   -3.0   53.4  |  4.10   2.98   2.70
3.55 |   -4.6   -3.6   53.6  |  6.89   3.59   2.50   ←矢状超标
fall=3.39s offX=5.0cm
```

`ΔY` 显示释放后身体**先下沉 4.3cm 再回弹** ⇒ 矢状面（踝撑不住）才是判死主因。

### 7.4 根因链

```text
com 下沉 4.3cm（踝矢状只有前馈 −9 N·m，撑不住）
  → 左右载荷失衡（406/399 → 214/469 → 164/397）
  → 骨盆被地面反力推着侧移（shift 0 → 8.9cm）
  → 膝相对踝的偏差被整体平移带出来
  → 判死 offX=5cm（矢状）
```

## 9. 当前效果与取舍（实测，tools/_tmp-v2.ts）

```text
配置                              max膝  maxShift maxRoll | 末hipL/0 末kneeL/1  fall
旧基线(KEEP=0, 髋策略关)             7.34    4.23    3.99 |   6.05°    8.49°     3.16
KEEP=0 + 髋策略                    2.68    8.84    2.06 |   1.89°    9.18°     2.98
KEEP=2 (轴0几何零) 髋策略关           16.05    6.99    9.07 |   6.11°    8.71°     3.14
KEEP=2 + 髋策略 (★新默认)             3.99    7.15    1.33 |   1.90°    9.25°     3.03
KEEP=2 + 髋策略 + roll400            3.83    8.43    3.00 |   2.03°    9.26°     3.02
```

**读法**：

- **髋角度**：髋策略把它从 6.05° 压到 **1.90°**（−69%）—— 这正是用户要的「髋水平」。
- **膝残差（max膝）**：KEEP=0 时 7.34 → 2.68（−63%），KEEP=2 时 16.05 → 3.99（−75%）。
- **⚠ maxShift 反而变大**（4.23 → 7~8.8）：因为 KEEP=2 下髋全力纠偏，
  **CoP 余量被用尽**（`hip_l/0` 出力顶到 −20 N·m）⇒ 骨盆侧移压不下去。
  这是论文硬约束，不是 bug —— 见 §6.4。
- **fall 略降**（3.16 → 3.03）：矢状判死（offX=5cm）没被额状回正改善，
  根因是踝矢状撑不住（§7.3）。

**⇒ 当前架构干净、机制正确，但收益被「CoP 余量」和「矢状踝」两个瓶颈卡住。**

**KEEP=2 + roll400 扫描**（tools/_tmp-hipgain.ts）：

```text
配置                      max膝  maxShift maxRoll max髋/膝角  fall
默认(pelvis245 cap20)      3.77    4.20    1.81    14.64°    3.17
roll400                    2.94    7.31    1.51     9.13°    3.04
roll700                    3.29    3.09    1.68     9.18°    3.03
roll400 cap40              3.49    3.83    1.74     9.10°    3.03
roll1200 cap40            20.92   12.30   10.78     8.53°    2.94
```

⇒ 开 roll 能把髋角从 14.6° 压到 9.1°，但 fall 从 3.17s 缩到 3.03s
（髋的同向力矩与膝的修正打架）。
⇒ 当前默认 `kpRoll=0`：优先保膝竖直。
