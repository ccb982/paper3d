# 蹲姿稳定架构 v15：论文对齐与唯一实施路线

日期：2026-11-14

## 0. 先给结论

**不要继续把两段 PD 当作最终方案，也不要再手动调参试图“永久蹲”。**

最终架构只有一条：

```text
QP 命令层（3D 浮动基 WBC）
  → 基础力 / 神经信号 τ_base（含侧向、矢状）
muscle 执行层
  → τ = τ_base + (−b·qd) + (−k·softzone)
drive.td
  → −B·ω，Bmax = 0.8·I_low/dt
```

- **QP 是命令层**：解浮动基逆动力学、接触、CoM、CoP、姿态，输出各关节基础力。
- **PD/muscle 是执行层**：只负责把基础力变成关节力矩，再加肌肉阻尼、被动刚度。
- **侧向也在 QP 里**：CoM 是 x/y/z 三维，CoP 是每脚二维；hip0/1、knee0/1、foot0/1 都是 QP 决策变量，不是独立侧向命令层。
- **两个 QP 不是论文**：论文是**一个 QP 里同时有 CoM task 和 CoP/contact 约束**。两段 PD 或两段 QP（CoM 一段、CoP 一段）只是解耦近似，保留为 fallback。
- **需要逆动力学**：QP 必须用 `M(q) q̈ + h(q,q̇) = Sᵀτ + Jcᵀ f`；两段 PD 不需要完整逆动力学，但 QP 需要。
- **求解器已换成 quadprog（Goldfarb-Idnani 对偶 QP）**：18 轴 reduced QP 现在 20–32 iter 收敛，fz≈343/343、τ 物理；剩余是侧向 cap 与 qdd cap 的协调，不再是 solver 发散。

## 1. 论文核对

### 1.1 TSID / HQP（Del Prete 2014）

- 浮动基、接触约束、任务空间逆动力学。
- 优先级：硬约束（动力学、接触）→ 高优先级任务 → 低优先级任务。
- 输出的是**关节力矩 + 接触力**，不是位置伺服。
- 链接：https://arxiv.org/abs/1410.3863

### 1.2 Atlas QP（Koolen 2016）

- 全身 QP：浮动基 6 + 关节 + 接触 wrench。
- 关键约束：浮动基动力学、接触、摩擦锥、力矩/关节限位。
- CoM/质心任务与接触力在同一个 QP 中协调。
- 链接：https://www.cs.cmu.edu/~cga/z/Koolen_IJHR_2016.pdf

### 1.3 Contact Wrench Cone（Caron 2015）

- 接触不是只 `fz≥0`：完整 CWC 含摩擦锥、CoP 支撑多边形、绕法向的 yaw moment 边界。
- 线性化实现：摩擦锥 8/16 边 + CoP 矩形 + `|my| ≤ k·fz`。
- 链接：https://hal.science/hal-01137021

### 1.4 蹲姿 WBC（Galdeano 2014 / Chen 2025 / Sovukluk 2025）

- Galdeano：squat-like 动作的 WBC，全身任务 + 接触。
- Chen 2025：TP-MPC + WBC；WBC 用**完整浮动基动力学**，任务含 CoM、chest、wrench，约束含浮动基动力学和摩擦。
- Sovukluk 2025：ID-WBC 与 PB-WBC 对比；逆动力学 WBC 是正确基线。
- 链接：
  - https://www.lirmm.fr/krut/pdf/2014_galdeano_ssd-0568454426/2014_galdeano_ssd.pdf
  - https://www.mdpi.com/1424-8220/25/2/435
  - https://arxiv.org/pdf/2507.18502

### 1.5 每脚 GRF / CoP（Lee & Goswami 2010 / HRP-4）

- 每脚独立 6D wrench；CoP 与踝 roll 是接触力分配的一部分，不是第二套 PD。
- 侧向回正通过 CoP/接触力，不是单独 hip0 PD。
- 链接：
  - https://pure.kaist.ac.kr/en/publications/ground-reaction-force-control-at-each-foot-a-momentum-based-human
  - https://arxiv.org/pdf/1809.07073v5

## 2. 最终架构

```text
World
  → Frame（只读 q, q̇, com, comVel, contacts, qTarget）
  → Model（浮动基 M, h, Jcom, Jc, J̇c）
  → WBC QP
      变量：q̈_base(6) + q̈_joint(18) + fL(6) + fR(6)
      等式：浮动基动力学 + 每脚 6D 接触 + fz 总量
      不等式：摩擦/CWC、CoP、τ 上下界、关节限位、fz≥0
      任务：CoM(x/y/z)、base 姿态、关节姿态、wrench 正则
  → τ_base（各关节基础力）
  → muscle：τ = τ_base − b·q̇ − k·softzone
  → drive.td：−B·ω
  → Plant
```

### 2.1 QP 变量

```text
x = [ q̈_base(6), q̈_joint(18), fL(6), fR(6) ]
```

`τ` 可由动力学等式消去，作为关节行：

```text
τ = M_j x + h_j − Jc_jᵀ f
```

### 2.2 等式

```text
M_b q̈ + h_b − Jc_bᵀ f = 0          （base 不可驱动）
Jc_L q̈ + J̇c_L q̇ = 0              （左脚 6D）
Jc_R q̈ + J̇c_R q̇ = 0              （右脚 6D）
fzL + fzR = m g                     （总量，防止 f=0 用 base 加速度扛重力）
```

### 2.3 不等式

```text
fz ≥ 0
|fx| ≤ μ fz, |fy| ≤ μ fz           （8/16 边线性化）
|my| ≤ k fz                         （CWC 扭转）
copMinX ≤ footX − mz/fz ≤ copMaxX
copMinZ ≤ footZ + mx/fz ≤ copMaxZ
τ_min ≤ τ ≤ τ_max                   （带 slack）
q̈_min ≤ q̈_joint ≤ q̈_max           （带 slack）
```

### 2.4 任务 / 优先级

论文是 HQP；工程上可以先做**归一化权重 QP**，但不要用 `1e6 vs 100` 这种未归一化权重。

```text
高：CoM(x/y/z) + base 姿态
中：关节姿态 / qTarget
低：wrench 正则、τ 正则、q̈ 正则
硬：动力学、接触、摩擦/CWC、CoP、τ/关节限位
```

CoM 和 CoP **不是两个 QP**：CoM 是 task，CoP 是 contact wrench 的约束/任务。

### 2.5 执行层

```text
τ_base = QP 输出
muscle: τ = τ_base − b·q̇ − k·softzone
drive.td: −B·ω
```

- QP 不负责阻尼、被动刚度、关节限位冲量。
- `muscle` 负责基础力 + 肌肉阻尼 + 被动刚度。
- `drive.td` 负责执行器/关节级阻尼。
- 同一物理来源只能有一个写手，禁止 drive 与 muscle 重复阻尼。

### 3.2 已修的关键 bug

1. base 旋转雅可比转置：`Jv[:,3:6] = −skew(d)` 原来写成了转置。
2. `Jw` base 单位阵行号越界：应为 `Jw[r·NV + 3+r]`。
3. `body.dofs[].vel` 滞后一拍：模型改为用当前刚体角速度重算 `qd18`。
4. 缺少 `fzL + fzR = mg`：QP 曾把接触力设成 0，用 base 加速度扛重力。
5. `copValid` 失效时踝 CoP 控制被整段跳过：现在接触期间继续用最后有效 CoP。
6. **零空间降维的数值误差**：`x0/Z` 的 `eqViol` 达 2.9，误判成侧向 cap；
   现在 quadprog 直接带 `meq=19` 等式约束，`eqViol=3.2e-12`。

## 4. 咱到底应该怎么做

### 第 0 步：冻结手动调参

两段 QP/PD 保留为 fallback，不再用调踝/调增益作为最终方案。侧向不单独做命令层。

### 第 1 步：模型定版

- 浮动基 6 + 18 关节；上身作为负载或全 joint。
- RNEA 计算 `M/h`；Jc 含 base 列；每脚 6D；Jdot 用真实采样间隔。
- 验证：
  - `M` 与质量矩阵/能量一致；
  - `h(q,0)` 与 `biasForce` 同号同量级；
  - `Jc·ν` 与真实脚点速度一致（<1e-2）；
  - 每脚 CoP 在支撑多边形内。

### 第 2 步：QP 按论文定版

- 一个 3D QP，不是两个。
- 变量/等式/不等式/任务按 §2。
- 侧向在 QP 里；CoM x/y/z；每脚 CoP；fz 总量；τ/关节限位 slack。
- HQP 优先；工程上先归一化权重，但保留 task 优先级接口。

### 第 3 步：solver（已接入 quadprog）

- `quadprog`（Goldfarb-Idnani 对偶 QP）已接入 `wbcHard.ts`。
- 实测：25 维/53 维 reduced QP，20–32 iter，17–97ms；`prim/dual=0`，fz≈343/343。
- 目标：继续压到 <10ms；10–30Hz。
- 失败/不可行必须 `ok=false`，回退两段 QP，禁止把垃圾解施加。
- 下一步是侧向 cap 协调 + 全 18 轴 apply，不是再换 solver。

### 第 4 步：shadow 验收

```text
maxViolation < 1e-3
fz ≥ 0，CoP 在脚内
τ 在 cap 内
qddJointMax < 50
foot2V < 10
hipY 上升 < 2cm
连续 5 seeds 通过
```

### 第 5 步：apply

- QP 基础力 → `muscle` 执行；阻尼/被动仍由 muscle 和 drive.td 负责。
- 先只替换矢状基础力，侧向仍由 QP 输出但逐步放权；确认侧向 cap/CoP 后全量。
- 过不了就回退两段 QP，不硬切。

### 第 6 步：再谈机器学习

- 只有 QP 的模型/求解器工作后，才考虑 ML：
  - 残差学习（模型误差）；
  - 参数辨识；
  - 策略学习（上层轨迹/落脚）。
- ML 不替代底层 QP/接触约束。

## 6. 禁止

```text
1. 把两段 PD 当最终方案。
2. 把侧向移出命令层。
3. 用 1e6 权重掩盖模型/约束错误。
4. 用有限差分 H/g 当 QP。
```
