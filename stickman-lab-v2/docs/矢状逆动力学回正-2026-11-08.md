## 2.1 两条腿必须协同

左右腿不是两个独立控制器。

```text
共同根：pelvis / hip
左右腿：并联支链
同一 QP：FzL/FzR、hip0L/R、hip1L/R、hip2L/R、knee2L/R、τL/R
```

共享约束：

```text
FzL + FzR = W
低侧顶 / 高侧落
hL - hR -> 0
pelvis roll -> 0
kneeOutL >= target
kneeOutR >= target
CoP / 摩擦 / 力矩 / ROM
```

不允许：

```text
左腿只追左腿 IK
右腿只追右腿 IK
一侧顶到饱和，另一侧不知道
kneeOut 只修一侧
```

正确形式：

```text
两条腿 → 一个 bilateral ID QP → 一个 CommandFrame → PD
```

## 3. 模型：一个髋 + 两条腿的三体系统

模型不是“两条各自独立的三节棍腿”。

主三体：

```text
P = 公共髋 / pelvis
L = 左腿
R = 右腿
```

左右腿通过 P 耦合，是一个三体系统。

每条腿内部仍然有：

```text
thigh : hip - knee
shank : knee - ankle
foot  : ankle - contact
```

但逆动力学求解的是：

```text
一个髋 + 两条腿
不是两个分开的单腿三节棍
```

关节：

```text
hip / knee / ankle
```

只做矢状：

```text
q   = [q_hip, q_knee, q_ankle]
q̇   = [q̇_hip, q̇_knee, q̇_ankle]
q̈*  = 目标轨迹
```

边界：

```text
P_hip   髋上部压力 / 骨盆外力
P_knee  膝下部压力 / 大腿负载
F_base  脚底接触力 / CoP / 摩擦
```

上半身：

```text
不建完整动力学
在 hip 处降阶为等效质量 + 外力 + 外力矩
```

脚 / 踝：

```text
是边界条件
不是矢状回正的主动输出
```

## 4.5 感受器唯一消费者

矢状逆动力学求解器是**矢状回正的唯一感受器消费者**。

```text
每帧只构建一次 SagittalSensorFrame
→ 只交给 sagittalIdSolver
→ solver 输出 CommandFrame
→ 其它层只消费 CommandFrame
```

这里“唯一消费者”指：

```text
矢状回正不再有第二个模块读原始感受器后直接生成 hip/knee 命令
base/support 只能作为 solver 的输入/初值
lateral / upper 是冻结的独立通道，不写 hip/knee2
PD 只执行 CommandFrame，不做回正决策
```

禁止：

```text
hipStrategy 自己再读 CoM / Fz
thighPower 自己再读 eSag
bilateralSolver 自己再读另一套接触
squatClean 在 solver 外再补一套 hip0 前馈
```

每帧尽可能完整地采集，带 valid/confidence：

```text
时间
  t, dt, physicsStep

关节
  q[hip0, hip1, hip2, knee0, knee1, knee2, foot0, foot1, foot2]
  q̇
  τ_applied
  min / max / tauMax / velMax
  左右两侧

接触
  contact L/R
  fz L/R
  CoP x/z L/R
  frictionUse L/R
  copInside / copValid
  foot pose / foot velocity

力链
  fParallel
  fParallelSigned
  fPerp
  fPerpSag
  fLat
  chainFeasible
  jointForce 仅回读，不当外部边界

骨盆 / 全身
  pelvis position / rotation
  roll / pitch / yaw
  pelvis velocity / angular velocity
  hip height hL / hR
  CoM position / velocity / acceleration
  XCoM
  support polygon / effective BoS

外部边界
  P_hip force / moment
  P_knee force / moment
  只从外部测量/估算，不重复加 jointLoads

base / IK
  baseSag / support 输出
  IK q* / H* / foot target
  固定脚状态
  held IK 缓存

模式 / 历史
  sagittal / lateral / none
  scheduler 状态
  上一拍 CommandFrame
  QP warm start
  接触切换 / 摩擦突变

```

规则：

```text
每个量必须有 valid / confidence / timestamp
缺失或 NaN → 明确 invalid
invalid 不参与硬约束
关键量 invalid → QP infeasible / fallback
```

## 5. 回正目标

逆动力学不是只解力，它必须追两类姿态目标。

### 5.1 稳定目标

```text
CoM / XCoM
CoP / 有效 BoS margin
左右负载
骨盆 roll / pitch / height
低侧顶 / 高侧落
```

优先级：

```text
先别倒
再谈姿态
```

### 5.2 IK 目标

```text
固定脚
+ 骨盆目标 pose
→ IK
→ q_ik = [hip, knee, ankle]
```

固定脚位 + 骨盆目标固定时：

```text
IK 是固定的
hip2 / knee2 / foot2 不再每帧自由
```

如果允许改髋：

```text
pelvis pose delta 是独立决策
IK 重新解
但 foot 仍然固定
```

### 5.3 kneeOut

回正的最低要求：

```text
kneeOutL >= target
kneeOutR >= target
target >= 0
```

例如：

```text
kneeOut >= 0.005
```

表示：

```text
膝盖最起码不内收
```

`kneeOut` 是 QP 约束：

```text
和 Fz、hip0/1、hip2/knee2 一起解
```

不是：

```text
单独给 hip0 加一个 kneeOutFf
```

独立 `kneeOutFf` A/B 已证伪。

## 6. 逆动力学

单腿：

```text
M(q) q̈ + C(q,q̇) + G(q)
  = τ
  + J_baseᵀ F_base
  + J_hipᵀ P_hip
  + J_kneeᵀ P_knee
```

其中：

```text
τ        = [τ_hip, τ_knee]
           控制变量

τ_ankle  = 边界/测量值
           不由矢状 ID 主动输出

F_base   = 脚底接触力 / CoP
P_hip    = 髋上部压力
P_knee   = 膝下部压力
```

### 6.1 base reference

基础力保留：

```text
τ_base / F_base0 / P_base
```

是静态标准姿势的解，不是外挂前馈。

两种合法写法：

```text
1. 解 delta：
   τ = τ_base + Δτ
   F = F_base0 + ΔF

2. 解 total：
   command = QP.total
   base 只作为 x0 / 正则项
```

禁止：

```text
base + QP.total
```

那会双算基础力。

### 6.2 Stage A：稳定态

```text
q̈* = 0
```

未知：

```text
ΔFz
Δτ_hip
Δτ_knee
hip0 / hip1 修正
```

目标：

```text
XCoM / CoP margin 最大
低侧顶 / 高侧落
力矩最小
kneeOut 约束
```

### 6.3 Stage B：IK 目标

```text
q* = q_ik
q̈* = 平滑轨迹
```

目标：

```text
追 hip / knee IK
pelvis 稳定
shank 不被破坏
contact / CoP / 摩擦仍然可行
```

## 7. 双大腿 QP

### 7.1 变量

```text
FzL, FzR
hip0L, hip0R
hip1L, hip1R
τ_hipL, τ_hipR
τ_kneeL, τ_kneeR
```

`hip2 / knee2`：

```text
固定脚 + 骨盆目标下由 IK 给出
不作为自由变量
```

如果进入 HIP 模式：

```text
pelvis pose delta 进入变量
IK 随 pelvis 重解
```

### 7.2 约束

```text
FzL + FzR = W
Fz >= 0
CoP ∈ support polygon
|F_t| <= μ Fz
τ ∈ torque / ROM
kneeOutL/R >= target
hip0/1 ∈ cap
hL - hR -> 0
pelvis roll -> 0
```

### 7.3 目标

```text
min：
  w1 * (XCoM - CoP)²
+ w2 * (hL - hR)²
+ w3 * Στ²
+ w4 * kneeOut violation²
+ w5 * ||q - q*||²
```

`base` 只进初值/正则，不在外面再叠。

### 7.4 低侧顶 / 高侧落

```text
eH = hL - hR
低侧 = 支撑侧
高侧 = 卸载侧
```

确定性关系：

```text
Fz_low 增加
Fz_high 减少
```

不能左右各自独立算。

## 8. CommandFrame

求解器输出的是相对 base 的增量：

```text
CommandFrame {
  deltaFzL/R
  deltaHip0L/R
  deltaHip1L/R
  deltaHip2L/R
  deltaKnee2L/R
  deltaHip2FfL/R
  deltaKnee2FfL/R
  kneeOutL/R
  feasible
  mode
  residual
}
```

执行：

```text
joint  = base.joint + Δjoint
ff     = base.ff    + Δff
```

执行映射：

```text
hip0 / hip1 / hip2 → 现有 hip PD
knee2              → 现有 knee PD
hip2Ff / knee2Ff   → 现有 PD 前馈
foot2              → base / IK，不变
knee0 / foot0      → shankLateral，不变
```

`foot2` 不进入 ID 输出。

## 8.5 求解周期、保持与防翻号

矢状回正不能每帧重算一套方向。

### 8.5.1 三层频率

```text
物理 / 感受器采样
  480 Hz / 60 Hz
  每帧更新 SensorFrame

矢状 ID 求解
  20–50 Hz（20–50 ms 一次）
  不是每帧

PD / 肌肉执行
  每个物理步
  只执行最近一次 CommandFrame
```

规则：

```text
采样高频
求解低频
执行高频
命令保持
```

### 8.5.2 CommandFrame 生命周期

```text
CommandFrame {
  solveId
  solvedAt
  validUntil
  holdUntil
  feasible
  mode
  ...
}
```

执行层：

```text
新帧未到 → 保持上一帧
超过 validUntil → 降级/fallback
新帧 infeasible → 保持上一可行帧直到 holdUntil
hold 过期仍 infeasible → fallback / step
```

### 8.5.3 防翻号

所有方向量必须带滞回：

```text
ΔFz
低侧 / 高侧
hip0 / hip1 方向
kneeOut 修正方向
STABILIZE / RECOVER
FORCE / HIP
```

规则：

```text
死区 deadband
确认时间 confirm
最小保持 minDwell
冷却 cooldown
```

只有满足：

```text
|error| > deadband
&& 持续 > confirm
&& 距上次切换 > cooldown
```

才允许翻转。

不能因为：

```text
CoP 在零附近抖
fz 噪声过零
左右 Fz 几乎相等
kneeOut 接近 target
```

就每帧翻方向。

### 8.5.4 QP 连续性

```text
warm start = 上一拍解
目标加正则：||x - x_prev||²
限制每拍变化：
  |ΔFz| <= maxDFz
  |Δhip0| <= maxDHip0
  |Δhip1| <= maxDHip1
  |Δτ| <= maxDTau
```

`kneeOut` 仍是硬约束；如果新解违反或 infeasible：

```text
保持上一可行解
不输出反号修正
```

### 8.5.5 模式保持

```text
STABILIZE / RECOVER：
  enter / exit 阈值分离
  minDwell 0.15–0.30 s
  cooldown 0.10 s

FORCE / HIP：
  先 FORCE
  FORCE 连续不满足 confirm 后才 HIP
  HIP 退出也要 cooldown

sagittal / lateral：
  继续使用现有调度器
  但求解器内部不得自行切 mode
```

### 8.5.6 接触突变例外

以下情况可以**立即重解**，但仍然只做 ramp，不跳变：

```text
contact 丢失 / 恢复
copValid 变化
摩擦突变
P_hip / P_knee 失效
fall / safeExit
```

### 8.5.7 验收

```text
同一状态下连续 100 帧：
  ΔFz 不反复过零
  hip0/1 方向不反复翻
  mode 不抖
  kneeOut 修正不反号
  没有每帧重算导致的力矩尖峰
```

## 9.4 状态机

```text
SagittalState {
  STABILIZE
  RECOVER
  HOLD
  FALLBACK
}

ForceMode {
  FORCE
  HIP
}
```

优先级：

```text
接触 / CoP / 摩擦
> kneeOut
> STABILIZE margin
> IK 姿态
> 力矩最小
```

进入条件：

```text

  margin < enter
  contact 不稳定
  CoP 接近边界

RECOVER:
  margin > exit
  contact 稳定
  force chain 可行
```

`STABILIZE` 与 `RECOVER` 必须有：

```text
enter / exit 阈值分离
minDwell 0.15–0.30s
cooldown 0.10s
```

禁止：

```text
每帧在 STABILIZE / RECOVER 之间跳
solve 外再改 mode
```

## 18. 理论定案（2026-11-08）

以下规则为本文最终口径，后续代码不得自行另立定义。

### 18.1 P_hip / P_knee

```text
P_hip / P_knee 是可选外部边界 wrench
不是 jointLoads
不是内部关节反力
```

来源：

```text
有外部测量/估计 → 使用
没有 → 标记 invalid
invalid → 该项置零，QP 退化为 base + 接触边界
```

禁止：

```text
把 fullInverseDynamics 的 jointForce 直接当 P_hip / P_knee
```

### 18.2 qStable

```text
qStable = 释放时捕获的基础 IK 姿态
         captive / baseSag 的标准蹲姿
```

用途：

```text
Stage A 只把它作为软正则
Stage A 的主目标不是追 qStable
而是 margin / Fz / 低侧高侧 / kneeOut
```

Stage B：

```text
qIK = 目标 IK
只有 margin > exit 且 contact 稳定时才追
```

不能把 `qStable` 和 `qIK` 同时当硬目标。

### 18.3 ankle / foot2

```text
foot2 只走 base / IK
ankle 不归矢状 ID 控制
```

因此：

```text
QP 不假设自己可以直接控制 ankle torque
CoP / 接触力是约束与反馈
不是“QP 想给多少就给多少”
```

如果固定 ankle 下 QP 的力/CoP 不可实现：

```text
QP infeasible
→ hold 上一帧
→ 过期 fallback
```

### 18.4 Fz / τ 执行关系

```text
τ_hip / τ_knee = 实际执行命令
FzL / FzR      = 软参考 / 预测目标
```

低层：

```text
PD 用 target + ff 执行 hip/knee
Fz 由实际接触产生
下一拍用实际 Fz 重新求
```

不允许：

```text
把 Fz 当成可以直接写关节的力
```

### 18.5 kneeOut

```text
kneeOut = 膝-踝有符号横向几何
```

约束：

```text
kneeOutL + J_L·Δhip >= targetL
kneeOutR + J_R·Δhip >= targetR
```

规则：

```text
硬约束
左右镜像符号必须实测验证
hip0/hip1 联合
cap 内求解
超 cap → infeasible
```

### 18.6 QP 优先级

从高到低：

```text
1. 接触存在
2. CoP / 摩擦 / 支撑多边形
3. kneeOut >= target
4. torque / ROM / 关节限位
5. margin / 低侧顶 / 高侧落
6. qIK
7. 力矩最小
```

冲突处理：

```text
1–4 任一不可行
→ 不输出新解
→ hold 上一可行帧
→ hold 过期 → fallback
```

不允许：

```text
为了 margin 牺牲 kneeOut
为了 IK 牺牲接触
为了低侧高侧超过 torque cap
```

### 18.7 base reference

```text
base = τ_base / F_base0
```

合法：

```text
τ_cmd = τ_base + Δτ
F_ref = F_base0 + ΔF
```

或：

```text
τ_cmd = QP.total
F_ref = QP.totalF
base 仅作 x0 / 正则
```

禁止：

```text
τ_cmd = τ_base + QP.totalτ
```

### 18.8 当前理论状态

```text
已定：
  qStable
  P_hip/P_knee
  ankle/foot2
  Fz/τ 关系
  kneeOut
  QP 优先级
  base reference

仍待实测验证：
  kneeOut 符号/雅可比
  Fz 对 PD 的可实现性
  P_hip/P_knee 估计有效性
  infeasible 时实际 fall 表现
```

验证前：

```text
只读 QP
不接 PD
```

## 21. 力矩量级、被动刚度与逐帧审计（2026-11-08）

### 21.1 用户结论

```text
现在矢状力矩量级太大
髋侧向力量级也太大

人蹲下时髋回正力没有这么大
但必须灵敏
被动刚度本身会阻止侧翻
```

### 21.2 设计原则

```text
被动刚度/阻尼 = 第一道抗侧翻
主动回正 = 小幅度、高灵敏、低权限
```

不是：

```text
用几十 Nm 的 hip0/passive 硬顶
用几百 Nm 的 hip2/knee2 硬拉
```

正确关系：

```text
passive stiffness
  负责常态抗侧翻和阻尼

active righting
  只在误差出现时给小幅修正
  增益可以高，但输出 cap 要低
  不允许长期大扭矩
```

### 21.3 当前量级

网页 3.4–4.0s 实际回读：

```text

hip0 applied   ≈ 20–57 Nm
hip2 cmd       ≈ 100–190 Nm
fLat           ≈ 20–63 N
fPerp          ≈ 75–222 N
地面力         ≈ 186% 体重（倒地动态）
```

这些不是安静蹲姿应有的量级：

```text
安静蹲姿：
  外部扰动≈0
  fLat/fPerp 应小且稳定
  主动 hip 回正力应小
  主要靠被动刚度和支撑
```

### 21.4 力链审计

```text

  k=504  b=17.3 e=+0.066  tau=10.8
  → 硬化出现，但太晚
```

### 22.3 结论

```text
被动件确实出力
但“刚蹲下就硬”没有做到：

1. 早期 k 只有 90
2. supportScale 只有 0.36–0.40
3. 3.8s 的 passive 大头是 b·vel 阻尼
4. 真正硬化到 k=504 已是 4.53s
```

直接增大 `SQC_P2_HIP_K`：

```text
K=300 → fall 2.87s
```

更差，说明不能只提高刚度；还要同时处理：

```text
supportScale
阻尼 b
relax/p2Soft 的缩放
主动/被动相位
```

### 22.4 架构要求

```text
被动刚度必须是第一道防线
但被动刚度不能被 relax 削到 0.36
早期 supportScale 应接近 1

```

## 23. 姿态伺服层级（2026-11-08）

### 23.1 正确顺序

```text
① 接触
② 基础力 base
③ PD / 肌肉内部刚度阻尼
④ 回正力
```

含义：

```text
PD 肌肉内部：
  目标角 + kp/kd + 共收缩/牵张反射
  第一道姿态防线
  让关节在目标附近保持刚度

base：
  基础支撑力/重力前馈
  负责静态承重和接触

回正：
  姿态误差出现后才动作
  小幅度、高灵敏、低权限
```

### 23.2 PD 不是刚性锁死

```text
PD 是有限刚度/阻尼
不是无限刚性锁死
```

所以：

```text
外部负载 → 先由 PD 刚度/阻尼吸收
剩余误差 → 回正
```

### 23.3 回正的位置

```text
回正不是常开大扭矩
回正不是替代 PD
回正只在姿态/误差出现后修正
```

回正输出必须：

```text
小
快
可回落
不覆盖 base
不抢 PD 的稳定职责
```

### 23.4 当前实现对应

```text
baseSag / support       → base
pdGroups / passive      → PD 肌肉内部
thigh / QP / idHip0     → 回正
```

但当前问题：

```text
passive k 已经偏大
回正/阻尼在 3.8s 仍在打架
极限环说明层级没有完全分开
```

### 23.5 设计结论

```text
先把 PD/base 的稳态刚度做对
再让回正只处理剩余误差
不能用回正去补 PD 的失稳
```
