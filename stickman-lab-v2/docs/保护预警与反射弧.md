## §1 三个东西必须分开

| 类别 | 定义 | 有无选择/状态 | 例子 | 归属 |
|---|---|---|---|---|
| **反射（Reflex）** | 固定"感觉→动作"回路 | 无选择；固定增益/延迟；可有极小相位状态 | 垫脚、牵张、负载、翻正、落地消力 | §3 |
| **恢复策略（RecoveryStrategy）** | 需要分级/锁存/切换的决策 | 有状态、有阈值 | pad→hip→step→giveup 选择器 | §2.7 |
| **保护程序（ProtectiveProgram）** | 跌倒已不可避免后的急救 | 有相位、**全权接管** | 绷直、重心转移、跪撑、起身 | §4 |

- "绷直身子"在神经科学里叫保护性反射，但**工程上归保护程序**（有触发状态、有相位、
  全权接管）——把它当反射会污染反射弧的"无状态"语义；
- 反射弧是**被动工具箱**：只按预警的 directive 或自身触发条件运行，不做策略选择；
- 三者的输出**一律经控制模块的整合器**（出口纪律，§5）。

## §2 摔倒预警（伺服层）——v4 设计

### 2.1 角色与分工（DEC 原则，Mergner & Lippi 2018）

- **预警 = 稳定性的"大脑"**：估计扰动、决定怎么补偿，输出 `StabilityProposal`
  （每拍连续；只读，不写关节），提案里包含**如何使用反射**（`reflexDirectives`）；
- **分工（用户定调）**：**主动侧移/单支撑/大动作由意图与动作发起**；
  **伺服负责保持稳定、别转移太过、回正**——即"扰动估计与补偿（DEC）"；
- 不存在第二套独立的"平衡控制器"；平衡模块就是预警。

### 2.2 处理链（五段，每拍常开）

```
意图/动作（主运动：粗 CoM 目标 / 单支撑构型 / 大动作）
        │
        ▼  伺服层
 ① 可行化：粗目标 → 当前支撑下可行、时间上可达的 CoM/CoP 指令轨迹
      （内部可行化的形态 = 候选组合成 → 预测评估 → 选最优作为提案，见 §2.3）
 ② 扰动估计与补偿（DEC）：外部扰动 + 模型误差 + 支撑状态 → 修正量
 ③ 目标守护：限幅到支撑区 / 限速 / 目标过期回正（governor）
 ④ 反射调用：策略层级 pad→hip→step→giveup（§2.7）
 ⑤ 输出：CoP 指令（垫脚/差动加载/单支撑姿态）+ reflexDirectives
```

**被控对象与传感**（Orin et al. 2013；van der Kooij 1999）：
- 被控量 = **质心动量**（现状用 CoM/XCoM 近似——够用，列升级）；
- 传感 = 多感觉加权整合（本体+前庭类比）——现状单通道（CoM/CoP/Fz 估计），列升级。

**增益纪律**（Peterka 2002；Kuo 1995）：所有环路增益**必须尊重延迟**——实测：
侧向位置环增益超过 ~1/3 即相位泵（`_probe-lateral-resonance` 门禁）。

### 2.3 内部可行化：候选 → 预测 → 选择（用户定调）

**不再是"单一公式出指令"，而是每拍对候选方案集打分选优**（伺服内部的单步微 MPC）：

- **候选 = 已验证工具箱的组合**：垫脚 CoP × 差动加载 × 单支撑门控姿态 ×
  bend/摆臂 × 迈步(未来) × 保护程序；组合 = 幅度预算分账（每级饱和给下一级）；
- **评估 = 降阶预测模型（不是全物理引擎 rollout）**：
  状态 4 维 `[comX, ẋ, comZ, ż]`，动力学 `ẍ = ω0²(x − p)`，`ω0² = g/h`
  （h/增益用实测标定）；候选的 p 走廊/速率/出力上限取自**实测能力表**（§2.6）；
  闭式 cosh/sinh（或 10–20 步 RK）积分 0.3–1s → 三元组
  `(终端目标误差, XCoM 边距, 出力 Σ|τ|)`；单候选 µs 级，每拍可跑。
  全物理 rollout 不做（成本爆炸 + 带执行层模型误差）；按候选类型挂专用简化模型：
  迈步→捕获点/可达落点，摆臂→动量/反旋（Hof 2007）；采样 MPC 列 P4+；
- **选择 = argmin cost + 迟滞/粘性**（上拍方案加权，防边界抖动——latch 教训）；
- **纪律**：不新增反馈环、不做主动耗散项（附录 A 五连败教训）；输出仍是
  StabilityProposal。

**伺服预测什么（用户定调，明确边界）**——全部在"质心-压力-负载"聚合层：

| 层 | 伺服要预测的 | 不预测（归谁） |
|---|---|---|
| **状态**（被预测对象） | CoM 位置/速度（x/z）、CoP、**Fz/负载分配 u**、支撑状态（双/单/接触）、扰动估计、XCoM 边距 | 关节级角度轨迹（执行方回路）；摆动脚落点（动作/迈步计划） |
| **能力**（各部位进模型的方式） | **脚**→CoP 可达域（前+14/后−5/侧±2cm）；**腿**→负载转移可达（u±0.85）+ 接触成立；**骨盆（髋外展）**→姿态权限；**腰/脊柱**→侧屈+屈伸权限；**臂**→动量/反旋（未来） | 关节级动力学——以**能力表约束**进预测，不逐关节积分 |
| **输出**（控制通道） | 脚/踝→pad；**双腿→差动加载（力环=支撑保障核心）**；**腰/骨盆→门控姿态**；矢状→bend | 动作自己的关节（pin） |

- **腰/脊柱**既是输出通道（伺服直接写侧屈/屈伸），也是状态贡献者（躯干质量占半，
  姿态直接改 CoM）；**骨盆/髋**是差动加载的执行器与单支撑姿态支点；
- **腿是负载通道不是位置支撑**——"正确发力把身体撑起来"= 预测"这块支撑能不能
  吃下这份负载"（Fz/接触/CoP），而不是假设位置到位就能撑；
- **时域**：决策 0.3–1s；移脚/迈步的支撑交接最长 ~1.5s；
- ★ **预测里必须含"支撑是否成立"**（接触/负载/新支撑多边形）——否则就是
  "抬腿后假设能撑"的失败模式（§2.8 实测例）。

**P1 已实现（2026-10）**：
- **支撑状态机**（滞回入 0.7/退 0.5 + 换脚判定）与相位（double/preshift/hold/recenter）；
- **支撑有效性预测**：XCoM 到支撑区边界余量 marginX/marginZ + 单支撑负载成立 loadOk，
  全部进 `StabilityProposal.support`（伺服输出仍只是提案）；
- **x 目标守护**（与 z 同构）：钳到实测 CoP 权限（前 +0.14 / 后 −0.05）、限速、过期回正
  ——实测把保持期矢状漂移从 −0.048 收到 **−0.008**（P1 的真实增益）；
- **落地预测（preland 相位）**：单支撑中摆腿下落（TTC<0.35s）或轻触 → 目标以
  0.05 m/s **温和滑向双脚中点（z）+ 前移 5cm（x）**——触地瞬间 CoM 已在新多边形内侧，
  并给放腿冲量留出脚跟权限边距（实测放腿末速 −0.30 → **−0.08**、放腿全程胸 1.406→1.424）；
- **支撑建议（suggest）**：`ok / recenter / step`（margin 越界 → step）——属伺服内部状态
  （用户定调：支撑属伺服、属**自动化撑地**）；
- **自动撑地（support directive）**：摆动腿**无人主动指挥**（无 pin/手动角/手力矩）时，
  伺服自动建撑点——落点在望 → 预撑（轻屈膝缓冲，触地即能承重）；支撑越界 → 加深
  （catch）；有主动指挥则让位（与消力同一条执行路径与让位规则）；
- **判定修正（实测）**：仅"卸载"（脚还踩地）不算单支撑——单支撑语义（mode/钳制/
  preland）要求**摆动脚真的离地**（脚体间隙 >2cm）；轻触同样要求 gap>1cm。
  **但姿态助力通道保留失衡门控**（离地门控会让权重转移在 ~45% 处停滞，实测）。
- **支撑腿也要伺服帮助（用户定调）**：单支撑中支撑腿有三层伺服照管——姿势张力
  （零位刚度，防塌）+ `load` 负载撑住（膝屈>0.10 → 伸展力矩 ≤150 N·m）+ 垫脚
  （踝 CoP）。极端瞬态受执行器饱和限制（实测 0.8 m/s 下压时差异仅 0.003 rad，
  是物理上限非逻辑缺陷）。
- **组织修正（2026-10）**：单支撑姿态通道的**判定上收伺服**（门控/锚点/del→角目标
  全部在 StabilityWarner 计算，作为 `lean` directive 的 `postureHip/postureSpine`
  参数下达），`LeanReflex.applyLateral` 回归**纯执行**（限速+写入）。行为逐位保持
  （servo-guard 数字一致）。执行方不再自行判定——对齐"反射弧=被动工具箱"原则。
- 相位经验：**preshift 过期时不得把目标拽向承重脚**（放腿落地瞬间横跨拉目标 =
  侧向踢飞，附录 A.7）；**姿态通道不得加滞回锁存**（持续压骨盆 → 矢状后漂，A.7）。

### 2.4 两层可行化的分工（用户定调）

| 层 | 可行化 | 面向 | 谁能控制 |
|---|---|---|---|
| **动作系统** | **对外可行化器**：外部意图 → 可行的动作提案（相位/时长/轨迹/过渡点，规划时按能力边界来） | 外部（游戏/AI/意图） | 是——动作者自己规划、参数化 |
| **伺服层** | **内部可行化**（§2.3）：稳定包络 | 只对稳定 | **否**——不可从外部设定/扩权，只读状态与当前目标，默默执行 |

1. **伺服没有任何外部旋钮**：动作改不了包络；动作目标超出包络时，伺服**静默钳制**
   （backstop），不询问、不报错；
2. **两层分开实现**：动作的可行化在动作系统内独立实现，伺服的可行化在伺服内独立实现，
   **不共用同一个可行化器/代码路径**。理由：职责不同、**故障隔离**（动作规划出错，
   伺服照样兜底）、**演化独立**（任务侧跟内容走、伺服侧跟动态状态走）；
3. 两层之间只有**只读数据**流动（动作可读伺服的支撑状态等作为输入），
   各自的可行化逻辑、模型与保守度**各自决定、各自演进**。

### 2.5 提案接口与 directives（现状）

```ts
interface StabilityProposal {
  comAdjust: { ax, az };                    // 期望 CoM 修正（世界系加速度）
  desiredCop: { x, z } | null;              // 期望 CoP（踝/柔性足的去处）
  reflexDirectives: { id: string; weight: number; params?: Record<string, number> }[];
  level: 0 | 1 | 2;                         // 派生标签（0 常规 / 1 饱和 / 2 出界）
  reason: string;
}
```

| directive | 携带 | 执行方 | 说明 |
|---|---|---|---|
| `pad` | kp/kd | `FootPad` | 四向 CoP；腾空脚禁用；侧向物理上限 ±2cm |
| `lean` | `copZ`（期望 CoP z） | `LeanReflex.applyLateral` | **差动加载**（双支撑）+ **门控单支撑姿态**（失衡>0.7 才开） |
| `bend` | x/kp/kd/spine | `LeanReflex.applyBend` | 髋力矩（cap 60）+ 脊柱屈伸位置通道 |
| `support` | side/depth | `LandingAbsorb.setPreBrace` | **自动撑地**：摆动腿无人指挥时，伺服给落腿预撑（屈膝缓冲，触地即承重）；越界加深（catch） |
| `load` | side/tau | `LeanReflex.applyLoadBrace` | **支撑腿撑住**（负载反射 lite）：单支撑中支撑膝在负载下屈曲（>0.10 rad）→ 伸展力矩托住（≤150 N·m）；让位同其他反射 |

### 2.6 能力表（实测标定，候选评估的约束来源）

| 通道 | 权限（实测） | 备注 |
|---|---|---|
| 垫脚（踝/柔性足 CoP） | 前 +14 / 后 −5 / 侧 **±2cm** | 侧向是**物理上限**（柔性足吸收踝滚，附录 A） |
| 差动加载（同号髋力偶↔负载差） | ±20 N·m ↔ u≈∓0.5、CoP 搬 ±8cm；反号无效 | **双支撑的主通道**（Winter 1996，最小相位） |
| 单支撑门控姿态（髋+脊柱） | hip 1.0·del（cap 0.30 rad）、spine 0.5·del（cap 0.12/段）、限速 1.2 rad/s | **门控到真实单支撑**（>0.7）——双支撑摇摆下会泵 |
| bend（矢状） | 髋力矩 ±60 N·m + spine/2 1.0·del（cap 0.08） | 垫脚前后为主，bend 是帮手 |
| 目标守护 governor | 单支撑目标钳 ±6cm（绕支撑脚）、双支撑 ±0.17；限速 0.1 m/s；过期 0.6s 后 0.05 m/s 回正 | 静默 backstop |

**符号约定（踩坑表，勿再弄反）**

| 通道 | 关节 | 把 CoM 推向 −z（支撑在右）的符号 |
|---|---|---|
| 髋 | `hip_*/0`（外展） | **负**角 |
| 脊柱 | `spine*/0`（侧屈） | **负**角 |
| 摆臂 | `shoulder_*/0` | **正**角（★ 与髋/脊柱**相反**——同号曾致正反馈发散） |
| 踝 | `foot_*/2` | 正 = 跖屈（垫脚前向）；消力要**背屈**（负） |
| 脊柱前后 | `spine*/2` | **正 = 向后弯（CoM 后移）/ 负 = 向前弯（CoM 前移）**（★ 2026-10 `_probe-lean-sign` 复测定死：+0.08→comX −0.019、−0.08→comX +0.018；用户目视一致；此前「正=前弯」注为误） |

### 2.7 升级与放弃（恢复策略）

| 级 | 触发 | 动作 |
|---|---|---|
| 0 | 需求 q 在能力表内 | 正常 directive（pad/lean/bend） |
| 1 | 预算用尽 / `|qZ|>0.2` | 标记饱和（迈步放行用，占位） |
| 2 | XCoM 出可恢复界持续 ~0.2s | **giveup → 保护程序全权**（§4） |

### 2.8 已知边界（物理约束，如实记录）

- **脚不动可撑区**：矢状 +14/−5cm、侧向 ±2cm（踝）+ 差动加载的作用范围；
  **CoM 超出可撑区且脚不动 = 伺服救不了**——只有两解：**姿势设计**（把 CoM 留在区内，
  动作的活）或**迈步**（未来）；
- 实测例：直控把腿抬到 45cm 会让 CoM 后移 ~16cm，保持相靠姿态硬撑、放腿即倒——
  抬腿姿势必须配躯干前倾补偿或先转移重心（动作层职责）；
- 单支撑时负载差饱和（u=1）⇒ 差动加载失去侧向权限，搬 CoM 只能靠门控姿态通道。

### 2.9 ★ 横向控制的两处正确性修正（2026-10，文献依据）

- **CoP 可行性投影**（Englsberger et al. 2013/2015）：`desiredCop` 生成后**必须夹进支撑多边形**
  （双脚踝锚点外扩半脚宽 5.5cm / 半脚长 10cm）——旧值 +0.03 在两脚外，髋环追不可达点满幅乱顶（实测 114–120 N·m）；
- **差动加载 u\* 重定心**（Winter 1996）：`u* = −(CoP目标 − 双脚中点) / (半跨距)`——旧式 `−copZ/0.16`
  以世界 0 点定心，只在对称站距正确；单支撑落地后两脚都挤在支撑侧（中心 ≠0）时**方向算反**（实测把 CoP 往反方向搬，是 E 相失控的直接原因之一）；
- 腰部容量：脊柱 τmax 120→170（单腿实测侧向 72 全饱和；"强肌肉控制"定调）。

### 2.10 ★ 已知伺服缺口（2026-10 现状——"伺服没做好"清单）

动作层与反射层已把可做的都做了（全压闸门/支撑下压/支撑力矩/APA/被动链/姿态限幅），
单脚剩余失稳已收敛到**伺服层自身的闭环品质**：

| 缺口 | 现象（实测） | 方向 |
|---|---|---|
| 横向环（差动加载 u 环） | 单支撑边界的权限/相位；±45 不够、±90 过冲；落地负载搬移慢 | 系统辨识（u→负载 增益/相位）后定参 |
| 姿态环（att/posture） | 曾自振（目标 ±0.21 摆动→169 N·m 内推，已修符号）；脊柱姿态跟随品质 | 闭环带宽/相位裕度复核 |
| 支撑侧向环 | 支撑髋承重力矩 70–85 N·m 与骨盆侧倾耦合 | 承重环与姿态环的耦合解耦 |

> 动作层侧（本节之前全部）已验收；上表三项即"伺服没做好"的具体化，是单脚全程不摔的最后一段。

### 2.11 ★ 伺服重构蓝图（2026-10，文献依据；用户定调：上下身分开/前后左右分开/应对现在与未来的抖动）

| 设计轴 | 文献 | 结论 |
|---|---|---|


### 2.13 ★ 伺服层内部架构：Now/Future 双管道 + 单提案出口（2026-10 用户定调）

**架构要干净**——伺服层（StabilityWarner）内部按"现在/未来"切两条**独立管道**，
在**一层整合**后只提交**一个 `StabilityCorrection` 提案**（提案制；控制层仍唯一裁定/写手）：

```
伺服层 StabilityWarner（内部）
├─ 管道 Now（现在）——"当前状态修正"
│    输入：当前传感（CoM/CoP/载荷/关节）
│    处理：差动加载(u环)/垫脚(CoP)/姿态(att)/支撑力矩/自适应陷波·PPF/增益条件(kd铁律)
│    输出：即时修正量
├─ 管道 Future（未来）——"预测与预期"
│    输入：状态+速度（外推）
│    处理：TTB/XCoM 外推 / preland 预转移 / 预载(APA) / 能量账本(波变量,抗未来抖动)
│    输出：预期修正量
└─ 整合层（唯一出口）
     两管道输出 → 逐轴融合(增量叠加)/冲突消解(紧迫度) → 单个 StabilityCorrection 提案
     提案 → 控制层 ingest → 裁定 → Executor（唯一写关节）
```

**纪律**：
1. **两条管道独立**：互不读对方的中间量（可并行/可单独测试）；只在整合层汇合；
2. **出口只有一个提案**：不新增提案通道（保持 `ingest(c: StabilityCorrection)` 不变）；
3. **Now 优先**（用户定调：现在的抖动优先处理）：整合时 Now 的紧迫度权重 > Future；
4. 反射弧（§3）仍是两管道共用的**被动工具箱**（由提案里的 `reflexDirectives` 调用）。

### 3.2 被动性纪律与让位

> ★ 2026-10 新增 **蹲起**（动作层 `actions.ts::SQUAT_RISE`）：膝 −95（蹲）+ 髋屈姿势 +0.25
> rad 补偿（**上身竖直**：动作自己保持姿势，不捞伺服）+ 缓释站起；实测行程 2.9cm、
> 躯干倾角 ≤4.2°、全程不离地、重心带 [0.007,0.034] m、末态站住（`probe-control` E）。

> ★ 2026-10 实测补充：**消力的"动作抑制"**——动作播放中 + **1.0s 尾随**内消力整体让位
> （`landing.setInhibit`，由控制模块每拍告知）。根因：蹬地挺腰动作结束"解钉"瞬间，
> 消力把蹬地的力尖峰/假落地当"落地"，以 depth 0.5 猛压膝盖（膝 −0.48 rad）——
> 就是可见的"蹬地腿抖"（挺腰 HF 曾被抬到 80/361）。负载持续判定（0.25s）试过会
> 误伤真落地已回退；**真落地由冲击项即时响应，不受抑制影响**（真落地场景无动作）。

> ★ 2026-10 加装 **抓地窗口**（用户定调："着地的时候不仅要屈膝，还得抓紧地、站稳"）：
> 触地边沿起 **0.3s** 内，消力反射把该脚**踝轴写到 0（放平贴地，kp200）**——仅在该轴
> 无主动命令时写（让位规则不变）——让足底快速满接触、载入后撑稳，再交还正常通道。
> 回读 `landing.gripOf(i)`。

- 输入=传感读数，输出=关节命令/力矩，**不选择、不锁存、不越级**；
- 需要选择的（分级、放弃）→ 是恢复策略（§2.7），不是反射；
- **pin 仲裁**：动作层对"归我管"的自由度打标（`ManualControl.pin`），反射执行方跳过；
  动作脚本播放时 `ActionSystem` 自动 pin 脚本写到的关节、结束解钉；
- **主动发力让位（用户定调）**：**垫脚与屈膝（消力）只在"非主动发力"时使用**——
  该关节存在主动命令（pin / 手动角 / 手动力矩）时反射不出力（由主动方负责）。
  消力已默认启用；**垫脚为选项 `yieldToActive`（默认关）**：动作的 pin 目前是
  脚本级全时段，直接开启会让蹬地开局"踝无人管"而摔（附录 A）——先让动作在主动
  窗口自给自足（逐轴动态归属 + 480Hz 重标）再打开。

### 3.3 落地/负载消力（连续力反馈，实测定型）

```
depthTgt = perFz·max(0, Fz/W − fz0) + perV·vImp·e^(−t/0.15)
          fz0=2.0W（单脚静载 1.0W 不弯）；vImp=触地边沿一次性捕捉的冲击速度
          （要求先"真腾空" airTime≥0.08s，防抬腿蹭地误触发）
上升 16 rad/s；回伸 τ=0.18s；maxDepth 0.6；膝为主，髋 +0.35、踝 −0.18（背屈）
```

- **"不只是落地：膝受力大就弯"**（用户定调）→ 连续力项常开；落地是它的特例；
- 验证：`_probe-landing` 低落峰值力 32%→21% W、高落膝屈随落高单调、回伸残差 ~0。

### 3.4 间歇控制（侧向的文献形态，Bottaro 2005）

静立摆动是**间歇控制的抖动**——控制器在阈值面才触发弹道式修正。
连续高增益 + 延迟 = 相位泵（附录 A）。侧向的快环应用**阈值+滞回+短脉冲**的形态；
现有差动加载已是"低带宽力环"，间歇化是后续精炼项。

**重写**：`FootPad.autoFromCom` 内计入支撑跖屈的 CoP 偏移（`pX -= ff/fz`）——
支撑的 ff（τ）会把 CoP 前移 τ/fz，目标同源扣除（一个环、同源目标），止住同轴对拉。

**实测（标准值基线 90/50/−50 上）**：
| 通道 | 重写前 | 重写后 |
|---|---|---|
| 支撑踝净矩 | −2~−77（背屈，被反制） | **+31~+84（跖屈✓，70% 标准）** |
| 支撑膝净矩 | 中性 | +30~+46（伸展✓） |

## §2.33 "单腿跳"回读（2026-10 用户：发力时承重腿在跳）

**回读**：Rfz 64→96→79→64→85（±15%W 垂直自激）；膝角 0.03~0.08 波动。
**降档实验**：90/50/−50→0.227（有跳但最优）；70/40/−40→0.155（且前漂 vx+0.22）；50/30/−30→0.141。
**结论**：跳≠支撑过强——**垂直环欠阻尼**（支撑柱静态力矩无阻尼项 + pad 同源环的相位）。
**阻尼实验**：−60 → 0.226、跳 64–96→**71–92**（改善未根治、前漂 vx 变差）；−120 → 0.145。
按用户"解决不了就回退"：**已回退**（标准值 0.227 干净版）。
**根治方向**（下一轮）：跳的源头 = pad 同源环的相位滞后（τ/fz 用的是上一拍台账）——
需相位补偿或预测项，非阻尼补丁。

## §5 设计纪律（从实测提炼，新增特性先过）

1. **出口纪律**：一切输出去控制模块的整合器，逐轴合并，唯一写点 Executor；无人绕过；
2. **能量纪律**：冲击/接地阶段只允许耗散（阻尼、退让），禁止"存储-返还"；
3. **相位纪律**：非最小相位通道（髋/腰/臂）**低带宽或间歇**；能走最小相位通道
   （踝/CoP、差动加载、迈步）就别用它们扛高频；
4. **可行性纪律**：两层可行化**分开实现**（§2.4）；伺服无外部旋钮、静默钳制；
5. **消融纪律**：每个特性可开关、可回读；新特性必须过对应探针：
   `_probe-lateral-resonance`（0.4 冲量衰减）、`probe-control` A–D、
   `_probe-servo-guard`（直控单支撑/回正）、`_probe-push-jitter`（HF 门禁）、
   `_probe-landing`、`_probe-bounce`；
6. **符号纪律**：改任何通道先看 §2.6 符号表；摆臂与髋/脊柱**反号**是曾经的发散源。

## 附录 A：演进史与实测坑（项目资产，勿删）

### A.1 抖动/共振彻查（2026-10，最高优先级事件）

- **回归定位（逐提交二分）**：静站 HF 与挺腰 HF 在最后提交从 5.4e-4/297 跳到
  86/1440——该提交把 Drive 默认 `kd 0.02→0.05`，显式阻尼越过低惯量轴
  （踝/柔性足链）的离散稳定界（`B·dt/M_uu < 2`）→ ~80–100Hz 全身微振；
- **有效手段（实测排序）**：① 回退干净版（kd 0.02）；② arch 引擎 220/40
  （共振相消点）；③ 物理 480Hz（稳定余量 ×4）；④ 关闭侧移 boost；
  ⑤ **差动加载取代位置环**（顺带把挺腰 HF 75.6→13.7，站立 2.5e-5）；
- **失败清单（勿重蹈）**：隐式 PD / 隐式阻尼 / HF 阻尼器 / 关节刹车 / 世界翻转吸收
  ——五类"新增反馈或速度改写式耗散"全部把驱动环搞崩。**耗散只能来自既有稳定通道**
  （kd 上限、引擎参数、频率余量），或**前馈**（输入整形/指令平滑）；
- **结论**：残余抖动是**有界极限环**（柔性足链 10Hz ±0.5° + ~109Hz 微分量），
  已达"控制算法可弥补"的量级（前馈处理，不再动反馈环）。

### A.2 横向自激（旧位置环的坑）

- 现象：位置式髋策略（非最小相位）高增益 + 延迟 → 0.4 m/s 冲量下摆幅
  **指数增长**（8→130cm 摔倒）；小信号也长（线性不稳定）；
- 当时修法：`leanGain ≤0.35` + boost 锁存（历史）；
- **根治**：差动加载（力环、最小相位）——现在位置通道只在"真实单支撑"门控下用。
- **纪律**：一切侧向/平衡新特性必须过 `_probe-lateral-resonance`（衰减）。

### A.3 垫脚侧向的物理上限（`_probe-roll-cal`）

- 踝滚 0.215 rad（±0.24 行程的 88%）只换来 **1.8cm** CoP——柔性足把踝滚吸收在
  脚内部（脚体相对鞋底滚、鞋底平贴），滚动传不到地面；**±2cm 就是物理上限**；
- 装配层健康（映射/回读/限位三探针验证）；更大侧向必须走差动加载。

### A.4 pin 与让位的教训

- 动作的 pin 是**脚本级全时段**：一按按钮，脚本碰过的关节从 t=0 钉到结束——
  蹬地开局 0.9s 踝"无人管"而摔（垫脚让位直接开启的失败）；
- 正解：**逐轴动态归属**（只钉"当前正在驱动"的轴），随后才能安全开启垫脚让位。

### A.5 保护程序的实测（`_probe-bounce`）

- 纯布娃娃砸地**不弹**；伺服开着就弹（4–9cm 回升）→ D 相必须真正卸力；
- 竖向触地回弹部分来自腿伺服欠阻尼（kd 调整影响见 A.1）。

### A.7 P1 支撑控制的实测教训（2026-10，探针逐片二分）

- **姿态通道滞回锁存：拒绝**。单支撑姿态通道（hip/0+spine/0）加"入 0.7/退 0.5"锁存后，
  持续压住骨盆姿态会耦合进矢状——保持期 1.5s 内 comX 从 −0.008 漂到 −0.197。
  逐帧门控（imb<0.7 立即松）反而稳。**锁存不是免费午餐**。
- **preshift 猛拽：拒绝**。目标过期时把内部目标拽向"承重脚中心"：放腿落地瞬间
  左右脚主从切换 → 目标横跨整个身体被拉过去（±0.24 的跳变）→ 侧向踢飞、外侧翻倒。
  已改为：preshift 只在目标新鲜时做常规双支撑钳制，过期走半速回中。
- **bend（髋+脊柱）单支撑下不可用**。隔离实测（pad 关）：默认 `bendSign=+1` 方向反了
  （CoM 反向跑到 −1.09）；改 −1 方向对，但**单支撑下任一侧通道（髋/脊柱）都会把
  CoM 往错误方向赶**（骨盆反应/非最小相位），双支撑下由 pad 兜底才无害。
  现状：`bendSign=-1`（修正），**bend 只在双支撑起效**（单支撑 cap=0、spine=0）。
- **旧 `_probe-bend` 标定被污染**：pad 开着时 ±1 都能把 CoM 推 +0.07（脚尖 +14cm
  权限盖过一切）——**隔离实验（NOPAD=1）才是可信标定**。
- **探针场景要选在设计包络内**：③b 的"通过"历史上靠摆动脚蹭地（Lfz 15%）刹车；
  把矢状治好（脚离地）后同一场景暴露为刀刃。验收场景本身也需按包络设计。
- **preland 温和预转移是放腿窗口的钥匙**：落地前把目标滑向双脚中点+前移 5cm，
  放腿末速 −0.30→−0.08、胸 1.406→1.424、④ 起点从"已在倒"变为"站着"；
  **前移量的物理判据**：冲量后 CoM 要留在 `x ≥ 脚跟 + v/ω0` 内（v=−0.08 时 x≥0）。
- **"冲量后修正"数学上不可能**：CoM 越过脚跟权限后（XCoM < −0.05）垫脚/髋/脊柱
  都无法回天（bend 的 CoM 权威只有 ~2–3cm 的量级）；一切必须在冲量**前**处理。
- **"卸载 ≠ 单支撑"**：只按 fz 失衡判单支撑会把"双足踩地、单侧卸载"的权重转移
  误当成单支撑（钳制收紧/门控收紧/lightTouch 误触发 preland）。修正 = 摆动脚
  离地（脚体间隙 >2cm）才进单支撑语义（`_probe-brace` 实测）。
- **姿态助力的失衡门控不能跟着收紧**：权重转移末段（双足仍踩地）靠姿态通道
  把 CoM 拉上支撑脚；加离地门控后转移卡在 ~45%、12s 走不完。两套门控分离：
  **支撑语义=失衡+离地；姿态助力=只看失衡**。
- **自动撑地（support directive）已接线**：摆动腿无人指挥时给落腿预撑
  （`_probe-brace` 中 ④ 起点撑深 0.033→0.067 生效）；但"腿回摆冲量"物理墙
  依旧——撑地解决的是"落得下、承得住"，救不了扫回的动量。
- **组织纪律（用户点名"伺服内部是不是乱了"）**：判定确实在泄漏（执行方自己算
  失衡/锚点/门控）——已把姿态通道判定上收伺服（提案携带 `postureHip/Spine`），
  执行方回归纯执行；**新纪律：任何执行方不得自行判定支撑状态**（只读提案参数）。
- **"为什么这么容易前后摔"的根因 = 站姿矢状位置**（`_probe-sag` 回读）：
  默认站姿 comX≈−0.009 **贴着踵侧**，后向 CoP 余量只剩 ~4cm（前向 15cm）——
  后推 >0.1 m/s 必倒。前移到 +0.025 后余量 ~6.5cm、门限 ~0.15 m/s。
  ★ **安静边界**：+0.03 起挺腰 HF 爆（345）、+0.035 站立炸——脚弓工作点会抬起
  柔性足链 ~70Hz 微极限环（回读：膝速度幅 0.9 rad/s 持续、θ 幅仅 0.002 rad）。
  所以站姿取 **+0.025（甜蜜点：站立 2e-5、挺腰 60、蹬地 C 首次生效 5.3cm）**；
  更大的静态余量需要先根治极限环的工作点敏感性。
- **"挺腰"机理与直觉相反**（`_probe-sag` C 段开环回读）：hip/2 **正力矩**（躯干
  前倾）→ CoM **后移**（骨盆/腿反作用吃掉）；**负力矩**（躯干后仰）→ CoM 前移、
  更稳——这才是本骨架有效的"撑起来"方向（与 `bendSign=−1` 修正一致）。
  躯干模式的 CoM 权威只有 ~1.5–3cm，**救不了大冲量**；前后防摔的主力是
  站姿余量（静态）+ 早动（XCoM 一越界就反应）+ 迈步（动作）。

## §2.35 主动发力写手清理 + 骨盆/被动承力 + 抬腿-平衡耦合（2026-10 末）

### 根因三连（"支撑腿用不上力"）
1. **`manual.clearAngle` 不驱离 Drive 旧目标**：让位后 Drive 里残留 kp≈237 的 PD 继续压关节。
   修：`clearAngle` 连 `drive.clearAngle(i)` 一起清（manual.ts）。
2. **姿势基线与程序关键帧无视 pin**：主动 ff 被默认刚度（postureTone 派生 kp）回写。
   修：`pin + |ff|>1` 时两者都让位（stability.ts / control.ts）。
   注意：**全量按 pin 让位会伤挺腰**（有 pin 无 ff 的轴丢了姿势 PD，HF 3.18e+1→1.24e+2）——
   条件必须是"pin **且**有主动力矩"。
3. **B 相首帧 ff 未写**：基线抢在 supportColumn 之前把膝目标写回 0（之后残留）。
   修：B enter 里立即调 `supportColumn`。

修后（HEAD 基线实测）：支撑膝 servo=0（纯 ff +53）、踝 ff +95~110（全身最大出力）、
**抬脚 6.8cm**、门禁 2.39e-5 / 3.18e+1 全绿。力矩分布：踝≈2×膝（Winter 框架 ✓）。

### 盆骨（用户问："需要专门做一个盆骨吗"）
**不需要**：`spineSegments=4` 时躯干自动分段，**段 0（key 'torso'）= 骨盆**，
髋关节按锚点挂其上（skeleton.ts:163,992）。缺的是它的**控制**不是结构。

### 被动承力（用户问："能不能被动传递力"）
**能，但有条件**：IT band 被动件（drive.ts:166，Inman 1947：人体约一半髋外展矩被动）
即该机制；但全局加强（k 12→60）**卡死 A 相转移**——被动件在功能活动范围内也咬合。
正确形态 = 阈值在功能域之外（或方向选择性），被动是安全网、不是主控。

### 横向漂移（弹射）根因：配重项**符号为同向**（正反馈）
`counterbalanceZ = kc(footZ−restZ)`：摆动腿外展向外→目标也向外→CoM 跟出界。
反号（−kc）后横漂从 comZ +0.54 收敛到 +0.05。**但抬脚从 6.8→3.2**（耦合）。

### 抬腿-平衡耦合矩阵（实测，均为反号配重）
| kc | B 保持 | 抬脚 | 最低胸 | comZ@5s |
|---|---|---|---|---|
| +0.25（原） | 0.55/−0.90 | **6.8** | 0.136 | +0.54 弹射 |
| −0.20 | 0.55/−0.90 | 3.1 | **0.213** | +0.02 ✓ |
| −0.25 | 0.70/−1.10 | **7.1** | 0.136 | +1.02 弹射 |
| −0.12 | 0.55/−0.90 | 5.6 | 0.137 | +0.71 |

规律：抬脚↑ → 摆动质量行程↑ → 横漂积累↑（配重项只含 footZ 侧向，不含抬腿质量的完整位移）。
**当前入驻**：反号 + kc 0.20 + 原抬腿（平衡最优 0.213；抬脚 3.1 待解耦后回升）。

### 待办
- 抬腿与平衡解耦：配重项用**摆动质量完整位移**（含抬腿行程）而非仅 footZ；
- 失稳链其余项：comX 前漂（5s 后 0.2→0.3）仍在；

## §2.36 承重盆骨（2026-10 末；用户："做一个能承重的盆骨"）

### 回读（`_probe-pelvis-load`）：盆骨**没承住**——能力不够实锤
- B 相骨盆**滚转 ±17~23°**（在摇滚，不是稳承）；
- 支撑髋外展：实际恒 −0.20 vs 目标 +0.05~+0.16（差 0.3 rad），**力矩 104~152 全饱和**（上限 120，
  Inman 静态需求 112 的 93%——本就贴极限）；spine1 侧屈 ±8°（摇晃上传）。
- 结构：盆骨=躯干段 0（`torso`，8.7kg，y=0.826），两髋+spine1 都挂在它上——**结构没问题，是力不够**。

### 修：分期承重（`stepPhases::pelvisBearing`）
- 文献：转移期骨盆下沉是**转移机制**（外展要自由）→ A 相不锁；单支撑期 Duchenne/力闭合 → B–E 锁。
- 实现：B–E 段支撑髋外展加力 `extra = clamp(1400×roll, ±90)`（ff 通道，与 servo 叠加）。
- 实测（±90档）：骨盆滚转 **17.4°→9.5°**、外展下沉 −0.22→−0.10、**抬脚 3.8→7.3cm**、
  最低胸 0.144→0.153；门禁 2.39e-5 / 3.18e+1 ✓。
- 反面教训：全局放开外展 τmax（0.60→0.85）**卡死 A 相转移**（默认伺服 kp 随 τmax 放大→骨盆锁平→
  无法转移）——能力必须**分期**给，不能全局加。

### 遗留
- 残余滚转 ~9.5°；中途失稳（最低胸 0.153）尚在。
