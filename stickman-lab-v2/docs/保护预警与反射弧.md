> **架构.md 仍是唯一真源**；本文档只在它的框架内做展开，冲突时以架构.md 为准。

## §1 三个东西必须分开（之前的一切混乱都在这里）

| 类别 | 定义 | 有无选择/状态 | 例子 | 归属 |
|---|---|---|---|---|
| **反射（Reflex）** | 固定"感觉→动作"回路 | 无选择；固定增益/延迟；可有极小相位状态 | 垫脚、牵张、负载、翻正、落地消力 | §3 |
| **恢复策略（RecoveryStrategy）** | 需要分级/锁存/切换的决策 | 有状态、有阈值 | pad→hip→giveup 选择器 | §2.5 |
| **保护程序（ProtectiveProgram）** | 跌倒已不可避免后的急救 | 有相位、**全权接管** | 绷直、重心转移、跪撑、起身 | §4 |

- "绷直身子"在神经科学里叫保护性反射，但**工程上归保护程序**（有触发状态、有相位、
  全权接管）——把它当反射会污染反射弧的"无状态"语义；
- 反射弧是**被动工具箱**：只按预警的 directive 或自身触发条件运行，不做策略选择；
- 三者的输出**一律经控制模块的整合器**，没有谁能绕过（出口纪律，§5）。

## §2 摔倒预警（伺服层）

### 2.1 角色

预警是稳定性的"大脑"：算 CoM/XCoM/CoP、决定怎么修，输出 `StabilityProposal`
（每拍连续；只读，不写关节），提案里包含**如何使用反射**（`reflexDirectives`）。
平衡模块属于预警——不存在第二套独立的"平衡控制器"。

### 2.2 提案接口（现状）

```ts
interface StabilityProposal {
  comAdjust: { ax, az };                    // 期望 CoM 修正（世界系加速度）
  desiredCop: { x, z } | null;              // 期望 CoP（踝/柔性足的去处）
  reflexDirectives: { id: string; weight: number; params?: Record<string, number> }[];
  level: 0 | 1 | 2;                         // 派生标签（0 常规 / 1 饱和 / 2 出界）
  reason: string;
}
```

当前 directive：`pad`（四向 CoP）、`lean`（左右：髋+脊柱+摆臂）、`bend`（前后）。

### 2.3 需求幅度（替代粗糙 PD）

```
q = 目标 − (CoM + v/ω0)     ω0 = √(g/h_CoM)
```

含动量项（XCoM 思想），x/z 各算各的。它同时是"幅度需求"：
**q 大于预算就说明救不回，应升 level / 给迈步或放弃**。

### 2.4 幅度预算（逐级分配）

| 级 | 通道 | 标定增益 | 饱和 |
|---|---|---|---|
| 踝/垫脚 | CoP 四向 | 侧 ±2cm / 前 +14 / 后 −5cm | 足几何（侧向全开的 bug 见 §7） |
| 髋 | 外展（骨盆） | ≈1.6 rad/m（实测权限 ~0.63 m/rad） | 0.4 rad |
| 脊柱 | 侧屈 | 0.5 + 2.0·boost rad/m | 0.22 rad/段 |
| 摆臂 | 肩水平 | ≈0.0675 m/rad（与髋/脊柱**反号**） | 1.0 rad |

- **boost（单支撑分账）**：脚力低通 80ms → 失衡度**滞回锁存**（>0.8 认单支撑，
  <0.5 释放）+ 0.15s 平滑；单支撑时腰多分、髋让位；
- 全饱和仍不够 → `level=1`（未来的迈步放行用）。

### 2.5 升级与放弃

| 级 | 触发 | 动作 |
|---|---|---|
| 0 | q 在预算内 | 垫脚/lean/bend |
| 1 | 预算用尽 | 标记饱和（未来接迈步提案） |
| 2 | XCoM 出可恢复界持续 ~0.2s | **giveup → 保护程序全权**（§4） |

### 2.6 符号约定（踩坑表，勿再弄反）

| 通道 | 关节 | 把 CoM 推向 −z（支撑在右）的符号 |
|---|---|---|
| 髋 | `hip_*/0`（外展） | **负**角 |
| 脊柱 | `spine*/0`（侧屈） | **负**角 |
| 摆臂 | `shoulder_*/0` | **正**角（★ 与髋/脊柱**相反**——同号曾致正反馈发散） |
| 踝 | `foot_*/2` | 正 = 跖屈（垫脚前向）；消力要**背屈**（负） |
| 脊柱前后 | `spine*/2` | **负** = 前弯（BOW 实测） |

### 2.7 横向自激（头号坑，必读）

- **现象**：横向冲量后摆幅**指数增长**（0.4 m/s 冲量下 8→130cm 直到摔倒）；
  小信号（2cm）也长——线性不稳定，不是饱和；
- **机理**：髋策略**非最小相位**（移 CoM 先反冲骨盆）+ 传感/执行延迟 →
  ~1Hz 以上相位反转，修正变泵；负载 boost 随摆幅调制会加剧；
- **修法**：`leanGain` 环路增益（**扫描实测 ≤0.35 才衰减**，默认 0.35）；
  boost 滞回锁存；动作的有意搬移期间临时抬到 1.0；
- **纪律**：一切侧向/平衡新特性必须过 `_probe-lateral-resonance`（0.4 冲量衰减）。

## §3 反射弧

### 3.1 清单（只放真正的固定回路）

| 反射 | 生物对应 | 触发 | 输出 | 依据 |
|---|---|---|---|---|
| **垫脚** | 踝-足触觉快环 | CoM/XCoM 误差 | 每脚四向 CoP（踝屈伸 + 内外翻 + 柔性足） | Winter 1995 / Hof 2005 |
| **落地/负载消力** | 负载/着陆缓冲 | 连续：Fz 超阈 / 触地冲击 | 按力大小屈曲→回伸（**函数式**，§3.3） | Geyer & Herr 2010；Blickhan 1989 |
| 牵张 | 肌梭单突触 | 关节角误差/速度 | 刚度/阻尼调制（Actuator 内建） | Nashner 1976 |
| 负载 | 高尔基腱器官 | 支撑脚 Fz 骤降 | 伸肌力矩脉冲（防腿软） | Nashner 1976 |
| 翻正 | 前庭-脊髓 | 躯干倾角/角速度 | 脊柱/髋回正力矩 | Horak & Nashner 1986 |
| 屈曲回撤 | nociceptive | 意外碰撞 | 快速屈腿（后置） | — |

### 3.2 每个反射的"被动性"纪律

- 输入=传感读数，输出=关节命令/力矩，**不选择、不锁存、不越级**；
- 需要选择的（分级、放弃）→ 是恢复策略，不是反射；
- **pin 仲裁**：动作层对"归我管"的自由度打标（`ManualControl.pin`），
  反射执行方跳过；动作脚本播放时 `ActionSystem` 自动 pin 脚本写到的关节、
  结束解钉（否则位置式反射会抢掉鞠躬/蹬地）。

### 3.3 落地/负载消力（连续力反馈，实测定型）

```
depthTgt = perFz·max(0, Fz/W − fz0) + perV·vImp·e^(−t/0.15)
          fz0=2.0W（单脚静载 1.0W 不弯）；vImp=触地边沿一次性捕捉的冲击速度
          （要求先"真腾空" airTime≥0.08s，防抬腿蹭地误触发）
上升 16 rad/s；回伸 τ=0.18s；maxDepth 0.6；膝为主，髋 +0.35、踝 −0.18（背屈）
```

- **"不只是落地：膝受力大就弯"**（用户定调）→ 连续力项常开；落地是它的特例；
- 验证：`_probe-landing` 低落峰值力 32%→21% W、高落膝屈随落高单调、回伸残差 ~0。

### 3.4 间歇控制（建议升级方向，文献支撑）

Bottaro 2005：静立摆动是**间歇控制的抖动**——控制器在阈值面才触发弹道式修正。
连续高增益 + 延迟 = 相位泵（§2.7 实测）。**侧向环应改为阈值+滞回+短脉冲**，
把现有的 latch/boost 思路升为一等公民，从结构上免疫共振。

### 3.5 小腿抖动 / "把力传到地面"——文献武器库（2026-10 查证）

| 方法 | 文献 | 机理 / 对我们的用法 |
|---|---|---|
| **稳定 PD（隐式/半隐式）** | Tan et al. 2011, IEEE CG&A（已引） | 根修：弹簧/阻尼按 **I_low 隐式化**（`τ=(kΔθ−Bω)/(1+(Bdt+kdt²)/I_low)`），离散无条件稳定。我们实验：站立 HF 86→**2.5e-4**；代价=轻关节有效刚度变软，动作力键需重标 |
| **受控软接触** | 接触模型（工程惯例） | `contactHz=60` 实测挺腰 HF 1440→**341**（4×）；代价=接触变软、延迟增 |
| **串联弹性驱动（SEA）** | Pratt & Williamson 1995, IROS | 机械低通：力经弹簧传到地，天然滤掉硬接触高频。**我们的柔性足（arch/mfoot 引擎弹簧）就是 SEA**——应把它当"力传地面"的滤波器来调（stiffness/damping），而不是当 bug 消 |
| **接触过渡的冲击/力控** | Whitney 1977, JDSMC；Volpe & Khosla 1993, IJRR | 落地/承重瞬间从位置伺服切到**力/阻抗（admittance）控制**；"力传到地"=直接控地反力，不靠位置硬顶 |
| **输入整形** | Singer & Seering 1990, JDSMC | 把蹬地力键做 **notch/整形**避开小腿共振模态，而不是事后扣阻尼 |
| **共收缩/阻抗调制** | Hogan 1984, IEEE TAC | 生物学原型：共收缩调阻尼——对应我们的 kd，但应**随接触状态调制** |

**综合路线（含实测/文献背书）**：
1. 短期配置：**受控软接触**（contactHz，4×，不碰动作标定，可回退）；
2. 中期根修：**隐式 PD**（Tan 2011）+ 动作力键按新有效刚度重标；
3. "力传地面"的正确姿势：**腿部力模式**（Whitney/Volpe 的力控思想）+ **柔性足当 SEA**（调 arch/mfoot 引擎参数）；
4. 力键用**输入整形**避开模态（Singer & Seering）。

## §4 保护程序（跌倒全权）

### 4.0 语义（用户定调）

- **触发 = 预测性"判不可挽回"**：在**落地前**（XCoM 出可恢复界持续 ~0.2s、
  迈步不可行/不允许），不是躺地上了才触发——要留最后 200–400ms 做安全着陆姿态；
- 触发后**任务优先级切换**（平衡目标作废）：

  ```
  保护自己（最小伤害） > 落定（不抽不弹） > 爬起来 > 恢复任务
  ```

  · 保护自己：防头颈、冲击只耗散不返还、**不挣扎**（giveup 卸力的意义）；
  · 落定：站立伺服必须死（弹/抽的来源）；
  · 爬起来：E 相，属**动作层**相位程序（侧滚→跪撑→站起），由游戏/意图请求
    触发（可以故意躺着不起来）；不是保护程序内部的反射；
  · 恢复任务：`release()` 还原上下文，平衡伺服重新上线。

### 4.1 五相设计

| 相 | 触发 | 主管 | 做什么 | 纪律 |
|---|---|---|---|---|
| A 判不可救 | XCoM 出界持续 ~0.2s / 胸高·倾角超阈 | 预警 giveup → `FallGuard.takeOver()` | 垫脚/髋/腰**全停**；动作提案被拒 | 锁存，只判一次 |
| B 下落定向 | 全权后 | 保护程序 | 安全着陆姿态：收下巴、手前伸、膝微屈（低刚度，按剩余时间插值） | 目标=安全姿势，**不是救平衡**；锁死=刚性倒立摆必摔 |
| C 触地吸收 | 各肢体接触事件 | 保护程序 + 消力**推广四肢** | 每接触肢体负载退让、耗散能量 | **能量纪律：只耗散不返还**（低 kp、高 kd，禁止位置硬顶） |
| D 落定 | 躯干接触+冲击过 | 保护程序→放松 | **limp 卸力**：站立伺服（姿势/重力/CoM）全停或刚度→0，只留阻尼 | **"倒下后站着的那套伺服必须死"**——实测它就是弹/抽的来源（`_probe-bounce`） |
| E 恢复 | 游戏/意图请求 | 动作层（起身程序） | 侧滚→跪撑→站起→交还站立伺服 | `release()` 还原任务上下文 |

### 4.2 现有执行方（FallGuard）

绷直（brace，全关节锁高刚度）、转移重心、跪撑（kneel）、`release()` 任务恢复——均已实现；
**自动触发还没接**（控制回路里 `guard.authority` 分支存在但没人调用 `takeOver`）。

### 4.3 实测教训

- 纯布娃娃砸地**不弹**；伺服开着就弹（4–9cm 回升）→ D 相必须真正卸力；
- 竖向触地回弹还有一部分来自腿伺服欠阻尼（Drive kd 0.02→0.05·τmax 后减半）；
- 保护程序触发时它独占（不与其他提案并行），处理完再恢复。

## §5 设计规则（从实测踩坑提炼，新增特性先过这五条）

1. **出口纪律**：一切输出（反射/策略/保护/伺服）经控制模块整合器，逐轴合并，
   唯一写点 Executor；无人绕过；
2. **能量纪律**：冲击/接地阶段只允许耗散（阻尼、退让），**禁止"存储-返还"**
   （硬位置保持 = 弹簧 = 弹）；
3. **相位纪律**：非最小相位通道（髋/腰/臂）**低带宽或间歇**；能走最小相位通道
   （踝/CoP、迈步）就别用它们扛高频；
4. **消融纪律**：每个特性可开关（`enabled`/`setEnabled`），可回读；
   新特性必须过对应探针：`_probe-lateral-resonance`（0.4 冲量衰减）、
   `_probe-bounce`（砸地不弹）、`_probe-landing`、`probe-control` A–D；
5. **符号纪律**：改任何通道先看 §2.6 符号表；摆臂与髋/脊柱**反号**是曾经的发散源。

**设计结论速查**：
- 左右平衡 = **双腿差动加载**（Winter 1996），不是踝滚转 → 侧向通道应按"负载调制"设计；
- 踝刚度天生差 9%（Winter 1998；Loram 2002）→ 反馈必须低增益+尊重延迟；
- 静立修正应**间歇式**（Bottaro 2005）→ 阈值+滞回+脉冲，免疫相位泵；
- 腰/臂用"**短促反旋**（动量通量）"而非静态偏置（Hof 2007）；
- 不对称站姿要**专用反馈+配置**（Bingham 2011）；**步宽是最便宜的稳定器**（Day 1993）。

## §7 已知缺陷 / 待办（按优先级）

1. **踝侧向的物理上限 = ±2cm**（`_probe-roll-cal` 实测：踝滚 0.215 rad（±0.24 行程的
   88%）只换来 1.8cm CoP——**柔性足把踝滚吸收在脚内部**，脚体相对鞋底滚、鞋底平贴，
   滚动传不到地面）。执行层装配本身健康（映射/回读/限位都验证过：`_probe-build-audit`、
   `_probe-readback`、`_probe-ankle-truth`）；更大的侧向 CoP 必须走
   **双腿差动加载**（Winter 1996），不是踝滚；
2. **侧向通道重构**：差动加载（负载目标）+ 间歇控制（§3.4），取代现在的
   低增益位置式补丁；
3. **单脚保持未重做**：稳定增益下重心转移能完成/安全放弃，保持相摆动脚拖地、
   CoM 漂到支撑脚外；历史"通过"多为刀刃运气；
4. **自动 giveup 未接**（§4.2）；**起身程序**（E 相）是动作层的占位；
5. 触发/消融/回读齐全前，不建议在游戏里依赖"倒地后自己起来"的行为。
