# 起立新架构（2026-10-26）

> 用户定调（2026-10-26）：
> 「你能不能做起立过程 / **蹲下法庭坚持 1s 后就起来** / **是反向的蹲下过程**」
>
> 本文只设计**起立（S3 蹲姿伺服 → S0 站立）**。蹲下路径（S0→S3）见
> `docs/蹲下新架构-2026-10-26.md`，本文**不改**它的任何一条。

---

## 0. 一句话架构

**起立 = 蹲下的镜像状态机**：同一个 `PPATH` 反向采样 + 同一个动作层相位程序 + 同一套
「动作层 manual 接管 → 交还常驻伺服」的交接契约，只是**方向反过来**，
且**口径切换（squat → stand）的时机**成了唯一的真正难点。

```text
蹲下：stand 口径 ──动作层 manual──▶ 蹲姿    ──captureSquatCourt──▶ squat 伺服
起立：squat 伺服 ─────────────▶ 起立动作层 ──switchPoseState('stand')──▶ stand 伺服
                    ↑ 触发：court.t ≥ 1.0s
```

## 1. 与蹲下的逐项镜像对照

| 项目 | 蹲下（已实现，别改） | 起立（本设计） |
|---|---|---|
| 触发 | 按钮 `squatdown` → `actions.play('squatDown')` | `main.ts` 每帧 `maybeSquatRise()`：`court.t ≥ RISE_HOLD` |
| 谁写关节 | 动作层 `manual.setAngle/setTorque`（髋/膝/踝/脊柱/肩/颈全接管） | 同左（镜像，同一套 `writePose` / `writeSupport`） |
| 轨迹真源 | `PPATH_RAW`（`actions.ts:238`），p = 0→1 | **同一张表，p = 1→0** |
| 口径 | 起于 `stand`，全程 `stand` 限位 | 起于 `squat`，**中期**切回 `stand`（见 §3） |
| 交接点 | `maybeSquatHandoff()` → `captureSquatCourt()` | `maybeSquatRiseEnd()` → `switchPoseState('stand')` |
| 结束时谁接管 | squat 伺服（`squatFrame`） | stand 常驻层（`supportClean` + `tension` + `gravityComp`） |
| 最怕的坑 | 蹲姿口径错位（`updateDofState` 后捕） | **口径切换太早 → 髋撞 100° 限位**（见 §3.1） |
| 第二怕的坑 | 门控永假 → `zeroAll()` 没人扶（已修） | 末相位清 manual 时 `_ref` 还是蹲姿（见 §3.3） |

★ 起立**不得**复用 `squatPhases()`（`actions.ts:123`）。那是"站立浅蹲 + 平衡反馈"的老动作
（`depth=-0.9`、`SAG_KP*pitch` 闭环），与 `PPATH` 深蹲不是同一个姿势域，接不上蹲姿伺服。

## 2. 状态机

```text
S0 站立（stand 口径，常驻层：supportClean + tension + gravityComp）
  ↓ 播放 squatDown（动作层 manual 接管）
S1 下降（stand 口径）
  ↓ maybeSquatHandoff()：姿势到位 + 双脚 fz>50（2026-10-26 已修，不再看 foot2/comX）
S2 交接冻结（captureSquatCourt：清速度 → switchPoseState('squat') → captureAngFrom/captureSquatBase）
S3 蹲姿伺服（squatFrame，court.released=true, court.t 从 0 起算）
  ↓ ★ 新增：court.t ≥ RISE_HOLD(1.0s)
R0 起立准备（动作层接管前置）
  ↓ actions.play('squatUp')；court = null（squat 写手全停，见 §4）
R1 起立（squat 口径，大扭矩伸髋伸膝）
  ↓ 髋 < HIP_SWITCH(95°) ⇒ switchPoseState('stand')  ← ★★ 唯一的口径切换点
R2 起立（stand 口径，反向 PPATH 后半段）
  ↓ 到达站姿（髋/膝进圈 + 双脚 fz>50）或走到最后相位
R3 收尾（supportCleanReset + captureRest + manual.clear）
  ↓
S0 站立
```

★ **S3 → R0 是硬触发**：只看 `court.t`，**不看 `court.fall`**。
理由（实测）：`captureSquatCourt` 路径下身体明明稳坐 30s，`court.fall` 却在 **0.57s** 就
报了倒下（判死基线 `ang0`/`support` 与动作层交接姿势的口径不一致）。若拿 `fall` 当闸门，
起立永远不会发生。`fall` 只写进日志，不参与决策。

## 3. ★★ 三个必踩的坑（都已在本项目实测过）

### 3.1 口径切换太早 = 髋撞 100° 硬限位 = 弹飞重演

实测（本会话，`tools/_tmp-blowup.ts`）：

```text
下蹲路径 p=0.9/1.0 目标 hip = 103.1°（actions.ts:248）
stand 口径髋矢状限位 = [-95°, +100°]（skeleton.ts:1972 ← partsMeta HIP_LIMIT）
⇒ 髋在 100.6° 撞限位：hip_l/2 vel = 19.88 rad/s、躯干 54 rad/s、全身 2.33 m/s
   （同帧全部提案最大只有 69.6 N·m ⇒ 不是伺服，是限位冲量）
```

**起立是完全同构的风险**：起立开始时髋在 ~130°（法庭摆姿）或 ~85°（动作层交接）。
此刻若 `switchPoseState('stand')` → `applyJointLimits('stand')` 把 `d.max` 重置成 100°，
而起立还在 130°，`drive` 的 lim 通道（髋是球铰 `engineLimited=false`，限位只走这条）
**下一帧就对髋发限位冲量**。

```text
★★ 不变量 R-A：`switchPoseState('stand')` 只能在 **hip_l/2 与 hip_r/2 都 < 95°** 之后调用。
   （留 5° 余量；两段式：R1 在 squat 口径下先把髋收到 <95°，R2 才切口径。）
```

参考实测：动作层交接路径的稳态是 **hip 82~88° / knee −99~−100°**（30s 内）⇒ 这条路本来就
已经 <95°，切 stand 安全；**法庭按钮路径**（`squatCourtSetup` 摆到 130°+）才必须走两段。

### 3.2 起立期不能用 stand 的 τmax

| 口径 | hip τmax | knee τmax | 髋限位 |
|---|---|---|---|
| `stand` | 212 | 212（默认） | −95..100° |
| `squat` | **800** | **450** | −120..175° |

起立初期（髋 130°、膝 −130°）要**对抗重力把腿伸直**，212 N·m 不够（蹲下期实测支撑力矩
就在百 N·m 量级）。⇒ 这也要求 **R1 段留在 squat 口径**，不能为了"早点让上身伺服正常"
就提前切。

### 3.3 末相位清 `manual` 时，接手的层必须已经"认得"当前姿势

蹲下端的教训（本会话已修）：动作层第 3 相位「交接」的 `enter` 是 `zeroAll()`
（`actions.ts:393`，清 hip/knee/foot/spine/neck/shoulder 的 manual 角 + 第 0 轴力矩归零），
若此时没人接手 ⇒ 深蹲一个写手都不剩，`supportClean` 的 `_ref` 还是**站立**目标 ⇒
一步内被拽向站姿，实测 **6.72 / 7.99 / 9.80 m/s**。

起立端镜像风险：R3 清 manual 的瞬间，`supportClean._ref` 若还是**蹲姿口径的角**
（`_ref` 是按 `name_axis` 键存的角度值，蹲姿口径 β≠站立口径） ⇒ 反向的同一场弹飞。

```text
★★ 不变量 R-B：R3 的顺序必须是
   ① switchPoseState('stand')（内部已 supportCleanReset + drive.captureRest + 限位恢复）
   ② supportCleanReset()（幂等，再保险一次，因为 R2→R3 之间姿势还在变）
   ③ drive.captureRest()
   ④ 最后才 manual.clear()
   即「**先让接手的人认姿势，再撤走原来的人**」，顺序反了就是弹飞。
```

### 3.4（附）动作层末尾必须有兜底，不能指望"条件成立"

蹲下端已经吃过一次：门控里两条**先天不可能成立**的判据（`|foot2|<10°` 而动作层自己在推
22°；`comX` 单调漂移 −2.5→−9.6cm）把交接拖到最后一帧，兜底才有了用。
起立端同理：

```text
★★ 不变量 R-C：`maybeSquatRiseEnd()` 除"姿势到位"外，必须有**相位兜底**——
   动作进入最后一个相位（或 status.active 变 false）且仍在蹲/半蹲（knee < −30°）
   ⇒ 无条件执行 R3。不依赖任何"条件自然满足"。
```

## 4. 写手归属（一个 DoF 只能有一个写手）

| 阶段 | 髋/膝/踝/脊柱 | 上肢/颈 | 说明 |
|---|---|---|---|
| S3 蹲姿伺服 | `squat.pairBase` + `squat.ankleVector` + … | `supportClean.arm`（0.35% 那套） | 现状 |
| R1/R2 起立 | **动作层 `manual.setAngle`（pin）** | 同左 | squat 写手全停 |
| R3→S0 | `supportClean` + `tension` + `gravityComp` | 同左 | 常驻 |

**让位手段：`court = null`。**
`squat.ts` 里所有写手都 gate 在 `baseState() === 'squat' && st.released`，
但 `squatFrame` 的入参 `court` 一旦为 `null`，`main.ts` 就不再调用 `squatFrame` ⇒
`courtInject`/`courtStep` 也不再跑（`courtInject` 里那次 `supportClean` 也随之停）。
⇒ **只置 `court = null` 即可，不必先切 `baseState`**（切了反而触发 §3.1）。
`baseState` 保持 `'squat'` 直到 R1 结束、`hip < 95°`。

★ **让位的真实判据（已核过代码）**：
- `supportClean` 第 136 行：`if (ctx.bal.manual.hasAngle(di) || ctx.bal.manual.torqueOf(di) !== 0) continue;`
- `tension` 层（`stability.ts`）：`if (this.manual.hasAngle(d.dofIndex)) continue;`

⇒ 动作层只要 `manual.setAngle(...)`（或写非零 torque），这两层就自动跳过该 DoF。
**不需要额外 `pin`**（`pin` 是"禁止改角度"的另一套语义，蹲下没用它，起立也别用）。
起立相位里**每个想要的 DoF 都必须显式 `setAngle` 或 `setTorque`**——漏一个，该 DoF
就会被 `supportClean`/`tension` 按**当前口径的目标**接管，而蹲姿口径的目标 ≠ 起立中姿势。

★ 另一条坑（`supportClean.ts:212`）：legacy 支路是 `if (!isSquat && !manual.hasAngle(di))`——
`baseState() === 'squat'` 期间它是**关掉**的。所以 R1 段（squat 口径）里
supportClean 对没被 manual 接管的 DoF **完全不发力**（不是"按目标拉"，是"根本不动"）。
这是 R1 段的安全裕度，也是 R1 段必须自己把姿势撑住的原因。

## 5. 轨迹

### 5.1 矢状：反向 `PPATH`（初值）

`PPATH_RAW`（`actions.ts:238`，11 个点，p=0..1）：

```text
p     hip     knee    sp1     sp2     sp3    neck   shoulder  comX
0.0    0.0     0.0   -4.0     5.7    -4.7     2.3      0.0    0.005
0.5   57.3   -56.7  -16.0    -6.3   -16.7     2.3     14.3   -0.019
0.9  103.1  -102.1  -25.7   -15.9   -26.4     2.3     25.8    0.010
1.0  103.1  -102.1  -25.7   -15.9   -26.4     2.3     25.8    0.010
```

起立初版直接 `p(t) = 1 − smooth(t / RISE_T)`，其余字段照查。

### 5.2 ★★ comX 不能照抄反向

反向采样会把 `comX` 从 `0.010` 走回 `0.005`，但物理上起立需要
**CoM 先停在脚掌上方（支点）再伸膝**，否则伸膝会把 CoM 往后推 → 后坐。

```text
★ 决策：起立前 1/3 段 comX 目标**保持在 +1.0cm 不动**（先"扛"住），
  到膝角 > −90° 之后才开始按反向 PPATH 往 0.005 收。
  这是一条独立的包络，不与蹲下共用同一张表的插值。
```

判据来源：蹲下期实测 `comX` 单调漂移 −2.5→−9.6cm 就足以让 squat 伺服救不回来、
进而前栽；起立端方向相反（后坐），但机理相同——**CoM 轨迹是独立自由度，不能当尾巴**。

### 5.3 踝

蹲下用 `ankleTgt = ANK_ACT·ankleEnv + ANK_K·comErr`（`actions.ts:432`），
并在 p=1 时 `ankleEnv → 0`。起立端**沿用同式**（`comErr` 符号自动反向），
但 `ANK_ACT/ANK_K` 需要独立标定——蹲下标定量是"往前推"，起立的跖屈方向需求不同。

★ 待标定项，初版先取 `ANK_ACT=0.25, ANK_K=6.0`（同蹲下），用探针扫。

## 9. 被否 / 不要做

| 方案 | 为什么否 |
|---|---|
| 复用 `squatPhases()`（老起立动作） | 是"站立浅蹲 + 平衡反馈"域，与 `PPATH` 深蹲姿势接不上 |
| 起立开始就 `switchPoseState('stand')` | §3.1：髋 > 100° ⇒ 限位冲量 ⇒ 19.88 rad/s 弹飞 |
| 用 `applyJointLimits('squat')` 放宽限位 | 它会**顺带**把 τmax 抬到 800/450/320 + velMax 放 999，stand 高增益下失去速度刹车 ⇒ 实测 0.07s 就 122 rad/s |
| 先 `manual.clear()` 再切口径 | §3.3：顺序反了 = 弹飞 |
| 拿 `court.fall` 当起立闸门 | 实测 0.57s 就误报 fall，起立永远不发生 |
| 起立期间让 squat 写手和动作层 manual 并存 | 违反"一个 DoF 一个写手"；`court = null` 才能真让位 |
| 反向 `PPATH` 的 comX 直接照抄 | §5.2：伸膝会把 CoM 往后推，需要独立包络 |

## 10. 未决问题（动手前需要定的）

1. **起立失败怎么办**：`court.fall >= 0` 时仍强行起立，还是原地保持？
   建议：**仍起立**（人倒了也是先爬起来），失败只记日志。
2. **起立成功后按钮状态**：`squatdown` 按钮的 `setActive` 要不要复位。
3. **法庭按钮路径（`squatCourtSetup`，髋 130°）** 是否也要接起立？
   要的话必须走 §3.1 的两段式（R1 在 squat 口径收髋到 <95°）。
4. `RISE_T` 是否也用 5.0s —— 人类从深蹲起身约 1.5~2.5s（比下蹲快），
   但本项目下蹲用了 5.0s（为了稳）。**建议起立先用 5.0s 保证稳，稳了再压到 2.5s。**
