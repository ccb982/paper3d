# 稳髋：大腿-小腿虚拟接触 + 髋矢状稳定（2026-10-21）

> 目标：蹲姿下稳住髋，减少上身抖动。
> 用户观察：真实深蹲大腿和小腿重叠，膝盖不需要独自承重；rig 里模拟不出软组织接触，
> 所以需要一条“虚拟承重通道”。
>
> **结论**：通道应该是 **shin ↔ thigh 的虚拟接触**，不是 ankle ↔ hip 的自由力。
> 接触力是等大反向的内力对，不改变净外力；外部支撑仍然是 GRF。

> **2026-10-21 清理后的当前代码**：蹲姿写手链只有
> `squat.pairBase` → `squat.ankleVec` → `squat.hipStab` → `supportClean.arm`。
> 下文 §1b/§6/§8 的 raw/独立写手已删除；§9 是当前按基础力分量接回的踝→髋虚拟支撑。

## 1b. 方案 B：虚拟腿柱（ankle → hip，历史）

如果目标就是“从踝到髋一条矢状、偏竖直、倾角小的力”，可以把它做成一条**虚拟压缩柱**，
而不是自由力：

```text
p_ankle = 踝/足侧附着点
p_hip   = 骨盆/髋侧附着点
L       = |p_hip − p_ankle|
L0      = 释放瞬间捕获的静止长度
δ       = L0 − L                 // 压缩为正
Ldot    = 长度变化率（闭合为正）
F       = max(0, k·δ + b·Ldot)   // 单侧：只压不拉
F       = min(F, F_max)          // 预算
```

- 沿 `p_hip − p_ankle` 方向：hip 受 `+F`，ankle 受 `−F`；
- **等大反向**：净外力为 0，不凭空；
- 线在矢状面内，接近竖直，倾角小；
- `L0/k/b/F_max` 都是状态参数，有审计；
- 只在 `squat && released && deep knee` 时申请；站立关闭。

物理意义：

- 它是一条**并联承重柱**，把竖向载荷从踝直接分到髋，减少 knee/2 和“扎马步”式髋力矩；
- 外部支撑仍然是 GRF；柱只是内部载荷重分配；
- 柱的刚度/预压缩决定分走多少载荷；`F_max` 防止它变成无限大力。

与方案 A（thigh-calf 接触）的区别：

| | A: shin-thigh 接触 | B: ankle-hip 腿柱 |
|---|---|---|
| 物理真实性 | 真实深蹲的软组织接触 | 控制抽象/虚拟结构 |
| 端点 | 小腿 ↔ 大腿 | 踝 ↔ 髋 |
| 绕过 | 膝 | 膝（直接） |
| 风险 | 接触点/法线要标定 | 容易变成“凭空柱”，必须用弹簧/预算约束 |

---

## 0. 为什么不是“踝→髋”

真实深蹲（脚跟坐、膝深屈）时，**大腿后侧和小腿后侧接触**，形成一条并联承重路径：
地面 → 足/踝 → 小腿 → **小腿-大腿接触** → 大腿 → 髋。

它绕过的是**膝关节的力矩**，但仍然经过小腿和大腿。
“踝→髋”没有对应的解剖结构；如果直接在小腿和髋之间加一对自由力，就是凭空内力，
而且不会自动产生接触力矩。**正确的虚拟通道端点是 shin 和 thigh。**

---

## 1. 虚拟接触模型

### 1.1 接触点

在 thigh / shin 的本地系里各取一个后侧点：

```text
p_thigh = thigh 后侧，距膝 s_t ≈ 0.10–0.14 m
p_shin  = shin  后侧，距膝 s_s ≈ 0.08–0.12 m
```

两个点都取矢状面后侧（-X 方向，按 rig 轴向调整），接触法线沿两点连线。

### 1.2 力

```text
d = p_thigh − p_shin
δ = r0 − |d|                 // r0 = 接触半径/初始间隙
v = (v_thigh − v_shin)·d̂      // 闭合速度
F = max(0, k·δ + b·(−v))     // 单侧接触：只压不拉
F = min(F, F_max)            // 预算
```

- `F` 沿 `d̂` 施加：thigh 受 `+F`，shin 受 `−F`（等大反向）。
- 只在 `δ > 0`（重叠）时出力；不重叠 = 0。
- **预算**：`F_max`、`k`、`b` 都是状态参数；接触力必须可审计。

### 1.3 门控

```text
baseState() === 'squat'
&& st.released
&& st.fall < 0
&& kneeAngle < −90°          // 深蹲才接触
&& fz > 阈值                  // 脚承重
```

站立不启用；非深蹲不启用。

### 1.4 物理性质

- 等大反向 → 净外力为 0；不违反动量守恒。
- 接触力对膝产生力矩，减少 knee/2 的承重需求。
- 对髋提供一条并联路径，减少“膝独自承重”导致的髋部摆动。
- 外部竖向支撑仍然是 GRF；接触力只是内部载荷重分配。

## 2. 髋矢状稳定

虚拟接触解决“载荷路径”，不自动解决“髋角稳定”。再加一层：

```text
τ_hip2 = Kp·(hip2_ref − hip2) − Kd·ω_hip2
```

- 只在蹲姿/释放后申请；
- 预算 `τ_max`（或复用 hip tauMax）；
- 经 `propose({kind:'ext', src:'squat.hipStab'})`，单一写手；
- 目标 `hip2_ref` = 释放姿势捕获角；
- 与虚拟接触配合：接触卸掉膝/髋的力矩，PD 负责角度/速度。

上身抖动如果还大，再单独查 trunk/spine 的阻尼，不要全压在髋上。

## 3. 分层与申请制

| 层 | 模块 | 职责 |
|---|---|---|
| 执行层 | `VirtualThighCalfContact`（新） | 计算/施加等大反向接触力；预算、审计；不是关节力矩 |
| 伺服层 | `squatHipStab`（新） | hip/2 PD 提案，预算、门控 |
| 控制层 | `ControlModule` | 仲裁 hipStab 提案 |
| 执行层 | `Executor` | 仍只负责关节力矩 |

**申请制纪律**：

- 虚拟接触不是“免费力”：有 `F_max`/`k`/`b` 预算，只在深蹲接触窗口申请；
- 每帧记录 `F/δ/v/接触点`，可回读；
- 不在站立/非深蹲启用；
- 不把接触力写成关节力矩再偷偷加回来。

## 4. 验收

| 指标 | 目标 |
|---|---|
| 接触力 `F` / 穿透 `δ` | 有值、单调、无尖峰；`F ≤ F_max` |
| knee/2 力矩 | 接触开启后下降（卸载） |
| hip/2 角度/速度 | 抖动幅度下降 |
| 上身加速度 | 抖动指标下降 |
| 判死 | 不低于当前 3.2s 窗口 |
| A/B | 接触 on/off、hipStab on/off 各一组 |

---

## 5. 不做什么

- 不做 ankle→hip 自由力通道（没有结构路径，等于凭空力）。
- 不做无预算的虚拟接触。
- 不改站立路径。
- 不用 hip 常值前馈代替接触；接触是载荷路径，hip PD 是稳定器。

## 6. 首轮实现与实测（2026-10-21）

当前代码只保留：

- `core/servo/squat.ts`：`squatHipStab`，hip/2 PD；
  默认 `SQC_HIP_STAB_KP=50`、`KD=5`、`TMAX=200`；申请制 `propose(ext)`。
- `squatAnkleVector`：脚踝唯一写手。
- `supportClean.arm`：蹲姿手臂/颈 PD。

> `squatAnkleRoll`、`squatLateralHip`、`squatLegStrut`、`squatLegForce`、
> `virtualLeg` 旧弹簧均已删除；下文相关实测仅作历史记录。

### 6.1 髋 PD（strut 关，SHAKE=1）

| KP/KD | headW 均值 | s4W 均值 | 判死 |
|---|---:|---:|---|
| 0/0（基线） | 1.77 | 2.10 | none（>3.2s） |
| **50/5（默认）** | **1.44** | **2.10** | 3.185s offZ |
| 100/10 | 1.97 | 2.54 | 3.125s offX |
| 200/20 | 1.69 | 2.20 | 3.060s offX |

- 50/5 把头部角速度均值从 1.77 降到 **1.44**，上身抖明显减小；
  代价是判死从 >3.2s 变成 3.185s（15ms）。
- 更大增益反而更差；50/5 是当前甜点。

### 6.2 虚拟腿柱（首轮问题）

实测发现：释放后 `L0=0.435m`，但 `L` 会升到 **0.48–0.51m**（髋-踝距离在增加）。
压缩柱只有 `L < L0` 才出力，所以大部分时间 **F=0**，等于没接上。

| 配置 | F@2.15 | headW | 判死 |
|---|---:|---:|---|
| compression-only，K=3000/Fmax=300 | 0 N | 1.69 | 3.115s |
| +F0=100，K=1000 | 36 N | 1.38 | 2.840s |
| +preload=0.10m | 0–48 N | 2.41 | 2.592s |

结论：**ankle→hip 在当前蹲姿不是压缩柱**；髋在远离踝。
压缩柱无法分担载荷；加预紧能压头部抖动，但 offX 更早倒。

下一步二选一：

1. **双向虚拟肌肉**：围绕 `L0` 的弹簧/阻尼（可拉可压），预算/审计；  
2. **真实大腿-小腿接触**：在后侧 thigh/calf 做单侧接触（更符合现实深蹲）。

该模型未采用；髋 PD 50/5 默认开。

## 7. 上身抖动是独立问题（2026-10-21 已修）

### 7.1 判定

`RIGID_UPPER=1` 冻结上身后：

| 指标 | 正常 | 冻结上身 |
|---|---:|---:|
| headW 均值 | 1.44 | **0.08** |
| s4W 均值 | 2.10 | **0.28** |
| 判死 | 3.185s offZ | **none（>3.2s）** |

=> 抖动来自**上身链本身**，不是骨盆/腿带出来的。髋和上身确实是两件事。

### 7.2 逐关节回读

| 体段 | 角速度趋势 |
|---|---|
| armL / armR | 0.3 → **2.2 rad/s**（主振） |
| head | 0.1 → 0.66 |
| spine4 | 0.5 左右 |
| spine2/3 | 0.1–0.3 |

主振是**手臂**；上身 PD 在蹲姿里没有真正出力。

### 7.3 根因

`core/servo/supportClean.ts` 蹲姿手臂/颈 PD 块：

```ts
if (!isSquat && Math.abs(tauA2) > 0.05) propose(...)
```

这块本身就在 `if (baseState() === 'squat')` 里面，`isSquat` 恒为 true，
所以条件永远 false —— **蹲姿下 PD 从未提交**。手臂只剩张力层/阻尼，越甩越大。

### 7.4 修复

```ts
if (Math.abs(tauA2) > 0.05) propose({
  dof: di, kind: 'torque', pri: PRI.action, tau: tauA2, src: 'supportClean.arm',
});
```

### 7.5 结果

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| headW 均值 | 1.44 | **0.29** |
| s4W 均值 | 2.10 | **0.26** |
| 2.5s 侧移 | 2.9 mm | 2.9 mm |
| 判死 | 3.185s offZ | 3.183s offX |

站立不受影响：这块只在 `baseState() === 'squat'` 内执行。

### 7.6 结论

- 髋稳定（hipStab 50/5）与上身稳定（蹲姿 arm/neck PD）分开；
- 上身抖的主因是 PD 死代码，不是髋；
- 修复后 head/s4 抖动降了约 5–8 倍；
- 剩余 offX 是另一个问题，不要再拿髋/上身 PD 去补。

## 8. 已删除的尝试：基础力 raw 矢量柱（2026-10-21）

按“虚拟柱属于基础力、力向量偏竖直带前向”实现了：

```text
F_hip  = (+F_fwd, +F_up, 0)
F_foot = (−F_fwd, −F_up, 0)
```

实测（当时的 `SQC_STRUT=1`；该写手/env 已删除）：

| UP/FWD | comX @2.7s | 判死 |
|---|---:|---|
| 100/30 | +475 mm | 2.281s |
| 150/40 | +484 mm | 2.217s |
| 200/50 | +433 mm | 2.173s |
| 150/60 | +522 mm | 2.227s |

**失败原因**：力施加在 hip/foot 锚点上，但方向不是沿踝-髋连线；这个
“竖直+前向”的力对锚点产生了一个**不受控的力偶**，直接把腿/躯干转飞。
等大反向只保证净外力为 0，不保证净力矩为 0。

结论：

- 该 raw 力写手已删除，`SQC_STRUT` 不再是有效 env；
- 不能把“期望的 hip 力”直接当 body force 打在锚点上；
- 正确做法是 **joint-space 虚拟力映射**：把期望 hip 力 `F_des` 通过腿的
  Jacobian 映射成 hip/knee/ankle 关节力矩 `τ = Jᵀ F_des`，由执行器施加；
  这样力沿链条传，不会产生未建模的力偶。
- 或者用一条**过关节/带明确力臂的线弹簧**，并显式补偿它的力矩。

单独的 CoM 前拉反馈之前是稳定的（fall=none），但它不是基础力；如果要做成
基础力，必须走 Jacobian 映射，而不是 raw force pair。

## 9. 踝→髋虚拟支撑：按基础力分量实装（2026-10-21）

早期 `squatLegForce` 是独立 `ext` 写手，被 `ankleVec` 仲裁/符号错，已删除。
现在按正确架构接回：

- 纯映射模块 `core/servo/virtualLegSupport.ts`：只算 `τ=JᵀF`，不 propose；
- `τ_a` 并进 `squat.ankleVec` 的 `Mdes[2]`，`τ_k` 并进 `squat.pairBase` 的
  `knee/2 base`；不是新写手，不会抢同轴；
- 默认沿腿线、`18.2N/侧`；门控：蹲姿/释放后/未判死/深屈/脚承重；
- 无头法庭：3.2s 不判死，`headW 0.35→0.19`；严格判死 `3.625s offZ 5cm`
  （已超过 3.6s 目标）；继续加大会在 2.9s 左右提前倒，当前是甜点。

参数：`SQC_LEG_SUPPORT`（默认 1）、`SQC_LEG_UP`（默认 18.2，沿腿线）、
`SQC_LEG_SIGN_A/K`。
