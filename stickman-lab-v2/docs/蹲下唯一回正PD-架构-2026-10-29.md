## 13. 人腿感受的是什么

### 13.1 局部感受

脚/小腿能直接感受：

```text
脚底压力
足底剪切
关节角
肌肉长度/张力
关节运动
```

不能直接感受：

```text
全身 COM
XCoM
```

### 13.2 重心

COM 是中枢估计：

```text
脚底压力
本体感觉
前庭
视觉
→ 中枢融合
```

不是某个小腿局部感受器。

### 13.3 论文

```text
Kavounoudias et al. 1998
  foot sole mechanoreceptors / pressure distribution

Roll et al. 2002
  plantar cutaneous inputs and balance

Proske & Gandevia 2012
  proprioception: muscle spindles / joint / force

Peterka 2002
  multisensory integration

Horak & Nashner 1986
  local ankle/hip strategies
```

### 13.4 结论

```text
脚/小腿：只能感受局部压力、关节角、倾斜
COM/XCoM：中枢估计，不是局部传感器
```

所以：

```text
local PD 只看角度/接触残差
COM 不进入脚/小腿 PD
```

## 26. 为什么小腿偏了但不回正


```text

```

### 26.2 关键

如果脚和 shank 一起滚：

```text

```

于是：

```text

```

### 26.3 结果


## 51. 脚受力是否全给地面

### 51.1 不是

关节力矩不会自动全部变成地面反力。

只有落在接触锥内的分量：

```text
N ≥ 0
|Ft| ≤ μN
CoP ∈ 脚掌
```

才会变成地面反力。

超出部分会：

```text
转动脚掌
抬起脚
加速脚
```

### 51.2 当前

```text
foot/0=40N·m
foot/2=66N·m
roll=37°
fz 7175 → 0
```

说明：

```text
力矩没有全部传给地面
一部分把脚掌滚起来/踢飞
```

### 51.3 为什么

```text
1. CoP 到边缘
2. 脚掌开始滚
3. 接触面积/摩擦下降
4. fz 掉
5. supportN 继续加 foot/2
6. 正反馈
```

### 51.4 结论

```text
脚不是“把力全给地面”
是力超过接触能力后
变成脚的旋转/离地
```


## 52. 力是否沿小腿与 CoP 居中

### 52.1 条件

如果合力严格沿小腿并通过脚掌中心：

```text
CoP ≈ 脚掌中心
```

如果踝/膝产生额外力矩：

```text
合力线偏离脚中心
CoP 偏移
```

### 52.2 当前

```text

foot/2=66N·m

```

说明：

```text

踝力矩把力线拉偏
```

### 52.3 让 CoP 居中

方法：

```text
1. 目标 CoP = 脚掌中心
2. 踝力矩只做 CoP 误差反馈
3. 膝/髋把合力线移到脚中心
```

## 53. 踝发力的方向

### 53.1 论文

```text
Winter 1995
  踝力矩控制 CoP
  GRF 从 CoP 指向 CoM

Hof 2005
  XCoM/CoP 关系

Neptune & Perry 2019
  跖屈肌推进 CoM

Caron 2019
  接触力必须满足接触约束
```

### 53.2 关键

踝肌肉产生的是：

```text
关节力矩
```

不是：

```text
一个可任意指定方向的力
```

地面反力方向由：

```text
CoP → CoM
摩擦
脚掌接触
```

决定。

### 53.3 “指向 CoP”是什么意思

CoP 是：

```text
地面反力作用点
```

不是力矩方向。

踝力矩改变 CoP：

```text
τankle → CoP 偏移
```

不是：

```text
踝力沿 CoP 方向推
```

### 53.4 为什么会飞

如果踝力矩超过接触能力：

```text
脚掌滚转
CoP 到边缘
N/摩擦下降
→ 脚离地
```

不是因为“踝力方向错”，而是：

```text
力矩把脚掌滚起来
```

### 53.5 结论

```text
踝发力方向：关节力矩
GRF 方向：CoP→CoM
不是踝力直接指向 CoP

脚飞：力矩超过接触能力
```


## 54. 侧向踝正确时不应让脚飞

### 54.1 用户判断

```text
如果侧向踝设计正确
不应该这么容易让脚飞
```

正确。

### 54.2 当前问题

当前侧向踝是：

```text
foot/0 = 角度 PD
```

输出可到：

```text
40N·m
```

但没有 CoP 反馈/限制。

结果：

```text
力矩超过脚掌接触能力
→ 脚掌滚转
→ 飞
```

### 54.3 正确侧向踝

侧向踝应该以 CoP 为物理约束：

```text

τlat = -Kcop·eCop - B·foot0Rate
```

并限制：

```text
|τlat| ≤ N · marginZ
```

当 CoP 到边缘：

```text
τlat 饱和
脚掌不再滚
```

不是继续加角度 PD。

### 54.4 结论

```text
侧向踝设计正确：
  以 CoP/接触为约束
  不是裸角度 PD

当前：
  角度 PD 直接 40N·m
  没有 CoP 限幅
  → 脚飞
```

## 67. 6N·m 为什么还会侧翻

```text
τ = N · ΔCoP
```


```text

```

```text

```


## 75. 方向对但为什么没变化

### 75.1 数据

```text
t=0.50 tilt=-8.0  foot/0=-28.3 footRoll=-8.0 fz=475
t=0.54 tilt=-11.6 foot/0=-32.8 footRoll=-23.2 fz=264
t=0.58 tilt=-19.7 foot/0=0.0  footRoll=-27.3 fz=0
```

方向是对的，但：

```text
tilt 继续变负
footRoll 继续变负
fz 掉到0
```

### 75.2 原因

踝力矩是内力：

```text
踝力矩 = 脚 ↔ 小腿 力偶
```

如果脚没有稳定接触：

```text
力矩先转脚
不是转小腿
```

结果：

```text
foot/0 越大
footRoll 越大
fz 越小
→ 力矩没有外部反力
```

### 75.3 结论

```text
方向对 ≠ 能改变小腿
```

需要：

```text
脚掌接触
CoP 在脚掌内
N/摩擦
```

才能把踝力矩变成小腿/身体的回正。

### 75.4 当前失败链

```text
踝力矩
→ 脚掌滚
→ fz=0
→ 脚离地
→ 力矩没有作用点
```

## 80. 目标姿态具体怎么算

### 80.1 捕获

释放瞬间：

```text
sag0 = atan2(kneeX − ankleX, kneeY − ankleY)
```

左右取平均：

```text
targetSag = (sag0_L + sag0_R) / 2
```

脚：

```text
targetFoot0 = average(foot0_L, foot0_R)
targetFoot2 = average(foot2_L, foot2_R)
```

侧向：

```text
targetTilt = 0
```

### 80.2 目标膝位置

给定踝 A、小腿长 Ls：

```text
K*_x = A_x + Ls·sin(targetSag)
K*_y = A_y + Ls·cos(targetSag)
K*_z = A_z
```

### 80.3 关键

`targetSag` 来自释放瞬间的当前小腿角。

所以释放时：

```text
K* = 当前 K
```

目标线和当前小腿线重合。

### 80.4 画出来是什么

```text
脚位置：当前
脚掌角：当前
小腿目标线：当前小腿方向
```

也就是：

```text
目标姿态 = 释放瞬间姿态快照
```

不是：

```text
独立设计的正确蹲姿
```

### 80.5 结论

```text
目标不是“理想姿态”
目标只是“保持释放瞬间的小腿方向”
```

如果释放姿态本身内收/歪，目标也跟着错。

## 82. 软限位统一收敛到两个 PD（2026-10-31）

### 82.1 原则

软限位不再由独立的 `squatLateralLimit` 硬夹关节，而是进入两个 PD 的目标和力矩：

```text
HipTaskPD:
  hip/0
  knee/2

ShankTaskPD:
  knee/1
  foot/0
  foot/2
```

### 82.2 形式

每个关节维护一组姿势相关限位：

```text
q_lo(pose), q_hi(pose)
```

PD 内部：

```text
q*_safe = clamp(q*, q_lo + margin, q_hi - margin)
τ = -Kq·(q - q*_safe) - Dq·q̇
```

接近限位时增加软约束力矩：

```text
q < q_lo: τ_limit = -Klim·(q - q_lo) - Dlim·q̇
q > q_hi: τ_limit = -Klim·(q - q_hi) - Dlim·q̇
```

再与任务力矩合成，不另开写手。

### 82.3 姿势限位

限位由当前阶段决定：

```text
stand
court_freeze
court_released
fallen
```

并随阶段做渐变，禁止一帧跳变。

### 82.4 硬限位

硬限位只保留为最后安全边界，不再参与日常回正。日常回正全部由两个 PD 的软限位完成。

### 82.5 取消的层

```text
squatLateralLimit 的硬夹
```

不再作为蹲姿回正层写手。

## 83. 脚部统一与贴地优先（2026-10-31）

### 83.1 原则

脚不是三个独立关节，而是一组统一接触结构：

```text
foot_*
arch_*
mfoot_*
```

它们必须服从同一个足底目标，不能各自维护目标。

### 83.2 最高优先级

```text
贴地
```

贴地包括：

```text
法向接触
CoP 在支撑面内
不滑移
不侧翻
```

脚部任何关节动作都不得破坏贴地。贴地优先级高于：

```text
踝角
arch 压力目标
mfoot 目标
关节软限位
```

### 83.3 次级任务

贴地满足后，脚部关节只做有限范围内的活动：

```text
foot/0、foot/1、foot/2
arch/0
mfoot/0
```

它们用于：

```text
压力分配
CoP 调整
足弓缓冲
```

不是独立回正写手。

### 83.4 控制归属

```text
HipTaskPD：
  hip/0、knee/2

ShankTaskPD：
  knee/1、foot/0、foot/1、foot/2 的目标角与软限位

足底统一层：
  foot/arch/mfoot 的接触目标
```

`arch` 和 `mfoot` 不再由单独的压力环独立驱动。

### 83.5 预载

冻结期最后阶段：

```text
arch 目标固定
mfoot 目标固定
足底接触目标建立
```

释放后：

```text
接触目标先保持
foot/arch/mfoot 一起渐入
```

禁止：

```text
arch 单独先动
mfoot 保持旧目标
foot 关节单独硬拉
```

### 83.6 结论

```text
脚部第一任务：贴地
第二任务：在贴地前提下活动脚部肌肉
```

任何脚部控制如果让 CoP 出支撑面、脚掌滚动或 fz 跳变，都视为失败。


## 106. 踝在基础力中的负载公式（2026-10-31）

### 106.1 静态踝力矩

```text
τ_sag = -Fz · (CoP_x - ankle_x)

```

```text
Fz      该脚法向力
CoP_x   前后压力中心
CoP_z   侧向压力中心
ankle   踝关节锚点
```

### 107.3 浮动基动力学

```text
M(q)q̈ + C(q,q̇) + G(q)
= Sᵀτ + JcᵀFc
```

```text

```

### 107.4 接触力到关节力矩

```text

```

支撑力分配：

```text

```

要求：

```text

```

### 107.5 CoP 与摩擦

```text
CoP = Σ(p_i·f_i) / Σf_i
```

约束：

```text

|F_tan| <= μF_n
```

### 107.6 前馈 + 反馈


负载相关刚度：


### 107.7 踝力矩估算


## 109. 运行时力链闭合（2026-10-31）

静态闭合不等于实际使用闭合。运行时每帧必须检查。

### 109.1 每帧检查顺序

```text
1. FootSensor.valid
2. contact 状态
3. CoP 在脚底多边形内
4. N 目标是否可分配
5. IK 目标是否可达
6. τ_req = JᵀF_support
7. utilization = |τ_req| / τ_cap
8. Shank rightingCapacity
9. Hip F_support 限额
10. 最后才提交关节目标
```

### 109.2 失败处理

```text
Sensor 无效：
  禁止新支撑力

contact 丢失：
  取消脚位置目标
  骨/髋进入找地

CoP 越界：
  限制踝目标
  降低 F_support

IK 不可达：
  缩小目标

utilization > 0.8：
  降低 F_support

Shank 饱和：
  Hip 停止加力
```

### 109.3 运行时不变式

```text
N_total <= 可支撑总量
CoP ∈ 支撑面
utilization < 0.8
contact 状态和脚目标一致
同一关节只有一个主动写手
```

### 109.4 验收

```text
每帧日志可回读
任一失败都有降级动作
不允许继续硬顶
```

目标不是“静态算出来闭合”，而是“实际运行时每帧都闭合”。

## 110. 预测故障与薄弱点（2026-10-31）

### 110.1 最可能故障

```text
1. 释放瞬间丢接触
2. F_support 把腿链压歪
3. IK 目标不可达
4. 脚目标高度错误
5. FootSensor 状态抖动
6. CoP 滤波滞后
7. 写手抢轴
8. 脚底分块压力不均
9. 隔离系统 N 目标错误
10. 缺少运行时降级
```

### 110.2 故障表

| 故障 | 症状 | 检测 | 处理 |
|---|---|---|---|
| 接触丢失 | fz 掉到 0 | contact/fz | 取消脚位置目标，腿找地 |
| 支撑过载 | 腿歪、踝滚 | utilization/CoP | 降低 F_support |
| IK 不可达 | 目标抖、膝过伸 | 可达性/限位 | 缩小目标 |
| 脚目标悬空 | 脚一直追 | targetY/sole | 目标改脚底点 |
| 状态抖动 | loaded/airborne 翻转 | 状态翻转计数 | 滞回 |
| CoP 滞后 | raw/filtered 差异大 | 差值 | 接触切换重置 |
| 写手抢轴 | 力矩翻号 | writer 记录 | 单轴单写手 |
| 分块压力异常 | arch/mfoot 跳 | parts N | 统一 FootTarget |
| N 目标错误 | fz 永远低 | fzTarget vs 质量 | 重算载荷 |
| 无降级 | 故障后继续加力 | 运行时检查 | 立即限力 |

### 110.3 薄弱点排序

```text
1. 接触丢失
2. 脚目标高度/位置
3. F_support 与 rightingCapacity 不匹配
4. IK 可达性
5. 感受状态抖动
6. 写手抢轴
```

### 110.4 验证顺序

```text
静态 N/CoP
→ 释放后 fz
→ 脚目标接地
→ N → Hip 闭环
→ IK + utilization
→ 侧向扰动
→ CoP 边界
→ 写手冲突审计
```

### 110.5 结论

```text
力矩不是主要弱点
接触、目标和力链容量才是
髋有力不等于腿链接得住
```

## 111. 开工前冻结接口（2026-10-31）

### 111.1 唯一文档

```text
主文档：docs/蹲下唯一回正PD-架构-2026-10-29.md
子模块：docs/柔性足-接触与抓地-架构-2026-10-31.md
```

主文档定义写手和总闭环；柔性足文档只定义足底局部模块。  
两者冲突时以主文档为准。

### 111.2 写手所有权

```text
hip/0：HipTaskPD
hip/1：无主动，限位+阻尼
hip/2：HipTaskPD
knee/0：ShankTaskPD
knee/1：无主动，限位+阻尼
knee/2：HipTaskPD
foot/0：ShankTaskPD
foot/1：ShankTaskPD
foot/2：ShankTaskPD
arch/mfoot：FootContact 目标
FootSensor：永不写执行器
```

同一 dof 两个主动写手 = 错误。

### 111.3 F_support 接口

```text
HipTaskPD 输出：
  F_support：世界系支撑力 N（x/y/z）
  supportBudget：N
  saturation：bool

ShankTaskPD 输入：
  F_support（前馈信息，不直接写 hip/knee）
```

分配不是固定百分比，而是：

```text
τ_leg = Jᵀ · F_support
```

HipTaskPD 负责 hip/0、hip/2、knee/2 的承重部分。  
ShankTaskPD 用 F_support 做踝/膝侧向的前馈和力链检查。

容量反馈：

```text
rightingCapacity / chainError / saturation
→ HipTaskPD 降低 F_support
```

### 111.4 足底目标

```text
foot target = 初始脚底 sole/CoP 点
y = 地面
x/z = 初始接触点
```

接触阈值：

```text
enter：fz > 0.05W
exit：fz < 0.02W
CoP margin：< 0.8 × 脚底范围
N 目标：W × loadShare
```

foot 刚体中心不能作为目标点。

### 111.5 IK 与力链

```text
τ_req = Jᵀ · F_support
utilization = |τ_req| / τ_cap
```

执行条件：

```text
contact == true
CoP 在脚底内
IK 可达
utilization < 0.8
```

不满足：

```text
缩小 IK 目标
或降低 F_support
```

### 111.6 运行状态机

```text
airborne
→ touchdown
→ loaded
→ slipping
→ lost
```

状态切换带滞回。  
`airborne/lost` 时禁止脚位置目标和新增支撑力。

### 111.7 每帧顺序

```text
1. FootSensor
2. 接触状态机
3. HipTaskPD 支撑力
4. Shank IK + 力链可行性
5. 写手提交
6. 反馈更新
```

### 111.8 开工判定

```text
以上接口冻结后：
  可以先写 FootSensor + 脚局部闭环
  再写 HipTaskPD 承重
  再写 ShankTaskPD IK + 力链
```

未冻结前不再改这些边界。
