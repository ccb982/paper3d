## §0 提案制契约（与 `架构.md` §3 对齐——本文档的前置约束）

用户定调：**所有要执行的动作都由"动作提案系统"（原名"迈步系统"）提案；它只提案，
不写关节**。三层 + 一个常开伺服：

```
意图层（游戏/AI/玩家）——最高：目标+约束（可禁止/改写动作，但关不掉稳定伺服）
    │ 目标 + 约束
动作提案系统（原名"迈步系统"）—— 事件层
    · 所有动作（迈步/摆手/下蹲/起身/空闲…）都从这里提案
    · ★ 迈步之前**先出"重心转移相位"**（comTrack），再出落足点与摆动腿轨道
    · 输出 ActionProposal { 相位序列 + 时长 + 预算 }；只提案不执行
    │ ActionProposal
控制层 ControlLayer —— 唯一裁定者 + 发布者
    · ingest(StabilityCorrection) + ingest(ActionProposal)
    · 裁定：manual > reflex > balance > action > program > posture
    · 向上暴露 play/abort/status + 直控通道；向下只写 Executor
    │ 关节命令（经 Executor，账本/τmax/限位兜底）
摔倒预警（独立·常开伺服层）—— 每拍连续出 StabilityCorrection { desiredCopShift,
    comAdjust, gainScale, level }（含 reflexDirectives：怎么用反射）；也不写关节
```

**两提案的联合纪律（"不打架"是唯一目标）**：
- **分工**：伺服修正常作用在 CoM/CoP/踝-髋；动作提案作用在轨迹/摆动腿——**不同轴直接并行**；
- **融合**：同轴时**增量叠加**（伺服修正叠在动作轨迹上），各自限幅；
- **让位**：同轴反向冲突超阈值按紧迫度裁定（安全优先，动作降权/暂缓该轴），记入 `decision.conflicts`。

**状态机归宿**（用户定调）：v1 的全局步态状态机**取消**——搬进动作提案系统内部，
就是本文档的**相位编排器**（迈步：重心转移 → 摆动 → 落足 → 稳定）。

**现状与目标态（诚实标注）**：
- 现状：`ActionSystem` + `Phase[]` 经控制模块的 `manual`/`comTarget` 通道写入——
  是"提案"的**退化实现**（控制层仍唯一整合下发，行为已验证）；
- 目标：按 §8 路线图逐步**形式化 `ActionProposal`**（相位序列+时长+预算 → `ingest`），
  迁移期间行为逐位不变（`probe-control` 门禁）。

## §1 角色与边界

| 属于动作层 | 不属于动作层 |
|---|---|
| 动作的**完整轨迹**：关节角/力矩关键帧、质心轨道、相位时序 | 平衡细节纠正（垫脚 CoP、差动加载、目标守护） |
| 动作的**成功判定**：触地/离位/载荷/到位等**事件**与安全出口 | 摔倒预警的预测量（CoM/XCoM/间隙） |
| 动作期间的**姿势主动保持**（蹲起竖直髋补偿、抬腿配重） | 反射弧（垫脚/消力/负载撑住/抓地）——只做让位与兜底 |
| 空闲行为（部位复合、随机参数） | 关节层（`executor/drive`，已冻结重建）的执行细节 |

纪律：
1. **动作要"明确"**：每一相必须有可检验的事件、明确的目标与速率、超时安全出口；
2. **不依赖伺服成功**：动作自己完成轨迹与姿势；伺服缺席时动作应"安全退化"（放弃/收尾）；
3. **只提案不执行（§0）**：动作只出姿态/力矩/质心目标（=提案内容），由控制层整合裁定下发；
   动作层**永不直写 Executor**；动作可 `pin` 声明"这些自由度归我"（反射让位）——但伺服仍可
   按 §0 的融合/让位规则同轴处理；
4. **写进去的都要能交还**：动作结束（含超时/完成路径）必须 `clearAngle`/解钉。

## §2 迈步原语（step primitive）——总设计

### 2.1 文献依据：抬腿后的重心与落脚怎么控

| 文献 | 关键结论（实验事实） | 对原语的含义 |
|---|---|---|
| **Mouchnino et al. 1992**（J Neurophysiol，PMID 1629766；腿侧抬 45° 实验） | 转移 = ①**移动腿弹道推蹬**（腓肠肌先放电）②调整段；**腿的启动被延迟到重心已到支撑脚上方**；支撑腿绕踝 AP 轴外旋（"倾斜策略"）+ 头颈/躯干反旋 | A 相"稳了才抬"**就是人类策略**；转移应由移动腿弹道推力主导；支撑侧姿态（后述伺服 posture）参与 |
| **Mouchnino et al. 1996**（J Neurophysiol，微重力对照） | **shift mode**（移重心）+ **stabilization mode**：抬腿期间**躯干反向侧倾配重，CoM 位置保持不动**；stabilization 在微重力仍存在 → 是不依赖重力的"运动定型" | ★ **抬腿后重心的答案**：不是伺服找补，而是**与抬腿耦合的前馈配重**（可做成不依赖状态的自平衡模式） |
| **Rogers & Pai 1990**（Exp Brain Res 81:398–402，`10.1007/BF00228132`） | 快速转移的初始横向冲量 **4:1 来自屈腿（移动腿）**；屈腿侧髋外展肌放电先于地面反力变化；慢速则支撑膝先行（两套速度策略） | A 相按速度分策略；快速段用**移动腿短促推蹬**加速重心，不靠伺服慢拉 |
| **Winter 1992**（Phys Ther 72:45–53，`10.1093/ptj/72.1.45`） | 摆动脚轨迹是**端点控制**任务：最小离地 **1.29cm±4mm**、触地水平速度 ≈0、**垂直接近速度≈0**、最后 10% 近水平；轨迹对**支撑髋外展 ±0.86°** 等也敏感 | 落脚 = 上靶 + **晚段平推回收**；摆动轨迹是"两层耦合"产物（支撑侧也算） |
| **Seyfarth, Geyer & Herr 2003**（J Exp Biol 206:2547–2555，`10.1242/jeb.00463`） | **晚段回收（retraction）**：落地前小腿匀速后收 → 自动修正攻角、**降低落地冲击**、收敛快 ~4 倍 | D 相"倒着收着落"（低冲击触地），而不是直直放下 |
| **Bauby & Kuo 2000**（J Biomech，`10.1016/s0021-9290(00)00101-9`） | 侧向平衡**需要主动控制**，**落脚点（foot placement）是主机制**，单步即可拦停侧向失稳 | 落点选择=动作层核心安全手段（早落+收回来的脚） |
| **MacKinnon & Winter 1993**（J Biomech，`10.1016/0021-9290(93)90027-c`） | 额状面平衡由**髋外展肌**主动控制骨盆/CoM；踝无 lateral 权限 | 抬腿侧髋接管/软目标、支撑侧承重环的来源 |
| **Englsberger et al. 2013/2015**（IROS/T-RO，`10.1109/TRO.2015.2405592`） | DCM/eCMP 控制：**期望 CoP 必须投影进支撑多边形**（不可行只能投影到边界）；越界只能靠**迈步调力向** | 伺服期望 CoP 的可行性投影（已实现）；"越界→迈步"接口的依据 |
| **Winter 1996**（J Neurophysiol 75:2334，`10.1152/jn.1996.75.6.2334`） | 并足站立 **M/L 平衡 = 髋 load/unload 机理**（两侧负载差驱动 CoP；踝内外翻在 M/L 几乎无效） | 差动加载 u 环的正确形式：`u* = −(CoP目标−双脚中点)/(半跨距)`（窄站距必须重定心） |
| **Ashton-Miller 2020/2022**（PLOS One，`10.1371/journal.pone.0242454`） | 单腿站立**髋外展需求 = 50–100%+ 最大肌力**（饱和是物理必然）；到 FBR 边界只有两条路：**躯干同侧侧弯（降需求 37%）**或**迈步** | 躯干调节器有文献背书；越界→迈步（=走路前置）；"增强腰"有据 |
| **Inman 1947**（JBJS 29:607，PMID 20253034） | 单腿髋外展力矩下界 = **体重 × 髋间距/2**；实测肌电只有理论值一半——**另一半来自 IT band 被动张力**；关节反力 2.4–2.6× 体重 | 我们测的需求 86–110 N·m 正是该下界域；**被动分担（IT band）是人体机制**——见执行层被动元件 |
| **McLeish & Charnley 1970**（J Biomech，`10.1016/0021-9290(70)90006-0`） | 实测：外展肌力 **1.0–1.8× 体重**、关节力 1.8–2.7×；**骨盆姿态影响巨大**（外展位最省） | 骨盆下沉（Trendelenburg）＝更省力的姿态——与"自然悬垂"一致 |
| **Prior 2014**（BMC SMR） | 骨盆下沉姿势 → 臀中肌激活 **−84%**、TFL **−143%**（转向 IT band 被动承载）；骨盆抬高才费肌肉 | 被动承载的姿势学证明；支撑侧应允许下沉（省主动肌） |
| **Bergmann 2001/2016**（J Biomech 34:859 `10.1016/S0021-9290(01)00040-9` / PLOS One，**有创植入体实测**） | 单腿站立**髋接触力 2.1–2.8×体重**（平稳）；**平衡挣扎瞬间冲到 5.5×体重** | 内部发力的直接实测：稳态不高，**"稳住"的过程里力大幅波动** |
| **单腿站立肌协同**（BMC SMR 2021，`10.1186/s13102-021-00392-z`） | 4 个协同：**两个踝主导 + 一个膝主导 + 一个髋/背主导**；闭眼时髋/背协同显著下降、踝上升 | OLB 内部发力的模块化组织——**髋/背（上身）是四大之一** |
| **Torres-Oviedo & Ting 2009**（J Neurophysiol，`10.1152/jn.00960.2009`） | 单腿/深蹲等极端构型**追加任务特异协同**（不重造协同） | 单腿 = 共用协同 + 一个特异协同 |
| **上身质量与躯干控制**（JIES 2023） | **上体质心偏差与总 CoM 摇摆相关 r=0.53；躯干同侧侧屈与 CoP 频率 r=−0.64** | ★ 用户直觉的直证：**上体（躯干）控制是单腿稳定的主要因素** |

### 2.2 相骨架与四个控制模式

```
A 转移  ── 左右重心： stanceBalance.transfer()
           = 人类同款闸门（CoM 到支撑脚上方才允许抬）+ ★弹道推蹬（移动腿短促推力）
           + ★预压（用户定调）：目标越过支撑脚 2.5cm——起始就更靠支撑侧
B 抬腿  ── 强制命令：明确收腿架（限速逼近、过事件线即交棒）
           + ★稳定模式 = **重心侧移补偿**（Mouchnino 1996）：摆腿动多少、comTarget 反向补多少
             （人类用躯干侧倾实现；我们直接写重心目标，主动写进动作）
C 落点  ── landingSeek 全权接管（端点控制，Winter）：
           目标点 = footfall(ctx)（CoM 外推 + 防撞带；走路版=步幅/捕获点）
           悬停 2cm（够地观感）；动作层只保留 CoM 目标
D 下落  ── 强制命令：目标高度→0 + ★晚段回收（Seyfarth：匀速后收、低垂直速度触地）
E 站稳  ── 中点回中（双脚支撑多边形）+ 抓地反射（触地 0.3s 踝放平）
```
★ 全程（B–E）三种主动控制（用户定调 2026-10）：
- **全压**：comTarget = 支撑脚 + 2.5cm 外越 + **抬腿质量变化的实时配重**（counterKc 0.25，边抬边算）；
- **腰**：躯干调节器**全量写每节脊柱**（kp500；侧/矢 ±0.18/±0.28；增益 1.4）——腰 τmax 已 120→170；
- **轻腿**：摆动腿显式低刚度（髋/膝 40/8、踝 25/5、外摆 25/6）——"抬起的腿重了 100% 不平衡"；
- **被动分担（优雅落点）**：髋外展轴的 **IT band 式被动力矩**（内收过阈后接入的非线性弹簧）——
  放**执行层被动元件**、不是控制增益：不碰 kp/默认分数（免疫"τmax 派生增益联动"），
  大角度自动分担（Inman：人体约一半靠它）、小角度零干扰。

安全出口（贯穿）：A 不动摇就放弃；B/C/D 任一相抖动超阈立刻早落；
`StabilityWarner.supportState`（margin/loadOk/suggest）**只读**供早落决策。

**迈步伺服层（摔倒预警）在每相的角色**（常开、只提案、不写关节）：
- A：支撑有效性预测（margin/loadOk/est）——动作的闸门读它；
- B/C/D：CoM/CoP 连续修正提案（与动作提案同拍联合；同轴增量叠加）；
- E：负载/回中微调；与动作的"中点回中"目标冲突时按紧迫度让位并记 `conflicts`。
- 配重（Mouchnino stabilization mode）= **动作自己的重心侧移目标**（`comTrack`/`setComTarget`），
  按相主动写定：摆腿动多少、重心目标反向补偿多少——不指望伺服事后找补；
  人类用躯干侧倾实现它（运动定型、微重力仍在），我们直接写 CoM 目标；伺服在其上仍可连续修正。
  ⚠️ 现状缺口：B 相尚无“与摆腿运动耦合的 comZ 反向项”（A/C/E 的 CoM 目标已有）→ 路线图 ①。

### 2.4 单腿站立的力链（文献 + 我们的实测）

**正常人的力链**（文献综合）：地面 → 足（CoP 在脚掌中，踝内外翻 ±2cm）→ 踝（小力矩，M/L 无权限）
→ **膝（≈0：腿绷直，负荷走骨骼轴向）** → 髋（外展肌 50–65% MVC + IT band 被动约一半；接触力
2.1–2.8×BW，挣扎瞬 5.5×BW）→ 骨盆（水平或摆动侧下沉 ≤5°）→ 腰（**位置性侧弯**：QL ≤ 竖脊肌 10%）
→ 躯干（同侧侧屈——上体质量控制，与 CoM 摇摆 r=0.53 / CoP 频率 r=−0.64）→ 上肢（微调配重）。

**我们的实测**（`tools/_probe-chain.ts`，C 保持期）：

| 环节 | 实测 | 人体 | 判定 |
|---|---|---|---|
| 支撑脚负荷 | 92–104% 体重 | 100% | ✓ |
| 踝力矩 | ±6–15 N·m | 小 | ✓ |
| 膝力矩 | −70~−89 N·m（恒定） | ≈10–20 | ✗ **伺服把膝当矢状执行器**（几何已对齐、非物理必需；85<150 未饱和，非倒因） |
| 髋外展 | 55→106 N·m | 50–106% MVC | ✓ |
| 骨盆侧倾 | −1~−5° | ±5° | ✓ |
| 躯干侧倾 | −1~+2.3° | 轻微同侧 | ✓（上体控制见文献） |

**结论**：静态力链环节与量级已全部对齐（骨骼/被动/肌肉三层 + 上体姿态）；"缺失"的不是静态环节，
而是 **① 伺服力矩分配**（膝被过度征用）与 **② 动态段（D/E 的动量时序）**——后者是当前失稳主战场。

**★ 闭合链原则（用户定调 2026-10，实测 + 文献）**：
**收脚/摆腿的发力必须经"支撑脚接地"的闭合链传递**——摆腿力矩对骨盆的反作用由支撑侧同步吸收，
否则变骨盆角动量/CoM 位移。实测（`_probe-chain` D/E）：摆腿外摆 τ **−42→+91 N·m**，支撑侧只 **±14** 在接
→ **骨盆倾角速度 ±50–80°/s**、CoM 漂移（vz 0.19→0.33）。

**★★ 传递机制 = APA（预期姿势调整，前馈而非反馈）**
| 文献 | 结论 |
|---|---|
| Cordo & Nashner 1982；Bouisset & Zattara 1987；Aruin & Latash（综述） | 姿势肌在动作发起**前 ~100ms** 激活，**产力方向与即将到来的反作用相反**（电机械延迟 80–100ms → 必须提前） |
| 步态发起系列（Sci Rep 2021 `10.1038/s41598-021-01694-5`；Yiou 综述） | **抬腿侧髋外展力矩 = 横向转移第一驱动**；APA 幅度随动作速度/质量缩放 |
| 双侧 GRF 预期调制（2026） | 支撑脚在动作前 50ms 就逐脚调制 GRF"接住" |
| Tai Chi 单腿提膝（2024） | "支撑腿在摆动腿发力期起稳定作用，**防止爆发释放造成重心漂移**" |

**★ 支撑柱 = 支撑力矩（Winter 框架；2026-10 架构化）**：支撑腿不塌 = **踝跖屈 + 膝伸展 + 髋伸展**三力矩
之和（"support moment"，各关节互相补偿、与垂直地面反力强相关）；跖屈肌是**持续激活**（触发=所需踝力矩，
非垂直载荷——2012）。实测回读曾见"和≈0"（踝背屈 −18 + 膝 0 + 髋伸 23）→ 塌；已由
`applySupportBrace`（反射升级：踝0.5/膝0.3/髋0.2 + 常开 tonic）补齐。

**收脚瞬间的消力（文献机制）**：① 共收缩增刚度（拮抗肌共收缩=净力矩小、刚度大——Latash）；
② **高不稳时抑制 APA**（Aruin & Latash 1998：APA 本身会变扰动源 → 收脚瞬间应**缩小**预调而非加大）；
③ 回收速度温和（Wisse 2005：轻度 retraction 才增稳）。

**实现**（修正此前"反馈"错误）：`stepPhases::writeReactionComp` 改为**前馈 APA**——读摆腿髋外摆的
**指令力矩**（无延迟），支撑髋反向预载；收脚窗口（非 hold）按 ② 缩放 0.5。
（注：膝的 85 N·m 已查明为 **kd 诱发的阻尼极限环**，kd 按 0.02·τmax 重标后回落到人体域 10–20。）

## §3 接口

### 3.1 关键帧动作（`ActionScript`，actions.ts）
```ts
interface ActionScript {
  name: string;
  frames: Keyframe[];        // { t, pose?: {关节/轴: rad}, torque?: {关节/轴: N·m} }
  comTrack?: ComPoint[];     // { t, x, z } 质心目标轨道（smoothstep 插值）
  expect?: string;           // 验收摘要
}
```
姿态/演示类动作（鞠躬、蹬地挺腰）；`ActionSystem.play(id)`，播放期间 `pinScript`。

### 3.2 相位程序（`Phase[]`，program.ts）——**复杂动作首选**
```ts
interface Phase {
  name: string;
  timeout: number;                       // 到时强制推进并调用 onTimeout（安全出口）
  enter?(ctx): void;                     // 相位进入：捕获几何量、设初始目标
  update?(ctx, dt): void;                // 每帧：读传感器 → 写目标（限速）
  done(ctx): boolean;                    // **事件**完成条件（不依赖时间）
  onTimeout?(ctx): void;                 // 超时兜底（绝不悬空）
}
// ctx = { sensors, bal(StabilityWarner), body }；写入经 bal.manual / bal.setComTarget
```
事件优先于时间（如落腿必须**真触地**）；所有相位必须有超时兜底。

### 3.3 仲裁（唯一写手）
- 直控（`manual`）> 反射 > 平衡 > 动作 > 程序 > 姿势（§0 表格）；
- **同拍联合**：动作提案（轨迹/摆动腿）与伺服提案（CoM/CoP/踝-髋）不同轴并行、
  同轴增量叠加；反向冲突超阈值按紧迫度让位（安全优先），记入 `decision.conflicts`；
- **程序式 pin 不在 ActionSystem 记账里**——相位结束（含完成路径）必须自己解钉；
- 动作写入的角度目标会盖住姿势基线的常量偏置，需要时把偏置并进目标。

## §4 单脚站立 = 迈步原语特例（当前实现规格）

支撑侧 `support`（示例右腿支撑，抬左腿）；`lift` 侧 = 另一侧。`ActionSystem` 默认
`stepPhases({ support: 'r', hold: 0.5 })`。

| 相 | 目标（明确） | 速率 | 完成事件 | 超时/安全出口 |
|---|---|---|---|---|
| **A 重心转移** | CoM 目标 → **支撑脚外越 2.5cm**（粗移 0.08 m/s 到 80% → 精靠 0.03 m/s） | 目标限速 | 支撑脚 >0.6W && 抬脚 <0.25W && \|comZ−支撑脚\|**<0.035**（全压上） && \|vz\|<0.10 | 7s → **无条件抬**（抬腿优先；安全由 C 早落兜底） |
| **B 抬腿（强制）** | 收腿架：髋 +0.60 / 膝 −0.90 / 踝 +0.08（**显式轻刚度 40/8、25/5**）；comTarget=支撑脚+2.5cm 外越+配重 | 1.5 rad/s 限速逼近 | **持续卸载 0.55s**（+2cm 保障） | 2s → 由 C/D/E 继续兜底 |
| **C 落点（寻找器全权）** | `seekLeg` 世界空间 P 控制（**显式轻刚度**）驱向落点，**悬停 2cm**；目标=CoM 外推 0.35s + 防撞带；CoM=支撑脚+2.5cm 外越+配重；**腰调节器全量写脊柱**（kp500） | 轻刚度 40/25 | 时间到 或 早落（\|comZ−支撑\|>0.06 / \|vz\|>0.15 / \|comX\|>0.09 / 0.2s 后 marginZ<−0.02） | 实测保持 −0.164→−0.143（0.5s 漂 2.1cm、vz≤0.06） |
| **D 下落（强制）** | 寻找器目标高度→0；腿角全部由寻找器驱动 | — | **轻触地** Fz ≥0.06W（单脚落腿本就轻，负重交给 E） | 2.5s → 全零压下 |
| **E 站稳** | CoM 以 0.05 m/s 回**双脚中点**（支撑多边形中心；旧"回中线 0"会出界）；腿角限速回零、解钉 | — | 双脚各 0.3–0.7W && \|comZ\|<0.03 | 3s → 全零回中并解钉 |

纪律：A 不收敛不抬腿（安全放弃优于勉强）；B/D 是**唯一允许写死关节角的强制段**；
其余时间抬起的腿由寻找器全权接管；E 的完成路径也必须解钉/交还。

**两层分工（用户定调）**：
- **落点选择（安全点）与"准备下落" = 动作层**（Bauby & Kuo）；
- **"落点是否真能撑住"的判断 = 伺服层**：`StabilityWarner.supportState` 常驻**只读**；
- **着地 = 屈膝消力 + 抓地**（触地 0.3s 踝放平贴地）由消力反射负责（`保护预警与反射弧.md` §3.1/§3.2）。

**★ 落点寻找器（已入 `step/landingSeek.ts`：`LandingSeek.seek`）**
- 职责：B 之后**全权接管**抬起的腿（除 B/D 强制命令）；世界误差 → 三轴 P；
- 灵敏度=实测近似（见 §2.3）；限幅限速；悬停高度可参数（C=2cm、D=0）。

## §5 实测教训（动作层相关）

1. **A 闸门不能按"完美收敛"卡**：旧版 \|comZ−支撑脚\|<3.5cm 且 \|vz\|<0.05 → 交互里常 7s
   超时放弃 = "抬腿概率极小"；放宽 + 兜底后 1.94s 即抬（探针，含加载训练策略）。
2. **抬腿后的"收缩"来自写死收腿架**：B 之后若继续维持折叠姿态 = "还是收缩"；
   交给寻找器（悬停 2cm + 端点误差驱动）后腿朝落点伸出 ✓。
3. **"抬脚内收"来自深收腿架几何**（0.65/−1.05 → 脚甩到前方内侧 x+0.22/z−0.11）；
   0.60/−0.90 + 寻找器后脚回到自己一侧。
4. **外摆符号（`tools/_probe-ab-sign.ts`）**：`hip_*/0` **负=内收可动、正=外推饱和**；
   "−0.45 防跨中线"历史上把脚拉向中线（方向理解反了）；安全落点在外摆上可实现性有限。
5. **CoM 目标的"内侧 +5cm 偏置"是自伤**：它主动制造内漂（落地时 vz 已 +0.14）→ 删除，
   CoM 老实压支撑脚；"倒向内"只留给失败安全。
6. **落腿轻**：单脚落腿 Fz 约 6–30%W（旧触地判据 0.25W 永远等不到）→ 触地=0.06W，负重交给 E。
7. **E 回中目标必须是双脚中点**：两脚都落在支撑侧时"回世界中线"= 重心出支撑区 → 必倒。
8. **抬腿几何/速率**：髋 0.45/膝 −0.75 竖直相消（只抬 1cm）；写死收腿架 0.60/−0.90 抬 5–6cm；
   B 走寻找器实测发散（高度环与髋耦合）——抬相必须写死（强制段）。
9. **消力动作抑制**：动作播放中 +1.0s 尾随消力让位——"蹬地腿抖"根因是解钉瞬间消力猛压膝盖；
   真落地由冲击项即时响应，不受抑制影响。
10. **蹬地挺腰重标**（历史）：深蹲 −40 / 轻蹬 +24·髋−16·踝+6；不再发射离地。

**已知缺口（伺服侧，动作层暂无法兜底）**：单支撑保持期横向持续漂移（支撑髋承重力矩
~70–85 N·m 与骨盆侧倾耦合；E 相支撑髋伺服力矩满幅 120 N·m 顶内漂），属伺服侧向环问题
（用户定调暂不管）。动作层缓解已做：抬腿侧软目标、A 收敛门、落点准、抓地、中点回中。

17. **"增强支撑发力"的两次实测 + 优雅解法**（2026-10）：① 硬抬 τmax（髋外展 0.60→0.78）→ **全崩**
    （τmax 是所有默认刚度/kp 的派生源，全局变硬 30%、A 相不收敛——骨架注释旧账的真根因）；
    ② 力矩实测（`_probe-hip-ab-demand`）：需求 86–110 N·m、τmax 120 = **正好落在人类数值域**
    （青年男 MVC 121±26 N·m；需求=50–100% 肌力是常态）——缺的不是"肌肉"，是**人体那半边的
    被动承载**。解法：**IT band 式被动力矩放执行层被动元件**——既加承载、又零调参扰动（优雅）。
16. **"承重腿斜"是机理产物**（实测世界倾角 10–11°、髋锚过冲支撑脚外 9cm）：动作层直接写承重髋
    **两个符号都试过**——闭链乱顶（ab 跑到 ±0.79、重心冲 −0.33）。单腿大转移物理上必须靠骨盆侧移
    （Winter：踝在 M/L 无权限）；"腿竖直+躯干侧偏"只能在站定期小幅修正里追求，或改伺服横向目标（骨盆位置）。
15. **腰增强 + 摆腿变轻 = 保持期质变**：脊柱 τmax 120→170 + 调节器全量/节（kp500）+ 摆腿轻 →
    C 保持 comZ −0.164→−0.143（0.5s 漂 2.1cm、vz≤0.06）、comX 全程稳 0.01（后倒消失）。
14. **"全压+预偏"**（用户定调）：A 目标越支撑脚 2.5cm、B–E 保持外越 2.5cm + 抬腿质量配重（kc 0.25）
    → B 期 comZ −0.159~−0.165（贴死支撑脚；旧只有 −0.10）。
13. **差动加载 u\* 必须按实际双脚几何重定心**（Winter 1996）：旧式 −copZ/0.16 只在对称站距正确；
    单支撑落地后两脚都在支撑侧（中心 ≠0）时方向算反（实测 CoP 被往反方向搬）。
12. **CoP 可行性投影**（Englsberger）：期望 CoP 必须夹进支撑多边形（旧值 +0.03 在两脚外，
    执行方追不可达点 → 髋环满幅乱顶）。
11. **力矩实测（`tools/_probe-sl-tau.ts`）**：单腿全程——腰**侧向 72 N·m/节打满（饱和 175/170/123 帧）**、
    承重膝 150 打满 44 帧、摆动腿髋屈峰值 **176**（默认真空 kp≈300 太猛）→ 腰 τmax **120→170**、
    摆腿显式低刚度（40/8、25/6）→ 摆动腿峰值 **176→45 / 82→59 / 68→37**（"抬腿的腿要轻"）。
