## §0 为什么重写（v1 的实测尸检）

### 0.1 v1 的死因：零输入下身体自己动

`probe-idle-drift`（v1）实测——**关重力、零 τ、零控制器**，静置 1 秒：

| 量 | 读数 |
|---|---|
| `knee_l/2` | **−114.0°**（自己弯了 114°） |
| `hip_l/0` / `hip_l/1` | 各 **−40°** |
| `hip_r/0` / `hip_r/1` | −22° / **+39°**（**左右不同号**） |
| `foot_l/1` / `foot_r/1` | +25.00° / −25.00°（各顶一侧限位） |
| `torso.y` | 1.429 → **1.511 m**（无重力下自己"浮"起来） |
| `Σ\|Δθ\|` | **454°** |

**这不是平衡问题，是物理/约束层的能量注入。**

（v2 的第一个验收测试就是防它复发——见 §5 T1。）

### 0.3 v1 的第二个死因：三代架构在同一文件里互相干扰

`ragdoll.ts` 4290 行，同时活着：
- **位置伺服**（K=48 弹簧 + `thRef` 目标）
- **V4 纯力矩**（`V4_MODULE_MODE()`，K≡0）
- 各种开关：`V4SGN`/`V4SFK`/`V4SFH`/`V4SFA`/`DMPFIX`/`TAUSLEW`/`SIGNHOLD`/`V4SLIPCAP`/`GRAVTAU`…

**v1 的 `setV4Torques(0)` 不是"松手"**：V4 下 `err=0`、无位置环 ⇒ 关节**永久停在被推到的角度**。
实测直接后果：`probe-joint-survey` 串行测 54 轴时，**前一个轴的姿态污染后一个轴** ⇒ 大量假阴性
（`hip_l/2` 实测能转 83°，却被报成"几乎不动 Δθ=0.29°"）。

### 0.4 v1 的第三个死因：摩擦补丁补错了地方

v1 把 `groundFriction` 从物理值调到 **10.0**（组合后 μ_eff = 5.45）。
但 `friction-budget` 算出：**单脚抗最大扰动只需 μ ≥ 0.23** —— 系数超了 24 倍。

**真凶不是 μ，是 `F_n`。** 库仑判据 `F_t,max = μ·F_n`：
- 脚落地瞬间 / 重心转移瞬间，**法向力会掉到接近 0**
- **μ 再大，乘 0 还是 0** ⇒ 那一瞬间脚就是滑的
- 症状：**抖**（μF_n 反复塌陷-恢复）+ **前移**（每次塌陷残留的水平速度累积）

## §1 唯二判据（任何改动都要过这两条）

### 判据 ① 脚不打滑（用户令：摩擦力小是完全没有站住的可能）

`|F_t| ≤ μ · F_n` 必须**在每一拍**都成立，且要有**余量记录**。

摩擦预算（`tools/friction-budget.ts` 的结论）：

| 量 | 值 |
|---|---|
| 体重 W | 686.7 N |
| CoP 行程（前后 / 左右） | ±0.110 m / ±0.266 m |
| LIPM ω = √(g/h) | 3.187 rad/s（h = 0.966） |
| 最大可控 CoM 加速度 | 1.117 m/s² |
| 抗该加速度所需水平力 | **78.2 N** |
| ⇒ 单脚（F_n = W/2）所需 μ | **≥ 0.228** ← 危险时刻 |
| ⇒ 双脚所需 μ | ≥ 0.114 |

**目标 μ_eff ∈ [0.8, 1.2]**（橡胶-水泥实测 0.8~1.0）。
鞋底 μ = 0.9 ⇒ 地面取 **μ_g ∈ [0.7, 1.5]**，默认 **1.0** ⇒ μ_eff = 0.95。

**v2 的做法（不是把 μ 调大）**：
- **足底用多接触点**（跟 / 跖骨 / 趾），而不是单块平板 ⇒ 压力中心可连续移动，
  `F_n` 不会因为"整块板翻转"而整块塌陷
- **每拍记录 `Σ|F_t| / (μ·ΣF_n)` 摩擦占用率**，超过 0.8 就在验收里报"危险"
- **接触刚度不要过硬**（`contact_natural_frequency` 温和），避免落地冲击把 F_n 打成尖峰后归零

### 判据 ② 力真的把身体拉回来（用户令：脚发力腰真能挺起来）

**通道通**：注入 τ ⇒ `applied` 必须等于注入值（±饱和），且 `τ → Δθ` 方向一致。
**力真起作用**：力矩要能改变 CoM 轨迹 / 胸腔高度，而不是原地抖动。

## §2 τ 注入：单一通道（v2 的核心设计）

v1 的"死通道"教训（`torqueCmd` 被 `v4Tau` 无条件覆盖）在 v2 用**类型系统**根除：

```
Executor.applyTorque(jointIdx, axis, tau)
   ↓  唯一的写入入口，带饱和 + 记账
   ↓
τ_axis = clamp(tau, -τmax[axis], +τmax[axis])   ← 只在这一处饱和
   ↓
impulse = τ_axis · dt   （绕该轴的世界方向，成对等大反向施加给父/子刚体）
   ↓
记账：this.tauCmd[idx] = tau（想要）
      this.tauApplied[idx] = τ_axis（实际下发）
      this.saturated[idx] = (|tau| > τmax)
```

**硬不变量（护栏，写进 `tools/verify-core.ts`）**：
- N1 `tauApplied === clamp(tauCmd, ±τmax)` 逐轴成立
- N2 每个物理步，**每个轴最多被写一次**（`writeCount` 计数，>1 即报错）
- N3 `saturated` 为真时必须有记录（不许静默削）
- N4 **不存在**其他写 τ 的路径（靠接口封装 + 反射断言）

## §3 关节：与 v1 逐位一致（用户令：关节原封不动）

`src/core/skeleton.ts` **原样移植**，不改一个字符：
- 18 关节 / 19 刚体 / 70.00 kg
- 躯干 4 段（骨盆 + spine1/2/3），`spineSegments=4`
- 踝/膝 = `revolute`（自由轴 = 局部 Z，另有 `setLimits`）
- 弓/中足 = `revolute`（自由轴 = 局部 X），走 Rapier 力模式马达
- 其余 = `spherical`（球铰，无引擎级限位 ⇒ 自研冲量限位）

**τmax 表（N·m，轴 [0,1,2]）** —— 原样继承：

| 关节 | [0] 外展 | [1] 扭转 | [2] 屈伸 |
|---|---|---|---|
| neck | 60 | 35 | 100 |
| shoulder | 60 | 35 | 100 |
| elbow | 24 | 14 | 40 |
| hip | 120 | 70 | **200** |
| knee | 90 | 52.5 | 150 |
| foot | 72 | 42 | **120** |
| arch / mfoot | 30 | 30 | 30 |
| spine | 72 | 42 | **120** |

**⚠ v2 要修正的一个 v1 缺陷**：踝/膝是 revolute（只有 1 个自由轴），
但 `maxTorque` 仍给三轴数值 ⇒ 用户看到"踝 τmax=72"会**误以为绕 3 轴都能发力**。
v2 在探针输出里**显式标注自由度**（`revolute[Z]` / `spherical[XYZ]`）。
