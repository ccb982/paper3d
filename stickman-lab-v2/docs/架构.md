# stickman-lab-v2 架构

> 目的：产出**能站住、能被高层动作驱动**的物理火柴人，作为隐藏 boss 移植回本体游戏。
> 本文是唯一真源。v1（`../stickman-lab/`）冻结留档，只作对照与素材来源。
>
> 2026-10 重写：执行层已完成并验收；本文同时给出**控制层**（执行层之上封装的一层）
> 的架构设计。控制层是唯一发布关节执行命令的地方，并且可以被直接操控。

## §0 已验收的现状（机器读数，不是自述）

| 测试 | 命令 | 读数 |
|---|---|---|
| T1 静息（零重力/零输入） | `npm run idle` | Σ\|Δθ\| = **0.0000°**（v1: 454°） |
| 逐自由度权限 | `npm run authority` | **46 轴下发比 1.0000**，±双向对称 |
| 站立 10s（平衡控制器） | `npm run stand 10` | 胸高 1.4224m（只掉 7mm）、ΣFz = 102% 体重、不变量通过 |
| 鞠躬（动作库） | `npm run probe probe-actions bow` | 前弯 0.179m、回位残差 **4mm**、双脚不离地 |
| 执行器不变量 | 全部探针 | `applied == clamp(cmd, ±τmax)` 每步成立、每自由度每步恰好施加一次 |

v1 的三个死因（零输入漂移 454°、执行层三代架构互相覆盖、限位与马达内耗）已分别在
执行层中根除：自碰撞关闭 + 原生球铰干净（实测注入 0.0000°）、Executor 单一写路径、
引擎限位/限位通道按"限位权限 ≥ 马达权限"推导。

## §1 总分层（自下而上）

```
┌───────────────────────────────┐   ┌───────────────────────────────┐
│ 摔倒预警系统（独立）            │   │ 迈步系统（独立）                │
│ StabilityReport               │   │ StepProposal                  │
│ XcoM边距 / TTB / 等级 / 建议   │   │ 落足点 / 摆动腿 / 重心轨道      │
└───────────────┬───────────────┘   └───────────────┬───────────────┘
                │ 只提交评估/提案（绝不直接写关节）  │
┌───────────────▼───────────────────────────────────▼───────────────┐
│ 控制层  ControlLayer（最终判定者 + 唯一关节命令发布者）             │
│   · 多传感估计（CoM/CoP/接触/姿态/关节态）                          │
│   · 反射弧 ReflexArc（脊髓级、短延迟、可打断）                       │
│   · 平衡策略 Equilibrium（踝/髋）                                   │
│   · 动作程序 MotorProgram（任务目标 + 协同，不出关节细节）            │
│   · 直控通道（手动/调试，最高优先级）                                │
│   · 判定：manual > reflex > balance > warning/step > program > posture│
└───────────────────────────────┬────────────────────────────────────┘
                                ▼ 关节命令（经 Executor）
```

**边界纪律**：
- 执行层只认"每自由度力矩/激活/角目标"，不认任何动作语义；
- **摔倒预警 / 迈步是两个独立系统**：它们可以独立开发与验收，但只向控制层提交
  `StabilityReport` / `StepProposal`（评估与提案），**绝不直接写关节**；
- 控制层做**最终判定**，向下只写 Executor（账本、τmax、限位由执行层保证）；
- 控制层向上暴露**动作名 + 参数**（`play/abort/status`）与**直控通道**
  （`setAngle/setTorque/setActivation`，最高优先级）。

## §2 执行层（已建成）

| 模块 | 职责 | 关键设计 |
|---|---|---|
| `core/skeleton.ts` | 骨架数据（不改） | 18 逻辑关节 / 46 自由度、静姿态、限位、τmax |
| `core/body.ts` | 刚体 + 铰链装配 | 球窝 → 原生球铰（3 转）；revolute → 多环链（踝 = 扭+内外翻+屈伸）；柔性足 arch/mfoot 原样（引擎 ForceBased 隐式弹簧） |
| `core/executor.ts` | **唯一 τ 写入口** | 先求和→单点饱和→成对冲量；账本 `cmd/applied/limit/saturated`；每自由度每步恰好施加一次 |
| `core/drive.ts` | 命令通道 | 阻抗伺服（一步收敛护栏 α）、黏性阻尼 τ=−B·ω（显式、限幅）、限位通道（越界冲量，权限压过马达）、激活通道 |
| `core/actuator.ts` | 人类式执行器 | 黏弹阻尼 + 一阶激活动力学 + Hill 力-长/力-速 |
| `core/world.ts` | 步进循环 | `updateDofState → beginStep → controller → drive → applyAll → step` |
| `core/quat.ts` | 四元数唯一实现 | 含 swing-twist 分解（球铰三轴语义） |

执行层**没有**：环境变量开关、隐藏的写 τ 路径、step 后的自研限位冲量。

## §3 控制层（ControlLayer）设计

### 3.1 定位（用户定调）

> "摔倒预警与迈步是两个独立系统，但是都给这个控制层做最后判定。
>  这一层也允许被直接操控。"

翻译成接口：

```ts
interface ControlLayer {
  // ── 消费两个独立系统的输出（只读）──
  ingest(report: StabilityReport): void;      // 摔倒预警：XcoM边距/TTB/等级/建议
  ingest(proposal: StepProposal): void;       // 迈步：落足点/摆动腿/重心轨道
  // ── 直控（最高优先级；调试/手动/游戏特殊输入）──
  setAngle(joint, axis, rad, kp?, kd?): void;
  setTorque(joint, axis, tau): void;
  setActivation(joint, axis, a): void;
  // ── 动作（高层语义；内部自己解算关节）──
  play(action: string, params?: object): void;
  abort(): void;
  readonly status: { action: string | null; t: number; phase: string; decision: string };
  // ── 判定结果（回读给 UI/探针）──
  readonly decision: {
    accepted: ('ankle'|'hip'|'step'|'program'|'manual')[];
    rejected: { kind: string; reason: string }[];
    xcomMargin: number; support: 'both'|'l'|'r'|'none';
  };
}
```

### 3.2 感知与状态估计（Sensors）

每物理步从 Body/Rapier 读取、滤波、延迟分发：

| 量 | 来源 | 用途 |
|---|---|---|
| CoM / CoM 速度 | `body.com/comVel`（质量加权 worldCom） | 平衡主回路 |
| 单脚 ΣFz / CoP | `body.footNormalForce` + 接触流形 | 支撑判定、踝策略 |
| 关节角/角速度/力矩 | `dof.angle/vel` + Executor 账本 | 反射与状态输出 |
| 躯干姿态/角速度 | spine4 刚体 | 翻正反射 |
| XcoM = x + ẋ/ω（ω=√(g/h)） | 计算 | 内部稳定性量（控制层判定用；预警系统另有其评估） |

参考：Peterka 2002（感觉整合 = CoM 误差的 PID + 权重）；Hof 2005（XcoM/动态稳定条件）。

### 3.3 反射弧层（ReflexArc）

**每个反射 = 独立模块**，统一接口：

```ts
interface Reflex {
  id: string;
  latency: number;                       // s，感觉延迟（固定环形缓冲）
  update(s: DelayedSensors, dt): ReflexOutput; // 触发条 + 力矩/激活增量
}
class ReflexArc {
  add(r: Reflex): void;
  step(dt: number): void;                // 写入 Executor 的 reflex 通道
}
```

内置反射清单（各有论文依据）：

| 反射 | 生物对应 | 触发 | 输出 | 依据 |
|---|---|---|---|---|
| 牵张反射 | 肌梭-单突触 | 关节角误差/速度 | 刚度/阻尼调制（Actuator 已内建，暴露为反射） | Nashner 1976 |
| 负载反射 | 高尔基腱器官 | 支撑脚 ΣFz 骤降 | 伸肌力矩脉冲（防腿软） | Nashner 1976 |
| 翻正反射 | 前庭-脊髓 | 躯干倾角/角速度 | 脊柱/髋回正力矩 | Horak & Nashner 1986 |
| 踝策略 | 本体+触觉 | 小幅 XcoM 越界 | CoP = x − (h/g)·a_des 的踝力矩 | Winter 1995 / Hof 2005 |
| 髋策略 | 同上 | XcoM 越界 > 阈值 or CoP 饱和 | 髋屈伸/外展力矩突发 | Horak & Nashner 1986 |
| 保护性迈步 | change-in-support | XcoM 出支撑且回收不可行 | 上报判定；放行后执行迈步提案 | Maki & McIlroy 1997 |
| 屈曲回撤 | nociceptive | 意外碰撞/夹脚 | 快速屈腿（后续） | — |

**延迟**：每个反射有独立 `latency`（牵张 20–40ms、前庭 60–100ms、长环 100–150ms），
由环形缓冲实现；延迟可调为零做对照。依据：Todorov & Jordan 2002（延迟反馈下的最优控制）。

### 3.4 平衡策略 + 两个独立系统的接入（摔倒预警 / 迈步）

**平衡策略（控制层自有）**
- **主回路**：CoM PD → 期望质心加速度 a_des（先按足底 CoP 可达范围限幅）；
- **踝策略**：LIPM 关系 p = x − (h/g)·a_des，由踝屈伸/内外翻实现 CoP；
- **髋策略**：当 CoP 饱和（|Δp| 顶到足缘）或躯干倾角阈值触发。

**两个独立系统（只进不出：提交评估/提案，不写关节）**

| 系统 | 输出（只读） | 内部依据 |
|---|---|---|
| 摔倒预警 | `StabilityReport { xcomMargin, ttb, level: 0\|1\|2, suggested: 'ankle'\|'hip'\|'step'\|'none', dir }` | XcoM 比支撑边距、外推时间；Pratt 2006 / Hof 2005 |
| 迈步 | `StepProposal { leg, footTarget(x,z), duration, comTrack }` | 落足点与摆动腿轨道；Maki & McIlroy 1997 |

**控制层最终判定（示例策略，可调）**
1. 直控/反射正在接管 → 提案进入 `rejected`（记录原因）；
2. 平衡策略可消化（XcoM 在踝/髋权限内）→ 采纳 ankle/hip，迈步提案**暂缓**；
3. level = 2 且踝/髋不可行 → 放行 `StepProposal`，由动作程序层执行摆动/落足；
4. 判定结果全部可回读（`decision.accepted/rejected`），探针据此打分。

两个系统**不得**绕过控制层直接调用 `Drive/Executor`；物理层只认控制层发布的命令。

### 3.5 动作程序层（MotorProgram，"不必输出详细关节指令"）

动作 = **闭环控制器**，不是关键帧：内部由 相位 → 任务空间目标/协同 →（由
平衡/反射/姿势解算关节命令）。对外只有名字与参数。

```ts
interface MotorProgram {
  id: string;
  duration: number;
  start(ctx, params): void;
  step(dt, ctx): ProgramOutput;   // { comTrack?, poseGoals?, synergy?, done }
  abort(): void;
}
```

- **协同（synergy）**：动作给 1~3 个协同通道（如"前屈链""左腿抬起链"），
  由固定权重映射到关节目标/激活 —— 这就是"不输出 44 轴细节"的实现方式。
  依据：d'Avella 2003、Ting & Macpherson 2005（姿势/动作由少量肌肉协同构成）。
- 首批程序：`stand`（重置到静姿）、`bow`（已验证）、`weightShift(side)`、
  `liftLeg(side)`（单腿站立）、`recover(perturb)`（髋策略+可选步）。
- 程序之间可**打断/串联**；被反射打断是正常语义（保护优先）。

### 3.6 仲裁与优先级（唯一的最终命令发布）

| 优先级 | 来源 | 作用方式 |
|---|---|---|
| 1（最高） | 直控通道（手动/调试/游戏特殊） | 直接写目标/力矩；覆盖同轴其他来源 |
| 2 | 反射弧 | 力矩增量；可短时突破平衡/程序的目标 |
| 3 | 平衡策略 | CoP/姿态目标；接管踝/髋 |
| 4 | **摔倒预警 + 迈步（控制层判定后）** | 仅当判定放行；步程序只拥有摆动腿/落足相关轴 |
| 5 | 动作程序 | 任务目标/协同（姿势/关节目标） |
| 6（基线） | 姿势张力 | 未被占用的轴回零位 |

**优先级是逐轴仲裁**：迈步程序放行后只接管摆动腿链，支撑腿与 CoM 仍在平衡策略手里。

- 所有来源最终走 **Executor**（求和 → 单点饱和 → 每自由度每步一次施加）；
- 任何来源都不能绕过执行层的 τmax/限位/账本。

## §5 验收判据（每一层）

- 执行层：T1 = 0.0000°、逐轴下发比 = 1.0000、不变量每步通过（已达成）；
- 平衡层：站立 ≥ 60s 不掉（当前 10s 已过）、水平推力扰动 60N 后 2s 内恢复、XcoM 边距有界；
- 反射层：延迟与增益可回读；撤掉任一反射的对照实验（消融）；
- 动作层：每个动作有 accept/reject 判据（如鞠躬 = 前弯 >0.15m 且回位 <0.12m，已过）；
- 直控：任何关节任何轴可被外部直接支配，回读 `applied == cmd`（已通过）。
