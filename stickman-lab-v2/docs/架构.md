
所以“被动层包含重力补偿”成立，但来源是 **pairBase**，不是 `gravityComp`。



只用于 `score/onset`，不能当伺服误差。精确回正必须用连续 `z/roll`。


是控制器死区，不是传感器精度。

## §9.95 2–4s 为什么没回正（高精度回读，2026-10-23）


## §9.99 脚压力内收/CoP 侧移：论文依据（2026-10-23）

### 9.99.1 论文结论

- **van Leeuwen et al. 2021, Sci Rep 11:21481**：
  踝力矩驱动 ML CoP；脚放得太内侧 → 外侧 CoP，放得太外侧 → 内侧 CoP；
  peroneus longus / soleus / tibialis anterior 参与。
- **Biomechanical response to mediolateral foot-placement perturbations 2020**：
  内侧扰动 → 踝内翻力矩增加 → CoP 外侧；
  外侧扰动 → 内翻减少 → CoP 内侧。
- **PLOS Comp Biol 2023（踝内外翻外骨骼）**：
  外翻力矩 → CoP 内侧；内翻力矩 → CoP 外侧。
- **Winter 1995**：
  双脚并排站立时，侧向主要靠 **hip abductors/adductors**；
  踝内外翻在非 tandem 站立中作用很小。
- **2024/2025 frontal perturbation 研究**：
  大侧向扰动主要靠 hip strategy / stepping，ankle 是辅助。

### 9.99.2 对应到我们

```text
foot/0 = 内外翻
外翻 → CoP 内侧
内翻 → CoP 外侧
```

所以“脚压力主动往内收”是**有论文依据的**，但准确说法是：

```text
用踝内外翻把 CoP 移到需要的位置
不是固定往内
```

方向取决于：

```text
CoM 偏哪边
当前脚在哪只脚承重
需要加速还是刹车
```

### 9.99.3 当前实现

```text
squatAnkleVector 被动分支：
  if (passiveOnly) Mx = 0;
```

→ 脚没有主动 CoP 侧移。

已有实验开关：

```text
SQC_FOOT_COM_K
```

```text
K=0    → 8.637s，slip 7
K=300  → 10.192s，slip 5
K=1000 → 6.771s，过冲
```

说明：

```text
脚 CoP 主动有用；
但符号/限幅/slip guard 没做完。
```

### 9.99.4 正确策略

```text
CoP_target = clamp(
  ankZ + Kcom·(comZ−com0) + Kvel·comVelZ,
  ankZ−limit,
  ankZ+limit
)
```

再由 foot/0 内外翻去追 CoP_target。

### 9.99.5 结论

```text
论文支持“脚压力内收/CoP 内移”是一种策略，
但它不是万能方向；
我们的脚现在确实缺主动 CoP，
下一步是带限幅和 slip guard 的 CoP 伺服，不是固定内收。
```

## §9.103 踝策略重做：CoP 反馈，不是脚踝角度 PD（2026-10-23）

### 9.103.1 论文结论

- **Hof 2007, J Biomech 40:451-457**：
  站立平衡三机制之一：**移动 CoP 相对 CoM 投影**；这是踝策略的力学核心。
- **Peterka 2002, J Neurophysiol 88:1097-1118**：
  姿势控制是主动力矩 + 被动刚度；PID/PD 参数化，刚度需配阻尼；有反馈延迟。
- **Morasso 2022, Front Comput Neurosci 16:956932**：
  踝策略 = 被动刚度 + 间歇主动反馈；目标来自虚拟倒立摆（VIP），不是逐关节 PD。
- **van Leeuwen 2021, Sci Rep 11:21481**：
  踝力矩驱动 ML CoP；脚 placement 误差由 CoP 侧移补偿。
- **Winter 1995**：
  并排站立侧向主要靠 hip abductors；踝内外翻是辅助，但在足底 CoP 控制上仍有效。

### 9.103.2 当前错误

```text
squatAnkleVector:
  if (passiveOnly) Mx = 0;
```

→ 被动分支里踝侧向主动力矩被直接清零。

```text
FootPad:
  if (baseState() === 'squat') return;
```

→ 柔性足/CoP 在蹲姿也不工作。

所以：

```text
脚不是没能力
是踝策略被写死为 0
```

### 9.103.3 正确踝策略

```text
eCom = comZ − com0
vCom = comVelZ
pDes = clamp(ankZ + Kp·eCom + Kd·vCom, ankZ±limit)
Mx   = sign · fz · (pDes − copZ)
```

- `pDes` 是**期望 CoP**，不是脚踝角。
- `limit` 必须小于脚宽，保留 CoP 余量。
- `Mx` 由 foot/0 内外翻执行。

### 9.103.4 与背肌/髋的分工

```text
踝：CoP 相对 CoM（小误差、快）
背肌/脊柱：HAT 姿态（局部）
髋：骨盆/全身 CP（大误差）
```

不是三套 PD 抢同一个 CoM。

### 9.103.5 下一步实装

```text
1. passiveOnly 不再清零 Mx
2. pDes 用 CoM 误差 + 速度
3. CoP limit 收到 ±20~25mm
4. foot/0 内外翻执行
5. 记录 CoP / 踝力矩 / margin
```

## §9.107 踝/髋/背肌协作：论文怎么做（2026-10-23）

### 9.107.1 论文分工

- **Hof 2007, J Biomech 40:451-457**：
  站立平衡三机制：
  1. CoP 相对 CoM 投影移动（踝/足底）
  2. 绕 CoM 反旋转（髋/躯干角动量）
  3. 外力
- **Runge 1999, Gait Posture 10:161-170**：
  踝/髋是**关节力矩连续谱**；纯 hip 不存在；快扰动才加 hip。
- **Morasso 2022, Front Comput Neurosci 16:956932**：
  踝 = 被动刚度 + 间歇主动反馈；
  髋 = 刚度控制；
  混合策略只在纯策略边缘出现。
- **Peterka 2002, J Neurophysiol 88:1097-1118**：
  PID/PD + 被动刚度 + 延迟；刚度与阻尼必须匹配。
- **Winter 1995**：
  并排站立侧向主要靠 hip abductors；踝内外翻是辅助。
- **Alexandrov 2001**：
  ML 的踝+髋合力矩是全局受控量。
- **Lippi & Mergner 2017 (DEC)**：
  踝控 CoM；pelvis-HAT 控 HAT 直立；模块化，不是三套 PD 抢。

### 9.107.2 正确的协作

```text
小误差 / 慢扰动：
  踝 CoP 主控，背肌/脊柱维持 HAT

踝 CoP 到边界 / 快扰动：
  髋接残余（角动量/骨盆）

HAT 局部弯：
  背肌+脊柱先修，不拉腿

不是：
  三个 PD 同时写同一个 CoM
```

优先级：

```text
约束/CoP 安全
→ 踝 CoP
→ 髋残余
→ 背肌/脊柱 HAT 姿态
```

```text

背肌/脊柱：BSS + CoM 项，7~8s 级别
```

结论：

```text
通道能叠加，
但没有论文里的“CoP→髋残余”分配器；
三者还不是真正协作。
```

### 9.107.4 为什么“踝对腿控制不够”

```text
踝容量够（170N·m）
被动刚度 100 最好，再大反而振荡
主动 CoP 只做居中，没有 CoM 位置项
髋没有接 CoP 饱和后的残余
```

所以不是踝没劲，是：

```text
踝没有完整 CoP 目标
髋没有接残余
背肌在单独救 HAT
```

### 9.107.5 下一步

```text
1. 踝：CoP 目标 = CoM/CP + 速度，限幅
2. 髋：CoP 饱和/大误差时才接，不常开
```

## §9.115 踝：连续 PD → 间歇控制（2026-10-23）

### 9.115.1 论文依据

- **Loram & Lakie 2002, J Physiol 545:1041-1053**：
  踝内在刚度只有临界值的 **91±23%**，本身不足以稳定；必须主动调制。

  安静站立 = 踝被动刚度 + **间歇主动反馈**；髋被动刚度。

  连续延迟 PD 很难稳；间歇控制鲁棒；纯踝策略比纯髋更稳、更省能。
- **Asai 2009, PLoS ONE 4:e6169**：
  间歇 PD + 相位平面切换/死区；稳定增益域远大于连续 PD。
- **Peterka 2002**：
  PID + 被动刚度 + 反馈延迟；刚度/阻尼需匹配。

```text
Kp>0 连续 CoP 位置反馈
```

## §9.120 回正伺服为什么烂：根因清单（2026-10-23）

### 9.120.1 不是“力不够”

```text
踝力矩容量 170N·m，实际 ~14N·m
背肌/脊柱有持续输出
hipStrut 有支撑
```

### 9.120.2 根因

1. **把 CoP 控制当成关节 PD**
   - Hof 2007：踝策略是移动 CoP 相对 CoM。
   - 连续位置 PD 在延迟系统里会振（Morasso 2022, Asai 2009）。

2. **没有延迟/相位模型**
   - Kp>0 连续 → 5~6s；间歇 → 9.5s。
   - 说明相位是主因，不是增益。

3. **目标不统一**
   - 踝追 CoP
   - 背肌追 trunk + CoM
   - 髋追支撑
   - 没有 allocator，三个目标互相抵消。

4. **CoP 饱和/足底接触**
   - 脚 CoP 到边缘，踝力矩被接触/摩擦限制。
   - 背肌 BSS 变成实际主承重（BSS_COM=0 → 4.9s）。

5. **没有稳定裕度**
   - 初始差 <0.4°，3s 后 head 分叉 ±5mm。
   - 这是控制器在临界稳定附近，微小差异被放大。

### 9.120.3 论文对应

- **Loram & Lakie 2002**：踝内在刚度 91% 临界，必须主动补。
- **Peterka 2002**：PID + 刚度 + 延迟，刚度/阻尼匹配。
- **Morasso 2019/2022**：被动刚度 + 间歇主动；连续 PD 不稳。
- **Asai 2009**：间歇 + 相位平面/死区，稳定域更大。
- **Hof 2007**：CoP 相对 CoM 是踝策略核心。
- **Sentis & Khatib**：约束 > 平衡 > 姿态，不能三个 PD 平级。

### 9.120.4 正确回正结构

```text
目标：court（CoM c0, trunk r0/z0, joints ang0）
外环：CoM/CP → 期望 CoP
踝：间歇 PD 追 CoP，限幅
髋：CoP 饱和残余
背肌：HAT 姿态，不抢 CoM
```

### 9.120.5 结论

```text
不是回正力小；
是 CoP 相位、目标分配、稳定裕度三者都没做好。
```

## §9.125 动态份额分配与“优先上身”（2026-10-23）

### 9.125.1 论文依据

- **Sentis & Khatib 2005/2006**：
  分层任务：约束 > 平衡 > 任务 > 姿态；低优先级在零空间。
- **Hof 2007**：
  CoM 加速度由 CoP、绕 CoM 反旋转、外力共同决定。
- **Morasso 2022**：
  同一 VIP 状态；踝/髋份额随状态变化，不是固定增益。
- **Asai 2009**：
  相位平面决定何时切换，份额也随状态变。
- **DEC 2017**：
  扰动估计驱动各模块补偿，不是固定配比。

### 9.125.2 优先级

```text
1. 接触/CoP 安全（硬约束）
2. CoM/CP 不出支撑
3. HAT/trunk 姿态（用户优先上身）
4. 关节姿态
```

“优先上身”成立，但不能压过接触/CoM 安全；否则上身回正、整个人倒。

### 9.125.3 动态份额

```text
w_ankle = clamp((copMargin - min)/(max-min), 0, 1)
w_hip   = 1 - w_ankle
w_trunk = f(|trunkError|, trunkCapacity)
```

- CoP 余量足：踝份额大，髋小。
- CoP 到边：踝份额降，髋升。
- trunk 误差大：背肌/脊柱份额升，但只做 HAT。
- 份额之和归一化。

### 9.125.4 约束

```text
u_ankle ≤ CoP margin
u_hip   ≤ hip torque cap
u_trunk ≤ back force/torque cap
```

不是简单相加，要在约束内分配。

### 9.125.5 实现顺序

```text
1. 先固定“接触/CoM 安全”为硬约束
2. HAT 姿态优先于关节姿态
3. 份额随 CoP margin / trunk error 动态变化
4. 每帧只输出一组 u_ankle/u_hip/u_trunk
```

### 9.125.6 结论

```text
动态分配 = 任务优先级 + 执行器余量 + 约束；
不是三个 PD 按固定比例相加。
```

## §9.141 系统辨识 + MPC 的论文做法（2026-10-23）

### 9.141.1 论文路线

- **Kajita 2003**：Preview control of ZMP；用未来参考和延迟补偿。
- **Wieber 2006**：线性 MPC 稳定行走；CoM/ZMP 约束。
- **Herdt 2010**：在线 MPC + 自动落脚。
- **Sentis & Khatib 2006**：whole-body task hierarchy。
- **Escande 2014**：Hierarchical QP，约束/优先级。
- **Peterka 2002**：姿势系统辨识；PID + 刚度 + 延迟。
- **Lippi & Mergner 2017**：DEC 扰动估计。
- **2025 squat TP-MPC + WBC**：三粒子 MPC + 全身控制。

### 9.141.2 系统辨识怎么做

```text
1. 给 CoM/HAT/脚 小扰动（脉冲/PRBS）
2. 记录 state/input
3. 拟合离散状态空间 / ARX：
     x[k+1] = A x[k] + B u[k−d]
4. 辨识：
     CoP → CoM
     hip/back → HAT
     接触 → CoP/滑移
5. 验证：不同扰动/seed 下预测误差
```

不要用单摆公式硬套；先辨识我们自己的 `A/B/delay`。

### 9.141.3 全状态 MPC

```text
状态：
  CoM z/v
  HAT roll/rate
  关节角/速度
  接触/CoP

控制：
  CoP 偏移
  hip torque
  back torque

约束：
  CoP ∈ 脚掌
  摩擦/接触
  hip/back torque cap
  关节限位
```

目标：

```text
min Σ (state−court)^T Q (...) + u^T R u
```

### 9.141.4 延迟

```text
预测里显式用 u[k−d]
或 Smith predictor / 状态预测
```

Peterka 2002 证明延迟是姿势控制核心；Kajita preview 也是为延迟。

### 9.141.5 结论

```text
先辨识 A/B/delay，再做 MPC；
否则 QP/MPC 只是把错误模型算得更快。
```

## §9.156 安全区/死区控制：论文支持（2026-10-23）

### 9.156.1 论文

- **Asai et al. 2009, PLoS ONE 4:e6169**：

### 9.156.2 所以你的思路对

```text
  |eZ| < eSafe
```

```text
r = sqrt((e/eSafe)² + (v/vSafe)²)
```

带滞回：

```text

退出：r < 0.6
```

```text

是保持在 safe region 内，
并且不持续向边界漂。
```

### 9.156.5 结论

```text
论文支持“安全区 + 加权修正”；
这比追求 mm 级归零更符合人体和延迟系统。
```

## §9.157 安全区怎么算、要不要动态（2026-10-23）

### 9.157.1 论文基础

- **Hof 2005**：extrapolated CoM / margin of stability。
- **Pratt 2006**：capture point。
- **Asai 2009**：phase-plane dead zone。
- **Wieber 2006 / viability**：安全集由“是否存在可行控制”定义。
- **Ames 2019**：control barrier function，安全集约束。

### 9.157.2 安全区不是固定 mm

```text
eSafe = min(
  baseE · copMarginFactor,
  capturePointLimit,
  contactFactor
)
```

其中：

```text
copMarginFactor = clamp((CoP_limit − |copOffset|) / CoP_limit)
contactFactor   = 1 if 双脚接触，滑移/单脚时减小
capturePoint    = e + v/ω，必须在支撑内
```

### 9.157.3 动态

```text
CoP 余量大 → 安全区稍大
CoP 到边 → 安全区缩小
滑移/单脚 → 安全区缩小
速度大 → 安全区缩小
```

### 9.157.4 小但要有下限

```text
安全区不能小于传感器噪声/极限环幅度，
否则会抖动。
```

### 9.157.5 结论

```text
安全区：动态、由 CoP margin + capture point + contact 计算；
不是固定 eSafe。
```

## §9.182 精确辨识方法（2026-10-23）

### 9.182.1 现成方法

- **Ljung 1999, System Identification: Theory for the User**：
  ARX/ARMAX/状态空间、PRBS、模型验证。
- **Pintelon & Schoukens 2012**：
  频域辨识、激励设计。
- **Forssell & Ljung 1999**：
  闭环辨识（direct/indirect/joint input-output）。
- **Atkeson 1986 / Swevers 1997**：
  机器人刚体参数辨识、最优激励。
- **Peterka 2002 / 2019 delayed intermittent ID**：
  人体姿势延迟/间歇参数辨识。

### 9.182.2 我们该用哪种

```text
1. 固定接触/支撑
2. 只给一个输入
3. 大脉冲或 PRBS
4. 记录 raw z/roll/v
5. 拟合 ARX / 状态空间
6. 多 seed train/test
```

不要：

```text
闭环激励
score/onset
小幅值 + 控制器抵消
```

### 9.182.3 最低可行实验

```text
impulse response：
  固定躯干/髋
  给已知冲量
  记录 0.5~1s 自由响应
  拟合二阶/ARX
```

PRBS 只用于确认线性范围，不先用。

### 9.182.4 结论

```text
方法成熟，不需要 ML；
关键是固定接触 + 足够激励 + 独立验证。
```

## §9.212 论文里的“膝竖直”是什么（2026-10-23）

### 9.212.1 没有直接叫 knee vertical 的控制器

姿势控制论文主要控：

```text
CoM / CoP
HAT orientation
关节角/力矩
```

“膝在脚正上方”通常作为：

```text
knee alignment / knee valgus / knee over foot
```

出现在**运动损伤/深蹲生物力学**，不是平衡控制器。

### 9.212.2 论文怎么做

- **Winter 1995**：侧向主要靠 hip abductors；膝不是主动侧向控制器。
- **Powers 2010**：髋外展/外旋控制膝外翻；膝对齐是髋/踝的结果。
- **深蹲 knee valgus 研究**：髋外展肌、踝背屈、足弓共同决定膝轨迹。
- 膝关节本身是铰链，侧向稳定靠韧带/髋/踝，不靠膝主动侧弯。

### 9.212.3 对我们的含义

```text
膝竖直 = 任务级目标
执行器 = hip/0 + foot/0
不是 knee 关节写手
```

论文支持这个分解，但不支持“给 knee 加侧向 PD”。

### 9.212.4 结论

```text
“膝竖直”可以作为我们的任务；
论文里对应的是 hip/ankle/foot 控制膝 alignment。
```

## §9.213 论文有没有单独讲蹲姿控制（2026-10-23）

### 9.213.1 有，但分两类

```text
1. 人体深蹲生物力学：
   关节贡献、膝对齐、足压
2. 人形机器人 squat control：
   MPC/WBC、CoM/脚/膝协调
```

### 9.213.2 代表论文

- **Squat Motion of a Humanoid Robot Using Three-Particle MPC and Whole-Body Control, 2025**：
  明确是蹲姿；三粒子 MPC + WBC；CoM/躯干/脚/膝协调。
- **Relationship among the COM Motion, the Lower Extremity and the Trunk during the Squat, 2024**：
  人体深蹲；膝管垂直、髋/踝管前后/CoM。
- **Effects of instability direction on early neuromuscular responses during rapid squatting, 2026**：
  快速蹲姿；躯干/髋肌方向性反应。
- **Powers 2010 / knee valgus 文献**：
  深蹲膝外翻；髋外展/踝背屈/足弓决定膝轨迹。

### 9.213.3 与传统站立策略的区别

```text
站立：
  踝/髋为主，膝近伸直

深蹲：
  膝大屈曲，膝/髋承重
  膝对齐是额外任务
  足压/大腿-躯干接触更重要
```

所以：

```text
蹲姿不是“站立策略 + 蹲下姿势”；
是额外需要 knee/hip/ankle 协同。
```

### 9.213.4 结论

```text
有蹲姿专门论文；
但多数平衡论文仍是站立。
我们做蹲姿，需要额外 knee alignment + 支撑。
```

## §9.242 双腿负重是否各 50%？（2026-10-24）

结论：

```text
对称双足站立/深蹲，平均接近 50/50；
```

- 2023 overhead deep squat：每条腿垂直 GRF 约 **45–60% BW**，

- 2022 bodyweight squat：双板测到左右 GRF/CoP 有不对称；

```text
目标不是把两条腿死锁在 50/50；

  CoM/CoP 决定总需求；
  左右脚按 CoP 分配；
```

我们的实现应：

```text
对称基线 50/50
+ CoM 横向偏移允许负载转移
+ 不强制左右完全相等
```

```text
PERCEPTION_FOOT_MU=0.6
SQC_SLIP_SCALE=0.2
```

滑移时已降低 K/SAG 出力。
后续应按 frictionUse 限幅，而不是继续加回正力。

## §9.252 摩擦显示 0% 的原因（2026-10-24）

`FootPerception.frictionUse` 计算没问题，
但 `body.footWrench()` 默认：

```text
PERCEPTION_FOOT_MODEL=0
→ 切向力 fx/fz 被清零
→ frictionUse = 0%
```

已开：

```text
PERCEPTION_FOOT_MODEL=1
```

刷新后摩擦百分比才有意义。

注意：

```text
主动力矩不能提高 mu；
只能通过载荷转移/改变切向需求来避免超预算。
```

如果 HUD 经常 >80–100%，应开始做 friction-aware 限幅。
