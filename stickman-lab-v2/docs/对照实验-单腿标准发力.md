# 单腿站立 · 标准发力对照实验（实验档案）

> 立档：2026-10-15。本文是**这些对照实验的唯一档案**：实验过程、判据标准、数据口径、对照记录、结论与待办。
> 目的（用户定调）：**上身两个发力模块（planeSag / lateralStab）作废**，用"冻结 + 手动注入"实验
> 重新设计发力参数，得出**单腿站立情况下的标准发力数据**。
>
> 用户原话（定档依据）：
> - "我要冻结抬腿后的上身，是彻底让上身固定。然后测承重腿和摆动腿的力矩，还有上身自身的重量。然后把得到的数值手动写入一个上身不发力、其他部分照常发力的身体。观察身体能否静止。然后得出单腿站立情况下的标准发力数据"
> - "盆骨也要冻结，你自己估算上身各个部分的力矩。然后手动写进那个躯体试一下，多试试就能得到正确的数据了"
> - "目前的上身发力的两个模块我完全不满意，作废了。……就用冻结+手动注入力的实验"
> - "我要的是单腿的时候的数据"（数据必须取自单腿相：摆动脚离地之后）

## 0. 实验总图（一图看懂）

```
单腿相成立(isLiftDone=摆动脚真实离地)
   │
   ├─ 实验A 冻结测量（MODE=meas）
   │    上身含盆骨彻底冻结(setUpperOff + setRigidUpper〔世界冻结 spine1-4+torso+双臂手，脊柱6轴超刚锁〕+ pair清零)
   │    → 取稳定窗口：上身质量账/各部力矩、脊柱6轴静态需求（=写回数据）、承重腿/摆动腿实测
   │    → .tmp/ubstd.json
   │
   ├─ 实验B 写回试验（MODE=inj）
   │    同种子同历史；抬脚后同刻：上身不发力（UPPER_OFF+pair清零，不冻结）
   │    每帧把写回数据写入脊柱6轴（executor 通道）；腿照常发力
   │    → 观察身体能否静止（判据见 §2.3）→ 迭代参数 → 收敛值 = 新模块的"标准发力"
   │
   └─ 实验C 诊断旁支（MODE=open / scan / KEEPUPPER对照）——只用于归因，不作为结论
```

**纪律**（沿《困境与关键期》"测量先行/不得单帧特调"）：
1. 单进程单种子（同进程多跑=模块级状态污染；多跑必须独立进程）；
2. 每次实验必须留档：参数、首违时间、尾态、波形结论（进 §5 表）；
3. 判据**冻结**——要改判据必须在本文件立档说明，不得临时换标准；
4. 冻结测量的写回值必须与引擎 `gravityComp` 对账（逐轴一致，本次全部 ±0.1 内）；
5. 数据只取**单腿相**（`isLiftDone` 之后）。

## 1. 仪器（探针）

主力探针：`tools/_tmp-ubstd.ts`（本实验专用）。

```bash
# 实验A 冻结测量（默认 MODE=meas）
node tools/run.mjs _tmp-ubstd

# 实验B 写回试验
MODE=inj SCALE=1 RUN=5 node tools/run.mjs _tmp-ubstd
MODE=inj SCALE=0 RUN=5 TRACE=1 TRACE_T=0.4 node tools/run.mjs _tmp-ubstd   # TRACE=看全程波形（不因首违中断）

# 实验C 旁支
MODE=open RUN=4 TRACE=1 node tools/run.mjs _tmp-ubstd      # 全开环：唯一支撑=实时重力补偿
MODE=scan node tools/run.mjs _tmp-ubstd                    # 扫"最接近静止"的时刻
MODE=inj SCALE=0 KEEPUPPER=1 PAIR0=0 TRACE=1 node tools/run.mjs _tmp-ubstd  # 对照：正常系统
```

**env 参数表**（全部进程级）：

| 参数 | 默认 | 含义 |
|---|---|---|
| MODE | meas | meas=冻结测量 / inj=写回试验 / open=全开环 / scan=找最静时刻 |
| SEED | 0 | >0 = 随机预历史（鲁棒协议复刻；逐种子独立进程） |
| FREEZE_DELAY | 0.40 | 抬脚(isLiftDone)后多少秒冻结/开注入（0.4=对齐 C 相摆腿冻结约定） |
| MEAS | 2.5 | 实验A 冻结后跑多久（窗口=末 1s） |
| RUN | 4.0 | 实验B 注入后跑多久 |
| SCALE / S0 / S2 / SIGN | 1 / =SCALE / =SCALE / 1 | 写回缩放：全局 / 轴0(左右) / 轴2(前后) / 全局符号 |
| GCSPINE | 1 | 0=把自动重力补偿在脊柱 6 轴上抵消（"上身真的一点力也不出"） |
| PAIR0 | 1 | 注入起把脊柱 6 轴 pair 命令清零（不听上一位写手的残留） |
| HOLD_KP / HOLD_KD | 0 / 0 | 可选：脊柱角 PD 钉在注入起点姿态（对照用，0=纯写回） |
| TRACE / TRACE_T | 0 / 0.5 | 密集波形（从抬脚起打点，不因首违中断）/ 打点间隔 |

**数据文件**：`.tmp/ubstd.json`
`{ seed, freezeDelay, poseSpine(冻结角), tauSpine(脊柱6轴写回值), poseLeg, tauLegDemand(腿需求gc), appliedLeg(腿实测总账), mass{upper,weight} }`

**谱系**（既有探针，勿重复造）：`_tmp-tq-budget`（力矩账 gravityComp 基准）、`_tmp-upper-rigid`（上身受力解剖）、`_tmp-inject`（frozen/inj/soft/replay 前身）。

## 2. 实验协议（写死）

### 2.1 实验A：冻结测量（MODE=meas）

**流程**
1. `World + ControlModule(postureTone:8)`，`resetFootLateral()`，`play('singleLegR')`，无预历史（SEED=0）；
2. `isLiftDone()` 第一次为真 → tLift（摆动脚真实离地=单腿相成立）；
3. `tLift + FREEZE_DELAY` 时刻一次性：
   - `setUpperOff(true)`（上身写手全关）；
   - `setRigidUpper(true)` + 每帧 `freezeUpperStep`（**世界冻结** spine1-4 + torso + arm_l/r + hand_l/r；
     **脊柱 6 轴超刚锁** kp=20000/kd=300 + pin）——**盆骨(torso)也在冻结集内**（用户："盆骨也要冻结"）；
   - 脊柱 6 轴 pair 命令清零（PAIR0）；
4. 再跑 MEAS 秒；**测量窗口 = 末 1.0s 均值**；终态算 `gravityComp`（静态需求）。

**产出标准**
- 上身质量账：逐部件（头/双臂双手/躯干4段）质量、重量、绕腰(spine1 轴0/轴2)、绕支撑髋(hip_承重/轴0)的力矩贡献；
- 脊柱 6 轴**写回数据**=静态需求（自算=Σ m·g×力臂沿轴投影；与引擎 gravityComp 对账必须一致）；
- 腿链：承重/摆动各 5 轴——**实测（executor 总账）**、净值（breakdown 合成）、需求 gc、角度。

**冻结时点标准**：主档=FREEZE_DELAY 0.40s（对齐 C 相约定）；对照档=0.0s / 1.2s。
**已知边界**：+0.4s 的冻结起点本身在侧摆（roll≈14.7°、约 50°/s）——见 §5 记录 D0/B1。

### 2.2 实验B：写回试验（MODE=inj）

**流程**
1. 同种子、同历史、同 FREEZE_DELAY；
2. 抬脚后同刻：`setUpperOff(true)` + 脊柱 pair 清零（**不冻结**——身体自由）；腿链控制器照常发力；
3. 每帧（drive 之前）经 executor 通道写脊柱 6 轴常量：`τ = SIGN × (轴0:S0 / 轴2:S2) × tauSpine[轴]`；
4. 跑 RUN 秒；TRACE=1 时全程打点（不因首违中断），否则首违即止。

**判据（唯一裁判，相对注入起点 t0，首违止）**
- 前后 |Δpitch| > 20° ；左右 |Δroll| > 10° ；CoM 偏移 |Δx|>5cm 或 |Δz|>5cm ；躯干掉高 >20cm → 判倒。
- **已知判据缺陷（在案）**：t0 姿态若本身在摆（本次 +0.4s 起点 roll 14.7°），"回正扫过"会先触发
  ±10° 首违（如 +0.10s），与实际倒（fz→0、大角度）不可分。**区分必须看 TRACE 波形**：
  首违时间与"实际倒下时间"在 §5 中分列记录。
- 静止的**建议加严口径【待用户裁定】**：尾 1s |vCoM|<1cm/s、|Δpitch|,|Δroll|<2°、支撑 fz 波动<±15% → 报"真静止"。

**迭代标准**：每轮只改一组参数（SCALE/SIGN/S0/S2/HOLD_KP/GCSPINE/FREEZE_DELAY），记录进 §5 表；
收敛目标 = 至少（a）不触发倒（fz 不归零）、（b）侧摆收敛不放大、（c）尾段漂移最小。

### 2.3 实验C：诊断旁支（不作结论）

- **open（全开环）**：`w.controller=null` + pair 全清零 + 唯一支撑=每帧实时 `gravityComp`。
  回答"这个冻结姿态本身能否静态平衡"——若倒，说明姿态带动量/CoM 偏置，**常量写回不可能按住**。
- **scan**：在正常系统里扫"最接近静止"时刻，指标 = |CoM−CoP| + 0.004·(|pitch|+|roll|)° + 0.8·|vCoM|。用于挑冻结时点。
- **KEEPUPPER=1**：正常系统（modules 照常）基线，用于对照"作废有据"。

## 5. 对照记录（实验结果表）

> 判据口径：首违=±20°/±10°/±5cm 首违时间；实际倒=fz→0 或大角度（TRACE 观察）。

|---|---|---|---|---|---|

| A1 | 冻结测量 | meas @+0.4s | — | — | §4 表（写回数据） |

**首违时间说明**：B1~B6、C1 的"首违"几乎全部由"起点 banked 姿态回正扫过 ±10°"触发（不是真倒），

**回写实况（注入后 0.1s，探针新打印）**：写入值在关节总账里只是小头——
spine1/0［写−18.3 / 实时gc−5.1 / **实际总账 +17.3**］；spine2/0［写−12.9 / gc−2.8 / **总账 +72.1**］；
spine3/0［写−4.0 / gc−0.7 / 总账 −22.2］。即：**入场摆动阶段，关节净力矩被运动阻尼/瞬态项主导，
常量写回被淹没**（这也解释了 B2 比 B1 更早倒）。

## 6. 当前结论（截至 2026-10-15）

1. **写回数据已可复现**：冻结态脊柱 6 轴静态需求（A1/A2），自算与引擎 gravityComp 逐轴一致；
   上身重量 47.46kg/465.6N、绕支撑髋 75~83 N·m 为单腿相的上身载荷基准。
2. **作废有据**：现两模块（planeSag/lateralStab）正常跑 +2.2s 倒；**无写回**反而 +4.6s——
   模块不仅无用还有害（用户已作废，工程上仅留 UPPER_OFF 开关）。
3. **常量写回不能静止**（现状）：单腿相入场姿态本身在摆（roll 14.7°、~50°/s、带侧向动量），
   C1 证明该姿态不是静态平衡点——**任何常量都按不住动量**；写回静态值（B2）还会加速发散。
4. **真正的病灶在腿侧**（在案）：支撑 fz 34~980N 跳（§7p 脚抖）、roll ±10° 摆——
   上身写回救灾不了下层摆动。上身标准数据要等下层至少"不抖"才能验证静态。

## 8. 基础挡标定（2026-10-15，`servo/upperBase.ts` 实装 + 对照扫描）
