# 回正控制器设计 v2

> 2026-10-23。旧链路（pairBase + BSS + ankleVector + hipStrut）保留为基线；本文定义新的统一回正控制器。
> 目标：**一个状态、一个 court 目标、一个优化器、一个低层映射**，不再让多个写手各自追 CoM。

---

## 0. 现状与教训

### 0.1 已做到

```text
被动刚度 + 托髋 + 现有基线：
  fixed probe 可见 7.308s
  网页 seed 好时可到约 8.8s（未做 seed 分布验证）
```

这是真实现象，不是失败：

```text
下盘能撑住一段时间
被动/支撑/背肌确实在出力
```

但：

```text
没有稳定回正到 court
时间再长也可能只是“晚点倒”
```

### 0.2 核心教训

```text
1. 多个写手同时写 CoM → 相位互相对抗
2. 闭环辨识得到的 B 不是 plant B（被控制器抵消）
3. 一步 QP 无法表达延迟/接触
4. 延迟队列/terminal 只加一项不能救
5. 直接翻转符号是玄学，不是设计
6. proposal 审计必须看“是否真的进了总线”
```

## 1. 设计目标

### 1.1 必须

```text
- 保持 court 姿态（CoM、trunk、head）
- 脚始终接触、不滑
- CoP 在脚掌内
- 只使用内力和地面反力
- 延迟显式
- 可解释、可回读、可复现
```

### 1.2 非目标

```text
- 不做神经网络/RL
- 不靠单点增益
- 不靠直接翻转符号
- 不把“多撑 1s”当成功
```

## 2. 总体架构

```text
Perception
  → StateEstimator
  → CourtTarget
  → SafeSet
  → RightingQP
  → LowLevelWBC
  → Actuators
  → CourtJudge
```

### 2.1 StateEstimator

```text
x = [
  e,        CoM 相对 court 的横向误差 (m)
  v,        CoM 横向速度 (m/s)
  trunkZ,   HAT 横向位移 (m)
  trunkR,   HAT 横滚 (rad)
  headR,    头部横滚 (rad)
]
```

来源：

```text
LateralSense.parts.trunk / head
CoM / comVel
foot CoP / contact / slip
```

不使用 `score/onset` 当伺服误差；只用连续 raw 量。

### 2.2 CourtTarget

```text
release 瞬间锁存：
  c0      CoM 目标
  r0      trunk 目标 roll
  trunkZ0 trunk 目标 z
  ang0    关节角目标
```

目标不允许被第一次伺服调用/后续状态污染。

### 2.3 SafeSet

```text
脚：contact=1，slip=0
CoP：|Cop - footCenter| < margin
CoM：capture point 在支撑内
```

安全区动态：

```text
eSafe = baseE · copMarginFactor · contactFactor
vSafe = baseV · copMarginFactor · contactFactor
rSafe = baseR · copMarginFactor · contactFactor
```

区内不主动高频修正；区外按距离加权。

### 2.4 RightingQP

```text
u = [p_cop, τ_hip, τ_back]

min  w_hat·||HAT−court||²
   + w_com·||CoM−c0||²
   + w_u·||u||²

s.t.
  p_cop ∈ [footMin, footMax]
  |τ_hip| ≤ hipCap
  |τ_back| ≤ backCap
  contact = 1
  delay: u[k−d]
  terminal: 末端可停
```

优先级：

```text
1. contact / CoP（硬）
2. CoM/CP（约束）
3. HAT/head（上身优先）
4. effort（最小）
```

### 2.5 LowLevelWBC

```text
p_cop  → ankle CoP（实测约 0.3N·m/mm）
τ_hip  → hip/0 或 hipStrut 支撑力
τ_back → spine1-3 + back muscle lines
```

同一 dof 只允许一个 active owner；passive/safety 通过独立 channel 叠加。

## 3. 系统辨识

### 3.1 原则

```text
开环辨识，不在闭环里估 B
固定接触/支撑
单输入激励
足够幅值、短时采集
train/test 分开
```

### 3.2 模型

```text
x[k+1] = A x[k] + B u[k−d]
```

输入：

```text
ua: ankle torque / impulse
uh: hip torque / impulse
ub: back force / impulse
```

### 3.3 已知

```text
hip B 跨 seed 一致
ankle B 跨 seed 一致
back B 符号仍不稳（激励/接触问题）
```

### 3.4 下一步

```text
back 用 0.2N·s 级 impulse
固定接触
3 seeds
拟合 A/B + d
多步预测验证（11~20 步）
```

## 7. HAT 姿态任务（2026-10-24 补充）

```text
CoM 回中不等于上身回正。
新增独立任务：
  torso pitch → 释放姿态 st.p0
  只写 spine1-3 axis 2
```

避免与 BSS 重复：

```text
BSS 继续负责侧向 roll（axis 0）
HAT 只负责矢状 pitch（axis 2）
```

参数：

```text
SQC_HAT_ORIENT=1
SQC_HAT_KP=300
SQC_HAT_KD=20
SQC_HAT_CAP=20
SQC_HAT_DEAD=0.5°
```

验收：

```text
2–4s torso pitch 跟随 p0
CoM 不出安全区
```

## 8. 髋-膝三角核心（2026-10-24 补充）

```text
核心稳定结构：
  hip center
  knee L / knee R
  foot L / foot R
```

最高优先级任务：

```text
T1 髋-膝三角：
  hip 在双脚中点上方
  knee L/R 在各自 foot 上方
  三角形左右对称、不塌
```

次级：

```text
T2 左右负载 50/50（允许 CoM 偏移）
T3 踝/脚承重 + CoP 约束
T4 上身保持在目标前倾角
```

```text
2024 squat review
2023 trunk/shank hip-knee moment ratio
2006/2021 hip abductor-knee valgus
2018 stance/foot placement
```
