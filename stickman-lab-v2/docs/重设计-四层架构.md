# 重设计：四层架构（2026-10-13 定稿）

> 用户定调："需要满足我说的那个 ±10 度的天平，全身绷直而且持续发力；
> 力都能正常传到地下，不影响腿；还需要有足够的肌肉和力矩。"
>
> 本文档回答：**为什么现在的"一堆律"必然砸腿，以及四层架构如何从原理上不砸腿。**

---

## 一、为什么必须重设计（2026-10-13 全天实锤）

### 1.1 病因链（全部有回读证据）
| # | 现象 | 实锤 |
|---|---|---|
| ① | 力砸腿 | 每个"律"都在**关节空间直接写矩**（M2 ±330、危险墙、黄金窗、反射弹簧）——任何关节矩的反作用都经骨盆/腿链；腿软 → 被反作用甩（膝 ±609°/s 极限环） |
| ② | 目标阶跃=冲量锤 | loadPull 一帧拉 3.5cm、卸载并入阶跃、增益一帧跳变 → M2 追阶跃目标猛泵 → 两脚互砸 |
| ③ | 多写手互扯 | 同一关节上：动作关键帧（kp90/350）+ legReflex + 支撑柱 + 重力补偿 + 姿势基线（违反"一轴一律"） |
| ④ | 刚度撞离散上限 | K400 在膝/髋上 = 极限环（踝锁老律 220-300 对全链同样成立） |
| ⑤ | **反证（设计的钥匙）** | **重力补偿是唯一"不砸腿"的力**——关掉它全系统 0.15s 崩（它恰是"传送重力所需的每关节份额"=静态一致的关节力矩） |

### 1.2 从 ⑤ 读出的原理
**力"传地下不影响腿" ⇔ 该力在关节空间被写成"静态一致解"**（每个关节只拿"传送该力所必需"的份额，无净内耗/无余量）。
重力补偿是"对重力的静态一致解"；任何平衡力都应对应"对它的静态一致解"。

## 二、四层架构

> ★ **战略锚点（用户定稿，2026-10-13）**——"大 CoM 余量"的用法：
> 当时我们的困难是**不知道大 CoM 余量怎么使用**；现在知道了：
> **就是让全身绷直，上身做 ±10° 的一个缓慢天平。**
>
> 物理自洽（为什么这个用法对）：
> - **刚性上身缓慢倾斜** → CoM 随体缓慢平移（τ ≈ h·sinθ，摆幅=余量预算，±10° 正好花掉它）；
> - **"缓慢" 是余量能用的前提**：慢 → 加速度 a≈h·ω²θ 小 → 不需要额外动量管理，
>   惯性力不蚕食余量（这正是"到达边界点也不应有大加速度"的量化形态）；
> - **越界 → 绷直档回拉**（三档状态机）——余量用完前的最后一击。
>
> ⇒ 架构的全部职责浓缩成一句话：**让全身保持刚性（层①）+ 让上身做慢天平（层②）+
> 越界有回拉（三档）**。时间分配（踝/髋/躯干/步的接力时序）= 文档 §三 迁移步骤的实测对象，
> **没有现成论文律，由实验试出来**（困境文档立档的"我们的研究前沿"）。

```
┌─ 层④ 硬件/直控 ── τmax 预算 · 接触容量(fz×CoP) · 离散上限帽(220-300) · manual 直控
├─ 层③ 事件/动作 ── 相位(A-E) · 落点(Rankin) · 迈步 · 天平预测(MoS/XcoM)   ← 保留现有
├─ 层② 任务层（平衡层）── 期望地面反力 F_des → τ = Jᵀ·F_des（唯一关节写手）
└─ 层① 张力层（posture）── 全身协同收缩场 A(t)：连续、慢变、永不阶跃
```

### 层① 张力层（"全身绷直 + 持续发力"）
- **唯一状态量**：激活度 `A(t) ∈ [0,1]`——**连续慢变**（一阶低通 τ≈0.5s，速率上限 ±1.5/s），由天平风险量（XcoM 余量/MoS）**平滑映射**，**不允许任何阈值跳变**。
- 输出：每关节的共收缩刚度/阻尼 = 基础值 + A(t)×增益；膝/踝等小惯量关节以**阻尼为主**（离散上限约束）。
- 文献：Gurfinkel 两层模型（tonic posture）；Wissmann 2025（威胁→僵直：摆幅↓频率↑）；SRS（van der Zee 2026，激活态刚度）。
- 验收：A(t) 的频谱无阶跃（ΔA/帧 < 0.5%）；关节力矩无 >5Hz 的 A 相关分量。

### 层② 任务层（"±10° 天平 + 力传地下"）
- **势阱定义**：在支撑面 CoP 上定义虚拟势阱 W(ξ)——ξ=XcoM 状态（ξ=x+v/ω₀），
  阱内（|上身倾角|≤10°）= 弱刚度慢精修（天平慢摆）；阱壁（>10°）= 强刚度回拉（绷直档）。
- **控制输出 = 期望地面反力** `F_des`（3 分量：Fz 承重 + Fz 横向偏置 + 绕 CoM 力矩）：
  - 平衡项：F = m·(g + a_des)，a_des = −K(ξ−ξ_ref) − D·v（阱内小 K/D，阱壁大 K/D，均为连续函数）；
  - 反旋转项：绕 CoM 转矩由躯干对（Hof 机制②）贡献，也写成 F_des 的一部分。
- **映射（唯一关节写手）**：`τ_j = Jᵀ_j · F_des`——J 用运行时可得量（`d.axisWorld`/`anchorWorld` 的
  τ_i = a_i·((r_i−p)×F)）；Fz 分量的链内静态解**与重力补偿同构**（这就是"传地下不影响腿"）。
- **接触约束**：F_des 先过**接触容量帽**（fz×CoP 余量）——超出部分**不写关节**（写=把脚踢翻）。
- 文献：Khatib 1987（操作空间）；Pratt 1997（Virtual Model Control）；Sugihara 2002（CoG 雅可比）；
  Winter（内力不动 CoM，只有 GRF 加速 CoM——F_des 才是合法控制量）；Hof 2007（机制②）。
- 验收（核心判据）：Jᵀ 通道输出任意 F_des 时，**承重腿关节角速度峰值 < 2°/s**（"完全无变化"）。

### 层③ 事件/动作层（保留）
现有 stepPhases/落点/早落步/天平预测/MoS 全部保留——它们只输出"事件与参考"（相位切换、
ξ_ref、步长），不再写关节。

### 层④ 硬件/直控层（保留 + 审计）
- τmax=能力上限；使用力矩回人体档（现有）——"足够的肌肉"由本节审计对照层①的 A(t) 需求：
  最大任务力 F_max 经 Jᵀ 分配到每关节的需求 ≤ 0.6×τmax 即达标（现有审计 §3.13 基线）；
- 接触容量帽、离散上限帽（刚度 ≤220-300）在此层强制执行（独立于上层怎么算）。

### 2.5 层间接口与写手纪律（架构稳定的核心，钉死）

**每个关节的每一帧，最终只有一个执行写手**——分层只准通过下列接口交换**标量/向量**，不得直接写关节：

| 层 | 读 | 写（唯一出口） | 禁止 |
|---|---|---|---|
| ③ 事件/动作 | 天平状态、相位 | **事件**（相位切换）+ **参考量**（ξ_ref、落点 s.ab、步长） | 直接写任何关节角/矩 |
| ① 张力层 | 风险量（XcoM 余量/MoS）、相位 | `(C(t), λ(t))` 每关节对——**共同激活 C 与参考角 λ**（经激活动力学 → drive 的 MusclePair） | 跳过激活动力学直接写矩；任何阈值跳变 |
| ② 任务层 | ξ 状态、F 容量、支撑几何 | **F_des**（3 分量期望地面反力）→ 唯一映射 τ=JᵀF → drive.setTorque | 逐关节手写 τ；映射域越界（把份额铺进脚/趾——§4.6 教训） |
| ④ 硬件/直控 | — | 容量帽（τmax×系数、接触 fz×CoP、刚度帽）**最后套壳**；manual 拥有最高优先级 | 被上层绕过 |

**让位规则（唯一例外）**：manual 声明过的自由度，其余写手停写（现状已实现 `hasAngle`/`isPinned`）；
**漂移期规则**：层①的 C 保持、λ 冻结（"肌肉保持当前姿态"），层②照常工作（它不写角只写力）。

**写手清单（迁移完成后）**：`manual（直控/保护） + drive.MusclePair（层①） + drive.setTorque(F_des 映射)（层②）` = 3 个，且互斥轴。
现状对照：脊柱单轴最多 5 个写手（lateralStab/iap/lumbar/危险墙/基线）——这是全部对拉问题的来源。

## 三、与现行代码的迁移路径（保资产、测量先行）

> ★ **用户优先级（2026-10-13 追加，最高）**：**上身第一**——
> 上身的**锁死**、**小幅移动**、**大力矩回正**、且**发力正确传地不影响脚**，才是最重要的。
> 迁移顺序据此调整：步骤 0/1 以**躯干链**为首要验证对象（腿=静默观测对象）。

| 步 | 动作 | 验收 |
|---|---|---|
| **0** | **Jᵀ 通道仪器（上身版）**：输入 F_des（躯干期望力），输出 τ=JᵀF，回读**腿关节速度**与躯干响应 | 上身按 F_des 响应；**承重腿关节速度 <2°/s** |
| 1 | 迁移**上身回正**：现 M2/危险墙/黄金窗 → 只写 F_des 的贡献者，Jᵀ 唯一映射（带域白名单，见 §4.5） | 对齐率 ≥70%、腿速判据保持、躯干 Ω 峰值下降 |
| 2 | 迁移**张力层**：iap/legMuscle/srs → 连续 A(t) 场（上身锁死=高 A 小幅移动） | ΔA/帧 <0.5%；无门控跳变；±10° 内躯干摆幅↓ |
| 3 | 迁移**躯干反旋转**（Hof 机制②）到 F_des 的力矩分量 | 危险动量 ≤121 档 |
| 4 | 清残留写手（动作关键帧的支撑腿侧向、baseline 接触） | 关节写手清单=1（Jᵀ）+manual |

**纪律**：每一步双 KPI（对齐率 + 危险动量）+ 腿速判据三表对照；任何一步不达标即回退该步。

## 四、追加要求：合适关节 + 肌肉（用户 2026-10-13 定调）

> "这个上身绷直、大 CoM 余量是人类方法；机器人没有合适关节，纯靠算法走钢丝。"
> "还要合适关节 + 肌肉。"

### 4.1 合适关节（把"绷直"从算法移交给引擎解算器）
- **样板已存在**：柔性足弓的引擎电机（`configureMotorPosition`，刚度 220/阻尼 40，`footPad.ts` 驱动）
  —— solver 级位置约束：**无条件稳定、无离散极限环**（对比：算法伺服 K400 → 膝 ±609°/s）。
- **第一转换（踝链）**：踝已是 revolute；把踝横向锁 K220 从算法伺服改为引擎电机
  （`setEngineMotorTarget` + `configureMotorMaxForce` 保留接触容量帽）；算法只慢速改目标位（天平移 CoP）。
- **膝（revolute 选项）**：已实测大回归（球面自由度在承力"让量"）——档案结论：需**腿链几何/IK 与铰链匹配**
  （过约束问题），留作几何议题，不在本轮。
- **髋（原生球铰）**：无引擎支持 → 保持低权限算法层，只做慢任务力。

### 4.2 肌肉（力不能只是理想力矩源）
四件事，缺一不成"肌肉"：
1. **激活动力学**（张力层的状态就是它）：`dA/dt = (u − A)/τ_act`，τ_act≈0.05-0.1s，A∈[0,1]——**连续、无跳变**（Zajac 1989 一阶激活）；
2. **力-长-速特性**：肌肉力 = A·F_max·f_L(L)·f_V(v̇)（Hill 1938 / Zajac 1989）——天然的速度限制=不再需要算法限幅；
3. **力矩臂路由**：肌肉→关节 = 力矩臂矩阵（=②层 Jᵀ 映射的物理原型；musculoskeletal 建模，OpenSim/Delp 2007）；
4. **成对共收缩**：主动肌/拮抗肌对 = 刚度（SRS：激活态刚度/阻尼，van der Zee 2026）——"绷直"=成对激活，不是单边大力矩。
- **肌力预算**：τmax = 肌肉最大等长力的力矩等效（层④审计："足够的肌肉"=每个任务力的 Jᵀ 分量 ≤0.6τmax）。
- **能量与变异性原则**（Leeuwis/Forbes 2026，PLoS CB）：站立有能量成本地形（微前倾 1.15° 最优、后倾 2×）；
  人站"最低成本附近 + 允许变异性"而非死锁姿态——**±10° 天平 = 能量最优带**；层②的势阱刚度不宜过大
  （低成本带内允许慢摆，越界才拉回——与三档状态机一致）。

### 4.3 修正后的层栈
```
层④ 硬件/能力 ── 合适关节（引擎级：足弓样板→踝链；膝=几何议题）+ 肌力预算（τmax）
层① 张力层 ──── 肌肉激活 A(t)（Zajac 一阶动力学）+ SRS 激活态刚度（van der Zee）
层② 任务层 ──── F_des → τ=JᵀF（力矩臂路由；Khatib/Pratt/Sugihara）
层③ 事件层 ──── 相位/落点/天平预测（保留）
```

### 4.4 上身肌力审计（2026-10-13，回答"有没有足够的肌肉和力矩对抗侧弯"）

**需求侧（重力的侧弯矩）**：上躯干 m_up≈45kg、杠杆 h≈0.25m（脊柱基座到上身 CoM）：
```
τ_gravity(θ) = m·g·h·sinθ ≈ 110·sinθ N·m
  θ=10°: 19 N·m   20°: 38   30°: 55   45°: 78   60°: 95
动态项（减速侧弯）：I_up≈3.2 kg·m²；速率 60°/s 停住 0.1s ≈ 32 N·m
```

**供给侧（本 rig 的脊柱肌力预算）**：
```
脊柱 3 关节 × 156 N·m（SPINE_TAU=260 × 轴系数 0.6）= 468 N·m 总额
单关节 156 N·m 即可盖住 60°+ 的重力矩
```

**审计结论（重要，定调）**：
1. **肌力/力矩从头到尾都不是瓶颈**——供给 ≈ 需求的 **5–25 倍**（60° 静态只需 95，总预算 468）。
2. 真正的瓶颈一直是另外三件事（今天全部实锤过）：
   - **伺服动力学**：小惯量+数字伺服 → 刚度被离散上限钉在 220–300/关节（K400 撞极限环），
     这限制了"锁"的**刚度**，不是**力矩**；
   - **多写手互扯**：同一关节上 2–4 个写手对拉（实测髋上 ±200-270 的"活"里大半是对拉残渣）；
   - **传力路径**：上身力矩的反作用经腿进入地面——腿链任何环节软/裸（膝曾 ±609°/s）就变成振荡。
3. ⇒ 设计推论：
   - **"对抗侧弯"的正确形态** = 肌肉对（共同激活=锁，差动=回正）+ 激活态阻尼（"让侧弯减缓"）；
     力矩预算富裕，**不需要**在单关节上堆高刚度（那恰好掉进离散陷阱）；
   - **"让侧弯减缓"**的显式手段 = 激活态阻尼项（layer①的 `musclePairDamp×C`）：
     当前 C≈0.3-0.55 档已有 ~7-12 N·m·s/rad/关节，按需可翻倍（阻尼不受离散上限的同一约束——
     它正比于速度，天然平滑）；
   - 审计基线：**任何 F_des 经 Jᵀ 分配到脊柱单轴的需求 ≤ 100 N·m**（<0.65×156）即合格，
     超标说明 F_des 或映射域有问题，而不是"肌肉不够"。

### 4.5 Jᵀ 首验记录（2026-10-13 探针 `_tmp-jt`，迁移前必读）

**实验**：δF=[0,0,−120N] 作用于 CoM / 躯干，τ=JᵀF 施加 0.3s，回读腿关节速度峰值：

| 施加方式 | 腿关节速峰 | 躯干倾角变化 | 结论 |
|---|---|---|---|
| 净关节（naive：hip_r/0=−80） | ±14°/s | 1.33° | 基线 |
| **全域 Jᵀ**（所有 dof 含脚/趾/臂） | **±327°/s** | 3.50° | ✗ 份额铺进脚/足弓（foot/arch 拿 99-115 N·m）→ 砸腿更狠 |
| **躯干链 Jᵀ**（仅 spine1-3） | ±12°/s | 1.61° | ✓ 腿安静（份额留在躯干，腿=被动传输） |

**教训（写死）**：映射域 = **任务链本身**（上身任务→脊柱链；不含腿/脚）。
腿的"Jᵀ 份额"不是要写进 τ 模式——**那正是传输本身**（经地面闭合的反力对）。
迁移步骤 1 的映射实现必须带**域选择**（dof 白名单），不是全 dof。
