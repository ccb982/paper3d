# 脚踝基础力与侧向力：3D 力矩合成（2026-10-21）

> **⚠️ 已废弃（历史记录）**：脚踝已重做；目标架构见
> `docs/脚踝重做-基础力与侧向力-2026-10-21.md`。
> 本文保留作设计演进记录，不再作为实现依据。

> **范围**：只设计 `foot/ankle`（`foot/0`、`foot/1`、`foot/2`，以及 `arch/mfoot` 的接触）。
> `hip/knee/spine` 不在本文；它们继续走现有 base/pair。
>
> **结论**：基础力和侧向回正力都不再按“单轴 pitch / 单轴 roll”分别写关节，而是先在**世界力矩空间**合成，再用真实踝轴矩阵**一次分配**到 `foot/0 + foot/2`。`foot/1` 预环锁死不参与。
>
> **一句话**：GRF 是竖直力；踝输出的是力矩。基础力 = 静态前馈力矩；回正力 = CoP 反馈力矩；两者相加后，用 `A=[u0,u2]` 最小二乘分配到两个真实踝轴。

---

## 0. 先纠正一个概念

| 量 | 是什么 | 谁产生 |
|---|---|---|
| 竖直力 `N` | 地面反力（GRF） | 地面接触，外力 |
| 踝力矩 `τ` | 关节内力偶 | 踝关节执行器 |
| CoP | `N` 的作用点 | 由踝/足力矩移动 |
| 身体转动 | `M_GRF = r × N` 的结果 | 由 `τ` 抵消/驱动 |

**踝力矩不能“合成出竖直力”**。它只能：
1. 平衡 `M_GRF`；
2. 移动 CoP；
3. 改变身体角动量。

所以“基础力竖直向上”应改成：**基础力在世界力矩空间里指向需要的方向**（通常是纯矢状 pitch），而不是“竖直力”。

**文献给我们的一句话**：踝力矩是 3D 矢量，应该多轴合成；但合成的是**力矩/CoP**，不是竖直力。

## 2. 坐标、轴与符号

本 rig 的世界系（skeleton.ts 约定）：

```text
+X = 前
+Y = 上
+Z = 角色侧向
```

踝锚点 `a`，CoP `c`，力臂：

```text
r = c − a = (rx, 0, rz)
N = (0, N, 0)          // 竖直地面反力
```

GRF 对踝的力矩：

```text
M_GRF = r × N = (−rz·N, 0, rx·N)
```

- `M_GRF_x = −rz·N`：roll / 侧向外翻
- `M_GRF_z = +rx·N`：pitch / 矢状
- `M_GRF_y = 0`：竖直力绕竖直轴无力矩

关节要平衡它，应提供：

```text
M_joint_des = −M_GRF = (+rz·N, 0, −rx·N)
```

但踝轴不是正交的：

```text
u0 = foot/0.axisWorld   // roll 主分量
u1 = foot/1.axisWorld   // preRing，已物理锁死
u2 = foot/2.axisWorld   // pitch 主分量
```

释放时约：

```text
u0 ≈ (0.80, −0.47, 0.37)
u1 = 锁死
u2 ≈ (0.42, 0, 0.91)
```

所以：

```text
τ = τ0·u0 + τ2·u2
```

**任何单轴力矩都会带其他分量**。这就是“链路里总有侧向”的几何原因。

## 3. 核心设计：世界力矩空间合成 + 一次分配

### 3.1 两个力矩源

```text
M_base  = 基础力（静态前馈）
M_fb    = 回正力（CoP/CoM 反馈）
M_des   = M_base + M_fb
```

**先加力矩，再分关节**。不要分别写 `foot/0`、`foot/2` 两个标量通道。

### 3.2 分配器

可用轴：`u0`、`u2`（`u1` 锁死）。构造 3×2 矩阵：

```text
A = [ u0  u2 ]
```

求关节力矩：

```text
τ = argmin || A·τ − M_des ||² + λ·||τ||²
  = (AᵀA + λI)⁻¹ Aᵀ M_des
```

- `τ = [τ0, τ2]ᵀ`
- `λ` 是正则化（防止两轴近共线时力矩爆）
- 残余 `E = A·τ − M_des` 必须回读；`||E||` 大 = 目标力矩超出两轴张成的平面
- 每个轴再 clamp 到 `tauMax`；若饱和，重新计算残余并记录

**可行性**：两个轴只能张成一个平面（3D 中的 2D 子空间）。`u0,u2` 的 y 分量不为 0，所以它们并不严格张成 x-z 平面；纯 x-z 目标会留一点 y 残余。`λ` 和残余回读是必须的。若残余长期过大，只有三条路：
1. 接受残余（y 分量通常不影响 CoP 太多）；
2. 改骨架，让 `u0,u2` 更接近 x-z 平面；
3. 解冻 `u1`（不推荐，会重新引入 yaw 污染）。

### 3.3 为什么必须在力矩空间合成

- 踝轴随姿势旋转：释放时 `u2=(0.42,0,0.91)`，2.35s 可能变成 `(−0.41,−0.19,0.89)`。**固定的关节力矩 base 会随轴旋转变成错误的 world moment**。
- 固定的 **world moment** base 不随轴旋转；每帧用当前 `A` 重新分配，净支撑力矩保持不变。
- base 和 righting 在力矩空间相加，不会出现“pair PD 把 base 抵消”的问题。

## 4. 基础力设计

### 4.0 固定的到底是什么

“基础力固定，再动态拆分到各轴”这句话，必须先定义固定对象：

| 方案 | 固定对象 | 可行性 | 结果 |
|---|---|---|---|
| 固定竖直力 | `F = (0, N, 0)` | ❌ | `N` 是地面反力（外力）；踝关节力矩不能产生净竖直力 |
| 固定关节力矩 | `τ0, τ2` 常数 | ⚠️ | 踝轴随姿势旋转后，world moment 会变，支撑方向漂 |
| **固定世界力矩** | `M_base` 常数 | ✅ | 每帧用当前 `A` 重新分配；净支撑力矩不变 |
| 固定世界扳手 | `(F, M)` | ⚠️ | 踝关节只能提供 `M`；`F` 由 GRF 提供 |

**本文方案 = 固定世界力矩 `M_base`，动态分配到当前踝轴。**

```text
M_base（固定）
  → A(t) = [u0(t), u2(t)]（当前轴）
  → τ(t) = A(t)⁺ M_base（动态关节力矩）
```

所以你的直觉是对的：**固定的是“世界力矩”，不是“关节力矩”，也不是“竖直力”**。每帧动态拆分到 `foot/0 + foot/2`。

### 4.1 捕获什么

基础力是**静态前馈**。捕获的是**踝的 world moment**，不是一组固定关节力矩：

```text
M_base = τ0_base·u0 + τ2_base·u2
```

其中 `τ0_base`、`τ2_base` 来自标准姿势下的 `staticBalance`（只取脚踝轴）。

也可以直接从名义 GRF 算：

```text
M_base = (0, 0, −rx0·N)
```

- `rx0 = copX0 − a.x`：标准姿势的矢状力臂
- 只保留 pitch（z），侧向（x）留给回正力
- 如果希望 base 也含静态 roll，则 `M_base = (+rz0·N, 0, −rx0·N)`；但这就把侧向权限又给了 base，需明确选择

**推荐**：`M_base` 只含 pitch，侧向全部由 `M_fb` 负责。这样 base 永远是“矢状支撑”，符合“基础力全走矢状面”的目标。

### 4.2 捕获时机

- 在**释放瞬间**捕获，不是 setup。当前 `court.ts` 在 setup 调 `captureSquatBase`；应在 `st.released` 的那一刻重捕一次 `M_base`（或至少重捕 `rx0`、`N`）。
- 捕获后 `M_base` 固定；每帧只重新分配，不重新反解。
- 姿态漂移不改 `M_base`；纠偏归 `M_fb`。

### 4.3 谁来写

- `squatPairBase` **不再写 foot/ankle**（只写 hip/knee/spine/neck）。
- 脚踝唯一的写手是 3D 分配器（`squatAnkle3D`）。
- `foot/2` 的 pair PD 必须关闭；否则它会在分配器之后再加一个关节力矩，破坏力矩合成。
- `foot/1` 预环物理锁死 + 所有写手 skip。

## 5. 侧向力（回正力）设计

### 5.1 目标

不是“产生侧向力”，而是把 CoP 拉回目标：

```text
rz = copZ − ankleZ
rx = copX − ankleX
目标：rz → rz_target（通常 0 或略内侧），rx → rx_target（名义值）
```

### 5.2 力矩反馈

```text
M_fb_x = Kp_z·(rz − rz_target) + Kd_z·(−ω_roll)
M_fb_z = Kp_x·(rx − rx_target) + Kd_x·(−ω_pitch)
M_fb   = (M_fb_x, 0, M_fb_z)
```

- `Kp_z ≈ N` 时，前馈项直接抵消 GRF 的 roll 力矩；再加小增益反馈修正。
- `Kp_x ≈ N` 同理，抵消 pitch。
- `ω_roll`、`ω_pitch` 从踝轴角速度估计（`foot/0.vel`、`foot/2.vel`，或足刚体角速度投影到轴）。
- 增益不是拍脑袋：`Kp` 从 `N` 起，`Kd` 从临界阻尼起；用 ±力矩标定确认符号。

### 5.3 符号标定（必须做）

在标准蹲姿、脚承重时：

```text
给 foot/0 加 +5 N·m → 看 CoP z 往哪边动
给 foot/0 加 −5 N·m → 看 CoP z 往哪边动
给 foot/2 加 +5 N·m → 看 CoP x 往哪边动
给 foot/2 加 −5 N·m → 看 CoP x 往哪边动
```

把符号写死到 `Kp/Kd`，不要靠“读代码猜”。预环锁死后轴方向变了，旧标定可能失效。

### 5.4 可行性钳位

踝只能把 CoP 移到支撑面内：

```text
|M_fb_x| ≤ N·halfWidth
|M_fb_z| ≤ N·halfLength
```

超出就饱和；不要用无限大的力矩去追一个脚外的 CoP。

### 5.5 门控

- `fz > 10% 体重` 才允许出力；脚卸载 → 零输出。
- `court.fall >= 0` → 零输出（否则倒地后 pair/分配器会把脚甩到 ±190 N·m）。
- `preRing`、`engineMotor`（arch/mfoot）不走这个分配器。

### 伪代码

```ts
// capture (release)
const u0 = body.dofs[foot0].axisWorld;
const u2 = body.dofs[foot2].axisWorld;
const tau0b = baseBuf[foot0];   // staticBalance 的踝轴分量
const tau2b = baseBuf[foot2];
M_base = tau0b*u0 + tau2b*u2;   // 或 (0,0,-rx0*N)

// each frame after release
const A = [u0, u2];             // 3x2
const M_grf = [-fz*rz, 0, fz*rx];
const M_fb = [
  Kp_z*(rz - rzTarget) - Kd_z*omegaRoll,
  0,
  Kp_x*(rx - rxTarget) - Kd_x*omegaPitch,
];
const M_des = M_base + M_fb;
const [tau0, tau2] = solve2x3(A, M_des, lambda);
propose(foot0, 'ext', clamp(tau0, tauMax0));
propose(foot2, 'ext', clamp(tau2, tauMax2));
```

## 8. 不做什么

- **不追“竖直力”**：GRF 才是竖直力；踝只输出力矩。
- **不再单轴加 K**：`foot/0` 单轴 K=0.8/1.5 的扫描没有站住；问题在分配/相位，不在增益。
- **不让 pair PD 写 foot/2**：它会抵消/翻号 base；脚踝唯一写手是 3D 分配器。
- **不把 base 和 righting 分成两个独立关节通道**：先在 world moment 空间相加，再分配。
- **不在 `foot/1` 预环上写力矩**：物理锁死，写手全 skip。
- **不把 `copSide` 的 2cm 限幅当成物理支撑面**：3D 分配器直接用支撑面半宽/半长钳位。
