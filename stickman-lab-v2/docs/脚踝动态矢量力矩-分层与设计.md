# 脚踝动态矢量力矩：分层与设计（2026-10-21 重做版）

> **⚠️ 已废弃（历史记录）**：旧脚踝架构全部作废；新设计见
> `docs/脚踝重做-基础力与侧向力-2026-10-21.md`。
> 本文保留作分层讨论的历史记录。

> **范围**：只设计 `foot/ankle`（`foot/0`、`foot/1`、`foot/2`，以及 `arch/mfoot` 的接触）。
> `hip/knee/spine` 不在本文。
>
> **结论（先回答“放哪层”）**：
>
> - **动态矢量力矩的“策略 + 分配”放伺服层**（`core/servo/`），因为它需要 CoP/CoM 反馈、base/righting 合成、按当前踝轴做最小二乘分配——这是控制语义。
> - **“施加 + 限幅 + 账本”放执行层**（`core/executor.ts`），因为执行层是唯一写关节力矩的地方，只认每自由度力矩，不认平衡语义。
> - **不要放进 `drive.step`**：`drive` 是执行层的阻抗/阻尼/限位，藏一个 CoP 反馈控制器会绕过提案总线，变成不可审计的隐藏写手。
> - 脚踝唯一写手 = **伺服层的 3D 分配器**；`foot/2` 的 pair PD 关闭；`FootPad` 蹲姿整段跳过；`foot/1` 预环物理锁死。

---

## 0. 一句话架构

```text
Sensors（CoP / CoM / fz）
  ↓
Servo 层：Ankle3DController
  M_base（固定世界力矩） + M_fb（CoP 反馈）
  → A(t) = [u0(t), u2(t)]
  → τ(t) = A(t)⁺ M_des
  → propose({ kind:'ext', dof: foot/0, foot/2 })
  ↓
ControlModule 提案仲裁
  ↓
Execution 层：Executor.applyAll
  clamp(τmax) → 成对力矩冲量 → 账本 cmd/applied/pair
```

**base/righting 在伺服层合成，关节力矩在执行层施加。**

---

## 1. 为什么不是执行层

执行层的契约（`docs/架构.md` §2）：

> 执行层只认“每自由度力矩/激活/角目标”，不认任何动作语义。

动态矢量力矩包含：

- CoP 误差反馈；
- base + righting 的任务合成；
- 支撑面可行性钳位；
- 按当前踝轴的最小二乘分配。

这些全是**控制语义**。放进 `Executor` 会破坏三条边界：

1. **隐藏写手**：`Executor` 变成“有时按 CoP 反馈算力矩”，账本里只有结果，没有 `M_des`、残差、轴矩阵，无法审计。
2. **仲裁失效**：`Executor` 在提案总线之后，任何“它自己算的力矩”都不经过 `ControlModule` 的逐轴仲裁。
3. **不可复用**：站立/蹲姿/单腿的踝策略不同；执行层应该保持通用，策略按状态切换。

执行层只多做一件事：**提供干净的施加原语**（`addTorque` / `applyAll` / 账本），以及 `Body` 的几何回读（`axisWorld`、`anchorWorld`、`dof.angle/vel`）。它不决定“要多少力矩”。

## 2. 为什么不是 `drive.step`

`drive.step` 已经在执行层里做：

- 被动阻尼 `td`；
- 限位冲量；
- 姿态阻抗/前馈；
- pair 的 `commandMusclePair`。

它没有 CoP、没有支撑面、没有 base/righting 任务。把 3D 矢量力矩塞进 `drive` 会：

- 绕过 `propose`，无法被仲裁/回读；
- 和 `foot/2` 的 pair PD、`FootPad` 形成第三个隐藏写手；
- 让 `lastBreakdown` 的 `ff/damp/act` 语义变得不可解释。

**结论**：`drive` 只保留执行层的阻尼/限位；3D 矢量力矩是伺服层的 `Ankle3DController`。

## 3. 分层职责表

| 层 | 模块 | 职责 | 不做什么 |
|---|---|---|---|
| 感知 | `Sensors` / `Body` | CoM、CoMvel、fz、CoP、`axisWorld`、`anchorWorld` | 不做控制 |
| 伺服 | `core/servo/ankle3d.ts`（新） | base 捕获、righting 反馈、world moment 合成、2 轴最小二乘、可行性钳位、门控 | 不直接写 executor |
| 伺服 | `core/servo/squat.ts` | 在 `squatFrame` 里调用 `ankle3d`；注册唯一写手 | 不再写 foot/ankle pair |
| 控制 | `ControlModule` | 提案仲裁、优先级、输出到 executor | 不发明踝策略 |
| 执行 | `Executor.applyAll` | clamp、成对冲量、账本 | 不读 CoP、不算 M_des |
| 执行 | `Body` | 刚体/铰链、`preRing` 锁死、轴/锚点回读 | 不做平衡 |
| 执行 | `Drive` | 阻尼/限位/阻抗 | 不藏 3D 控制器 |

## 4. 动态矢量力矩的设计

### 4.1 固定的是世界力矩，不是关节力矩/竖直力

| 固定对象 | 可行性 | 说明 |
|---|---|---|
| 固定竖直力 `F=(0,N,0)` | ❌ | `N` 是 GRF（外力）；关节力矩不能产生净竖直力 |
| 固定关节力矩 `τ0,τ2` | ⚠️ | 踝轴随姿势旋转，world moment 会漂 |
| **固定世界力矩 `M_base`** | ✅ | 每帧用当前轴重新分配，净支撑力矩不变 |
| 固定世界扳手 `(F,M)` | ⚠️ | 踝只能提供 `M`；`F` 由 GRF 提供 |

```text
M_base = 常数（世界力矩，推荐只含 pitch）
A(t)   = [u0(t), u2(t)]
τ(t)   = (AᵀA + λI)⁻¹ Aᵀ M_des
```

### 4.2 坐标与符号

```text
+X 前，+Y 上，+Z 侧向
r = CoP − ankle = (rx, 0, rz)
N = (0, N, 0)
M_GRF = r × N = (−rz·N, 0, rx·N)
M_joint_des = −M_GRF = (+rz·N, 0, −rx·N)
```

- `M_GRF_x = −rz·N`：roll / 侧向外翻
- `M_GRF_z = +rx·N`：pitch / 矢状
- `M_GRF_y = 0`

### 4.3 base（固定前馈）

```text
M_base = (0, 0, −rx0·N)        // 推荐：只含 pitch
```

- `rx0 = copX0 − ankleX`：释放瞬间的名义矢状力臂。
- 在**释放瞬间**捕获，不是 setup；捕获后固定。
- 每帧用当前 `u0,u2` 重新分配；姿态漂移不改 `M_base`。
- 如果希望 base 也含静态 roll：`M_base = (+rz0·N, 0, −rx0·N)`；这会重新给 base 侧向权限，需明确选择。

### 4.4 righting（CoP 反馈）

```text
rz = copZ − ankleZ
rx = copX − ankleX

M_fb_x = Kp_z·(rz − rz_target) + Kd_z·(−ω_roll)
M_fb_z = Kp_x·(rx − rx_target) + Kd_x·(−ω_pitch)
M_fb   = (M_fb_x, 0, M_fb_z)
```

- 起点：`Kp_z ≈ N`、`Kp_x ≈ N`（直接抵消 GRF 力矩）；再加小增益反馈。
- `Kd` 按临界阻尼起；符号用 ±5 N·m 的 CoP 响应实测标定。
- 钳位：`|M_fb_x| ≤ N·halfWidth`，`|M_fb_z| ≤ N·halfLength`。
- 门控：`fz > 10% 体重`；`court.fall >= 0` 时零输出。

### 4.5 合成与分配

```text
M_des = M_base + M_fb
A = [u0 u2]                    // 3×2，u1 预环锁死
τ = (AᵀA + λI)⁻¹ Aᵀ M_des
τ0 = clamp(τ0, ±tauMax0)
τ2 = clamp(τ2, ±tauMax2)
E = A·τ − M_des                // 必须回读；||E|| 大 = 目标不可达
```

- 两个轴只能张成一个平面；`u0,u2` 不是纯 x-z，纯 x-z 目标会留 y 残余。
- `λ` 防止两轴近共线时力矩爆。
- 若残余长期过大：接受残余 / 改骨架让轴更接近 x-z / 解冻 foot/1（不推荐）。

## 5. 代码落点

### 5.1 新模块 `core/servo/ankle3d.ts`

```ts
export interface Ankle3DInput {
  fz: number;
  cop: { x: number; z: number };
  com: { x: number; z: number };
  comVel: { x: number; z: number };
  u0: [number, number, number];
  u2: [number, number, number];
  a0: [number, number, number];   // foot/0 anchor
  a2: [number, number, number];   // foot/2 anchor
  released: boolean;
  fallen: boolean;
}

export interface Ankle3DOutput {
  tau0: number;
  tau2: number;
  Mdes: [number, number, number];
  residual: number;
}
```

函数：

```ts
captureAnkleBaseMoment(body, baseBuf): [number, number, number]
computeAnkle3D(input, baseM, gains): Ankle3DOutput
```

### 5.2 `squat.ts`

- `squatPairBase`：只写 `hip/knee/spine/neck`；**不写 foot/ankle**。
- `squatFrame`：`courtStep` → `squatPairBase` → `squatAnkle3D` → `courtInject`。
- 删除/停用 `squatAnkleRoll`（被 3D 分配器取代）。

### 5.3 `stability.captureSquatBase`

- 捕获 `M_base`（踝 world moment），存入 `sqAnkleBaseM`。
- `sqBaseBuf` 的 foot/ankle 清零（不让 pair 写脚踝）。
- 释放瞬间重捕一次 `M_base`/`rx0`/`N`。

### 5.4 执行层

- `Executor.applyAll`：只 clamp/施加/记账；`preRing` 清账 skip。
- `DofLedger` 回读 `cmd/applied/pair`，新增 `ankle3d` 的 `Mdes/residual` 可在伺服层日志里读，不必塞进 executor。
- `Body`：`preRing` 锁死；`axisWorld`/`anchorWorld` 每步更新供伺服层读。
- `Drive`：不新增 3D 控制器；foot/0/2 的阻尼要么关掉，要么从 `M_des` 里扣除。

### 5.5 `FootPad`

- 蹲姿 early return（已做）；不写 foot/0、foot/2、arch。
- 站立仍按原逻辑，不混入蹲姿矢量力矩。

## 6. 验收

| 指标 | 目标 |
|---|---|
| `foot/1` | 恒 0 |
| `‖Aτ − M_des‖` | < 1–2 N·m（或明确记录） |
| CoP z 误差 | 从 40–60 mm 降到 < 10 mm |
| 2.5s 侧移 | < 10 mm |
| 判死 | 不低于 base-only 的 2.485s；目标 > 3s |
| 倒地后 | 踝力矩归零，无 ±190 N·m 尖峰 |
| 符号标定 | ±5 N·m 的 CoP 响应方向与 `Kp` 一致 |
| 分层审计 | 伺服层能打印 `M_base/M_fb/M_des/A/τ/residual`；执行层只打印 `cmd/applied` |

## 7. 不做什么

- 不追“竖直力”：GRF 才是竖直力。
- 不再单轴加 K。
- 不让 `pair PD` 写 `foot/2`。
- 不把 base/righting 分成两个独立关节通道；先在 world moment 空间相加，再分配。
- 不在 `foot/1` 预环上写力矩。
- 不把 3D 控制器塞进 `Executor` 或 `Drive`。
