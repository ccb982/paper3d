# 下盘两 PD 重构（2026-11-05）

## 0. 结论

下盘只有两个肌肉 PD：

```text
HipTaskPD   : hip0 / hip1 / hip2
ShankTaskPD : knee0 / knee1 / knee2 / foot0 / foot1 / foot2
```

所有下盘的**肌肉力矩和被动组织力矩**，包括主动、被动刚度、肌肉阻尼、共收缩、力矩饱和，全部由这两个 PD 输出。  
命令层只出神经信号（目标 / 前馈），不直接写关节力矩。

执行器阻尼和数值阻尼不属于肌肉，放在执行器/引擎，不放进 PD。  
关节限位也不属于 PD。它是执行器/引擎的硬约束。

允许两种阻尼并存，但必须按物理来源分工：

```text
PD 内：B_muscle + B_passive
执行器：B_actuator
求解器：B_numeric / limit
```

上身不在本次范围：`drive` 对脊柱、颈、肩、肘的阻尼、被动、pair、IAP、SRS 全部保留。

## 2. 两个 PD 的内部模型

每个 PD 内部包含四类机制，但只有一个写手：

```text
① 主动
   a      激活动力学
   co     共收缩
   fL/fV  力-长度 / 力-速度

② 被动刚度
   kEff   关节囊 / 韧带 / 肌腱 / 被动弹簧
   slack / deadband / hardening

③ 阻尼
   kd     关节阻尼
   bEff   被动黏性阻尼

④ 读数
   tension 关节张力，只读，不产生额外力矩
```

输出：

```text
B_muscle  = 肌肉内在阻尼 + 反射阻尼
B_passive = 关节囊 / 韧带 / 肌腱被动阻尼

τ_pd = τ_active
     + τ_passive_stiffness
     − (B_muscle + B_passive)·v
```

`B_muscle` 和 `B_passive` 都在 PD 内部，仍只产生一个 PD 力矩。

约束：

```text
同一物理来源只允许一个写手
PD 的肌肉/被动/阻尼由 PD 汇总后统一 propose
执行器阻尼由 executor 写，不能伪装成 PD 或肌肉
不允许 drive 再对下盘 PD-owned 轴直写 P2 / 肌肉阻尼
```

### 3.4 两套阻尼的分工（定稿）

两套阻尼可以并存，因为它们是并联的不同物理来源，不是两套肌肉：

```text
PD 内部
  B_muscle  = 肌肉内在阻尼 + 反射阻尼
  B_passive = 关节囊 / 韧带 / 肌腱被动阻尼

执行器
  B_joint    = 关节级阻尼 = B_actuator + 低层支撑调制
               （当前实现；不是肌肉阻尼）
  B_actuator = 电机、减速器、背电动势、摩擦（B_joint 的子集）

求解器/约束
  B_numeric  = Baumgarte / 约束稳定阻尼
  limit      = 关节 min/max、限位冲量
```

总力矩：

```text
τ_total = τ_pd
        + τ_joint
        + τ_constraint

τ_pd     = τ_active + τ_passive_stiffness
           − (B_muscle + B_passive)·v

τ_joint  = −B_joint·v
```

`B_total = B_muscle + B_passive + B_joint` 只作为审计读数，不是第二个写手。

当前实现的 `B_joint` 是执行器/关节级阻尼，包含执行器阻尼和低层支撑调制；它不叫肌肉阻尼。严格把 `legReflex` 迁入 PD 需要单独重标定，不能和当前 live 版混做。

#### 允许

```text
PD 肌肉阻尼 + 执行器阻尼：可以并存
PD 被动阻尼 + 执行器阻尼：可以并存
PD 内 B_muscle 和 B_passive：可以并存，但都在 PD 内
```

#### 禁止

```text
同一个物理来源重复计算
PD kd 已经是肌肉阻尼，drive 再加一套“肌肉阻尼”
把 legReflex 的支撑/摆动倍率塞进 B_actuator
把 Bmax 当成生理被动参数
```

### 3.5 当前 td 的拆分表

## 10. 文献依据

这些文献支持的是“分层辨识”，不是“每个关节再补一个全局阻尼”。

| 主题 | 文献 | 结论/用途 |
|---|---|---|
| 关节动力学：内在 + 反射 | Kearney & Hunter 1990, *Crit Rev Biomed Eng* 18:55–87；PMID 2204515 | 关节刚度/阻尼与反射分量需要分开辨识，阻尼随力矩/激活变化 |
| 内在/反射分量辨识 | van der Helm et al. 2002, *J Neurosci Methods* 119:1–14；PMID 12234629 | 支持把 intrinsic 与 reflexive 分量分开 |
| 被动/主动踝关节力学 | Weiss, Kearney & Hunter 1986, *J Biomech* 19:727–735 / 737–751；PMID 3793747 / 3793748 | 被动机械与主动机械分开，不能用一个全局阻尼代替 |
| 肌肉 F-V / 肌腱模型 | Zajac 1989, *Crit Rev Biomed Eng* 17:359–411；PMID 2676342 | 肌肉内在速度依赖/阻尼属于肌肉模型 |
| 短程刚度 | Rack & Westbury 1974, *J Physiol* 240:331–350；PMID 4424163 | 主动肌肉有短程刚度/阻尼，属于 PD 肌肉内部 |
| 牵张反射 | Nichols & Houk 1976, *J Neurophysiol* 39:119–142；PMID 1249597 | 反射调节刚度/阻尼，应归反射/PD，不是执行器 |
| 阻抗控制 | Hogan 1985, *J Dyn Syst Meas Control* 107:1–7 | 阻尼是阻抗的一部分，不是独立“第二套肌肉” |
| 阻抗适应 | Franklin et al. 2003, *J Neurophysiol* 90:3270–3282；PMID 14615432 | 中枢通过阻抗（含阻尼）适应稳定/不稳定环境 |
| 数值约束稳定 | Baumgarte 1972, *Comput Methods Appl Mech Eng* 1:1–16 | 数值阻尼属于求解器/约束，不是生理阻尼 |

结论：

```text
文献支持：
  肌肉/反射阻尼 → PD
  被动组织阻尼   → PD 被动项
  执行器/数值阻尼 → 执行器/求解器

文献不支持：
  同一关节上两套都叫“肌肉阻尼”
  用一个全局常数 B 代替按来源分离的阻尼
```

本文件只定义下盘两 PD 的边界，不改变上身设计。

## 12. 阻尼收敛设计（最终）

目标不是把阻尼删成两个数，而是收敛成两个 owner：

```text
PD owner：
  B_muscle  = 肌肉内在 + 反射
  B_passive = 关节囊 / 韧带 / 肌腱
  合并为 B_pd，一个速度状态、一个滤波、一个写手

执行器 owner：
  B_actuator = 电机 / 减速器 / 背电动势 / 摩擦
  只作用于执行器，不伪装成肌肉

求解器：
  B_numeric / limit = Bmax / 关节限位 / 约束稳定
```

总力矩：

```text
τ_pd    = τ_active + τ_passive_stiffness − B_pd·v
τ_exec  = −B_actuator·v
τ_total = τ_pd + τ_exec + τ_constraint
```

### 12.1 当前 td 的拆分

```text
B_joint = B_actuator + B_reflex + B_execDefault
```

归属：

```text
B_actuator  → 执行器
B_reflex    → PD / 反射
B_execDefault    → 先确认来源：
                kp=0 的残留 target → 清除或重命名
                kp>0 的真实目标   → PD 目标阻尼
```

当前实测下盘 `B_execDefault` 是负载项；已改为显式规则，数值保持不变。它仍归执行器 `B_joint`，不迁 PD。

### 12.2 逐轴迁移，不做大改

```text
4. 另一侧
```

每个轴只做：


### 12.3 已落地（第一轮）

## 13. 矢状 / 侧向回正调度（定稿）

### 13.1 两个回正力

```text
矢状回正：
  救全身 / CoM / 髋
  输出 hip + knee2 目标
  HipTaskPD / ShankTaskPD 执行

侧向回正：
  只保抓地 / 小腿力链
  只输出 shank / foot0 目标
  不写 hip
  ShankTaskPD 执行
```

命令层只出神经信号；PD 出肌肉力矩；关节限位仍在执行器/引擎。

### 13.2 模式

```text
mode ∈ { none, sagittal, lateralL, lateralR }
```

硬规则：

```text
同一帧只允许一个 mode
不允许 sagittal + lateral 同时回正
不允许 lateralL + lateralR 同时 active
```

### 13.3 时间域状态机

调度按 `clock` 计时，不按帧数：

```text
SQC_MODE_MIN_HOLD ≈ 0.30 s
SQC_MODE_CONFIRM  ≈ 0.10 s
SQC_MODE_COOLDOWN ≈ 0.10 s
```

含义：

```text
min_hold  ：任何 mode 至少保持 0.30s
confirm   ：侧向需求必须连续成立 0.10s 才允许进入 lateral
cooldown  ：刚切完 0.10s 内禁止反向切换
```

调度可以每帧读取误差，但**只累计时间**；真正切换只发生在时间条件满足后。

### 13.4 切换规则

```text
sagittal → lateralL/R：
  侧向需求持续 confirm
  且 sagittal 已保持 min_hold

lateral → sagittal：
  已保持 min_hold
  侧向误差回落后再 confirm

lateralL ↔ lateralR：
  不允许直接跳
  先 hold
  再 fade out 当前侧
  cooldown 后 fade in 另一侧
```

inactive 命令必须 hold，不能继续出新目标。

### 13.5 侧向单侧与淡入淡出

```text
同一时刻 active shank 唯一
另一侧 hold
进入 active：fade in
退出 active：fade out
禁止脉冲
```

### 13.6 验收

```text
mode 切换次数不随帧率增加
最短 dwell 不小于 SQC_MODE_MIN_HOLD
同一帧 mode 唯一
侧向左右不同时 active
live 不出现 mode 抖动
```

当前状态：

```text

侧向命令层已抽取

  min_hold 0.30s / confirm 0.10s / cooldown 0.10s
```

## 22. 小腿侧向回正：传感器 / PD / 命令层责任划分（2026-11-06）

### 22.1 结论

```text
小腿力链传感器：不是当前主要错误来源
  输出 fParallel / fPerp / CoP / friction，作为测量量使用
  当前只额外做了 fPerp 低通

小腿 PD：不是回正方向的计算层
  只执行 target / ff / 肌肉阻尼 / 被动刚度
  PD 的 kp / kd / cap 不负责决定“往哪边回正”

命令层：当前回正目标和力度算法错误
  这是小腿内收、侧偏、力链不通的主因
```

### 22.2 当前命令层实际算法

```text
fPerp
  → forceK × fPerp
  → delta
  → knee0Target = baseKnee0 + kneeSign × sideSign × delta
  → knee0Ff     = kneeSign × ffK × delta

foot0Target = baseFoot0
```

也就是说：

```text
把 fPerp 这个残余力标量
直接乘一个常数
再乘一个猜测的符号
推给 knee0
```

### 22.3 为什么方向和力度都不对

缺少：

```text
目标侧向力链 F_lat*
实际力链 F_lat_actual
目标小腿倾角
脚到膝的几何关系
```
