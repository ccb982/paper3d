# 监督型回正协调器 HipTaskPD 架构（2026-10-29）

> HipTaskPD 不是髋关节 PD，也不是最高主宰。
> 它是一个监督型回正协调器：预测 XCoM，在 ShankTaskPD 留下的脚底预算内请求骨盆/COM 回收。

---

## 1. 定位

```text
HipTaskPD = 监督型回正协调器
```

不是：

```text
HipTaskPD = 只写 hip/1 的髋关节 PD
HipTaskPD = 完全指挥 ShankTaskPD 的最高分配器
```

它负责：

```text
XCoM/COM 误差
  ↓
期望地面力 F_des / CoP 目标
  ↓
按 N/CoP 预算分配
  ↓
hip / ankle / knee
```

脚/踝/膝是 ShankTaskPD 的本地执行层；髋是监督层。
HipTaskPD 不能覆盖 ShankTaskPD 的脚底接触和局部 CoP。

---

## 2. 论文依据

```text
Khatib 1987
  操作空间：任务力 τ = Jᵀ·F，不是逐关节手写

Sentis & Khatib 2005
  任务优先级 + 零空间投影
  低优先级只能在优先级剩余空间里动作

Pratt et al. 2001
  Virtual Model：先定义期望地面力，再映射到关节

Hof 2005
  XCoM 是动态稳定预测
  任务目标应是 COM/XCoM，不是 hip anchor

Horak & Nashner 1986
  小扰动踝，大扰动髋
  踝/髋是策略连续谱

Mirshams Shahshahani & Ashton-Miller 2020
  髋策略通过脚底剪切力/CoP 影响 COM
  CoP 不能出 BOS

Caron 2019
  所有关节力矩必须满足 N/CoP/摩擦

Winter 1998
  踝力矩控制 CoP，但权限受脚掌边界限制

Kuo 1995
  平衡需要状态反馈/预测
```

结论：

```text
一个任务力分配器
不是 ShankTaskPD + HipTaskPD 各算一套
```

```text
  targetXCoM

  hipHalf
```

## 4. 控制目标

```text
xcomError = xcomZ − targetXcomZ
```

期望地面力：

```text
F_des = −Kx·xcomError
        − Dv·comVelZ
        − Ma·comAccZ
```

提前量：

```text
lead = clamp((TTB_lead − ttb) / TTB_lead, 0, 1)
urgency = confidence · (onset ? 1 : lead)

F_des *= 1 + Klead·urgency
```

目标不是 hip anchor：

```text
不说 targetHipZ − actualHipZ
```

目标是把 COM/XCoM 拉回支撑中心。

---

## 5. 分配顺序

```text
1. 脚接触
   N > 0
   CoP ∈ 脚掌
   |F_t| ≤ μN

2. 踝 CoP
   τ_ankle = Jᵀ_ankle · F_des
   只使用踝份额

3. 膝支撑
   τ_knee = Jᵀ_knee · F_des
   负责 comY / 腿伸展

4. 髋骨盆
   τ_hip = Jᵀ_hip · F_des
   负责骨盆/COM 回收
```

优先级：

```text
脚接触 > 踝 CoP > 膝支撑 > 髋骨盆
```

低优先级只能使用剩余预算。

---

## 6. 输出

```text
hip/0
hip/1

foot/0
foot/2

knee/1
knee/2

CoP target
```

不分别写四套目标；全部来自同一个 `F_des`。

## 7. 预算

脚掌半宽：

```text
3.8cm
```

默认分配：

```text
髋预留 60~70%   → 2.3~2.7cm CoP
踝保留 30~40%   → 1.1~1.5cm CoP
```

高风险：

```text
TTB 小 / onset / confidence 高
髋 75~80%
踝 20~25%
```

低风险：

```text
髋 50%
踝 50%
```

规则：

```text
释放时预留
髋优先使用
不用时还给踝
N 掉了预算自动消失
不允许 CoP 越界
```

---

## 8. Jᵀ 分配

```text
τ = Jᵀ · F_des
```

其中：

```text
J = ∂(COM/XCoM) / ∂q
```

实际实现可以先用：

```text
F_des 经过优先级和预算
再分给 hip/ankle/knee
```

但分配结果必须来自同一个任务力，不是四套独立 PD。

## 12. 权限层级：髋不能完全指挥 Shank

HipTaskPD 不是最高主宰，ShankTaskPD 也不是完全听髋。

正确层级：

```text
1. 脚接触 / N / CoP          ← 最高，硬约束
2. ShankTaskPD 局部踝/膝回正  ← 主执行层
3. HipTaskPD 骨盆/COM 请求    ← 监督层，只能用剩余预算
```

ShankTaskPD 负责：

```text
脚掌抓地
踝调小腿
膝支撑
CoP 不越界
```

HipTaskPD 负责：

```text
预测 XCoM
请求骨盆/COM 回收
请求 hip/0、hip/1
```

Hip 的请求必须满足：

```text
ShankTaskPD 当前脚底 N/CoP 允许
否则被拒绝或降额
```

所以不是：

```text
HipTaskPD 完全分配一切
ShankTaskPD 完全服从
```

而是：

```text
ShankTaskPD 保住脚底和局部回正
HipTaskPD 在剩余权限内做 COM 预测调节
```

论文对应：

```text
Sentis & Khatib 2005  高优先级任务占主导，低优先级只用剩余空间
Caron 2019            接触约束高于任务力矩
Horak & Nashner 1986  踝策略是基础，髋策略是大偏差补充
```

## 13. 左右髋独立：common / differential

论文没有把左右髋固定成：

```text
τL = +τ
τR = −τ
```

它允许左右髋独立：

```text
τL、τR 各有自己的大小和方向
```

工程上分解为：

```text
common = (τL + τR) / 2
diff   = (τL − τR) / 2
```

含义：

```text
common：骨盆/COM 整体侧移
diff  ：骨盆左右倾斜
```

所以：

```text
τL = common + diff
τR = common − diff
```

当前错误：

```text
τL = +want
τR = −want
```

等价于：

```text
common = 0
diff   = want
```

也就是：

```text
只有骨盆倾斜
没有骨盆平移
```

这会看起来像“扭骨盆”，不是“杠杆回正”。

正确分配：

```text
common 由 XCoM/COM 误差决定
diff   由骨盆水平/左右脚 N 差决定
```

并且：

```text
common 和 diff 都要受 N/CoP 预算限制
```

论文对应：

```text
Mirshams Shahshahani & Ashton-Miller 2020
  额状面两连杆模型
  左右 hip abduction moment 独立

Horak & Nashner 1986
  髋策略允许骨盆/躯干左右不对称

Neumann 2010
  左右髋外展肌分别控制骨盆侧倾

Winter 1995/1998
  髋控制骨盆和 COM 的侧向位置
```

## 14. 髋预测前馈

髋不能等 XCoM 误差出现才出力。

未来 XCoM：

```text
xhat(t+T) = xcom + comVel·T + 0.5·comAcc·T²
```

预测前馈：

```text
F_ff = −Kff·(xhat − targetXcom)
```

总任务力：

```text
F_des = F_feedback + F_ff
```

其中：

```text
F_feedback = −Kx·(xcom − target) − Dv·v − Ma·a
```

提前量：

```text
onset / TTB / confidence → T
TTB 越小，T 越提前
onset → 先出预紧力矩
```

论文对应：

```text
Hof 2005       XCoM 预测
Kuo 1995       状态反馈/预测
Peterka 2002   延迟补偿
Horak 1986     髋策略提前介入
```

验收：

```text
预算还没消失前，髋已经出力
不是等误差变大
```

## 15. 髋关节能力 vs 脚底 CoP 预算

必须区分两个量：

```text
髋关节力矩能力
  hip/0 可用约 800N·m
  人体最大髋外展约 100N·m 量级

髋力矩能转化成多少地面反力
  受脚掌 CoP 限制
  τ_ground ≈ N · CoP_margin
```

当前：

```text
N ≈ 550N
footHalf ≈ 3.8cm
reserve ≈ 0.6

budget ≈ 0.6 × 550 × 0.038 ≈ 12.5N·m
```

所以：

```text
10N·m 是 CoP 允许髋使用的“地面反力矩”
不是髋关节只能出 10N·m
```

论文：

```text
Neumann 2010   髋外展肌能力
Horak 1986     髋策略
Caron 2019     接触约束 N/CoP
Hof 2005       动态稳定边界
```

## 16. 初始预紧 / 主动刚度

当前释放瞬间：

```text
F_des ≈ 10N
hip/0 tau ≈ 1.6~2.1N·m
budget ≈ 9.9~10.4N·m
```

问题：

```text
预算有约 10N·m
实际只用 1.6~2.1N·m
初始 COM 误差≈0
髋没有预紧
```

也就是：

```text
初始状态的髋像没有主动刚度的被动关节
等误差出现才开始出力
```

正确行为：

```text
释放时先建立主动预紧
类似被动刚度，但由髋主动实现
```

建议：

```text
τ_pre = preloadFrac · budget

preloadFrac 默认 0.2~0.3
高风险 onset/TTB 时可到 0.4
```

作用：

```text
先建立髋的抵抗刚度
扰动来时不用等误差
但预紧不能造成侧向漂移
```

验收：

```text
释放后 0~100ms
hip tau 已达到 budget 的 20~30%
comZ 不漂
N/CoP 不越界
```

## 17. 侧向回正 = 支撑选择 + 卸载 + 髋外展

侧向回正不是“两边髋同时硬顶”。

完整策略：

```text
1. 读 XCoM/COM 方向
2. 选支撑侧
3. 把负载转移到支撑侧
4. 卸载另一侧
5. 支撑侧髋外展
6. 脚底 CoP 偏移
7. 地面反力推 COM
```

### 17.1 支撑侧选择

输入：

```text
xcomZ
comVelZ
fzL / fzR
CoP margin L/R
TTB / confidence
```

规则：

```text
优先选 CoP 余量大、fz 足够的一侧
如果 XCoM 已明显偏向一侧，支撑侧优先选该侧
带滞回，避免左右来回切
```

状态：

```text
support = 'l' | 'r' | 'both'
```

### 17.2 卸载

```text
targetLoadSupport ≈ 0.65~0.75
targetLoadOther   ≈ 0.25~0.35
```

通过：

```text
骨盆目标偏移
髋 common/diff
脚底 CoP 目标
```

实现，不是直接写 N。

### 17.3 髋外展

```text
支撑侧 hip/0 主导
非支撑侧 hip/0 辅助/卸载
```

左右不再固定 `+τ/-τ`。

```text
τ_support = common + diff
τ_other   = common - diff
```

其中权重由支撑侧、N、CoP margin 决定。

### 17.4 预算

```text
支撑侧优先拿 CoP 预算
非支撑侧只保留稳定/接触预算
```

并且：

```text
N > 0
CoP 不越界
不能为了卸载把脚抬离
```

### 17.5 禁止

```text
双支撑平均承重
两边髋同时等幅硬顶
不选支撑侧
不卸载摆动侧
```

### 17.6 当前代码

```text
HipTaskPD：已加入 support='l'|'r'|'both'
已加入负载目标：
  support 侧 65~75%
  other   侧 25~35%
common/diff 已分左右
```

仍不稳定：

```text
fall≈0.89
```

下一步是调支撑侧滞回、卸载速度和 diff 增益。

### 17.7 论文

```text
Horak & Nashner 1986   hip strategy 是大扰动策略
Winter 1995/1998       load/unload 是髋策略一部分
Mirshams 2020          stance limb hip 产生脚底剪切力
Neumann 2010           髋外展肌控制骨盆侧倾
Caron 2019             CoP/N 约束
```

## 18. 人蹲下为什么稳

不是姿势问题。

人蹲下稳，靠的是：

```text
双脚固定
BOS 大
左右脚共同承重
髋-膝-踝协同
关节主动刚度/阻尼
CoP 在脚掌内
COM 在双脚之间
```

不是靠一个很小的 hip/0 力矩硬顶。

## 19. 当前回正力为什么小

```text
footHalf ≈ 3.8cm
copUse = 0.35
ankleShare = 0.4
hipReserve = 0.6
```

预算被多层切碎：

```text
3.8cm × 0.35 = 1.33cm
再 × 0.4 = 0.53cm
```

实际侧向力：

```text
F_lat = N·ΔCoP/h
≈ 500 × 0.01 / 0.5
≈ 10N
```

而人体能用接近整个脚掌/双脚 BOS，配合髋/膝/踝和姿态刚度。

不是人蹲下脆弱，是我们的权限分配太碎。

## 20. 应该怎么做

```text
1. 不做固定 60/40 预留
2. 先保证双脚 N 和脚掌接触
3. CoP 预算按当前威胁动态分配
4. 踝先用，饱和后再给髋
5. 髋力矩必须真的产生地面反力
6. 不用时立即把预算还给踝
7. 双支撑优先，不轻易卸载
```

不是：

```text
固定预留 60% 给髋
髋不用
踝只剩 40%
最后谁都没力
```

## 21. 验收

```text
踝用到脚掌可用 CoP
髋用到 N·CoP 预算
双脚 N > 0
support 和实际承重侧一致
fall 明显晚于当前
```
