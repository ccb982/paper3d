# 写手收敛：从 10 个写手到 2 个（2026-10-26）

> 本文是 `docs/蹲下新架构-2026-10-26.md`（实测校准）与 `docs/最终架构-蹲姿回正.md`（论文版）的**实现口径**。
> 目标口径一个都不改：永久蹲下、脚不发滑、上身不出可控域、世界/重力相对不变量。
> 改的只有一件：**谁来写这一帧的关节力矩**。
>
> 硬约束（沿用旧文档，不撤销）：
> 1. 「别乱加写手，我只想让你修正已有写手」——**本文的产线写手数是 2，比现在的 10 少。**
> 2. 「无论是髋还是背肌、脊柱的调整，都要脚发力传到上身」——上身预算由地面反力余量决定，不许凭空写。

---

## 0. 一句话结论

现在的问题**不是**"写手太多在打架"，而是：

> **一个关节力矩有三条并联通路，一个钳位；同一物理量（侧向 CoP 目标）有两个写手，其中一个把另一个整段丢掉；躯干每一轴被两条定律并联且永不仲裁；另外 18 个写手躺在 env 分支里随时能复活。**

所以"收敛"不是删功能，是**把写手从"各自发明一个增量"改成"共用一个求解器的输出"**：
10 个活写手 + 18 个死写手 → **2 个活写手 + 0 个死写手**。

## 1. 现状：一个力矩，三条通路，一个钳位

### 1.1 三条通路（这是所有"写手打架"的物理基础）

`proposalBus` 收到提案后，`control.ts:222-229` 按 `` `${dof}|${kind}|${channel}` `` 仲裁，`control.ts:247-268` 分派：

| kind | 落点 | 累加语义 | 谁在用（squat hold） |
|---|---|---|---|
| `pair` | `executor.commandPair` → `pairBank` 配 `(c, ref, base)` | **不产生力矩**，只配置执行器 | `squat.pairBase` |
| `ext` | `executor.addTorque` → `l.cmd += τ` | **相加，无上限** | `squat.ankleVec`、`passiveLock.*`、`hipTwistLock`、`kneeTwistLock`、`swingKnee` |
| `torque` | `drive.setTorque` → `this.ff[i] = τ` | **覆盖（赋值）** | `supportClean.arm`、`stability` 的 `tension` |

然后在 `executor.applyAll`（`executor.ts:169-227`）里三者汇成一个标量：

```text
l.pair = pairTorque(pairBank)                    // 执行器内部自己算（executor.ts:186-202）
t      = l.cmd + l.pair                          // ← ext + torque + pair 全在这里相加
t      = clamp(t, ±τmax)                         // ← 唯一一次饱和
t     += clamp(l.passive, ±τmax)
imp    = t·dt + clamp(l.limit, ±impulseMax)
```

**结论**：`ext` / `torque` / `pair` 之间**永不仲裁**，它们只是同一个 `t` 的三个加数。
仲裁只在**同一 kind** 内部生效。所以"加一种 kind"就等于"多开一条并联通路"——这是写手数失控的结构性原因，不是纪律问题。

## 2. 六个病根（带行号）

### P1（最严重）侧向 CoP 目标有两个写手，后者把前者整段丢掉

**前者（对的）** `squat.ts:206-225`——真正的 DCM 律，而且已经是论文形式：

```ts
const omega = Math.sqrt(9.81 / com.y);                                  // ≈3.19
const rawZ  = (1 + lambdaCp / omega) * (com.z + comVel.z / omega - c0.z);  // = (1+λ/ω)·Δξ
// 逐脚 ±zLimAlloc(9cm) 钳位，再按 fz 权重做 3 次重分配 ⇒ zAlloc{l,r}
```

这正是 Caron 2019 的 `Δz = kp·Δξ`（`kp = 1 + λ/ω`，λ=1 ⇒ 闭环极点 `−λ·ω`，时间常数 0.31 s）。

**后者（错的）** `squat.ts:289`：

```ts
targetZ = servoOn ? ankZ + servoCop : zAlloc[side];
```

`servoOn` 取决于 `ctl.lateralServo.active`，而 `lateralServo.ts` 的 `postCop` 分支**先跑且直接 return**：

```ts
const postCop = Math.abs(eRoll) > postDead
  ? clamp(postK * eRoll, ±0.006)      // postDead = 0.3°，postK = 0.15，钳位 ±6mm
  : 0;
if (postCop !== 0 && !this.armed) {
  this.copReq += ...; this.active = true; this.phase = 'pushBrake';
  return;                              // ← 真的 CP 环永不执行（它要求 armed，squat 永远不 armed）
}
```

**后果链**（全部实测）：

* `comZ = +39 mm, comVelZ = +21 mm/s` ⇒ 应给正向修正，实际 `copReq = −6 mm`（**符号是反的**）。
* `Mx = rollSign · rollK · fz · (targetZ − cop)`（`squat.ts:311`），`rollK=0.9`、`fz≈430`、`targetZ−cop≈6mm`
  ⇒ `Mx ≈ 2.3 N·m`。实测 `Mdes[0] = 2~11`，其中 **≈+6.4 是 `SQC_MUSCLE_F=-230` 的常值前馈**（`musclePreMoment`），
  也就是说**踝侧向力矩有一多半是一个开环常值偏置**。
* `SQC_COP_Z_LIMIT 0.09→0.15` **零变化**（3.98 s 逐位相同）——因为 9cm 的钳位根本不在生效路径上。
* `SQC_LAT_SERVO_POST_ROLL=0`（杀掉 postCop ⇒ `servoOn=false` ⇒ 退回 `zAlloc`）是**单变量最大收益**：
  **3.98 → 4.84 s，roll 峰值 51°→24°**。

> 这一条同时解释了"侧向权限是硬约束"和"调 `SQC_COP_Z_LIMIT` 没用"两个旧结论：
> **权限不是不够，是根本没接上。** 理论上的 ±9cm 被一个 ±6mm 的遗留分支短路了。

### P5 `base` 与 `PD` 塞进同一个字段

`squat.ts:80-90`：

```ts
let base = baseBuf[d.dofIndex] ?? 0;      // 释放瞬间的静态支撑快照（冻结）
```

## 3. 文献：为什么"少而聚合"在原理上是对的

### 3.1 平衡只需要 6 个状态量（CMM）

Orin & Goswami 2008（Centroidal Momentum Matrix）证明：自由漂浮人形的全部广义速度可以**线性**映射到质心处的 6 维动量
`h = H_G(q)·q̇`，且 `ḣ = Σᵢ [fᵢ; (pᵢ−p_G)×fᵢ] + [m·g; 0]`。
Herzog et al. 2016（Auton. Robots 40(3):473-491）把这条直接写进分层逆动力学的最高优先级任务，
并明确指出收益是「**减少开环参数个数**」——因为动量耦合是**显式**处理的，不用每个关节各调一套。

> 对本项目的意义：**L0 只需要一个状态向量**（`com, comVel, L, Ldot, cop, fz`），
> 现在散在 `ctl.sensors` / `ctl.perception` / `ctl.lateral.state` / `ctl.lateral.parts` / `squatDynamicSupport` 五处的读数必须合并。
> 五个读数源 ⇒ 五套符号约定 ⇒ 五处可以各自"看起来对"。

### 3.2 任务要有严格优先级，不是加权求和

Sentis & Khatib 2005（behavioural primitives + null-space projection）、Escande/Mansard/Wieber 2014、Saab et al. 2013（HQP active-set）：
低优先级任务必须在高优先级任务的**零空间**里求解，加权求和会被"一个软约束的小权重"污染关键任务（Herzog 2016 摘要原话）。

> 对本项目的意义：`T1 直立 → T2 支撑矩 → T3 平衡` 必须**逐级扣预算**（`resid = req − used`），
> 不是三条定律各写各的然后相加（现在就是相加）。

### 3.3 DCM 的反馈律就是一行 P（+I）

Caron 2019（Biped Stabilization by Linear Feedback of the VHIP, arXiv:1909.07732）：
令 `Δξ̇ = ω₀(Δξ − Δz)`，要求 `Δξ̇ = (1−k_p)·ω₀·Δξ` ⇒ **`Δz = kₚ·Δξ`**，
「An integral term can also be added to eliminate steady-state error」。

同一篇给出了本项目最关键的一句话：

> 「As long as the eCMP is feasible … it achieves optimal closed-loop dynamics. When the corresponding ZMP falls outside of the support area, **it is projected back to it and closed-loop pole placement is not guaranteed any more**.」

——**支持域外只能投影回退，理论保证失效。** 这就是 `probe-push` 量到的"侧向被动只有 ±0.070 m，是主动域的 26%"。

它还给出了第三条策略：**VHIP —— 即使 ZMP 顶在边界，仍然可以通过改变高度来平衡。**
蹲姿的高度本来就是自由量 ⇒ **CoP 饱和时降高度（蹲更深）是一个有理论依据的兜底**，而现在的代码没有任何地方用它。

### 3.4 支撑矩是可加的：`Ms = M_hip + M_knee + M_ankle`

Winter 1995（Gait & Posture 3:193-214）：站立/行走中下肢三关节的伸展力矩之和 `Ms` 与地面反力对质心的力矩一致；
深蹲的定性规律是**髋贡献最大、膝随深度上升、踝在负重时上升**。

> 对本项目的意义：**分配器（allocator）有严格的物理定义**，不是"我发明一个混合比"。
> `Ms_req` 是唯一需求，`(Mh, Mk, Ma)` 是它的一个分解 ⇒ 分配器只需要决定"分解比例"，不需要每条腿各调一套 PID。

### 3.5 踝优先，饱和后髋接管

Horak & Nashner 1986（J Neurophysiol 55:1369-1381）：支撑面缩小/扰动变大时，人从**踝策略**切到**髋策略**
（近端发力、躯干作为反作用质量）。Pratt et al. 2006 给出 capture point 与三策略的代数触发条件。

> 对本项目的意义：**远端起效、近端兜底**是生物学的顺序，也是唯一的顺序——
> 因为 `ΔCoP ≈ τ/Fz` 意味着踝是唯一能直接移动 CoP 的关节；髋只能靠角动量"借"。

### 3.6 肌肉协同：少数固定混合比

d'Avella, Saltiel, Bizzi 2003（Nat Neurosci）：自然动作由少数肌协同按固定权重线性叠加。
Asai et al. 2009 把同一框架用到 sit-to-stand，得到个位数的协同数。

> 对本项目的意义：**分配器的 `κ_knee` / `κ_hip` 应该是常数表**，不是每帧最优化。
> 这直接否掉了"引入 QP 求解器"的必要性。

### 3.7 平衡点假说：执行器本来就只要两个输入

Feldman 1966 / Hogan 1984（λ 模型）。项目自己的 `musclePair.ts` 头注释已经写了这条，
并且已经把它实现成 `(c, ref)`——**共激活调刚度、`ref` 调平衡点**。

> 对本项目的意义：**收敛后的分配器输出恰好就是 `(c, ref)` 两维**，
> 不需要新执行器通路、不需要改 `executor` 的物理。这是"零新增写手"能成立的数学原因。

### 3.8 论文 → 本项目决策对照

| 结论 | 来源 | 落到哪 |
|---|---|---|
| 平衡只需 6 维动量状态 | Orin & Goswami 2008；Herzog 2016 | `StanceState`（L0），合并 5 个读数源 |
| 严格优先级 / 零空间 | Sentis & Khatib 2005；Escande 2014 | `solveTasks` 逐级扣预算（L1） |
| `Δz = kp·Δξ (+I)`，域外投影 | Caron 2019 | 已经在 `squat.ts:207`，**要接上电**（P1） |
| CoP 饱和 → 改高度 | Caron 2019（VHIP） | 新增兜底分支（蹲更深），L1 内部 |
| `Ms = Mh+Mk+Ma` | Winter 1995 | `allocate()` 的定义（L2） |
| 踝先 / 髋后 | Horak & Nashner 1986 | `allocate()` 的顺序（L2） |
| 少数固定协同比 | d'Avella 2003；Asai 2009 | `κ` 常数表，不做在线优化 |
| `(c, ref)` 两个控制量 | Feldman 1966；Hogan 1984 | `toPairCommand()`（L3） |

## 4. 新架构：3 层计算 + 2 个写手

```text
                 ┌─────────────────────────────────────────────┐
                 │ L0  StanceState —— 一帧读一次（唯一读数入口） │
                 │  com[3] comVel[3] ξ[2] L[3] Ldot[3]          │
                 │  copL/copR  fzL/fzR  polyL/polyR             │
                 │  trunkPitch/Roll  q[]  qd[]                  │
                 └───────────────────┬─────────────────────────┘
                                     │  只读，不写关节
                 ┌───────────────────▼─────────────────────────┐
                 │ L1  solveTasks —— 3 条任务，严格优先级        │
                 │  T1 支撑矩  msReq = msStatic(st)             │
                 │  T2 CoP     copDes = clamp(poly, nom+kpΔξ+kiI)│
                 │             sat? → VHIP 降高度               │
                 │  T3 躯干    tauTrunk = PD(world tilt)        │
                 │             cap = 地面反力余量               │
                 └───────────────────┬─────────────────────────┘
                                     │  输出「想要多少」，仍不写关节
                 ┌───────────────────▼─────────────────────────┐
                 │ L2  allocate —— 收敛点（纯代数，无 propose）  │
                 │  Ms_req ──┬─ τa = clamp(±τaCap)    远端优先   │
                 │           ├─ r = Ms−τa                        │
                 │           ├─ τk = clamp(κk·r, ±τkCap) 协同比  │
                 │           └─ τh = r−τk              近端兜底   │
                 │  左右按 fz 权重；ΔCoP=τ/fz 换算避免虚权限     │
                 └───────────────────┬─────────────────────────┘
                                     │  (c, ref) 两个数
     ┌───────────────────────────────┴──────────────────────────┐
     │ L3  只有 2 个写手                                          │
     │   stance.legs   hip/knee/foot × 9 轴/侧  （矢状 pair，侧/扭 ext）│
     │   stance.upper  spine1-4 / neck / 肩 / 肘  （torque，每帧 1 次）│
     └───────────────────────────────┬──────────────────────────┘
                                     │
                 ┌───────────────────▼─────────────────────────┐
                 │ L4  执行器（完全不动）                        │
                 │  t = clamp(l.cmd + l.pair, ±τmax) + passive  │
                 │  + limit 冲量 → 等大反向力偶                  │
                 └─────────────────────────────────────────────┘
```

### 4.1 写手归属表（目标：每 DoF 恰好 1 个 owner）

| DoF 轴 | owner | 通路 | 说明 |
|---|---|---|---|
| hip 轴 2（屈伸） | `stance.legs` | pair | 力矩 → 反解 `ref`；不再有冻结 base 之外的第二个 PD |
| hip 轴 0（外展） | `stance.legs` | ext | 由 L2 给出，**不再被 knee/1 门控** |
| hip 轴 1（旋转） | `stance.legs` | ext | 姿态保持，小 cap |
| knee 轴 2 | `stance.legs` | pair | 力矩 → `ref` |
| knee 轴 0/1 | `stance.legs` | ext | 姿态保持，小 cap |
| foot 轴 0/1/2 | `stance.legs` | ext | 保留 `mapMomentToAxes`，但 `targetZ` 只有一个来源 |
| spine1-4 轴 2 | `stance.upper` | pair | 力矩 → `ref` |
| spine1-4 轴 0/1 | `stance.upper` | ext | 单一 PD |
| neck / 肩 / 肘 | `stance.upper` | torque | **每帧 1 次**，`ARM_AXES` 去重 |
| 限位 / 被动阻尼 | —（不进总线） | — | 属执行器 `passive` / `limit` 桶 |

### 4.2 L2 的公式（可直接抄进代码）

```ts
// ① 支撑矩需求：沿用已验证口径（squatDynamicSupport 的符号，与 base 对账一致）
const msReq: [number, number] = [msStar[0], msStar[1]];   // [横滚轴, 俯仰轴]

// ② CoP 目标（DCM PI，Caron 2019）
const omega = Math.sqrt(G / Math.max(0.3, st.com[1]));
const xi    = [st.com[0] + st.comVel[0] / omega, st.com[2] + st.comVel[2] / omega];
const xiRef = [st.c0x, st.c0z];
const Iint  = integrator.step(xiRef, xi, dt);              // 带抗饱和
const dCop  = [kpDcm * (xiRef[0] - xi[0]) + kiDcm * Iint[0],
               kpDcm * (xiRef[1] - xi[1]) + kiDcm * Iint[1]];
const copDes = clampToPolygon(nomCop, add(dCop));          // sat 时置标志

// ③ 分配（Winter 1995 叠加；Horak & Nashner 1986 顺序）
const wL = st.fzL / Math.max(1e-6, st.fzL + st.fzR);
for (const [side, w] of [['l', wL], ['r', 1 - wL]]) {
  const ms = { x: msReq[0] * w, z: msReq[1] * w };
  const ta = clamp(solveAnkle(ms.x, ms.z, st.copOf(side)), ±KA * TAU_ANKLE_MAX);
  const r  = sub(ms, ta);
  const tk = clamp(mul(r, KAPPA_KNEE), ±TAU_KNEE_MAX);     // KAPPA_KNEE = 常数
  const th = sub(r, tk);                                   // 近端兜底
  out.set(side, { foot: ta, knee: tk, hip: th });
}

// ④ 力矩 → pair 的 (c, ref)（Feldman 平衡点假说）
//    τ = (kp·(ref−θ) − kd·ω)·sgn + base,  kp = min(2c·ks, 0.5·4I/dt²)
const c   = clamp(Math.abs(tau) / (2 * f0 * MARGIN), cMin, cMax);
const kp  = Math.min(2 * c * ks, 0.5 * 4 * I / (dt * dt));
const kd  = Math.min(2 * c * bs, 0.8 * 2 * I / dt);
const ref = theta + ((tau - base) / sgn + kd * omega_i) / kp;
```

**为什么这不算"新增写手"**：`(c, ref)` 是 `pair` 通路**已经存在**的两个输入（`squat.ts:95` 就在传），
`L2` 是一个**不调用 `propose` 的纯函数**。写手数从 10 减到 2。

### 4.3 上身的预算约束（硬约束 2 的落地方式）

`stance.upper` 的 cap **不是常数**，而是双腿用剩的余量：

```text
budget = |msReq| − Σ|τa| − Σ|τk| − Σ|τh|      // 地面还能承接多少反作用
tauTrunkCap = clamp(budget * KAPPA_TRUNK, 0, TRUNK_CAP_MAX)
```

地面没余量 ⇒ 上身躯干不许扭。这同时消掉了 P2 里"两条定律并联"的问题：
躯干只有一个定律，且它的权限由腿的余量显式给出，不再靠两套 K 相互抵消。

## 8. 不做的事（边界）

1. **不引入 QP / 优化求解器库。** `package.json` 只有 `rapier3d` + `three`；
   3.6 节的协同比论证说明固定混合比够用。WBC 那一套（TSID/HOQP）是为 30+ DoF 多接触准备的，
   这里单支撑面、双接触点，代数解足够。
2. **不改执行器的物理。** `applyAll` 的"求和→饱和→等大反向力偶"是对的，问题全在它上游。
3. **不新增派发通路。** 不加第 4 个 kind。写手收敛之后，"同 DoF 多 kind"应当恒为 0。
4. **不做步态。** 蹲→起立是 `docs/起立新架构-2026-10-26.md` 的范围，本刀不碰。
5. **不动站立/行走的 `supportClean` 分支。** 只切 squat。
6. **不靠调 `SQB_SCALE` / `SQ_PAIR_KS` 之类增益来"达成" §7。**
   单变量实测已经证明：`SQB_SCALE 0.9/1.1` ⇒ 4.27/4.05，`pairKs=600` ⇒ 4.62，`BS=30` ⇒ 2.21（崩）。
   增益能买到的最多是 0.6 s，而 D 一步（拆 P1）就是 0.86 s，且方向正确。
