# 蹲下支撑架构 v3（2026-10-27）

> 本文只定义**新的支撑架构**，不继承旧文里的固定法庭目标、主动侧向回正和混在一起的 base/PD。
>
> 一句话：
>
> **矢状面用 pairPD + 前馈支撑；正面只靠被动刚度；现在不做主动侧向回正。**
>
> 当前实现仍是原型，文中明确区分「已实现」「目标」「未做」。

## 0. 三个硬约束

1. **法庭姿态只是初始条件，不是伺服目标。**
   释放后不冻结、不重捕成固定 ref；动作自己找平衡。
2. **支撑力和回正力分账。**
   前馈只托住重力/GRF，不负责把身体拉回某个姿势。
3. **现在只做矢状支撑。**
   不做主动侧向回正、不做横向 CoP 闭环；正面稳定只靠被动刚度、脚间距和支撑面。

## 1. 平面拆分

| 平面 | 允许的力 | 不允许的力 |
|---|---|---|
| 矢状面 | pairPD、基础前馈、踝矢状前馈、关节软限位 | 用横向误差去改矢状 PD |
| 正面 | 被动刚度、软限位、脚/踝被动侧向 | 主动 hip0 回正、横向 CoP 闭环 |
| 扭转 | 软限位/阻尼 | 用矢状力矩硬拧 |

膝和髋的主动力只走矢状轴：

```text
hip/2   屈伸
knee/2  屈伸
spine/2 前后
```

横向只保留：

```text
hip/0   外展/内收    被动刚度 + 软限位
hip/1   内外旋       软限位
knee/0  侧向被动     软限位
foot/0  内外翻       被动刚度/软限位
```

**pairPD 不写 axis 0/1；base 不写 axis 0/1。**

## 2. 支撑前馈（只给范围，不给姿势）

### 2.1 垂直支撑

```text
N_L + N_R = W
初始：N_L = N_R = W/2
之后：按实际 fz 或负载分配，但不再追固定 CoM 目标
```

每只脚：

```text
0 ≤ N_i ≤ W
CoP_i 钳在脚掌支撑区内
fz_i < 阈值 ⇒ 该腿前馈 = 0
```

### 2.2 踝矢状前馈

```text
CoP_target = clamp(comX, ankleX − footHalf, ankleX + footHalf)
τ_ankle_ff = −Fz · (CoP_target − ankleX)
```

这是当前 `squatAnkleFeedforward` 的口径：

```text
cap = 80 N·m
只在脚承重时出力
不读目标角
```

### 2.3 髋/膝矢状前馈

用当前姿势 + 实际 GRF，不用固定 base 表：

```text
τ_j = − Σ m_b·g·(x_b − x_j)
       − N_i·(CoP_i − x_j)
```

- `j` = hip/2、knee/2
- `N_i` = 该脚实际法向力，不是固定 `W/2`
- `CoP_i` = 实际/钳位后的纵向 CoP
- 只取矢状分量；横向投影丢弃
- 结果限制在关节 `tauMax` 和标定 cap 内

**初始对称：**

```text
τ_L = τ_R = (τ_L_raw + τ_R_raw) / 2
左右镜像符号
```

这一步保证法庭第一帧没有净侧向力矩。

## 3. pairPD 的定位

pairPD 是**矢状姿势/硬度执行器**，不是支撑前馈。

```text
τ_pair = kp·(ref − θ) − kd·ω + base
```

本架构规定：

- 只用于 hip/2、knee/2、spine/2 等矢状轴
- `base` 是前馈支撑分量
- `ref` 不冻结成法庭角，也不在释放瞬间重捕成塌腿角
- `kp` 低、`kd` 足够；ref 只作范围中心/慢参考
- `ref` 不参与横向
- pairPD 与支撑前馈分开记账，避免“既托又拉”

若只做纯支撑：

```text
kp ≈ 0
base = τ_ff
pair 仅作为执行器
```

## 4. 被动刚度（正面）

只在关节超出中性死区后出力，不追 CoM：

```text
τ_lat = −K·(θ − θ_rest) − B·ω
```

要求：

- 只写 hip/0、hip/1、knee/0、foot/0，以及 spine1-3 的 0/1
- 承重腿才生效
- `θ_rest` 用中性/慢参考，不用法庭固定目标
- `K/B` 有 cap，不能变成主动侧向回正
- 不读 comZ/CoPz 做闭环

脊柱被动刚度（`squatSpinePassive`）：

```text
spine1-3 轴 0/1
K=200 N·m/rad，B=6，cap=30 N·m，死区 0.5°
rest=0，不读 CoM
```

当前软限位：

```text
hip/0 ±20°，K=30，B=3，cap=25 N·m
hip/1 ±15°
```

这是安全边界，不是支撑力。

## 5. 法庭流程

1. 运动学摆蹲姿
2. 脚掌放平/贴地
3. 静置期开重力 + 满驱动预载（`SQC_GONS=1`、`SQC_LIVE=1`）
4. 释放时保持预载，不把 output/gravity 拉回 0
5. 释放后：
   - 不重捕成固定目标
   - 不做主动侧向回正
   - 只跑矢状 pairPD + 前馈 + 被动刚度

**当前已知问题：** `captureSquatBase()` 在释放时会重捕；`baseAng` 可能从 setup 的 ±15° 变成当前塌腿角。新架构要求：**前馈可以用当前姿势，但 lateral/ref 不能被塌腿角覆盖。**

## 11. 2026-10-28 下盘软限位（重做口径）

蹲下下盘已经稳定，因此下盘目标改为：

```text
膝竖直
髋水平
脚抓地
```

但**不使用硬关节限位**（`joint.setLimits` 会造成冲击/卡死/力链中断）。改用：

```text
大力矩软限位 + 强回正
```

### 11.1 两条腿独立发力

```text
共享任务：
  CoM / 躯干 / 总 CoP

左右腿各自：
  自己的 fz
  自己的 CoP
  自己的 hip/knee/ankle 力矩
```

一侧饱和时另一侧接管，但禁止用髋单独替代脚。

### 11.2 软限位定律

```text
band = 允许的几何死区

if |e| <= band:
    τ = 0

if |e| > band:
    τ = -K·(e - sign·band) - B·ω
    限幅到人体关节量级
    只在承重腿生效
```

特点：

```text
不是硬限位，不锁死角度
不是位置目标，不把腿拉回某个固定姿势
超过几何带才强回正
```

### 11.3 轴与目标

```text
髋水平：
  hip/0 差动（左右和）
  目标：骨盆/髋线水平，不是单侧 0°

膝竖直：
  knee 额状轴（jointPlane: knee/1）
  目标：膝在踝正上方/小腿竖直

脚抓地：
  foot/0 只做小被动/软限位
  主抓地由 CoP 和踝矢状承担
```

### 11.4 力矩预算

```text
K/B 可以大，但必须：
  - 承重腿才写
  - 每轴有 cap
  - 先有脚 CoP/摩擦预算
  - 左右独立，不共享一个 hip2 力矩
```

### 11.5 当前状态

```text
squatHipSoftLimit 只是安全软限位（hip0 ±20、hip1 ±15）
不是“膝竖直/髋水平”的强回正
需要新增下盘软限位控制器，而不是继续加硬 setLimits
```

## 12. 2026-10-28 下身回正：CoM 主目标，关节角作参考带

### 12.1 分工

```text
CoM / XCoM / comAcc → 回正主目标
关节角             → 参考带/约束，不是主目标
脚 fz/CoP          → 唯一外部力入口
```

蹲下时下盘应该“基本不动”，但**不是把关节角锁死**：

```text
关节角在窄带内：不追角度，只做 CoM 回正
关节角超出窄带：软限位/强回正
```

### 12.2 下盘两条独立通道

```text
矢状：
  hip/2、knee/2、foot/2
  目标来自脚位/基础姿态
  由 CoMx/XCoM 决定支撑量

侧向：
  hip/0、knee/1、foot/0
  目标：髋线水平、膝竖直、脚抓地
  由 CoMz/XCoM 决定左右脚 fz/CoP
```

左右腿各自有自己的：

```text
fz 目标
CoP 余量
hip/knee/ankle 力矩上限
```

共享的只有：

```text
CoM / 躯干 / 总 CoP
```

### 12.3 方向优先于大小

```text
hip/0 = 额状（外展/内收）
hip/1 = 扭转
hip/2 = 矢状
knee/0 = 扭转
knee/1 = 额状
knee/2 = 矢状
foot/0 = 额状
foot/2 = 矢状
```

侧向倒时主要用：

```text
hip/0 + knee/1 + foot/0
```

不是只加 hip/2、knee/2；方向不对时加大力矩只会更差。

### 12.4 力矩

人体量级：

```text
髋伸 ≈ 2~4 N·m/kg
膝伸 ≈ 2~3 N·m/kg
踝跖屈 ≈ 1.5~2.5 N·m/kg
髋外展 ≈ 1~2 N·m/kg
```

当前实测：

```text
hip2 ≈ 50~90 N·m
knee2 ≈ 30~80 N·m
foot0 ≈ 2~3 N·m
```

明显低于人体；但不能只加 cap，必须先确认：

```text
方向正确
脚 fz/CoP 接得住
关节角没有越出窄带
```

### 12.5 当前实现顺序

```text
1. 先标定 hip/knee/foot 的物理轴方向
2. 只做 CoM 侧向回正，不经角度主控
3. 再加关节角窄带约束
4. 最后加矢状 CoM 回正
```

现有 `squatLegRighting` 是角度主控实验版，默认关，不属于最终架构。


### 12.6 下盘关节角是扰动的第一触发源

不能只等 `comZ`：

```text
下盘关节角变化 / 角速度
→ 已经是扰动前兆
→ 应立即触发踝/膝/髋短促回正
```

每条腿独立：

```text
hip/0  髋线水平
knee/1 膝竖直
foot/0 抓地
```

触发量：

```text
e_joint = 关节角 − 参考带
v_joint = 关节角速度

trigger = max(|e_joint|/e0, |v_joint|/v0)
```

`trigger > 1`：

```text
短促 burst
踝 CoP 移动
膝/髋支撑增加
burst 后重新评估
```

约束：

```text
CoM 是目标/结果，不是唯一触发
脚 fz/CoP 仍是力入口
左右腿独立触发、独立预算
禁止 hip-only
```

## 13. 踝回正写手：关节力矩，不是直接力

### 13.1 写手层级

```text
写手：foot/0 关节力矩
目标：该脚 CoPz
结果：脚底接触产生 GRF
```

踝不能直接写“地面反力”；GRF 是接触的结果。控制器只能写踝关节力矩，CoP 是它和 Fz 的比值：

```text
τ_ankle ≈ -Fz · (CoP - ankleZ)
CoP ≈ ankleZ - τ_ankle / Fz
```

### 13.2 每只脚独立

```text
左脚：
  fz_L
  CoP_L 范围
  foot_L/0 符号
  K_L / cap_L
  burst/hysteresis_L

右脚：
  fz_R
  CoP_R 范围
  foot_R/0 符号
  K_R / cap_R
  burst/hysteresis_R
```

不能左右共用同一个误差、同一个符号、同一个增益。

### 13.3 论文口径

```text
Winter 1995        GRF/CoP 与踝力矩
Hof 2005/2008      站立方程/XCoM
Horak & Nashner 1986 踝策略
Loram & Lakie 2002   踝 intrinsic stiffness
Loram et al. 2005    间歇弹道式踝力矩
Peterka 2002         反馈延迟
Caron et al. 2019    多接触 CoP/contact wrench cone
Hyon 2006/2009       全身力分配
```

论文/机器人控制里通常是：

```text
任务层：CoM / CoP / GRF
低层：踝关节力矩或阻抗
```

不是直接写一股“地面力”。所以当前“写 foot/0 关节力矩”方向是对的；错在左右脚没有独立标定。
