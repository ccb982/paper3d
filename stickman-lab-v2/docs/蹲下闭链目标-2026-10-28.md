# 蹲下闭链目标架构（2026-10-28）

> 本文定义**蹲姿姿态目标的新来源**：不再是「关节角读数」，而是**从脚落点出发的闭链解**。
>
> 用户定调（2026-10-28）：
>
> > 「目标位置全用脚的落点算。蹲下的时候脚不可以再动了，
> > 知道脚的位置就能得到膝的位置和髋的位置。」
> > 「大腿的角度不定，但是有个大致的范围。重点看髋。」
>
> 实现：`src/core/servo/closedChain.ts`（只解算，不出力）
> 探针：`tools/_tmp-fullcalib.ts`（标定）、`tools/_tmp-chain-verify.ts`（验证）

---

## 0. 为什么要换目标来源

### 0.1 现状的问题

蹲姿回正力目前拿 `baseTable.squat.ang` 的目标角当 ref（经 `captureAngFrom` 覆盖成实测值）。实测发现：

```text
静止时  踝z=16.33cm  膝z=19.47cm  髋z=12.50cm
        膝盖外撇 3.15cm（相对踝）
        大腿偏内 6.97cm（相对膝）
但读数  knee_0 = −0.02°   hip_0 = +0.13°   foot_0 = +12.09°
```

**读数「归零」≠「几何垂直」** —— rest 姿态自带外八偏置（`body.ts` 的多环链 + `captureSquatBase` 的 `foot/axis≠2` 清零都掩盖了这一点）。

后果：把 `hip0/knee0/foot0` 目标设成 0，回正力会去拉一个**几何上并不竖直**的姿态。

### 0.2 闭链替代

```text
脚落点钉死（实测 3s 漂移仅 5~6mm）
    ↓
脚落点 + 胫骨长 + 股骨长  ⇒  膝、髋的世界位置被唯一确定
    ↓
目标 = 位置（不是角度）
```

与蹲深无关、与每次摆姿的差异无关——**唯一基准是脚**。

## 1. 目标定义

### 1.1 约束（全部从脚落点推）

| 约束 | 表达式 | 含义 |
|---|---|---|
| 膝盖竖直（额状） | `K*_z = A_z` | 膝盖不内扣不外撇 |
| 膝盖竖直（矢状） | `K*_x = A_x` | 胫骨在矢状面竖直 |
| 髋水平 | `H*_z = K*_z` | 大腿额向不偏（骨盆方正） |
| 大腿矢状角 | **自由** | 用户：'大腿的角度不定，但有个大致范围' |

`A` = 踝锚点（脚落点基准，捕获时固定），`K` = 膝锚点，`H` = 髋锚点。

### 1.2 为什么髋的矢状不约束

约束「胫骨矢状竖直」会要求 `hip_2` 转 **+30°**（实测）——远超「大致范围」。

所以矢状修正**限幅**（`SQC_CHAIN_SAG_MAX`，默认 ±8°），大腿角度由动作层决定，回正力只做小幅纠偏。

### 2.1 三条硬结论

**① 髋锚点完全不动**（`髋x/髋z` 恒 0）——髋的世界位置由**骨盆**决定，不由腿关节决定。

「髋水平」= 大腿额向不偏（`髋z−膝z=0`），承担者：

```text
hip_l/1（扭转轴）  ∂(髋z−膝z)/∂θ = +0.711 cm/deg   ← 主承担
hip_l/0（外展轴）  ∂(髋z−膝z)/∂θ = −0.155 cm/deg
```

⇒ **单靠 `hip_0` 拉不动髋水平**（实测需 45°，超行程）。必须用 `hip_1`。

**② 脚踝三轴对膝/髋全无影响**（全 0）——脚踝只影响踝锚点。

⇒ 踝是链的末端，**不能用来摆膝/髋**。之前"拉 `foot_0` 让髋水平"的路子从物理上就不成立。

**③ 矢状与额状耦合**：踝 roll 轴在世界系偏离竖直 29.2°（`[0.873,-0.488,0]`），
`hip_0` 的世界轴偏离纯 x 轴 27.7°。⇒ 跨平面混解会打架。

## 3. 求解结构

```text
每帧：
  读当前锚点 A / K / H（世界系）
  残差：
    rKz = (K*_z − K_z) − (A*_z − A_z)      Δ(膝z−踝z)
    rHz = (H*_z − H_z) − (K*_z − K_z)      Δ(髋z−膝z)
    rKx = (K*_x − K_x) − (A*_x − A_x)      Δ(膝x−踝x)
  雅可比（解析 a×(P−pivot)，子树感知，单位 m/rad）：
    额状  未知量 = hip_0, hip_1, knee_0, knee_1   约束 = [rKz, rHz]
    矢状  未知量 = hip_2, knee_2                   约束 = [rKx]（限幅 ±8°）
  阻尼最小范数最小二乘 → Δθ
  目标角 = 当前角 + Δθ（单次修正限幅 ±20°）
```

### 3.1 子树感知（解析雅可比的必要条件）

锚点钉在**父体**上：转该关节时锚点不动；转上游关节时锚点随父体走。

```text
膝锚宿主 = thigh  →  在 hip 子树内（随 hip 动）、不在 knee 子树内（不随 knee 动）✓
踝锚宿主 = shin   →  在 hip/knee 子树内、不在 foot 子树内 ✓
髋锚宿主 = torso  →  不在任何腿关节子树内 ⇒ 恒不动 ✓
```

（`anchorHostBody` = 关节的 `parentKey` 对应刚体；`movesWith` = 宿主是否 ∈ `body.subtree[joint]`）

### 3.2 分平面的理由

踝 roll 轴斜 29°、髋外展轴斜 28° ⇒ 矢状与额状的响应矩阵互相耦合。
分开解各自独立，物理上不打架。

## 5. 分层（不变的部分）

```text
基础力 = pair PD + 被动张力        ← 不动
回正力 = 软限位强回正              ← 消费本模块的目标角
```

本模块**只解算，不出力**：

- 不写 `executor`
- 不碰 `proposalBus`
- 不碰 `baseTable`（不覆盖 `ang` 表）

出力由回正力层接（下一步）。

## 6. API

```ts
import { captureClosedChainTarget, solveClosedChainAngles, closedChainAngle } from './servo/closedChain';

// 捕获（一次性）：脚落点已钉死、姿势已成形后
const tgt = captureClosedChainTarget(body);   // null = 段长异常

// 每帧重解
solveClosedChainAngles(body, tgt);

// 读目标角（给回正力层）
const ref = closedChainAngle(tgt, dofIndex);
```

|---|---|---|
| `SQC_CHAIN_SAG_MAX` | 8 | 矢状修正限幅（度）——保持大腿角度在"大致范围"内 |
