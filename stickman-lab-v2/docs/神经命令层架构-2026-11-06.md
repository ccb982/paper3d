## 8. 平衡余量与早期侧偏（新增定稿）

### 8.1 初始状态

```text
初始蹲姿是平衡的
正常人类蹲下的平衡余量很大
不是“已经偏了再救”
而是“每帧都不让它偏出去”
```

所以不能把侧向问题当成“末端救援”问题。

### 8.2 失败链

```text
初始平衡
→ 侧偏刚出现
→ 没有及时做负载转移 / hip0 / CoP 修正
→ XCoM 继续外移
→ CoP 余量耗尽
→ 到后期才加大回正
→ 已经超出支撑面，救不回来
```

### 8.3 正确时序

每一帧都要做：

```text
1. 读 CoM / XCoM / CoP
2. 读 fzL / fzR / 负载
3. 算支撑面余量
4. 算力链
5. 在余量还大时就开始修正
```

不是等：

```text
TTB 很小
或 |eLat| 很大
或已经出安全区
```

才开始回正。

### 8.4 分层动作

```text
余量充足：
  小修正
  负载微调
  hip0 / CoP 微调
  不打扰

余量开始下降：
  优先负载转移
  hip0 侧向
  foot0 抓地
  力链修正

余量接近边界：
  髋/踝已不够
  进入 change-in-support
  迈步 / 支撑改变
```

### 8.5 回正力不是越大越好

```text
回正力必须：
  早
  连续
  与偏差/速度成比例
  有余量时就开始
  不是等偏差大了才饱和输出
```

当前问题：

```text
早期修正不足
hip0 cap 太小/太晚
负载和 CoP 没有及时参与
等到侧偏严重时已无法恢复
```

### 8.6 每帧闭环

```text
每帧：
  更新平衡余量
  更新负载
  更新力链
  更新 hip0 / hipFf / CoP
  输出小修正或升级修正

不允许：
  只在 fall/threshold 时动作
  只靠 hip0 cap 硬救
  等 XCoM 出支撑面再处理
```

### 8.7 当前结论

```text
不是“侧偏严重时回正力不够”
是“侧偏刚开始时没有及时、连续地修正”
```

正常人类蹲姿余量很大，控制器应该每帧守住这个余量，而不是把它耗到只剩救援窗口。

## 10. 矢状回正：真正错误在力链回正方案

### 10.1 结论

```text
真正错误：
  矢状力链回正的实现

不是：
  PD
  td
  关节角本身
  小腿侧向
```

关节角回正不是主回正手段；它只应该在偏差小时接管。

### 10.2 正确职责

```text
偏差大 / 负载不均 / CoM 偏：
  先走力链回正
  决定谁支撑、谁卸载
  分配 FzL* / FzR*
  hipFf / legFf / hip2 下压

偏差小 / 力链已通 / CoM 稳：
  关节角回正
  hip2 回 IK 目标
```

### 10.3 支撑 / 卸载

```text
FzTotal = fzL + fzR

FzL* = FzTotal/2 + Δ
FzR* = FzTotal/2 − Δ

Δ 来自 CoM / CoP / eLoad
```

哪侧需要支撑：

```text
该侧 Fz* 升高
该侧 hip / leg 下压
另一侧卸载
```

不是左右各算一个 legFf 同时加力。

### 10.4 力链模式 / 关节角模式

```text
FORCE_CHAIN：
  大偏差
  负载 / CoM 优先
  hipFf / legFf 大力矩
  关节角只维持 IK
  不允许关节角抢主修正

JOINT_IK：
  偏差小
  力链已通
  hip2 回 IK
  小力矩
  不再继续大力链
```

切换：

```text
FORCE_CHAIN → JOINT_IK：
  负载差、CoM、fPerp 都进入小误差带

JOINT_IK → FORCE_CHAIN：
  负载差 / CoM / fPerp 超出大误差带

必须滞回，不能每帧切
```

### 10.5 当前实现的问题

```text
没有明确的 support / unload 角色
没有 FzTotal 的左右预算
legFf 每侧独立算
hip2TrackFf 和关节角修正同时存在
没有 FORCE_CHAIN / JOINT_IK 模式切换
```

当前不是论文里的 load/unload，而是：

```text
高度力 + 单侧 legFf + hip2 angle 修正
混在一起输出
```

## 12. 矢状 / 侧向回正的职责与轮流契约（2026-11-07 定稿）

### 12.1 职责不同

矢状回正（全身通道）：

```text
管：
  CoM 前后
  左右负载不均
  髋力链 / roll / posture
  全身"救回来"

出：
  hip0 / hip1 / hip2 目标
  hipFf
  knee2 的矢状修正

不负责：
  小腿抓地
  脚底局部 CoP / 力链细节
  踝（foot2）——只保力链 / 抓地，不参与矢状回正
```

矢状承重（高度环，常在线）：

```text
管：
  髋高 H*
  髋太高 → 削基础力（baseGate）
  髋太高 → 膝盖软一点（kneeHipFlex / knee2Support）

出：
  hipFf（高度力）
  relax / baseGate / kneeHipFlex / knee2Support

不出：
  hstar 关节目标（已删除）
  关节方向修正（交给矢状回正）
```

侧向回正（局部通道）：

```text
管：
  一条 active 小腿的抓地 / 力链
  小腿倾角、F_perp、CoP 在脚掌内

出：
  knee0 / foot0 目标（+ fade）

不负责：
  hip（任何轴）
  CoM
  全身负载分配
  矢状轴（knee2 / foot2）
  不"救全身"
```

说明：

```text
"矢状回正"是控制通道名，不是解剖平面名。
hip0 / hip1 虽然是侧向轴，但属于全身平衡 → 归矢状通道。
侧向通道永远不写 hip。
```

### 12.2 轮流契约

```text
mode ∈ { none, sagittal, lateralL, lateralR }

同一帧只有一个 mode
sagittal 与 lateral 不同时 active
lateralL / lateralR 不同时 active
base / support 永远在线，不受 mode 控制
调度器是唯一开关
命令层不得自行激活
```

禁止的旁路（本次已处理）：

```text
sagOn = scheduler.sagittalOn || !lateralGrip     ← 命令层自兜底，已删
lateralActiveNow = scheduler.lateralSide === s
                 || (shankSelSide === s && forceOn) ← 力链旁路，已删
```

抓地 / 力链不满足时：

```text
lateralReady = false
→ 调度器不进入侧向
→ 已在侧向则按 confirm + cooldown 退回 sagittal
→ 不在命令层里让两个回正同时运行
```

已知边界（必须承认）：

```text
lateral mode 期间 CoM / 髋回正暂停
  因为侧向层被禁止写 hip、禁止救全身
  只能靠 min_hold + confirm/cooldown 限制这个窗口
  不允许用"侧向层偷偷写 hip"来补
```

切换时序：

```text
min_hold 0.30s
confirm  0.10s
cooldown 0.10s
命令层 fade 0.08s（SQC_SAG_FADE_TC）
```

| 关节 / 轴 | sagittal mode | lateral mode | 常在线 |


### 12.5 验收


## 13. 髋回正：唯二任务（力链修正 + 关节角修正）

### 13.1 结论

髋只执行两个任务，没有第三个：

```text
① 力链修正（P0，force task）
   左右腿负载 / CoP / 力链
   成对输出，支撑侧加载、卸载侧卸载
   大权限，允许关节角暂时偏离 IK

② 关节角修正（P1，posture task）
   IK / 中立姿态 / roll / hipZ 姿态安全
   小权限，只在力链任务进入小误差带后接管
   在力链任务的零空间里工作，不抢主修正
```

说明：

```text
"姿态/roll 安全"属于任务②，不是第三个任务。
小腿侧向不是髋的任务：侧向层只保 fParallel/fPerp/CoP 力链，
                     不参与左右负载分配，也不写 hip。
```

### 13.2 设计

```text
输入：
  fzBudget.fzLTarget / fzRTarget    任务①的唯一左右负载目标
  CoM / XCoM / CoP / fzL / fzR      任务①的反馈
  ik.hip0/1/2、roll、hipZErr        任务②的目标/反馈
  baseFf / heightFf                 常在线，不属于髋的两个任务

任务① 力链修正：
  Δ = FzL* − FzR*
  supportSide = sign(Δ)
  输出成对力：
    support 侧  +F(Δ)
    unload  侧  −F(Δ)
  FzL* + FzR* ≈ W（总重不被力链任务改写）
  允许 hip/leg 关节角偏离 IK
  不允许左右各自独立算、独立饱和

任务② 关节角修正：
  输出 hip0/hip1/hip2 的小角度修正
  只在任务①的力误差/负载差/eLat 进入小误差带后生效
  力链模式中只维持 IK，不做主修正

调度（全局，不按侧）：
  mode ∈ { FORCE_CHAIN, JOINT_IK }
  同一帧两条腿只有一个 mode
  FORCE_CHAIN → JOINT_IK：力误差、eLoad、eLat 都进入小误差带并持续 T
  JOINT_IK → FORCE_CHAIN：大误差带 / CoP 出界 / 抓地失效，立即
  必须滞回 + fade（SQC_SAG_FADE_TC）
```

### 13.3 文献依据

```text
Horak & Nashner 1986, J Neurophysiol 55:1369-1381
  大扰动/短支撑面用 hip strategy：髋产生水平剪力，踝力矩很小；
  身体最终停在非直立位置 → 力/CoM 优先于关节角姿态。

Runge et al. 1999, Gait Posture 10:161-170
  快速扰动在踝力矩上叠加髋屈力矩；纯髋力矩（无踝/腿配合）未观察到
  → 力任务必须成对/多关节，不能只写一个 hip 轴。

Winter 1995, Gait Posture 3:193-214
Winter et al. 1996, J Neurophysiol 75:2334-2343
  并排站立 M/L 平衡 = hip load/unload；5% 垂直力 ≈ 1cm CoP
  → 左右负载必须是同一 Δ 驱动的一对反向量。

Weaver et al. 2017, J Biomech 53:90-96
  蹲、弯腰、站立三种姿势的 M/L 控制仍然是髋 load/unload
  → 蹲姿不能用 hip0 小角度目标当主回正。

Raibert & Craig 1981, ASME JDSMC 103:126-133
  混合位置/力控制：接触约束方向控力，自由方向控位置。

Khatib 1987；Sentis & Khatib 2010, IEEE TRO
  CoM/约束/力任务高优先级，posture 在零空间。

Romano et al. 2015, ICRA（iCub）
  全身平衡：force task 最高优先级，postural task 最低优先级。

Afschrift et al. 2016, J Neurophysiol
  踝/髋策略按机械代价切换，小扰动踝、大扰动髋
  → 用误差带 + 滞回切换，不用硬阈值逐帧翻。
```

### 13.4 当前实现为什么不对（逐帧证据）

`docs` 对应探针：squatCourtSetup，放开后每 0.02s，直到判倒。

```text
t=2.30  mode=sagittal  hipFade=0.99  roll=1.0°
        postureHip0=0.2°  loadHip0=0.2°  comHip0=0.0°  hip0Delta=0.4°
        hip0 applied=+155 N·m

t=2.40  mode=sagittal  hipFade=1.00  roll=2.0°
        postureHip0=0.4°  loadHip0=-0.0° comHip0=0.0°  hip0Delta=0.4°
        hip0 applied=+86 N·m

t=2.48  mode=sagittal  hipFade=1.00  roll=5.3°
        postureHip0=1.1°  loadHip0=0.0°  comHip0=0.0°  hip0Delta=1.1°
        hip0 applied=+69 N·m

t=2.54  mode=sagittal  hipFade=1.00  roll=8.5°
        postureHip0=1.8°  loadHip0=0.4°  comHip0=0.0°  hip0Delta=2.3°
        hip0 applied=+117 N·m
```

问题：

```text
1. mode=sagittal、hipFade=1 → 不是模式/淡出关掉回正。
2. roll 0→8.5°，主回正量只有 1-2.3°：cap 只有 hipCap=4.6°、hip1Cap=3.4°。
3. hip0 applied 在 ±100 N·m 之间翻号，actual hip0 只在 ±2.8° 内动：
   PD 在顶一个几乎不动的角度目标，脚又踩在地上，力全变成骨盆反作用。
4. loadHip0/comHip0 几乎为 0：负载项在角度通路上是死的。
5. 左右 hip0 目标没有形成有效的反 roll 差动。
```

结论：

```text
现在的回正策略把"侧向平衡"当成 hip0/hip1 的小角度目标来做，
控制量选错了：脚踩地时角度目标被约束住，只会让 PD 饱和翻号；
真正的控制量是左右负载/CoP（力），不是关节角。
```
