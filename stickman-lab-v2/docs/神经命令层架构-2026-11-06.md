## 8. 平衡余量与早期侧偏（新增定稿）

### 8.1 初始状态

```text
初始蹲姿是平衡的
正常人类蹲下的平衡余量很大
不是“已经偏了再救”
而是“每帧都不让它偏出去”
```

所以不能把侧向问题当成“末端救援”问题。

### 8.2 失败链

```text
初始平衡
→ 侧偏刚出现
→ 没有及时做负载转移 / hip0 / CoP 修正
→ XCoM 继续外移
→ CoP 余量耗尽
→ 到后期才加大回正
→ 已经超出支撑面，救不回来
```

### 8.3 正确时序

每一帧都要做：

```text
1. 读 CoM / XCoM / CoP
2. 读 fzL / fzR / 负载
3. 算支撑面余量
4. 算力链
5. 在余量还大时就开始修正
```

不是等：

```text
TTB 很小
或 |eLat| 很大
或已经出安全区
```

才开始回正。

### 8.4 分层动作

```text
余量充足：
  小修正
  负载微调
  hip0 / CoP 微调
  不打扰

余量开始下降：
  优先负载转移
  hip0 侧向
  foot0 抓地
  力链修正

余量接近边界：
  髋/踝已不够
  进入 change-in-support
  迈步 / 支撑改变
```

### 8.5 回正力不是越大越好

```text
回正力必须：
  早
  连续
  与偏差/速度成比例
  有余量时就开始
  不是等偏差大了才饱和输出
```

当前问题：

```text
早期修正不足
hip0 cap 太小/太晚
负载和 CoP 没有及时参与
等到侧偏严重时已无法恢复
```

### 8.6 每帧闭环

```text
每帧：
  更新平衡余量
  更新负载
  更新力链
  更新 hip0 / hipFf / CoP
  输出小修正或升级修正

不允许：
  只在 fall/threshold 时动作
  只靠 hip0 cap 硬救
  等 XCoM 出支撑面再处理
```

### 8.7 当前结论

```text
不是“侧偏严重时回正力不够”
是“侧偏刚开始时没有及时、连续地修正”
```

正常人类蹲姿余量很大，控制器应该每帧守住这个余量，而不是把它耗到只剩救援窗口。

## 10. 矢状回正：真正错误在力链回正方案

### 10.1 结论

```text
真正错误：
  矢状力链回正的实现

不是：
  PD
  td
  关节角本身
  小腿侧向
```

关节角回正不是主回正手段；它只应该在偏差小时接管。

### 10.2 正确职责

```text
偏差大 / 负载不均 / CoM 偏：
  先走力链回正
  决定谁支撑、谁卸载
  分配 FzL* / FzR*
  hipFf / legFf / hip2 下压

偏差小 / 力链已通 / CoM 稳：
  关节角回正
  hip2 回 IK 目标
```

### 10.3 支撑 / 卸载

```text
FzTotal = fzL + fzR

FzL* = FzTotal/2 + Δ
FzR* = FzTotal/2 − Δ

Δ 来自 CoM / CoP / eLoad
```

哪侧需要支撑：

```text
该侧 Fz* 升高
该侧 hip / leg 下压
另一侧卸载
```

不是左右各算一个 legFf 同时加力。

### 10.4 力链模式 / 关节角模式

```text
FORCE_CHAIN：
  大偏差
  负载 / CoM 优先
  hipFf / legFf 大力矩
  关节角只维持 IK
  不允许关节角抢主修正

JOINT_IK：
  偏差小
  力链已通
  hip2 回 IK
  小力矩
  不再继续大力链
```

切换：

```text
FORCE_CHAIN → JOINT_IK：
  负载差、CoM、fPerp 都进入小误差带

JOINT_IK → FORCE_CHAIN：
  负载差 / CoM / fPerp 超出大误差带

必须滞回，不能每帧切
```

### 10.5 当前实现的问题

```text
没有明确的 support / unload 角色
没有 FzTotal 的左右预算
legFf 每侧独立算
hip2TrackFf 和关节角修正同时存在
没有 FORCE_CHAIN / JOINT_IK 模式切换
```

当前不是论文里的 load/unload，而是：

```text
高度力 + 单侧 legFf + hip2 angle 修正
混在一起输出
```

## 12. 矢状 / 侧向回正的职责与轮流契约（2026-11-07 定稿）

### 12.1 职责不同

矢状回正（全身通道）：

```text
管：
  CoM 前后
  左右负载不均
  髋力链 / roll / posture
  全身"救回来"

出：
  hip0 / hip1 / hip2 目标
  hipFf
  knee2 的矢状修正

不负责：
  小腿抓地
  脚底局部 CoP / 力链细节
  踝（foot2）——只保力链 / 抓地，不参与矢状回正
```

矢状承重（高度环，常在线）：

```text
管：
  髋高 H*
  髋太高 → 削基础力（baseGate）
  髋太高 → 膝盖软一点（kneeHipFlex / knee2Support）

出：
  hipFf（高度力）
  relax / baseGate / kneeHipFlex / knee2Support

不出：
  hstar 关节目标（已删除）
  关节方向修正（交给矢状回正）
```

侧向回正（局部通道）：

```text
管：
  一条 active 小腿的抓地 / 力链
  小腿倾角、F_perp、CoP 在脚掌内

出：
  knee0 / foot0 目标（+ fade）

不负责：
  hip（任何轴）
  CoM
  全身负载分配
  矢状轴（knee2 / foot2）
  不"救全身"
```

说明：

```text
"矢状回正"是控制通道名，不是解剖平面名。
hip0 / hip1 虽然是侧向轴，但属于全身平衡 → 归矢状通道。
侧向通道永远不写 hip。
```

### 12.2 轮流契约

```text
mode ∈ { none, sagittal, lateralL, lateralR }

同一帧只有一个 mode
sagittal 与 lateral 不同时 active
lateralL / lateralR 不同时 active
base / support 永远在线，不受 mode 控制
调度器是唯一开关
命令层不得自行激活
```

禁止的旁路（本次已处理）：

```text
sagOn = scheduler.sagittalOn || !lateralGrip     ← 命令层自兜底，已删
lateralActiveNow = scheduler.lateralSide === s
                 || (shankSelSide === s && forceOn) ← 力链旁路，已删
```

抓地 / 力链不满足时：

```text
lateralReady = false
→ 调度器不进入侧向
→ 已在侧向则按 confirm + cooldown 退回 sagittal
→ 不在命令层里让两个回正同时运行
```

已知边界（必须承认）：

```text
lateral mode 期间 CoM / 髋回正暂停
  因为侧向层被禁止写 hip、禁止救全身
  只能靠 min_hold + confirm/cooldown 限制这个窗口
  不允许用"侧向层偷偷写 hip"来补
```

切换时序：

```text
min_hold 0.30s
confirm  0.10s
cooldown 0.10s
命令层 fade 0.08s（SQC_SAG_FADE_TC）
```

## 13. 髋回正：唯二任务（力链修正 + 关节角修正）

### 13.1 结论

髋只执行两个任务，没有第三个：

```text
① 力链修正（P0，force task）
   左右腿负载 / CoP / 力链
   成对输出，支撑侧加载、卸载侧卸载
   大权限，允许关节角暂时偏离 IK

② 关节角修正（P1，posture task）
   IK / 中立姿态 / roll / hipZ 姿态安全
   小权限，只在力链任务进入小误差带后接管
   在力链任务的零空间里工作，不抢主修正
```

说明：

```text
"姿态/roll 安全"属于任务②，不是第三个任务。
小腿侧向不是髋的任务：侧向层只保 fParallel/fPerp/CoP 力链，
                     不参与左右负载分配，也不写 hip。
```

### 13.2 设计

```text
输入：
  fzBudget.fzLTarget / fzRTarget    任务①的唯一左右负载目标
  CoM / XCoM / CoP / fzL / fzR      任务①的反馈
  ik.hip0/1/2、roll、hipZErr        任务②的目标/反馈
  baseFf / heightFf                 常在线，不属于髋的两个任务

任务① 力链修正：
  Δ = FzL* − FzR*
  supportSide = sign(Δ)
  输出成对力：
    support 侧  +F(Δ)
    unload  侧  −F(Δ)
  FzL* + FzR* ≈ W（总重不被力链任务改写）
  允许 hip/leg 关节角偏离 IK
  不允许左右各自独立算、独立饱和

任务② 关节角修正：
  输出 hip0/hip1/hip2 的小角度修正
  只在任务①的力误差/负载差/eLat 进入小误差带后生效
  力链模式中只维持 IK，不做主修正

调度（全局，不按侧）：
  mode ∈ { FORCE_CHAIN, JOINT_IK }
  同一帧两条腿只有一个 mode
  FORCE_CHAIN → JOINT_IK：力误差、eLoad、eLat 都进入小误差带并持续 T
  JOINT_IK → FORCE_CHAIN：大误差带 / CoP 出界 / 抓地失效，立即
  必须滞回 + fade（SQC_SAG_FADE_TC）
```

### 13.3 文献依据

```text
Horak & Nashner 1986, J Neurophysiol 55:1369-1381
  大扰动/短支撑面用 hip strategy：髋产生水平剪力，踝力矩很小；
  身体最终停在非直立位置 → 力/CoM 优先于关节角姿态。

Runge et al. 1999, Gait Posture 10:161-170
  快速扰动在踝力矩上叠加髋屈力矩；纯髋力矩（无踝/腿配合）未观察到
  → 力任务必须成对/多关节，不能只写一个 hip 轴。

Winter 1995, Gait Posture 3:193-214
Winter et al. 1996, J Neurophysiol 75:2334-2343
  并排站立 M/L 平衡 = hip load/unload；5% 垂直力 ≈ 1cm CoP
  → 左右负载必须是同一 Δ 驱动的一对反向量。

Weaver et al. 2017, J Biomech 53:90-96
  蹲、弯腰、站立三种姿势的 M/L 控制仍然是髋 load/unload
  → 蹲姿不能用 hip0 小角度目标当主回正。

Raibert & Craig 1981, ASME JDSMC 103:126-133
  混合位置/力控制：接触约束方向控力，自由方向控位置。

Khatib 1987；Sentis & Khatib 2010, IEEE TRO
  CoM/约束/力任务高优先级，posture 在零空间。

Romano et al. 2015, ICRA（iCub）
  全身平衡：force task 最高优先级，postural task 最低优先级。

Afschrift et al. 2016, J Neurophysiol
  踝/髋策略按机械代价切换，小扰动踝、大扰动髋
  → 用误差带 + 滞回切换，不用硬阈值逐帧翻。
```

### 13.4 当前实现为什么不对（逐帧证据）

`docs` 对应探针：squatCourtSetup，放开后每 0.02s，直到判倒。

```text

        postureHip0=0.2°  loadHip0=0.2°  comHip0=0.0°  hip0Delta=0.4°
        hip0 applied=+155 N·m

        postureHip0=0.4°  loadHip0=-0.0° comHip0=0.0°  hip0Delta=0.4°

```

问题：


```text

```

## 14. 髋回正收敛版：一个选择器 + 两个任务（2026-11-07）

> 2026-11-07 回退：本方案实验效果差，代码已回到 `7848c4be`（收敛前）。

### 14.1 命名

不再用 `stable / unstable` 当状态名。状态名直接写当前执行的任务：

```text
JOINT_HOLD     任务②：关节角修正（IK + posture）
FORCE_RECOVER  任务①：力链修正（成对 load/unload）
```

"稳定 / 不稳定"只作为**进入条件**，不是状态：

```text
稳定条件成立 → JOINT_HOLD
任一误差出大带 → FORCE_RECOVER
```

### 14.2 唯二任务

```text
任务① 力链修正（FORCE_RECOVER 独占）
  输入：Δ = (FzL*−FzL) − (FzR*−FzR)   // 去共模
  输出：一对力 +F / −F
  同一 Δ、同一 cap、同一帧、两条腿
  关节角：不追 IK

任务② 关节角修正（JOINT_HOLD 独占）
  输入：IK q* + roll/hipZ posture
  输出：hip0/hip1/hip2 小角度修正
  力链 ff = 0
```

### 14.3 状态定义（唯一选择器）

```text
eForce   = max(|FzL*−FzL|, |FzR*−FzR|) / W
eChain   = 不满足 {contact, copValid, copInside, fParallel>0}
           或 max(|fPerp|) > chainOn
ePosture = max(|roll|/rollRef, |pitch|/pitchRef, |qErrMax|/qRef)

进入 FORCE_RECOVER：
  eForce > FORCE_HI 或 eChain 或 ePosture > POSTURE_HI
回到 JOINT_HOLD：
  !eChain 且 eForce < FORCE_LO 且 ePosture < POSTURE_LO
  持续 HOLD_T
```

默认（可用 `SQC_HIP_STATE_*` 覆盖）：

```text
FORCE_HI=0.20  FORCE_LO=0.08
POSTURE_HI=2.0 POSTURE_LO=1.0
ROLL_REF=5°  PITCH_REF=10°  Q_REF=8°
HOLD_T=0.15s  CHAIN_ON=120
```

### 14.4 初始状态

初始蹲姿是捕获的静力平衡，因此一定是 `JOINT_HOLD`：

```text

任务② = 0     q* = 捕获姿势，误差 0
base   = 捕获的静力平衡
```

放开第一帧髋不主动回正；只维持捕获姿势。

### 14.5 左右腿协作

```text
FORCE_RECOVER 只有一个 Δ、一个 F、一个 cap：
  F_support = +F
  F_unload  = −F
  两条腿同帧应用，不允许 per-side 独立算/独立饱和。
```

### 14.6 "只有一个修正方案"是否合理

合理，但要限定含义：

```text
"一个" = 每帧只有一个任务 owner；
不是"只输出一个标量力矩"。

任务① 是力向量（ML 负载差 + AP 力链误差），
      可分布到 hip/leg/ankle 多个关节，但只有一个来源、一个 pair。
任务② 是姿态向量（hip0/1/2），但只有一个 owner。
```

这样既不会左右打架，也不会退化成"纯髋一个力矩"（Runge 1999 已证明纯髋力矩不存在）。

## 15. 监督器提案：力链是约束/优先级，关节角是任务（2026-11-08，未验证）

> 状态：**仅设计记录，未实现**。§13/§14 的 `FORCE_CHAIN / JOINT_IK` 是上一版
> 二值切换；本节提出**连续权重监督器**，作为命令层重做的候选方案。
> 用户原话：**「力链是约束/优先级，关节角是任务，监督器输出权重。」**

### 15.1 一句话

```text
力链  = 约束 / 优先级（feasibility / constraint）
关节角 = 任务（posture task）
监督器 = 输出连续权重 { wForce, wAngle, wStep }，不做二值模式切换
命令   = base + wAngle·关节角修正 + wForce·力链修正
```

不再用 `forceMode` 这种“进入就关掉另一套”的硬开关。

### 15.2 状态

感受器 → 状态，命令层只消费状态，不直接读原始传感器：

```text
q / qdot                         关节角 / 角速度
CoM / XCoM / CoP                 平衡状态
fzL / fzR / GRF                  左右负载
contact / copValid               接触有效性
frictionUse / tauUtil            摩擦锥 / 关节力矩利用率
fParS / fSag / fLat / fPerp      有符号力链分量（检测层已定稿）
chainOk                          接触 + CoP + 力矩 + 摩擦可行
```

派生裕量：

```text
mCop    CoP 到支撑多边形边界的距离 / 尺度
mFric   1 − frictionUse
mTau    1 − tauUtil
mRom    关节 ROM 余量
mChain  力链可行性与偏差（fSag/fLat/fPerp + chainOk）
```

### 15.3 监督器

不做“力链 or 关节角”的布尔判断，输出连续权重：

```text
m = min(mCop, mFric, mTau, mRom, mChain)

wForce = smoothstep((thrHi − m) / (thrHi − thrLo))
wAngle = 1 − wForce
wStep  = smoothstep((thrCritical − m) / band)
```

约束：

```text
wForce / wAngle 加滞回 + 速率限制
wStep > 0 时不靠踝/髋硬救，进入 step / change-in-support
初始稳定态 m 高、eAngle 小：
  wForce = 0
  wAngle = 0
  command = base
```

“力链是约束/优先级”的含义：

```text
mChain 低 → wForce 上升
  力链修正拿到更高优先级/更大权重
  关节角任务只能在剩余权限里工作
mChain 高 → wForce 下降
  关节角修正接管
```

### 15.4 命令形状

```text
CommandFrame = {
  base,                         // 捕获的稳定蹲姿，永远在
  angleCorrection,              // 关节目标角：hip0/1/2、knee0/2、foot0/2
  forceCorrection,              // CoP / GRF / 接触力目标，不是第二套关节 PD
  wAngle, wForce, wStep
}

command = base + wAngle·angleCorrection + wForce·forceCorrection
```

边界：

```text
关节角修正是任务：出目标角
力链修正是约束/优先级：出 CoP/GRF/接触力目标或等价 ff
力链修正不能再生成一套关节空间 PD 律
每个 DoF 最终只有一个命令 owner
```

### 15.5 单写手

```text
每帧一个 CommandFrame
每个 DoF 一个 proposal（squat.command）
actions / manual 只做覆盖
base / support / height / load 都是 CommandFrame 内部项，不再各自 propose
禁止：
  多个 squat.* 抢同一轴
  supportClean 蹲姿腿写手
  loadFf / comFf / forceFf 多路并联
  forceMode 清零 hip2Δ
```

### 15.6 初始稳定态

```text
初始蹲姿 = 捕获的静力平衡
m 高、eAngle 小 → wForce = wAngle = 0
所有修正项 = 0
只输出 base
```

验收：静息 10s 内 `wForce=0`、`wAngle=0`、`hip2Δ=0`、侧向/踝修正=0；
不能出现“初始就靠回正力撑着”。

### 15.7 待验证问题（怎么做还不确定）


## 17. 预测模型：三连杆腿 + 髋/膝外部力矩（2026-11-08）

> 设计依据：用户标注 `docs/不知道怎么做了啊.json`。

### 17.1 结论

```text

  小腿 shank

  关节：hip / knee / ankle

不预测：
  全身所有关节
  躯干/手臂的完整动力学

  在 hip 处降阶为“等效质量 + 外力 + 外力矩”
```

所以不是全身预测，只是**腿这条三连杆 + 髋处边界条件**。

### 17.2 状态与输入

```text
状态：
  q = [q_hip, q_knee, q_ankle]
  q̇ = [q̇_hip, q̇_knee, q̇_ankle]

外部/边界：
  M_hip   髋处来自骨盆/躯干的外力矩
  M_knee  膝处来自大腿/负载的外力矩
  M_ankle 足/地面通过踝传入的力矩
  F_hip   髋处等效外力
  CoP / 接触力 / 摩擦

控制输入：
  τ_hip / τ_knee / τ_ankle
```

三连杆动力学：

```text
M(q)·q̈ + C(q,q̇) + G(q) = τ + J_hipᵀ·F_hip + M_ext
```

其中 `M_ext = [M_hip, M_knee, M_ankle]`。

### 17.3 预测什么

```text
预测时域：0.3–0.6 s
预测输出：
  hip / knee / ankle 轨迹
  pelvis（hip）位置/速度
  小腿角、大腿角
  CoM / XCoM
  CoP / 有效 BoS 余量
  关节力矩/ROM 是否越界
```

`XCoM`：

```text
ξ = x + v / ω0
有效 BoS 取静态 BoS 的 30–50%
```

### 17.4 候选策略

```text
A 踝/CoP
B knee-out + hip-down（不迈步）
C 左右负载转移 + hip abduction
D step（最后手段）
```

每条策略都用同一个三连杆模型前向预测；比较：

```text
1. XCoM 是否留在有效 BoS
2. CoP / 摩擦是否可行
3. 髋/膝/踝力矩与 ROM
4. 力矩代价、CoM 位移
```

选择**第一个可行且代价最低**的策略。

### 17.5 为什么只预测三连杆

```text
- 需要预测的是腿对骨盆/足的响应
- 躯干/手臂对腿的主要影响可降阶为 hip 处 F/M
- 全身自由度预测成本高，且当前执行层只有腿在主动回正
- 三连杆足以判断：
    knee-out 是否把膝/小腿带回
    hip-down 是否降低 CoM、增加 CoP 余量
    踝是否还有权限
    是否需要 step
```

### 17.6 与命令层的关系

```text

  → 仍是每个 DoF 一个 writer
  → 预测层不直接写关节
```

### 19.1 定位

```text
PredictiveHipCommander（矢状髋回正指挥层）
  不是第二个 PD
  不直接写关节
  输出：回正策略 + 髋矢状参考 + 预测前馈
  执行：HipCommand / PD / 接触层
```

数据流：

```text
感受器
  → 状态估计
  → P_hip / P_knee 估计
  → 最小预测模型
  → 倒下趋势 + 候选回正 rollout
  → 选策略/参考
  → HipCommand（唯一 hip writer）
  → PD / 接触
  → 感受器
```

### 19.2 只预测什么

```text
预测：
  会不会倒
  往哪边倒
  还有多少时间/余量
  哪个回正方式最优
  该动作对 hip / knee / shank 的影响

不预测：
  全身所有关节的完整轨迹
  长时间开环轨迹
  与回正无关的四肢动作
```

输出是一个**趋势 + 策略**，不是完整轨迹：

```text
fallTrend:
  direction: AP / ML / mixed
  margin: 有效 BoS − |XCoM|
  timeToBoundary
  risk: 0..2
bestAction:
  do_nothing / ankle / knee-out+hip-down / load-unload / step
  hip0/1/2 参考
  hip2 ff
  predicted eSag / eSagV
```

### 19.3 消费的感受器

```text
骨盆：roll / pitch / height / 速度
CoM / XCoM / CoM 速度
足底：接触 / fz / CoP / 摩擦利用率
关节：hip/knee/foot 角度、速度、applied torque
足位：左右脚 anchor / 支撑多边形
力链：fParallelSigned / fPerpSag / fLat
```

`P_hip / P_knee` 估计：

```text
P_hip  = 上半身对 hip 的等效力 + 力矩
P_knee = 小腿/足/地面对 knee 的等效力 + 力矩

来源：
  inverse dynamics / joint loads / GRF / CoP
  不允许用目标值反推测量值
```

### 19.4 最小模型

```text
状态：
  q = [q_thigh, q_hip, q_knee]
  q̇ = [q̇_thigh, q̇_hip, q̇_knee]

边界：
  P_hip  = F_hip + M_hip
  P_knee = F_knee + M_knee

动力学：
  M(q)q̈ + C(q,q̇) + G(q)
    = τ + J_hipᵀ·P_hip + J_kneeᵀ·P_knee
```

不建全身模型；小腿/足/上半身压缩成上下边界压力。

### 19.5 预测算法

```text
频率：20–50 Hz（低层 240–480 Hz 不变）
时域：0.3–0.6 s
方式：receding horizon
```

每一步：

```text
1. 读当前状态 + P_hip/P_knee
2. 对候选动作做短时 rollout：
     do_nothing
     ankle/CoP
     knee-out + hip-down
     load-unload + hip abduction
     step（可选）
3. 预测每个候选的：
     XCoM 是否越过有效 BoS
     CoP / 摩擦 / 力矩 / ROM
     shank 被带走多少
4. 代价：
     J = w1·margin violation
       + w2·effort
       + w3·CoM excursion
       + w4·shank disturbance
5. 选第一个可行且 J 最小的
6. 输出策略 + 髋参考 + 前馈
7. 下一拍重算
```

滚动预测只做**趋势/策略**，不追求长轨迹精确。

### 19.6 输出给 HipCommand

```text
SagittalHipReference:
  strategy
  hip0/1/2 target
  hip2 ff
  predicted eSag / eSagV
  predicted margin
  valid / confidence
```

约束：

```text
一个 DoF 一个 writer
HipCommand 仍唯一出口
预测层不直接 propose
预测失效 → 回退手写兜底
```

### 19.7 与现有层的关系

```text
§17：最小预测模型（hip/knee/thigh + P_hip/P_knee）
§18：为什么必须预测（髋自由度高）
§19：预测如何成为矢状髋回正指挥层

Lateral / 踝 / base：
  仍走原通道
  预测层只提供约束/影响估计
```

### 19.8 验收

```text
静息：
  预测层输出 do_nothing
  不产生持续修正

小扰动：
  预测 margin 下降
  在 eLat 阈值前选中 ankle 或 knee-out+hip-down

侧翻：
  预测能给出 fallTrend 和 bestAction
  能原地恢复时不选 step

执行后：
  hip/knee 外部力矩与预测一致
  shank 不被破坏
  预测 margin 上升
  没有第二个 hip writer
```

## 21. 逆动力学求解器：替代旧矢状命令层（2026-11-08 定稿）

> 用户定稿：**先用逆动力学求到稳定态，再求到 IK 目标；基础力也进动力学求解；3 节棍模型足够。**
> 目标：逆动力学求解器彻底替代旧的手写矢状回正命令层。

### 21.1 定位

```text
InverseDynamicsSolver（矢状唯一命令出口）
  输入：关节/骨盆/接触/感受器 + P_hip/P_knee
  求解：稳定态接触力/关节力矩
         IK 目标轨迹的关节力矩
  输出：CommandFrame
  执行：现有 PD/肌肉层

旧 hipStrategy / 手写回正：
  只做 fallback，不再是主命令
```

### 21.2 基础力必须进 solve

基础力不是外部前馈，而是接触 wrench 的一部分：

```text
M(q)q̈ + C(q,q̇) + G(q)
  = τ
  + J_baseᵀ·F_base
  + J_hipᵀ·P_hip
  + J_kneeᵀ·P_knee
```

```text
F_base  = 脚底/地面反力、CoP、摩擦
P_hip   = 髋上部压力
P_knee  = 膝盖下部压力
τ       = hip/knee/ankle 力矩

baseFf 只能作为初值/正则项，不能在外面重复叠加。
```

### 21.3 两阶段求解

#### A. 到稳定态

```text
q̇ = 0, q̈ = 0
未知：τ、F_base、P_hip/P_knee

约束：
  CoP ∈ 支撑多边形
  摩擦锥
  关节力矩/ROM/腿长
  左右脚接触

目标：
  CoM/XCoM 余量最大
  + 力矩最小
  + 左右负载合理
```

输出：

```text
每条腿 Fz / 横向力
hip/knee/ankle 稳态 τ
base force 分配
```

#### B. 稳定后再到 IK 目标

```text
q* = 捕获/IK 目标
q̈_des = 平滑轨迹
未知：τ、F_base
约束：同上
验证：预测 margin 上升、shank 不被破坏
```

### 21.4 三连杆范围

```text
模型：hip / knee / shank
边界：P_hip / P_knee
上身、足、地面：实际参数 + 边界压力

只做矢状。
侧向 / roll：仍走原通道。
```

### 21.5 可行性保证

只能保证模型内可行：

```text
QP 可行
  → 解在模型/约束内正确可行
QP 不可行
  → 明确报 infeasible，不得假装有解
```

执行前必须检查：

```text
1. 动力学残差
   ||M q̈ + C + G − τ − JᵀF||
2. CoP / 摩擦 / 力矩 / ROM / 腿长
3. 预测 XCoM margin 是否上升
4. shank 是否被 P_knee 破坏
```

真实世界的模型误差、接触切换、摩擦突变、延迟无法绝对保证；必须保留：

```text
step / hold 兜底
```

### 21.6 替代边界

```text
允许：
  逆动力学求解器成为矢状唯一命令出口
  baseFf 作为初值/正则
  手写策略只做 fallback

禁止：
  求解器外再叠一套 hip 回正
  两个 hip writer
  把 F_base 和 baseFf 双算
  无解时继续下发
```

### 21.7 验收

```text
静息：
  求解器输出稳态 τ/F_base
  不产生持续修正

稳定态：
  左右脚 Fz 合理
  CoM/XCoM margin 不下降
  关节力矩不饱和

IK 目标：
  q 平滑到目标
  shank 稳定
  CoP/摩擦可行
  无第二个 writer

失败：
  QP infeasible → 明确拒绝并 fallback
```

### 21.8 滚动求解与最低要求（2026-11-08）

```text
不要求一次求解就完全回正。
按 receding horizon 滚动：

每 20–50 ms 求解一次
输出下一小段 τ / F_base / 目标
低层 PD 保持不变
下一拍重新求解
```

推荐：

```text
第一阶段：静态稳定求解，20–50 Hz
第二阶段：加 0.2–0.4 s 短时域
第三阶段：再扩到 0.6 s
```

最低验收：

```text
同状态 A/B：
  预测 XCoM/CoP margin 必须比现有矢状层好
  实际 fall 时间必须推迟，不能更早
  关节力矩在 budget 内
  shank 不被破坏
  不出现第二个 writer
```

只要没达到这条：

```text
不替换旧层
求解器只读 / 旁路
继续调模型或约束
```

力矩足够大不等于一定能回正：

```text
还要满足 CoP / 摩擦 / 接触 / ROM
力矩大但接触不可行 → 仍然救不了
```

目标顺序：

```text
1. 先让求解器对现状有正贡献
2. 再让它替代旧矢状回正
3. 最后才追求“最优回正”
```

## 23. 双大腿确定性差动：低侧顶、高侧落（2026-11-08 定稿）

> 用户定稿：**两腿必须同时考虑；哪边低哪边顶起来，哪边高就落下去。这是确定关系。**

### 23.1 结论

```text
pelvis 是公共根
左右腿是并联支链
低侧 = 支撑侧，必须顶起
高侧 = 卸载侧，必须落下
```

这不是策略选择，而是**几何/力平衡的确定性关系**：

```text
hL = 左髋高度
hR = 右髋高度
e  = hL − hR

ΔFz = Kp·e + Kd·(vL − vR)
FzL* = W/2 + ΔFz
FzR* = W/2 − ΔFz
```

同时：

```text
低侧腿长/支撑增加
高侧腿长/支撑减少
两腿成对动作，不能各自独立算
```

### 23.2 关节映射

```text
髋高 / pitch：
  两腿 common hip2 / knee2

roll / 左右高低：
  两腿 differential hip0 / hip1
  低侧外展/顶起，高侧内收/落下

Support：
  低侧 Fz 增加
  高侧 Fz 减少
```

### 23.3 硬约束

```text
FzL* + FzR* = W
低侧 leg length / support ↑
高侧 leg length / support ↓
两脚仍接触
CoP / 摩擦 / 力矩 / ROM 可行
```

不允许：

```text
左右各自算自己的 hip2/knee2
低侧不顶、高侧不落
一侧顶到饱和，另一侧还不知道
```

### 23.4 与逆动力学求解的关系

```text
Bilateral ID Solver：
  一次同时求左右腿 τ、Fz、leg length
  用 hL−hR / roll 作为确定性差动目标
  低侧顶、高侧落是方程约束，不是 if/else
```

输出：

```text
FzL* / FzR*
hip2L/knee2L 与 hip2R/knee2R（common + differential）
hip0/hip1 差动
hipResidual（骨盆力/力矩残差）
```

### 23.5 验收

```text
低侧：
  支撑力增加
  腿长/髋高增加
  不被高侧拖走

高侧：
  支撑力减少
  腿长/髋高下降
  仍保持接触

整体：
  hL − hR 收敛
  pelvis roll 收敛
  FzL* + FzR* = W
  hipResidual → 0
```

### 23.6 kneeOut 是逆动力学约束，不是独立前馈

```text
kneeOutL/R 必须和 FzL/R、hip2/knee2、hip0/hip1 联合求解
不能单独把 kneeOutFf 加到 hip0
```

独立 A/B 已证伪：

```text
baseline            fall 3.28
kneeOutFf × +0.5    fall 2.93
kneeOutFf × -0.5    fall 2.99
```

正确形式：

```text
约束：kneeOutL >= target
      kneeOutR >= target
与：
  FzL + FzR = W
  hL − hR → 0
  pelvis roll → 0
  CoP / 摩擦 / torque / ROM
同时求解
```

输出：

```text
Bilateral solve 内同时给：
  低侧顶 / 高侧落
  kneeOut 约束
  hip0/hip1 差动
  hip2/knee2 腿长
不允许在求解器外再补一套 hip0 前馈。
```
