
## 4. 髋矢状命令

职责：

```text
CoM 居中
左右脚负载
H* / 髋高
髋力链
posture
```

输入：

```text
CoM / XCoM
fzL / fzR
CoP
contact / friction
H* / IK
hip 实际角度 / 角速度
hip2Target / hip2Actual
力链
```

输出：

```text
hip0 / hip1 / hip2 目标
hipFf
```

优先级：

```text
P0 左右脚负载
P1 CoM / 髋力链
P2 H*
P3 posture
```

基础力与回正力：

```text
baseFf    = 高度 / 支撑 / 重力前馈
rightFf   = 负载 / CoM / 力链
hipFf     = baseFf + rightFf
```

命令层独立，PD/td 只执行。

## 8. 平衡余量与早期侧偏（新增定稿）

### 8.1 初始状态

```text
初始蹲姿是平衡的
正常人类蹲下的平衡余量很大
不是“已经偏了再救”
而是“每帧都不让它偏出去”
```

所以不能把侧向问题当成“末端救援”问题。

### 8.2 失败链

```text
初始平衡
→ 侧偏刚出现
→ 没有及时做负载转移 / hip0 / CoP 修正
→ XCoM 继续外移
→ CoP 余量耗尽
→ 到后期才加大回正
→ 已经超出支撑面，救不回来
```

### 8.3 正确时序

每一帧都要做：

```text
1. 读 CoM / XCoM / CoP
2. 读 fzL / fzR / 负载
3. 算支撑面余量
4. 算力链
5. 在余量还大时就开始修正
```

不是等：

```text
TTB 很小
或 |eLat| 很大
或已经出安全区
```

才开始回正。

### 8.4 分层动作

```text
余量充足：
  小修正
  负载微调
  hip0 / CoP 微调
  不打扰

余量开始下降：
  优先负载转移
  hip0 侧向
  foot0 抓地
  力链修正

余量接近边界：
  髋/踝已不够
  进入 change-in-support
  迈步 / 支撑改变
```

### 8.5 回正力不是越大越好

```text
回正力必须：
  早
  连续
  与偏差/速度成比例
  有余量时就开始
  不是等偏差大了才饱和输出
```

当前问题：

```text
早期修正不足
hip0 cap 太小/太晚
负载和 CoP 没有及时参与
等到侧偏严重时已无法恢复
```

### 8.6 每帧闭环

```text
每帧：
  更新平衡余量
  更新负载
  更新力链
  更新 hip0 / hipFf / CoP
  输出小修正或升级修正

不允许：
  只在 fall/threshold 时动作
  只靠 hip0 cap 硬救
  等 XCoM 出支撑面再处理
```

### 8.7 当前结论

```text
不是“侧偏严重时回正力不够”
是“侧偏刚开始时没有及时、连续地修正”
```

正常人类蹲姿余量很大，控制器应该每帧守住这个余量，而不是把它耗到只剩救援窗口。

## 9. 当前工作范围（冻结）

本阶段只允许修改：

```text
矢状髋回正命令层
  hip2 目标
  hip2 / 大腿下压力链
  每条腿 FzL* / FzR*
  CoM 前后
```

```text

→ 该侧 hip2 / hipFf 增加
```

不在本阶段范围：

```text

knee0 / foot0
侧向抓地
PD
td
关节限位

```

边界：

```text
命令层只输出 hip2Target / hipFf / legFf
PD 只执行

HipCommand 是唯一髋命令输出
小腿和侧向完全冻结
```
