# 基础力写手审计（2026-10-16）

> 本文的公理（用户定调）：
> 1. **基础力 = 只包含基础力和张力**；回正力是单独的（"回正力是用来回正的"）。
> 2. **对抗重力的力用关节发力，要走审批（提案总线），别凭空发力。**
> 3. **只需要基础力就必须保持单腿稳定站立**；重心天然就是偏的，基础力维持的是单脚站着的状态。
> 4. **抬腿结束那一刻 = 标准态**；放开瞬间重力与主动力必须**互补**，全身始终维持这个状态。
> 5. 侧向：**"侧向力反正是完全不够"** —— 竖直打通后，回正力是最后的战场。

## 0. 基准态：放开瞬间对账（100% 互补 ✅ 2026-10-16 达成）

法庭（`_tmp-hold10`，静置 2.0s 清零 → 放开），放开瞬间逐关节回读：

| 关节 | 重力需求 | 实际出力 | 差 |
|---|---|---|---|
| hip_r/0 | −89 | −89 | **0** |
| hip_r/2 | +51 | +51 | **0** |
| knee_r/0 | −71 | −71 | **0** |
| knee_r/2 | −80 | −80 | **0** |
| foot_r/0 | −17 | −17 | **0** |
| foot_r/2 | −44 | −45 | **1** |

**含义**：标准态（放开瞬间）竖直链路每个关节的重力需求与主动出力分毫不差。
竖直不再是瓶颈；放开后唯一死因 = **侧向 roll 10° 崩溃 @2.13s**。

达成路径（三件套）：
1. `body.gravityComp` 浮动基座修正：支撑腿用**互补子树**（扛上方全身），不再用子树；
2. 支撑侧判定改**脚高度差**（位置判据）——静置期速度清零会把接触冲量杀成 0，`footNormalForce` 会误判 mode=none；
3. 驱动一步收敛护栏（tCap）给踝补**惯量下限 1.5**（原只有髋 0.8）——踝实际带全身，惯量巨大。

## 3. 保留写手归档（逐个：基础力是怎样的）

### 3.1 gravityComp —— 重力补偿（竖直链主力）

- **位置**：`body.ts: gravityComp(out, gY, supSide)`；`stability.ts: contributeBaseline` 每帧调用
- **通道**：`propose({kind:'torque', pri: PRI.servo, src:'gravityComp'})` —— 走审批（用户："走审批，别凭空发力"）
- **基础力 = 抗重力矩**：
  - 支撑腿关节（`_${supSide}` 且名 `hip/knee/foot/ankle`）：**互补子树** = 不在该关节子树里的全部身体 = 其上方重量，取重力矩的反；
  - 摆动腿关节：自身子树（自己的小腿+脚）；
  - 符号（实测标定）：**踝(foot/ankle) → +τ，髋膝(hip/knee) → −τ**。
- **支撑侧判定**：脚高度差 >2cm（位置判据，不受静置清零影响）
- **实测**：放开瞬间对账 6 关节全互补（见 §0）；竖直到此为止。

### 3.2 supportClean —— 支撑腿标准姿态基座

- **位置**：`servo/supportClean.ts`；每帧由 stepPhases（app）/ court（法庭）调 `supportClean(ctx, side)`
- **通道**：`propose` torque（ax0/ax2 同时出 **pair** 肌肉对提案）
- **基础力 = 支撑腿标准姿态的"基座 + 分配"**：
  - **B0 常数基座（按支撑模式分套）**：
    - 站立套（mode=both/none）：hip0=−9, hip2=11, knee0=96, knee2=−6.5, foot0=52, foot2=−5
    - 单腿套（mode=l/r）：全 0 —— 竖直交给 gcomp 互补，此档留给侧向微调
  - **方向态分配**：dirState 的 dirN/dirP（latN/sagN）→ 每轴 N/P 双参数（`SC_*_N` / `SC_*_P`）
  - **kCom 重心链分配**：按 CoM 误差沿链分力（髋 .45 / 膝 .15 / 踝 .10 / 脊柱 .30）
  - **预算帽（基于脚上力）**：`SC_CAP=300` 单轴钳；踝预算 `SC_FOOTW=0.10`（`capFootLat = max(15, fz·fw·copK)`，矢状 `fz·0.12`）
- **env**：`SC_HIP0…SC_FOOT2`（站立）、`SC_*_S`（单腿）、`SC_FOOTW`、`SC_KP_*` 等

### 3.3 trunkClean —— 躯干链竖直基座

- **位置**：`servo/trunkClean.ts`；由 supportClean **唯一入口**调用一次/帧
- **通道**：`propose` torque
- **基础力 = 躯干链的竖直支撑基座**：`TR_B0_LAT=2`、`TR_B0_SAG=0`（受力审计后从 10/5 下调）
- **env**：`TR_B0_LAT` / `TR_B0_SAG`

### 3.4 摆动腿基座 —— 抬腿后的抬起保持

- **位置**：supportClean 的摆动侧分支
- **通道**：`propose` torque
- **基础力 = 摆动腿的"抬起保持"**：
  - 单腿套（抬腿中/单腿期）：hip2=**140**, knee2=**−220**（法庭 TRL 标定：脚高 10.9cm、fzL=0、膝稳定 −36°、髋 18°）
  - 站立套（双支撑期）：0/80/0/−55/0/0
- **env**：`SW_HIP2_S` / `SW_KNEE2_S` 等

### 3.5 stepPhases —— 迈步相位驱动

- **位置**：`step/stepPhases.ts`（actionSystem 的相位机）
- **通道**：`propose` torque/angle/pair/clear（PRI.action=40）
- **基础力 = 动作期的相位驱动**（迈步/落步的竖直承接）；调用 supportClean / swingColumn / rescueOffsets / setLiftDone / captureSupportPose
- 动作结束后由 tone + supportClean 接管

### 3.6 tone —— 双支撑姿势张力

- **位置**：`stability.ts`（contributeBaseline 前段）
- **通道**：**直写** `drive.setAngle(dof, rest, kp)`，`kp = postureTone·0.5·τmax/lim`
- **基础力 = 双支撑的默认姿势 PD**（保持 rest 姿态）：
  - **单腿期整段让位**（`legReflex.side ≠ null` 时 continue）——§2.479 用户："姿态张力基线：双支撑照常，单腿期整段让位"
  - 踝策略接管的轴让位；有主动 ff 的 pin 让位（挺腰 pin 除外）
  - 髋外展轴 kp 钉在 120 等效（τmax 放开到 170 后的旧档保护）
- **env**：`TONE`（法庭模板 TONE=0/8）

### 3.7 actions —— 动作层（⚠️ 直写，待迁总线）

- **位置**：`actions.ts` + `control.ts` ④
- **通道（三条全是直写）**：
  - poseTargets → `drive.setAngle`（control.ts:107，带 pair/pin/ff 让位守卫）
  - torqueTargets → `executor.addTorque`（control.ts:114）
  - 姿势键 → `manual.setAngle/pin`（actions.ts 内多处）
- **基础力 = 程序动作的姿势关键帧 + 附着力矩**（idle/walk/挥手等）
- **★ 待迁**：改为总线提案（PRI.action=40），由仲裁统一管理

### 3.8 leanReflex —— 双支撑姿势层

- **位置**：`leanReflex.ts`；由 control ⑥ 的 directives（lean/load/posture/trunk）调用
- **通道**：**直写** `executor.addTorque`（髋差动对偶/支撑撑/姿势）+ `manual.setAngle`（脊柱侧向）
- **基础力 = 静态双支撑的姿势层**（慢/常开）：
  - 差动加载力偶（Winter 律，双支撑机制）；`applySupportBrace` 支撑撑；`applyPosture` 髋/脊柱侧向；`applyTrunk` 矢状
  - **单腿期**：脊柱侧向让位（`if (!singleLeg)`），髋对偶仍工作
- **门控**：`WAR_REFLEX=0` 全关（纯基础力测试用）

### 3.9 footPad —— 足底四向 + 足弓

- **位置**：`footPad.ts`；由 control ⑥ 的 pad directive 调用
- **通道**：**直写** `executor.addTorque`（flex/inv 四向）+ `body.setEngineMotorTarget`（arch 足弓）
- **基础力 = 足底垫脚（CoP 四向）+ 足弓支撑**
- **门控**：`PAD`（0=关）；支撑腿侧判定跳过

### 3.10 momReg —— 角动量调节

- **位置**：`servo/momentum.ts`；control ④ 调用
- **通道**：**直写** `manual.setAngle`（手臂）
- **基础力 = 角动量管理**（手臂摆动配平躯干）
- **门控**：`MOM`（useMom）

### 3.11 drive 被动层 —— 执行器本体

- **位置**：`drive.ts`（所有主动命令的公共出口）
- **通道**：`executor.addTorque(tex+td)`（主动合成）+ `addPassiveTorque`（lum）
- **内容 = 执行器的物理层**：
  - 马达 PD（servo 通道，目标角来自 manual/drive.setAngle）
  - 肌肉对（pair，共激活 + λ 目标）
  - 被动刚度（stiff）、黏性阻尼（damp，两帧平均防 Nyquist）
  - 脊柱张力（lum，`IAP=200` 角刚度——"增强脊柱内部的拉力，把脊柱拉起来"）
  - 一步收敛护栏（tCap = α·I·ωmax/dt；**惯量下限：髋 0.8、踝 1.5**——两者都实际带全身）
  - 限位冲量（无引擎限位的球铰）
- **冲突检测器**：同轴同帧反号双写手 >5N·m 计数（ff 豁免——gcomp 与伺服是合法结构）

### 3.12 manual —— 直控通道

- **位置**：`manual.ts`
- **通道**：`drive.setAngle/setTorque` 回放（每帧）
- **基础力 = 直控（用户拖拽，PRI.direct=100 最高）+ 各写手的角度命令存储**
- **已知坑**：`manual.clear()` **不清驱动 PD**——清目标必须用 `clearAngle(d.name, d.axis)`（法庭 ④ 已加）
