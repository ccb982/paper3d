# 单腿蹲 · 主动发力机制（2026-10-21 定稿）

> 用户原话："力都是脚主动发力得到的才对吧——要多少力，脚就发多少力。"
> 本文档定义：蹲下（尤其单腿）的**唯一正确发力机制**。基础力不是"猜出来的关节力矩"，
> 而是**地面反力的需求 + 脚主动蹬地的执行**。

---

## 0. 一句话结论

**脚是唯一的发力源。** 身体能站的唯一外部力是地面反力（GRF）。所有关节力矩都是
"把地面反力按需求分配到关节"的结果（`τ = Jᵀ·F`），不是独立写进去的"虚空力"。

---

## 1. 为什么"重力补偿"不够

| 场景 | 机制 | 结果 |
|---|---|---|
| 双腿站立 | 纯子树重力补偿（`gravityComp`） | 能稳——CoM 在双支撑多边形中部，余量大 |
| 双腿蹲 | 子树重力 + GRF 项（静态解） | 勉强——CoM 接近脚尖，余量小 |
| **单腿蹲** | **必须主动蹬地 + 接触力闭环** | 只靠补偿必倒——支撑多边形只有一个脚掌 |

单腿时：
- 支撑多边形 = 单脚掌（前后 ~24cm、左右 ~10cm）；
- CoM 必须精确落在脚掌内，且地面必须真的给出 `N = W`；
- 重力补偿只保证"关节力矩抵消体重"，**不保证地面给得出反力**；
- 只要 CoP 出脚掌 / 脚离地，反力消失 → 任何力矩都变成虚空力 → 飞。

## 2. 物理原理（论文依据）

### 2.1 唯一外部力 = 地面反力
- 机器人浮动基动力学：`M(q)q̈ + h(q,q̇) = Sτ + Σ Jᵀ_c,i f_c,i`
  （RH5 humanoid, arXiv:2101.10591；TALOS benchmark, PMC8934419）
- 关节力矩是内力；**只有接触力能改变整机质心动量**。
- 逆过来：想要质心受某个合力，就必须让脚对地施加对应的反作用力。

### 2.2 地面反力 → 关节力矩：`τ = Σ Jᵀ_c f_c`
- MIT Humanoid：`τ_j ≈ Σ_i Jᵀ_c,i f_c,i`（arXiv:2104.09025, eq.14）
- 对矢状面单腿支撑、竖直力 `F=(0,N,0)` 作用在 CoP：
  ```
  τ_j = −[ Σ_子树 m·g·(x−x_j) + N·(CoP − x_j) ]     // 每个关节
  ```
  这就是 `Jᵀ·F` 的逐关节展开；**踝是出口，膝/髋是传递**。

### 2.3 CoP 必须在支撑多边形内（否则脚转/飞）
- 单边接触 + 摩擦锥：`f_z > 0`，`|f_x| ≤ μ f_z`；
- CoP 到达脚掌边缘 → 脚开始绕边旋转（Frontiers 2015, arXiv:1710.10598）；
- 人形控制里用 contact wrench cone / ZMP 约束保证这一点（PMC10613887）。

### 2.4 踝策略 = 用 CoP 控质心
- Horak & Nashner 1986：踝策略 = 绕踝力矩移动 CoP；
- Winter 1995：安静站立 = 倒立摆，AP 用踝；
- Peterka 2002：`T_a = Kp·e + Kd·ė`，CoP ∝ 踝力矩；
- Hof 2005：`XcoM = x + v/ω0`，`CoP = x − ẍ/ω0²` —— **CoP 要带速度项**，
  只放在 CoM 正下方只能让加速度为零，速度收不住。

### 2.5 蹲姿生物力学（为什么腿/髋力矩大）
- 蹲下时 COM 前后位移由髋、踝、膝共同决定；踝同时影响垂直与前后
  （PMC11307177, 2024）；
- 膝伸展力矩与 CoP 位置强相关（Ishida 2022a/b）；
- 单腿蹲髋关节接触力可达 **8.4 BW**（PMC12289039）——腿/髋必须"非常有力"，
  这不是可选项，是物理必需；
- 双脚 GRF/CoP 天然不对称（PMC9528672）——所以左右必须各自算，不能取平均。

## 3. 机制设计（实现规格）

### 3.1 支撑腿（单腿蹲 = 支撑腿承担全部体重）
```
每帧：
  N_support = W = m_total · g          // 单腿全重
  CoP = clamp(comX + Kd·vCom, 脚掌内)  // 静态=comX；动态加 XcoM 速度项
  τ_j = −[ Σ_子树 m·g·(x−x_j) + N·(CoP − x_j) ]   // 踝/膝/髋
  τ_spine = −Σ_子树 m·g·(x−x_j)        // 脊柱只传力
  τ_ankle += Kf·(N − fz_measured)      // ★ 接触力闭环：脚主动补足
```
- `Kf`：接触力闭环增益（N·m/N），从 0.01~0.05 起调；
- 所有力矩**只走提案总线**（`kind:'torque'`，`src:'squat.base'`）；
- 蹲姿**单源**：除 `squat.base` 与唯一阻尼外，禁止其他关节写手。

### 3.2 摆动腿
不参与支撑：只做重力补偿/动作层，不写 `squat.base`。

### 3.3 双腿蹲（过渡）
两条腿各 `N = W/2`，CoP 各自在脚掌内；左右独立计算，**不取平均**
（实测左右捕获值 hip -76.5/-76.5 对称，但 GRF 可不对称）。

### 3.4 为什么旧实现是"虚空力"
```
旧：staticBalance 算出的 τ 直接当关节力矩下发，脚底没有任何力需求/闭环；
    GRF 只出现在公式里，靠接触求解器"碰巧"给出。
    → 姿势一漂，公式不再一致 → 净内力 → 脚飞/抽搐。
```
新实现的关键差别：**接触力闭环**——`fz < N` 时踝主动加力，`fz > N` 时减力，
脚永远在"要多少发多少"的状态。

## 7. 架构定稿（2026-10-21 深夜，覆盖以上实现描述）

**旧基础力通道已全删**（蹲姿的 gBuf / staticBalance / captureSquatBase / antiG 全部移除）。
蹲姿的主动发力**只允许走肌肉对（pair）**：

```
控制层：squatPairBase
  τ_base = −[子树重力 + N·(CoP−x_j)]      // 需求（静态解+GRF）
  propose({kind:'pair', c, rad:目标角, tau:τ_base})
        │
控制层：control.step
  executor.commandPair(dof, C·outputScale, ref, τ_base·outputScale)
        │
执行层：executor.applyAll（每步一次，受 τmax）
  pairTorque() = f1 − f2
    kp = 2C·ks（共收缩刚度，Feldman/Hogan/Atkeson）
    kd = 2C·bs（共收缩阻尼）
    稳定域：kp ≤ 0.5·4I/dt²，kd ≤ 0.8·2I/dt
    τ_des = kp·(ref−θ) − kd·ω + τ_base
```

- **站立不动**：antiG 只服务站立（纯子树重力补偿），pair 在站立无命令（C=0）；
- **蹲姿/单腿站立**：只用 pair；
- pair 模块：`src/core/servo/musclePair.ts`（唯一主动发力执行器）；
- 驻留位置：执行层（executor），控制层只写 (C, ref, base)。
