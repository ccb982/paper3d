# stickman-lab 架构设计

> **项目定位**：一个**离线/在线可跑的 3D 物理人形实验室**。最终交付物是**一具能正常行走、能主动攻击的敌人**，
> 以「特殊 boss」的形式移植回《全新的游戏》。
>
> 本文档是**架构真源**：模块边界、接口契约、关键决策的实测依据、验收口径、以及移植路线。
> 改代码前先读第 5 章（设计决策）与第 9 章（验收），那里写的都是花钱买来的教训。

## 1. 目标与定位

### 1.1 最终目标（用户定调）

> "我的这个机器人仿真的目标是做出**能正常行走和攻击的敌人**，作为**特殊 boss** 进全新的游戏中。"

拆成三个可验收的子目标：

| # | 子目标 | 验收口径 |
|---|---|---|
| G1 | **正常行走** | 连续 ≥ 6 s 不摔倒（`tilt` 全程 < `fallAngle`），沿 +X 净位移 ≥ 3 m，侧向漂移 ∫\|z\|dt 小 |
| G2 | **主动攻击** | 对目标假人能打出命中（`hits ≥ 3 / 回合`），而不是站着挨打 |
| G3 | **可移植** | 导出基因组 + 驱动器能在本体游戏里跑，不需要重新训练 |

### 1.2 为什么独立成项目

- **不能边开发边训练**：一次 40 代训练是 16 万物理步，必须离屏跑。把学习逻辑塞进本体会让本体的帧率变成噪声源。
- **接口要干净**：本体是"搜打撤"玩法，实验室研究的是"骨链控制"这一个问题。
- **验收要机器化**：独立项目才能长出一整套 `tools/*.probe.ts`（见第 9 章），每改一处物理都能一键回归。

### 1.3 交付物（三件套，缺一不可）

1. **基因组**：`brain` 的 3163 个 float32，base64 + JSON 外壳 ≈ 16.5 KB。
2. **驱动器**：`Ragdoll` + `Sim` 的最小闭包（本文件第 2 章列的接口）。
3. **验收工具**：`verify-core` + `probe-*`，保证移植后行为可复现。

## 2. 系统边界与移植契约

### 2.1 移植时**需要**的（内核，约 4 个文件）

```
core/skeleton.ts  骨架几何（parts.json → 刚体/关节/质量/限位）
core/ragdoll.ts   世界 + 刚体 + 球关节 + 自实现三轴马达 + 姿态读数
core/brain.ts     MLP 前向（零分配）
core/sim.ts       把上面三者接起来 + 适应度
core/genome.ts    基因组打包/解包
```

### 2.2 移植时**不需要**的

`evolution.ts`（训练用）、`viewer.ts`（渲染）、`hud.ts`（面板）、`tools/*`（验收）。

> ★ 这意味着**包体可以砍掉一半**：训练期需要的 48 个 World 在游戏里只要 1 个。

### 2.3 Boss 控制器对外契约（`BossController`）

| 方向 | 接口 | 说明 |
|---|---|---|
| 输入 | `setTarget(x, z)` | 索敌目标；由本体 AI 决定打谁/追谁 |
| 输入 | `setMode('patrol' \| 'chase' \| 'attack')` | 状态机由本体驱动，实验室只负责**运动学执行** |
| 输出 | `rootPos() / rootQuat()` | 把躯干刚体位姿喂给本体（用于 UI 血条、音效定位、索敌） |
| 输出 | `phase` | 步态时钟相位（0..1），本体拿它做脚步声/攻击前摇同步 |
| 输出 | `hits` | 命中事件计数，本体据此扣玩家血 |
| 边界 | **不碰** | 伤害数值、掉落、遗物、对话 —— 全部留在本体 |

★ 关键约束：**实验室不产生玩法级副作用**。它只输出"身体做了什么"，不输出"游戏发生了什么"。

```
① Sim.begin(genome)
   └─ buildWorld()            整世界重建（见 5.7）—— 不是 reset()
   └─ doll.reset(0)           摆回初始站姿

② 每物理步（120 Hz）
   ├─ 若到控制周期（60 Hz）：
   │    controlTick()   →  填 70 维观测  →  brainForward  →  ×JOINT_MAX_SPEED
   │                                                       →  doll.setMotorTargets()
   └─ doll.driveMotors(dt)   自实现三轴马达（见 5.4）

   └─ 算适应度 → Trainer.recordAndBreed() → 下一代
```

## 5. 关键设计决策（每条都附实测依据）

### 5.1 必须是真 3D 球关节（用户定调）

**决策**：所有关节是 `JointData.spherical()`，六自由度全开（不锁任何平移/旋转轴），每关节 3 个转动自由度。

**为什么 2D 方案被废弃**（原话：「跑一个 2d 的机器人没有任何意义」）：

> 2D 版把"前进"和"侧向"塞进了同一个轴：所有刚体锁 `enabledTranslations(T,T,F)` + `enabledRotations(F,F,T)`，只能绕 Z 转。
> 而绕 Z 转 = 肢体在画布平面内左右摆 = **外展**，不是**屈伸**。
> 也就是说 2D 版本根本表达不了"迈腿"：腿的屈伸平面（矢状面）跟它的旋转轴（侧向轴）在 2D 里是同一个平面，
> 于是"走路"只能靠整体前倾 + 滑行。

3D 之后髋/膝的屈伸 = 绕**侧向轴**转，肢体在**矢状面**内摆动 —— 这才是迈腿。

### 5.2 世界轴约定

| 轴 | 含义 | 依据 |
|---|---|---|
| **+X** | 前（行走方向） | 适应度 `distance = torso.x − startX` |
| **+Y** | 上 | 重力 `(0, −9.81, 0)` |
| **+Z** | 角色侧向 | 画布横向映射到这里 |

**素材只有正面视图，没有深度** ⇒ 世界 X 一律置 0（诚实归零，不编造深度）；
画布 x → 世界 Z，且**取负**：`z = −(canvasX − centerPx)·px2m`。
（相机在 +X 看向 −X、up = +Y 时，屏幕右 = −Z；不取负会左右镜像。）

### 5.3 关节三轴语义（三处必须一致）

| 索引 | 轴 | 语义 | 力矩系数 |
|---|---|---|---|
| 0 | 绕 X | **外展 / 侧摆**（把下垂肢体往身体两侧抬） | ×0.60 |
| 1 | 绕 Y | **扭转**（绕肢体自身长轴） | ×0.35 |
| 2 | 绕 Z | **屈伸**（往前后摆 = **迈步主自由度**） | ×1.00 |

★ 这个口径必须同时守住三处：`brain.ts`（输出含义）、`ragdoll.driveMotors`（施加方向）、`sim.ts`（输入填装）。
**改一处不改另外两处 = 全身动作错乱，且不会有任何编译错误。**

关节最大力矩（`JOINT_MAX_TORQUE`，取自 MuJoCo `humanoid.xml` 的 actuator gear）：

```
颈 100   肩 100   肘 40   髋 200   膝 150   （N·m，再乘上表的三轴系数）
```

三轴系数是必要的：统一给同一个数会让"扭转"自由度过强 ⇒ 腿绕自己长轴乱转，看起来像抽筋。

### 5.4 马达必须自实现（Rapier 0.14 绑定不可靠 —— 本项目第 4 次踩坑）

**已确认不可用**：

| 现象 | 证据 |
|---|---|
| `configureMotorVelocity` 无可用增益区间 | 1→20 不出力；30 直接爆炸 |
| `ImpulseJoint.handle` 读回坏值 | 读回 `5e-324` |
| `SphericalImpulseJoint` 是**空类** | `dynamics/impulse_joint.d.ts:171` `class SphericalImpulseJoint extends ImpulseJoint {}` |
| 马达/限位源码里写着 | "Unsupported by this alpha release" |
| **关节冲量完全无法读回** | `rapier_wasm3d_bg.wasm.d.ts` 里 `rawimpulsejointset_*` 只有 `jointType`/`anchor`/`limits`/`motor` 配置，**没有任何 impulse 接口** |
| `jointType()` 读回走另一条绑定路径 | `RawGenericJoint.spherical()` **确实被调用**（`impulse_joint.js:415`）但读回报成 `GenericImpulseJoint` ⇒ **判据必须用行为，不能用类名** |

**自实现马达的两条硬不变量**（改之前先想清楚这两条）：

1. **限加速度**：`|imp| ≤ α·|err|·Ieff`，其中 `Ieff = 1/(1/Ic + 1/Ip)`
   （3D 版取两个刚体三个主惯量的最小值再合成，偏保守）。α = 0.35，限位回程时 0.7。

   > 为什么必须有：只按 τmax 限力矩、不限加速度，手臂惯量 ≈ 0.03 kg·m²，100 N·m 一个 1/120 s 步就打出
   > Δω ≈ 28 rad/s，而速度误差本身可能只有 1 rad/s ⇒ 显式积分的比例控制**必然振荡发散**。
   > 实测（`probe-spike`）：不限的话峰\|线速度\| 284.7 m/s、峰\|角速度\| 1244 rad/s —— 一个 70 kg 人形跑出音速。

2. **位置感知软限位**：只在**越界之后**才介入，回程速度按 `min(LIMIT_SOFT_ZONE, hi − lo)` 的斜坡。

   > ★★ **这里踩过一次最严重的坑，禁止改回去**：如果给软限位加"提前量"（`if (a > hi − zone)`，zone = 17°），
   > 膝的限位是 **[−145°, +2°]**，静止姿态 0° 恰好在 +2° 内侧 ⇒ **一开局就判定膝盖越界、全力往后掰**。
   > 实测躯干从 1.128 m 一路塌到 0.698 m，整个人形自己跪下去，而且"站桩"直接踩到摔倒阈值。
   > **提前量对小范围关节是灾难。**

### 5.5 ★ 被动姿态张力（`restTension`，默认 9.0）

**问题**：网络输出的目标是**角速度**，不是位置。「零输出」= 纯阻尼控制 —— 它能抵抗关节**运动**，
但**不抵抗静态力矩**：重力压着膝盖，只要膝盖不转，阻尼项就输出 0 力矩，膝盖便一路弯到限位。
实测零输出时躯干从 1.128 m 被压到 0.693 m（蹲姿），直接踩到摔倒阈值。

**修法**：在等效目标速度里叠加 `−k·θ`（k = `restTension`），把关节往初始姿态拉。

> ★ 为什么是"改目标速度"而不是"直接加一个弹簧力矩"：
> 直接加 `k·θ` 的弹簧力矩有显式积分稳定条件 `k < 2·Ieff/dt` —— 前臂 I ≈ 0.03、dt = 1/120 ⇒ k < 7.2 N·m/rad，
> 而要让 70 kg 人形站住需要的 k 是几十上百，**必然发散**。
> 改成写进目标速度后，它自动走上面那套 `α·|err|·Ieff` 的稳定性上限，**结构性稳定**。
> 物理含义也站得住：这就是 PD 控制的 P 项（角速度目标是 D 项），对应肌肉的静息张力/韧带刚度。

**k 的取值依据**（`probe-ground`，体重 687 N）：

| k | 静息接触力 | 占体重 | t=2s 躯干 y | CoM 撑在支撑区内 |
|---|---|---|---|---|
| 0（纯阻尼） | 423 N | 62% | 0.261 m | 2.25 s / 3 s |
| 3 | 527 N | 77% | 0.597 m | 2.25 s / 3 s |
| 6 | 606 N | 88% | 1.107 m | 2.25 s / 3 s |
| **9（当前默认）** | **720 N** | **105%** | **1.120 m** | **2.75 s / 3 s** |
| 12 | 725 N | 106% | 1.122 m | 3.00 s / 3 s |

判据：**静止站立时地面接触力应当 ≈ 体重**。k ≥ 9 才真正对账（k=6 只有 0.88 倍）。
再往上是饱和的，但张力越大网络越难克服（会压低步幅），故取 **9.0**。

### 5.6 确定性：必须 `buildWorld()` 整世界重建，不能只 `reset()`

**问题**：Rapier 的解算器会把上一轮的**累积冲量**存在关节里做暖启动，而 `reset()` 只清刚体位姿和速度。
实测（`probe-reset`）：同一份基因组连续重放，**从第 1 步就分叉**（不是第 2 步之后 ⇒ 不是混沌敏感性）。

**但"删关节再重建"也清不掉**（`verify-core` 对照）：剩下的 2.55e-3 m 偏差来自**地面接触**缓存。

**唯一有效的做法**：每次 `begin()` 都 `world.free()` + `new World` + `new Ragdoll`。

| 路径 | 同一基因组两次评估的偏差 |
|---|---|
| 仅 `reset()` | 1.84e-3 m ❌ |
| `buildWorld()` 整世界重建 | **0.00e+0 m** ✅ |

⇒ 这是"学不出走路"的**直接原因之一**：残留状态污染个体间适应度 + 噪声极大。

### 5.7 关节姿态的真源：旋转向量（exponential map）

- 关节角 = `quatToRotVec( q_parent⁻¹ ⊗ q_child )`，`|rv| ≤ π`，表达在**父体本地系**。
- 相对角速度 = 世界相对角速度用父体四元数逆旋转到本地。
- **不用欧拉角**：欧拉角有万向锁，且三轴语义会随姿态漂移。

关节锚点约束的刚度由 `solverIterations` 决定（`probe-ball` E 段，同一 5.0 N·m·s 冲量）：

```
iters  4 → 486 mm（撕裂）   8 → 65 mm   16 → 29 mm   32 → 9.5 mm
代价（单世界 2000 步） 10.6 / 10.5 / 14.2 / 23.6 µs 每步
⇒ 默认 16；要更硬的关节就 32（物理开销 +66%）
```

纯重力下锚点漂移只有 **2.6 mm**，且能自由摆出 Z 向位移 ⇒ 3 个转动自由度是**真实的**。

### 5.8 自碰撞全关

角色自己的刚体之间**永不互撞**（碰撞分组 `GROUPS_SELF` / `GROUPS_GROUND` 分离），只碰地面。
理由：人形自碰撞会让 ES 早期学出各种赖皮姿态（手臂撑住身体等），且接触数暴涨拖慢物理。

### 5.9 观测必须包含角速度（3D 的"平衡反馈"）

2D 版只有「躯干绕 Z 转角 + 绕 Z 角速度」两个标量。3D 之后换成
**躯干四元数 4 维 + 躯干角速度 3 维** —— 后者是平衡反馈的关键量，
**没有它网络感知不到自己在倒**（2D 版只有绕 Z 一个分量，等于瞎子）。

## 6. 观测 / 动作 / 频率规格

### 6.1 观测（70 维，`INPUT_LAYOUT`）

| 区间 | 内容 | 维 |
|---|---|---|
| 0–1 | 步态时钟 sin/cos | 2 |
| 2–5 | 躯干四元数 | 4 |
| 6–8 | 躯干线速度 (vx,vy,vz) | 3 |
| 9–11 | 躯干角速度 (wx,wy,wz) | 3 |
| 12 | 躯干高度 | 1 |
| 13 | 躯干侧向 z（走歪了多少） | 1 |
| 14–40 | 9 关节 × 3 轴**旋转向量**（父体本地） | 27 |
| 41–67 | 9 关节 × 3 轴**相对角速度** | 27 |
| 68–69 | 左右脚掌 y | 2 |

`INPUT_COUNT = 2+4+3+3+1+1+27+27+2 = 70` ✔

### 6.2 动作（27 维）

每关节 3 个数 = **目标角速度**（父体本地三轴），`tanh` 后 × `JOINT_MAX_SPEED` (= 9.0 rad/s)。
每个控制周期更新一次，而在物理步之间由马达持续施加力矩 ⇒ 力矩是**连续量**，不是脉冲。

### 6.3 频率与回合

```ts
physicsHz: 120        // 刚体-马达链的稳妥档
controlHz: 60         // 网络只在控制周期被调用（每周期 = 2 个物理步）
duration: 6           // 一次评估 6 s
gaitHz: 1.15          // 步态时钟频率（给网络一个节拍输入，更容易长出周期步态）
solverIterations: 16
fallHeightRatio: 0.62 // 躯干高度 < 初始 ×0.62 ⇒ 摔倒
fallAngle: 1.25       // tilt > 1.25 rad ⇒ 摔倒
```

## 7. 适应度设计

### 7.1 权重表（`sim.ts` 的 `W`，集中在一处方便调参）

| 项 | 权重 | 含义 |
|---|---|---|
| `distance` | 3.0 | **净前进距离**（torso.x − startX） |
| `velocity` | 0.6 | 前进速度积分（塑形，让早期就有梯度） |
| `upright` | 1.2 | **惩罚**不正立：`W × ∫(cos tilt − 1)dt ≤ 0` |
| `height` | 0.8 | 躯干离地高度偏差 |
| `lateral` | 1.0 | 侧向漂移 `∫|z|dt` |
| `energy` | 0.02 | 关节耗能 |
| `step` | 0.4 | 两侧脚掌交替触地（鼓励迈步而不是蹭） |
| `fall` | 2.0 | 摔倒一次性扣分 |
| `hit` | 4.0 | 战斗：命中一次 |
| `hurt` | 0.02 | 战斗：被击中（按出拳次数） |
| `approach` | 0.8 | 战斗：手贴近假人 `∫max(0, 1 − d/1.2)dt` |

### 7.2 三处**必须记住**的修正（这是"学不出走路"的第二大原因）

1. **`distance` 从"评估期内最远距离"改成净位移。**
   用最远距离时，往前扑倒滑出去也算分 ⇒ ES 学会了"扑"而不是"走"。
   （实测：最优个体直立占比 97% 却只前进 0.28 m，而当代最佳全程"摔倒=是"。）

2. **`upright` 从"奖励直立"改成"惩罚不直立"。**
   ★ 为什么不做成 `+1.2 × ∫cos`：那样"站着不动 6 秒"就白拿 7.2 分，会形成一个离"走得一般"很近的**局部最优**，
   ES 会直接卡在那里。改成惩罚后，站桩总分 = 0，任何倾斜/扑倒都从 0 往下扣，梯度方向正确。

3. **新增 `lateral`**：任务要求沿 +X 直走，偏出去要扣。

### 7.3 战斗适应度

```
W.hit × hits − W.hurt × hurts + W.approach × accClose
+ W.upright × (accUpright − elapsed) − W.height × accHeight
+ 0.5 × progress − (fallen ? W.fall : 0)
```

命中判定：`拳头到假人躯干的距离² < 0.68²` 且 `速度 > 1.0`。

## 8. 进化算法（`evolution.ts`）

**为什么不用 PPO/DQN**：那需要逐状态的价值估计和大量超参，动辄几十万步才出结果，还得拽进来一个深度学习框架（体积 + 复杂度都超标）。
进化策略在这类「低维连续控制 + 有明确标量分数」的问题上又稳又便宜：
不需要梯度、天然可并行、可随时中断查看、一段时间不用就能直接导出权重（基因组就是全部状态）、
种群本身带探索（不会像单个体 RL 那样卡在局部最优后彻底死掉）。

```ts
population: 48        // 每个个体一个独立 World
eliteFrac: 0.2
sigmaInit: 0.06       // ★ 3D 后必须降（原 0.28）
sigmaMin: 0.004
sigmaMax: 0.2
mutationProb: 0.12    // 每个参数被变异的概率
seed: 20261001        // 固定种子 ⇒ 结果可复现
```

**1/5 成功法则**：若超过 1/5 的子代比上一代好 ⇒ 步子太保守，放大 σ；否则缩小 σ。

### 8.1 ★ 高维 ES 学不动：初始化与 σ 尺度错配（第三个根因）

**症状**：σ 一路顶到上限、40 代最佳分在 1.6 附近乱跳（等于随机游走）。

**根因**：`randomGenome` 原来用统一 std = 1.2，而输入 70 维 ⇒ 第一层预激活 std ≈ 1.2·√70 ≈ 10，
tanh 全部饱和；且 σ = 0.28 比权重量级（≈0.12）还大两倍。

**修法**：
- `randomGenome` **按扇入缩放**：`s1 = scale/√inputs`，`s2 = scale/√hidden`；`b1/b2 = 0`（显式注明：初始行为 = 保持初始姿态）。
- 经验口径：**ES 的 σ 应当和权重量级同阶，被变异的参数比例应当 ~1/√n。**

## 9. 验收体系（每改一处物理，至少跑 `verify-core`）

### 9.1 `verify-core` —— 硬断言（全绿才算没坏）

覆盖 5 个板块：骨架自检 / 物理与确定性 / 适应度与进化 / 基因组存档 / 战斗阶段。
其中 3 条是"花钱买的"：

| 断言 | 为什么值得单列 |
|---|---|
| ★ 髋三轴各自可独立驱动 | 用来**取代**"关节类型 == SphericalImpulseJoint"的类名判据（类名判据是坏的，见 5.4） |
| ★ 躯干能真绕 X 翻滚（max\|q.x\| > 0） | 平面方案下这里**恒为 0** —— 这条就是"3D vs 2D"的机器判据 |
| ★ 同一基因组两次独立评估偏差 = 0 | 确定性（见 5.6），同时保留"仅 reset() 确实有偏差"的对照断言 |

### 9.2 `probe-*` —— 各回答一个物理问题

| 工具 | 回答的问题 | 关键读数 |
|---|---|---|
| `probe-ball` | 球关节锚点牢不牢？求解器迭代数的代价？ | 锚点漂移 vs iters；纯重力漂移 2.6 mm |
| `probe-motor` | 马达出力对不对？质量对不对？ | 读回质量偏差 < 1e-6 kg |
| `probe-spike` | 满功率应力下会不会炸？ | 峰 \|v\| / 峰 \|ω\| / 最大超限 |
| `probe-reset` | 暖启动缓存清得掉吗？ | 重放第 1 步就分叉 ⇒ 必须整世界重建 |
| `probe-fitness` | 适应度地貌长什么样？ | 零输出 vs 恒定偏置的分数差 |
| `probe-fight` | 拳头几何上够得着假人吗？ | 逐控制周期打印手的位置/速度/距离 |

### 9.3 ★ `probe-forces` —— 逐组件受力回读（力审计）

> **为什么不用截图**：截图只能证明"看起来像在动"，证明不了"力是怎么走的"。

**前提**：Rapier 0.14 **完全没有关节冲量/反力的读回接口** ⇒ 关节力只能**反推**。

三条可测的量做牛顿收支：

```
① 重力      = m·g                        （已知）
② 接触力    = contactImpulse(i) × normal()（从接触流形读，方向按 flipped 定）
③ 马达力矩  = Ragdoll.motorImpulse        （我们自己施加的，直接记账）
⇒ 关节反作用力 = 动量变化 − 重力 − 接触力（残差）
```

**五组读数**：

| 段 | 内容 |
|---|---|
| [A] | **独立校验**：全身动量收支 `Σ m·a = M·g + Σ 接触力`（关节力与马达力矩都是内力，整体自动抵消） |
| [B] | 逐刚体：质量 / 重量 / 接触力 / 关节合力 / m·a / \|m·a\|÷重量 |
| [C] | **关节传递力（子树动量收支法）** —— 力从地面沿骨链传到头的路径图 |
| [C2] | **闭式校验**：躯干是树根、**与地面无接触**，故 `m·a + m·g·ŷ + Σ关节力 = 0` |
| [D] | 执行器读数：每关节每轴的实际力矩 / 上限 / 饱和率 |
| [E] | 重心控制：CoM、水平修正所需的力、脚底摩擦上限 |

**判据（站桩，窗口 1.5–2.5 s，体重 687 N）**：

```
[A] Σ接触力(流形) = 719.8 N     Σ接触力(动量法) = 686.5 N     一致到 4.9%  ✔
    ★ 为什么不是 0：contactImpulse 里含求解器的**位置偏置冲量**（穿透恢复），
      它被计入流形读数但不产生净动量变化 ⇒ 流形法系统性偏高几个百分点。
      两法一致到 5% 以内即可认为接触读数可信（竖直方向与摩擦无关，最干净）。
[C2] 躯干残差 = (-3.3, −33.4, −0.4) N ⇒ 4.9%  ✔（继承同一个接触偏置）
```

**读数（站桩）—— 这就是"力是怎么走的"**：

| 关节 | 子侧质量 | 传递力 | \|F\| | 物理解释 |
|---|---|---|---|---|
| neck | 5.67 kg | (−0.7, **+55.6**, 0.0) | 55.6 N | = 头+颈自重 56 N ✔ |
| shoulder_l | 3.50 kg | (−0.3, **+34.3**, 0.1) | 34.3 N | = 上臂+前臂自重 34 N ✔ |
| elbow_l | 1.54 kg | (−0.1, **+15.1**, 0.1) | 15.1 N | = 前臂自重 15 N ✔ |
| hip_l | 11.27 kg | (−0.1, **−257.0**, −0.1) | 257.0 N | 子侧地面反力 368 − 腿自重 111 |
| knee_l | 4.27 kg | (−0.0, **−325.6**, −0.0) | 325.6 N | 子侧地面反力 368 − 小腿自重 42 |

下肢的 257 N / 326 N **不是**关节自身"重"，而是**该关节要替上半身扛的差**：
地面反力比这条腿自身重得多，多出来的部分必须由**髋/膝向上传递**。
两腿经髋向上托起的力合计 498.7 N，上半身实际重量 465.6 N，差 33.1 N —— 正是那个接触偏置。

**执行器（站桩 vs 走路 25 代后）**：

| 关节·轴 | 站桩力矩 | 走路力矩 |
|---|---|---|
| hip_r · 屈伸 | 2.2 / 200 N·m（1%） | **−47.8 / 200 N·m（24%）** |
| hip_l · 屈伸 | 2.3 / 200 N·m（1%） | −32.8 / 200 N·m（16%） |
| knee_l · 屈伸 | −2.1 / 150 N·m（1%） | 11.2 / 150 N·m（7%） |

⇒ 站桩时全部执行器饱和率 ≤ 11%（**干活的是被动姿态张力**，不是马达）；
走路时髋的屈伸轴升到 24% —— **这才是"迈腿"的执行器**。

**重心控制**：[E] 段给出 `CoM`、水平修正所需的力 `Σ 接触力·x̂`、脚底摩擦上限 `μ·N`。
★ 结构性限制：**本骨架没有踝关节**（脚与小腿一体化）⇒ 脚掌无法单独施力矩，
水平方向的 CoM 修正**只能靠脚底摩擦**（μ = 1.0 时上限 ≈ 体重），平衡只能靠髋/膝/躯干挪 CoM。
