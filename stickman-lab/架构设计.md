# stickman-lab 架构设计

> **项目定位**：一个**离线/在线可跑的 3D 物理人形实验室**。最终交付物是**一具能正常行走、能主动攻击的敌人**，
> 以「特殊 boss」的形式移植回《全新的游戏》。
>
> 本文档是**架构真源**：模块边界、接口契约、关键决策的实测依据、验收口径、以及移植路线。
> 改代码前先读第 5 章（设计决策）与第 9 章（验收），那里写的都是花钱买来的教训。

## 1. 目标与定位

### 1.1 最终目标（用户定调）

> "我的这个机器人仿真的目标是做出**能正常行走和攻击的敌人**，作为**特殊 boss** 进全新的游戏中。"

拆成三个可验收的子目标：

| # | 子目标 | 验收口径 |
|---|---|---|
| G1 | **正常行走** | 连续 ≥ 6 s 不摔倒（`tilt` 全程 < `fallAngle`），沿 +X 净位移 ≥ 3 m，侧向漂移 ∫\|z\|dt 小 |
| G2 | **主动攻击** | 对目标假人能打出命中（`hits ≥ 3 / 回合`），而不是站着挨打 |
| G3 | **可移植** | 导出基因组 + 驱动器能在本体游戏里跑，不需要重新训练 |

### 1.2 为什么独立成项目

- **不能边开发边训练**：一次 40 代训练是 16 万物理步，必须离屏跑。把学习逻辑塞进本体会让本体的帧率变成噪声源。
- **接口要干净**：本体是"搜打撤"玩法，实验室研究的是"骨链控制"这一个问题。
- **验收要机器化**：独立项目才能长出一整套 `tools/*.probe.ts`（见第 9 章），每改一处物理都能一键回归。

### 1.3 交付物（三件套，缺一不可）

1. **基因组**：`brain` 的 **4228** 个 float32，base64 + JSON 外壳 ≈ **22.1 KB**（raw 16.5 KB；`verify-core` [4] 段实测）。
2. **驱动器**：`Ragdoll` + `Sim` 的最小闭包（本文件第 2 章列的接口）。
3. **验收工具**：`verify-core` + `probe-*`，保证移植后行为可复现。

## 2. 系统边界与移植契约

### 2.1 移植时**需要**的（内核，约 4 个文件）

```
core/skeleton.ts  骨架几何（parts.json → 刚体/关节/质量/限位）
core/ragdoll.ts   世界 + 刚体 + 球关节 + 自实现三轴马达 + 姿态读数
core/brain.ts     MLP 前向（零分配）
core/sim.ts       把上面三者接起来 + 适应度
core/genome.ts    基因组打包/解包
```

### 2.2 移植时**不需要**的

`evolution.ts`（训练用）、`viewer.ts`（渲染）、`hud.ts`（面板）、`tools/*`（验收）。

> ★ 这意味着**包体可以砍掉一半**：训练期需要的 48 个 World 在游戏里只要 1 个。

### 2.3 Boss 控制器对外契约（`BossController`）

| 方向 | 接口 | 说明 |
|---|---|---|
| 输入 | `setTarget(x, z)` | 索敌目标；由本体 AI 决定打谁/追谁 |
| 输入 | `setMode('patrol' \| 'chase' \| 'attack')` | 状态机由本体驱动，实验室只负责**运动学执行** |
| 输出 | `rootPos() / rootQuat()` | 把躯干刚体位姿喂给本体（用于 UI 血条、音效定位、索敌） |
| 输出 | `phase` | 步态时钟相位（0..1），本体拿它做脚步声/攻击前摇同步 |
| 输出 | `hits` | 命中事件计数，本体据此扣玩家血 |
| 边界 | **不碰** | 伤害数值、掉落、遗物、对话 —— 全部留在本体 |

★ 关键约束：**实验室不产生玩法级副作用**。它只输出"身体做了什么"，不输出"游戏发生了什么"。

## 5. 关键设计决策（每条都附实测依据）

### 5.1 必须是真 3D 球关节（用户定调）

**决策**：所有关节是 `JointData.spherical()`，六自由度全开（不锁任何平移/旋转轴），每关节 3 个转动自由度。

**为什么 2D 方案被废弃**（原话：「跑一个 2d 的机器人没有任何意义」）：

> 2D 版把"前进"和"侧向"塞进了同一个轴：所有刚体锁 `enabledTranslations(T,T,F)` + `enabledRotations(F,F,T)`，只能绕 Z 转。
> 而绕 Z 转 = 肢体在画布平面内左右摆 = **外展**，不是**屈伸**。
> 也就是说 2D 版本根本表达不了"迈腿"：腿的屈伸平面（矢状面）跟它的旋转轴（侧向轴）在 2D 里是同一个平面，
> 于是"走路"只能靠整体前倾 + 滑行。

3D 之后髋/膝的屈伸 = 绕**侧向轴**转，肢体在**矢状面**内摆动 —— 这才是迈腿。

### 5.2 世界轴约定

| 轴 | 含义 | 依据 |
|---|---|---|
| **+X** | 前（行走方向） | 适应度 `distance = torso.x − startX` |
| **+Y** | 上 | 重力 `(0, −9.81, 0)` |
| **+Z** | 角色侧向 | 画布横向映射到这里 |

**素材只有正面视图，没有深度** ⇒ 世界 X 一律置 0（诚实归零，不编造深度）；
画布 x → 世界 Z，且**取负**：`z = −(canvasX − centerPx)·px2m`。
（相机在 +X 看向 −X、up = +Y 时，屏幕右 = −Z；不取负会左右镜像。）

### 5.3 关节三轴语义（三处必须一致）

| 索引 | 轴 | 语义 | 力矩系数 |
|---|---|---|---|
| 0 | 绕 X | **外展 / 侧摆**（把下垂肢体往身体两侧抬） | ×0.60 |
| 1 | 绕 Y | **扭转**（绕肢体自身长轴） | ×0.35 |
| 2 | 绕 Z | **屈伸**（往前后摆 = **迈步主自由度**） | ×1.00 |

★ 这个口径必须同时守住三处：`brain.ts`（输出含义）、`ragdoll.driveMotors`（施加方向）、`sim.ts`（输入填装）。
**改一处不改另外两处 = 全身动作错乱，且不会有任何编译错误。**

关节最大力矩（`JOINT_MAX_TORQUE`，取自 MuJoCo `humanoid.xml` 的 actuator gear）：

```
颈 100   肩 100   肘 40   髋 200   膝 150   （N·m，再乘上表的三轴系数）
```

三轴系数是必要的：统一给同一个数会让"扭转"自由度过强 ⇒ 腿绕自己长轴乱转，看起来像抽筋。

### 5.4 马达必须自实现（Rapier 0.14 绑定不可靠 —— 本项目第 4 次踩坑）

**已确认不可用**：

| 现象 | 证据 |
|---|---|
| `configureMotorVelocity` 无可用增益区间 | 1→20 不出力；30 直接爆炸 |
| `ImpulseJoint.handle` 读回坏值 | 读回 `5e-324` |
| `SphericalImpulseJoint` 是**空类** | `dynamics/impulse_joint.d.ts:171` `class SphericalImpulseJoint extends ImpulseJoint {}` |
| 马达/限位源码里写着 | "Unsupported by this alpha release" |
| **关节冲量完全无法读回** | `rapier_wasm3d_bg.wasm.d.ts` 里 `rawimpulsejointset_*` 只有 `jointType`/`anchor`/`limits`/`motor` 配置，**没有任何 impulse 接口** |
| `jointType()` 读回走另一条绑定路径 | `RawGenericJoint.spherical()` **确实被调用**（`impulse_joint.js:415`）但读回报成 `GenericImpulseJoint` ⇒ **判据必须用行为，不能用类名** |

**自实现马达的两条硬不变量**（改之前先想清楚这两条）：

1. **限加速度**：`|imp| ≤ α·|err|·Ieff`，其中 `Ieff = 1/(1/Ic + 1/Ip)`
   （3D 版取两个刚体三个主惯量的最小值再合成，偏保守）。α = 0.35，限位回程时 0.7。

   > 为什么必须有：只按 τmax 限力矩、不限加速度，手臂惯量 ≈ 0.03 kg·m²，100 N·m 一个 1/120 s 步就打出
   > Δω ≈ 28 rad/s，而速度误差本身可能只有 1 rad/s ⇒ 显式积分的比例控制**必然振荡发散**。
   > 实测（`probe-spike`）：不限的话峰\|线速度\| 284.7 m/s、峰\|角速度\| 1244 rad/s —— 一个 70 kg 人形跑出音速。

2. **位置感知软限位**：只在**越界之后**才介入，回程速度按 `min(LIMIT_SOFT_ZONE, hi − lo)` 的斜坡。

   > ★★ **这里踩过一次最严重的坑，禁止改回去**：如果给软限位加"提前量"（`if (a > hi − zone)`，zone = 17°），
   > 膝的限位是 **[−145°, +2°]**，静止姿态 0° 恰好在 +2° 内侧 ⇒ **一开局就判定膝盖越界、全力往后掰**。
   > 实测躯干从 1.128 m 一路塌到 0.698 m，整个人形自己跪下去，而且"站桩"直接踩到摔倒阈值。
   > **提前量对小范围关节是灾难。**

### 5.5 ★★ 马达 = 位置环 PD（`kP = 48`，配套稳定性护栏 `motorAlpha = 1.0`）

**这一节是全项目最贵的一次修正：把"站不住"从"控制问题"改判为"硬件参数问题"。**

#### (1) 从"角速度目标"改成"位置目标"

**原问题**：网络输出的目标是**角速度**。「零输出」= 纯阻尼控制 —— 它能抵抗关节**运动**，
但**不抵抗静态力矩**：重力压着膝盖，只要膝盖不转，阻尼项就输出 0 力矩，膝盖便一路弯到限位。
实测零输出时躯干从 1.128 m 被压到 0.693 m（蹲姿），直接踩到摔倒阈值。

**修法**（`ragdoll.driveMotors`）：

```
θ_ref = cmd ×（cmd ≥ 0 ? posRefScale·hi : posRefScale·(−lo)）   // 网络给的目标角，非对称斜率
err   = kP·(θ_ref − θ) − kD·ω_rel                              // 等效目标角速度
τ     = clamp(err · τmax / JOINT_MAX_SPEED, ±τmax)
```

★ **`cmd = 0` 时它退化为旧公式**（`err = −kP·θ − kD·ω_rel`，正是旧的 `target = −k·θ`）
⇒ **严格泛化**：零输出的形式一字没变，但网络第一次拿到了位置通道。
★ 非对称斜率是为了同时保住「`cmd = 0 ⇒ θ_ref = 0`」与「`|cmd| = 1 ⇒` 顶到量程 90%」——
膝 `[−145°, +2°]` 这种非对称关节必须这么映射。

#### (2) ★★ `kP` 为什么从 9 提到 48（`probe-posture` [B2]，6 s 回合）

`k=9` 是按**"静息接触力 ≈ 体重"**这一条标定的（6→88%、9→105%、12→106% 饱和）。
**但那条判据根本管不到"抗屈曲"**。真判据是「绑定姿态的 CoM 投影本来就在支撑多边形内
（A9 已验）⇒ 关节足够硬时它是一个**静定的刚体站姿**，应该永远站着」。

| kP（α=1.0） | 零输出存活 | ξz 峰值 | 域内占比 | 峰\|v\| |
|---|---|---|---|---|
| 9 | 1.40 s | 1.88 | 69% | 2.6 m/s |
| 24 | 1.73 s | 3.33 | 70% | 2.1 m/s |
| **48（当前默认）** | **6.00 s 跑满** | **0.27** | **93%** | **0.7 m/s** |
| 90 | 6.00 s 跑满 | 0.20 | 100% | 0.2 m/s |

★ 塌陷机制（[C2] 时间轴回溯）：**髋关节被重力压开 83°~96°，直接"劈叉"塌下去** ——
膝关节几乎不动（<16°），所以不是"倒"，是**关节柔性造成的屈曲**。
★ 取 48 而不是 90：抗屈曲需要 kP ≥ ~48，再往上收益递减，且会把人偶变成纯位置伺服的木偶、
丢掉"关节柔性"这个对战斗姿态有用的自由度。
★ 静力接触力不受影响（那条曲线在 k≥12 就饱和在 ~106% 体重）。

#### (3) ★★ 稳定性护栏 `α` 从 0.35 提到 1.0 —— 它一直是**真正的瓶颈**

护栏 `|imp| ≤ α·|err|·Ieff` 给出的**有效关节刚度**是：

```
有效刚度 = kP · min( τmax/9 ,  α·Ieff/dt )
                  └ 设计值 ┘   └ 护栏值 ┘
```

髋外展：设计值 13.3，而 α=0.35 时护栏值只有 `0.35×0.083×120 = 3.49` ⇒ **只用了 26% 的力气**。
实测（`motorDemand` / `motorImpulse` 回读，全 36 轴求和）**实际/想要 = 22%**。

| α（kP=9） | 零输出存活 | τ应用/τ需求 |
|---|---|---|
| **0.35（旧）** | 1.28 s | **22%** |
| 1.0 | 1.40 s | 37% |
| 1.6 | 1.85 s | 52% |

★ 为什么 **1.0 是有依据的、不是"把安全阀拧松"**：本护栏的语义是"每步最多吃掉多少比例的
相对角速度误差"。α = 1 恰好是**一步收敛**（一步后误差归零且不过冲），α = 2 才是显式 P 控制的
振荡边界。0.35 是当年给"角速度目标控制器"定的（那时轻肢体 `I≈0.03`、τmax=40 一步就能打出
Δω=28 rad/s），换位置环之后它就成了性能杀手。
★ 实践上不会失控：kP 高时 τ 会先被 **τmax** 夹住（膝 Δθ=2.28 rad 时 err=109、护栏允许
5.1 N·m·s，τmax 只给 1.25 N·m·s）⇒ 真正生效的是物理力矩上限。
★ 且实测**峰线速度随 α 提高而下降**（3.4 → 0.1 m/s）：关节越硬，人偶越不抖。

> ★ 这条的通用教训（**值得移植到别处**）：
> **一个"按最坏情况定的安全余量"会在系统演化后变成瓶颈，而且它静默** ——
> 从 `motorImpulse` 看不出任何异常（它已经是被削过的值，看起来"很合理"）。
> ⇒ 必须让人能回读 **"想要 / 实际"这一对**（`motorDemand`），并且把 α 做成**可扫描的旋钮**。


### 5.6 确定性：必须 `buildWorld()` 整世界重建，不能只 `reset()`

**问题**：Rapier 的解算器会把上一轮的**累积冲量**存在关节里做暖启动，而 `reset()` 只清刚体位姿和速度。
实测（`probe-reset`）：同一份基因组连续重放，**从第 1 步就分叉**（不是第 2 步之后 ⇒ 不是混沌敏感性）。

**但"删关节再重建"也清不掉**（`verify-core` 对照）：剩下的 2.55e-3 m 偏差来自**地面接触**缓存。

**唯一有效的做法**：每次 `begin()` 都 `world.free()` + `new World` + `new Ragdoll`。

| 路径 | 同一基因组两次评估的偏差 |
|---|---|
| 仅 `reset()` | 1.84e-3 m ❌ |
| `buildWorld()` 整世界重建 | **0.00e+0 m** ✅ |

⇒ 这是"学不出走路"的**直接原因之一**：残留状态污染个体间适应度 + 噪声极大。

### 5.7 关节姿态的真源：旋转向量（exponential map）

- 关节角 = `quatToRotVec( q_parent⁻¹ ⊗ q_child )`，`|rv| ≤ π`，表达在**父体本地系**。
- 相对角速度 = 世界相对角速度用父体四元数逆旋转到本地。
- **不用欧拉角**：欧拉角有万向锁，且三轴语义会随姿态漂移。

关节锚点约束的刚度由 `solverIterations` 决定（`probe-ball` E 段，同一 5.0 N·m·s 冲量）：

```
iters  4 → 486 mm（撕裂）   8 → 65 mm   16 → 29 mm   32 → 9.5 mm
代价（单世界 2000 步） 10.6 / 10.5 / 14.2 / 23.6 µs 每步
⇒ 默认 16；要更硬的关节就 32（物理开销 +66%）
```

纯重力下锚点漂移只有 **2.6 mm**，且能自由摆出 Z 向位移 ⇒ 3 个转动自由度是**真实的**。

### 5.8 自碰撞全关

角色自己的刚体之间**永不互撞**（碰撞分组 `GROUPS_SELF` / `GROUPS_GROUND` 分离），只碰地面。
理由：人形自碰撞会让 ES 早期学出各种赖皮姿态（手臂撑住身体等），且接触数暴涨拖慢物理。

### 5.9 观测必须包含角速度（3D 的"平衡反馈"）

2D 版只有「躯干绕 Z 转角 + 绕 Z 角速度」两个标量。3D 之后换成
**躯干四元数 4 维 + 躯干角速度 3 维** —— 后者是平衡反馈的关键量，
**没有它网络感知不到自己在倒**（2D 版只有绕 Z 一个分量，等于瞎子）。

### 5.10 ★ 躯干是**一张贴图 + 骨架折叠**（蒙皮），不是把贴图切成条

**用户定调（原话）**：「这不受我要的效果，身体**只有一个纹理**，只是可以被关节折叠」。

**曾经的错误实现 —— "蜈蚣"**：躯干切成 4 段刚体后，`viewer` 仍**逐刚体**建 mesh，每段各画一整张
`PlaneGeometry(w, h)` ⇒ 同一张胸甲贴图被沿脊柱重复画 4 遍叠起来，看起来像蜈蚣。

**决策**：躯干 4 段只建**一个 mesh、一张完整纹理**；

```
PlaneGeometry(w, H, 1, K·SUB)   K = spineSegments = 4, SUB = 6
  ⇒ 24 行 × 2 列 = 50 顶点
  ⇒ 只替换 position 缓冲，UV / index 原样复用（整图连续覆盖，不裁不切不拉伸）
  ⇒ mesh.frustumCulled = false（顶点由蒙皮算出，three 的包围盒不会自动更新）
```

**绑定与蒙皮**（`viewer.ts` 里的**模块级纯函数**，故意不含 WebGL ⇒ 可以离屏逐条验收）：

| 函数 | 职责 |
|---|---|
| `buildSkinBinding(sk, segIdx, sub)` | 每顶点算归属段 `s0/s1`、权重 `w1`、绑定姿态位置 `bindPos`、两段局部位移 `loc0/loc1` |
| `skinPositions(b, segT, segR, out)` | 每帧：`pos = w0·(T_s0 + R_s0·loc0) + w1·(T_s1 + R_s1·loc1)` |
| `groupPlates(sk)` | **"一块板 = 一个组件"的唯一真源** ⇒ `{plain, skinned}` |
| `bindSegPositions` / `identitySegRotations` | 绑定姿态自检用 |

**★ 关键数学推导（决定了"不需要 dual-quaternion"）**：
绕 Z 弯（前后弯）时，板内横向偏移 `d` 沿的是 **Z 轴 = 旋转轴** ⇒ `d` 在旋转下不变 ⇒

```
p_s − p_{s+1} = (R_s − R_{s+1})·(0, a, 0)      模长 = 2·sin(θ/2)·|a|
                                              a = 顶点离关节面的高度差
```

- `a = 0`（顶点**正好落在关节面上**）⇒ 两段候选位置**严格重合** ⇒ LBS 无误差、既不重叠也不裂开
  （`probe-skin` [E1] 实测 **5.6e-8 m**）。
- 离关节处的"折痕圆化"深度上界 = `(1/16)·2sin(θ/2)·segLen`（θ = 25° 时上界 5.44 mm，实测 4.84 mm）。

⇒ 够用，**不需要 dual-quaternion 蒙皮**。

**硬不变量**：**护甲板数 = 素材组件数（10），与刚体数（13）无关。**
躯干 4 段合成 1 块蒙皮板；其余 9 个组件各 1 刚体 1 块单片板。
`viewer` 构造末尾自检，不符即 warn；`probe-skin` [I] 段把它变成硬断言。

### 5.11 ★★ 站立可行性的硬结论（回答"能不能靠调重心站住"）

> 推导与验收在 `tools/probe-stability.ts` 与 `tools/probe-push.ts` —— **纯解析 / 单世界短时物理，
> 不碰浏览器、不碰 GPU、不开 DevTools**（用户在玩游戏时也能跑）。

**先砸掉三个会带偏方向的直觉**：

1. **CoM 没有直接驱动器。"调重心" ≡ "调 CoP" ≡ "调地面反力"，是同一个自由度。**
   关节力矩是**内力对**，对 CoM 的净贡献恒为 0 ⇒ 改 CoM 加速度只能靠合外力（重力固定 + 地面反力）
   ⇒ "能调多少"完全由**支撑域**决定，与控制律多聪明无关。
2. **"CoM 投影落在支撑多边形内"是错的判据**（静力近似，比真约束宽得多）。
   真约束是倒立摆 `ẍ = ω²(x − p)`；判据是 **DCM（捕获点）`ξ = x + ẋ/ω` 在域内**。
   ξ 越界后**任何 p 都救不回来** ⇒ 只能迈步。
3. **躯干直立 ≠ 不摔。** 整体像棍子竖直平移倒下时，躯干倾角**始终 ≈ 0**。

**本骨架实测常数**：

| 量 | 值 | 备注 |
|---|---|---|
| CoM（绑定姿态） | `(0, **0.9659**, 0.0055)` m | 质量加权，按 collider `offsetY + comY` |
| `p_max` 前后 / 侧向（凸包） | **0.1100** / 0.2662 m | 前后才是走路方向的约束 |
| `ω = √(g/z_c)` | **3.1869** rad/s | τ = 1/ω = **0.3138 s**（DCM 每 τ 涨 e 倍） |
| 最大可控 CoM 加速度 `ω²·p_max` | 1.1174 m/s²（0.114 g） | |
| `x = 0` 时可刹 CoM 速度 `ω·p_max` | **0.3506 m/s** | 抓地速度上限 |
| 摩擦上限 `μ·N` | 687 N | 刹 0.1 m/s 只需 **10.2 ms** ⇒ **摩擦从来不是瓶颈** |

⇒ **站立不动 ⟺ |ẋ| ≲ 0.35 m/s。走路（~1 m/s）在数学上不可能靠调 CoP 救回 —— 站与走是两个域。**

**★★ 凸包是"主动"可达域，直接拿它当阈值会把平衡权限高估 4 倍**（`probe-push` [Z] 段）：

两脚**等载荷**时，净 CoP = 两脚 CoP 的平均值 ⇒ 其范围 = **单只脚的宽度**，而**不是站姿宽度**：

| 方向 | 被动（等载荷） | 主动（需差动卸载一只脚） | 被动占比 |
|---|---|---|---|
| 前后 X | ±0.110 m | ±0.110 m | **100%**（两脚同向，无损失） |
| 侧向 Z | **±0.070 m** | ±0.266 m | **26%** |

⇒ **没有任何控制器时，侧向可调范围只有 7 cm。** 想把侧向域撑开**必须主动差动分配载荷** ——
那是控制任务，不是几何事实。想在被动下变大，只能**加宽脚掌的侧向宽度**。

★ 实测印证（`probe-push` A5 / `diag 9`）：`restTension = 9`、**零命令零扰动**，`ξz` 随步态缓慢发散：

```
 t(s)   胸腔y   胸腔倾角°   CoM z    ξz
 0.00   1.429      0.0     0.005   0.005
 0.75   1.410      5.7     0.032   0.035
 1.00   1.379      3.9     0.036   0.053
 1.25   1.211     29.9     0.090   ★0.216   ← 越过被动域 0.070 后立刻翻

```

2.5 s 内**侧向 ξz 峰值 0.999（= 被动域 0.070 的 14 倍）**，胸腔 1.379 → **0.196 m**。
⇒ **"静息就站不住"不是调参问题，是侧向余量本来就没有。**

**★ 设计敏感度（选型用）**：`v_catch = √(g/z_c)·p_max`

- `∂v/∂p_max = ω = 3.187` —— **线性**收益；
- `∂v/∂z_c = −ω·p_max/(2z_c) = −0.182` —— **开方**收益。

⇒ 差 **17.6 倍**：**脚掌加长 1 cm ≈ 重心降低 17.6 cm。** 预算别花在"降重心"上。
（脚掌长 0.220 m = 身高 12.2%，解剖值应 ≈ 15% ⇒ 短 18.5%；且**无踝关节**。）

> ★★ **修正（`probe-posture` [B3]）**：上面这条是 `v_catch = ω·p_max` 的**解析上限**，
> 前提是**有东西在把 CoP 开到域边缘**。零输出（没有任何重心控制）时脚长 +80%，
> 被动抗扰阈值**一点没动**（0.03 → 0.03 m/s）。
> ⇒ **"脚太短"确实限制了天花板，但它不是"现在站不住"的原因**；

**★ 观测 / 适应度体检（"直立率高但不前进"的根因）**

- ~~观测 88 维里**没有 CoM / CoM 速度 / CoP / DCM / 双脚载荷分配** ⇒ 策略在**原理上**拿不到重心。~~
  **（当时的观测口径；现已补重心块 6 维 ⇒ 94 维，见 6.1.1。这条诊断本身是对的。）**

  而胸腔只占 **12.4%** 质量、中心离 CoM **0.4635 m** ⇒ 代理极弱。
- ⇒ 不是调参问题，是**目标函数在优化代理量**。`probe-push` B3 已证明"调增益"方向不对

### 5.12 ★★ 发力质量：把"抽风式频繁发力"变成一个数

> **用户观察（原文）**：「这近乎抽风的频繁发力，现实中的人是不怎么需要频繁抽风发力的」。

这句话是对的，而且**必须先量化再谈优化** —— "抽风"不是形容词，它有三个可测的侧面
（`probe-posture` [C3] 段）：

| 侧面 | 定义 | 物理含义 |
|---|---|---|
| ① 发力强度 | 每物理步 `Σ\|τ\|` 的均值（N·m） | 使了多大劲 |
| ② 抖动 | `Σ\|τ_t − τ_{t−1}\| / dt`（N·m/s） | 力矩有多"毛" |
| ③ 换向频率 | 每轴每秒 `τ` 变号次数（Hz） | 有多"频繁" |

| 基因组 | 存活 | ① Σ\|τ\| | ② 抖动 | ③ 换向 | ⑤ Σ(Δτ)² | 抖动罚 | 适应度 |
|---|---|---|---|---|---|---|---|
| **① 零基因组（= 什么都不做）** | **3.50 s（跑满）** | **3792** | **66** | **2.83 Hz/轴** | **188** | **−0.02** | **+5.11** |
| ② 随机基因组 scale=1 | 0.60 s | 174 752（**46×**） | 103 642（**1570×**） | 24.49（**8.7×**） | 4.17e6（**22169×**） | **−417** | −436.22 |
| ③ 随机基因组 scale=3（抽风） | 0.38 s | 213 401（56×） | 138 530（2100×） | 29.79（10.5×） | 6.08e6 | −608 | −617.88 |
| ④ 站桩训练 best | 3.50 s | 4754 | 297 | 5.88 | 376 | −0.04 | +5.14 |

> 口径：默认 `node tools/run.mjs probe-posture`（3.5 s 回合，确定性 seed ⇒ 可复现）。
> ⑤ = `W.smooth` 实际乘的**抖动积分**（(N·m)²），"抖动罚" = `W.smooth × Σ(Δτ)²`。
> ★ ④ 是"学出来的"最好个体 —— 分数与零输出持平（+5.14 vs +5.11）。
> ★★ **W.smooth 上线后的前后对比**（同一 seed、同一硬件）：④ 的 Σ\|τ\| **6105 → 4754**、
> 换向 **6.26 → 5.88 Hz/轴** ⇒ 抖动罚确实让"学出来的解"少使了力气，
> 且**分数没掉**（+5.15 → +5.14）：这是"用更少力气维持同样结果"的直接证据。

**⇒ "发力多少"与"站得多好"在这套硬件上是负相关的。** 不是"力气不够"，是"力气用错了地方"。

**★ 为什么真人不抽风（机理）**：倒立摆的失稳时间常数 `τ = 1/ω = 0.31 s`
⇒ 需要的是**小幅、连续**的踝/髋修正（人类 COP 摆动主要落在 **0.5~2 Hz**，不是几十 Hz）。
抽风式的高频大力 = 给系统灌高频能量：把自己顶出支撑域 + 把接触抖散。
本骨架零输出时的换向频率实测 **2.83 Hz/轴** —— 那正是"残余摆动 + 接触抖动"的自然频带，
也就是"不抽风"的参照；抽风个体是它的 ~10 倍。

**★★ 由此得到的适应度补丁（已落地）**：

`W.energy = 0.02 × ∫Σout²` **罚不动这件事** —— 它量的是"出力大小"，**不量抖动**。
一个高频小幅来回抽的控制器 `Σout²` 可能并不大，但 `dτ/dt` 极大。
⇒ 已补 **`W.smooth = 1e-4 × Σ(Δτ)²`**（抖动积分，见 §7.5；判据 `C3a`/`C3b`）。
★ 为什么用**力矩**而不是网络输出：力矩里已经含了 `−kD·ω_rel` 这个反馈项，
用输出会漏掉"网络命令很平滑、但关节实际在硬顶"的那种抽风。
★ 标定不是拍脑袋：静息 Σ(Δτ)² = 188 ⇒ 罚 **−0.02 分**（可忽略）；抽风 4.17e6 ⇒ 罚 **−417 分**（压死）。

### 5.13 ★★ 分通道稳定权限回读：「各关节到底啥情况」（`probe-coact`）

> 用户提问：「回读看看各个关节到底啥情况 / **能不能腰部腿部同时发力使自己稳定** / 甚至胳膊也需要发力？」
> `probe-forces` 只回答"静息时每个关节出了多大力"（≤7% 饱和），**没回答"能不能拿来稳定"**。
> 本节是那三个问题的机器答案（`npm run coact`，9 条断言全绿）。

#### (1) 判据框架：稳定性只看 ξ，力矩是内力对

关节力矩是**内力对**，整体对 CoM 净贡献恒为 0 ⇒ **它自己进不了 ξ**。能进 ξ 的只有两条通道：

| 通道 | 谁有 | 物理含义 |
|---|---|---|
| **搬 CoP**（地面反力分布） | **只有脚** ⇒ 腿的活 | 改支撑点位置 |
| **搬 CoM**（重心初始条件） | 任何大质量块 ⇒ **腰 / 胳膊**的活 | 改 ξ 的起点 |

★★ 本骨架**没有踝关节**（脚与小腿一体）⇒ **侧向 CoP 不可直接控**：髋外展把整条腿绕髋转出去、脚离地，
那是「**换支撑**」而不是「挪压力中心」；膝顶 CoP 只有 `Δp = τ/N_leg` 一条（L4）。
⇒ **侧向平衡只能靠搬 CoM 或迈步；前后方向才有真 CoP 通道。**

#### (2) 实测：站桩时执行器权限**远未用满**（不是"力不够"）

| 部位 | 峰值饱和率（准静态窗口内单步最大） |
|---|---|
| 腿（髋/膝） | **4%** |
| 臂（肩/肘） | **7%** |
| 腰（spine1/2/3） | **17%**（最吃力 `spine1.外展`） |

⇒ 与 5.5 的结论一致：**执行器不是瓶颈**（余下 83%~96% 的权限没使）。

#### (3) 实测：各通道的侧向 ξ 权限（不开环反馈的"持续出力"）

| 通道 | Δξ_z (m) | ×被动半宽 | 驱动组饱和 | 结论 |
|---|---|---|---|---|
| 基线（零命令） | +0.007 | 0.11× | — | 唯一静平衡点 |
| **抬左腿**（髋外展 0.8） | **+0.021** | **0.33×** | 腿 75% | 同时搬 CoP（+0.032）与 CoM；**但域变窄**（余量+ 0.056→0.042） |
| **双臂外展** 0.8 | **−0.012** | **0.19×** | 臂 16% | ★ **性价比最高**：7.5 m/100% 饱和 |

#### (4) ★★★ 三条被实测**证伪/证实**的结论（已钉成断言）

1. **★ 证伪：「腰部腿部同时发力 ⇒ 更稳」在开环下是反的。**
   腰 0.8 倒 @**1.54 s**；腰+腿 倒 @**1.38 s**；腰+腿+臂 倒 @**1.38 s**
   ⇒ 一起发力**倒得更快**（两侧余量被同时掏空）。断言 `A8`。
2. **★ 证实：绑定姿态是唯一静平衡点 —— 矢状面姿势一改就倒。**
   微蹲（膝 13°）倒 @1.82 s、缓蹲倒 @1.45 s、**协调蹲（髋膝屈 + 腰反向配平）仍倒 @1.67 s**、腰前屈倒 @1.88 s，
   全部是**前后向**越界（2.2×~14.1×）。断言 `A7`。
   ⇒ 「腰腿协同保持躯干直立」在**没有反馈**时救不回来：不是姿势不对，是**没有闭环**。
3. **★ 胳膊：要，但不是主梁 —— 它是性价比最高的精调通道。**
   16% 臂饱和换 0.19× 站立域（7.5 m/100%），而抬腿要 75% 腿饱和换 0.33×（2.8 m/100%）。
   ⇒ 静态平衡阶段（腰/髋/膝 96% 没使）优先用胳膊微调；迈步/转向时它的价值更大（配重 + 角动量）。

#### (5) ⇒ 对路线图的直接影响

- **执行器权限这一关已经彻底排完**（§5.5 + 本节）：腰/腿/臂都远远够用。
  ⇒ 第 4 步重训若还是"站不住"，**不要再调硬件参数**，缺的是**闭环**（观测里有 ξ、`W.balance` 已就位，靠 ES 学）。

  **一次给大就会倒**。这给第 4 步的 ES 提供了一个很强的形状先验：**腰是主通道、胳膊是精调、矢状面别乱动**。

### 5.15 ★★ 为什么"只迈得出第一步"（`probe-gait`：绕过 ES 直接问物理）

用户 2026-10-01："现在甚至无法移动多远，第一步会迈出去，但是第二步不会迈了。
需不需要走直线分数加权或者什么手段教会他走第二步？"

`tools/probe-gait.ts`（`npm run gait`）把"**物理能不能走**"和"**ES 有没有找到**"彻底分开：
手工把时钟接进输出层（`h0=tanh(5·clock.sin)`，输出取一次谐波 + 可调占空比），
**不训练**就得到一个规整的周期步态，然后扫 24 组参数：

| 输出缩放 | 终点 x | 存活 | 换脚次数 |
|---|---|---|---|
| ×1.00 | 0.27 m | 0.47 s | 1 |
| ×0.50 | 0.82 m | 1.24 s | 2 |
| ×0.30 | 0.68 m | 1.32 s | 0 |
| ×0.15 | **1.21 m** | 1.82 s | 1 |
| ×0.05 | **1.21 m** | **2.60 s** | 1 |

步频扫描（0.6~2.0 Hz）几乎无差别（0.96~1.22 m，全程 1 次换脚）⇒ **步频不是杠杆**。

⚠ **探针自己的时间基准曾经是错的**（已修）：`advance(1)` 推进的是**物理步**（120 Hz），
探针却按控制周期（60 Hz）计数 ⇒ 实际只跑了 duration/2 秒，回合也永远走不到 `ticksTotal`
（`finish()` 不触发 ⇒ 分项是空的）。所以早期版本报出的"存活 3.63 / 5.20 s"**偏大一倍**，
真实值是 1.82 / 2.60 s（上表已按修好的基准重填）。结论不变：小幅度走得远、活得久。

**结论（直接回答用户）**：

1. **走直线加权没用**。它只能改变**已有动作的方向**；而"落地之后再迈"这个动作
   在物理层**一次都没出现过**（24 组里换脚最多 2 次）。
2. **但机制上确实有个"学不到"的原因，已修**：原奖励是 `step 0.4/步` 对 `fall 2.0`
   ⇒ **"迈一步再倒"净负分（−1.6）** ⇒ ES 的最优解是"别迈步"。
   ⇒ 加了 **超线性步数奖励** `W.step2 · n(n−1)/2`（n=2 → +1，n=3 → +3，n=4 → +6），
   语义就是"第 2 步开始越来越值钱"。
3. **踩到并修掉一次奖励劫持**：只按换脚次数发分 ⇒ ES 找到"**原地抖腿**"
   （6 次换脚、腾空 0 s、`step2` = +12，但 `Σ(Δτ)²` 飙到 4810、1.05 s 就摔、倒着走）。
   ⇒ 换脚计数加**前进速度门槛** `SimConfig.stepVMin`（默认 0.05 m/s）：
   站着抖腿拿不到分，只有"换脚时身体确实在往前"才算一步。
4. **全幅步态 0.27 s 就双脚腾空**（把整个人甩起来）⇒ 加 `W.air` 惩罚**腾空时间**，
   把搜索从"跳"推回"走"。
5. **剩下的才是结构缺口**：没有**踝/足自由度**（§11 已记）。落地之后没有人管重心，
   所以第二步必然断。实测摆动权限相对支撑能力过强（×0.05 才走得远）
   ⇒ 摆动相/支撑相需要分别的权限上限，或者补踝关节 + 踝策略。

### 5.15.2 ★ 奖励拆成"必须有"和"可选项"（用户 2026-10-01 二次定调）

| 项 | 权重 | 门槛 | 可调 |
|---|---|---|---|
| **`W.switch` 换脚奖励（必须有）** | 0.3 / 次 | 只要求 **左右交替** + 换脚瞬间 `vx > 0.05` | 滑块 0~2 |

  `Trainer.recordAndBreed` 每代线性抬到 `stepMinDxMax = 0.30 m`（60 代走完）；

- UI（`index.html` 控制台新增"步态奖励"区 + `hud.ts` 绑定 + `main.ts` → `Trainer.applyGaitTuning`）：

### 5.15.3 ★★★ 步态奖励最终形态：**"迈步 → 站稳 → 再迈"循环**（用户三轮定调）

> ① "还不如让这玩意只迈两步，但是每迈一步都要稳，需要自行调整平衡"
> ② "需要一个迈步后保持稳定的加分，而且在迈步后要高于迈下一步的收益，然后逐渐减弱，再迈下一步"
> ③ "循环为迈步，保持稳定，再迈下一步，再保持稳定的循环"
> ④ "迈一步立刻迈第二步应该是负分；一条腿连着迈两步更是负上加负"
> ⑤ "换脚奖励必须有，前进奖励要弱" + "走直线和阈值都是可选项（做成可调按钮）"

**一次有效迈步**打开一个**稳定窗口**（`holdMaxSec = 2.0 s`，上限），窗口内只要 **CoM 还在支撑域内**
就计"站稳秒数"；窗口按 `stepDecay^已迈步数` 打折（0.6^n ⇒ **第一步 > 第二步 > …**）。
窗口用完或摔倒就不再给分 ⇒ 想继续拿分**必须再迈一步** ⇒ 最优解自然长成那个循环。

| 项 | 权重 | 判据 | 可调 |
|---|---|---|---|
| `W.switch` **换脚奖励（必须有）** | 0.3 / 次 | 左右交替 + 换脚瞬间 `vx > 0.05` | 滑块 0~2 |
| `W.step` 大位移奖金 | 4.0 / **米** | 直线（可关）+ 位移门槛 + 累计门槛 | 阈值滑块 0~0.3 m（起步 0.05，60 代课程抬到 0.30） |

⇒ 迈步 → ≤1.2 s 内站稳 → 窗口一关 0.25 s 后就开始扣静止罚、间隔 <0.2 s 又算抢步 ⇒ 循环被压得很紧。

| 会迈步的步态 | 1.220 | 0.00 | ✅ 会迈步的静止罚更少 |

#### ★ 走路模式关掉 DCM 越界罚（`tools/probe-seed` + `tools/probe-trainwalk` 实测）

`W.hold`（保持分）与 DCM 越界罚**用的是同一个判据**（CoM / ξ 是否在支撑域内），
一个给分一个扣分 ⇒ **同一个动作被正反两次惩罚**。实测（6 s walk）：

| 基因组 | 换脚 | 迈步 | 重复步 | 前进 | 保持 | balance | 总分 |
|---|---|---|---|---|---|---|---|
| 相位种子 ×0.15 | 2 | 0.67 | 0.80 | 0.41 | 0.12 | **−50.46** | −51.55 |

| "两脚蹭地往前挪"（从不迈步） | 0 | 0 | 0 | 0 | 0 | 0 | −2.87 |

#### ★ 前进奖励只对"有效迈步推进的位移"付费

`W.distance` 从"总位移"改成"上一次有效迈步之后、且在站稳窗口内推进的位移"
（`accProgress`，参考点 `stepRefX`）。原因：位移是最容易拿的大分项，
一个"蹭地不迈步"的策略能拿 1.17 m 而适应度最高。现在**迈了步才有钱、站稳时蹭地也没钱**。

#### 无头训练探针 `tools/probe-trainwalk`（`node tools/run.mjs probe-trainwalk [代] [种子]`）

**仍要诚实记着**：`probe-gait` 的门槛分项计数显示，
那组能走 1.21 m 的手工步态 `switch:3 / noAlt:0 / tooSmall:2` ——
**它两次换脚都发生在身体还没走出去的时候，之后 3 秒一路滑行不再换脚**。
所以现在这套奖励**规则是对的、也调得动了，但"第二步"仍然拿不到**；
下一刀还是 §11 的踝/足自由度（或先用 `probe-gait` 那组 ×0.15 步态给种群做种子）。

**有效迈步**（`Sim.controlTick` + `SimConfig.stepMinDx/stepMaxDz/stepMinTotal`）必须**同时**满足：

| 条件 | 阈值 | 为什么 |
|---|---|---|
| ① 左右**交替**：`stance` 严格 l→r 或 r→l（连着同一只脚不算） | — | "迈一个脚后再次迈另一个脚" |
| ② 换脚瞬间在前进 | `vx > 0.05 m/s` | 堵"原地抖腿"（实测被劫持过：6 次换脚 +12 分、1.05 s 就摔） |
| ③ 这一脚是**直线**：本步横向漂移 | `|Δz| ≤ 0.06 m`（≈27° 航向） | "位移为直线" |
| ④ **大位移**：本步净前进 | `Δx ≥ 0.12 m` | "大位移才有奖励" |
| ⑤ 累计前进门槛（前 30 cm 不计分） | `≥ 0.30 m` | 不让"原地小碎步"刷分 |

奖励 = `W.step · Σ(有效迈步的 Δx)`（**每米 4.0**）+ 超线性加成 `W.step2 · n(n−1)/2`（n = 有效迈步数）
+ `− W.air · 腾空时间`。

**验收（`npm run gait` 的"验收"段）**：

| 用例 | 换脚奖励 `switch` | 大位移奖金 `step` | 判定 |
|---|---|---|---|
| 前进型相位步态（x=1.21 m, z=0.01 m） | **0.300** ✅ | 0.000（只换脚 1 次、且都发生在还没走出去时） | ✅ 换脚奖发得出 |
| 侧向抖（只驱动髋外展，x=0.06 m，存活满 6 s） | 0.000 ✅ | 0.000 | ✅ 无前进 ⇒ 换脚奖也不给（防抖腿） |
| 纯侧向位移 | — | 0.000 | ✅ 不奖励 |

⇒ 奖励口径已经按要求收紧并**可验证**，但**当前物理还拿不到它**：
连最好的手工步态也只有 1 次换脚，而"第二次交替迈步"需要落地后管住重心 ——
这指向 §11 的**踝/足自由度缺失**，不是奖励问题（奖励已经不能再紧了，再紧就永远为 0）。

`Sim.fitnessTerms()` 已抽出成独立方法（诊断接口 `sim.terms` 打印分项）——
以后再出现"训练结果不如预期"，先看是**哪一项**在主导，别再猜。

（跟"骨盆会深蹲、胸腔塌地才算摔"这个判定口径一致。）

#### 6.1.1 ★★ 重心块（14–19，**6 维**）：从"看不到重心"到"看得见发散"

补这 6 维之前，观测里**没有任何 CoM / CoM 速度 / CoP / DCM** —— 策略在**原理上**拿不到
"我在往哪倒"，只能拿**胸腔**当代理，而胸腔只占 **12.4% 质量、离 CoM 0.4635 m**。
实测症状正是这个：**直立占比 48~97%，却只前进 0.37 m 且仍判摔**（`probe-push`）。

| 维 | 量 | 缩放/口径 | 为什么是这个口径 |
|---|---|---|---|
| 14–15 | `com.x/z − sup.cx/cz` | m，相对**支撑域中心** | 减去域中心后 0 = 站着不动的位置；只报绝对坐标时"站在哪"取决于初始落点，网络学不到偏移量 |
| 16–17 | `com.vx/vz` | ×2 | 水平抓地上限约 0.35 m/s ⇒ 映射到 ~0.7，别让速度维被 tanh 前面几层直接淹掉 |
| 18–19 | `(ξ − sup.c)/half`，ξ = x + ẋ/ω | clamp ±3 | **0 = 域中心、±1 = 域边缘**。clamp 到 ±3 而不是 ±1：已经摔出去时仍要有梯度，否则越界即饱和、学不到"往回走" |

★★ **DCM ξ = x + ẋ/ω 才是真平衡判据，不是"CoM 投影落在支撑多边形内"。**
倒立摆的发散分量在 ξ 上，`ξ ∈ 支撑域` ⇔ 存在一个可抓回的加速度预算；
只看 CoM 投影会漏掉"重心在域内但速度已经冲出去"（这正是 0.37 m 就摔的机制）。
`ω = √(g/z_c)` 随高度变化，所以 `dcm()` / `omegaAt()` 都读**当帧 CoM 高度**，不是常数。

★ **水平用"被动"半宽**：两脚等载荷时净 CoP 只能动到**一只脚宽**的范围；
拿双脚凸包当域会**高估约 4 倍**，策略会把 ξz = 0.2 当安全区（`readSupport` 同时报 passive / active 两套，索引用 passive）。

★ 归一化用 `half`（半宽）不是 `width`；`sup.halfX` 是**前后**向、`sup.halfZ` 是**侧向**，别按 xzy 的直觉配错轴。
侧向被动半宽最苛刻：实测只有 **±0.063 m**（见 5.11 / [B3]），这就是"站稳"的硬预算。

### 6.2 动作（**36 维**）

每关节 3 个数 = **目标关节角**的比例（父体本地三轴，`tanh` 后 ∈ [−1,1]），
经 `posRefScale` 映射到实际目标角 θ_ref，由**位置环 PD** 追踪：

```
θ_ref = cmd × (cmd ≥ 0 ? +posRefScale·hi : −posRefScale·lo)   // hi/lo = 该轴正/负行程
err   = kP·(θ_ref − θ) − kD·ω_rel
τ     = clamp(err · τmax / JOINT_MAX_SPEED, ±τmax)
```

每个控制周期更新一次 θ_ref，物理步之间由马达持续施加 ⇒ 力矩是**连续量**，不是脉冲。

★★ **这一版是"目标角速度"的严格泛化，不是换了个控制器**：

```
cmd = 0  ⇒  θ_ref = 0  ⇒  θ_ref − θ = −θ  ⇒  err = −kP·θ − kD·ω_rel
```

把 `kP·θ` 并进"目标"，`err` 就退化成旧公式 `τ = k(target − ω_rel)`（`target = −k·clamp(θ)`）。
所以**未训练（全 0 基因组）的行为 = 旧控制器的静息行为**，唯一变的是 `kP` 与护栏 α 的**数值**。

#### 6.2.1 ★★ 旧版（目标角速度）为什么必须废掉

`targets = 0` **不是"松手"**，而是"**把这个关节的角速度刹到 0**"：

```
err = target − ω_rel     // target = 0 ⇒ err = −ω_rel ≠ 0（真实负载下永远不为 0）
```

`probe-push` A 组实测：静息时**零出力轴仅 0.00%** —— 每个轴每步都在出力；
而且**打满的是肘（100%）**，髋/膝只用 37% / 55%。那是"关节空间的无差别制动"，
**不是"重心空间的平衡控制"**：把 36 个轴全刹住 = 让身体僵住，而**僵住的倒立摆一点恢复能力都没有**
（它不改变 `p`）。两条死结：

1. **纯速度目标没有静态刚度** ⇒ 静载荷下必然**蠕变**（`restTension = 0` 时 1 s 内胸腔 0.888 → 0.149 m）。
   旧版靠 `restTension` 打补丁；位置环的 `kP·(θ_ref−θ)` **本身就是静态刚度**，补丁可以拆。
2. **它不可被网络调制**：固定的 `target += −k·clamp(θ, ±ref)` 只能把关节拉回**初始姿态**，
   网络既无法主动维持一个非零姿态，也无法表达"把 CoM 挪到某个位置"。
   位置环下网络直接给 θ_ref ⇒ 姿态与重心都是可表达的。

#### 6.2.2 ★★ 行动力 ≠ 关节权限：`motorAlpha` 才是真瓶颈（见 5.5）

改成位置环后**仍然站不住**时，第一嫌疑**不是**"网络不会控"，而是**执行器够不够力**。
`ragdoll.ts` 里有两条独立的限幅，必须分开记账：

```
有效关节刚度 = kP · min( τmax/JOINT_MAX_SPEED ,  α·Ieff/dt )
                       └──── 设计值 ────┘   └── 稳定性护栏 ──┘
```

- `τmax` 是"马达力气"（`probe-ground` 静力测试在 kP≥12 就饱和在 ~106% 体重，**不是瓶颈**）。
- `α`（`MOTOR_ALPHA`）= 每步最多吃掉多少比例的相对角速度误差。**当年为"速度目标"定的 0.35，
  在位置环下把髋刚度压到设计值的 26%**（实测 `τ应用/τ需求 = 22%`）⇒ 髋被重力压开 83~96°（"劈叉"），
  这不是"倒"，是**关节柔性屈曲**。
- 现在 `kP = 48`、`α = 1.0`：α=1 的语义是**一步收敛且不过冲**（α=2 才是振荡边界），
  不是"把安全阀拧松"。实测零输出存活 1.28 s → **6.00 s 跑满**。完整扫描表见 5.5 [B2]。

⇒ **凡"改完动作还站不住"的排查顺序**：先打**权限对账单**（τ应用/τ需求、有效刚度 vs 设计值），
再谈控制/网络/适应度。见 `probe-posture` [B2] / [C3]。

## 7. 适应度设计

### 7.1 权重表（`sim.ts` 的 `W`，集中在一处方便调参）

| 项 | 权重 | 含义 |
|---|---|---|
| `distance` | 3.0 | **净前进距离**（torso.x − startX） |
| `velocity` | 0.6 | 前进速度积分（塑形，让早期就有梯度） |
| `upright` | **0.5** | **惩罚**不正立：`W × ∫(cos tilt − 1)dt ≤ 0`（1.2 → 0.5：平衡已交给 `balance`，见 7.4） |
| `height` | 0.8 | 躯干离地高度偏差 |
| `lateral` | 1.0 | 侧向漂移 `∫\|z\|dt` |
| `energy` | 0.02 | 关节耗能 `∫Σout²`（★ 量**出力大小**，量不到**抖动**，见 7.5） |
| `step` | 0.4 | 两侧脚掌交替触地（鼓励迈步而不是蹭） |
| `fall` | 2.0 | 摔倒一次性扣分 |
| **`survive`** | **0** | **存活奖励（每秒）**。默认 **0 = 关闭**；只有"站桩考核"这类关掉了 `distance/velocity` 的评测才打开（考核里设 1.5）★ 全局打开会重新长出"站着不动"的局部最优 |
| **`balance`** | **2.0** | **★★ DCM 越界积分** `∫(eX² + eZ²)dt`，`e = max(0, \|ξ\| − 1)`（归一化后域内 = 0）。**这是"站得住"真正的梯度来源**；侧向用**被动**半宽（等载 CoP 预算 = 一只脚宽） |
| `hit` | 4.0 | 战斗：命中一次 |
| `hurt` | 0.02 | 战斗：被击中（按出拳次数） |
| `approach` | 0.8 | 战斗：手贴近假人 `∫max(0, 1 − d/1.2)dt` |
| **`smooth`** | **1e-4** | **抖动罚** `∫Σ(τ_t − τ_{t−1})²/dt dt = Σ(Δτ)²`（逐**物理步**、用 `motorImpulse/dt`）。实测：静息 188 → **−0.02 分**（可忽略）；抽风 4.2e6 → **−417 分**（压死）。见 5.12 / 7.5 |

★ **三档权重预设**（`DEFAULT_SIM.weights` / 站桩考核 `STAND_W`）：

```
标准（走/战）  : W = 默认（distance 3.0、velocity 0.6、survive 0）
站桩考核       : { distance: 0, velocity: 0, step: 0, survive: 1.5 }   // 只考"能不能站住"
```

### 7.2 三处**必须记住**的修正（这是"学不出走路"的第二大原因）

1. **`distance` 从"评估期内最远距离"改成净位移。**
   用最远距离时，往前扑倒滑出去也算分 ⇒ ES 学会了"扑"而不是"走"。
   （实测：最优个体直立占比 97% 却只前进 0.28 m，而当代最佳全程"摔倒=是"。）

2. **`upright` 从"奖励直立"改成"惩罚不直立"。**
   ★ 为什么不做成 `+1.2 × ∫cos`：那样"站着不动 6 秒"就白拿 7.2 分，会形成一个离"走得一般"很近的**局部最优**，
   ES 会直接卡在那里。改成惩罚后，站桩总分 = 0，任何倾斜/扑倒都从 0 往下扣，梯度方向正确。

3. **新增 `lateral`**：任务要求沿 +X 直走，偏出去要扣。

### 7.3 战斗适应度

```
W.hit × hits − W.hurt × hurts + W.approach × accClose
+ W.upright × (accUpright − elapsed) − W.height × accHeight
+ 0.5 × progress − (fallen ? W.fall : 0)
```

命中判定：`拳头到假人躯干的距离² < 0.68²` 且 `速度 > 1.0`。

### 7.4 DCM 越界惩罚（`W.balance = 2.0`，**已实现**）

**被替换的旧方案**：唯一的直立项是 `W.upright × ∫(cos(tiltOf(chest)) − 1)dt`，它优化的是**代理量** ——
胸腔只占 12.4% 质量、中心离 CoM 0.4635 m。实测症状与之完全吻合：
"直立占比 48~97%、净前进 0.37 m、**仍判摔**"。

**现在的项**（与 5.11 的判据同源，落在 `sim.controlTick` 的 `accBalance`）：

```
W.balance × Σ (ex² + ez²) · dt
ex = max(0, |ξx − cx| / halfX − 1)        // ξ = x + ẋ/ω（捕获点），**归一化**后域内 = 0
ez = max(0, |ξz − cz| / halfZ − 1)        // 侧向 halfZ 用**被动**半宽（~0.06–0.07）
```

- **越界才扣、越界越狠（平方）**，域内给 0 ⇒ 与 `upright` 的"站桩不白拿分"性质一致，
  不会造出一个"站着不动就白拿分"的新局部最优。
- ★ 为什么是**归一化**而不是米：站立时 half 只有 ~0.07 m、迈步时 half 在变，
  用米会让"域大的时候小犯规"和"域小的时候不犯规"混在一起不可比；归一化后跨姿态可比。
- ★ 侧向必须用**被动**半宽，不能用凸包 —— 两脚等载荷时净 CoP = 两脚 CoP 的**平均**，
  侧向可调范围只有"单只脚的宽度"。用凸包（0.266）等于给策略 4 倍宽容度，
  它会把身体送到 ξz = 0.2 还以为自己很安全（实测静息就是这样翻的）。
- ★ **为什么不是"CoM 投影落在支撑多边形内"**：静力投影判据是**静态近似，比真实约束宽得多**。
  真约束是不稳定倒立摆 `ẍ = ω²(x−p)`，稳定 ⇔ ξ 在域内。`probe-stability` 实测：
  走路量级 0.5 m/s 已超过本骨架的可刹上限 `ω·p_max = 0.351 m/s` ⇒ **静止站立在数学上已不可能，
  只有迈步能救**。用静力判据会给出"余量 0.11 m，很安全"的**错误结论**。
- ★ 取值 2.0 的来由：一次典型摔倒越界量 1~3 个半宽、积分 ≈ 1~9、×2 后 2~18 分 ——
  与 `distance` 满分（3×3 = 9）同量级、比 `fall`（2.0）重，即"慢慢倒下去"和"直接判摔"都被明显惩罚，
  但不会把分数压成常数。
- 配套把 `W.upright` **降权**（1.2 → **0.5**），否则两个惩罚互相掩盖，看不出是谁在起作用。
  （保留它是因为"弯腰驼背"确实要以姿态扣分，只是不该由它负责平衡。）

### 7.5 抖动惩罚（`W.smooth = 1e-4`，**已实现**）

**被替换的旧方案**：`W.energy = 0.02 × ∫Σout²` 量的是**出力大小**，量不到**抖动** ——
一个每步朝相反方向猛扯、净输出 ≈ 0 的抽风关节，`out²` 很小、energy 几乎不罚，
但它把接触抖散了（实测抽风个体存活 0.38~0.60 s）。

**现在的项**（`sim.accumulateSmooth()`，逐**物理步**累加）：

```
accSmooth += Σ_axis (Δτ)² ,   τ = motorImpulse / dt        // 只作差、不平滑
W.smooth   = 1e-4
```

- ★ **为什么用 τ 而不是 `out`**：τ 里含 `−kD·ω_rel` 反馈项，高频换向在力矩上才看得见；
  `out` 是低频指令，抽风可以表现为"指令不怎么变、力矩每步撕扯"。
- ★ **为什么平方和而不是 Σ|Δτ|**：与 `W.balance` 同理 —— 真人式的小幅连续修正几乎不罚，
  大幅高频按平方放大。
- ★ **为什么第一步跳过**（`tauPrimed`）：没有前值时 Δτ 会把"起步瞬间 0 → 一个正常力矩"
  记成一次巨大抖动（假罚）。
- ★★ **量化标定**（`probe-posture` [C3]，3.5 s 回合，确定性）：

| 基因组 | Σ(Δτ)² | **抖动罚** | 存活 |
|---|---|---|---|
| 零基因组（静息） | 188 | **−0.02 分** | 3.50 s |
| 站桩训练 best | 376 | −0.04 分 | 3.50 s |
| 随机 scale=1（抽风） | 4.17e6 | **−417 分** | 0.60 s |
| 随机 scale=3（抽风） | 6.08e6 | −608 分 | 0.38 s |

⇒ 静息/正常站立 **可忽略**（< 0.1 分），抽风 **直接被压死**（≫ `distance` 满分 9）。
判据已做成断言：`C3a`（抽风罚 ≥ 10× 静息罚，实测 **×22169**）、`C3b`（静息罚 < 0.1 分）。
- 与 `balance` 的关系：`balance` 治的是"倒"，`smooth` 治的是"抖散接触导致倒"，两者不重叠、同时开。

## 8. 进化算法（`evolution.ts`）

**为什么不用 PPO/DQN**：那需要逐状态的价值估计和大量超参，动辄几十万步才出结果，还得拽进来一个深度学习框架（体积 + 复杂度都超标）。
进化策略在这类「低维连续控制 + 有明确标量分数」的问题上又稳又便宜：
不需要梯度、天然可并行、可随时中断查看、一段时间不用就能直接导出权重（基因组就是全部状态）、
种群本身带探索（不会像单个体 RL 那样卡在局部最优后彻底死掉）。

```ts
population: 48        // 每个个体一个独立 World
eliteFrac: 0.2
sigmaInit: 0.06       // ★ 3D 后必须降（原 0.28）
sigmaMin: 0.004
sigmaMax: 0.2
mutationProb: 0.12    // 每个参数被变异的概率
seed: 20261001        // 固定种子 ⇒ 结果可复现
```

**1/5 成功法则**：若超过 1/5 的子代比上一代好 ⇒ 步子太保守，放大 σ；否则缩小 σ。

### 8.1 ★ 高维 ES 学不动：初始化与 σ 尺度错配（第三个根因）

**症状**：σ 一路顶到上限、40 代最佳分在 1.6 附近乱跳（等于随机游走）。

**根因**：`randomGenome` 原来用统一 std = 1.2，而输入维度很高（当时 70 维）⇒ 第一层预激活 std ≈ 1.2·√70 ≈ 10，
tanh 全部饱和；且 σ = 0.28 比权重量级（≈0.12）还大两倍。

**修法**：
- `randomGenome` **按扇入缩放**：`s1 = scale/√inputs`，`s2 = scale/√hidden`；`b1/b2 = 0`（显式注明：初始行为 = 保持初始姿态）。
- 经验口径：**ES 的 σ 应当和权重量级同阶，被变异的参数比例应当 ~1/√n。**

### 9.3 ★ `probe-forces` —— 逐组件受力回读（力审计）

> **为什么不用截图**：截图只能证明"看起来像在动"，证明不了"力是怎么走的"。

**前提**：Rapier 0.14 **完全没有关节冲量/反力的读回接口** ⇒ 关节力只能**反推**。

三条可测的量做牛顿收支：

```
① 重力      = m·g                        （已知）
② 接触力    = contactImpulse(i) × normal()（从接触流形读，方向按 flipped 定）
③ 马达力矩  = Ragdoll.motorImpulse        （我们自己施加的，直接记账）
⇒ 关节反作用力 = 动量变化 − 重力 − 接触力（残差）
```

**五组读数**：

| 段 | 内容 |
|---|---|
| [A] | **独立校验**：全身动量收支 `Σ m·a = M·g + Σ 接触力`（关节力与马达力矩都是内力，整体自动抵消） |
| [B] | 逐刚体：质量 / 重量 / 接触力 / 关节合力 / m·a / \|m·a\|÷重量 |
| [C] | **关节传递力（子树动量收支法）** —— 力从地面沿骨链传到头的路径图 |
| [C2] | **闭式校验**：躯干是树根、**与地面无接触**，故 `m·a + m·g·ŷ + Σ关节力 = 0` |
| [D] | 执行器读数：每关节每轴的实际力矩 / 上限 / 饱和率 |
| [E] | 重心控制：CoM、水平修正所需的力、脚底摩擦上限 |

**判据（站桩，窗口 1.5–2.5 s，体重 687 N）**：

```

    ★ 为什么不是 0：contactImpulse 里含求解器的**位置偏置冲量**（穿透恢复），
      它被计入流形读数但不产生净动量变化 ⇒ 流形法系统性偏高几个百分点。
      两法一致到 5% 以内即可认为接触读数可信（竖直方向与摩擦无关，最干净）。
[C2] 躯干残差 = (-3.3, −33.4, −0.4) N ⇒ 4.9%  ✔（继承同一个接触偏置）
```

**读数（站桩）—— 这就是"力是怎么走的"**：

|---|---|---|---|---|

地面反力比这条腿自身重得多，多出来的部分必须由**髋/膝向上传递**。

## 12. 下一步路线图（★ 已按 `probe-stability` / `probe-push` 的结论重排）

### 指导原则：**先排执行器，再谈控制器**

问过的问题：「需不需要补一个姿态控制算法？」答案是 **不需要手写稳定器**，但**原因在本轮被修正了**：

1. ~~权限够~~ **❌ 这个判断当时是错的**：`probe-push` [X] 测出的"最坏情况只用 50~55% 权限"是在
   `α = 0.35` 这个**护栏**下测的 —— 它把**可用**权限当成了**设计**权限。
   真正的瓶颈是 α 把有效刚度压到 **22%**（见 5.5 [B2]）。★ **教训：测"够不够"之前先确认"给没给"。**
2. 产物是**要移植的 boss**，它还得会走 / 会追 / 会打。手写稳定器只管"站"，
   而它会和学出来的策略**抢同一批关节**（软限位 + 姿态张力 + 外挂稳定器三方抢执行器，调参复杂度爆炸）。
3. 真正卡住的是**结构/参数**（有效刚度 22%、被动侧向域只有 ±0.06~0.07 m、脚短且窄、无踝），
   不是"没人用这些力"。

### ✅ 第 1 步 · 动作空间改成 PD **位置**目标（`ragdoll.ts` + `brain.ts`）— 已完成

**★ 不改变维数、不改变网络形状** —— 只是把输出语义从"角速度系数"换成"目标角"：

```
θ_ref[k] = cmd × (cmd ≥ 0 ? posRefScale·hi : −posRefScale·lo)   // 非对称斜率
err      = kP·(θ_ref − θ) − kD·ω_rel                            // 仍走 α·|err|·Ieff 稳定上限
```

- `cmd = 0` ⇒ `err = −kP·θ − kD·ω_rel` ⇒ 行为**正好等于旧公式**（**严格泛化**，不是推倒重来）。
- ★ 非对称斜率是为了同时保住「`cmd = 0 ⇒ θ_ref = 0`」与「`|cmd| = 1 ⇒` 顶到量程 90%」——
  膝 `[−145°, +2°]` 这种非对称关节必须这么映射。
- 稳定性由 5.4 那条 `|imp| ≤ α·|err|·Ieff` 兜底（`α` 现为 1.0，见下）。

### ✅ 第 1.5 步 · **硬件权限对账**（本轮新增，★ 这是"站不住"的真根因）— 已完成

## 12.5 ★★ 走路奖励：11 项经典配方（2026-10-01 全量重构）

### 为什么要推倒重来
旧版一个 `total` 里塞了 **30 个手调权重 + 21 个记账器 + 23 个步态旋钮**，而且
"换脚/站稳/抢步"与"逐关节程序"两套系统**互相耦合**（前进奖励的门 = 旧状态机打开的
`holdWindow`）⇒ 改 A 影响 B、无法预测组合结果。用户判定"乱成一锅粥"，决定重构成
**一份能说出每项出处**的配方。

### 主干文献
**Rudin, Hoeller, Reist, Hutter, CoRL 2022**（"Learning to Walk in Minutes Using
Massively Parallel Deep RL"，ANYmal 四足；后被 Cassie 双足复用）。原文明确写了
*"neither the reward function nor the action space has any gait-dependent elements"*
—— 没有步态时钟、没有相位、没有换脚检测；**交替步态是"足端腾空时间"自己长出来的**。
他们换到**双足 Cassie** 时必须**额外加一项"鼓励单脚支撑"**才走出走路步态 ——
**这就是"一次抬一条"的正式版本**。另参考 Raibert 1984 / Pratt 2006（落脚点 = CoM + v·T/2，
即捕获点；我们早期把 ξ 当"越界就罚"用，等于罚走路本身，已弃用）。

## 12.6 ★★ 踝关节：代码就绪但**默认关闭**（2026-10-01）

用户要求"脚做踝关节，纹理上用脚部位的 UV 扭曲"。已实现：
- 脚掌拆成**独立刚体** + 踝 revolute（俯仰 [−10°,18°]、内外翻 ±8°、45 N·m）；
- 踝锚点用**实测值**（`limbAxes.paw.yWide=2792` 靴顶 + `paw.centerX` 靴心）；
- 小腿刚体重新居中到"膝→踝"段（否则膝锚点落到胶囊外 66~70 mm）；
- 脚掌碰撞体是**薄鞋底板**而不是高盒（高盒绕顶部旋转时底角会扎进地面 21 mm，
  把踝锁死 —— 实测 25° 时就是这个坑）。

**但打开后走不了**：脚一旦拆成独立刚体，腿部动力学就变了 —— 0.5 s 内骨架塌 41 cm、
实际关节运动幅度涨 1.5 倍、位移 1.25 m → 0.08 m；**把踝锁死（限位 0）也一样坏**
⇒ 不是自由度的问题，是刚体拆分后 PD 增益/惯量分布要重调。
所以放倒 `cfg.ankleEnabled = false`（默认 = 加踝前的物理），**不想让一个走不了的自由度进主干**。
下一步：重调 kP/kD，或把踝做成刚性锁而不是位置伺服，再考虑打开 + 做脚部 UV 扭曲。

## 12.7 ★★★ 迈步的两层奖励：先重心转移，再换支撑脚（2026-10-01）

### 触发这次改动的实测（用户："抬一次脚就摔倒了，什么也学不到"）
| 量 | 值 |
|---|---|
| 两脚 z 位置 | ±0.164 m（站距 0.328 m）|
| 站桩时 CoM z | 0.007 m（双脚均分，载荷 0.53/0.47）|

| 单脚侧向半宽（含外八 25° 投影）| **0.139 m** |
| 结论 | **差 1.23× ⇒ 长时间单脚支撑几何上不可能** |
| 站距收到 0.181 m（stance 0.55）| 1.43× 可行，但脚骨会比画出来的靴子**内缩 7 cm** ⇒ 不可接受 |

进一步实测：**站桩时根本抬不起脚** —— 种子相位步态的鞋底离地峰值（0.092 m）只出现在
**倒塌过程中**，站立期间两脚始终接触地面；换支撑脚事件数恒为 0 ⇒
"抬腿/交替"类奖励对**所有**策略都给 0 分，ES 完全没有信号。

### 但髋外展能把重心挪过去（这是关键可行性实测）
手写基因组只驱动髋**外展轴**（axis 0）：

| 外展幅度 | 载荷左 | 载荷右 | 倒地 |
|---|---|---|---|
| 0.0 | 0.53 | 0.47 | 倒 |

| 0.6 | **1.00** | **0.00** | 倒 |
| 1.2 | 0.00 | 1.00 | 倒 |

⇒ **能力存在**：髋外展限位 ±45°、骨盆横向可移 ~0.15 m，正好够把重心挪到支撑脚上。
所以正确的教学顺序是 **重心转移 → 换支撑脚 → 抬脚**，直接教抬腿是教一个学不到的动作。

### 落地的两项奖励
| 项 | 权重 | 定义 | 说明 |
|---|---|---|---|
| `shift` | 2.0 | `min(∫\|载荷左−载荷右\|dt, 1.5s) × alive` | **封顶**的"能力门槛"：会单腿平衡这件事值 1.5 s。不封顶的话实测策略只要永远单腿站就刷 20 分而换脚数为 0 |
| `single` | 2.5 | `Σ_换脚事件 φ(v*−v_x) + 双脚离地时间罚` | 换支撑脚（载荷 >70% 换边，0.15 s 不应期）**只有在正在推进时才计价** —— 不加这层实测 6 代就学会"原地金鸡独立式交替"（换脚 14 次/6 s、位移 −0.38 m） |
| `velTrack` | 1.0 | 额外乘 `min(1, 换脚数/2)` | **前进分要迈过步才给**：实测零输出会**自己往前滑 0.65 m**（外八 25° + 纯阻尼 ⇒ 被动自走），不设门槛的话"什么都不做"拿满速度跟踪 |

### 两个踩过的判据 bug
1. **Rapier 窄相保留"预测性接触"**：脚离地 9 cm 仍报接触 ⇒ 几何接触判据（`numContacts>0`）
   让"抬腿"永远为 0。改用 `contactDist(k) ≤ 2 mm` 才准。
2. **按法向过滤把接触全滤掉**：`footLoadFrac` 里加了 `|n·y|>0.5` 才算竖向载荷，
   而外八 25° 下接触流形的法向 y 分量达不到 0.5 ⇒ 载荷恒为 0、份额永远是 0.5/0.5
   （"重心转移"这项完全没有信号）。自碰撞本来是关的，鞋底上的接触只可能是地面，直接不过滤。

## 12.8 ★ 训练存档 + 闭环性质（2026-10-01）

### 存档（用户："刷新一下页面就没了，也存不下来"）
之前只有"导出单个基因组文件"，**刷新页面照样全丢**（进化状态、σ、随机数都没了）。现在两层：

| 层 | 内容 | 触发 |
|---|---|---|
| **自动存档** `localStorage` | 种群 + 历史最优 + σ + **随机数状态** + 奖励权重 + 历史尾部 | 每个新代写一次；启动时自动读档 |
| **会话文件** | 同上 + 版本号 + 网络形状 | UI 的"导出/导入"按钮 |

关键点：**连随机数内部状态一起存**（`Rng.getState/setState` + `makeGaussian` 的
Box–Muller **缓存样本** + 1/5 法则用的 `prevMean`）。少了任何一样，读档后继续训就会分叉。
`tools/probe-persist.ts` 逐位验证：**训练 3 代 → 存档 → 换一台"机器"读档 → 再训 3 代
≡ 一路训到底**（最好个体 11.698894 = 11.698894，种群逐参数相同）。
另外：网络形状不符（关节数变了）会**明确报错**而不是静默塞进去；坏 JSON、长度不符都报错；
Node 下没有 localStorage 时安全降级。体积：整代种群 ≈ 400 KB（localStorage 上限 5 MB，够）。

### 它是回放还是闭环？（`tools/probe-closed.ts`：观测消融 + 推扰）
训练 8 代后的基因组，把观测的某一路置零看轨迹变不变：

| 消融 | 终点 x | 终点 z | 躯干倾角 | 与基准偏差 |
|---|---|---|---|---|
| ① 完整观测 | −0.239 | 0.119 | 35.9° | 0 |
| ② 只留时钟（关节+姿态全置零）| −0.054 | −0.071 | 32.5° | **0.1413** |
| ③ 去掉关节反馈 | 0.019 | −0.037 | 35.7° | **0.1421** |
| ④ 去掉躯干姿态+角速度 | −0.012 | 0.102 | 39.3° | 0.0439 |
| ⑤ 侧向推 30 N·s @0.25 s | −0.145 | **0.333** | **52.8°** | 0.0449 |
| **对照组**：手工种子基因组 | 完整 0.362m | 只留时钟 0.362m | — | **0.0000** |

**结论**：
1. 训练出来的**不是回放** —— 去掉关节反馈轨迹变化极大（偏差 ≈ 轨迹长度的 60%）；
   而手工种子（纯时钟驱动的开环振荡器）同一个测试给出**恰好 0.0000** ⇒ 测试有能力区分两者。
2. **对物理世界有反应**：推一把会改变结果（终点 z 0.119→0.333）。
3. **但不会恢复**：倾角从 36° 变成 53°，只是换了个倒法；而且 0.5 s 后再推就毫无影响
   （回合在 0.4 s 就摔完了 —— 说明当时的策略连站都站不住）。

### 真正的短板：**没有外部感知**
82 个输入里没有任何外部信息：❌ 地形高度 ❌ 障碍物 ❌ 目标/方向（"往哪走"写死在奖励里）
❌ 足底接触力（只有脚底**高度**两个数）❌ 除时钟外无记忆。
⇒ 它能被动响应自己的身体状态，但**看不见世界、接不了任务**。
经典配方（Rudin）的另一半是：**commanded velocity 是策略的输入**，且在一整段指令范围里训练，
同一份参数就能听指令 —— 那才叫"能和外界交互"。


## 12.9 ★★★ 捕获点行走控制器：第一个真的会走路的控制器（2026-10-01）

### 动机
用户："压根走不起来"。前面所有奖励/探针工作都建立在"物理能不能走"这个未验证的前提上，
所以先手写一个**经典控制器**来回答它。摆动脚落到 **ξ = CoM + v/ω**（捕获点 / Raibert 落脚点），
而不是按正弦盲摆；用二连杆 IK 把脚的目标位置转成髋/膝的目标角。

### 结果（`npm run capture`）
| | 位移 | 存活 | 真实换脚（单腿支撑） |
|---|---|---|---|
| 零输出基线 | 0.472 m（滑） | 1.83 s | 0 |
| 开环相位步态 | 1.25 m | 1.8 s | 0 |
| **捕获点控制器** | **0.625 m** | **4.32 s** | **4** |

逐拍 trace 里能看到 **载荷 0.00/1.00**（全部体重压在一只脚、另一只脚离地）——真正的单腿支撑。

### 三个关键点（每一个都是踩坑换来的，参数固化在 `phaseSeed.CAPTURE_GAIT`）
1. **落地吸能**：支撑脚刚落地的一小段时间（`absorb=0.4 rad`，衰减 τ=0.25 s）额外屈膝。
   没有它 ⇒ 迈步后躯干俯仰发散（实测 −1.2°→−13°、vx 0.28→0.55 m/s 前扑），2.9 s 就倒。
2. **俯仰反馈的符号与髋的符号约定相反**（`kPitch` 取**正**值才接得住；之前坐标下降选到 +1.24
   却在放大前扑，是因为同时还有吸能项在起作用，单项无法隔离）。
3. **Raibert 落脚点的方向**：`x* = ξ + kv·(v_des − v_x)·T_s/2`（慢了把脚放更靠前）。
   写成 `(v_x − v_des)` 会**一路往后走**（实测 −0.26 ~ −1.15 m）。

### 排除掉的两条路（省得以后重试）
- **侧向（髋外展）调节无权**：`kLat` 从 −0.6 扫到 +1.0，位移全是 0.542~0.571 m，一模一样 ——
  因为 CoM.z 只偏离中线 0.01 m，横向根本不是当前的死因。
- **状态触发换脚 vs 固定时钟**：都是 2.92 s，换脚规则不是瓶颈（但状态触发更符合经典做法，保留）。

### 训练目标必须防退化
只按"存活"搜参数时，搜索会买最便宜的稳定：**永远不迈步**（实测 `thresh=0.45` ⇒ 0 次换脚、
活满 8 s）。所以目标用 `活着(20) + 位移 + 0.6×步数 + 0.5×存活`，并给每个参数加物理合理区间。


## 12.10 ★ 把捕获点控制器降维成基因组：一个结构性结论（2026-10-01）

### 目的
手写控制器能走，但它塞不进 4228 个权重。要让 ES 学会走，**至少得有个"会走的起点"**。
做法：把"状态机 + 二连杆 IK"在腿的工作范围（脚在地面附近、腿接近伸直）内线性化 ——
IK 在那附近几乎是线性的 ⇒ 可以用"**线性反馈 + 相位锁定振荡**"逼近。

### 结果：线性近似丢掉了大部分性能（`npm run capgen`）
| | 位移 | 存活 | 真实换脚 |
|---|---|---|---|
| 手写捕获点控制器 | **0.625 m** | 4.32 s | 4 |
| 同参数基因组版（最优） | −0.264 m | 1.77 s | 2（但**一路倒退**）|

### 结构性结论：交替**本质上是不连续**
固定反相正弦 ⇒ 两条腿对称摆 ⇒ **支撑腿也在摆**，永远没有稳定支撑相。
而"哪条腿在摆"在真实行走里由**载荷**决定：被压住的是支撑腿，卸载的才能摆。
所以我给观测**加了两维"每脚载荷份额"**（`control.ts` 里每拍已经算过，白拿），
并把种子写成线性的 `hip = A·(载荷左 − 载荷右)`：载荷大的伸直成支撑、小的屈膝摆动，
差值的正反馈自然形成交替。

⚠ 但**我手写的坐标下降搜不到那个步态**（一直收敛到"不摆腿、站着不动"）——
这是搜索能力的限制，不是物理的限制。ES 有随机重启 + 变异，比我的坐标下降强，
但也**需要正确的引导**（否则同样会收敛到"不动"）。

### 顺带修掉的一个可复现性问题
把求解器冲量接进观测后，"同一份基因组重放得分一致"这条门禁失效了
（存档往返的适应度在第 6 位数字上分叉）——**求解器冲量在不同 Sim 实例之间不是逐位可复现的**。
解法：观测里的载荷份额**量化到 1%**（对策略完全够用），门禁恢复逐位一致。


## 12.11 ★ 观测补齐"行走需要的三样东西" + 三个真 bug（2026-10-01）

### 一、为什么要补这三样
把捕获点控制器降维成基因组（§12.10）失败到只剩 2 步还倒退。逐项排查后发现
**不是权重不够，而是策略根本"看不见"决定行走的三件事**。补进观测（`sim.observe`）：

| 新增 | 维度 | 为什么非有不可 |
|---|---|---|
| 每脚**载荷份额** | 2 | "哪条腿在摆"由载荷决定（被压住的是支撑腿）。没有它只能固定反相正弦 ⇒ 支撑腿也在摆 |
| 每腿**摆动窗口** | 2 | 抬腿是**不连续**决策。给成 0~1 脉冲后，`hip = A·窗口` 一行线性就能写 |
| 两脚**世界 x/z（相对 CoM）** | 4 | 没有它写不出 Raibert 落脚（"脚该落在哪"），只会两条腿一起蹦 |

观测维度：`22 + 6N` → **`30 + 6N`**。新维度全部**追加在关节块之后**，旧权重下标不变，
所以之前调好的镇定器/相位种子全部照常工作（`gait`/`stability`/`coact` 仍全绿）。

⚠ 基准必须取 **CoM**，不能取支撑域中心：`posture.ts` 里 `sup.cx = (x0+x1)/2` 就是
**两脚中点**，所以"脚相对支撑域中心"恒等于 ±半步宽，脚的位置信息被完全抵消（我踩过）。

### 二、三个真 bug（都是"加了东西但没接对"）
1. **观测下标当隐层下标用**：输出行只有 `hidden=32` 项，我却把观测下标（≈98）写进去
   ⇒ 整条 Raibert 项**写到行外被静默丢弃**，表现是"加了落脚增益但结果一模一样"。
2. **抬腿符号反了**：`hip -= amp·窗口` 在 `amp>0` 时把脚**按在地上**（脚最高仅 0.019 m，
   身体被甩出 0.42 m 后扑倒）；符号翻过来才真抬得起来（0.074 m）。
3. ★ **`begin()` 漏了重置 `lastLoadFrac`**（新加的观测量）。Trainer 复用同一个 Sim 训练，
   于是上一代的载荷被带进下一个个体的**第一帧**，而新建 Sim 从默认值开始 ⇒
   "存档→续训"从**第 4 代**起与"一路训到底"分叉（1.490 vs 1.508）。

### 三、由此加了两条门禁（防同类 bug 复发）
- `verify`：**复用的 Sim ≡ 新建的 Sim**（同一基因组逐位同分）——直接盯住"跨 reset 残留状态"。
- `persist` 拆成 **①a 状态逐位相同**（RNG 状态/σ/代数/最优/整份种群，训练**之前**比）
  和 **①b 再训 6 代逐位相等**。
  ⚠ 顺序很关键：训练之后再比种群是没有意义的（适应度不同→选择不同→种群合法分叉）。
  我一度以为 Rapier 跨实例不可复现、想把断言改成容差 —— 实测三个独立实例对同一基因组
  **分差 0.00e+0**，真因就是上面第 3 条。确定性是成立的，断言保持逐位相等。

### 四、现状（诚实记录）
- 手写捕获点控制器：**0.625 m / 4 步 / 4.32 s** —— 仍然是唯一真会走的。
- 基因组版：抬腿幅度、落脚增益都接上了，位移能变正（最大 +0.42 m），
  但那是**扑出去**；**真实换脚数仍是 0**。
- 定位到的剩余缺口：抬腿幅度最大 0.074 m，且**支撑腿拿不到 >70% 载荷** ——
  因为 `kPitch/kCom` 这类反馈对两条腿是**同一组权重**，抬一条腿会同时把另一条也卸掉。
  手写控制器靠 IK 把支撑脚钉在世界上才没这个问题。
  **下一步**：让每条腿的"撑住增益"由**对侧载荷**决定（`hip_l += kL·load_r`），
  即"被压住的那条腿用力撑"——这条是线性的，正是可写进基因组的形态。

## 12.12 ★★★ 根因："训练一直偏好站着不动"不是权重问题，是奖励结构问题（2026-10-01）

### 一、直接测出来的现象
把每代的**最优个体**单独拿出来重跑，打印原始记账量：

```
接地帧: 0脚=1  1脚=0  2脚=359      ← 6 秒里 99.7% 的时间两只脚都在地上
accSingle=-0.008  accLift=0.001  switchQ=0.000  altCount=0
fitness=4.06   其中 jointMove=2.81
```

**最优解是"站在原地疯狂扭关节"**。走路项（lift/single/switch）全部 ≈ 0，
加起来最多给 ~0.3 分，而"要动"一项就给 2.81 —— 差一个数量级，ES 没有任何理由去学走路。

### 二、两个真 bug（都是"看起来在写奖励，实际上没生效"）
1. ★ `jointMove` **没有门控**。修复：只在**恰好一脚着地**（`nGround === 1`）时给分。
   - ⚠ 判据必须是 `=== 1`，不能是 `<= 1`：`<= 1` 会让"**两只脚同时腾空**"（蹦）也拿满分，
     实测第 4 代立刻出现 `jointMove=2.45` 而 `altCount=0` 的蹦跳解。
   - ⚠ 要门控的是**逐关节累加器 `accJtMove`**（`tt.jointMove` 由它算出），
     不是 `accMoveSum`（那个只喂 `moveFrac` 诊断）。我第一次改错了地方、白跑一轮。
2. ★ `bestTermsNow = sim.terms` 存的是**活引用**。`terms` 是 Sim 上的可变字段、
   Trainer 又**复用同一个 Sim** ⇒ 它会被后面每个个体覆盖掉。
   于是历史（和 UI）里"最优个体的分项"一直是**最后一个被评测个体**的分项。
   我据此误判了好几轮（表格里"抬腿 2.81"，同一个体实测 0.00）。修复：`{ ...sim.terms }`。

### 三、修复效果（同一份种子、同一 σ、同样的 6 代）
| | 第 4 代 | 第 5 代 | 第 6 代 |
|---|---|---|---|
| 修复前 | altCount **0** | altCount **0** | altCount **0** |
| 修复后 | — | **altCount 6** | **altCount 7**，单腿分 1.10，1脚=28 帧 |

**ES 自己发现了迈步。**种子会不会走是次要的，**奖励不能奖励原地扭**才是关键。
（顺带：`lift` 项原来两条腿的腾空时间各自独立累加 ⇒ 蹦一下拿双份分，
已改成"恰好一脚离地给满、双脚同时离地给一半"。）

### 四、顺带补上的观测（`30+6N` → `36+6N`）
每条腿的**髋→脚向量 (dx, dy, |d|)**，各 3 维。teacher 的动作就是二连杆 IK
（`acos`/`atan2`），自变量正是这个向量；看不见自己腿长时网络只能用 tanh 硬拟合，
行为克隆 MSE 卡在 0.17、克隆网络实测 −0.832 m / 0 步。

### 五、为此加的门禁
- `npm run steptrain`：训练 6 代内必须出现 `altCount ≥ 2` 的个体，
  且最优个体 `jointMove ≤ 1.5`（不许靠原地扭取胜）。**这条直接盯着上面两个 bug。**
- `posture` 的失败从 3 条降到 1 条（只剩已知的 B3a 脚长敏感性）。

### 六、还没解决的（诚实记录）
- 训练出来的迈步个体会**摔**、会**往后退**（`switchQ=0`，因为它要求在推进时才计价）。
  下一步该动的是 `velTrack` / 目标速度项，而不是再调"要动"。
- 行为克隆（`npm run clone`）能拟合到 MSE 0.17 并**方向为正走 0.627 m / 4.46 s**，
  但仍不产生被检测到的单腿支撑（换脚 0）⇒ 克隆质量还不够，需要更好的拟合或蒸馏。

## 12.13 ★★★ 文献步态参考奖励 + "盆骨优先"（用户 2026-10-02）

用户要求：**程序化地交替奖励骨盆与膝关节**，并且**先查文献**看人走路时这两个关节
怎么动；还指出"人是肌肉发力，可能需要微调"。新增 `src/core/gaitRef.ts`。

### 一、文献依据（关键帧 + 时序）
- **Oberg et al.**（N=116 男/61 女，正常步速 1.19 m/s）：膝 midstance **15.7±5.0°**、
  摆动峰值 **66.9±5.2°**；髋屈伸总活动度 **46.9±5.3°**。
- **Perry / Winter** 八相分期：支撑 60%、摆动 40%；单支撑 10~50%，
  双支撑 0~10% 与 50~60%。膝：IC 5° → 承重 18° → midstance 8° → 预摆动 40° →
  摆动峰值 66° → 伸回 5°。髋：IC 25° → 末期支撑 **−8°（伸展）** → 摆动峰值 30°。
- **Chehab et al.** 关键点分解的重建 RMSE：髋 5.6°、膝 4.8°、踝 3.4°
  ⇒ **容差取 5°**（低于这个量级的偏差临床上没有意义）。
- 参考曲线用 **Fritsch–Carlson 单调三次插值**：关节角在 IC 附近有极值，
  普通样条会插出"假峰"（`probe-gaitref` 里有无过冲的门禁）。

### 二、符号约定：**实测**出来的，不靠猜
`jointAngle(i)` 没有 axis 参数、返回绕本地 Z 的**相对 restRad 偏差**。

（膝屈曲是负角）。这条写在 `gaitRef.ts` 里做单一真源。

### 三、"盆骨优先"（近端先动）的文献口径
① 臀中肌在**触地前**就激活：步行 onset 距 IC **−103.5±79.3 ms**（下楼 −125.7±84.1）。
② 触地后健康人 GMed 延迟仅 **32.7±30.4 ms**；膝 OA 者显著更慢 ⇒ 骨盆掉、膝外翻力矩大。
③ **激活"量"比"时刻"更重要**：GMed 激活量与骨盆倾斜 r_s=0.361、与膝外翻力矩
   r_s=−0.303 显著相关；onset 时刻与两者都不显著（Kim 2015）。
④ 股四头（膝吸震）**不在早期启动**，减速后期才介入 ⇒ 膝**滞后**髋。

实现（`PelvisFirstTracker`）：
- **髋的速度峰值必须先于膝** 50~250 ms；膝先动 ⇒ **负分**（这是要治的病）；
- **触地前 100 ms 髋就在动**（预激活），按"占本步峰值比例"给分；
- ⚠ 测**峰值时刻**而不是启动时刻：实测本 rig 髋/膝 |角速度| 峰值 11~19 rad/s，
  阈值 0.35 rad/s 会在**同一拍内**双双越过 ⇒ 领先量恒为 0 ms（第一版白测了）。

- 参考分能区分"像人"与"乱动"：teacher 1.534 vs 随机 1.136 ✔
- **盆骨优先项的单元测试**（构造已知时序）：髋先动 125 ms → **1.00**；
  膝先动 125 ms → **−0.62（被罚）**；同时动 → 0（有意不给分）✔

### 五、一个诚实的发现

（IK 同时驱动髋和膝，两者峰值同一拍）。所以 `pelvisFirst` 不是给已有控制器加分，

## 12.14 ★★★ "迈步 → 稳住"课程：交替不得太快 + 迈步后能稳住（用户 2026-10-02）

用户原话：
> 交替奖励不得太快，教会迈步之后的稳住才行，甚至要把迈步之后能稳住也纳入奖励之中，
> 可能要找文献怎么迈步后能稳定。

新增 `src/core/stability.ts` + 门禁 `npm run settle`。

### 一、文献依据（全部可量化）
① **稳定裕度 MoS**（Hof et al. 2005）：`MoS = BoS边缘 − XCoM`，`XCoM = x + ẋ/ω`。
   **MoS > 0 才是动态稳定**；MoS < 0 是"不稳的一步"（Pai & Patton 1997）。
   MoS 与"推倒身体所需冲量"成正比。
② **人把 MoS 维持在近似恒定值**（Hof 2008；Rosenblatt & Grabiner 2010；MacLellan & Patla 2006；
   截肢患者亦然）⇒ 人**用落脚位置控制 MoS**。所以奖励不是"越稳越好"，
   而是"**MoS 落在合理带内**"：`MOS_TARGET = 0.30 m`，带外缓慢衰减。
③ **迈步不能太快**（Maki et al.）：摆动 30 ms 太快 ⇒ 支撑域来不及减速 CoM；
   延长到 **~270 ms** 才达最大稳定性；实测人**主动比"最小稳定值"多花 ~135 ms**
   （≈80% 最优稳定性）⇒ 行为上**重稳定、轻速度**。Hof et al. 2010：侧向落脚需 **~0.28 s**。
   ⇒ `MIN_SWING = 0.28 s`。
④ **不稳的步会被立刻修正**：一回归分析里 MoS<0 的步**几乎总是**紧跟一个 MoS≥0 的步
   ⇒ "迈步后能稳住"在数据上就等于"这一步起手不稳、最后稳住了"（人类 recovery step）。
⑤ Horak & Nashner 1986/1987 三策略次序：扰动变大时**髋策略（近端）先于踝策略到达极限**
   ⇒ 与 §12.13 的"盆骨优先"一致。

### 二、设计：奖励"**结算过的步**"，而不是"迈出去的步"
一步要拿分必须 ① 摆动 ≥ MIN_SWING ② 之后 450 ms 内 MoS 保持 ≥ 0。
**计价按"结算分"（渐进塑形）而不是时间积分**：
- 步速分 `paceFrac = clamp01(tSwing / MIN_SWING)`：0.1 s → 0.36 分，0.28 s → 满分；
- 稳分：整窗 MoS ≥ 0 → ×1；起手不稳但收住 → ×0.7（文献④）；没稳住 → ×0.3。
⇒ "迈得慢但每步都稳住"严格优于"迈得快但没稳住"，而且**处处有坡可爬**。

### 三、过程中修掉的 4 个真 bug（都是"看起来在写奖励"）
1. ★ 跟踪器初始状态是 `swing` ⇒ 一条**从不离地**的腿被当成"刚落地、摆动 0 秒"，
   站桩的镇定器被判 **26 次"摆动太快"**，奖励完全反了。初始必须是 `settle`。
2. ★ 接触抖动：Rapier 的接触信号会抖（脚在空中偶发一帧接地），
   teacher 因此被判 9 次"太快"（摆动计时被那一帧清零）⇒ 加**去抖**（连续 2 帧才换状态）。
3. ★ 抖动会伪造"迈步"：站桩时脚的 2 帧假离地被当成步 ⇒ 镇定器拿到 **24 个结算步**。
   ⇒ 加"最小腾空 4 帧（≈33 ms）才算是迈了一步"。
4. ★ `MIN_SWING` 硬阈值是**悬崖**：ES 现有摆动只有 ~0.1 s，硬阈值让它一步都拿不到分，
   `steptrain` 从 altCount=7 掉回 **0** ⇒ 改成渐进塑形后 `steptrain` 恢复通过。
5. 另：`settle` 按时间积分会被"一直站着 MoS 很好"刷分（镇定器一度拿到 26 分）
   ⇒ 改为按累计结算分计价；MoS 的过程梯度交给独立的 `moS` 项（且只在单支撑时给）。

### 四、门禁 `npm run settle`（10 条合成轨迹单元测试 + 端到端，全绿）
| 合成轨迹 | 结算步 | 太快 | 恢复 | 累计分 |
|---|---|---|---|---|
| 快抖 80 ms + MoS 正 | 0 | 6 | 0 | 1.61 |
| 正常 350 ms + MoS 正 | **6** | 0 | 0 | **6.00** |
| 正常 350 ms + MoS 负 | 0 | 0 | 0 | 1.80 |
| 触地不稳→随后稳住 | **6** | 0 | **6** | 4.20 |

判别力来自**结算步数**：只有"迈得慢且稳住"的才算；负向信号由 `moS` 项承担。

### 五、诚实的现状
- **手写捕获点 teacher 目前拿 0 分**：它 6 秒内没能走完一步（末态：左腿仍在摆动相
  `tSwing=200ms`，右腿稳住窗口只到 150/450 ms），MoS 最小 **−712 mm**。
  按 Hof 的判据它**迈步之后并没有稳住** —— 这正是要教的东西，不是 bug。
- 端到端这一层目前只能验证"MoS 在算、站着的人不刷分"；
  "迈步→稳住"状态机的判别力由 10 条合成轨迹单元测试负责。
- 权重：`settle = 3.0`（按累计结算分）、`stepPace = 1.5`（按太快次数罚）、`moS = 0.5`。

## 修复记录：`enforceLimits` 惯量算错导致「到处乱飞」（2026-10-04）

### 现象
ES 训练里很多个体「到处乱飞」——四肢自旋、肢体抽筋，但质心几乎不动。
各代平均适应度被炸到 `-1.2e4 ~ -3.1e5`（正常摔倒约 `-2`），best 却正常（`-0.6 ~ -2.2`）。

### 排查过程
1. 先怀疑是适应度累加器爆炸 → 逐项拆开后发现元凶是 `jointMotion`（占 73%）和 `tiltRate`（占 27%）。
2. 逐 tick 记录 `|ω|`：19.9 → 672.9 → **7060 rad/s**，指数发散；而**力矩被正确限幅在 200 N·m**、指令合法（0.95）。
3. 据此排除「策略问题」，转向数值路径。对三个冲量/力矩通道做二分（`driveMotors` / `enforceLimits` / `applySupportPoint`）：

   | 情况 | 发散个体 | 最差 ωmax |
   |---|---|---|
   | 基线（全开） | 29/30 | 157441 |
   | 关 `driveMotors` | 0/30 | 5461 |
   | **关 `enforceLimits`** | **0/30** | **104** |
   | 关 `applySupportPoint` | 29/30 | 157441 |

4. 逐子步对比 `enforceLimits` 前后 `|ω_rel|`：**每次调用放大 3.6~9.4 倍**
   （neck 1.0→4.3、shoulder_l 2.2→21.0、elbow_l 26.6→96.7）。

### 根因
`ragdoll.enforceLimits` 的限位冲量惯量用了**求和**：

```ts
const Iax = Math.max(Ip.x,Ip.y,Ip.z) + Math.max(Ic.x,Ic.y,Ic.z);   // ✗ 求和
```

两体被冲量耦合时的折合惯量应��**并联** `1/(1/I_p + 1/I_c)`（即已有的 `jointIeff`）。
求和比并联大 **2~9 倍**（等惯量时 sum = 2×harmonic；主惯量各不相等时可到 9×）。

⇒ 施加后实际角速度变化 `J/I_real`远超 `wRel`，**不是「恰好归零」而是过冲并反向**
⇒ 再次越界 → 再次触发 → **每子步放大 4~9 倍的正反馈**。

关键点：它走 `applyTorqueImpulse`，**完全绕过马达力矩限幅**，
所以会出现「力矩只有 200 N·m 而 ω 达 7e4 rad/s」这种看似矛盾的现象。

### 修复
```ts
const Iax = this.jointIeff[i];   // ✓ 并联折合惯量
```

### 效果
| 指标 | 修复前 | 修复后 |
|---|---|---|
| 30 个随机个体发散数（ω>1e4） | 29/30 | **0/30** |
| 最差 ωmax | 157441 rad/s | **96 rad/s** |
| 最差 fitness | −407820 | **−23.4** |
| 平均 fitness | −3e4 量级 | **−13.90** |
| `probe:stand` 零输出 | 站满 30s | 站满 30s |

### 教训
1. **注释里的"保守"可能是反的**：旧注释写「取最大主惯量作保守下界，避免限位形同虚设」，
   但限位冲量要「恰好归零」**必须精确**，用偏大的惯量等于每次都过冲。方向反了。
2. **限幅力矩 ≠ 速度有界**：冲量级通道（`applyTorqueImpulse`）不经过马达限幅，
   能量可以绕开力矩上限注入。看到「力矩正常但速度爆炸」要先怀疑冲量路径。
3. **二分法要确认patch 生效**：`Sim.begin()` 会 `buildWorld()` 重建 ragdoll，
   monkey-patch 必须放在 `begin()` **之后**，否则五种情况读数完全相同（全是无效值）。
4. **不能在 `finished` 之后读状态**：`finish()` 会停马达并清速度，
   要在 rollout 过程中逐 tick 跟踪极值。

## 架构收敛：删除第二套并行状态机（2026-10-04）

用户定调：**「架构需要干净和收敛」** —— 一个平衡维持系统、一个迈步系统、一个状态机、回读与 UI 各只有一处实现。

### 发现的违规

`sim.ts` 里藏着**一整套并行的步态/平衡实现**，与 `gaitState.ts` 逐拍并行推进：

| 并行实体 | 文件 | 与正规实现的冲突 |
|---|---|---|
| `GaitPhaseMachine`（`gp`） | `gaitPhase.ts` | 每拍 `gp.step()`，自己的 `'both'\|'step'\|'adjust'` 相位 |
| `GaitCommander`（`cmd`） | `commander.ts` | 每拍 `cmd.step()`；**`orderLeg(cmd.now)` 决定摆动腿** |
| `ModuleSet`（`mod`） | `modules.ts` | reward 的相位门禁 `mod.active(name, gp.now, …)` |
| `PelvisFirstTracker`（`pfL/pfR`） | `gaitRef.ts` | 「盆骨优先」评分有自己的跟踪器 |
| `BalanceJudge`（`bal`） | `balanceJudge.ts` | 第二套平衡判据（`HEAD_MIN/MAX` 被 `void` 显式丢弃） |

⇒ **控制走 `gaitState`，评分走 `gp`/`cmd`**。摆动腿、相位门禁、循环信用三处判据分叉。
最严重的是 `DEFAULT_SIM.driver = 'brain'`（`sim.ts:221`）—— **默认路径根本不经过
`gaitState`/`balanceSystem`/`stepSystem`**，而 4 个探针全部显式 `driver:'controller'`。

### 收敛做法

**相位与摆动腿只有 `gaitState` 一个来源。**

1. `Sim.attachRigState(rs)` —— 由 `Controller` 构造时注入 `RigState`
   （`controller.ts`）。reward 的相位/摆动腿从此读 `gaitState`。
2. `Sim.gaitPhase` —— 归一化访问器，把 `rs.phase`（`DOUBLE/SHIFT/SINGLE/PUSH/STEP`）
   映射到原三值口径（`both/step/adjust`），供少量 `===` 比较用。
3. `Sim.gaitSwingLeg` —— 摆动腿取 `rs.swingLeg()`；无 `RigState`（`driver='brain'`）
   时退回接地数几何判据，**不再有第二套状态机**。
4. `Sim.gate(name, nGround)` —— 替代 `ModuleSet.active(...)`，**纯函数**
   `f(相位, 接地脚数)`，无内部状态、无 `reset()`。
5. 循环信用（原 `gp.tally.lastCredit`）改由 `rs.phase === 'SINGLE'` 直接判定。
6. **删除文件**：`gaitPhase.ts`、`commander.ts`、`modules.ts`。
7. 删除死 getter `cmdOrders/cmdTimeline/cmdLabel/stateTrace`（外部零引用）。

**保留**（不是控制状态机，是 reward 侧测量）：
- `wholeBodyAngularMomentum`（纯函数，Herr 2008 的 L(t)≈0 判据）
- `BalanceJudge`（WBAM 导数 + 头高比 + `valid` 闸门的**累加器**，不做控制决策）
- `scoreLeg`/`STANCE_FRAC`（文献步态形状的**纯函数**评分）
- `PelvisFirstTracker`（髋领先时序的**逐腿测量**，不决定相位）

- `sim.ts` 不 import 任何并行状态机模块

4. **`main.ts`**：`onDriver` 退化为「(重)建控制器会话」；主循环只保留控制器分支。
5. **`lab.ts` / `hud.ts`**：`Driver` 类型从 `'brain' | 'teacher'` 收敛为单取值 `'teacher'`

6. **全部探针**里冗余的 `driver:'controller'` 一并删除（唯一路径，没有可错的地方）。

## 矢状面站不住：不是缺摩擦，是缺踝的 CoP 权限（2026-10-04）

用户提问方向：「我需要柔性足和摩擦力，看来我需要一个专门负责环境条件的、
专门施加外力，不然脚部的侧向摩擦力无从谈起。」

### 先作废两个错误的实测读数（我自己的测量错误）

| 曾经的结论 | 作废原因 |
|---|---|
| 「承重脚水平发力 `Fx` 恒为 0」 | 用了**不存在的** Rapier API `manifold.tangentImpulse()`，异常被 `try/catch` 吞掉后返回 0。真实接口只有 `contactImpulse()` 与 `normal()`，**不暴露切向冲量** |
| 「踝实际力矩只有 0~9 N·m」 | 探针没走 `Controller` 的 `sim.motor.set(out)` 写入路径，读的是从未被更新的 `motorTarget` 数组。换对路径后踝实际 **28~57 N·m**（且 `τ需求 = τ实际`，未被削） |

### 环境的真实状态：摩擦**不是**瓶颈

- 地面 `groundFriction = 1.0`、身体 `bodyFriction = 0.9`，Rapier 默认 Average
  ⇒ 合成摩擦系数 **0.95**，法向力 ~60~90 N ⇒ **摩擦容量约 60~85 N**。
- 脚掌滑移速度全程 **0.0008~0.008 m/s** ⇒ **静摩擦一直在锁住脚**，不是自由滑动。
- 捕获点漂到 −49 mm 时**仍在支撑面内**（脚半长 140 mm）⇒ **理论上可救**。

⇒ **缺的不是摩擦，是「把 CoP 推到捕获点要求的位置」所需的踝力矩。**
踝 `τ = 30~57 N·m`（上限 120），踝角只走到 −3°，而负向还剩 −10° ⇒ 权限耗尽。

### 为什么打不开矢状面的地面反力通道

试过 `torqueControl: true`，结果与 `false` **逐位相同**（存活 2.2 s、|com.x| 959 mm、|vx| 1.471）。

原因不是漏了开关，而是**轴归属把它排除**：

- `τ = JᵀF`（`jacobianTorque`）的结果只写 **`hip/0`（外展轴）**；
- 矢状的 `hip/2`·`knee/2`·`foot/2` 归**位置伺服**；
- 那条「挡位 II 让位」的分支是**被有意删掉的** —— 保留会在同一轴上双计，
  轴归属门禁实测 3 处冲突（见 `balance.ts` 挡位 I 注释）。

⇒ `wantedForce` 算出的 `comp.sagittal = 84~141 N`（同期 LIPM 需求只要 4→30 N，**够用**）
**在架构上到不了矢状关节**。矢状面的唯一执行器是位置伺服，
它的瓶颈就是踝 CoP 权限（`kCopSag = 6`、`maxAnkleSag` 限幅）。

### ⇒ 下一步：柔性足（用户已有论文依据）

刚性脚绕踝转动 ⇒ CoP 迁移受**关节角**限制（只剩 7°）。
柔性足让 CoP 在**接触面内**迁移而不受刚性转动约束 ⇒ 把这 7° 放大成几十 mm CoP 行程。
这属于**接触/环境模型**（`ragdoll.ts` 的 collider 构造与足部接触参数），
正好落在用户说的「专门负责环境条件」那个职责上——但**不新增控制系统**：
力仍由 `balanceSystem` 经 `requestTorque` 进入现有仲裁链。

### 附：把 `torqueControl` 保持为 true 的理由

它现在是「侧向外展轴的 τ 通道开关」，与矢状无关。但保留 `true` 让
`latTransfer`（额状重心转移，唯一写者 = `τ=JᵀF`）真正生效 ——
这与用户「不要双脚均匀受力、尽快把重心压到一只脚」的目标直接相关。

## A.1 「平衡态」的文献定义

**MSt（中支撑，12-31%）就是"重心转移到支撑脚上"的那一帧** —— Perry 原文

period does body alignment approximate that of a stable quiet-standing posture」。

## A.4 伺服机制：三条依据

# ★★★ 附录 B：静态伺服平衡 = **全链一次性求解**（2026-10-05 用户定调）

## B.0 为什么要推翻现有的"逐关节 PD"

现有伺服是**逐关节独立位置环**：每个关节各自算 `τ = kP·(θ_ref−θ) − kD·ω`，
各自被自己的稳定性护栏（`|τ·dt| ≤ α·|err|·I_eff`）夹住。实测下来的后果：

| 实测现象 | 出处 |
|---|---|
| 弓的 `archStiffness` 从 3 扫到 260，弓角摆幅**恒为 20°**、结果逐位相同 | `probe-footroll` |
| 马达权限 `τ应用/τ需求 = 0%`（hold 分支 171 / 50262） | `probe-stand` |
| 同一帧里各轴的修正互相顶，实测互相抵消 | `probe-coact` |

根因是**结构性的**，不是调参能解决的：

1. **各关节不知道别人在做什么。** 髋外展往 +Z 推，膝 unknowingly 也在改侧向；
   两者的效果在足部叠加后可能**互相抵消**，而两边都以为自己做完了。
2. **护栏各自算 `I_eff`。** 承重脚被地面反作用约束，它的等效惯量是"整个身体绕踝的
   惯量"（≈0.5~1 kg·m²），不是脚掌自身的质量（薄盒脚掌 ≈0.005）。用后者算，
   踝只能拿到 τmax 的 **3~8%**——而所有指标看起来都"正常"（同一个坑修过两次）。
3. **不存在唯一的解。** 逐关节独立求解 ⇒ 同一个"把重心挪过去"的需求，有无穷多种
   关节力矩分配方式；护栏再各自截断，最终落地的是**互相矛盾后剩下的残数**。

⇒ **这不是"再调一版增益"能救的**，必须换求解结构。

## B.1 两类系统的职责边界（用户定调，不可混淆）

| | 迈步系统 `step` | 伺服平衡 `balance` |
|---|---|---|
| 时间尺度 | 一个相位里**依次**推进 | **每个控制拍一次** |
| 作用范围 | **一次动一个模块**（单腿、单相位） | **从足部到身体整条力链一起求** |
| 输出 | 一串关节目标角 | **一个唯一的、综合的、完整的修正方案** |
| 允许互相干扰吗 | 允许（它就是在动） | **不允许**（必须自洽） |

**关键区别在"一次动一个模块" vs "整链一次求解"**：
迈步本质是**时序**问题（这一拍抬哪条腿、髋屈多少），可以分步推进；
而平衡是**耦合**问题（CoM 要往 +Z 挪 50mm，踝/膝/髋/脊柱各该出多少力矩），
拆开求就必然互相矛盾。

## B.2 求解的物理模型（整链，一次）

把"保持/修正平衡"写成一个**带约束的最小范数问题**（QP），每个控制拍解一次：

```
minimize  ‖ W·τ ‖²                        （力矩尽量小 ⇒ 唯一解）
subject to
   M·a_des + g = Sᵀ·f_ground + Jᵀ·τ        （① 全链牛顿-欧拉：唯一等式约束）
   CoP = c(f_ground) ∈ 支撑多边形           （② 压力中心不许跑到脚外）
   f_ground·ŷ ≥ 0                          （③ 地面只能推不能拉）
   f_ground·ŷ = m·g  (Σ 法向 = 体重)         （④ 竖直方向必须被地面托住）
   |τ_j| ≤ τmax_j                          （⑤ 力矩限幅）
   θ_min ≤ θ ≤ θ_max                       （⑥ 关节限位）
   θ_ref,ref − Δ ≤ θ* ≤ θ_ref,ref + Δ       （⑦ 别离关键帧太远）
```

其中：

- `S` = 接触选择矩阵（哪几块鞋底着地），`f_ground` = 未知的地面反力（多个接触点）
- `J` = 全身雅可比（**所有**关节，含踝与弓），`τ` = 所有关节力矩
- `a_des` = 期望的 CoM 加速度（由 DCM / ξ 给出，见 B.3）
- `W` = 加权对角阵（各关节按 τmax 归一 ⇒ "最小力矩"而不是"最小角速度误差"）

### 为什么这个解是**唯一**的

`minimize ‖W·τ‖²` 配合**等式**约束 ①，在 `W` 正定时，
可行集是仿射子空间、目标函数严格凸 ⇒ **唯一解**（QP 的 KKT 条件给出唯一 τ）。
约束 ②③④⑤⑥⑦ 只做**截断**（active set），不引入第二个解。

这一条是用户"**每次给出一个唯一的、综合的、完整的修正方案**"的数学落点：
不是"给出一堆各自还行的修正，让它们碰碰运气"，而是"给出**那一个**自洽解"。

## B.3 `a_des` 从哪来（衔接附录 A）

伺服平衡不自己发明目标，只把两个物理量变成一个期望加速度：

```
ξ = CoM_z − (CoM_zdot / ω₀) · DCM_z,   ω₀ = √(g / h_com)     ← 附录 A 的 LIPM
a_des,z = −k_ξ·(ξ − ξ_target) − k_ẋ·(CoM_zdot − ĊoM_zdot)      ← ξ 收敛律
a_des,x = k_form · (支撑面内多边形形心 − CoM_x)                  ← 防前后倒
a_des,y = k_support · (m·g − Σf_ground,ŷ)                       ← 见 B.5
```

`ξ_target` 由**相位**给（`GaitState` 的 `keyPose`），不由平衡自己定 ——
这就是附录 A.3「两套系统不再抢同一根轴」在解算器里的具体形式。

## B.4 与现有代码的对应关系（哪些能留、哪些必须换）

| 现有 | 处置 | 理由 |
|---|---|---|
| `balance.ts` 的 `latStiff`/`latDamp`（Winter 伺服） | **并入 `W`** | Winter 的 `K = I·ω₀²` 变成 QP 的权重，而不是独立的 PD |
| `postureLoadGain`/`toneScale[]`（载荷依赖张力） | **变成约束 ④⑤ 的活跃集** | "承重时张力更大"是 QP 在接触约束下自然给出的结果，不需要单独特判 |
| `torqueCmd`（`τ = JᵀF` 单关节通道） | **换成 ① 的解** | 它现在是"只靠髋外展推"（已实测有害并部分删除），正是"一次动一个模块"的错误形态 |
| `Ragdoll` 的 `motorAlpha` 护栏 | **降级为安全网** | QP 已在约束 ⑤⑥ 内解出合法 τ，护栏不再参与"能不能出力"的决策 |
| `holdCmd` 让位分支（P 项置零） | **删除** | 它是"定量支撑交给 JᵀF"这一临时架构的遗留；QP 一次性给出完整方案，不需要让位 |
| `step.ts` 的摆动腿角度律 | **保留不变** | 迈步系统按 B.1 就该"一次动一个模块"，不参与全链求解 |
| 弓的 `ForceBased` 电机（K=400） | **保留** | 真实足弓是刚性桁架；它由 Rapier 隐式求解，不与 QP 冲突 |

## B.5 求解频率与奇异点处理

- **频率**：每个**控制拍**解一次（现 60Hz）。关节力矩在拍内零阶保持。
  ⇒ 这也是 60Hz 弹跳嫌疑的排查对象之一（见 B.7）。
- **接触集合切换**：支撑腿切换时 `S` 变列数 ⇒ 解跳变。
  处理：切换后先跑 **2~3 拍"无解也不施力"**（让接触自己稳定），
  锁定期内 `a_des` 只用支撑腿的 ξ，**不**提前给新腿加权（B.6 的锁机制）。
- **欠驱动/奇异**：`τmax` 全被约束住时 QP 可能不可行 ⇒ 退化为**加权最小二乘**
  （软约束），并把"不可行度"作为诊断量回读，绝不静默。
- **地面法向不足**（`Σf_ŷ < m·g`）在真站立里必然发生（除非有外力），
  所以 ④ 只能是**软**约束；此时身体在下落，`a_des,y` 应给出负值去追，
  而不是硬要求托住。

## B.6 与锁机制的衔接

B.1 说平衡"整链一次求解"，而状态机有"支撑腿锁定"。二者不冲突，但必须分清：

- `locked` = **承诺**（这拍只信这条腿的 ξ），由 `GaitState` 拥有；
- QP 的解 = **执行**（在承诺范围内自己分配怎么做到），由 `balance` 拥有。

QP **不允许**改写 `locked`，只允许在 `locked` 给定的支撑集合内求解。
交接（Handover）时 `S` 变化，QP 自然会把权重从旧腿搬到新腿 ——
**不需要**现在那段"先在髋部造一个横向力把 CoM 推过去"的力通道（已实测有害）。

## B.7 已知未解决（不能假装已解决）

- **60Hz 周期-2 竖向振动**（去趋势后 18~24mm/帧、r≈0.95）。
  已实测排除：马达出力（归零仍在）、`motorAlpha`、控制频率、共面块接缝（留缝无效）、
  弓本身。`enforceLimits` 是部分贡献（24.5mm → 10.5mm）但非根因。

  ⇒ 这是当前**第一优先**，因为它污染 ξ 的测量，QP 求解器接上去也无从验收。

## C.0 本节的前提：站立秒数不是验收指标

用户 2026-10-05 明确：**「该做的机制做就行了，不需要在意 1s、2s 的站立时间差距」**。

起因是同一个"站立时长"被误读了**四次**，每次错法不同：

| 曾报的数字 | 实情 |
|---|---|
| 18s+ | 弓未接串联链时（弓关节力 1N＝自重，等于没有柔性足）|
| 7.37s / 4.43s | **死亡判定触发时刻**，不是站立极限 |
| 6.00s | `duration=6` 跑满，`finish(false)` ≠ 摔倒 |
| "2s 都没有" | 判据阈值换过 ���次，每次结论不同 |

⇒ 因此：

1. **站立判据唯一化**到 `src/core/standing.ts`，三类结束互斥穷尽
   （`fell` / `survived` 跑满 / `aborted` 探针中断），探针只准调它，不准自己拼结论。
2. **跌倒判定只剩一条：头碰地**（用户定调）。砍掉 `bodyHitGround`（弓/内侧前足
   合法承重时就要接地，拿它们当判据等于"脚一干活就死"）、躯干高度比、倾角。
3. 退化判据的阈值**来自实测静立噪声**（CoP 噪声底 AP≈18mm / ML≈6mm，
   Nigg 2006），不是拍的；退化方向取"最先越界"的那一项，按退化量排序。

**这一节的验收标准是"机制是否正确、自洽、可回读"，不是秒数。**

## C.1 全链 QP（`src/core/systems/wholeBodyQp.ts`）

### 要解决的问题（全部实测，非推断）

- 逐关节独立 PD 下，各轴不知道别人在做什么，修正在足部**互相抵消**而两边都以为做完了
- 护栏各自用**自由**惯量算。承重脚的等效惯量是"身体绕踝的惯量"（0.5~1 kg·m²），
  不是脚掌自身的 0.005 ⇒ 踝只能拿到 τmax 的 3~8%，**而所有指标看起来都正常**
- **不存在唯一的解**：同一需求有无穷多种力矩分配，护栏各自截断后落地的是残数

### 问题形式

```
minimize   Σ wᵢ·τᵢ²
s.t.       Σ τᵢ·(axisᵢ × rᵢ) = F_des          ← 水平两个方向
           |τᵢ| ≤ τmaxᵢ                         ← 盒
           F_des ∈ cone(支撑多边形)               ← CoP 可行
```

目标严格凸 + 等式约束 ⇒ 目标函数在仿射子空间上严格凸 ⇒ **唯一解**。
这就是 B.2 那条"唯一的、综合的、完整的修正方案"的数学落点。

### 算法：主动集法（POCS 被实测否掉）

试过 POCS（投影梯度），两种失败都记在代码注释里：

| 做法 | 实测后果 |
|---|---|
| 交替投影，步长 1.0 | 等式投影把刚夹回盒内的分量推出去 ⇒ 输出达 τmax 的 **100 倍**（髋矢状 −41997 N·m vs τmax 200）|
| 交替投影，步长 0.5 | 在盒边界来回弹跳 ⇒ `F_des=20N` 给出 **322.8N**（过冲 16 倍）|

**盒 + 等式这类混合约束上 POCS 不收敛。** 改用主动集：把违规轴钉在边界、
对剩下的自由轴解降维后的 1×1 / 2×2 闭式 ⇒ 精确、单调、无过冲。

### 两个必须记对的力学点

**① 力臂必须三维，且用叉积 `c = axis × r`。**

第一版只留 `rx/rz` 两个分量，把「绕 X 轴（额状旋转）」当成能产生侧向力 —— 反了。
绕 X 产生的是**前后向**力（`c_x = −a_z·r_y`）。

这恰好纠正了一个此前归因错的观察：**踝的额状权限弱是几何决定的**（踝离地只有
5cm 力臂），不是增益问题。矢状同理：`c_z = a_x·r_y`，臂也是 5cm。

**② CoP 可行性 = 合成水平力落在支撑多边形的凸锥内**（Piazza et al. 2024,
arXiv:2401.05318, Thm 1 / Lemma 1：ZMP ∈ conv(S) ⇔ 存在纯压力的可行接触力分布）。

第一版写的是 `|F| ≤ 半宽 × 686` —— **686 是体重（竖直方向）**，与水平分力的
可行性毫无关系，纯属臆造。已删。

### 离线验收（`tools/probe-qp.ts`，不依赖仿真状态）

| 项 | 判据 | 结果 |
|---|---|---|
| 唯一性 | 同一输入多次求解 | 三次**逐位相同** |
| 等式残差 | 合成 == F_des | **0.00 N** |
| 限幅 | 无轴超 τmax | 0 轴超限 |
| 欠定 | F_des=300/1000/3000N | 残差如实报出、`feasible=✗`（不静默）|
| 权重旋钮 | `ankleMul` 4→1→0 | 踝从主动参与 → 完全排除，分配按预期变化 |

### 接线

- 轴：承重腿整条链（踝/膝/髋）+ 腰（spine1/2/3），矢状 + 额状
- `F_des` 由 ξ 收敛律给出：`F = −m·ω₀²·ξ`，**只水平两方向**（竖向由体重承担）
- 解走 `rs.requestTorque`（`mode='tau'`），**不与位置环双计**
- `wholeBodyBalanceTick()` 每拍调一次，返回可回读的 `QpTick`

```

踝旋前    0.3   膝侧   8.2   髋侧  23.3   腰侧倾  9.3
踝矢状   -0.3   膝矢状 -10.9  髋矢状 -31.1  腰屈伸 -12.4
```

髋能出的力大 18 倍**。这是几何决定的，不是权重设置问题。

## C.2 弓的串联承力链（`柔性足设计.md` §8.1）

### C.6 `F_des` 的参考点：这是本轮最贵的 bug

第一版 `ξ = com − ẋ/ω₀` 用了**两个错**的参考点：

2. **单脚鞋底中心**：实测左脚 `soleBounds Z=[0.077,0.257]` ⇒ 中心 `z=+0.167`，

| 等式残差 | 137~478N | **恒 0.00N** |

### C.7 ★ 下一个机制缺口：QP 的等式**不含体重**

12s 真实对比：

| | com.y | 头碰地 | com 漂移 |
|---|---|---|---|
| QP 开 | 0.9623 → **0.2987** | 未碰 | +1.362m (X) |
| QP 关 | 0.9623 → 0.1211 | — | — |

**两种模式都塌**（QP 略好）。原因是结构性的，不是调参：

> 现在的等式是 `Στᵢ(axisᵢ×rᵢ) = F_des`，**只管水平地面反力**。
> 而"撑住 70kg 体重"需要的静力矩（原 `sagSupport` 位置环提供 ~52 N·m 髋力矩）
> **根本不在这个等式里**。QP 把它算出来，就必然把它擦掉。

⇒ 必须把等式换成附录 B.2 的**完整逆动力学**：

```
minimize  Σ wᵢ·τᵢ²
s.t.      M(q)·a_des + C(q,q̇) + g(q) = Sᵀτ + JᵀF_contact
          F_contact ∈ contact wrench cone
          F_des = M·a_des + C + g − Sᵀτ   （竖向也在内）
```

即：**法向力也进等式**，竖向不再"由体重承担"这句假设。
当前实现的准确定位是**水平地面反力的全链力矩分配器**，不是全身平衡器。
在补上这个之前，不能说静态伺服平衡做完了。

（注意：com 漂移在 **X** 方向，而脚长 283mm 在 X、宽 180mm 在 Z
 ⇒ 本 rig 的 X 是前后向。**这与"`hip/0` = 外展"那条轴注释不一致**，
   需另开一条核对，本轮未处理。）
