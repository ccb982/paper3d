## 0. 定调与验收（不可协商）

### 0.1 用户定调（架构级）

1. **一个平衡系统主动调控所有关节力矩**；静息输出即人类量级。
2. **主动修正机制只有一个**（阻尼、脊柱张力不算"修正"）。
3. **承重无上限，发力有上限**。
4. **唯二判定标准**——见 §0.2。**站立时长不属于架构验收，属于控制算法阶段**。
5. **关节没有"可控的运动"之前，一切控制算法无从谈起。**
   ⇒ 本轮（第二轮）的**唯一**目标 = 把"关节权限"这件事做成可测、可复现的事实。

### 0.2 唯二判定标准

| # | 标准 | 工具 | 通过线 |
|---|---|---|---|
| ① | **脚不打滑** | `probe-slip` | 每拍窜动 ≤ 1mm 量级 |
| ② | **发力真能拉回身体** | `probe-deadchan` + `probe-authority` | 注入 τ 后 `applied` 随之改变（通道通）**且** CoP 位移 ≥ 理论 `τ/Fz` 的 50% |

> ★ 2026-10-08 新增判据 ②a "**通道通**"：见 §5.2 的 A0 教训——
> 在证明"力不够"之前，必须先证明"力到得了"。这是本次新增的强制前置检查。

### 0.3 永不再犯清单（考古结论，逐条带实测出处）

| # | 禁则 | 为什么 |
|---|---|---|
| N1 | **禁止两条 τ 通道争同一根轴**（同轴相加/覆盖） | v3 实测 10× 权威衰减；2026-10-08 又发现 `torqueCmd` 被 `v4Tau` 无条件覆盖 ⇒ 全套权威探针假阴性 |
| N2 | **禁止把"站立时长"当架构指标** | 它是控制器品质，会掩盖结构缺陷（v3 曾用它把架构问题"测没了"） |

## 2. 物理层：τ 注入的唯一通道（★ A0 修复点）

### 2.1 事实：Rapier 里的关节 τ 由两条"外部通道"叠加

```ts
// ragdoll.ts（修复后）
let tq = this.torqueCmd[idx]!;              // 通道①：仲裁器出口（setTorqueTargets）
if (this.v4Tau.length > 0) {
  tq += vs * (this.v4Tau[idx] ?? 0);        // 通道②：v4 控制输出（setV4Torques）
}
tau = clamp(位置环反馈) + tq               // ③ 位置环反馈（err·τmax/(ωmax·k)）
```

**语义**：位置环给反馈、两条 τ 通道给前馈，**相加后整体饱和**。
符号矩阵（`V4SGN/V4SFK/V4SFH/V4SFA`）**只作用于通道②**。

### 2.2 A0 修复了什么（2026-10-08）

**修复前**：
```ts
let tq = this.torqueCmd[idx]!;
if (this.v4Tau.length > 0) tq = vs * this.v4Tau[idx];   // ← 无条件覆盖
```

**后果链**：
```
controller.ts:647  AUTH_TAU 注入 → rs.requestTorque → rs.treq
controller.ts:663  setTorqueTargets(rs.tauOut) → ragdoll.torqueCmd
ragdoll.ts:3308    let tq = torqueCmd        ← 读到了
ragdoll.ts:3317    tq = vs * v4Tau           ← 丢弃，覆盖
```
⇒ **所有走仲裁器 τ 通道的注入/实验永久无效**（假阴性）。
`probe-authority`、`probe-lift-waist` 的"注入没反应"全由此解释。

**实测铁证**（`probe-deadchan`，注入 `foot_l/axis2 = +40 N·m`）：

| t (s) | 修复前 `applied` | 修复后 `applied` | 说明 |
|---|---|---|---|
| 0.608 | **−120.0** | **−97.7** | 前：等于 `v4Tau`（注入被丢）；后：`−137.7→clamp` |
| 0.642 | **−107.8** | **−67.8** | 逐位等于 `v4Tau` ⇒ 铁证 |
| 0.675 | **−62.2** | **−26.5** | 同上 |

**风险**：零。生产路径上 `rs.treq` 唯一写者是 `AUTH_TAU` 探针钩子
（`grep requestTorque` 仅 `controller.ts:647`）⇒ `tauOut ≡ 0` ⇒ 修复式退化为旧行为，
**逐位等价**（已用备份 A/B 验证）。

> ★ **遗留待办**：`v4Tau` 目前**不享受稳定性护栏豁免**（`ragdoll.ts:3425` 的
> `ff` 只含 `torqueCmd`）。语义上 v4 输出也是前馈，应一并豁免。
> 但这会改变行为 ⇒ 留给 §7 的 A1，与"躯干任务唯一化"同批 A/B。

## 3. 动力学定理：力怎么进腰（证明二的形式化）

> 文献：Shafiee-Ashtiani et al. 2016/2017（CMP/ZMP 分解）；Pratt et al. 2006（Capture Point
> + hip strategy 的 Capture Region）。

### 3.1 两通道分解

```
外部通道（唯一能动 CoM）：  m·a_CoM = F_GRF + m·g
                            Ḣ_CoM  = (CoP − CoM) × F_z
内部通道（不动 CoM）：      Ḣ_trunk = τ_hip − τ_spine
恒等关系：                  CMP := CoP − Ḣ_CoM/F_z
```

### 3.2 定理（"力进腰"的充要路径）

1. 地面力 `F*` 改 **CoM 轨迹**（外）——L1 的领地。
2. 髋力矩 `τ_hip` 改 **躯干角动量 Ḣ_trunk**（内）——**它不出现在 CoM 方程里**。
3. 二者在 **CoP 处交汇**：髋力矩能重分配两脚载荷 ⇒ 移动 CoP。

⇒ **"力进腰" ≡ `τ_hip` 进入躯干角动量方程。**
这不是"力够不够"的问题，是"**有没有这条通道**"的问题。

### 3.3 量化：髋策略能扩展多少捕获范围

Pratt 2006 的 Capture Region（含飞轮/髋策略）：

```
Capt_region = Capt_point ± (τ_max / (m·g)) · [(e^{ωT_R2} − 2e^{ω(T_R2−T_R1)} + 1) / e^{ωT_R2}]
其中 ω = √(g/z₀)
```

**代入本项目实测值**：`m = 56.0 kg`（`rs.sk.massTotal`）、`g = 9.81`、
`z₀ = 0.966 m`（`probe-stability`）⇒ `ω = 3.19 rad/s`。
躯干可施加的髋矩 `τ_hip ≤ 200 N·m` 级（实测 `probe-deadchan` 中 `v4Tau` 峰值 ~170 N·m）。

⇒ `τ_max/(mg) = 200/(56×9.81) = 0.364 m` —— **单看量级就比踝的 CoP 权限
（前后 ±0.110 m，`probe-stability`）大 3.3 倍。**

**结论**：**髋策略不是"备选"，它是比踝更强的平衡权限来源。**
把 `kTrunk` 出厂设成 0（`controlV1` 的现状）等于**主动放弃了最大的权限**。

### 3.4 与 §0.1 定调 2 的关系（"主动修正机制只有一个"）

- 踝 CoP 策略 = 通过**移动 CoP** 改 CoM 加速度（外）；
- 髋策略 = 通过**产生 Ḣ_trunk** 改 CMP（内），从而把 `CMP` 从 `CoP` 处**拉开**，
  等效于**在力层扩展可达的 CoP 范围**。

两者**不是两个"修正"**，而是**同一个 CoP/CMP 分配问题的两个执行器**——
这正好符合定调"一个平衡系统主动调控所有关节力矩"。

## 4. 控制层：为什么用分段职责（chainV1）而不是整体 QP

### 4.1 两种范式的取舍

| | WBC-QP（`controlV1`） | 分段职责（`chainV1`） |
|---|---|---|
| 文献 | Bellicoso 2018；Sentis & Khatib 2005 | 工程化：给每根轴一个显式写者 |
| 决策变量 | `[q̈; τ; λ]` 联合解 | 无联合解，逐段累加 |
| 优点 | 理论上能处理约束耦合 | **可解释、可单点隔离、可单点验收** |
| 缺点 | "所有关节 τ 一起算" ⇒ 串味/对拉；难定位 | 段间耦合靠人工设计 |

**项目选择：分段职责为默认（`V4CHAIN=1`）。**
理由：项目当前的第一矛盾是"**关节权限不可测**"，不是"约束耦合不够好"。
分段职责能把"哪一段没出力"直接测出来；QP 只会给一个"整体最优但看不出谁没干活"的解。

> ★ `controlV1` **保留**为对照分支（`V4CHAIN=0`）。**不删**——
> 它是唯一能验证"分段职责是否输给联合优化"的基准。删了就没有 A/B 了。

### 4.2 chainV1 的分段契约（每轴唯一写者）

```
腿（per leg）：
  support 段 → 膝（高度 PD，VHIP λ 的工程形）
  cop     段 → 踝（ξ 相对偏差 → CoP 修正）
  trunk   段 → 髋（躯干俯仰/侧倾 → τ_hip）    ★ 这就是 §3.2 的 T2
躯干（全局）：
  脊柱张力段 → spine1..3（可调的静态支撑，非"修正"）
```

**当前缺陷（§7 的 A2/A3 要修）**：
- `segTrunk` 被 `g = clamp(|xiErr|/0.05, 0, 1)` 门控 ⇒ **站桩 ξ≈0 ⇒ 躯干段输出 = 0**。
  这是"静止时腿/腰零出力"的同一个结构性原因。
- `xiErr = xiX − copBase`，而 `copBase = comX`（无命令时）⇒ `xiErr = vx/ω` ⇒ **零速即零输出**。

### 4.3 优先级与冲突（与文献对齐）

Sentis & Khatib 2005 的层次：**约束 > 操作任务 > 姿势**，用零空间投影
`τ = J₁ᵀF₁ + N̄₁ᵀJ₂ᵀF₂ + …`，`J₁N̄₁ ≡ 0`。

本项目的对应：
```
约束（不可违反）= 关节限位 + 摩擦锥 + 接触不滑      → ragdoll 层硬实现
操作任务（平衡） = CoM/CoP 目标（cop 段 + support 段）→ 最高优先
姿势（残余）     = 躯干俯仰 + 脊柱张力                → 在平衡任务之后
```

**当前的实现是"加法 + 饱和"而非"零空间投影"**——
这在两个任务都在同一根轴上冲突时会内斗（N1 的历史根源）。
**§7 的 A1 需要一个"同轴冲突检测"**：若两个段写同一根轴，必须显式声明优先级，
不允许隐式相加。

```
感知层（只读）      提案层（只写自己的产物）      执行层（唯一 τ 写者）
─────────────       ─────────────────────       ──────────────────
```

**契约（硬）**：
- 感知层**不发目标、不发力矩**，只写 `rs.copPlan` / `warning`。
- 提案层**不发力矩**，只写"落足点/位移意图"（`rs.copPlan`、`rs.shiftDemandF`）。
- 执行层是**唯一 τ 生成者**。
