# 重构方案：承重腿标识 + 锁定腿闸门 + 单一关节状态 + 显式交换协议

> 本文只写**架构**，不写实现。
> 每条设计后面标了文献依据；**没有依据的数字标了"需自行推导"**。

---

## 0. 为什么要重构

现在「**这条腿是谁**」「**这条腿能不能抬**」「**这个关节该听谁的**」三件事
写在 `teacher.ts` 一个 1300 行函数里（45 个可变闭包变量，`stanceL` 被 **6 处**赋值，
其中两处是重复的同一行），并且**三套状态机**（`sim.gp`、`wtStage`、`latchedStance`）
同时回答同一个问题。

后果有两类：
- **同轴多 owner**：实测 `hip_l/0` 一格里 `balance` 与 `step` 同时在写。
- **文档与代码不一致**：`ankleEnabled=false`（本 rig 没有踝），
  但 `balanceHold.ts` 整段踝 CoP 策略建立在「踝存在」之上，且**无法被证伪**。

## 1. 核心语义：承重腿 ≠ 锁定腿

**两个独立字段，不是一个 bool。**

| | **承重腿 load-bearer** | **锁定腿 locked** |
|---|---|---|
| 本质 | 一枚**标识** | 一道**闸门** |
| 获得 | **必须检测达标**才授予 | **触地瞬间**，无条件 |
| 语义 | 「系统认定这条腿此刻在承重」 | 「这条脚刚落地，**解锁前禁止再抬**」 |
| 撤销 | 跌破阈值（带迟滞） | 承重达标 **且** 稳定窗口满足 |
| 作用对象 | 平衡维持系统的作用目标 | 迈步系统的**否决权** |

三种状态，两个字段各管一件：

| 时刻 | 锁定 | 承重 | 含义 |
|---|---|---|---|
| t0 前脚落地 | ✓ 前脚 | 仍是后脚 | 不许再抬前脚，体重还在后脚 |
| t1 重心转移达标 | ✓ 前脚 | **→ 前脚** | 达标授予 |
| t2 稳定窗口满 | 前脚解锁 | 前脚 | 允许迈后腿 |

> ⚠ **禁止**用同一个 `stanceL: boolean` 表达两件事。现在就是这么用的，
> 所以"锁定"和"承重"永远分不开，也答不出"为什么刚落地又倒了"。

## 2. 不可变式（启动时断言，违反就拒绝启动）

今天大部分脏 bug 的成因都是「非法状态可以表示」。

| # | 不变式 | 理由 |
|---|---|---|
| I1 | 关节清单以 `sk.joints` 为唯一真源；查不到必须返回 `-1` 并报错 | `JOINT_ORDER` 与实际 joints 不一致；旧回退让 `foot_l` 返回索引 9 = `spine1`（**指令下到腰上**） |
| I2 | 网络形状 = `36+6n` / `3n`，与关节数一致 | `BRAIN_SHAPE=shapeForJoints(9)` 而骨架 12 关节 ⇒ 观测**静默截 18 维**、只驱动 9/12 关节、10 步内 `com` 全 NaN 而**不报错** |
| I3 | 每关节 3 个受控轴；禁止"有马达无关节"或"有关节无马达" | 现在 42 个马达槽位 / 36 个实际轴，6 个死槽（`foot_l/r`） |
| I4 | 每轴同拍内**只有一个 owner** | 实测 `hip_l/0` 一格两个 owner |
| I5 | `locked` 的腿数 ≤ 1；`loadBearer` 只能取非锁定腿或 null | 防双锁 / 锁定与承重矛盾 |
| I6 | 控制频率是物理频率的整数分之一 | `subStep` 与 `controlTick` 的时序依赖 |

## 3. 逐关节体检

启动产出一次 `RigReport`，UI 与冒烟测试**读同一份**。

| 部位 | 关节 | 可驱动轴 | 力矩上限(轴0/1/2) | 必须回答 |
|---|---|---|---|---|
| 颈 | `neck` | 0 | 100/60/35 | 保持不动是否够 |
| 肩 | `shoulder_l/r` | 轴2 | 100/60/35 | 只做摆臂反相是否必要 |
| 肘 | `elbow_l/r` | 0 | 40/24/14 | 能否作碰撞缓冲 |
| **髋** | `hip_l/r` | 轴0、轴2 | 120/70/200 | **轴1 外展实测权限 ≈ 0**，须定位 |
| **膝** | `knee_l/r` | 轴2 | 90/52/150 | 锁膝目标角与符号 |
| **腰** | `spine1/2/3` | 0 | 72/42/120 | `spineSync` 在单腿模式被 `!singleLeg` 关闭 |
| **踝** | **不存在** | 0 | 45/27/16（死槽） | 无踝 ⇒ 无 CoP 通道 |

**空格必须显示"不存在"**，不允许留白（现在 `foot_*` 显示"未驱动"，像没在工作）。

## 4. 分层与数据流

```
① rig.ts        不可变式 + 逐关节体检 → RigReport（启动一次）
② rigState.ts   ★唯一的关节状态★  承重标识 / 锁定 / 需求 / 仲裁结果 / 读数
③ gaitState.ts  状态机：判据 + 相 + 交换协议 + 权限预算 α(t)
④ balanceHold   平衡维持系统 → 提需求（承重腿 + 腰·姿态分量）
⑤ stepSystem    迈步系统     → 提需求（摆动腿 + 腰·受限修正槽）
⑥ arbitrate     合并成一个 targets（唯一写入者）
⑦ 写 Rapier + 产出不可变快照
⑧ RigSnapshot   UI / 探针 / 冒烟测试 全部只读这一份
```

**关键：④⑤ 是并发的。** 每拍两个系统都跑、都往 `rigState` 提需求，由 ⑥ 合并。
它们不是"某拍只跑一个"。

## 5. `rigState` —— 唯一的一份关节数据

现在每个模块各持一份数据副本（`BalanceHoldInput` 一份、`StepSystemInput` 一份、
`teacher` 还有 45 个 `let`），于是"同轴被写两次"在物理上无法避免。

```
rigState
├─ 身份（唯一真源）
│   ├─ loadBearer : 'l'|'r'|null        // 标识，达标授予
│   ├─ locked     : { l, r }           // 闸门，触地置位
│   ├─ phase      : DOUBLE|SHIFT|SINGLE|STEP
│   └─ authority  : α(t)               // 权限预算，见 §6
├─ 读数（每拍从物理回读一次，两系统共享）
│   ├─ joint[axis] : { pos, vel, loadFrac, grounded, limitHit }
│   └─ com / dcm / supportDomain / grf
├─ 仲裁结果（⑥ 写入，唯一写入者）
│   └─ target[axis] : { value, owner, system, suppressed[] }
└─ 事件：touchdown[side] / criteriaMet / lockReleased[side]
```

**读**（两系统唯一的数据来源）：
`bearer()` `supportLeg()` `swingLeg()` `isLocked(side)`
`jointPos(axis)` `jointVel(axis)` `loadFrac(side)` `com` `dcm` `grf` `phase` `phaseT`

**写需求**（不是直接设值）：
`request(axis, value, system)` / `requestRange(axis, [lo,hi], system)`

`request` 只登记意图，合并交给 ⑥。这样"两个系统同时操作同一根轴"
就变成一条**可声明的规则**，而不是先写覆盖后写。

## 6. 仲裁规则

### 6.1 通用

| 情形 | 处理 |
|---|---|
| 同轴多需求 | 按固定优先级取一个，**记录被压制的**（`suppressed[]`） |
| 需求为区间（IIK） | 取交集；空交集记 `conflict`，由状态机决定回退 |
| 锁定腿上的**抬腿**需求 | **直接丢弃**（锁定是门，不是优先级） |
| 超限位 | 夹到限位，记 `clamped` |
| 目标变化率超限 | 斜率限制，记 `slewLimited` |

### 6.2 优先级（固定、声明式）

```
0. 锁定闸门      —— 是否决权，不参与排序
1. 平衡维持系统  —— 支撑腿 + 腰（决定"不倒"）
2. 迈步系统      —— 摆动腿 + 腰的受限修正槽
3. 回退绑定姿态  —— 两者都没提该轴
```

### 6.3 非干扰保证

> "Under an exact model, dynamically consistent projectors, inactive actuator saturation,
> and **no change in the active contact/friction inequalities**, the key property is
> `J_j N̄_{1..i} = 0` for all `j ≤ i`."
> —— Sentis & Khatib, IJHR 2005

⚠ **最后那个条件对仿真器最危险**：接触集翻转正是投影保证失效的地方。
所以本项目**不能只靠投影**，必须同时做 §8 的可见性（被压制的系统要看得见）。

### 6.4 腰：共享，但有预算

**结论：文献一致认为腰是共享的，不该独占给任何一方。**

- Herr et al. 2008：全身角动量虽小，但靠**段间抵消**（额状 ~95% / 矢状 ~70% / 垂直 ~80%）。
  原文警告：*"Such a stability feature cannot be achieved using a bipedal control scheme
  that simply applies a zero-moment, constant angular momentum control."*
- Van Criekinge SWEAT2 2020：躯干训练改善步速/步长/CoM 漂移，**下肢运动学不变**
  ⇒ 躯干是**为步态服务**而训练的，责任天然共享。
- 反面证据：Moreno-Segura 2022 躯干训练改善平衡但**不改善步态**（p=0.11）
  ⇒ 不能让迈步系统独占躯干。

**权限切分（Sentis & Khatib 2006 混合控制的逐自由度选择矩阵 `Ω_m`/`Ω_f` 是其祖先）**：

| 分量 | 归谁 | 说明 |
|---|---|---|
| 腰的姿态/力线对齐 | 平衡维持系统 | 决定"不倒"，主权限 |
| 腰的反相旋转（`spineSync`） | 迈步系统，**受限槽** | Takemura 2007；只做一点修正 |

**迈步系统的腰修正槽预算 `α(t) · A_max`：**

| 量 | 取值 | 依据 |
|---|---|---|
| 幅度 `A_max` | **±6°** | 骨盆横断面旋转实测 6°（Mann 1975；Staszkiewicz 2012：走 6.3±1.8°、跑 9.3±2.1°；Crosbie 1997：6.3±2.5°） |
| 相位 | **必须随速度变**，不能用固定反相 | 胸-骨盆相对相位 −110°(0.56 m/s) → −50°(1.44 m/s)（Bruijn 2008） |
| 捕获点余量 | `\|ΔMoS_z\| ≤ 2.5 mm` | **需自行推导**：好的单腿保持 MoS = −0.025 m 侧向（arXiv:2608.00500），取 10% 为预算 |
| 交换时连续性 | `α(t)` 用 3/2 斜坡，在区间前 **⅓** 升/降 | HugWBC arXiv:2502.03206 Eq.14 |
| 切换频率 | 平均连续 **199 拍**（p=0.005） | 同上；防抖 |
| 冲突处理 | 交接期 mask 掉腰的正则项 | 同上 |

**结构化的有界残差写法**（Nava/Pucci/Nori 2017, iCub）：
```
τ⁰ = h_j − J_jᵀ f + u⁰
```
`u⁰` 就是"在系统 A 不控的方向上那一点额外修正"，且他们**专门分析了单支撑下零动态的稳定性**。

**非干扰的硬件级证据**（Herzog et al., Dynamic Walking 2015）：
*"able to **absorb a push e.g. at a stance leg, while a swing leg motion remains unaffected**"*
—— 这就是要证明的性质：摆动腿动，支撑腿被推，系统 A 吸收，步态不中断。

**Focchi 的优先级栈**可直接借：Contact(1) → **Trunk orientation(2)** → Postural(3)。
腰在中间，介于"不许倒"和"随便摆"之间。

## 7. 状态机与交换协议

### 7.1 状态与两系统的行为

| 状态 | 承重标识 | 锁定 | 平衡维持系统 | 迈步系统 | 腰的 α |
|---|---|---|---|---|---|
| `DOUBLE` | null 或任一 | 无 | 全程在线：摆正 + 髋策略 | 待机，算落脚点 | 0 |
| `SHIFT` | 仍是旧腿 | 新腿**锁定** | 全程在线：把重心拉到新腿 | 已完成 | 0 |
| `SINGLE` | → 新腿 | 新腿解锁 | 全程在线：单支撑伺服 | 待机，算落脚点 | 0 |
| `STEP` | 新腿 | — | 全程在线：支撑腿伺服 | **抬腿** | 0 → 1（斜坡） |

### 7.2 用户描述的序列

> "迈腿后需要让前腿变为支撑腿，等重心转移到前腿后，身体平衡保持住了，再迈后腿"

```
STEP ──触地──► SHIFT ──承重判据达标──► SINGLE ──稳定窗口──► STEP(下一条腿)
       │           │
       │           └── 这段里新腿 locked=true ⇒ 迈步系统不能再抬它
       └── 触地瞬间 locked=true（无条件）
```

**两个系统全程在线**，不是"到某段只跑一个"：
平衡维持在 `STEP` 里维持支撑腿；迈步系统在 `SHIFT`/`SINGLE` 里持续算落脚点但不抬腿。

### 7.3 三个交换点

**交换点 1 —— 进入 `STEP`（迈步系统获得摆动腿 + 腰槽）**

许可条件（**全部**满足）：
| # | 条件 | 依据 |
|---|---|---|
| P1 | `loadBearer != null` 且该腿已解锁 | 重心必须先到位 |
| P2 | 摆动腿**未锁定** | 锁定闸门 |
| P3 | 支撑腿 MoS ≥ 阈值 | Hof 2005 |
| P4 | 双支撑相剩余时长足够 | 见 7.4 |

交换后：平衡维持系统**不退出**，继续全权控制支撑腿 + 腰的姿态分量；
迈步系统获得摆动腿全部轴 + 腰的 α 份额，**α 从 0 斜坡升到 1，不是跳变**。

**交换点 2 —— 触地（TO）**

条件：摆动脚首次接地。
⚠ 接触检测**不能只用载荷阈值**——滑移时阈值失效会造成支撑相误判
（Piperakis 2022，需要区分 5 种接触态含 Unknown）。

交换后：
- 摆动腿**立即锁定**（无条件，不等达标）
- 迈步系统失去该腿全部权限
- 腰修正槽 α 斜坡降回 0
- **承重标识不立即转移** —— 要等判据达标

**交换点 3 —— 承重达标（`SHIFT` → `SINGLE`）**

| # | 条件 | 建议初值 | 依据 |
|---|---|---|---|
| B1 | 该脚接地 | — | 几何 |
| B2 | 实测载荷占比 ≥ 阈值 | 0.60，迟滞 0.45 | 两腿承重分配 |
| B3 | CoM 投影在该脚支撑域内（MoS ≥ 0） | 0 | Hof 2005 |
| B4 | 连续满足 ≥ 窗 | 80 ms | 抗抖 |

解锁条件：
| # | 条件 | 建议初值 |
|---|---|---|
| U1 | 承重判据已达标 | — |
| U2 | MoS 连续 ≥ 阈值 | ≥ 0，窗 120 ms |
| U3 | 躯干倾角速率在界内 | — |

### 7.4 三条硬规则（都有文献）

**R1 · 抬腿是"双钥匙"门。**
Kuindersma：*"the requirement that both conditions [perceived contact AND planned contact]
were true was essential for breaking contact with the ground"*。
⇒ 迈步系统抬腿必须 **状态机许可 AND 实际接地检测为 false**，缺一不可。

**R2 · 交接必须在双支撑相里完成。**
Lee et al.：*"the absence of DSP can lead to discontinuous variations in robot CoM
acceleration during support transitions, resulting in **discontinuous joint torque
commands**"*。
⇒ **禁止在单支撑相中间切换控制权**；交接窗口必须落在双支撑相内。

**R3 · 相位要平滑，不能硬阈值。**
用 HugWBC 的平滑接触概率（正态 CDF）：
```
C(φ) = Φ(φ̄/σ)·[1−Φ((φ̄−0.5)/σ)] + Φ((φ̄−1)/σ)·[1−Φ((φ̄−1.5)/σ)]
```
把切换点 φ̄=0 / 0.5 变成区间 ±3σ ⇒ 直接得到一条**连续的权限调度 α(t)**，
正好喂给 Jarquín 的平滑切换（α(t) 插值 + 阻尼常驻最低优先级、权重永不低于 1 ⇒ q̇ 连续）。

**交接时序模板**（Lee et al. 的相触发条件，最直接可复用）：
> *"When the current time `t` reaches the optimized phase duration `T_new`,
> a phase transition is triggered; then `t` is reset to zero."*
> 且 **`f^ctrl_{T_new} = 0` during DSP**（big-M 约束）——**落脚点修正只在单支撑相允许，双支撑相强制为 0**。
> 本方案类比：**腰的修正槽 α 只在单支撑相非零，双支撑相强制 0**。

## 8. 数据回读收敛：UI 与冒烟测试同源

### 8.1 问题
同一个量现在在四个地方各算一次（`dbgLog`、`Sim.terms`、`probe-arch` 统计、UI 的 DOM），
于是"冒烟测试读到的"和"UI 绘制的"可以不一致。

### 8.2 契约
```
controller.step() → 不可变快照 RigSnapshot（每拍整体替换）
                         ↓
        ┌────────────────┴────────────────┐
     UI（只画这个）                探针 / 冒烟测试（只读这个）
```
1. 快照是**唯一可读出口**，UI/探针/冒烟测试都不得自行计算物理量。
2. 快照**不可变**：持有旧快照不会被后续 tick 改变。
3. **UI 不做推导**：前后腿/承重/锁定必须由控制器直接产出，UI 只上色排版。
4. **冒烟测试 = UI**：提供一个探针直接消费 UI 消费的那份快照，
   断言"UI 能画出来的字段"全部非空。这条就是防再次失同步的门禁。

### 8.3 快照最少字段

| 组 | 字段 |
|---|---|
| 身份 | `loadBearer`、`locked{l,r}`、`phase`、`phaseT`、`supportLeg`、`swingLeg`、`authority` |
| 腿 | 每侧 `grounded`、`loadFrac`、`soleY`、离地高度、CoM 相对位置 |
| 前后腿 | 每侧 `isFront`/`isBack`（**由实测脚 x 得出**，不是硬编码左右） |
| 关节 | 每轴 `pos`/`vel`/`target`/`owner`/`system`/`suppressed[]`/`clamped`/`limitHit` |
| 平衡 | `com`、`dcm`、`MoS`、`grf`、倾角、躯干高度 |
| 判据 | `bearerCriteria{B1..B4}`、`unlockCriteria{U1..U3}`、`stepPermit{P1..P4}` **逐条真假** |
| 冲突 | 每轴 `suppressed[]`（谁被压住了） |

> **判据逐条回显**是关键：这样"为什么没迈步"不用推断，直接看到 `P3 = false（MoS = −33 mm）`。

## 9. 单腿站立 = 平衡维持系统的验收（迈步系统同时在线，但不考核落地）

用户要求：**单腿站立验证平衡系统；迈步系统同时工作，但不要求能正常落地。**

这正好对应文献里现成的三档评分（arXiv:2608.00500）：

| 档 | 定义 |
|---|---|
| **Perfect** | 支撑脚**从不跳**、摆动脚**从不触地**、不摔 |
| **Marginal** | 仅靠跳或靠摆动脚触地才站住 |
| **Failure** | 摔 |

⇒ **把摆动脚的触地单独计分**，就实现了"考核平衡、不考核落地"。

## 13. ★★ 力的传导：自下而上（用户 2026-10-03 定调，最高优先级原则）

> **"力是自下往上传导的"**
> **"脚踝关节应该写的，而且足部还要学会发力"**

这一条**推翻**了本文档 §10 与 §11 里"先不动 `ankleEnabled`"的安排。
它同时改写了三个东西：**硬件范围**、**控制律的入口**、**相位的定义**。

### 13.1 传导链：一条链，一个 CoP

```
        地面反力（作用在足底某点，直线向上穿过该点）
             │  τ_踝 = F_z × (CoP − 踝)
             ▼
        踝（矢状 = 跖屈/背屈；额状 = 内翻/外翻）
             │  小腿骨（沿胫骨）
             ▼
        膝（伸肌顶住 ⇒ 腿的刚性）
             │
             ▼
        髋（伸肌把躯干拉回支撑脚上方）
             │
             ▼
        骨盆 —— 重心最高权重段之一
             │
             ▼
        脊柱 spine1/2/3
             │
             ▼
        胸腔姿态（"站得直不直"）
```

**力线是一条直线，从足底一直穿到躯干。** 中间任何一个关节的力矩都是
「这条力线到该关节的垂直距离 × F」。所以：

### 13.2 三个直接推论（决定了控制器怎么写）

**推论 A · 躯干姿态是结果，不是目标。**
想让躯干直，**不是**给脊柱一个角度，而是让 GRF 力线**穿过髋**。
力线一旦偏，髋就产生屈曲力矩，躯干必然被折向前（"鞠躬"）。

> 实测证据（本项目，`probe-posture`）：GRF 横/竖比 **0.074~0.333**（歪 4°~18°），
> 力线落到**髋后方 11~65 cm** ⇒ 对髋产生 11~65 cm 力臂的**屈曲**力矩 ⇒ 鞠躬。
> ⇒ 正确的目标量是 **力线对齐**，不是"竖直"。

**推论 B · 控制律的入口是"足底 CoP"，不是"关节角"。**
既然躯干姿态是整条链的结果，那**每关节各自独立 PD** 在原理上就是错的：
它们各自为战，没有一个在说"整条链要满足什么"。

⇒ **控制律要改成：先定足底目标（压力中心 + 压力大小 + 方向），再反解关节力矩。**

```
目标：足底压力中心 p（矢状 x_摆 + 额状 z_摆）、竖直力 F_z、切向力 f_t
      ↓（力矩平衡 / 逆运动学）
分配：τ_踝, τ_膝, τ_髋, τ_spine1..3 使整条力线穿过髋且不违反限位/摩擦锥
```

这不是"再加一个模块"，而是**换入口**。文献依据：Kuindersma 的 QP 把
**接触力 λ 当决策变量**，Sentis/Khatib 的混合控制用选择矩阵把每个任务的
笛卡尔自由度劈成"运动控制"与"力控制"两半（`Ω_m` / `Ω_f`）。

**推论 C · 足部必须能主动发力，否则整条链没有起点。**
没有踝 ⇒ 没有 CoP ⇒ 力线钉死在脚掌几何形心 ⇒ 整条链只有一个固定的工作点。
**足部发力就是这条链的"发动机"**：
- **踝策略**：小幅跖屈/背屈 → CoP 在踝前后移动 → 修正 CoM（LIPM：`p−x = −(I/(W·h))·ẍ`）
- **蹬离**：摆动相末跖屈 → 地面反力斜向前 → 身体被**推**出去（这是前进的唯一来源）

### 13.3 硬件范围：踝必须开

| 项 | 现状 | 要改成 |
|---|---|---|
| `ankleEnabled` | **false** ⇒ 无踝关节，脚掌是小腿第二个 collider | **true** ⇒ 脚掌独立刚体 + 踝球铰 |
| `ankleTorque` | 45 N·m | **待定**，见 13.4 |
| 踝的三个轴 | 死在 `JOINT_ORDER` 里的"幽灵槽" | 真实关节，进入 `rig.ts` 体检表的「踝」行 |

`rig.ts` 已经把 `foot_l/foot_r` 登记为 `PHANTOM_JOINTS`；开踝之后它们会自动
从"幽灵"变成真实关节（`assertRigInvariants` 里那两行随之失效），体检表会开始列出它们。

⚠ **开踝的已知代价**（必须一起处理，否则测不出是哪个引起的）：
- 脚掌拆成独立刚体后 PD 增益与惯量分布要重调（历史实测：开着会**塌 41 cm / 0.5 s**）
- `enforceLimits` 现在拿不到踝的正确惯量（它用"两体主惯量最大值"作保守下界）
- 关节数 12 → 14 ⇒ **网络形状必须同步改**（`shapeForJoints` 自动跟随，但旧基因组作废）

### 13.4 踝的力矩预算（按文献重算）

 ankle 产生的 CoP 偏移 = `τ_ankle / (m·g)`，m = 70 kg ⇒ `m·g = 687 N`。

| 用途 | 需要的力矩 | 对应 CoP 偏移 | 来源 |
|---|---|---|---|
| 安静站立（踝策略） | 26~50 N·m | 38~73 mm | Loram & Lakie 2002；Di Giulio 2019（实测 26.3±5.3） |
| 步行蹬离峰值 | **≈ 56 N·m** | 82 mm | Gao, J Foot Ankle Res 2024：峰值跖屈力矩 0.80 N·m/(kg·m) |
| 当前配置 | **45 N·m** | 65 mm | `cfg.ankleTorque` |

⇒ **45 N·m 够"站"，不够"蹬"。** 若要推进，踝力矩上限应提到 **≥ 60 N·m**。
参照：膝 150、髋 200 N·m，60 N·m 的踝并不越级。

### 13.5 对架构分层的影响

**① 仲裁顺序反过来。** 之前写的优先级是"平衡维持 > 迈步"，那是**按系统**排的。
现在力的入口在足底，所以每一拍的正确顺序是：

```
足底目标（p, F_z, f_t）
   ├─ 平衡维持系统：给出「让力线穿过支撑脚 / 髋」的足底目标
   ├─ 迈步系统：    给出摆动腿的蹬离足底目标（也在足底）
   └─ 仲裁：两者都要"足底力"，先合并成**一个足底目标**（冲突按接触约束处理，
             不允许出现"一个想左一个想右"的压力中心）
        ↓ 逆运动学
   τ_踝 → τ_膝 → τ_髋 → τ_spine（由整条链一次性分配，不是各自独立 PD）
```

⇒ **足底目标必须在系统之间仲裁完，再往下分配**。否则就是两条链打架。

**② 相位要加"蹬离"。** 现在的四相不够：

| 相 | 新增/变化 |
|---|---|
| `DOUBLE` → `SHIFT` → `SINGLE` → **`PUSH`** → `STEP` | `PUSH` = 支撑腿跖屈蹬离（**产生前进的唯一来源**） |
| `STEP` 的摆动末段 | 预摆动跖屈（文献 17.2°，Front Neurorob 2022） |

**③ 足部发力的学习目标要写进验收。** "会发力"不是"有力矩"，是：

| # | 判据 | 依据 |
|---|---|---|
| F1 | 踝力矩与 CoP 偏移**成比例**（不是"指令大 ⇒ 力矩大"） | Prince 1994：`p−x = −(I/(W·h))·ẍ` |
| F2 | 蹬离产生的地面反力**水平分量 > 0** | 力学直推 |
| F3 | 蹬离后 CoM 速度增量 ≈ `τ_ankle/(m·h)·Δt` | 逆动力学一致性 |
| F4 | 安静站立时踝力矩落在 **26~50 N·m**（不超不多） | Loram & Lakie 2002 |

> ⚠ F4 是**有上下文的合格区间**，不是"越大越好"。
> 大力矩而力线不对 = 原地较劲。

## 14. ★★ 足部必须柔性 —— 才能多向发力（用户 2026-10-03）

> **"足部，脚踝都是要发力的，脚部可能还需要柔性从而实现多向发力"**

§13 定了"力的入口在足底"。这一节解决**那个入口到底能不能被控制**。

### 14.1 为什么刚性足做不到

刚性平底盒 + 刚性地面 ⇒ 接触压力分布由**几何**决定，压力中心（CoP）被钉在
接触面的形心附近。绕踝转会压实盒面，但**合力矩不变** ⇒ CoP 移不动。

这就是本项目历史上的 `applySupportPoint` 失败的原因：它在偏移点 +F、脚心 −F
施加一个**外部力偶**。Sardain & Bessonnet（IEEE TSMC-A 2004）已经证明这条路走不通——
CoP 由**地面反力对该点的力矩平衡**定义，在接触凸包内施加力偶不改变净力矩，
只是把载荷重新分配，合力位置没动。

⇒ 结论不是"CoP 不可控"，而是**"刚性足不可控"**。

### 14.2 柔性怎么把 CoP 变成可控量

| 机制 | 做法 | 效果 |
|---|---|---|
| **衬垫柔性** | 足底各处的**法向柔度不同**（跟/掌/趾不同刚度），或等效为若干弹簧接触点 | 各点压力**独立**，合力位置 = 各点压力的加权形心 ⇒ **CoP 变成连续可控量** |
| **串联弹性** | 足底 + 跟腱串联在踝关节**远端** | 被动刚度（储能/释能），踝策略的"免费"部分 |
| **分段足** | 跟 / 掌 / 趾拆成独立刚体 + 铰 | 允许 rocking ⇒ CoP 行程从"面内"扩到"面外" |

### 14.3 文献依据（都有具体数）

**① 分段足把恢复余量提高 58~66%**
Mummolo, Akbas & Carbone, *Front. Robot. AI* 8:613038 (2021)，全身平面双足、
真实关节力矩上限、逐点求 Boundary of Balance：

| 足模型 | 最大可恢复 CoM 速度（前 / 后） | 可行余量（前 / 后） |
|---|---|---|
| 平底刚性 | **+0.484 / −0.292 m/s** | +6.72 / −8.21 cm |
| **分段足（跟↔趾 rocking）** | **+0.802 / −0.461 m/s** | **+13.8 / +18.9 cm** |
| 增幅 | **+66% / +58%** | 约 2 倍 |

同文还量化了**髋策略（多质量力矩）的"免费"额度**：分段足在前/后可达余量处
可提供 **45.67 / 37.38 N·m** 的多质量力矩——这是"把 CoM 搬过去"的内部力矩预算。

**② 人类的被动踝刚度就在踝的远端（足 + 跟腱串联）**
Loram & Lakie, *J Physiol* 545:1041（2002）：踝的机械刚度约 **5 N·m/deg 每条腿**，
双踝合计 = `mgh` 的 **91%**，且 *"is relatively constant and **is not under neural control**"*。
同文：*"When a dorsiflexion of 0.055 deg is applied to the foot, approximately **70% of that
rotation is transmitted through the foot and ankle joint**"* ⇒ 柔顺性主要在**足与跟腱**，
不在踝关节本身。

**③ 小的被动踝转动就能跨过临界刚度**
Lakie et al., *J Physiol* 2018（PMC5860743）：被动背屈 **18.7°** 使刚度从
**50% → 77% mgh**（0.7° 扰动）、**77% → 109% mgh**（0.1° 扰动）。
对照 Sasagawa et al., *PLOS ONE* 2009：**80% mgh 时直立姿态是鞍点**，必须有主动控制。
⇒ 柔性足把被动刚度从 0% 抬到 77~109% mgh，**这是"不花神经代价就站住"的那部分**。

**④ 刚性平底在不平地面必然失稳**
Khashimoto et al., *J. Robotic Society of Japan* 18:271（2006，"Waseda Shoes"）：
*"The rigid, flat soles of most such robots rarely maintain four-point contact on uneven
terrain, however, and may lose balance."*

**⑤ 顺序弹性是成熟工程手段**
Rehder et al.（ANYmal）系列弹性驱动；Kim et al., *IEEE T-RO* 32(6)（2016）
"Stabilizing series-elastic point-foot bipeds using whole-body operational space control"。

### 14.4 "多向发力"具体指什么

刚性足只能沿**接触法向 + 摩擦锥**发力。柔性足解锁的是：

| 方向 | 刚性足 | 柔性足 |
|---|---|---|
| 矢状（前后） | 力臂受限于踝到脚尖/脚跟 | CoP 在衬垫内**连续移动**，行程 = 衬垫有效长度 |
| 额状（左右） | 几乎为 0（本项目实测 Δz≈4mm） | 内外翻 + 足底横向柔度 ⇒ 横向压力分布可控 |
| 绕足长轴滚转 | 无 | 跟/掌/趾压力差 ⇒ 踝内外翻有力臂 |
| 储能/释能 | 无（刚性力不做功） | 串联弹性 ⇒ 蹬离是"释放弹簧"，不是"额外发力" |

⇒ **"蹬离"的物理本质是释放足底/跟腱储存的弹性能量**，而不是靠更大的踝力矩硬顶。
这解释了为什么 §13.4 里 45 N·m 够站不够蹬：有了柔性，**同样 45 N·m 能蹬出更多冲量**。

### 14.5 实现层级（按性价比排序）

| 级 | 内容 | 成本 | 收益 | 验收判据 |
|---|---|---|---|---|
| **F1** | **接触柔度**：`contact_natural_frequency` + `contact_damping_ratio`（Rapier 0.14 原生支持） | 极低 | ❌ **实测无效，见 14.5.1** | ❌ 不作为解锁 CoP 的手段 |
| **F2** | **多接触点衬垫**：足底拆成 N×M 个小 collider（或等价的多弹簧接触模型） | 中 | **CoP 真正可控**（各点压力独立） | F1 的 CoP 行程 > `ankleTorque/(mg)` 理论上限 ⇒ 说明已脱离"刚性几何"限制 |
| **F3** | **分段足**：跟/掌/趾独立刚体 + 铰 | 高 | rocking，CoP 行程再扩；Mummolo 的 +66% | 被动可恢复 CoM 速度从 0.48 → 0.80 m/s 量级 |

⚠ **F3 会改变几何与质量分布**，因此**必须与"开踝"分两个阶段各自验收**
（否则测不出收益来自开踝还是分段足）。

### 14.5.1 ★ 实测：F1（均匀接触柔度）**不解锁 CoP**（2026-10-03）

用 `Ragdoll.readCoP()`（直接由接触冲量加权：`CoP = Σ(P·λ)/Σλ`）实测，
踝角 ±12° 时的 CoP 行程：

| `contactHz` | 矢状面 CoP 行程 | 额状面 CoP 行程 | Σλ（总冲量） |
|---|---|---|---|
| 0（刚性） | **12.1 mm** | 14.3 mm | 3.15 |
| 10 | 13.3 mm | 19.4 mm | **1.26** |
| 30 | **12.1 mm**（与 0 逐位相同） | 14.3 mm | 3.15 |
| 60 | 13.5 mm | 17.3 mm | 3.00 |

理论上限 `τ/(mg)` = 60/687 = **87 mm**。

**两个结论：**

**① F1 无效。** 矢状面行程始终 ≈12 mm（差理论 **7 倍**），
且 `contactHz=30` 与 `0` 的读数**逐位相同** ⇒ 30 Hz 仍近似刚性。
`contactHz=10` 时 Σλ 从 3.15 掉到 1.26（接触**确实**软了），
但 **CoP 行程一点没变**。

> **机理**：均匀软化让整只脚一起陷下去，**压力分布的"形状"不变** ——
> 它降低了接触刚度，但**没有给压力一个自由度**。
> 要让控制器**选择**压力落在哪里，必须让各处的**法向柔度不同**
> 或各接触点的**法向力可独立指定** ⇒ **只有 F2 能解锁**。

**② 顺带测出踝的符号与我原先的假设相反。**
刚性足上正踝角（跖屈，脚尖下压）让 **CoP 后移**（−5.2 mm @ +12°），
不是前移。机理：刚性平底绕踝转 ⇒ 脚尖离地、脚跟吃重 ⇒ 接触形心自然后退。
⇒ `systems/balance.ts` 里 `kCopSag` 的符号**必须按 F2 落地后的实测重新标定**，
不能沿用基于 ΔCoM 的旧推断（ΔCoM 量的是身体怎么动，混着惯量与耦合）。

**⇒ F2（多接触点衬垫 / 各点法向力可独立指定）从"可选"升为"必须"。**
F1 可以保留作为"被动踝刚度"的手段（对应 Lakie 2018 的 77~109% mgh），
但**不要指望它给 CoP 权限**。

### 14.6 仲裁上的一个变化

足底目标现在**有两个来源**：
- **平衡维持系统**：站立/单支撑时的压力中心（让力线穿过支撑脚 / 髋）
- **迈步系统**：摆动末段的蹬离压力中心（也在足底，Pre-swing 跖屈 17.2°）

两者都作用在**同一只脚**上（支撑末期 / 摆动末期切换时）。所以：

```
足底压力目标（各接触点的法向力分配）
   ├─ 平衡维持系统：CoP ← 支撑脚
   ├─ 迈步系统：    蹬离 ← 摆动脚（且只在 pre-swing 窗内）
   └─ 仲裁：按接触点合并；同一接触点上冲突 ⇒ 按**接触约束**处理
             （不允许出现"一个想左一个想右"的压力中心）
```

这与 §13.5 的"足底目标先合并再往下分配"是同一条规则，
只是现在它有了**物理载体**（衬垫各点的法向力），不再是抽象量。

## 15. ★ 阶段 1.5 实测记录：开踝 + 护栏修复（2026-10-03）

按 §13.3/§13.6 把踝打开、并修了 `driveMotors` 的稳定性护栏。**结论：还不能开。**

### 15.1 护栏 bug（已修，必要但不充分）

护栏 `|imp| ≤ α·|err|·Ieff` 里的 `Ieff` 用 `min(I.x,I.y,I.z)`（三个主惯量最小值）。
脚掌是 1.5 kg 薄盒 ⇒ `Ieff ≈ 0.0047 kg·m²`；要放行 `τmax=60 N·m` 需要 `Ieff ≥ 0.0556`
⇒ **踝只能拿到 8.4% 的力矩**（实测 `τ_demand 60.00` / `τ_applied 5.02`，权限 0.084）。

> ★ **同一个坑修过两次**：第二次漏在 `driveMotors`。`enforceLimits` 的注释里
> 早就写着"惯量不能用 jointIeff（它取主惯量的最小值，对细长的脚掌极小）⇒ 冲量严重不足"，
> 修好后**没同步到这里**。

**物理上的正确修法**（已实现，`RagdollOptions.ankleGroundFactor`）：
承重的脚被地面反作用**约束住**，它在踝处的等效惯量不是脚掌质量，而是
"脚掌之上整个身体绕踝的惯量"（点质量近似 `Σmᵢrᵢ²` ≈ 0.5~1 kg·m²）。
实测 factor 放开后 **权限 0.084 → 1.000**，`τ_applied = 60.00 N·m = τ_demand`。

⚠ 但**不能一放开**：factor 太大时**脚被踹飞**（接触 `Σλ` 归零 ⇒ 整条力链断）。
已做成可扫旋钮（默认 1 = 不放大，保持旧行为）。

### 15.2 真·CoP 读数推翻了我自己的一个结论

`Ragdoll.readCoP()`（`CoP = Σ(P·λ)/Σλ`，直接由接触冲量加权）实测：

- 踝角 ±12°（**软限位内**，PD 只出 ~1 N·m）⇒ CoP 矢状行程 **12.1 mm**，理论 87 mm
- 我曾据此写"刚性足把 CoP 钉死，接触柔度 F1 无效"
- ⚠ **这个结论是错的**：命令软限位内的角度，PD 本来就只出维持该角度的力矩，
  CoP 位移小是**必然**的，不能反推"不可控"。**测 CoP 权限必须让踝饱和。**
- 修正后（饱和命令）：实际踝力矩仍只有 0.6~1.6 N·m ⇒ 因为**位置环在平衡点自然停下**。
  ⇒ **位置控制的关节无法命令力矩**；CoP 由"GRF 力线落在踝的哪一侧"决定，
  而力线位置由**整体构型**决定（这正是 §13.1 传导链的反向因果）。

⇒ 平衡系统的踝律已从"角度 PD"改成**直接闭环在实测 CoP 上**
（`θ_ref = −k·(ξ − CoP_实测)`，符号由实测确定，不再猜）。
