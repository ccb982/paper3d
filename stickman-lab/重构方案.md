# 重构方案：承重腿标识 + 锁定腿闸门 + 单一关节状态 + 显式交换协议

> 本文只写**架构**，不写实现。
> 每条设计后面标了文献依据；**没有依据的数字标了"需自行推导"**。

---

## 0. 为什么要重构

现在「**这条腿是谁**」「**这条腿能不能抬**」「**这个关节该听谁的**」三件事
写在 `teacher.ts` 一个 1300 行函数里（45 个可变闭包变量，`stanceL` 被 **6 处**赋值，
其中两处是重复的同一行），并且**三套状态机**（`sim.gp`、`wtStage`、`latchedStance`）
同时回答同一个问题。

后果有两类：
- **同轴多 owner**：实测 `hip_l/0` 一格里 `balance` 与 `step` 同时在写。
- **文档与代码不一致**：`ankleEnabled=false`（本 rig 没有踝），
  但 `balanceHold.ts` 整段踝 CoP 策略建立在「踝存在」之上，且**无法被证伪**。

## 1. 核心语义：承重腿 ≠ 锁定腿

**两个独立字段，不是一个 bool。**

| | **承重腿 load-bearer** | **锁定腿 locked** |
|---|---|---|
| 本质 | 一枚**标识** | 一道**闸门** |
| 获得 | **必须检测达标**才授予 | **触地瞬间**，无条件 |
| 语义 | 「系统认定这条腿此刻在承重」 | 「这条脚刚落地，**解锁前禁止再抬**」 |
| 撤销 | 跌破阈值（带迟滞） | 承重达标 **且** 稳定窗口满足 |
| 作用对象 | 平衡维持系统的作用目标 | 迈步系统的**否决权** |

三种状态，两个字段各管一件：

| 时刻 | 锁定 | 承重 | 含义 |
|---|---|---|---|
| t0 前脚落地 | ✓ 前脚 | 仍是后脚 | 不许再抬前脚，体重还在后脚 |
| t1 重心转移达标 | ✓ 前脚 | **→ 前脚** | 达标授予 |
| t2 稳定窗口满 | 前脚解锁 | 前脚 | 允许迈后腿 |

> ⚠ **禁止**用同一个 `stanceL: boolean` 表达两件事。现在就是这么用的，
> 所以"锁定"和"承重"永远分不开，也答不出"为什么刚落地又倒了"。

## 2. 不可变式（启动时断言，违反就拒绝启动）

今天大部分脏 bug 的成因都是「非法状态可以表示」。

| # | 不变式 | 理由 |
|---|---|---|
| I1 | 关节清单以 `sk.joints` 为唯一真源；查不到必须返回 `-1` 并报错 | `JOINT_ORDER` 与实际 joints 不一致；旧回退让 `foot_l` 返回索引 9 = `spine1`（**指令下到腰上**） |
| I2 | 网络形状 = `36+6n` / `3n`，与关节数一致 | `BRAIN_SHAPE=shapeForJoints(9)` 而骨架 12 关节 ⇒ 观测**静默截 18 维**、只驱动 9/12 关节、10 步内 `com` 全 NaN 而**不报错** |
| I3 | 每关节 3 个受控轴；禁止"有马达无关节"或"有关节无马达" | 现在 42 个马达槽位 / 36 个实际轴，6 个死槽（`foot_l/r`） |
| I4 | 每轴同拍内**只有一个 owner** | 实测 `hip_l/0` 一格两个 owner |
| I5 | `locked` 的腿数 ≤ 1；`loadBearer` 只能取非锁定腿或 null | 防双锁 / 锁定与承重矛盾 |
| I6 | 控制频率是物理频率的整数分之一 | `subStep` 与 `controlTick` 的时序依赖 |

## 3. 逐关节体检

启动产出一次 `RigReport`，UI 与冒烟测试**读同一份**。

| 部位 | 关节 | 可驱动轴 | 力矩上限(轴0/1/2) | 必须回答 |
|---|---|---|---|---|
| 颈 | `neck` | 0 | 100/60/35 | 保持不动是否够 |
| 肩 | `shoulder_l/r` | 轴2 | 100/60/35 | 只做摆臂反相是否必要 |
| 肘 | `elbow_l/r` | 0 | 40/24/14 | 能否作碰撞缓冲 |
| **髋** | `hip_l/r` | 轴0、轴2 | 120/70/200 | **轴1 外展实测权限 ≈ 0**，须定位 |
| **膝** | `knee_l/r` | 轴2 | 90/52/150 | 锁膝目标角与符号 |
| **腰** | `spine1/2/3` | 0 | 72/42/120 | `spineSync` 在单腿模式被 `!singleLeg` 关闭 |
| **踝** | **不存在** | 0 | 45/27/16（死槽） | 无踝 ⇒ 无 CoP 通道 |

**空格必须显示"不存在"**，不允许留白（现在 `foot_*` 显示"未驱动"，像没在工作）。

## 4. 分层与数据流

```
① rig.ts        不可变式 + 逐关节体检 → RigReport（启动一次）
② rigState.ts   ★唯一的关节状态★  承重标识 / 锁定 / 需求 / 仲裁结果 / 读数
③ gaitState.ts  状态机：判据 + 相 + 交换协议 + 权限预算 α(t)
④ balanceHold   平衡维持系统 → 提需求（承重腿 + 腰·姿态分量）
⑤ stepSystem    迈步系统     → 提需求（摆动腿 + 腰·受限修正槽）
⑥ arbitrate     合并成一个 targets（唯一写入者）
⑦ 写 Rapier + 产出不可变快照
⑧ RigSnapshot   UI / 探针 / 冒烟测试 全部只读这一份
```

**关键：④⑤ 是并发的。** 每拍两个系统都跑、都往 `rigState` 提需求，由 ⑥ 合并。
它们不是"某拍只跑一个"。

## 5. `rigState` —— 唯一的一份关节数据

现在每个模块各持一份数据副本（`BalanceHoldInput` 一份、`StepSystemInput` 一份、
`teacher` 还有 45 个 `let`），于是"同轴被写两次"在物理上无法避免。

```
rigState
├─ 身份（唯一真源）
│   ├─ loadBearer : 'l'|'r'|null        // 标识，达标授予
│   ├─ locked     : { l, r }           // 闸门，触地置位
│   ├─ phase      : DOUBLE|SHIFT|SINGLE|STEP
│   └─ authority  : α(t)               // 权限预算，见 §6
├─ 读数（每拍从物理回读一次，两系统共享）
│   ├─ joint[axis] : { pos, vel, loadFrac, grounded, limitHit }
│   └─ com / dcm / supportDomain / grf
├─ 仲裁结果（⑥ 写入，唯一写入者）
│   └─ target[axis] : { value, owner, system, suppressed[] }
└─ 事件：touchdown[side] / criteriaMet / lockReleased[side]
```

**读**（两系统唯一的数据来源）：
`bearer()` `supportLeg()` `swingLeg()` `isLocked(side)`
`jointPos(axis)` `jointVel(axis)` `loadFrac(side)` `com` `dcm` `grf` `phase` `phaseT`

**写需求**（不是直接设值）：
`request(axis, value, system)` / `requestRange(axis, [lo,hi], system)`

`request` 只登记意图，合并交给 ⑥。这样"两个系统同时操作同一根轴"
就变成一条**可声明的规则**，而不是先写覆盖后写。

## 6. 仲裁规则

### 6.1 通用

| 情形 | 处理 |
|---|---|
| 同轴多需求 | 按固定优先级取一个，**记录被压制的**（`suppressed[]`） |
| 需求为区间（IIK） | 取交集；空交集记 `conflict`，由状态机决定回退 |
| 锁定腿上的**抬腿**需求 | **直接丢弃**（锁定是门，不是优先级） |
| 超限位 | 夹到限位，记 `clamped` |
| 目标变化率超限 | 斜率限制，记 `slewLimited` |

### 6.2 优先级（固定、声明式）

```
0. 锁定闸门      —— 是否决权，不参与排序
1. 平衡维持系统  —— 支撑腿 + 腰（决定"不倒"）
2. 迈步系统      —— 摆动腿 + 腰的受限修正槽
3. 回退绑定姿态  —— 两者都没提该轴
```

### 6.3 非干扰保证

> "Under an exact model, dynamically consistent projectors, inactive actuator saturation,
> and **no change in the active contact/friction inequalities**, the key property is
> `J_j N̄_{1..i} = 0` for all `j ≤ i`."
> —— Sentis & Khatib, IJHR 2005

⚠ **最后那个条件对仿真器最危险**：接触集翻转正是投影保证失效的地方。
所以本项目**不能只靠投影**，必须同时做 §8 的可见性（被压制的系统要看得见）。

### 6.4 腰：共享，但有预算

**结论：文献一致认为腰是共享的，不该独占给任何一方。**

- Herr et al. 2008：全身角动量虽小，但靠**段间抵消**（额状 ~95% / 矢状 ~70% / 垂直 ~80%）。
  原文警告：*"Such a stability feature cannot be achieved using a bipedal control scheme
  that simply applies a zero-moment, constant angular momentum control."*
- Van Criekinge SWEAT2 2020：躯干训练改善步速/步长/CoM 漂移，**下肢运动学不变**
  ⇒ 躯干是**为步态服务**而训练的，责任天然共享。
- 反面证据：Moreno-Segura 2022 躯干训练改善平衡但**不改善步态**（p=0.11）
  ⇒ 不能让迈步系统独占躯干。

**权限切分（Sentis & Khatib 2006 混合控制的逐自由度选择矩阵 `Ω_m`/`Ω_f` 是其祖先）**：

| 分量 | 归谁 | 说明 |
|---|---|---|
| 腰的姿态/力线对齐 | 平衡维持系统 | 决定"不倒"，主权限 |
| 腰的反相旋转（`spineSync`） | 迈步系统，**受限槽** | Takemura 2007；只做一点修正 |

**迈步系统的腰修正槽预算 `α(t) · A_max`：**

| 量 | 取值 | 依据 |
|---|---|---|
| 幅度 `A_max` | **±6°** | 骨盆横断面旋转实测 6°（Mann 1975；Staszkiewicz 2012：走 6.3±1.8°、跑 9.3±2.1°；Crosbie 1997：6.3±2.5°） |
| 相位 | **必须随速度变**，不能用固定反相 | 胸-骨盆相对相位 −110°(0.56 m/s) → −50°(1.44 m/s)（Bruijn 2008） |
| 捕获点余量 | `\|ΔMoS_z\| ≤ 2.5 mm` | **需自行推导**：好的单腿保持 MoS = −0.025 m 侧向（arXiv:2608.00500），取 10% 为预算 |
| 交换时连续性 | `α(t)` 用 3/2 斜坡，在区间前 **⅓** 升/降 | HugWBC arXiv:2502.03206 Eq.14 |
| 切换频率 | 平均连续 **199 拍**（p=0.005） | 同上；防抖 |
| 冲突处理 | 交接期 mask 掉腰的正则项 | 同上 |

**结构化的有界残差写法**（Nava/Pucci/Nori 2017, iCub）：
```
τ⁰ = h_j − J_jᵀ f + u⁰
```
`u⁰` 就是"在系统 A 不控的方向上那一点额外修正"，且他们**专门分析了单支撑下零动态的稳定性**。

**非干扰的硬件级证据**（Herzog et al., Dynamic Walking 2015）：
*"able to **absorb a push e.g. at a stance leg, while a swing leg motion remains unaffected**"*
—— 这就是要证明的性质：摆动腿动，支撑腿被推，系统 A 吸收，步态不中断。

**Focchi 的优先级栈**可直接借：Contact(1) → **Trunk orientation(2)** → Postural(3)。
腰在中间，介于"不许倒"和"随便摆"之间。

## 7. 状态机与交换协议

### 7.1 状态与两系统的行为

| 状态 | 承重标识 | 锁定 | 平衡维持系统 | 迈步系统 | 腰的 α |
|---|---|---|---|---|---|
| `DOUBLE` | null 或任一 | 无 | 全程在线：摆正 + 髋策略 | 待机，算落脚点 | 0 |
| `SHIFT` | 仍是旧腿 | 新腿**锁定** | 全程在线：把重心拉到新腿 | 已完成 | 0 |
| `SINGLE` | → 新腿 | 新腿解锁 | 全程在线：单支撑伺服 | 待机，算落脚点 | 0 |
| `STEP` | 新腿 | — | 全程在线：支撑腿伺服 | **抬腿** | 0 → 1（斜坡） |

### 7.2 用户描述的序列

> "迈腿后需要让前腿变为支撑腿，等重心转移到前腿后，身体平衡保持住了，再迈后腿"

```
STEP ──触地──► SHIFT ──承重判据达标──► SINGLE ──稳定窗口──► STEP(下一条腿)
       │           │
       │           └── 这段里新腿 locked=true ⇒ 迈步系统不能再抬它
       └── 触地瞬间 locked=true（无条件）
```

**两个系统全程在线**，不是"到某段只跑一个"：
平衡维持在 `STEP` 里维持支撑腿；迈步系统在 `SHIFT`/`SINGLE` 里持续算落脚点但不抬腿。

### 7.3 三个交换点

**交换点 1 —— 进入 `STEP`（迈步系统获得摆动腿 + 腰槽）**

许可条件（**全部**满足）：
| # | 条件 | 依据 |
|---|---|---|
| P1 | `loadBearer != null` 且该腿已解锁 | 重心必须先到位 |
| P2 | 摆动腿**未锁定** | 锁定闸门 |
| P3 | 支撑腿 MoS ≥ 阈值 | Hof 2005 |
| P4 | 双支撑相剩余时长足够 | 见 7.4 |

交换后：平衡维持系统**不退出**，继续全权控制支撑腿 + 腰的姿态分量；
迈步系统获得摆动腿全部轴 + 腰的 α 份额，**α 从 0 斜坡升到 1，不是跳变**。

**交换点 2 —— 触地（TO）**

条件：摆动脚首次接地。
⚠ 接触检测**不能只用载荷阈值**——滑移时阈值失效会造成支撑相误判
（Piperakis 2022，需要区分 5 种接触态含 Unknown）。

交换后：
- 摆动腿**立即锁定**（无条件，不等达标）
- 迈步系统失去该腿全部权限
- 腰修正槽 α 斜坡降回 0
- **承重标识不立即转移** —— 要等判据达标

**交换点 3 —— 承重达标（`SHIFT` → `SINGLE`）**

| # | 条件 | 建议初值 | 依据 |
|---|---|---|---|
| B1 | 该脚接地 | — | 几何 |
| B2 | 实测载荷占比 ≥ 阈值 | 0.60，迟滞 0.45 | 两腿承重分配 |
| B3 | CoM 投影在该脚支撑域内（MoS ≥ 0） | 0 | Hof 2005 |
| B4 | 连续满足 ≥ 窗 | 80 ms | 抗抖 |

解锁条件：
| # | 条件 | 建议初值 |
|---|---|---|
| U1 | 承重判据已达标 | — |
| U2 | MoS 连续 ≥ 阈值 | ≥ 0，窗 120 ms |
| U3 | 躯干倾角速率在界内 | — |

### 7.4 三条硬规则（都有文献）

**R1 · 抬腿是"双钥匙"门。**
Kuindersma：*"the requirement that both conditions [perceived contact AND planned contact]
were true was essential for breaking contact with the ground"*。
⇒ 迈步系统抬腿必须 **状态机许可 AND 实际接地检测为 false**，缺一不可。

**R2 · 交接必须在双支撑相里完成。**
Lee et al.：*"the absence of DSP can lead to discontinuous variations in robot CoM
acceleration during support transitions, resulting in **discontinuous joint torque
commands**"*。
⇒ **禁止在单支撑相中间切换控制权**；交接窗口必须落在双支撑相内。

**R3 · 相位要平滑，不能硬阈值。**
用 HugWBC 的平滑接触概率（正态 CDF）：
```
C(φ) = Φ(φ̄/σ)·[1−Φ((φ̄−0.5)/σ)] + Φ((φ̄−1)/σ)·[1−Φ((φ̄−1.5)/σ)]
```
把切换点 φ̄=0 / 0.5 变成区间 ±3σ ⇒ 直接得到一条**连续的权限调度 α(t)**，
正好喂给 Jarquín 的平滑切换（α(t) 插值 + 阻尼常驻最低优先级、权重永不低于 1 ⇒ q̇ 连续）。

**交接时序模板**（Lee et al. 的相触发条件，最直接可复用）：
> *"When the current time `t` reaches the optimized phase duration `T_new`,
> a phase transition is triggered; then `t` is reset to zero."*
> 且 **`f^ctrl_{T_new} = 0` during DSP**（big-M 约束）——**落脚点修正只在单支撑相允许，双支撑相强制为 0**。
> 本方案类比：**腰的修正槽 α 只在单支撑相非零，双支撑相强制 0**。

## 8. 数据回读收敛：UI 与冒烟测试同源

### 8.1 问题
同一个量现在在四个地方各算一次（`dbgLog`、`Sim.terms`、`probe-arch` 统计、UI 的 DOM），
于是"冒烟测试读到的"和"UI 绘制的"可以不一致。

### 8.2 契约
```
controller.step() → 不可变快照 RigSnapshot（每拍整体替换）
                         ↓
        ┌────────────────┴────────────────┐
     UI（只画这个）                探针 / 冒烟测试（只读这个）
```
1. 快照是**唯一可读出口**，UI/探针/冒烟测试都不得自行计算物理量。
2. 快照**不可变**：持有旧快照不会被后续 tick 改变。
3. **UI 不做推导**：前后腿/承重/锁定必须由控制器直接产出，UI 只上色排版。
4. **冒烟测试 = UI**：提供一个探针直接消费 UI 消费的那份快照，
   断言"UI 能画出来的字段"全部非空。这条就是防再次失同步的门禁。

### 8.3 快照最少字段

| 组 | 字段 |
|---|---|
| 身份 | `loadBearer`、`locked{l,r}`、`phase`、`phaseT`、`supportLeg`、`swingLeg`、`authority` |
| 腿 | 每侧 `grounded`、`loadFrac`、`soleY`、离地高度、CoM 相对位置 |
| 前后腿 | 每侧 `isFront`/`isBack`（**由实测脚 x 得出**，不是硬编码左右） |
| 关节 | 每轴 `pos`/`vel`/`target`/`owner`/`system`/`suppressed[]`/`clamped`/`limitHit` |
| 平衡 | `com`、`dcm`、`MoS`、`grf`、倾角、躯干高度 |
| 判据 | `bearerCriteria{B1..B4}`、`unlockCriteria{U1..U3}`、`stepPermit{P1..P4}` **逐条真假** |
| 冲突 | 每轴 `suppressed[]`（谁被压住了） |

> **判据逐条回显**是关键：这样"为什么没迈步"不用推断，直接看到 `P3 = false（MoS = −33 mm）`。

## 9. 单腿站立 = 平衡维持系统的验收（迈步系统同时在线，但不考核落地）

用户要求：**单腿站立验证平衡系统；迈步系统同时工作，但不要求能正常落地。**

这正好对应文献里现成的三档评分（arXiv:2608.00500）：

| 档 | 定义 |
|---|---|
| **Perfect** | 支撑脚**从不跳**、摆动脚**从不触地**、不摔 |
| **Marginal** | 仅靠跳或靠摆动脚触地才站住 |
| **Failure** | 摔 |

⇒ **把摆动脚的触地单独计分**，就实现了"考核平衡、不考核落地"。

**指标目标**（同一篇）：
| 指标 | 好的单腿保持 | 通用策略（8 个 SOTA，90 段测试） |
|---|---|---|
| MoS 侧向 | **−0.025 m** | −0.16 ~ −0.74 m |
| MoS 前后 | **+0.048 m** | — |
| 捕获点出域时长 | **0.09 s / 3.3 s** | 3.11~3.25 s / 3.3 s |
| 支撑脚滑移 | 小 | 84~581 mm/s |
| 侧向支撑半宽 | **< 3 cm** | — |

> 那篇的结论值得记住：*"eight released state-of-the-art generalist policies hold a clean
> single-leg stance on **0 of 90** test motions; they stay up only by stepping or hopping,
> **recovering from imbalance rather than preventing it**."*
> ⇒ 单腿站立确实是**区分"会平衡"和"会自救"**的分辨性基准。

**测试集规格**（照抄其结构）：支撑腿下蹲深度 × 摆动脚高度 的 3×3 网格，
每段 4.98 s，取中间约 3.3 s 单支撑窗评估，左右各半。

**本阶段对迈步系统的要求**（明确降低）：
- ✅ 必须在线、必须在正确相位输出落脚点与摆动轨迹
- ✅ 必须受交换协议与锁定闸门约束
- ❌ **不要求**落地质量、不要求步长、不要求速度跟踪
- 计分只看它**是否被正确门控**（该抬时抬、不该抬时压住）

**其它相关依据**：
- Herzog 2016 的动量平衡控制器*"works even when the robot is standing on only one foot"*
- 临床 Single Leg Stance test 的规范值 25~33 s（健康 60~69 岁）
  ⇒ 作为参考量级，**不作为通过标准**（该测试的跌倒预测效度在文献里本身有争议）

## 10. 迁移路线

每阶段结束时必须能跑冒烟测试。

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| **0** | 本文档评审：确认承重/锁定语义、交换协议、α 预算 | 无歧义 |
| **1** | `rig.ts`：I1–I3 + 逐关节体检 → `RigReport` | 启动即断言；`foot_*` 明确显示"不存在" |
| **2** | `rigState.ts`：承重标识 + 锁定 + 需求仲裁（**纯逻辑、无物理**） | 单元测试：锁定/解锁/仲裁/冲突可预测 |
| **3** | 两系统改为提需求，删各自数据副本 | 每轴 owner 数恒为 1（断言） |
| **4** | 状态机 + 交换协议 + `α(t)` | 三个交换点的判据逐条可回读 |
| **5** | `RigSnapshot` + UI/冒烟测试同源 | 冒烟断言 UI 字段全部非空 |
| **6** | 平衡维持系统接入，单腿站立基线 | **Perfect 档**：摆动脚不触地、不摔、MoS 达标 |
| **7** | 迈步系统接入（门控 + 摆动轨迹 + 腰修正槽） | 迈腿数 > 0，且 α 预算不超 2.5 mm MoS |
| **8** | 训练回路接入（ES 学残差，不学全部） | 训练改善而不破坏基线 |

> 1–5 全是"让非法状态不可表示"，**不改变任何控制行为**，
> 因此可以零物理风险换地基。6 才开始动控制。
