## 0. 一句话架构

**一个状态机定相位，两个系统出意图，一个模块出力气。**

```
状态机（六态环）──显式方向──▶ 迈步系统（每状态一次动作 + 提案）
                                    │
              摆动腿提案/腰槽        ▼
                          ┌──────────────────────┐
                          │ **唯一姿势模块**       │
   CoM/支撑/计划 ─────────▶│  supportLeg.ts        │──▶ 腿/髋/踝/躯干张力的
   （监督层 copPlan）       │  力向量 + 吊索 + CoP  │    **唯一出口**
                          └──────────────────────┘
                                    ▲
            平衡余部（守卫层 + 腰部工具 spineDefaultTone）
```

**边界纪律（不可协商）**：
1. **状态机不发任何关节目标**（只定相位、只发方向/验收）；
2. 迈步**不写承重腿轴**；平衡不**新增**摆动腿要求（可修正提案）；
3. **腿/髋/踝的发力只有一个出口**（唯一姿势模块）；
   平衡系统的四条力通道（④c矢状JᵀF / ⑤横向 / ⑥踝VIP+CoP / spill）写路径**已物理删除**。

## 2. 唯一姿势模块（`supportLeg.ts`）—— 全部"力气"

### 2.1 结构（一个出口，多路需求）

```
需求层（不新增信号，全部收编既有律）
 ├─ 支撑载荷 Fv        ← 原始 CoP 力 / 载荷滤波×体重（稳健）
 ├─ 矢状刹车 Fh        ← −mω²·overX − 2mω·vxK·vx      （CoM 位置+速度）
 ├─ 侧向力 Fhz         ← balance 的 computeWantedForce.comp.lateral
 ├─ CoP 目标 copT      ← 监督层 plan.needX
 ├─ VIP 踝弹簧         ← k·q_vip − c·q̇（Loram & Lakie 内禀踝刚度）
 └─ 挺腰（折角驱动）    ← spine*/2 折角 + 变化率（预先项）

吊索层（肌筋膜链，Vleeming / Wilke）
 ├─ S1 表层后线：蹬伸力 → 同侧 spine1/2 + spine2/2 伸张力矩   （转正）
 └─ S2 force closure：左右载荷差 → spine1/2 张力               （转正）
   （S3 后功能线/BFL、S4 前功能线：已建，**实测净负 ⇒ 默认关**）

执行层（**唯一**）
 ├─ 静力映射（腿轴坐标系 `LIMBFRAME=1`）：τ_j = r×F_limb（等价展开）
 ├─ CoP 积分追随（增量式 + 速率限幅）
 └─ requestTorque（`loadBearing=true`）+ requestHold（让位）
```

## 3. 状态机（`gaitState.ts`）

- 六态环：`DOUBLE → LOAD → PUSH → THRUST → LIFT → SWING → DOUBLE`；
- **只做两件事**：①指定角色（support/swing）②验收（姿态是否符合本状态）；
- 输出表含 `roleSup/roleSw`、各状态**显式方向**、交接判据（`loadAcceptFrac=0.6`、
  `handoverTolZ` 等）；
- **角色标签防抖**：`FRONTHYST=0.06`（前后腿迟滞带，正常步态落脚差 ≥100mm 不会误锁）。

## 4. 迈步系统（`step.ts`）

- 每状态**一次动作**（关键帧）+ 提案（`proposeUpperBody` / `requestWaistSlot`）；
- `SWGATE=1`：**只摆动相写关键帧**（修"双脚在地被抬脚"的开局泵）；
- `KFSTATE=1`：非摆动相用 `KEY_POSES[STATE_TO_GAIT]`（修 LOAD 踝被钉死）；
- **点到为止**：`loadFrac[recv] ≥ loadAcceptFrac` 即 `shiftDemandF=0`；
- W3 应急落足：`copPlan.{stepX,stepZ,stepUrgent}` → 髋偏移 + 摆动加速。

## 8. 文献契约（每篇约束的条款）

|---|---|---|

## 9. 验收体系

**主指标（唯一）**：**站立窗** —— 时间窗口径
`{|pitch|<10° ∧ 腰最弯<10° ∧ CoM.y>0.85m}` 的最长连续时长 ≥ 1.0s。
**真倒（头y<0.6）必须附注站立窗**，不得单独引用（假读数三次教训）。

**门禁**：`probe-axisown` 全绿 + `probe-readback` 全绿 + `typecheck`=0。

**纪律**：
1. 每个新开关**默认关**、单变量扫描、**正收益才转正**；
2. **消融必须验证"改动真的生效"**（`envNum` min/空串陷阱 5 次；恒等类改动做"应当恒等"对照）；
3. **§22.54 规律**：任何"更符合理想"的改动若掉站立窗 ⇒ 当前形态可能是**功能**不是冗余，
   记录并改为"替换而非叠加"。

### 10.3 间歇控制（Bottaro 2005 / Gawthrop 2011）—— 已实现 + 恒等验证

- **文献**：*"Body sway = the residual **chattering** of an **intermittent stabilization** process"*（Bottaro）；
  *"**continuous observation, intermittent action**"* + 事件触发 + **不应期** + hold（Gawthrop）。
- **实现**（`supportLeg.ts`，`INTERM=1`）：剪力命令走事件触发门
  （`INT_TRIGX/INT_TRIGV`）+ 不应期（`INT_REFRAC`）+ 触发间保持。
- **恒等验证** ✓：阈值极小+规则采样 ⇒ 与基线**逐位相同**（1.73/1.63/27.3）——正是原文断言。
- **朴素参数化净负**（`REFRAC=0.25`→1.23/0.59；0.15/0.35→直接倒）。
- **缺口**：文献的完整版还需 **intermittent predictor**（开环段内的预测/内部模型）——
  "throw and catch" 的"catch"靠预测。**待办**。

### 10.4 两个待办（有数据支撑）

1. **τ 收敛 / 翻号**：剪力速度项是翻号主犯（3s 9 次），但它是**唯一的高频阻尼来源**
   ——因为**被动刚度缺一半**（VIP 270 vs 文献 590）。
   **候选配方**：`VIPK→550 + FH_VXK→0.2`（实测：窗口 1.73/1.63 ≈ 基线、翻号 9→4，
   但 τ 饱和 11→14——剩余峰值来自 **CoM/CoP 摆动 ±176mm**）；
   **下一步**：`needX` 规划的**平滑化**（ξ 的速度部分低通，目标不逐拍抖）。
2. **膝侧向限位**：`knee_l/0` 冲到 52°（限位 6°）——限位权限/硬投影问题。
