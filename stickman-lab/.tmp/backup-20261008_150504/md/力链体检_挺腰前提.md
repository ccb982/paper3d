# 力链体检报告：**"脚部强制发力，能不能把弯下去的腰挺起来"**

> 用户令（2026-10-08）：
> 「我先要求脚部强制发力，能把弯下去的腰挺起来。这是谈控制算法的前提。
> 各个关节都不能用，后续真的无从谈起了。总之架构也要干净收敛，之前错误的代码就应该丢弃。」

本报告只回答**一个问题**：力从脚走到腰，这条路通不通。不谈控制算法、不谈增益整定。

工具：`node tools/run.mjs probe-lift-waist [踝τ] [膝τ] [髋τ] [秒] [模式]`（新增）
　　　`node tools/run.mjs probe-authority ...`（项目原有，本次发现已失效——见 §4）

---

## 0. 一句话结论

**力到得了腿和骨盆（可测、方向正确、量级可调），但它进不了"腰"——而这不是执行器不够力，
是"把力送进腰"的那条通道在代码里根本不存在（默认关闭 + 走错通道 + 符号反）。**

- `V4KTRUNK`（唯一被文档指定为"力进腰"的任务，§3.5 证明二）**出厂值 = 0** ⇒ 从未生效。
- 打开后，它**走的是 `controlV1` 分支**，而当前的默认链路是 `chainV1`（`V4CHAIN=1`）
  ⇒ 打开也没用（实测 0/40/100/200 输出**逐位相同**）。
- 强行切到 `controlV1`（`V4CHAIN=0`）后，**符号是反的**：躯干 pitch 从 0° 被推到 **+82°**
  （往"折"的方向走），而不是回正。
- 项目自带的验收工具 `probe-authority`（§0.2 判据②）**在 V4 模式下永久不可能通过**，
  因为它的注入点 `torqueCmd` 被 `v4Tau` 无条件覆盖（§4）。

## 1. 实验设计与原始数据

### 1.1 弯腰基线（全段关闭、零注入）

```
 t   | 腰高(spine4) 骨盆高 | 躯干pitch | CoM.y | 脚L fz 脚R fz | 髋τ实 膝τ实 踝τ实
 0.01 |      1430      826 |     0.0°  |  962  |    0     60  |    0     0     0
 0.11 |      1426      823 |    -0.2°  |  959  |  184    185  |   -2     6   -23
 0.41 |      1401      804 |    -2.0°  |  939  |  153    156  |  -27   129  -156
 0.81 |      1257      715 |   -11.3°  |  848  |   31    141  |  -48   524  -101
 1.21 |       384      308 |   -22.8°  |  327  |    0      0  |    2  1384  -115
★ 腰高 1430 → 135 mm  躯干 0 → 155.1°（脸朝下）
```

**读法**：脚从 t=0.01 起只承 **60N + 184N ≈ 360N / 687N = 52%**（与昨天的体检一致）。
脚一旦卸空（t=1.21 起 fz=0），身体立刻脸朝下拍在地上。
**注意 `膝τ实` 一路冲到 1384 N·m（τmax=150，9.2×）** —— 这是位置伺服在硬撑，不是控制输出。

### 1.2 强制踝发力（注入 120 N·m，走正确通道 `V4SIGNCAL`）

```
 t   | 腰高      骨盆高 | 躯干pitch | 踝τ实
 0.01 | 1430      826   |    0.0°  |  120   ← 注入确实到达
 0.41 | 1399      802   |   -2.0°  |  -57
 1.21 |  318      318   |  -19.7°  |  -52
★ 腰高 1429 → 161 mm（Δ −1268mm）  ⇒ 与基线**几乎相同**
```

**踝单独发力对"挺腰"没有可测影响。**（不是没到达——`踝τ实=120` 是确认的；
是踝的力度相对躯干重力矩差一个量级。）

### 1.3 三关节全开（踝/膝/髋 各注入 200 N·m）

```
 t   | 腰高      骨盆高 | 躯干pitch | 髋τ实 膝τ实 踝τ实
 0.01 | 1430      826   |    0.0°  |  200   200   200
 0.31 | 1211      804   |   -0.6°  |  -60    68   446
 0.71 |  417      790   |   -3.0°  | -149   -10   451   ← 骨盆被撑住(790mm)
 1.41 |  344      820   |   -8.2°  | -398   116   381
 2.01 |  210      591   |  -37.8°  | -379   174   268
★ 腰高 1429 → 174 mm
```

**这是最有信息量的一组**：t=0.71~1.71 期间**骨盆被稳定撑在 820mm**（腿确实在发力承重），
**但胸腔折叠到 344mm** ⇒ 身体是"骨盆立着、上身折下去"的 **Z 字折叠**。
⇒ **腿的力到得了骨盆，到不了胸腔。这就是"力链断在腰上"的直接证据。**

### 1.4 髋注入扫描（隔离"从胯发力"的权威性）

| 注入 | 骨盆高(t=1.0) | 躯干pitch(t=1.3) | 观察 |
|---|---|---|---|
| 0（基线） | 563 | −19°→153° | 全塌 |
| **+200** | **708** | **+30°** | 骨盆明显被托起，但躯干反而前折 |
| −200 | 592 | −16°→61° | 反向 |
| +400 | 113 | +40° | 过载，直接崩 |

⇒ **髋有可测的权威性（骨盆 563→708，+145mm）**，但它的效果是**推动/制动骨盆**，
**不是把胸腔"竖直"**。注意符号：注入 +200 而回读 `髋τ实 = −173~−221`（**符号翻转**）。

## 2. 根因定位（三条，全部可复现）

### 根因 A：`V4KTRUNK` 出厂 = 0，且 `chainV1` 不读它

`src/core/v4/controlV1.ts`：
```ts
kTrunk: 0, bTrunk: 0,            // DEFAULT_V4_1（出厂值）
const kTrunk = envNum('V4KTRUNK', cfg.kTrunk);   // ← 只影响 controlV1 分支
```
`chainV1.ts` 的躯干段**不读 `V4KTRUNK`**，它只用自己的 `CHAIN_DEFAULTS.kTrunk = 60`：
```ts
export const CHAIN_DEFAULTS: ChainParams = { kTrunk: 60, ... };
```
而 `chainV1` 的 `segTrunk` 又被 `V4C3` 开关 + `xiErr` 缩放控制：
```ts
const g = Math.min(1, Math.max(0, Math.abs(xiErr) / 0.05));
const k = p.kTrunk * g;
```

**后果**：文档 §3.5 证明二说"力进腰 = T2 的显式任务 `τ_hip`"，
但 T2 在默认链路上是**另一个模块里的一套数**，两套并存、互不知道对方。

### 根因 B：唯一 + 生效 的躯干任务，**符号是反的**

`controlV1.ts:669`：
```ts
let trunkPitch = 0;
const bi = doll.sk.bodies.findIndex((b) => b.key === 'spine3');
if (bi >= 0 && doll.bodyWorldAxis(bi, 1, tmp.rj)) {
  const ux = tmp.rj[0]!, uy = tmp.rj[1]!;
  trunkPitch = Math.atan2(ux, uy);      // 「前倾为正」
}
...
d += -kTrunk * (k === 2 ? trunkPitch : trunkRoll);   // 线 689
```

实测（`V4CHAIN=0 V4KTRUNK=200`）：
```
 0.51 | 1362 | +8.6°    1.01 | 490 | +82.7°
★ 躯干 0 → 123.8°（**被推向正方向 = 更折**）
```
期望：躯干前倾为正 ⇒ 应用正 τ 把它拉回 0。实测**越拉越前倾**。
⇒ 要么 `d` 的符号约定错，要么 hip 关节的 `d` 到物理 τ 之间还有一次符号翻转
（`ragdoll.ts` 的 `V4SFK/V4SFH/V4SFA` 符号矩阵，默认 +1）。

### 根因 C：`chainV1` 的躯干段只在"有 ξ 误差"时出力

```ts
const xiErr2 = inp.xiX - copBase2;      // copBase2 = comX（无命令时）
const trunk = on3 ? segTrunk(q.trunkPitch, q.trunkRate, xiErr2, paramsT) : 0;
```
且 `segTrunk` 内部再乘一次 `g = clamp(|xiErr|/0.05, 0, 1)`。
**站桩 ξ≈0 ⇒ trunk 输出 = 0**（与昨天"静止腿输出 0"同一个结构）。

## 4. ★ 附带发现：项目自带的验收工具已失效

`probe-authority`（§0.2 判据②的指定工具）注入路径：
```
controller.ts:647  rs.requestTorque(aJ, aAxis, aTau, 'balance', 'authority实验')
                   ↓ 进入 rs.tauOut
controller.ts:663  doll.setTorqueTargets(rs.tauOut)
                   ↓ 写入 this.torqueCmd
ragdoll.ts:3308    let tq = this.torqueCmd[idx]!;        ← 到达
ragdoll.ts:3317    tq = vs * this.v4Tau[idx];            ← **无条件覆盖，丢弃**
```

⇒ **在 V4 模式（默认）下，`probe-authority` 注入的 τ 永远到不了物理层。**
它的输出（`CoP.x=0`、`ΔCoP=0`、CoM 只是正常漂移）是**假阴性**，
会被误读成"权威性不够"，实际是"注入根本没发生"。

**这是"之前错误的代码"的典型样本** —— 两条 τ 通道（`torqueCmd` / `v4Tau`）
在物理层被要求二选一，但**没有按 v4 宪章"同一根轴只有一个数"收敛**，
留下一条死通道在做"看起来像对照实验"的事。

## 5. 修复序（架构不变，只补接线；按依赖排序）

> 目标：让 §0.2 判据② 真实通过 —— 用**可测的 CoP 位移**证明"脚发力 → 腰被拉回"。

| 步 | 动作 | 验收 |
|---|---|---|
| **A0** | **删掉死通道**：`ragdoll.ts:3308` 的 `torqueCmd` 在 V4 模式下不再被消费（或明确注释它是 legacy）；把 `probe-authority` 的注入改走 `v4Tau` | `probe-authority` 的 `CoP.x` **不再恒 0** |
| **A1** | **统一躯干任务的唯一写者**：把 `controlV1` 的 T2 与 `chainV1` 的 `segTrunk` 收敛成一个 —— 只保留一个模块能写 `hip_*` 的躯干分量 | `V4KTRUNK` 在 `V4CHAIN=1` 下也生效（或彻底移除该 env） |
| **A2** | **修符号**：用 `probe-lift-waist` 扫描 `V4KTRUNK ∈ {±50, ±150}`，取"躯干 pitch 向 0 收敛"的符号，写死进代码 | 注入后躯干 pitch **减小** |
| **A3** | **给出厂值**：`kTrunk` 从 0 改成一个实测能挺腰的量级（先用 `probe-lift-waist` 顶点扫） | 腰高在注入期间**上升** |
| **A4** | **补脊柱通道**：全腿注入时骨盆能撑住但胸腔折 ⇒ 脊柱必须有独立的回正力矩（当前 `V4KSPB=150` 是弱弹簧，且目标是 0） | Z 字折叠消失（胸腔高 ≈ 骨盆高 × 0.95） |

**A0 必须最先做**，否则后面每一步都没有可信的仪表。

## 6. 回答用户

- **"脚部强制发力能不能把弯下去的腰挺起来"**：
  **当前的代码不能。** 不是执行器没力（踝 120/髋 200 都实测到达），是：
  ① 唯一被设计来做这件事的任务（T2 / `kTrunk`）**默认关闭**；
  ② 打开也**走错分支**（`chainV1` 不读它）；
  ③ 强行启用后**符号反**（越拉越折）；
  ④ 项目自带的验收工具**注入点已死**，所以你此前看到的"测不出来"是假阴性。

- **"各个关节都不能用"**：`lift-waist` 显示 200 N·m 全腿注入下，
  骨盆能被撑到 820mm（腿能用），**但胸腔持续下折**（腰不能用）。
  这两件事必须分开修。

- **"架构要干净收敛，错误的代码应该丢弃"**：
  建议的第一刀就是 §5 的 **A0**（删 `torqueCmd` 死通道）——
  它是"同一根轴两个数"的最后残留，违反你自己的通道宪章 §3.0。
