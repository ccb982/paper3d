## 1. 已实测确认的故障（不是推测）

### 1.1 现象

```
   t   承重  L载   CoM.z  CoP内侧余量   足跟  外侧柱   趾  |  倾角
 0.42   l  100%     -1      111mm       114      0     0  |   6.6°
 1.22   r   24%    -31       14mm       262      0     0  |  20.5°
 1.28   r    8%    -37       **0mm**      61      0     0  |  22.8°
 1.35   r   64%    -46        0mm        0      0     0  |  27.0°  ← 侧翻
```

- 承重**几乎全部集中在「足跟 + 外侧缘」**
- 跖骨 / 趾长期 **≈ 0%**（没有蹬离能力）
- CoP 内侧余量降到 **0mm**（压力中心跑到支撑面边缘）⇒ 倾角同步爬到 27°

### 1.2 根因

**脚是单个刚体，内侧弓被硬编码离地 22mm 之后永远不可能接地。**

```
挂在 foot_l 上的关节: foot_l    ← 这是「踝」（关节名就叫 foot_l），不是脚内部的关节
```

6 块鞋底（足跟 / 外侧柱 / 内侧弓·后 / 内侧弓·前 / 跖骨头 / 趾）是**同一个刚体上的
6 个 collider**，脚内部**零自由度**。而 `archRise = 0.022` 是硬编码常量，
没有任何力能把它压下去。

⇒ 支撑面从"一个面"退化成**"后跟—外侧缘"一条线** ⇒ 侧向 CoP 无处可去 ⇒ 侧翻。

### 1.3 造成这个设计的那条错误注释（已更正）

`skeleton.ts` 弓形段原写着：

> 「而且弓本身就是**拱形柔顺结构**（承重压缩、离载回弹 = arch recoil），
> **不需要额外的中足关节去模拟**。」

**这句话是假的。** 拱形柔顺需要**形变能力**，而整只脚是单个刚体、形变能力为 0。
这条注释把一个**缺失的机制**描述成了**已有的机制**，正是本项目最要防的那类假权威。
（已改写为显式的更正说明 + 实测证据。）

### 1.4 连带解释了一批此前的"调参失败"

此前我调过的站距、额状刚度/阻尼、腰张力、髋外展权限，全部是在
**用躯干的功替代一只本该自己在承重的脚**。所以：

| 现象 | 真实原因 |
|---|---|
| 脊柱一加张力，重心就不动（存活掉到 0.73s） | 搬运重量的功**全压在腰上**，腰一受约束就崩 |
| 髋外展 τmax 120→200 **反而更差** | 它在替脚干活，给多就冲过目标 |
| 最小 X3 能到 2mm 但驻留只有 0.08s | 重心能过去，**脚下没东西接住** |

## 2. 文献依据

| 来源 | 结论 |
|---|---|
| **Jeon & Cho 压力垫综述** | 「第一接触点通常在踝关节中心**外侧**，在**距下关节产生旋前力矩**，允许柔性活动」；「**内侧弓把重量传递到足的外侧缘**」 |
| **Welte 2023** | 内侧弓的**可动性**是人类两足行走的演化产物 |
| **jjrmc 54:618（2015）** | 侧向体重移动时「lateral weight shifting resulted in an outward tilt due to **foot pronation**」；腓骨肌 + 旋后肌参与 |
| **Winter 1998** J Neurophysiology 80:1211 | 额状面刚度由**髋外展/内收肌**提供；足只是被动的支撑面 |
| **2025 J Neurophysiol** | 稳定力矩来自**前馈肌张力**调节短程刚度；髋膝有前馈、踝只有反馈 |

**关键分工**：髋外展负责**托住和搬运重心**（Winter），足负责**接住**（Jeon & Cho）。
现在足完全没有接的能力 ⇒ 髋必须一个人干两份活 ⇒ 权限永远不够。

## 3. 设计：弓刚体 + 旋前关节

### 3.1 拓扑

```
现在：  shin_l ──foot_l(踝 revolute 轴2)──▶ foot_l(6 块鞋底，单刚体)

改成：  shin_l ──foot_l(踝 revolute 轴2)──▶ foot_l(足跟/外侧柱/跖骨/趾)
                                            └──arch_l(内侧弓·后 + 内侧弓·前)
```

- 刚体数 **15 → 17**，关节数 **14 → 16**
- 新关节 `arch_l` / `arch_r`：**revolute，绕足长轴（局部 X）** = 旋前/旋后

### 3.2 旋前的几何

内侧弓顶点离地 `archRise = 22mm`，弓区沿足长约 22%~57%（半长 ~40mm）。
要让它踩实需要约 `atan(22 / 40) ≈ 28°`。

| 参数 | 取值 | 理由 |
|---|---|---|
| 限位 | **−4° ~ +16°** | 正 = 旋前（向下踩实）。**只给到 16° 是刻意留 12° 不踩实** —— 见 3.4 |
| 关节锚点 | 足长 **22%** 处（`cfg.archAtFrac = 0.22`） | 弓的近端，靠近跖骨 |
| τmax | `ankleTorque × 0.25` = **30 N·m** | 它是**被动承载**件，不是主动执行器 |
| 阻尼 | 必须有 | 见 3.4 |

### 3.3 为什么限位只给 16°（而不是踩实的 28°）

28° 能让弓完全踩实，但那样脚就变成**平板**了 —— 弓形消失，
`Lugade & Kaufman 2014` 要求的 CoP 行程（足宽 27%）反而丧失。

**目标是"弓能踩下去一部分"，不是"弓踩平"。** 16° 让内侧弓承重但保留弓形，
侧向 CoP 多出一段行程，同时脚不会塌成一块板。

### 3.4 阻尼是必需项，不是可选项

**中足关节当初被删掉的原因就是塌陷。** 但正确结论是
**"缺限位和阻尼"**，不是"不该有中足关节"。所以弓关节必须同时有：

- **限位**：`[−4°, +16°]`，`revoluteAxis = [1,0,0]`（只放开局部 X）
- **阻尼**：否则弓在受载时是欠阻尼的，承重→回弹会像弹簧一样抽
  （与 `ragdoll.ts` 里踝的 `jointGain` 覆盖同一套机制，可直接复用）

**验收判据**：单腿站立时弓的角度应该稳定在某个值附近（不 oscillate），
且 `arc` 的实际承重 > 0。

## 4. 顶点解算（手写蒙皮，复用现有 LBS）

### 4.1 现状：躯干已经有双骨 LBS

`viewer.ts` 的 `skinPositions()` 已经是标准的二骨线性混合蒙皮：

```ts
SkinBinding {
  loc0, loc1      // 每个顶点在骨0/骨1 绑定姿态下的局部坐标
  vS0,  vS1       // 每个顶点的骨0/骨1 驱动刚体下标
  vW1             // 每个顶点在骨1 上的权重（w0 = 1 − w1）
}
// out = w0 · (R0·loc0 + T0) + w1 · (R1·loc1 + T1)
```

**脚不需要新写一套，只需要按脚的几何填一份 `SkinBinding`。**

### 4.2 脚的绑定权重

靴子贴图由 `foot_*` **整张画**（`plateHidden` 的前足不画，否则出现"两只脚"）。
所以弓刚体必须 `plateHidden = true`，靴子网格由**两组刚体共同驱动**：

```
所有顶点：        vS0 = foot_* 下标
弓区顶点：        vS1 = arch_* 下标
权重 w1 = smoothstep(archX0, archX1, vertexLocalX)
                = 0   在弓的近端（x = archAtFrac 处）
                = 1   在弓的远端
弓后方的顶点（足跟）：w1 = 0，完全跟 foot_*
弓前方的顶点（跖骨/趾）：w1 → 1，完全跟 arch_*
```

**平滑过渡是必须的**：硬切会让靴子在弓的边界处被撕开。

### 4.3 验收判据（沿用躯干那套）

`viewer.ts` 已有收敛性判据：**单位旋转时输出必须等于绑定位置**。
弓的绑定也要过这一条 —— 即 `foot_*` 与 `arch_*` 都处于绑定姿态时，
`sPose()` 的输出必须逐位等于绑定顶点。

### 4.4 必须 `frustumCulled = false`

顶点每帧变，包围球失效。躯干已经这么做了（`viewer.ts:34`），脚照做。

## 5. collider 与读回的连带修改（极易漏）

| 位置 | 必须改什么 | 漏了会怎样 |
|---|---|---|
| `ragdoll.soleCols[side]` | 内侧弓两块要从 `foot_*` **转到 `arch_*`** | 承重读回仍是错的分布（弓块挂在错的刚体上） |
| `ragdoll.soleColBody[side]` | 同上，一一对应 | 同上 |
| `ragdoll.soleBlockLabels` | 加弓刚体的标签 | 读回少两块 |
| `ragdoll.footSoleBounds(side)` | 弓旋转后鞋底包围盒要含 `arch_*` 的块 | CoP 侧缘余量算错 |
| `ragdoll.readCoP(side)` | 同上 | CoP 算错 |
| `footSoleBounds` 的半宽 | 弓踩下后内侧支撑面**变宽** | 支撑面判据失真 |
| `skeleton.ts` 的质量分配 | 弓的质量从 `foot_*` 拆出（≈30%） | 总质量漂移 |
| `net`（CoM） | 新增 2 个刚体后重心会变 | `com.z` 基线偏移，所有标定值失效 |

**最后一条是最大的坑**：`soleMass` 的分配一改，整机 CoM 就变了，
此前所有标定过的常数（`latStiff`、`omega0`、站距…）都要重量。

## 6. 实施顺序（每步都要回读，不要盲改）

本轮已尝试过一次实现，**连续踩了三个作用域错误**：
`archBlocks`/`L`/`HW` 定义在 `colliders: (() => {...})()` 的 IIFE 内、外部不可见；
`cx` 不可见；`joints` 数组在 `bodies` 循环**之后**才声明。
而且 `str.replace` 静默失败而脚本仍打印 `ok` —— **必须每次替换都带断言**。

1. **先读清结构**：`buildSkeleton` 里 `bodies` / `joints` 的构造顺序，
   `parentAnchor`/`childAnchor` 的坐标系约定，`ColliderDef` 的 `offsetX/Y/Z` 语义。
   **不要猜。**
2. 把 `archRise` / `L` / `HW` / `archBlocks` **提到 `bodies.push` 同一作用域**，
   让弓段可见。
3. 插弓刚体 + 弓关节，`tsc` + 回读刚体数（15→17）与关节数（14→16）。
4. `soleCols` / `soleColBody` / 读回函数改指向。
5. 弓关节的**限位 + 阻尼**接线。
6. 顶点解算：`SkinBinding` 按 4.2 的权重填一份，`frustumCulled = false`。
7. **重量全部标定值**（CoM 变了）。

## 7. 验收判据

| 项 | 判据 |
|---|---|
| 弓能承重 | `probe-footroll` 的弓块载荷 **> 0**（当前 ≈0） |
| 弓不塌 | 单腿站立时弓角稳定，不 oscillate |
| 弓不塌平 | 弓角峰值 **< 16°**（限位内），弓形可见 |
| 侧向 CoP 行程变大 | 内侧余量从 **0mm** 变成正数 |
| 驻留时间 | `X3` 驻留 > **1.0s**（当前 0.08s） |
| 顶点解算 | 单位旋转时输出逐位等于绑定位置 |
| 相位机 | 能走到 **STEP**（当前只到 MSt） |
