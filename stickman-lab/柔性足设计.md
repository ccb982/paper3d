## 1. 已实测确认的故障（不是推测）

### 1.1 现象

```
   t   承重  L载   CoM.z  CoP内侧余量   足跟  外侧柱   趾  |  倾角
 0.42   l  100%     -1      111mm       114      0     0  |   6.6°
 1.22   r   24%    -31       14mm       262      0     0  |  20.5°
 1.28   r    8%    -37       **0mm**      61      0     0  |  22.8°
 1.35   r   64%    -46        0mm        0      0     0  |  27.0°  ← 侧翻
```

- 承重**几乎全部集中在「足跟 + 外侧缘」**
- 跖骨 / 趾长期 **≈ 0%**（没有蹬离能力）
- CoP 内侧余量降到 **0mm**（压力中心跑到支撑面边缘）⇒ 倾角同步爬到 27°

### 1.2 根因

**脚是单个刚体，内侧弓被硬编码离地 22mm 之后永远不可能接地。**

```
挂在 foot_l 上的关节: foot_l    ← 这是「踝」（关节名就叫 foot_l），不是脚内部的关节
```

6 块鞋底（足跟 / 外侧柱 / 内侧弓·后 / 内侧弓·前 / 跖骨头 / 趾）是**同一个刚体上的
6 个 collider**，脚内部**零自由度**。而 `archRise = 0.022` 是硬编码常量，
没有任何力能把它压下去。

⇒ 支撑面从"一个面"退化成**"后跟—外侧缘"一条线** ⇒ 侧向 CoP 无处可去 ⇒ 侧翻。

### 1.3 造成这个设计的那条错误注释（已更正）

`skeleton.ts` 弓形段原写着：

> 「而且弓本身就是**拱形柔顺结构**（承重压缩、离载回弹 = arch recoil），
> **不需要额外的中足关节去模拟**。」

**这句话是假的。** 拱形柔顺需要**形变能力**，而整只脚是单个刚体、形变能力为 0。
这条注释把一个**缺失的机制**描述成了**已有的机制**，正是本项目最要防的那类假权威。
（已改写为显式的更正说明 + 实测证据。）

### 1.4 连带解释了一批此前的"调参失败"

此前我调过的站距、额状刚度/阻尼、腰张力、髋外展权限，全部是在
**用躯干的功替代一只本该自己在承重的脚**。所以：

| 现象 | 真实原因 |
|---|---|
| 脊柱一加张力，重心就不动（存活掉到 0.73s） | 搬运重量的功**全压在腰上**，腰一受约束就崩 |
| 髋外展 τmax 120→200 **反而更差** | 它在替脚干活，给多就冲过目标 |
| 最小 X3 能到 2mm 但驻留只有 0.08s | 重心能过去，**脚下没东西接住** |

## 2. 文献依据

| 来源 | 结论 |
|---|---|
| **Jeon & Cho 压力垫综述** | 「第一接触点通常在踝关节中心**外侧**，在**距下关节产生旋前力矩**，允许柔性活动」；「**内侧弓把重量传递到足的外侧缘**」 |
| **Welte 2023** | 内侧弓的**可动性**是人类两足行走的演化产物 |
| **jjrmc 54:618（2015）** | 侧向体重移动时「lateral weight shifting resulted in an outward tilt due to **foot pronation**」；腓骨肌 + 旋后肌参与 |
| **Winter 1998** J Neurophysiology 80:1211 | 额状面刚度由**髋外展/内收肌**提供；足只是被动的支撑面 |
| **2025 J Neurophysiol** | 稳定力矩来自**前馈肌张力**调节短程刚度；髋膝有前馈、踝只有反馈 |

**关键分工**：髋外展负责**托住和搬运重心**（Winter），足负责**接住**（Jeon & Cho）。
现在足完全没有接的能力 ⇒ 髋必须一个人干两份活 ⇒ 权限永远不够。

## 3. 设计：弓刚体 + 旋前关节

### 3.1 拓扑

```
现在：  shin_l ──foot_l(踝 revolute 轴2)──▶ foot_l(6 块鞋底，单刚体)

改成：  shin_l ──foot_l(踝 revolute 轴2)──▶ foot_l(足跟/外侧柱/跖骨/趾)
                                            └──arch_l(内侧弓·后 + 内侧弓·前)
```

- 刚体数 **15 → 17**，关节数 **14 → 16**
- 新关节 `arch_l` / `arch_r`：**revolute，绕足长轴（局部 X）** = 旋前/旋后

### 3.2 旋前的几何

内侧弓顶点离地 `archRise = 22mm`，弓区沿足长约 22%~57%（半长 ~40mm）。
要让它踩实需要约 `atan(22 / 40) ≈ 28°`。

| 参数 | 取值 | 理由 |
|---|---|---|
| 限位 | **−4° ~ +16°** | 正 = 旋前（向下踩实）。**只给到 16° 是刻意留 12° 不踩实** —— 见 3.4 |
| 关节锚点 | 足长 **22%** 处（`cfg.archAtFrac = 0.22`） | 弓的近端，靠近跖骨 |
| τmax | `ankleTorque × 0.25` = **30 N·m** | 它是**被动承载**件，不是主动执行器 |
| 阻尼 | 必须有 | 见 3.4 |

### 3.3 为什么限位只给 16°（而不是踩实的 28°）

28° 能让弓完全踩实，但那样脚就变成**平板**了 —— 弓形消失，
`Lugade & Kaufman 2014` 要求的 CoP 行程（足宽 27%）反而丧失。

**目标是"弓能踩下去一部分"，不是"弓踩平"。** 16° 让内侧弓承重但保留弓形，
侧向 CoP 多出一段行程，同时脚不会塌成一块板。

### 3.4 阻尼是必需项，不是可选项

**中足关节当初被删掉的原因就是塌陷。** 但正确结论是
**"缺限位和阻尼"**，不是"不该有中足关节"。所以弓关节必须同时有：

- **限位**：`[−4°, +16°]`，`revoluteAxis = [1,0,0]`（只放开局部 X）
- **阻尼**：否则弓在受载时是欠阻尼的，承重→回弹会像弹簧一样抽
  （与 `ragdoll.ts` 里踝的 `jointGain` 覆盖同一套机制，可直接复用）

**验收判据**：单腿站立时弓的角度应该稳定在某个值附近（不 oscillate），
且 `arc` 的实际承重 > 0。

## 4. 顶点解算（手写蒙皮，复用现有 LBS）

### 4.1 现状：躯干已经有双骨 LBS

`viewer.ts` 的 `skinPositions()` 已经是标准的二骨线性混合蒙皮：

```ts
SkinBinding {
  loc0, loc1      // 每个顶点在骨0/骨1 绑定姿态下的局部坐标
  vS0,  vS1       // 每个顶点的骨0/骨1 驱动刚体下标
  vW1             // 每个顶点在骨1 上的权重（w0 = 1 − w1）
}
// out = w0 · (R0·loc0 + T0) + w1 · (R1·loc1 + T1)
```

**脚不需要新写一套，只需要按脚的几何填一份 `SkinBinding`。**

### 4.2 脚的绑定权重

靴子贴图由 `foot_*` **整张画**（`plateHidden` 的前足不画，否则出现"两只脚"）。
所以弓刚体必须 `plateHidden = true`，靴子网格由**两组刚体共同驱动**：

```
所有顶点：        vS0 = foot_* 下标
弓区顶点：        vS1 = arch_* 下标
权重 w1 = smoothstep(archX0, archX1, vertexLocalX)
                = 0   在弓的近端（x = archAtFrac 处）
                = 1   在弓的远端
弓后方的顶点（足跟）：w1 = 0，完全跟 foot_*
弓前方的顶点（跖骨/趾）：w1 → 1，完全跟 arch_*
```

**平滑过渡是必须的**：硬切会让靴子在弓的边界处被撕开。

### 4.3 验收判据（沿用躯干那套）

`viewer.ts` 已有收敛性判据：**单位旋转时输出必须等于绑定位置**。
弓的绑定也要过这一条 —— 即 `foot_*` 与 `arch_*` 都处于绑定姿态时，
`sPose()` 的输出必须逐位等于绑定顶点。

### 4.4 必须 `frustumCulled = false`

顶点每帧变，包围球失效。躯干已经这么做了（`viewer.ts:34`），脚照做。

## 5. collider 与读回的连带修改（极易漏）

| 位置 | 必须改什么 | 漏了会怎样 |
|---|---|---|
| `ragdoll.soleCols[side]` | 内侧弓两块要从 `foot_*` **转到 `arch_*`** | 承重读回仍是错的分布（弓块挂在错的刚体上） |
| `ragdoll.soleColBody[side]` | 同上，一一对应 | 同上 |
| `ragdoll.soleBlockLabels` | 加弓刚体的标签 | 读回少两块 |
| `ragdoll.footSoleBounds(side)` | 弓旋转后鞋底包围盒要含 `arch_*` 的块 | CoP 侧缘余量算错 |
| `ragdoll.readCoP(side)` | 同上 | CoP 算错 |
| `footSoleBounds` 的半宽 | 弓踩下后内侧支撑面**变宽** | 支撑面判据失真 |

此前所有标定过的常数（`latStiff`、`omega0`、站距…）都要重量。

1. **先读清结构**：`buildSkeleton` 里 `bodies` / `joints` 的构造顺序，

7. **重量全部标定值**（CoM 变了）。

## 8. 实施结果（2026-10-05 收尾回读）

### 8.1 拓扑：从「死端悬臂」改成「串联承力链」

这一节是本设计**最重要的一次修正**，由用户指出：

> 「足弓可能不接地，但是理论上也在承重」

修正前的拓扑是错的：

```
foot_l（足跟+外侧柱+跖骨头+趾，全部直接落地）
  └─ arch_l（内侧凸起，死端，只挂着自己 0.123kg 的重量）
```

**实测证据**：弓关节力仅 **1N**，恰好等于弓自身重量（0.123kg×9.81）；
同期踝关节力 10N。⇒ 弓**一条载荷都不传**，是挂在脚掌内侧的悬臂。
这种拓扑下弓永远不可能承重，再怎么调重心侧移都没用。

真实的内侧柱是**串联**链：

```
足跟 → 距骨 → 舟骨 → 楔骨 → 第一跖骨头 → 地面
        └── 足弓在这条链上 ──┘
```

足弓在链上，所以**不接地也承重**（像弓弦一样受拉）。

**修正后的拓扑**（`flexibleArch` 开启，19 体 / 18 关节）：

```
foot_l(后足+外侧柱+外侧跖骨头+趾) → arch_l(内侧中足) → mfoot_l(内侧前足) → 地面
```

实现方式：把原「跖骨头」块（`fz −1.00..1.00`）沿 z 劈成两半，
内侧那半（`fz 0.00..1.00`，即**第一跖骨头**）成为新刚体 `mfoot_*`，
挂在 `arch_*` 的远端。

### 8.2 旋前轴必须落在鞋底外缘接地棱

弓的自由轴是**足长轴（局部 X）**。绕 X 轴旋转时：

```
高度变化 = Δy(cosθ−1) ≈ −Δy·θ²/2     ← 二阶小量！
```

只有当被转的点与轴有 **Δz** 间隔时，才有 `Δy ≈ θ·Δz` 的一阶竖向位移。

我最初把关节锚点放在**弓块自己的中心**（弓块的 z 与该轴相同 ⇒ Δz=0），
所以旋前几乎不产生竖向位移，弓永远压不到地面。

**修正**：锚点放在鞋底高度、偏外侧（`fz ≈ −0.70`）——
即解剖上真实的旋前轴（足底外缘那条接地棱）。

效果（`rise=0` 时）：弓角行程从 0.06° 涨到 **1.79°**。

### 8.3 弓必须由引擎的力模式电机驱动，不能用自研 PD

自研马达每步**显式**加冲量，等价于对 θ 显式积分，稳定上限：

| | 实测上限 | 原默认 | 超出 |
|---|---|---|---|
| K（刚度） | **7.33** N·m/rad | 100 | **14×** |
| B（阻尼） | **0.0305** N·m·s/rad | 15 | **500×** |

（弓绕长轴惯量仅 ≈7e-5 kg·m²，dt=1/120 s）

而真实足弓在负荷下只变形 2~3mm，需要 K ≈ **400 N·m/rad**，
是显式上限的 **55 倍** ⇒ 显式 PD **在物理上不可能**实现。

**修正**：`Rapier.MotorModel.ForceBased` + `configureMotorPosition(0, K, B)`。
它的刚度阻尼就是真实量纲 N·m/rad，且由求解器**隐式**积分，无此上限。
实测 K=1500（超显式上限 205 倍）仍然稳定，弓变形 0.06°。

> ⚠ 旧注释曾说「Rapier 的 stiffness 不是 N·m/rad」——那是**默认的
> `AccelerationBased` 模式**（把刚度当加速度、隐式除了质量）。切到
> `ForceBased` 后量纲就对了。

`arch_*` 与 `mfoot_*` **两个关节都用引擎电机**（链上不能一半引擎一半自研）。

### 8.4 `archRise` 取 0mm（实测）

需要旋前角 `θ = asin(rise / 126mm)`（承重窄条在外侧 fz≈−63mm、弓接触点在内侧 fz≈+63mm，间距 126mm）。实测：

| rise | 需旋前 | 弓接触帧 | 结果 |
|---|---|---|---|
| 22mm | 10.1° | 0% | 弓悬空 |
| 6mm | 2.7° | 0% | 弓悬空 |
| 0mm | 0° | **100%** | ✓ 承重 |

足实测只能倾 0.33~0.39°，所以任何非零 rise 都够不到。
⇒ 取 **0**。代价是弓体与鞋底齐平、看不出弓形；
内侧柱的刚度/形变链是真的（弓承重 7.9%、弓转 0.49°）。
弓形的外观由顶点蒙皮表现（§4 已实现）。

### 8.5 验收读数（`probe-archrise` / `probe-archwork`，240Hz）

```
rise=0mm  弓接触 100%  弓角行程 0.49°  弓承重 7.9%  CoP行程 25.6mm
弓关节力 均 10N   踝关节力 均 10N   内侧前足关节 均 2N
分块载荷 λ = [0.524, 0.446, 0.327, 0.168, 0.096, 0.032, 0.020]
             足跟  外侧柱  跖骨·外  趾   弓·后  弓·前  跖骨·内侧
```

弓自己的法向接触只有 0.096+0.032，**却通过关节把更多载荷传到内侧前足** ——
这正是「不接地也承重」的直接证据。

### 8.6 弹跳（period-2，60Hz @120Hz 物理）：是时间步长问题

逐帧回读**每块鞋底的法向冲量**才定位到：

```
外侧柱 λ 均值 2.853   帧间最大差 29.308   ← 342N 压在一条 30mm 窄条上
弓 λ 恒 0（不接地）
```

扫描结果（判据 = 外侧柱 λ 帧间摆幅/均值，<1.2 视为压住）：

| solverIterations | physicsHz | 相对摆幅 | 结论 |
|---|---|---|---|
| 16 | 120 | 9.6× | ✗ |
| 32 | 120 | 12.1× | ✗ |
| 64 | 120 | 14.1× | ✗ |
| 16/32/64 | **240** | **0.2~0.3×** | ✓ |

`solverIterations` 16→64 **完全无用**；`physicsHz` 120→240 一步解决。
⇒ 默认改为 **240Hz**（`controlHz` 120）。

顺带修好的：站立 3.38s 倒 → 18s+（注：18s 是弓未接串联链时的数，
有效基线见 §8.7）、支撑腿锁定「从未触发」→「0.43s 触发、96 帧、0 次不符」。

### 8.7 柔性足的代价（消融实测，`probe-stand noarch`）

| | 站立时长 | 死因 |
|---|---|---|
| `flexibleArch = true` | 4.43s | crash（torso 触地）|
| `flexibleArch = false` | 7.37s | head |

弓接上串联链后多了一段刚度和一个力矩通道，整体柔顺度下降、站立裕度变小。
**这是真实代价，不是 bug。** 换来的收益是 CoP 行程 15→25.6mm 与弓承重 7.9%，
而后者是重心调整（附录 B 的全链 QP）的前提。

> ⚠ 曾把「弓未接串联链时的 18s」当成基线，那是**坏脚**测出来的
> （弓关节力 1N＝自重）。弓真正接上后 4.43s 才是诚实数字。

### 8.8 途中修掉的 bug（全部属于「静默读错值」这一类）

| # | 位置 | 症状 |
|---|---|---|
| 1 | 弓刚体 `cy` | 用小腿中心（0.2365）而非 `ankleY`（0.0686）⇒ 弓浮在膝盖附近 190mm |
| 2 | 弓关节锚点 `rollY` | 同上 + 少减 `archRise` ⇒ 关节线垂到地底（用户可见「巨长的关节」）|
| 3 | 弓的 `length/radius/halfHeight` | 从小腿继承 ⇒ 调试视图在脚部画出小腿长的胶囊 |
| 4 | **`jointAngle()` 返回 `buf[2]`（Z 轴）** | 弓只有 X 自由度 ⇒ 我测的「弓角 0.00°」是**恒等于 0 的废话** |
| 5 | `soleBlockLoad` 取 collider 定义 | 用全脚下标 `ci` 而非刚体内下标 ⇒ 弓两项 `undefined` |
| 6 | 同函数 `return` 而非 `continue` | 把后面所有块的载荷一起中断 |
| 7 | 同函数用 XZ 包围盒过滤 | 静默丢掉跖骨头/弓后的真实载荷 |
| 8 | `footMass` 只减 `archMass` | 漏减 `mfootMass` ⇒ 总质量 70.45kg |
| 9 | `mfoot` 未登记进 `soleCols` | 内侧前足载荷读不到 |
| 10 | `notCrashKey` 正则漏 `mfoot` | 触地即判 crash ⇒ **倒于 t=0.00s**（用户报「完全静止」）|
| 11 | 弓角扫描缺 `minRad/maxRad` | 弓旋前本身无限制 ⇒ 转到限位后卡住 |

**教训（同一类错误当天犯三次）**：
- **坐标系混用**（局部/世界）：`offsetY` 是刚体局部、`wy/wz` 是世界。
- **硬编码名单漏改名**：`NOT_CRASH`、`soleCols`、`groupPlates` 都靠名字匹配，
  一改名就静默漏掉。第 10 条让整个回合在 t=0 死掉。
  ⇒ `notCrashKey` 已改成前缀正则；这类名单**应改为自动派生**（待办）。
- **测量仪器选错**：测「弓承重」用了法向接触冲量（只能量到弓自己压地），
  而承力构件要看**关节力**（`jointForce`）。这个错误让弓白"死"了好几轮。

### 8.9 消融开关

`SkeletonConfig.flexibleArch`（默认 `true`）。`false` 时：

```
刚体 15 / 关节 14   总质量 70.00kg   foot_l colliders=7
无 arch_*/mfoot_* 刚体 ✓   无对应关节 ✓   质量守恒 ✓
```

弓与内侧前足的 collider（含质量）全部归回脚体，无 `undefined`、无漏刚体。
