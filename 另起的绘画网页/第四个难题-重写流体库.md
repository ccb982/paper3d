1. 架构全景图（三层结构）
我们将系统拆分为 核心层（Core）、求解器层（Solvers） 和 管理编排层（Manager）。
核心层：负责 GPU 纹理内存管理（Ping-Pong 双缓冲）、分辨率定义、通道映射。
求解器层：纯函数式（或纯无状态类）。每个求解器只做一件事：平流、压力投影、Level Set 重初始化。它们不持有纹理，只接收输入纹理，写入输出纹理。
管理编排层：持有速度场、颜色场等具体实例，按固定顺序调用求解器，并处理外力注入。
2. 核心层设计：FluidGrid 与 Field
设计要点：彻底解耦“数据存储”和“数据含义”。
FluidGrid：持有一个分辨率（如 256x256）和两个 WebGLRenderTarget（双缓冲 A/B）。它只负责提供 swap() 方法和当前/下一个纹理的引用。
Field：是对 FluidGrid 的“视图”包装。它指定了纹理中 R/G/B/A 四个通道各自代表什么物理量。
例如 ColorField：{ R: "Hue", G: "Saturation", B: "Lightness", A: "Alpha" }。
例如 VelocityField：{ R: "VelocityX", G: "VelocityY", B: "Unused", A: "Unused" }。
关键创新（针对你只平流 S/L 的需求）：所有求解器在运行时都必须接受一个 ChannelMask（通道掩码） 参数（例如 vec3(0, 1, 1)），指定哪些通道参与计算。未标记的通道（如 Hue）在平流时直传，不做任何插值。
3. 求解器层设计（三大独立模块）
每个求解器都是一个独立的类，没有内部状态（State），只有配置参数（Params）。
A. 半拉格朗日平流求解器（AdvectionSolver）
职责：输入源场 + 速度场 + 通道掩码 + dt → 输出平流后场。
算法：标准反向追踪 + 双线性插值。
特殊处理（专为你定制）：
反向追踪时，掩码为 0 的通道（如 H）直接返回当前像素值，不参与 texture2D(backUv) 采样。
这样，H 固定在原地，而 S/L 自由流动，完美满足你的需求。
配置项：最大追踪步长限制（Clamp Step），边界模式（Clamp/Repeat/Zero）。
B. NS 方程压力投影求解器（PressureSolver）
职责：输入散度场 → 输出压力场，或输入速度+压力 → 输出无散速度。
算法：标准 Poisson 方程，GPU 迭代（Jacobi 或 PCG）。
专为特效优化：压力迭代次数不追求物理精确，5~10 次即可。多出的迭代只会抹平细节，不利于火球/闪电的尖锐感。
配置项：迭代次数，过松弛因子（可选）。
C. Level Set 界面追踪求解器（LevelSetSolver）
职责：输入 Level Set 场（SDF） + 速度场 → 输出平流后的 SDF。
附加功能：包含窄带重初始化（Reinitialization），保持 SDF 距离场的性质（虽然技能特效不严格需要，但后续做“水/火交界”时极其有用）。
4. 管理编排层：FluidSimulation（新建）
这是唯一持有状态的地方。它包含：
velocity（速度场，2 通道）
color（颜色场，4 通道，存 HSL加透明度）
density（密度/能量场，可选，用于火球亮度）
完整帧迭代流程（一个 Tick）：
注入外力（技能触发点）：向 velocity 添加径向爆炸力、旋转力（龙卷风）、上升浮力（火）。
速度平流：调用 AdvectionSolver.forward(velocity, velocity, mask=R/G, dt)。速度自己平流自己。
涡度限制（Vorticity Confinement）：这一步不放在独立求解器，而是作为管理层的后处理函数。计算速度旋度，增强卷曲细节（这是技能特效“锋利感”的灵魂）。
压力投影：调用 PressureSolver.solve(velocity)，强制速度散度为零（模拟不可压流，让流动看起来有“质量感”）。
颜色/残差平流：调用 AdvectionSolver.forward(color, velocity, mask=G/B, dt)。H 固定，S/L 流动。
边界处理（可选）：将边缘速度强制归零，防止能量泄露。
5. 针对“技能特效”的独有优化设计（加分项）
分辨率隔离：速度场可以跑 128x128（省性能），颜色场跑 256x256（精细）。平流时，颜色场采样速度场时自动做纹理坐标缩放。这就解决了性能与质量的矛盾。

2. 平流求解器接口（支持逐通道掩码）
typescript
// 平流配置（每个通道独立开关）
interface AdvectionMask {
  r: boolean;  // true = 参与平流，false = 静止直传
  g: boolean;
  b: boolean;
  a: boolean;
}

class AdvectionSolver {
  // 核心方法：传入掩码，决定哪些通道“流动”，哪些“钉住”
  advect(
    input: THREE.Texture,      // 输入场（RGBA）
    velocity: THREE.Texture,   // 速度场（RG，像素/秒）
    dt: number,
    mask: AdvectionMask        // { r: true, g: false, b: true, a: false }
  ): THREE.Texture;
}
3. GPU 着色器的核心实现（通道混合采样）
这是新架构的灵魂所在。着色器不再是“全通道平流”，而是逐通道选择采样源：

glsl
uniform vec4 uMask; // 对应 r/g/b/a，1.0=流动，0.0=静止

void main() {
    vec2 uv = vUv;
    
    // 1. 反向追踪（如果至少有一个通道需要流动才计算，否则跳过）
    vec2 backUv = uv - (texture2D(uVelocity, uv).rg * uDt / uResolution);
    backUv = clamp(backUv, 0.0, 1.0);
    
    // 2. 采样两个位置的值
    vec4 staticVal = texture2D(uInput, uv);        // 当前像素（静止）
    vec4 flowVal = texture2D(uInput, backUv);      // 回溯像素（流动）
    
    // 3. 按通道混合（掩码选择）
    vec4 output;
    output.r = mix(staticVal.r, flowVal.r, uMask.r);
    output.g = mix(staticVal.g, flowVal.g, uMask.g);
    output.b = mix(staticVal.b, flowVal.b, uMask.b);
    output.a = mix(staticVal.a, flowVal.a, uMask.a);
    
    // 4. 可选：针对色相（H）的特殊环绕保护（如果你把 H 放在 R 通道）
    // 如果 H 流动，插值后做 fmod(output.r, 1.0)
    gl_FragColor = output;
}
注意：mix(static, flow, mask) 在 mask=0 时退化为直传，在 mask=1 时为纯平流。如果你想做“半平流”（如 50% 混合），甚至可以把 mask 设为 0.5，产生拖尾/残影效果——这也是技能特效常用的手法。

1. 核心原则：数据语义与物理通道的强绑定（写入架构文档）
在 FluidSimulation 管理层，定义一个全局语义映射，所有模块（平流、渲染、注入）都必须遵守：

typescript
// 这是你引擎的“宪法”

  r: 'hue',        // 0.0 ~ 1.0 (循环)
  g: 'saturation', // 0.0 ~ 1.0
  b: 'lightness',  // 0.0 ~ 1.0
  a: 'alpha'       // 0.0 ~ 1.0
} as const;
强制规定：

任何地方禁止在平流、外力注入、压力投影阶段对 HSLA 数据进行 RGB 转换。

唯一的转换点（HSLA → RGB）发生在最终渲染（后处理阶段），即你准备显示或编码为 RGB565 的前一刻。

2. 针对“一字节/二字节通道计算”的纹理格式选型
你提到最终要转为 RGB565（5-6-5，共 16 位）。这意味着最终输出时，R/G/B 各通道的精度需求并不一致（G 最高 6 位）。

但在平流计算阶段，我强烈建议你使用 THREE.UnsignedByteType（即 8-bit 归一化整数，范围 0-255）：

格式	每通道字节数	精度	推荐理由
UnsignedByteType	1 字节	8-bit (256 级)	与 RGB565 的 5/6-bit 完美匹配。平流产生的中间值可以直接映射到最终输出，几乎没有二次量化损失。显存带宽仅为 Float32 的 1/4。
HalfFloatType	2 字节	16-bit 浮点	虽然精度高，但你的最终目标是 5-6-5 bit，用 16-bit 浮点平流是“大材小用”，而且带宽翻倍。
FloatType	4 字节	32-bit 浮点	绝对不要用。技能特效不需要物理级精度，纯粹浪费带宽和性能。
结论：你的纹理应该使用 UnsignedByteType（一字节通道）。如果你未来想尝试更高精度（如渐变过渡更平滑），最多升级到 HalfFloatType（二字节通道），但初始版本用 UnsignedByteType 完全足够。

4. 平流 Shader 的“无色相环陷阱”保护（专门针对 H 通道）
由于 H（色相）是环形的（0.0 和 1.0 是同一个颜色），双线性插值在边界处会产生错误（例如 0.9 和 0.1 插值出 0.5，实际应该是 0.0）。你的旧代码曾通过 normalizeHue 处理，但新架构需要将它内置于平流模块。

解决方案：在 AdvectionSolver 中，如果检测到 logicalChannel === 'hue' 且启用了平流，在采样后强制执行：

glsl
// 只对存储 Hue 的通道做环形修正
float hue = texture2D(uInput, backUv).r;
// 如果采样值因双线性插值出现负值或超 1，用 fmod 包裹
hue = fract(hue + 1.0); // 处理 -0.1 → 0.9
// 如果 Hue 通道被禁用平流（直传），则不需要此修正
这个修正只针对 R 通道（H），不影响 S/L/A（它们是线性空间，直接插值即可）。

5. 最终 RGB565 转换层（后处理 Shader）
你的最终渲染（或导出） Shader 应该这样写：

glsl
uniform sampler2D uDynamicField; // HSLA 场 (RGBA_UnsignedByte)
uniform float uGlobalAlpha;      // 如果有固定透明度需求

varying vec2 vUv;

// 辅助：HSLA → RGBA (标准转换)
vec3 hsl_to_rgb(float h, float s, float l) { /* 标准函数 */ }

void main() {
    vec4 hsla = texture2D(uDynamicField, vUv);
    
    // 如果某些通道被禁用（未启用平流），它们的值可能为 0 或默认值，
    // 此时你可以在 CPU 端或 Uniform 中传入备用的 H/S/L/A 值。
    // 但为了正确性，请确保所有 4 个通道都有值（即使未平流，初始也要赋值）。
    
    vec3 rgb = hsl_to_rgb(hsla.r, hsla.g, hsla.b);
    float alpha = hsla.a;
    
    // 输出标准 RGBA（显示器用），或者你可以在 JS 端读取此纹理后打包为 RGB565。
    gl_FragColor = vec4(rgb, alpha);

6. 更新后的完整架构规格（融入 HSLA 语义）
层级	组件	职责	关于 HSLA 的约束
管理层	FluidSimulation	持有 channelConfig，触发重建	将 config.r/g/b/a 映射到 hue/sat/light/alpha 语义
核心层	FluidGrid	分配物理纹理（UnsignedByteType，动态通道数）	不关心数据含义，只负责搬运
求解器层	AdvectionSolver	动态生成 Shader，执行半拉格朗日平流	强制为 H 通道（物理 R）添加 fract 环形保护
后处理层	RenderShader	将 HSLA 转为 RGBA（显示）或打包为 RGB565	唯一进行 HSLA→RGB 转换的地方
注入层	ForceGenerator	向速度场或颜色场添加外力	修改颜色场时，必须以 HSLA 值注入（例如“提高饱和度”= 修改 G 通道）
总结
物理通道 = RGBA，逻辑语义 = HSLA，这是你引擎的最高法则。

使用 UnsignedByteType（一字节/通道），完美匹配 RGB565 的精度，且带宽极低。

动态通道选择依然生效：选 2 通道就是 2 字节/像素，选 4 通道就是 4 字节/像素。

环形保护只针对 H 通道（R 通道），其他通道正常线性插值。

颜色空间转换严格锁定在最终渲染环节，平流管道内保持纯净的 HSLA 数据搬运。

现在你可以放心开工了！这个设计确保了 “数据在物理通道中以 RGBA 形式存储，在逻辑上以 HSLA 被理解，在最终输出时以 RGB565 被交付” 的完美闭环。




1. 致命的隐式约束：速度场的“单位”必须是“像素/秒”（Pixel/s）
这是当前设计最容易出问题的地方。

你的着色器公式：backUv = uv - vel * uDt / uResolution。

推导：vel 必须是以“像素/秒”为单位的物理速度。例如，速度 100px/s，dt=0.016，则单步移动 1.6 像素。

隐患：如果你从 FluidSimulator（旧版）直接拿速度纹理，旧版虽然也除以 resolution，但它的速度场生成（如爆炸）通常输出的是归一化速度（-1~1 或 0~1），乘以一个巨大的系数（如 strength）后勉强算作像素速度。

建议：在 AdvectionSolver 的文档中显式警告，并要求传入速度场前自行确保单位正确。或者，你可以增加一个 velocityScale 的 Uniform，让上层调用者可以自由缩放。

2. 数值耗散（模糊）是被刻意引入的，你无法在 Solver 层面关闭
你的 FluidGrid 使用了 LinearFilter（双线性插值）：

typescript
minFilter: THREE.LinearFilter,
magFilter: THREE.LinearFilter,
半拉格朗日平流 + 双线性插值 = 强数值耗散（画面会快速变模糊）。

这其实是好事：对于技能特效，耗散能消除高频锯齿，让能量涌动看起来更平滑。

代价：细节（如尖锐的闪电、清晰的边界）会被抹平。

解决方案（无需改动代码）：如果你未来需要保留锐利边缘，可以在调用 advect 后，额外调用一个 “锐化（Unsharp Mask）” 或 “涡度限制（Vorticity Confinement）” 后处理来补偿。

/**
 * 生成圆形水坑（默认初始颜色场）
 * @param resolution 纹理尺寸
 * @param center 归一化中心 (0~1)
 * @param radius 归一化半径
 * @param color 颜色 (r,g,b,a) 0~1
 */
export function createCircleField(
  resolution: { w: number; h: number },
  center: { x: number; y: number } = { x: 0.5, y: 0.5 },
  radius: number = 0.2,
  color: [number, number, number, number] = [0.2, 0.5, 0.8, 1.0]
): Float32Array {
  const { w, h } = resolution;
  const data = new Float32Array(w * h * 4);
  for (let y = 0; y < h; y++) {
    for (let x = 0; x < w; x++) {
      const ux = x / w;
      const uy = y / h;
      const dx = ux - center.x;
      const dy = uy - center.y;
      const dist = Math.sqrt(dx*dx + dy*dy);
      const inside = dist < radius ? 1 : 0;
      const idx = (y * w + x) * 4;
      data[idx] = color[0] * inside;
      data[idx+1] = color[1] * inside;
      data[idx+2] = color[2] * inside;
      data[idx+3] = color[3] * inside;
    }
  }
  return data;
}

// src/fluid/editor/FluidEditor.ts
import * as THREE from 'three';
import { FluidGrid, AdvectionSolver, AdvectionMask } from '../core';

export type ViewMode = 'color' | 'velocity' | 'density';

export interface FluidEditorConfig {
  resolution: { w: number; h: number };
  channels: { r: boolean; g: boolean; b: boolean; a: boolean };
  enableAdvection: boolean;
  enablePressure: boolean;   // 预留

  injection: {
    enabled: boolean;
    position: { x: number; y: number }; // 归一化
    radius: number;           // 归一化半径
    rate: number;             // 每帧注入量（0~1）

/**
 * FluidEditor 管理所有场和物理更新。
 * 内部使用 FluidGrid 双缓冲，公开读写纹理。
 */
export class FluidEditor {
  private renderer: THREE.WebGLRenderer;
  private config: FluidEditorConfig;

  // 场
  public colorGrid: FluidGrid;
  public velocityGrid: FluidGrid;
  // 密度场（可选，用于显示）
  public densityGrid?: FluidGrid;

  // 求解器
  private advectionSolver: AdvectionSolver;

  // 纹理数据（用于初始化和注入）
  private colorData: Float32Array;
  private velocityData: Float32Array;

  // 当前时间步
  private time: number = 0;

  constructor(renderer: THREE.WebGLRenderer, config: FluidEditorConfig) {
    this.renderer = renderer;
    this.config = config;

    // 计算实际通道数（根据配置的勾选）
    const colorChannels = this.countChannels(config.channels);
    // 速度场始终是 2 通道 (RG)
    const velocityChannels = 2;

    // 创建网格
    this.colorGrid = new FluidGrid(config.resolution, colorChannels as 1|2|3|4, 'uint8');
    this.velocityGrid = new FluidGrid(config.resolution, velocityChannels as 1|2|3|4, 'uint8');

    // 初始化数据
    const { w, h } = config.resolution;
    this.colorData = new Float32Array(w * h * 4);
    this.velocityData = new Float32Array(w * h * 2);

    // 填充初始数据
    this.initFields();

    // 上传到纹理
    this.uploadColorData();
    this.uploadVelocityData();

    // 创建平流求解器
    this.advectionSolver = new AdvectionSolver(renderer);
  }

  private countChannels(channels: { r: boolean; g: boolean; b: boolean; a: boolean }): number {
    let count = 0;
    if (channels.r) count++;
    if (channels.g) count++;
    if (channels.b) count++;
    if (channels.a) count++;
    return Math.max(1, count); // 至少1个通道
  }

  private initFields() {
    // 默认：中心圆形水
    const { w, h } = this.config.resolution;
    const center = { x: 0.5, y: 0.5 };
    const radius = 0.2;
    const color: [number, number, number, number] = [0.2, 0.5, 0.8, 1.0];

    // 填充颜色数据
    for (let y = 0; y < h; y++) {
      for (let x = 0; x < w; x++) {
        const ux = x / w;
        const uy = y / h;
        const dx = ux - center.x;
        const dy = uy - center.y;
        const dist = Math.sqrt(dx*dx + dy*dy);
        const inside = dist < radius ? 1 : 0;
        const idx = (y * w + x) * 4;
        this.colorData[idx] = color[0] * inside;
        this.colorData[idx+1] = color[1] * inside;
        this.colorData[idx+2] = color[2] * inside;
        this.colorData[idx+3] = color[3] * inside;
      }
    }

    // 速度初始为零
    this.velocityData.fill(0);
  }

  private uploadColorData() {
    // 根据 channels 配置决定上传哪些通道
    const channels = this.config.channels;
    const data = this.colorData;
    const tex = this.colorGrid.write.texture as THREE.DataTexture;
    // 重新创建纹理以匹配通道数（或者使用 setData 更新）
    // 由于 FluidGrid 使用 RenderTarget，我们需要通过像素缓冲区更新
    // 简便方法：使用 canvas 或直接操作 renderTarget 的纹理
    // 这里我们直接更新纹理数据（如果支持）
    // 由于 FluidGrid 内部是 RenderTarget，不能直接 setData，我们使用临时 canvas 或调用 renderFullscreen
    // 但为了简单，我们将数据写入 canvas，然后绘制到 RenderTarget
    const canvas = document.createElement('canvas');
    canvas.width = this.config.resolution.w;
    canvas.height = this.config.resolution.h;
    const ctx = canvas.getContext('2d')!;
    const imageData = ctx.createImageData(canvas.width, canvas.height);
    const dst = imageData.data;
    for (let i = 0; i < data.length; i++) {
      dst[i] = data[i] * 255;
    }
    ctx.putImageData(imageData, 0, 0);
    // 使用 copy 材质绘制到 RenderTarget
    // 复用 AdvectionSolver 的渲染方法？或者创建临时材质
    // 此处简化：直接用 canvas 绘制到纹理（但需要上传到 GPU）
    // 更合理：使用 Three.js 的 Texture 上传
    // 但由于是 RenderTarget，我们使用一个临时纹理
    const tempTex = new THREE.CanvasTexture(canvas);
    // 使用 copy 材质
    const copyMat = new THREE.ShaderMaterial({
      uniforms: { tex: { value: tempTex } },
      vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
      fragmentShader: `uniform sampler2D tex; varying vec2 vUv; void main() { gl_FragColor = texture2D(tex, vUv); }`
    });
    // 获取 renderer 并渲染到 colorGrid.write
    const prevTarget = this.renderer.getRenderTarget();
    this.renderer.setRenderTarget(this.colorGrid.write);
    this.renderer.clear();
    const scene = new THREE.Scene();
    const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), copyMat);
    scene.add(quad);
    const cam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
    this.renderer.render(scene, cam);
    this.renderer.setRenderTarget(prevTarget);
    this.colorGrid.swap(); // 交换，使 read 指向新数据
    // 清理
    tempTex.dispose();
    copyMat.dispose();
    scene.remove(quad);
    quad.geometry.dispose();
  }

  private uploadVelocityData() {
    // 类似，但只需上传 RG 通道
    // 使用 canvas 绘制
    const { w, h } = this.config.resolution;
    const canvas = document.createElement('canvas');
    canvas.width = w;
    canvas.height = h;
    const ctx = canvas.getContext('2d')!;
    const imageData = ctx.createImageData(w, h);
    const dst = imageData.data;
    for (let i = 0; i < this.velocityData.length; i++) {

      dst[i*4+1] = this.velocityData[i*2+1] * 255; // G
      dst[i*4+2] = 0;
      dst[i*4+3] = 255;
    }
    ctx.putImageData(imageData, 0, 0);
    const tempTex = new THREE.CanvasTexture(canvas);
    const copyMat = new THREE.ShaderMaterial({
      uniforms: { tex: { value: tempTex } },
      vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
      fragmentShader: `uniform sampler2D tex; varying vec2 vUv; void main() { gl_FragColor = texture2D(tex, vUv); }`
    });
    const prevTarget = this.renderer.getRenderTarget();
    this.renderer.setRenderTarget(this.velocityGrid.write);
    this.renderer.clear();
    const scene = new THREE.Scene();
    const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), copyMat);
    scene.add(quad);
    const cam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);

  /**
   * 每帧更新
   * @param dt 时间步（秒）
   */
  public step(dt: number) {
    // 0. 应用重力（累加到速度场）
    this.applyGravity(dt);

    // 1. 注入源（每帧添加）
    this.applyInjection(dt);

    // 2. 如果启用平流，平流速度场和颜色场
    if (this.config.enableAdvection) {
      // 速度自平流
      this.advectVelocity(dt);
      // 颜色平流（使用速度场）
      this.advectColor(dt);
    }

    // 3. 压力投影（预留）
    // if (this.config.enablePressure) { ... }

    // 4. Level Set（预留）
    // if (this.config.enableLevelSet) { ... }

    // 5. 边界处理（例如钳制边界速度）
    this.applyBoundary();

    // 更新内部时间
    this.time += dt;
  }

  private applyGravity(dt: number) {
    // 速度场施加重力（向下为负）
    const { w, h } = this.config.resolution;
    const g = this.config.gravity; // 负值
    if (g === 0) return;
    // 读取当前速度场纹理，累加
    // 由于我们是双缓冲，需要读取当前速度，写入另一个
    const velRead = this.velocityGrid.read;
    const velWrite = this.velocityGrid.write;
    // 使用一个全屏材质累加重力
    const gravMat = new THREE.ShaderMaterial({
      uniforms: {
        velTex: { value: velRead },
        gravity: { value: g * dt },
        resolution: { value: new THREE.Vector2(w, h) }
      },
      vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
      fragmentShader: `
        uniform sampler2D velTex;
        uniform float gravity;
        uniform vec2 resolution;
        varying vec2 vUv;
        void main() {
          vec2 vel = texture2D(velTex, vUv).rg;
          vel.y += gravity; // 重力向下（负方向）
          gl_FragColor = vec4(vel, 0.0, 1.0);
        }
      `
    });
    const prevTarget = this.renderer.getRenderTarget();
    this.renderer.setRenderTarget(velWrite);
    this.renderer.clear();
    const scene = new THREE.Scene();
    const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), gravMat);
    scene.add(quad);
    const cam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
    this.renderer.render(scene, cam);
    this.renderer.setRenderTarget(prevTarget);
    this.velocityGrid.swap();
    gravMat.dispose();
    scene.remove(quad);
    quad.geometry.dispose();
  }

  private applyInjection(dt: number) {
    const inj = this.config.injection;
    if (!inj.enabled) return;
    // 在注入位置持续添加颜色和速度
    // 读取当前颜色场和速度场，写入新值（叠加）
    // 为了简化，我们直接修改 CPU 数据然后上传？但这样每帧上传开销大。
    // 更好的办法：使用 GPU 叠加
    // 使用两个全屏材质分别叠加颜色和速度
    // 颜色注入：在圆内将颜色设为注入色，并逐渐混合
    // 速度注入：在圆内将速度设为注入速度
    // 但更真实的是“注入源”应该增加质量，所以颜色应该累加（但会溢出）
    // 我们可以直接设置像素值为注入颜色，但这样会覆盖原有颜色，导致水花不连续。
    // 更好的方式：使用“添加”混合模式，但当前纹理是 uint8，累加会饱和。
    // 我们可以使用浮点纹理，但为了简单，先直接用注入颜色覆盖（适用于恒定注入源）
    // 但用户期望的是持续注入，所以我们应该在注入区域不断添加颜色和速度。
    // 由于我们使用 uint8，累加会饱和，但可以接受（因为饱和后保持最大值）
    // 实现方式：读取当前值，加上注入量，钳制到255
    // 这需要在 GPU 上做，我们使用 Shader 叠加
    // 为了简化，我们每帧用 CPU 更新一小块区域？但会拖慢性能。
    // 权衡：使用 GPU 计算，对于注入区域，读取旧值，加上增量，写入新值。
    // 这里我们采用一个简单的方法：在注入区域，将颜色设为注入颜色，将速度设为注入速度（覆盖）
    // 这样会产生“水龙头”效果，但可能不自然。但为了演示，是可以的。
    // 进阶可以增加混合因子。
    const { w, h } = this.config.resolution;
    const { position, radius, rate, velocity, color } = inj;
    // 使用 Shader 叠加
    const colorMat = new THREE.ShaderMaterial({
      uniforms: {
        colorTex: { value: this.colorGrid.read },
        pos: { value: new THREE.Vector2(position.x, position.y) },
        radius: { value: radius },
        color: { value: new THREE.Vector4(color[0], color[1], color[2], color[3]) },
        rate: { value: rate * dt } // 每帧注入量
      },
      vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
      fragmentShader: `
        uniform sampler2D colorTex;
        uniform vec2 pos;
        uniform float radius;
        uniform vec4 color;
        uniform float rate;
        varying vec2 vUv;
        void main() {
          vec2 uv = vUv;
          float d = distance(uv, pos);
          float mask = smoothstep(radius, 0.0, d); // 内部为1，边缘渐变
          vec4 oldColor = texture2D(colorTex, uv);
          // 混合：将注入颜色与旧颜色混合，注入量由 rate 控制
          // 简单叠加：新颜色 = oldColor + (color - oldColor) * rate * mask
          vec4 newColor = oldColor + (color - oldColor) * rate * mask;
          gl_FragColor = newColor;
        }
      `
    });
    // 渲染到 colorGrid.write
    const prevTarget = this.renderer.getRenderTarget();
    this.renderer.setRenderTarget(this.colorGrid.write);
    this.renderer.clear();
    const scene = new THREE.Scene();
    const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), colorMat);
    scene.add(quad);
    const cam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
    this.renderer.render(scene, cam);
    this.renderer.setRenderTarget(prevTarget);
    this.colorGrid.swap();
    colorMat.dispose();
    scene.remove(quad);
    quad.geometry.dispose();

    // 速度注入类似
    const velMat = new THREE.ShaderMaterial({
      uniforms: {
        velTex: { value: this.velocityGrid.read },
        pos: { value: new THREE.Vector2(position.x, position.y) },
        radius: { value: radius },
        vel: { value: new THREE.Vector2(velocity.x, velocity.y) },
        rate: { value: rate * dt }
      },
      vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
      fragmentShader: `
        uniform sampler2D velTex;
        uniform vec2 pos;
        uniform float radius;
        uniform vec2 vel;
        uniform float rate;
        varying vec2 vUv;
        void main() {
          vec2 uv = vUv;
          float d = distance(uv, pos);
          float mask = smoothstep(radius, 0.0, d);
          vec2 oldVel = texture2D(velTex, uv).rg;
          vec2 newVel = oldVel + (vel - oldVel) * rate * mask;
          gl_FragColor = vec4(newVel, 0.0, 1.0);
        }
      `
    });
    this.renderer.setRenderTarget(this.velocityGrid.write);
    this.renderer.clear();
    const velScene = new THREE.Scene();
    const velQuad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), velMat);
    velScene.add(velQuad);
    this.renderer.render(velScene, cam);
    this.renderer.setRenderTarget(prevTarget);
    this.velocityGrid.swap();
    velMat.dispose();
    velScene.remove(velQuad);
    velQuad.geometry.dispose();
  }

  private advectVelocity(dt: number) {
    // 速度自平流：使用速度场平流自己
    // 注意：速度场是 2 通道，我们需要使用 AdvectionSolver，但 AdvectionSolver 目前只支持 4 通道。
    // 需要扩展 AdvectionSolver 支持通道数，或者我们直接修改为 RG 通道。
    // 为了简单，我们暂时将速度场打包为 RGBA（A 无用）来使用 AdvectionSolver，或者修改 AdvectionSolver 支持通道数。
    // 最快的办法：改造 AdvectionSolver 使其支持任意通道数（1-4），传入通道掩码。
    // 但当前 AdvectionSolver 假设输入是 4 通道，并且掩码作用于 RGBA。
    // 我们可以将速度场放在 RG 通道，在调用 advect 时传入 mask 只对 R 和 G 平流。
    // 但 AdvectionSolver 的构造函数需要 FluidGrid，而 FluidGrid 的通道数是由构造时决定的。
    // 我们可以新建一个 FluidGrid 用于速度场（2 通道），然后调用 AdvectionSolver 时，由于 AdvectionSolver 内部使用 uMask 控制通道，但纹理采样始终是 .rgba，会读取多余通道。
    // 但我们仍然可以用，因为未使用的通道（B/A）不影响结果。
    // 所以可以复用 AdvectionSolver，传入速度网格（2通道）和 mask {r:true, g:true, b:false, a:false}。
    // 但 AdvectionSolver 的 advect 方法签名目前是 (grid: FluidGrid, velocity: THREE.Texture, dt, mask)，其中 velocity 纹理是独立的，不是 grid 的纹理。
    // 所以我们可以将速度网格的 read 纹理作为 velocity，并传入当前速度网格自身作为 grid 进行自平流。
    // 但自平流需要输入和输出同一个 grid，但 AdvectionSolver 内部会进行交换。
    // 我们可以临时创建一个副本？或者直接使用速度网格进行自平流。
    // 更简洁：我们为速度场单独实现平流，或者复用 AdvectionSolver 的逻辑。
    // 鉴于 AdvectionSolver 已经实现了通用的平流，我们只需将速度场作为输入，同时作为速度源。
    // 调用：advectionSolver.advect(velocityGrid, velocityGrid.read, dt, {r:true, g:true, b:false, a:false});
    // 但 AdvectionSolver 内部使用了 uMask，但它的 Shader 会采样 input 纹理和 velocity 纹理，并且 output 写入 grid.write。
    // 这完全可行！
    // 但注意，由于速度场只有 RG 通道，B/A 未定义，但采样时仍然会读取，不过不影响。
    // 所以我们可以这样做。
    const mask: AdvectionMask = { r: true, g: true, b: false, a: false };
    this.advectionSolver.advect(
      this.velocityGrid,
      this.velocityGrid.read,
      dt,
      mask,
      { boundaryMode: 'clamp' } // 边界钳制
    );
  }

  private advectColor(dt: number) {
    const colorChannels = this.config.channels;
    const mask: AdvectionMask = {
      r: colorChannels.r,
      g: colorChannels.g,
      b: colorChannels.b,
      a: colorChannels.a
    };
    // 如果所有通道都是 false，则跳过
    if (!mask.r && !mask.g && !mask.b && !mask.a) return;
    this.advectionSolver.advect(
      this.colorGrid,
      this.velocityGrid.read,
      dt,
      mask,
      { boundaryMode: 'clamp' }
    );
  }

  private applyBoundary() {
    // 简单边界：将边界上的速度设为0，防止溢出
    // 由于是双缓冲，我们读取当前速度，写入新速度，将边界像素置0
    const { w, h } = this.config.resolution;
    const velRead = this.velocityGrid.read;
    const velWrite = this.velocityGrid.write;
    const boundaryMat = new THREE.ShaderMaterial({
      uniforms: {
        velTex: { value: velRead },
        resolution: { value: new THREE.Vector2(w, h) }
      },
      vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
      fragmentShader: `
        uniform sampler2D velTex;
        uniform vec2 resolution;
        varying vec2 vUv;
        void main() {
          vec2 uv = vUv;
          vec2 vel = texture2D(velTex, uv).rg;
          // 检查是否在边界（距离边缘1像素）
          float eps = 1.0 / resolution.x;
          if (uv.x < eps || uv.x > 1.0-eps || uv.y < eps || uv.y > 1.0-eps) {
            vel = vec2(0.0);
          }
          gl_FragColor = vec4(vel, 0.0, 1.0);
        }
      `
    });
    const prevTarget = this.renderer.getRenderTarget();
    this.renderer.setRenderTarget(velWrite);
    this.renderer.clear();
    const scene = new THREE.Scene();
    const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), boundaryMat);
    scene.add(quad);
    const cam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
    this.renderer.render(scene, cam);
    this.renderer.setRenderTarget(prevTarget);
    this.velocityGrid.swap();
    boundaryMat.dispose();
    scene.remove(quad);
    quad.geometry.dispose();
  }

  /**
   * 获取颜色场纹理（用于显示）
   */
  getColorTexture(): THREE.Texture {
    return this.colorGrid.read;
  }

  /**
   * 获取速度场纹理（用于显示，但需要转换 RG 为颜色）
   */
  getVelocityTexture(): THREE.Texture {
    return this.velocityGrid.read;
  }

  /**
   * 更新分辨率（重新创建所有网格）
   * 注意：这会丢失当前模拟状态（但可保留数据）
   */
  setResolution(w: number, h: number) {
    // 重新创建网格，并重新上传当前数据（或重新初始化）
    // 简单起见，重新初始化所有场
    this.config.resolution = { w, h };
    // 重新创建网格
    const colorChannels = this.countChannels(this.config.channels);
    const velocityChannels = 2;
    this.colorGrid = new FluidGrid({ w, h }, colorChannels as 1|2|3|4, 'uint8');
    this.velocityGrid = new FluidGrid({ w, h }, velocityChannels as 1|2|3|4, 'uint8');
    // 重新初始化数据
    this.colorData = new Float32Array(w * h * 4);
    this.velocityData = new Float32Array(w * h * 2);
    this.initFields();
    this.uploadColorData();
    this.uploadVelocityData();
  }

  /**
   * 销毁资源
   */
  dispose() {
    this.colorGrid.dispose();
    this.velocityGrid.dispose();
    this.advectionSolver.dispose();
  }
}

// src/fluid/editor/useFluidEditor.ts
import { useEffect, useRef, useState, useCallback } from 'react';
import * as THREE from 'three';
import { FluidEditor, FluidEditorConfig, ViewMode } from './FluidEditor';

export function useFluidEditor(
  renderer: THREE.WebGLRenderer | null,
  initialConfig?: Partial<FluidEditorConfig>
) {
  const [editor, setEditor] = useState<FluidEditor | null>(null);
  const [viewMode, setViewMode] = useState<ViewMode>('color');
  const animationFrameRef = useRef<number>();
  const lastTimeRef = useRef<number>(performance.now());

  // 配置状态（用于 UI 绑定）
  const [config, setConfig] = useState<FluidEditorConfig>(() => ({
    resolution: { w: 256, h: 256 },
    channels: { r: true, g: true, b: true, a: true },
    enableAdvection: true,
    enablePressure: false,
    enableLevelSet: false,
    gravity: -50, // 像素/秒²
    injection: {
      enabled: true,
      position: { x: 0.5, y: 0.1 },
      radius: 0.05,
      rate: 0.5,
      velocity: { x: 0, y: -100 },
      color: [0.2, 0.5, 0.8, 1.0]
    },
    ...initialConfig
  }));

  // 初始化编辑器
  useEffect(() => {
    if (!renderer) return;
    const ed = new FluidEditor(renderer, config);
    setEditor(ed);
    return () => {
      ed.dispose();
    };
  }, [renderer]); // 只在 renderer 变化时重建

  // 动画循环
  useEffect(() => {
    if (!editor) return;
    const step = (timestamp: number) => {
      const dt = Math.min((timestamp - lastTimeRef.current) / 1000, 0.05);
      lastTimeRef.current = timestamp;
      if (dt > 0) {
        editor.step(dt);
      }
      animationFrameRef.current = requestAnimationFrame(step);
    };
    animationFrameRef.current = requestAnimationFrame(step);
    return () => {
      if (animationFrameRef.current) {
        cancelAnimationFrame(animationFrameRef.current);
      }
    };
  }, [editor]);

  // 更新配置（部分）
  const updateConfig = useCallback((updates: Partial<FluidEditorConfig>) => {
    setConfig(prev => {
      const newConfig = { ...prev, ...updates };
      // 如果分辨率变化，需要通知编辑器重新创建网格
      if (updates.resolution && editor) {
        editor.setResolution(updates.resolution.w, updates.resolution.h);
      }
      // 其他配置的变化可以在下一帧生效（editor.step 中读取最新 config）
      return newConfig;
    });
  }, [editor]);

  // 切换视口模式
  const setView = useCallback((mode: ViewMode) => {
    setViewMode(mode);
  }, []);

  // 获取当前视口纹理（根据模式）
  const getDisplayTexture = useCallback((): THREE.Texture | null => {
    if (!editor) return null;
    switch (viewMode) {
      case 'color': return editor.getColorTexture();
      case 'velocity': return editor.getVelocityTexture();
      default: return null;
    }
  }, [editor, viewMode]);

  return {
    editor,
    config,
    updateConfig,
    viewMode,
    setView,
    getDisplayTexture,
  };
}

function renderTextureToCanvas(texture: THREE.Texture, canvas: HTMLCanvasElement) {
  const renderer = new THREE.WebGLRenderer({ canvas, alpha: true });
  renderer.setSize(canvas.width, canvas.height);
  const scene = new THREE.Scene();
  const cam = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
  const mat = new THREE.ShaderMaterial({
    uniforms: { tex: { value: texture } },
    vertexShader: `varying vec2 vUv; void main() { vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0); }`,
    fragmentShader: `uniform sampler2D tex; varying vec2 vUv; void main() { gl_FragColor = texture2D(tex, vUv); }`
  });
  const quad = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), mat);
  scene.add(quad);
  renderer.render(scene, cam);
  renderer.dispose();
  scene.remove(quad);
  quad.geometry.dispose();
  mat.dispose();
}

注意事项
渲染循环：目前每帧使用 requestAnimationFrame 驱动，并且每次都会重新创建 ShaderMaterial 来渲染纹理到 canvas，这效率较低。但为了简单演示，先这样实现。后续可以优化为复用材质，或者使用 onUpdate 回调。

上传纹理：uploadColorData 和 uploadVelocityData 中使用 canvas 上传，每帧更新时并不需要，只在初始化或分辨率变化时调用。模拟过程中的纹理更新由 GPU Shader 直接操作。

注入源：使用了覆盖式注入，实际效果类似“水龙头”，持续注入新的颜色和速度。如果你想要更自然的注入，可以改为累加方式（但 uint8 会饱和）。

性能：分辨率增大时，GPU 压力上升，确保 max 限制合理。

针对 WebGL / Three.js 环境，性能开销最小且纯 GPU 并行的压力迭代方式，我强烈推荐 红-黑 SOR（Red-Black Successive Over-Relaxation）。它的实现极其精简，仅需 2 个 片元着色器 Pass，且无需任何 CPU 回读。

为什么选红-黑 SOR？
求解器	GPU 并行性	收敛速度	是否需回读	实现复杂度
雅可比迭代	完美（全并行）	非常慢（需几百次）	否	极低
高斯-赛德尔	差（数据依赖）	快	否	低（但 GPU 顺序错乱）
红-黑 SOR	优秀（分两步全并行）	快（SOR 加速）	否	低
多重网格	复杂	极快	否	极高
PCG	一般	快	是（致命伤）	高
红-黑 SOR 通过将网格像素划分为“红”（(x+y)%2 == 0）和“黑”（(x+y)%2 == 1）两个独立集合，使得在更新红点时，所有邻居（上下左右）都是黑点（上一轮的值），不存在数据竞争。这样就能用两次全屏 Pass 完成一次完整迭代，完美适配 GPU 的并行架构。

第二步：实现红-黑 SOR 着色器（核心）
Pass 1：更新红色像素
条件：(x + y) % 2 == 0。公式为：
p_new = (1 - omega) * p_old + omega * ( (p_left + p_right + p_top + p_bottom) - div ) / 4

其中 div 是速度场的散度（div = du/dx + dv/dy），omega 是超松弛因子（1.0 ~ 2.0，典型值 1.7）。

glsl
// 红色像素更新着色器（Red Pass）
uniform sampler2D uPressure;   // 当前压力
uniform sampler2D uVelocity;   // 速度场
uniform vec2 uResolution;
uniform float uOmega;

varying vec2 vUv;

void main() {
    vec2 uv = vUv;
    ivec2 pos = ivec2(uv * uResolution);
    
    // 只处理红色像素
    if ((pos.x + pos.y) % 2 != 0) {
        gl_FragColor = texture2D(uPressure, uv);
        return;
    }

    // 采样邻居（单位像素偏移）
    vec2 left  = texture2D(uPressure, uv + vec2(-1.0/uResolution.x, 0.0)).r;
    vec2 right = texture2D(uPressure, uv + vec2( 1.0/uResolution.x, 0.0)).r;
    vec2 top   = texture2D(uPressure, uv + vec2(0.0, 1.0/uResolution.y)).r;
    vec2 bottom= texture2D(uPressure, uv + vec2(0.0, -1.0/uResolution.y)).r;

    // 计算速度散度（中心差分）
    vec2 vel = texture2D(uVelocity, uv).rg;
    vec2 velR = texture2D(uVelocity, uv + vec2(1.0/uResolution.x, 0.0)).rg;
    vec2 velL = texture2D(uVelocity, uv + vec2(-1.0/uResolution.x, 0.0)).rg;
    vec2 velT = texture2D(uVelocity, uv + vec2(0.0, 1.0/uResolution.y)).rg;
    vec2 velB = texture2D(uVelocity, uv + vec2(0.0, -1.0/uResolution.y)).rg;
    float div = (velR.x - velL.x) / (2.0 * uResolution.x) + (velT.y - velB.y) / (2.0 * uResolution.y);

    float p_old = texture2D(uPressure, uv).r;
    float p_new = (left + right + top + bottom - div) / 4.0;
    p_new = (1.0 - uOmega) * p_old + uOmega * p_new;

    gl_FragColor = vec4(p_new, 0.0, 0.0, 1.0);
}

一、核心思路
压力场只与速度场有关，与颜色场（HSLA）无关。
压力迭代的目的是修正速度场，使其散度为零。因此，压力场始终是单通道标量，不需要按 HSLA 通道分别计算。

“基于 HSL 的 RGB565” 可能是指你希望压力值采用低精度格式存储，以节省显存和带宽。
可以使用 THREE.RedFormat + THREE.HalfFloatType（半精度浮点，2 字节/像素）或 THREE.UnsignedByteType（1 字节，但精度极低，不适合压力求解）。推荐 HalfFloat，精度足够，带宽仅为 Float 的一半。

支持 1~4 通道任意选择 是指颜色场（HSLA）的通道数，与压力场无关。压力场始终单通道，你可以根据 config.channels 开启/关闭颜色平流，但压力解算只依赖于速度场的散度，与颜色通道数无关。

针对十几张纹理（多个独立流体层）：

如果它们共享同一个速度场，则只解一次压力，所有颜色层共用修正后的速度。

如果每层有独立速度场，则需要对每个速度场分别解压力。此时可串行调用 solvePressure，GPU 会流水线化，总开销约等于单层耗时 × 层数，远小于 CPU 回读。

private solvePressure(iterations: number, omega: number): void {
  const { w, h } = this.config.resolution;
  
  // 为红、黑两个 Pass 准备着色器（缓存到 GPUOps）
  for (let iter = 0; iter < iterations; iter++) {
    // Pass 1: 更新红色像素
    this.runSORPass('red', omega);
    // Pass 2: 更新黑色像素
    this.runSORPass('black', omega);
  }
}

private runSORPass(color: 'red' | 'black', omega: number): void {
  const key = `sor_${color}_${omega.toFixed(4)}`;
  const mat = this.gpu.getMaterial(
    key,
    {
      uPressure: { value: this.pressureGrid.read },
      uVelocity: { value: this.velocityGrid.read },
      uResolution: { value: new THREE.Vector2(this.config.resolution.w, this.config.resolution.h) },
      uOmega: { value: omega },
      uColor: { value: color === 'red' ? 0 : 1 } // 用 uniform 控制红/黑
    },
    // 着色器代码（见下文）
  );
  this.gpu.render(this.renderer, this.pressureGrid.write, mat);
  this.pressureGrid.swap();
}
3. 红‑黑 SOR 片段着色器（整合到一个 Pass 中）
glsl
uniform sampler2D uPressure;
uniform sampler2D uVelocity;
uniform vec2 uResolution;
uniform float uOmega;
uniform int uColor; // 0=红色, 1=黑色

varying vec2 vUv;

void main() {
    ivec2 pos = ivec2(vUv * uResolution);
    int isRed = (pos.x + pos.y) & 1; // 1 为红，0 为黑
    int target = 1 - uColor;         // 当 uColor=0 时 target=1（红色），uColor=1 时 target=0（黑色）
    if (isRed != target) {
        gl_FragColor = texture2D(uPressure, vUv);
        return;
    }

    vec2 uv = vUv;
    vec2 texelSize = 1.0 / uResolution;

    // 采样邻居压力
    float pL = texture2D(uPressure, uv + vec2(-texelSize.x, 0.0)).r;
    float pR = texture2D(uPressure, uv + vec2( texelSize.x, 0.0)).r;
    float pT = texture2D(uPressure, uv + vec2(0.0,  texelSize.y)).r;
    float pB = texture2D(uPressure, uv + vec2(0.0, -texelSize.y)).r;

    // 计算散度（中心差分）
    vec2 vC = texture2D(uVelocity, uv).rg;
    vec2 vR = texture2D(uVelocity, uv + vec2( texelSize.x, 0.0)).rg;
    vec2 vL = texture2D(uVelocity, uv + vec2(-texelSize.x, 0.0)).rg;
    vec2 vT = texture2D(uVelocity, uv + vec2(0.0,  texelSize.y)).rg;
    vec2 vB = texture2D(uVelocity, uv + vec2(0.0, -texelSize.y)).rg;

    float div = (vR.x - vL.x) / (2.0 * uResolution.x) + (vT.y - vB.y) / (2.0 * uResolution.y);

    float pOld = texture2D(uPressure, uv).r;
    float pNew = (pL + pR + pT + pB - div) / 4.0;
    pNew = (1.0 - uOmega) * pOld + uOmega * pNew;

    gl_FragColor = vec4(pNew, 0.0, 0.0, 1.0);
}

    {
      uPressure: { value: this.pressureGrid.read },
      uVelocity: { value: this.velocityGrid.read },

     uniform sampler2D uPressure;
     uniform sampler2D uVelocity;
     uniform vec2 uResolution;

       vec2 uv = vUv;
       vec2 texelSize = 1.0 / uResolution;
       float pL = texture2D(uPressure, uv + vec2(-texelSize.x, 0.0)).r;
       float pR = texture2D(uPressure, uv + vec2( texelSize.x, 0.0)).r;
       float pT = texture2D(uPressure, uv + vec2(0.0,  texelSize.y)).r;
       float pB = texture2D(uPressure, uv + vec2(0.0, -texelSize.y)).r;

  this.velocityGrid.swap();
}

三、关于“支持 1~4 通道任意选择”与带宽优化
压力场：始终使用 1 通道，独立于颜色通道数。

颜色场：colorGrid 的通道数由 config.channels 决定（1~4）。

二、三层架构划分
第1层：底层注入函数（三个基础原子操作）
这是整个系统的唯一物理场写入入口。任何对速度场或颜色场的修改，最终都必须归结到这三个函数之一。

散度注入（Divergence Injection）

作用：在指定区域注入正/负散度（源/汇），直接影响压力泊松方程的右端项，驱动流体发散或汇聚。

修改对象：速度场的散度（或等效地，直接修改速度场的径向分量）。

水量/颜色注入（Color/Water Injection）

作用：在指定区域注入颜料（HSLA 值），改变颜色场的局部浓度。

修改对象：颜色场纹理（colorGrid）。

速度注入（Velocity Injection）

作用：在指定区域注入指定方向和大小的速度矢量。

修改对象：速度场纹理（velocityGrid）。

约束：这三个函数是唯一直接操作 FluidGrid（colorGrid / velocityGrid / pressureGrid）底层纹理的地方。任何其他代码不得直接调用 gpu.render 或操作 write 目标。

第2层：操作模块（独立类）
这是一个独立的业务逻辑层，负责构建各种高级流体效果。

职责：提供面向用户的便捷操作函数（如“添加漩涡”、“爆炸”、“定向风”、“重力”、“持续喷射”等）。

约束：这些操作函数只能调用上述三个底层注入函数，绝对不允许直接操作 FluidGrid 或调用 gpu.render。

独立性：该类不持有任何网格引用，仅依赖注入器接口。

第3层：管理层（现有 FluidEditor）
职责：负责时间步进（step）、平流（advect）、压力投影（solvePressure）以及调度操作模块。

变化：移除 applyGravity、applyInjection 等函数中直接操作纹理的代码，改为调用操作模块的对应方法（而操作模块内部调用底层注入函数）。

解耦效果：FluidEditor 不再关心“如何写入”物理场，只关心“何时调用”哪些操作。

  private quadGeom: THREE.PlaneGeometry;
  private materials: Map<string, THREE.ShaderMaterial> = new Map();

  private static readonly VS = /* glsl */ `
    varying vec2 vUv;
    void main() {
      vUv = uv;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
    }
  `;

  constructor() {
    this.scene = new THREE.Scene();
    this.camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);
    this.quadGeom = new THREE.PlaneGeometry(2, 2);
    this.quad = new THREE.Mesh(this.quadGeom);
    this.scene.add(this.quad);
  }

  /**
   * 获取或创建材质（按 key 缓存）。
   * 如果材质已存在则只更新 uniforms，避免重新编译着色器。
   */
  getMaterial(
    key: string,
    uniforms: Record<string, { value: unknown }>,
    fragmentShader: string,
  ): THREE.ShaderMaterial {
    let mat = this.materials.get(key);
    if (mat) {
      for (const [name, u] of Object.entries(uniforms)) {
        if (mat.uniforms[name]) mat.uniforms[name].value = u.value;
      }
      return mat;
    }
    mat = new THREE.ShaderMaterial({
      uniforms,
      vertexShader: GPUOps.VS,
      fragmentShader,
      depthTest: false,
      depthWrite: false,
    });
    this.materials.set(key, mat);
    return mat;
  }

  /**
   * 全屏渲染到 RenderTarget。
   */
  render(
    renderer: THREE.WebGLRenderer,
    target: THREE.WebGLRenderTarget,
    material: THREE.ShaderMaterial,
  ): void {
    const prevMat = this.quad.material;
    this.quad.material = material;

    const prevTarget = renderer.getRenderTarget();
    renderer.setRenderTarget(target);
    renderer.clear();
    renderer.render(this.scene, this.camera);
    renderer.setRenderTarget(prevTarget);

    this.quad.material = prevMat;
  }

  dispose(): void {
    for (const mat of this.materials.values()) mat.dispose();
    this.materials.clear();
    this.quadGeom.dispose();
  }
}

// src/fluid/core/FluidInjector.ts
import * as THREE from 'three';
import { FluidGrid } from './FluidGrid';
import { GPUOps } from './GPUOps';

export interface InjectionOptions {
  position?: { x: number; y: number }; // 归一化 0~1
  radius?: number;                     // 归一化半径
  mask?: THREE.Texture;                // 可选外部掩码纹理（覆盖位置/半径）
  global?: boolean;                    // 如果为 true，则忽略 position/radius，作用于全场
}

/**
 * 底层注入器 —— 唯一直接修改 FluidGrid 的接口。
 * 提供三个原子操作：散度注入、颜色注入、速度注入。
 * 所有注入操作均通过全屏着色器实现，并封装对 write 目标的写入。
 */
export class FluidInjector {
  private renderer: THREE.WebGLRenderer;
  private gpu: GPUOps;

  constructor(renderer: THREE.WebGLRenderer, gpu: GPUOps) {
    this.renderer = renderer;
    this.gpu = gpu;
  }

  /**
   * 散度注入（源/汇）
   * @param grid 速度场网格（将直接修改其 write 目标并 swap）
   * @param divergence 散度值（正为源，负为汇），单位：1/s
   * @param options 注入区域参数
   */
  injectDivergence(
    grid: FluidGrid,
    divergence: number,
    options: InjectionOptions = {},
  ): void {
    const { position = { x: 0.5, y: 0.5 }, radius = 0.1, mask, global = false } = options;
    const key = `divergence_${global ? 'global' : 'local'}`;
    const mat = this.gpu.getMaterial(
      key,
      {
        uVelocity: { value: grid.read },
        uDivergence: { value: divergence },
        uPos: { value: new THREE.Vector2(position.x, position.y) },
        uRadius: { value: radius },
        uGlobal: { value: global ? 1 : 0 },
        uMask: { value: mask || null },
        uResolution: { value: new THREE.Vector2(grid.resolution.w, grid.resolution.h) },
      },
      /* glsl */ `
        uniform sampler2D uVelocity;
        uniform float uDivergence;
        uniform vec2 uPos;
        uniform float uRadius;
        uniform int uGlobal;
        uniform sampler2D uMask;
        uniform vec2 uResolution;
        varying vec2 vUv;

        void main() {
          float maskVal = 1.0;
          if (uGlobal == 0) {
            float d = distance(vUv, uPos);
            maskVal = smoothstep(uRadius, 0.0, d);
            if (uMask != null) maskVal *= texture2D(uMask, vUv).r;
          }
          vec2 vel = texture2D(uVelocity, vUv).rg;
          // 散度注入：沿径向方向修改速度，使得该区域速度向外发散或汇聚
          vec2 dir = vUv - uPos;
          float len = length(dir);
          if (len > 0.0) {
            vec2 radial = dir / len;
            float delta = uDivergence * maskVal / uResolution.x; // 简单扩散
            vel += radial * delta;
          }
          gl_FragColor = vec4(vel, 0.0, 1.0);
        }
      `,
    );
    this.gpu.render(this.renderer, grid.write, mat);
    grid.swap();
  }

  /**
   * 颜色注入（HSLA）
   * @param grid 颜色网格
   * @param color 要注入的颜色（HSLA，各分量 0~1）
   * @param rate 混合速率（0~1），每帧向该颜色靠近的比例
   * @param options 注入区域参数
   */
  injectColor(
    grid: FluidGrid,
    color: { h: number; s: number; l: number; a: number },
    rate: number,
    options: InjectionOptions = {},
  ): void {
    const { position = { x: 0.5, y: 0.5 }, radius = 0.1, mask, global = false } = options;
    const key = `color_${global ? 'global' : 'local'}`;
    const mat = this.gpu.getMaterial(
      key,
      {
        uColor: { value: grid.read },
        uTargetColor: { value: new THREE.Vector4(color.h, color.s, color.l, color.a) },
        uRate: { value: Math.min(1, Math.max(0, rate)) },
        uPos: { value: new THREE.Vector2(position.x, position.y) },
        uRadius: { value: radius },
        uGlobal: { value: global ? 1 : 0 },
        uMask: { value: mask || null },
      },
      /* glsl */ `
        uniform sampler2D uColor;
        uniform vec4 uTargetColor;
        uniform float uRate;
        uniform vec2 uPos;
        uniform float uRadius;
        uniform int uGlobal;
        uniform sampler2D uMask;
        varying vec2 vUv;

        void main() {
          float maskVal = 1.0;
          if (uGlobal == 0) {
            float d = distance(vUv, uPos);
            maskVal = smoothstep(uRadius, 0.0, d);
            if (uMask != null) maskVal *= texture2D(uMask, vUv).r;
          }
          vec4 current = texture2D(uColor, vUv);
          vec4 target = uTargetColor;
          vec4 mixed = mix(current, target, uRate * maskVal);
          gl_FragColor = mixed;
        }
      `,
    );
    this.gpu.render(this.renderer, grid.write, mat);
    grid.swap();
  }

  /**
   * 速度注入
   * @param grid 速度网格
   * @param velocity 速度矢量（像素/秒）
   * @param options 注入区域参数
   */
  injectVelocity(
    grid: FluidGrid,
    velocity: { x: number; y: number },
    options: InjectionOptions = {},
  ): void {
    const { position = { x: 0.5, y: 0.5 }, radius = 0.1, mask, global = false } = options;
    const key = `velocity_${global ? 'global' : 'local'}`;
    const mat = this.gpu.getMaterial(
      key,
      {
        uVelocity: { value: grid.read },
        uVel: { value: new THREE.Vector2(velocity.x, velocity.y) },
        uPos: { value: new THREE.Vector2(position.x, position.y) },
        uRadius: { value: radius },
        uGlobal: { value: global ? 1 : 0 },
        uMask: { value: mask || null },
      },
      /* glsl */ `
        uniform sampler2D uVelocity;
        uniform vec2 uVel;
        uniform vec2 uPos;
        uniform float uRadius;
        uniform int uGlobal;
        uniform sampler2D uMask;
        varying vec2 vUv;

        void main() {
          float maskVal = 1.0;
          if (uGlobal == 0) {
            float d = distance(vUv, uPos);
            maskVal = smoothstep(uRadius, 0.0, d);
            if (uMask != null) maskVal *= texture2D(uMask, vUv).r;
          }
          vec2 current = texture2D(uVelocity, vUv).rg;
          vec2 added = uVel * maskVal;
          gl_FragColor = vec4(current + added, 0.0, 1.0);
        }
      `,
    );
    this.gpu.render(this.renderer, grid.write, mat);
    grid.swap();
  }
}

import { FluidInjector } from '../core/FluidInjector';
import type { FluidGrid } from '../core/FluidGrid';

export interface InjectionConfig {
  enabled: boolean;
  position: { x: number; y: number };
  radius: number;
  rate: number;
  velocity: { x: number; y: number };
  color: [number, number, number, number];
}

/**
 * 操作模块 —— 提供高级流体效果。
 * 所有方法仅调用 FluidInjector 的原子注入函数，不直接操作网格。
 */
export class FluidOperations {
  private injector: FluidInjector;

  constructor(injector: FluidInjector) {
    this.injector = injector;
  }

  /**
   * 施加重力（全局速度注入）
   * @param grid 速度网格
   * @param dt 时间步长
   * @param gravity 重力加速度（像素/秒²，正值向下）
   */
  applyGravity(grid: FluidGrid, dt: number, gravity: number): void {
    if (gravity === 0) return;
    // 注意：用户坐标 Y 向下，纹理坐标 Y 向上，故取反
    this.injector.injectVelocity(grid, { x: 0, y: -gravity * dt }, { global: true });
  }

  /**
   * 连续注入源（颜色 + 速度）
   * @param gridColor 颜色网格
   * @param gridVelocity 速度网格
   * @param dt 时间步长
   * @param config 注入源配置
   */
  applyInjection(
    gridColor: FluidGrid,
    gridVelocity: FluidGrid,
    dt: number,
    config: InjectionConfig,
  ): void {
    if (!config.enabled) return;
    const rate = config.rate * dt;
    const pos = { x: config.position.x, y: 1.0 - config.position.y }; // 翻转 Y
    const vel = { x: config.velocity.x, y: -config.velocity.y }; // 翻转 Y

    // 颜色注入
    this.injector.injectColor(
      gridColor,
      { h: config.color[0], s: config.color[1], l: config.color[2], a: config.color[3] },
      rate,
      { position: pos, radius: config.radius },
    );

    // 速度注入
    this.injector.injectVelocity(
      gridVelocity,
      vel,
      { position: pos, radius: config.radius },
    );
  }

一、视口分层架构（从底层到顶层）
为了分离“静态内容”与“动态流体”，将渲染视口拆分为四个逻辑层：

静态底图层（Layer 0）：存放 FTX 导入后解码得到的 baseTexture（基础色）。该层是静态的，不参与任何更新。

残差流体层（Layer 1）：将 FTX 的 residualTexture（量化后的 H/S/L 通道）作为流体模拟器的初始状态。该层由 GPU 流体解算器驱动，每帧更新（执行平流运算）。

动态合成层（Layer 2）：在 GPU（着色器）中实时混合 Layer 0 和 Layer 1。具体逻辑为：解码 Layer 1 的残差增量，应用到 Layer 0 的基础色 HSL 上（特别处理色相环绕），输出最终的彩色画面。


二、FTX 数据的导入与初始化流程
修改现有的多帧导入逻辑，在解析 FTX 文件后，增加以下初始化动作：

解析与存储：照常解析出 baseTexture、residualTexture、bbox 和调色板。

创建专属流体实例：为每个导入的帧（或图层）创建一个独立的 FluidEditor 实例。将其分辨率设置为与残差纹理匹配（建议直接采用 FTX 的 sourceResolution，或根据 bbox 裁剪以节省性能）。

初始化流体场：将导入得到的 residualTexture 的像素数据（R/G/B 通道）直接灌入 FluidEditor 的颜色场（colorGrid）中，作为流体属性的初始值。

状态管理：在全局 Store 中建立一个新的映射表，将“图层 ID”与“流体编辑器实例”绑定，以便后续每帧调用。

三、动态特效的运行循环（每帧执行）
当用户开启“流体特效层”时，主渲染循环增加以下步骤：

驱动流体模拟：调用当前图层绑定的 FluidEditor.step(dt)，推进残差纹理的平流。残差的三个通道（H/S/L 增量）随着速度场流动，产生动态扭曲效果。

注入速度源（关键交互）：为了产生“技能特效”的动态感，系统需要向流体中注入速度。设计上，速度源可以来自：

用户鼠标拖拽（手动绘制流向）。

预先定义的动画曲线（如爆炸冲击波、旋风路径）。

更新合成纹理：将平流后的最新残差纹理传递给合成层着色器，触发画面刷新。

四、合成层的核心数学逻辑（无代码描述）
合成层只做一件事：将“被平流扭曲后的残差”叠加回“静态基础色”上。处理流程如下：

采样静态底图的像素，转化为 HSL 空间。

采样流体层对应的像素，分别提取 R、G、B 通道。这三个通道并非普通颜色，而是经过量化编码的 H/S/L 残差增量。着色器需内置反量化公式，将其还原为物理增量值（范围通常在 -0.5 到 +0.5 之间）。

进行叠加：

色相（H）：采用环形累加（用取模运算处理超过 0-1 范围的环绕）。

饱和度（S）和明度（L）：采用线性累加并截断（限制在 0 到 1 之间）。

将合成后的新 HSL 转回 RGB 输出显示。

五、用户交互与图层控制（UI 设计）
在现有的侧边栏（LayerControl）中，为特效部分预留操控入口：

特效开关：独立控制残差流体层的显示与隐藏（方便对比原图与特效效果）。

模拟速度/强度：提供滑块实时调整流体平流的步长（时间缩放）或残差的影响力强度。

注入工具：提供一个简易的交互方式（如点击画布），向鼠标位置注入定向的速度场，直观地模拟“技能释放”时产生的气流扰动。

六、针对当前代码架构的微调建议（非代码）
性能裁剪：针对大面积透明或平缓的区域，流体计算可以直接跳过。建议利用 FTX 自带的 bbox，只对边界框内的像素区域建立流体网格，而非全屏计算。

帧间预测适配：如果开启帧间预测，导入后的静态底图是全帧，但流体只需平流残差部分，两者互不干扰，可以并行处理。

导出考量：未来若需导出动态特效视频，只需连续读取合成层每一帧的输出即可，无需保存速度场。

以上即为设计全貌。简单概括就是：静态底图为“骨”，残差流体为“肉”，平流让“肉”动起来，合成着色器将两者重新粘合。这套方案完全基于你现有的 ftxCore、FluidEditor 和 MainCanvas 结构，无需推翻重来。

        data = scaled.data;
        width = w;
        height = h;
    }

    this.uploadToGrid(this.colorGrid, data, 4);

设计目标：双层级颜色正确性验证器
你要解决的是“导入的帧数据颜色完全错了”这个 bug，通过像素级采样，分别验证残差数据和合成逻辑是否正确。

比较层级 1：颜色视口 vs 原始残差纹理（验证“残差数据是否被损坏”）
比较对象 A（左侧/参考）：颜色视口（Color Viewport）

来源：流体模拟器当前颜色场（FluidEditor 的 colorGrid 中的 HSLA 数据）。

含义：残差数据在 GPU 中经过平流/注入/压力等物理模拟后，当前实际呈现的值（如果是静止且无注入，理论上应与导入时一致）。

比较对象 B（右侧/待测）：原始残差纹理（Raw Residual Texture）

来源：导入 FTX 时存储的原始 residualTexture（ImageData），尚未进入流体模拟器。

含义：从基础色编辑器导出时的原始残差编码值（R=ΔH, G=ΔS, B=ΔL 量化值）。

目的：
检查流体解算器是否在未经用户主动操作（注入/平流/压力）的情况下，错误地改变了残差数据（比如纹理上传时格式转换出错，或边界处理导致数据泄露）。

比较层级 2：合成视口 vs 残差 + 基础色（验证“合成公式是否匹配”）
比较对象 A（左侧/待测）：合成视口（Composite Viewport）

来源：流体模拟器当前颜色场（同层级 1 的 A），但此时视图模式切换到“合成”时，GPU 着色器实时计算 基础色 + 解码残差 后的最终 HSL。

含义：用户最终看到的总合成颜色。

比较对象 B（右侧/参考）：残差 + 基础色（理论合成值）

来源：在 CPU（JavaScript）中，从原始 baseTexture 读取基础色 HSL，从原始 residualTexture 读取残差量化值，手动应用与合成着色器完全一致的反量化公式（d = (val * 2 - 1) * range），叠加后计算出的理论 HSL。

含义：合成着色器应该输出的标准答案。

目的：
验证 CPU 端的反量化/合成算法与 GPU 着色器实现是否完全一致（排除浮点精度误差、色相环绕处理不同、范围参数不同等问题）。如果这个层级差值很大，说明合成公式的实现有 bug（比如反量化范围用错，或者色相没有做 fract 环绕）。

修改 1：FluidEditor.ts – 修改 samplePixel 方法
颜色场存储的是 HSLA 值，而 samplePixel 错误地将其转换为 RGB 再转 HSL，导致数据失真。现在直接返回原始 HSLA 值。

文件：src/fluid/editor/FluidEditor.ts

typescript
// 替换原有的 samplePixel 方法
samplePixel(x: number, y: number): {
  residualH: number;   // R 通道 = H 增量 (0~1)
  residualS: number;   // G 通道 = S 增量 (0~1)
  residualL: number;   // B 通道 = L 增量 (0~1)
  alpha: number;
  velX: number;
  velY: number;
} {
  const { w, h } = this.config.resolution;
  const px = Math.max(0, Math.min(w - 1, Math.floor(x)));
  const py = Math.max(0, Math.min(h - 1, Math.floor(y)));

  // 1. 读取颜色像素（RGBA uint8）—— 颜色场就是 HSLA，直接读取
  const colorPixels = this.readColorPixels();
  const idx = (py * w + px) * 4;
  const r = colorPixels[idx] / 255;
  const g = colorPixels[idx + 1] / 255;
  const b = colorPixels[idx + 2] / 255;
  const a = colorPixels[idx + 3] / 255;

  // 2. 读取速度像素
  const velData = new Float32Array(2);
  const target = this.velocityGrid.readTarget;
  const prevTarget = this.renderer.getRenderTarget();
  this.renderer.setRenderTarget(target);
  this.renderer.readRenderTargetPixels(target, px, py, 1, 1, velData);
  this.renderer.setRenderTarget(prevTarget);

  return {
    residualH: r,
    residualS: g,
    residualL: b,
    alpha: a,
    velX: velData[0],
    velY: velData[1],
  };
}

// 辅助：RGB -> HSL
function rgbToHsl(r: number, g: number, b: number): { h: number; s: number; l: number } {
  const max = Math.max(r, g, b);
  const min = Math.min(r, g, b);
  let h = 0, s = 0, l = (max + min) / 2;
  if (max !== min) {
    const d = max - min;
    s = l > 0.5 ? d / (2 - max - min) : d / (max + min);
    if (max === r) h = ((g - b) / d + (g < b ? 6 : 0)) / 6;
    else if (max === g) h = ((b - r) / d + 2) / 6;
    else h = ((r - g) / d + 4) / 6;
  }
  return { h, s, l };
}

// 合成公式（与合成着色器一致）
function computeCompositeHsl(
  baseHsl: { h: number; s: number; l: number },
  residualHsl: { r: number; g: number; b: number }, // 0~1 量化值
  rangeH: number,
  rangeSL: number
): { h: number; s: number; l: number } {
  const dH = (residualHsl.r * 2.0 - 1.0) * rangeH;
  const dS = (residualHsl.g * 2.0 - 1.0) * rangeSL;
  const dL = (residualHsl.b * 2.0 - 1.0) * rangeSL;

  let finalH = baseHsl.h + dH;
  finalH = finalH - Math.floor(finalH); // fract
  const finalS = Math.max(0, Math.min(1, baseHsl.s + dS));
  const finalL = Math.max(0, Math.min(1, baseHsl.l + dL));
  return { h: finalH, s: finalS, l: finalL };
}

一、 当前颜色注入的“致命缺陷”（问题确认）
目前的颜色注入（FluidEditorUI 中的 buildInjectionConfig 和 injectColor）存在本质上的错误：

注入的是“纯色颜料”：无论模式是“水”（青色）还是“颜料”（红色），注入的都是一个单一的、均匀的 HSLA 值（例如 [0.0, 0.8, 1.0, 1.0]）。

无视了“残差纹理”：编辑器辛辛苦苦从 FTX 文件解压出来的、蕴含丰富细节的原始残差纹理（origResidual / stashedResidual），在注入时完全被忽略了。

后果：用户点击注入时，得到的只是一坨颜色呆板、毫无纹理细节的“色块”，而不是“带有复杂噪点和原有图案细节的技能特效”。这违背了“基础色 + 残差平流”的设计初衷。

二、 您的新设计理念：“残差克隆 + 噪点采样注入”
您要彻底重写颜色注入逻辑，将其升级为“基于原始残差纹理的块状采样注入器”。

1. 输入源（数据源）
注入器不再使用硬编码的纯色，而是实时采样当前已加载到内存中的 FTX 原始残差纹理（即您在 FluidEditorUI 中用 stashedResidualRef 保存的那份 ImageData）。

2. 核心操作流程
当用户在画布上点击或拖拽时，系统执行以下逻辑：

定位（Position）：获取鼠标在画布上的归一化坐标 (x, y)。

生成“噪点块状区域”（Noisy Block Region）：

在点击位置周围，生成一个不规则形状的区域，而不是完美的圆形。

“块状”和“噪点”意味着：该区域由多个随机大小、随机位置的小方块（或像素簇）拼凑而成，边缘参差不齐，看起来像破碎的马赛克或噪点云。

这样做是为了打破人工痕迹，让注入的残差与原有的静态残差自然地“融接”，避免出现生硬的圆形边界。

采样（Sampling）：

遍历上述“块状区域”内的所有像素坐标。

将这些坐标映射到原始 FTX 残差纹理（stashedResidual）上，读取该位置对应的 (H, S, L) 增量值（即量化残差）。

注入（Injection）：

将采样得到的这些 (H, S, L) 值，逐像素地写入（或叠加）到动态流体网格（FluidGrid 颜色场）的对应位置。

随后，这些被注入的残差区域将参与到后续的流体平流计算中，像正常的颜料一样开始流动、扩散和扭曲。

3. 增加随机扰动（噪点增强）
在采样和注入之间，您还希望加入随机噪点逻辑：

不是 1:1 原封不动地复制原纹理，而是在采样值的基础上，叠加微小的随机偏移（±delta）。

目的：让注入的纹理既保留了原始 FTX 的独特细节（如法阵纹路、能量条），又因为随机噪点的加入而变得富有生息，不会因为完全复制而显得重复死板。

三、 新设计带来的巨大优势（为什么这么做）
真正的“技能特效”编辑：您不再只是注入颜色，而是在注入“具有特定形态和细节的能量碎片”。

保留原始细节：FTX 中的残差纹理包含了极为丰富的颜色梯度和边缘细节，新注入方式能让这些细节“活”过来，而不是被纯色覆盖。

自然的动态过渡：块状的噪点区域在平流作用下会撕裂、拉伸、融合，产生的视觉效果完全符合自然流体的混沌美，非常适合做爆炸、星云、魔法阵绽放等特效。

重复利用资源：您只需导入一张 FTX 作为“残差图库”，就可以通过反复点击不同的位置，像盖章一样将图库里的细节“拓印”到动态场景中，极大地丰富特效层次。

四、 后续实现的技术路线（仅复述，不生成代码）
UI 交互层：

在 FluidEditorUI 中增加一个新的注入模式（例如“残差印章 / Residual Stamp”）。

鼠标按下时，触发“生成噪点块状区域”算法。

采用“多矩形随机采样”或“Perlin噪声阈值”生成不规则二值掩码。

typescript
// 在 FluidInjector 类中添加
injectColorTexture(
  grid: FluidGrid,
  colorTex: THREE.Texture,
  maskTex: THREE.Texture,
  rate: number,
): void {
  const mat = this.gpu.getMaterial('injectColorTexture', {
    uColor: { value: grid.read },
    uColorTex: { value: colorTex },
    uMaskTex: { value: maskTex },
    uRate: { value: Math.min(1, Math.max(0, rate)) },
  }, /* glsl */ `
    uniform sampler2D uColor;
    uniform sampler2D uColorTex;
    uniform sampler2D uMaskTex;
    uniform float uRate;
    varying vec2 vUv;
    void main() {
      float maskVal = texture2D(uMaskTex, vUv).r;
      vec4 current = texture2D(uColor, vUv);
      vec4 injected = texture2D(uColorTex, vUv);
      vec4 mixed = mix(current, injected, uRate * maskVal);
      gl_FragColor = mixed;
    }
  `);

  this.gpu.render(this.renderer, grid.write, mat);
  grid.swap();
}

  maskCanvas.width = w;
  maskCanvas.height = h;
  const maskCtx = maskCanvas.getContext('2d')!;

private buildMaterial(
  mask: AdvectionMask,
  boundaryMode: 'clamp' | 'repeat' | 'zero',
  wrapHue: boolean,
): THREE.ShaderMaterial {
  // ... vertexShader 保持不变 ...

  // 动态生成片段着色器
  let boundaryFn: string; // ... 保持不变 ...

  // 色相环保护
  const hueWrap = (wrapHue && mask.r)
    ? '  result.r = fract(result.r + 1.0);\n'
    : '';

  const fragmentShader = /* glsl */ `
    uniform sampler2D uInput;
    uniform sampler2D uVelocity;
    uniform float uDt;
    uniform vec2 uResolution;
    uniform vec4 uMask;
    uniform vec4 uDefaultValues; // ★ 新增：关闭通道时的后备默认值

    varying vec2 vUv;

    // ... Catmull-Rom 采样函数不变 ...

    void main() {
      vec2 uv = vUv;

      // 1. 反向追踪
      vec2 vel = texture2D(uVelocity, uv).rg;
      vec2 backUv = uv - vel * uDt / uResolution;

      // 2. 边界处理
      ${boundaryFn}

      // 3. 采样流动值（注意：不再需要静态值了！）
      vec4 flowVal = sampleCatmullRom(uInput, backUv, uResolution);

      // 4. 逐通道混合：mask=0 → 使用默认值，mask=1 → 使用平流值
      vec4 result;
      result.r = mix(uDefaultValues.r, flowVal.r, uMask.r);
      result.g = mix(uDefaultValues.g, flowVal.g, uMask.g);
      result.b = mix(uDefaultValues.b, flowVal.b, uMask.b);
      result.a = mix(uDefaultValues.a, flowVal.a, uMask.a);

      // 5. 色相环保护
      ${hueWrap}
      gl_FragColor = result;
    }
  `;

  // 创建材质时绑定默认值
  return new THREE.ShaderMaterial({
    uniforms: {
      // ... 其他 uniforms ...
      uDefaultValues: { value: new THREE.Vector4(0.0, 0.5, 0.5, 1.0) }, 
      // ★ 默认值：H=0(红), S=0.5, L=0.5, A=1(完全不透明)

  });

第二步：运行时插值逻辑（完整实现）
为了让路径移动逻辑清晰且健壮，我将在 FluidOperations.processContinuousSources 中集成状态管理。以下是核心逻辑：

typescript
// editor/FluidOperations.ts - processContinuousSources 方法片段

public processContinuousSources(
  gridColor: FluidGrid,
  gridVelocity: FluidGrid,
  dt: number,
  gridDensity: FluidGrid | null = null,
  time: number = 0,
): void {
  if (!this.continuousInjectionEnabled) return;
  if (this.continuousSources.length === 0) return;

  for (const src of this.continuousSources) {
    let config = src.config;
    
    // ========== 路径点处理 ==========
    const waypoints = config.waypoints;
    if (waypoints && waypoints.length >= 2) {
      // 获取或创建运行时状态
      let state = this.waypointStates.get(src.id);
      if (!state) {
        // 初始：逻辑步进为 0，进度为 0
        state = { logicalStep: 0, progress: 0 };
        this.waypointStates.set(src.id, state);
      }

      const mode = config.waypointMode || 'forward';
      const speed = config.waypointSpeed || 1.0;
      const total = waypoints.length;

      // 更新进度
      state.progress += dt * speed;

      // 如果进度达到 1.0，前进一个逻辑步进
      while (state.progress >= 1.0) {
        state.progress -= 1.0;
        state.logicalStep++;
      }

      // 根据模式计算当前实际索引和下一索引
      let idx0: number, idx1: number;
      const getIndices = (step: number): { idx0: number; idx1: number; t: number } => {
        let p0: number, p1: number;
        if (mode === 'forward') {
          p0 = step % total;
          p1 = (step + 1) % total;
        } else if (mode === 'backward') {
          // 反向：逻辑步进对应物理索引为 (total - 1 - (step % total) + total) % total
          // 但更简单：我们将逻辑步进映射到反向序列
          const cycle = total * 2 - 2;
          const pos = step % cycle;
          if (pos < total) {
            p0 = pos;
            p1 = (pos + 1) % total;
          } else {
            const rev = cycle - pos;
            p0 = rev;
            p1 = (rev - 1 + total) % total;
          }
        } else { // pingpong
          const cycle = total * 2 - 2;
          const pos = step % cycle;
          if (pos < total) {
            p0 = pos;
            p1 = (pos + 1) % total;
          } else {
            const rev = cycle - pos;
            p0 = rev;
            p1 = (rev - 1 + total) % total;
          }
        }
        return { idx0: p0, idx1: p1, t: state.progress };
      };

      const { idx0, idx1, t } = getIndices(state.logicalStep);
      const p0 = waypoints[idx0];
      const p1 = waypoints[idx1];

      // ★ 关键：覆盖 position 为插值结果
      const interpolatedPos = {
        x: p0.x + (p1.x - p0.x) * t,
        y: p0.y + (p1.y - p0.y) * t,
      };

      // 创建 config 副本，用插值位置覆盖静态 position
      config = { ...config, position: interpolatedPos };
    }

    // ========== 波形控制（与路径点叠加） ==========
    // 注意：波形是在速度方向上做摆动，不影响位置。如果路径点启用，位置已经固定，波形只影响速度方向。
    // 如果用户想路径点 + 波形，可以叠加。
    if (config.wave?.enabled) {
      // ... 原有波形逻辑
    }

    // 执行注入
    this.applyInjection(gridColor, gridVelocity, dt, config, gridDensity);
  }
}

四、核心解算器实现（参考 FluidPlayer 重写）
1. 解算器类结构
新建 src/fluid/FluidSolver.ts，其构造函数接收：

renderer: THREE.WebGLRenderer（主画布的渲染器）

config: FluidConfig

resolution: { w: number; h: number }（从 frameData.sourceResolution 获取）

内部持有：

gpu: GPUOps（复用独立播放器的 GPUOps 类）

injector: FluidInjector（使用同一个 gpu 实例）

colorGrid, velocityGrid, pressureGrid, densityGrid（FluidGrid 实例，分辨率由参数决定）

obstacleTex: THREE.Texture | null（墙体纹理，从区域实体生成）

baseHslTex: THREE.DataTexture | null（基础色纹理，用于合成视图）

时间、帧计数、注入源队列等。

2. 主要方法
loadResidual(residualImageData: ImageData)
将量化残差 ImageData 上传到 colorGrid（使用 uploadToColorGrid 方法，参考播放器实现，内部用 GPUOps 的 copy pass）。

setBaseHslTexture(baseHslData: Float32Array, width: number, height: number)
创建或更新 baseHslTex，用于合成视图。

updateConfig(newConfig: Partial<FluidConfig>)
合并配置，并同步到内部状态（如分辨率变化需重建网格）。

step(dt: number)
执行单帧模拟：重力 → 持续注入 → 速度自平流 → 颜色/密度平流 → 边界 → 压力投影 → 速度缩放/限幅 → 手动注入。

render(viewMode: ViewMode, target?: THREE.WebGLRenderTarget)
根据当前视图模式选择对应的着色器场景，使用 renderer.render() 输出到屏幕或指定目标（默认渲染到屏幕，覆盖主画布内容）。

reset()
清空速度场、压力场、密度场，重新加载残差纹理到颜色场。

addContinuousSource(config: InjectionConfig) / removeContinuousSource(id)
管理持续注入源列表。

queueInjection(config: InjectionConfig)
将一次性注入加入队列，在下一帧 step 中执行。

dispose()
释放所有 FluidGrid 和纹理资源。

3. 与播放器的差异
不再包含 canvas 尺寸自适应逻辑，因为渲染器尺寸由主画布控制。

移除 resizeCanvas 方法，由主画布统一管理。

移除 UI 相关的 renderSourceList 等方法。

移除 _previewResidualTex 等预览相关，因为基础色和残差都已由主画布预解码。

适配主画布的坐标系（Y 轴向下），确保注入位置和速度方向正确。

五、渲染集成（复用主画布 WebGL 渲染器）
主画布（MainCanvas）中已有一个 Three.js WebGLRenderer 用于区域色块图层的模板缓冲渲染。我们可直接复用该渲染器，在流体模式下接管其渲染内容。

1. 创建解算器实例
在 MainCanvas 组件中，添加一个 useEffect 监听 activeLayerId 和 frameDataMap[activeLayerId] 的变化，当存在残差纹理且未创建解算器时，实例化 FluidSolver：

tsx
const fluidSolverRef = useRef<FluidSolver | null>(null);
useEffect(() => {
  const frameData = frameDataMap[activeLayerId];
  if (!frameData?.residualTexture || !frameData?.fluidConfig) {
    fluidSolverRef.current?.dispose();
    fluidSolverRef.current = null;
    return;
  }
  if (!fluidSolverRef.current) {
    const config = { ...defaultFluidConfig, ...frameData.fluidConfig };
    fluidSolverRef.current = new FluidSolver(webglRenderer, config, {
      w: frameData.sourceResolution || 512,
      h: frameData.sourceResolution || 512,
    });
    fluidSolverRef.current.loadResidual(frameData.residualTexture);
    if (frameData.baseHslData) {
      fluidSolverRef.current.setBaseHslTexture(
        frameData.baseHslData.data,
        frameData.baseHslData.width,
        frameData.baseHslData.height
      );
    }
  }
  return () => fluidSolverRef.current?.dispose();
}, [activeLayerId, frameDataMap]);
2. 驱动模拟与渲染
在主画布的动画循环中（已有 requestAnimationFrame），检查 fluidSolverRef.current 是否存在且 fluidRuntime.isPlaying 为 true，则调用 step(dt)，然后调用 render(viewMode) 将结果渲染到屏幕。

tsx
// 在动画循环函数中
if (fluidSolverRef.current && fluidRuntime?.isPlaying) {
  const dt = Math.min(0.033, deltaTime) * (fluidRuntime.speed || 1);
  fluidSolverRef.current.step(dt);
  fluidSolverRef.current.render(fluidRuntime.viewMode || 'color');
}
3. 叠加方式
完全接管模式：当流体视图启用时，先清除主画布 2D Canvas 的内容（或将其透明），然后让 WebGL 渲染器直接覆盖整个画布。

混合模式：流体渲染结果作为半透明层叠加在 2D Canvas 之上（需要设置 renderer.setClearColor(0x000000, 0) 且 alpha: true），但这样会带来混合复杂度和性能开销，建议直接接管。

重力 X/Y 滑块或数值输入。

列表显示当前 fluidConfig.continuousSources。

手动注入：在画布上点击时，触发 queueInjection（需在主画布鼠标事件中判断是否处于流体注入模式）。

七、障碍物（墙体）支持
主画布已有 regionEntities 提供精确的区域边界。在启用墙体时，我们可调用 fluidSolverRef.current.enableObstacles()，然后遍历当前图层的区域实体，将其 boundary 光栅化为 obstacleTarget 纹理（1 通道 Uint8），再传给 FluidSolver 内部。

复用 processMaskRingCPU 或 rasterizeRegionMask 生成墙体纹理。

墙体更新时机：当区域实体变化或墙体开关变化时重新生成。

八、纹理复用细节
残差纹理：直接使用 frameData.residualTexture（ImageData），调用 loadResidual 内部会创建 DataTexture 并上传到 colorGrid。

基础色纹理：使用 frameData.baseHslData（Float32Array）创建 DataTexture，用于合成视图。该纹理只需创建一次，更新时重新上传数据。

速度/压力/密度场：均为 FluidGrid 内部 RenderTarget，无法复用，但显存占用可控（512×512×4 通道约 1MB）。

九、生命周期与错误处理
当切换图层或关闭流体功能时，务必调用 dispose() 释放所有 GPU 资源。

若 frameData.residualTexture 不存在，解算器无法初始化，需给出提示。

分辨率变更时（如切换帧），重建网格并重新加载残差。
