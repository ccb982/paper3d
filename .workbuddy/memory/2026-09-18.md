## 水里持续游动音效降速（用户「降低在水里持续游动的音频播放速度」）

根因不是"触发太频繁"，是**素材时长 vs 节流间隔倒挂**：
`涉水.mp3` = **0.73s**，而 `playSfx('waterWade', 330)` 间隔 330ms → 每 0.33s 起一个新实例，
上层还没播完就叠下一个（≈2.2 层重叠）→ 听着像急促的连续噪声。
（`入水.mp3` = 1.54s / 节流 400ms，同样倒挂，但用户没提，未动。）

改动（4 处，tsc EXIT=0）：
1. `platform/PlatformAdapter.ts`：`playSfx(src, rate?)`
2. `platform/WebAdapter.ts`：`new Audio` 后 `a.playbackRate = rate`（**必须在 play() 之前设**）
3. `services/audio/Sfx.ts`：`playSfx(id, minGapMs, rate?)` → 透传
4. `WorldMode.updateWaterEntry`：`playSfx('waterWade', 700, 0.75)`
   —— 慢放 0.75（时长 0.73→0.97s，音调降） + 间隔 330→700ms。
   ★ 只改了音效节流，**没动水面泛波的 gap**（340 - speed*28），视觉波纹节奏不变。

### 后续（同一轮）：用户要「慢放但**连续**，慢放比例可随机」→ 改循环轨

点播再怎么拉间隔都是一段一段的，游动是持续状态 → 改成**循环轨**：

1. **素材**：ffmpeg 加工 `public/sfx/涉水_loop.mp3`（0.63s，5.2KB，64k 单声道）：
   主体 `atrim 0:0.59` + 尾 `atrim 0.59:0.73,afade=t=out:d=0.14` → `amix=normalize=0` 叠回开头
   （0.73s 原素材直接 loop 会有接缝咔哒）。
2. `config/sfx.ts`：`LOOP_SFX` 加 `waterSwim`；**删掉**一次性 `SFX.waterWade`（不再点播，免留死配置）。
3. `WebAdapter`：**loopTrack 单槽 → `loopTracks: Map<src, LoopTrack>`**，多条循环轨可同时响
   （引擎 + 涉水互不顶掉）；`playLoopSfx(src, {rate?, volume?})`，`stopLoopSfx(src?)`（不传 = 全停）。
   ★ `playbackRate` 必须在 `play()` 之前设；已在册的轨换 rate 直接改属性（不改循环性、不重头播）。
4. `WorldMode.updateWadeLoop(dt)`（每帧裁决，`updateWaterEntry` 之后调用）：
   在水里 + 位移速度 > 0.3 → 起轨；停 / 出水 / 非 explore / 死亡 → `stopWadeLoop()`。
   ★ **随机慢放**：起轨时 `0.70 + random()*0.15`，**同一条轨内固定**（每次入水变一次，不逐帧抖）；音量 0.35。
   停止点：`enterShipInterior()`（interior 时 update 直接 return）、`dispose()`。
5. 水面泛波视觉节奏不变；入水瞬间的 `waterEnter` 一次性音保留。

### 再后续：用户反馈「水里持续游动声音不明显」→ 选段错了 + 音量给低了

排查用数据，不靠猜（脚本跑完已删）：

| 素材 | I (LUFS) | peak | 40ms 窗平均 RMS | 判读 |
|---|---|---|---|---|
| 涉水.mp3 | -16.5 | -2.3 | ≈-22 | 一声"哗"的瞬态，crest 15dB |
| 涉水_loop 旧版 | -18.2 | -1.2 | **-22.0** | 循环后更轻、听着"一下一下" |
| 入水.mp3 | -16.0 | +3.1 | 前 0.4s 冲击(-6dB) + **0.45~1.25s 平坦持续段(-20~-24)** | ★ 尾段才是"人在水里"的声音 |
| 涉水_loop 新版 | -18.8 | -2.4 | **-19.8，起伏 6.5dB** | 用入水尾段重做 |

两个真因：
1. **选段错**：持续声要选**平坦段**（起伏小），不能用瞬态素材（`涉水.mp3`）去 loop —— 后者 crest 15dB，平均能量低，循环起来就是"一下一下"。
   重做：`atrim 0.45:1.25`（入水尾段）+ 尾 0.16s 淡出 `amix` 叠回 → 归一 -1.5dBFS。
2. **音量给低**：一次性音效 `new Audio()` 的 volume 默认 **1.0**，循环轨我给了 0.35 → 比脚步声
   （`stepGrass` I=-22.9 @1.0）还轻 5dB。→ 改 **0.65**（等效 ≈ -22.9，与脚步持平）。
   慢放范围 0.70~0.85 → **0.80~0.92**（<0.8 明显发闷，反而更听不清）。

踩坑：
- **这版 ffmpeg 的 `acompressor` 对短素材提不了响度**：threshold=0.08/ratio=14 把整体压掉
  （I 反而 -19.5→-28.7）；改 threshold=0.35/ratio=6 只换来 +1.3dB。
  **peak 已经贴顶（≈-1.2dBFS）时，压缩不是解药 —— 要么换选段，要么调播放音量。**
- 判断"循环素材像不像持续声"看**40ms 窗 RMS 包络的起伏**（新版 6.5dB ✓），
  单看 LUFS/peak 看不出来（旧版 LUFS 甚至更高）。

### ★★ 真 bug：循环轨淡入被每帧打断 →「在水里移动几乎没声」

用户反馈「几乎没声，不如最一开始的（点播版），但那个不连续」。查代码而不是继续调素材，找到：

- `updateWadeLoop` **每帧**调 `playLoopSfx`；`playLoopSfx` 在册分支里无条件 `fadeTo(vol)`；
- `fadeTo` 会先 `clearInterval` 上一个计时器、再从**当前音量**重新起一段 **BGM_FADE_MS=700ms** 淡入；
- 结果：淡入每帧被重置，音量按指数逼近，约 **1.5~2s** 才到目标 → 游一下就出水 = 等于没声。
  （引擎轨只在 phase 变化时调用，所以这个 bug 从来没暴露。）

修法（`WebAdapter`）：
1. `LoopTrack` 加 `target` 字段 → **只有目标音量真的变了才重新 fade**（每帧调用不再打断）。
2. `fadeTo` 加可选 `ms` 参数（默认仍 BGM_FADE_MS）→ 循环轨用 **`LOOP_FADE_MS = 220`**
   （循环轨跟的是秒级动作，700ms 淡入来不及）。
3. 起轨时 `target` 一并记录；`stopLoopSfx`（单轨 + 全停）也走 220ms。
   ★ 回归检查：play() 被自动播放拦截时 `el.paused` 仍为 true → 下一帧走 paused 分支重试，不会卡死在 0。

### 素材比例也反了 → 动作层改主层

第一版「河流主 + 划水压 6dB 次」太平坦没冲击。重做：
`Sea swimming loop`(1181) **6.0~7.5s 主层**(0dB，首尾都在响区) + `River water flowing`(2454)
20~21.5s **压 6dB 垫底**（填浪间隙的静音谷）→ amix → 主体 1.25s + 尾 0.25s 淡出叠回 → 归一 -1.5dBFS。

**成品**：1.28s / 10KB，I=**-16.5 LUFS**（与最初点播的 涉水.mp3 持平，比中间那版 -17.3 好），
40ms 窗平均 RMS **-17.9dB**、最大 **-14.1dB**（有冲击）、起伏 7.7dB、无静音谷。
播放音量 0.65 → **0.85**（等效 ≈ -17.9 LUFS，比脚步 -22.9 明显一档）。

**教训**：做"持续声"循环时，连续层只负责填空隙，**冲击/动作层必须是主层** ——
否则得到一段平坦底噪，在数据上达标（LUFS/RMS 都不差）但人耳完全注意不到。
