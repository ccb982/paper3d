## 水里持续游动音效降速（用户「降低在水里持续游动的音频播放速度」）

根因不是"触发太频繁"，是**素材时长 vs 节流间隔倒挂**：
`涉水.mp3` = **0.73s**，而 `playSfx('waterWade', 330)` 间隔 330ms → 每 0.33s 起一个新实例，
上层还没播完就叠下一个（≈2.2 层重叠）→ 听着像急促的连续噪声。
（`入水.mp3` = 1.54s / 节流 400ms，同样倒挂，但用户没提，未动。）

改动（4 处，tsc EXIT=0）：
1. `platform/PlatformAdapter.ts`：`playSfx(src, rate?)`
2. `platform/WebAdapter.ts`：`new Audio` 后 `a.playbackRate = rate`（**必须在 play() 之前设**）
3. `services/audio/Sfx.ts`：`playSfx(id, minGapMs, rate?)` → 透传
4. `WorldMode.updateWaterEntry`：`playSfx('waterWade', 700, 0.75)`
   —— 慢放 0.75（时长 0.73→0.97s，音调降） + 间隔 330→700ms。
   ★ 只改了音效节流，**没动水面泛波的 gap**（340 - speed*28），视觉波纹节奏不变。

2. **音量给低**：一次性音效 `new Audio()` 的 volume 默认 **1.0**，循环轨我给了 0.35 → 比脚步声

   慢放范围 0.70~0.85 → **0.80~0.92**（<0.8 明显发闷，反而更听不清）。

踩坑：
- **这版 ffmpeg 的 `acompressor` 对短素材提不了响度**：threshold=0.08/ratio=14 把整体压掉
  （I 反而 -19.5→-28.7）；改 threshold=0.35/ratio=6 只换来 +1.3dB。
  **peak 已经贴顶（≈-1.2dBFS）时，压缩不是解药 —— 要么换选段，要么调播放音量。**
- 判断"循环素材像不像持续声"看**40ms 窗 RMS 包络的起伏**（新版 6.5dB ✓），
  单看 LUFS/peak 看不出来（旧版 LUFS 甚至更高）。

### ★★ 真 bug：循环轨淡入被每帧打断 →「在水里移动几乎没声」

用户反馈「几乎没声，不如最一开始的（点播版），但那个不连续」。查代码而不是继续调素材，找到：

- `updateWadeLoop` **每帧**调 `playLoopSfx`；`playLoopSfx` 在册分支里无条件 `fadeTo(vol)`；
- `fadeTo` 会先 `clearInterval` 上一个计时器、再从**当前音量**重新起一段 **BGM_FADE_MS=700ms** 淡入；
- 结果：淡入每帧被重置，音量按指数逼近，约 **1.5~2s** 才到目标 → 游一下就出水 = 等于没声。
  （引擎轨只在 phase 变化时调用，所以这个 bug 从来没暴露。）

修法（`WebAdapter`）：
1. `LoopTrack` 加 `target` 字段 → **只有目标音量真的变了才重新 fade**（每帧调用不再打断）。
2. `fadeTo` 加可选 `ms` 参数（默认仍 BGM_FADE_MS）→ 循环轨用 **`LOOP_FADE_MS = 220`**
   （循环轨跟的是秒级动作，700ms 淡入来不及）。
3. 起轨时 `target` 一并记录；`stopLoopSfx`（单轨 + 全停）也走 220ms。
   ★ 回归检查：play() 被自动播放拦截时 `el.paused` 仍为 true → 下一帧走 paused 分支重试，不会卡死在 0。

### 素材比例也反了 → 动作层改主层

第一版「河流主 + 划水压 6dB 次」太平坦没冲击。重做：
`Sea swimming loop`(1181) **6.0~7.5s 主层**(0dB，首尾都在响区) + `River water flowing`(2454)
20~21.5s **压 6dB 垫底**（填浪间隙的静音谷）→ amix → 主体 1.25s + 尾 0.25s 淡出叠回 → 归一 -1.5dBFS。

**教训**：做"持续声"循环时，连续层只负责填空隙，**冲击/动作层必须是主层** ——
否则得到一段平坦底噪，在数据上达标（LUFS/RMS 都不差）但人耳完全注意不到。

### 一、两级火力（§16.4 / §22.2 / §22.9）

| 档 | 形态 | 特点 |
|---|---|---|
| **普通远程兵** | **机动单位** `ranged`（F5） | 弱、能动、可被冲脸 |
| **高危火力点** | **固定工事** | 高 HP / 高 DPS / 覆盖广，正面几乎打不到 |

★ 这两档必须分清，别混（一个进 SoA 当代理跑，一个是静态结构）。

### 二、★★ 高危火力点藏在工事之后 = 纵深两层（§22.9，本轮的"恶心"核心）

```
玩家火力 ──► [ 外层：工事线（可拆、吃伤害、挡视线） ] ──► [ 内层：高位火力点（高危） ]
```

- 外层工事**替火力点吃伤害 + 遮视线**；火力点躲后面俯射缺口与接近路。
- **LOS 规则** `FP_LOS_BLOCK`：被外层遮挡时正面伤害大幅衰减/不命中；工事拆出缺口 → 暴露。
- ★★ **反制红线（必须有解）**：①侧面/绕后（LOS 断开方向）②范围/间接火力 ③先拆外层
  ④**绝不允许"看不见、打不到、还一直在输出"的死角**。→ 铁律 19。
- ★ **与 §23 咬合**：高位火力点是**正面主力啃不动的点**，正好由**偷袭分队从背向端掉** ——
  "正面 + 绕后"组合拳存在的意义就在这里（§23.6 表格已加一行）。

### 三、陷阱（§24）

- ★ **定性**：工事是"挡住你"，陷阱是"等你来踩"。陷阱**不是障碍**（不改通行代价），
  是**触发式的一次性危害**。
- 种类（第一版三种）：**诡雷/地雷**（踩踏伤害）、**绊线/拉发**（警报 + 呼叫就近编队）、
  **陷坑/减速带**（把玩家钉在火力区）。后续可加诱饵（假补给/假遗物）。
- ★★ **工事缺口就是最好的陷阱位**：玩家被 §22.3 的两阵营掩码逼着从"门"过，门里埋雷 =
  纵深布防最后一环（§22 那张图的"门"从此有两重含义）。
- ★ **己方无害** `passFaction`：敌人自己踩不响（沿用 §22.3 掩码思路，否则 AI 自锁，铁律 13 的教训）。
- ★ **可见性红线**（同铁律 17）：不显形但**必须有线索** —— 地面异常纹理 / 微弱提示音 /
  **敌人自己不走的"绕开轨迹"**（这条最优雅：AI 行为本身即提示）；可侦察显形；
  可**用范围攻击提前引爆**、可载具/召唤物趟雷。
- ★★ **与工事相反：陷阱不参与 HPA\*** —— 它是 trigger 不是障碍，**不进代价模型、不标脏 cluster**
  （铁律 22 专门记这条，防以后混）。
- 上限 `MAX_TRAPS_PER_BN`、`TRAP_ARM_TIME`（待发前可安全拆除）、随波次清理、不入存档。

### 新增参数（§19）

`MAX_TRAPS_PER_BN` 6 / `TRAP_ARM_TIME` 4s / `TRAP_REVEAL_R` 8m

### 新增铁律（§25 的 19~22）

19. 高危火力点必须有解（侧面/绕后·间接火力·拆外层）—— 不许"看不见又打不到"的死角
20. 陷阱必须可察觉/可侦察（不许纯隐形踩雷）
21. 陷阱对己方无害（`passFaction`，绝不自触）
22. 陷阱不参与寻路代价（是 trigger 不是障碍；**不得**标脏 cluster —— 与工事相反）

## 蜂群 v2 追加：飞行兵种（只做轰炸，不缠斗）

用户原话：「然后还要有飞行兵种，但是我就不指望飞行兵种持续攻击了，怪恶心的，
就只起个轰炸作用即可。」

落地：`全新的游戏/蜂群架构.md` 1225 → **1316 行**。新增 **§25 飞行兵种**，
铁律顺延为 **§26**（新增 23~26 条）；同步改 §13.1 / §15.3 / §16.2 / §16.4 / §18(F10) /
§19 / §20 / §23.6 / 目录。

### 核心设计（§25）

- ★★ **这是一次用户主动要的"减法"**：持续空中攻击"怪恶心" → **只保留轰炸**这一个作用。
  行为铁律：**不追击、不缠斗、不持续开火**。
- **出击循环（sortie）**：待机 → 进场（预定航线）→ **投弹（一次）** → 撤离（投完就走）→
  冷却 `FLYER_SORTIE_COOLDOWN` 12~20s → 回待机。
  ★ 同时在场上限 `MAX_AIR_SQUADS = 1`（别搞成"满天空都是"）。
- ★★ **导航：不参与地面寻路**。飞在天上 → 无视坑/深水/陡崖/通行宽度/**工事**/**陷阱**。
  → **不要**塞进 §15 的地面 corridor，走**独立空中层**（直线 + 避障，绕开高于飞行高度的东西即可），
  也不进 §14 的车道/阵型。
  ★ AgentPool SoA 新增 `isAir`(Uint8) / `altitude`(Float32) 两列（§16.2）。
- **投弹 = 唯一攻击方式**：落点由大编队指定区域（玩家/舰船/正面要突破的点）。
  ★★ **落点指示 + 延迟引信 `BOMB_FUSE_TIME` 1.5s** → 玩家有反应窗口
  （"轰炸"套路的标准公平性设计，同铁律 17/20 的可察觉红线）。
  ★ 投弹航段是飞行兵**最脆弱**的时候（可被击落）。
- ★ **与 §22/§25 咬合的关键平衡**：飞行兵飞越工事、不踩陷阱、无视地形 → 很容易变成"万能解"。
  → 建议让**高危火力点兼有对空能力**（一个工事两种威胁），形成防空威慑。
- ★ 与 §23 呼应：总攻时**轰炸正面吸引注意力 + 偷袭绕后**是天然组合。

### 新增铁律（§26 的 23~26）

23. 飞行兵不参与地面导航（不进 corridor/车道/工事代价/陷阱触发）—— 独立空中层

25. 轰炸必须有落点预警 + 可躲的反应窗口
26. 防空威慑必须存在 —— 否则飞行兵成了无视地形/工事/陷阱的万能解
