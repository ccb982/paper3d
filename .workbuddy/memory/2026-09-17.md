## 激光音「小到几乎听不见」= 自己的 ffmpeg filter 写错（已修）

- 用户反馈听不见后重测：素材本身 RMS 0.16（比击地 0.038 高 4 倍），**素材没问题**。
- 真凶 = 加工链里的 `afade=t=out:st=0:d=0.02`（本意"去掉起始爆音"）。
  **fade-OUT 从 st 起淡到 0 后会一直保持静音**，所以整段只剩开头 0.02s。
  对照实验（1678 裁 0~0.45s）：
    带该 afade → RMS 0.0052 / peak 0.112
    不带     → RMS 0.1625 / peak 0.945      ← 差 31 倍
- 修法：删掉它；尾端淡出改写成 `afade=t=out:st=<末尾时刻>:d=0.05`。
- 顺带换了变体素材：1678(裁 0~0.45) + 1467(裁 0.19~0.60，前 0.19s 是起音)。
  轻压缩(threshold .15 / ratio 3 / makeup 2) + 峰值归一 0.82 / 0.88。
- 成品 RMS **0.169 / 0.190**（旧版 0.023，+7~8 倍），比入水(0.128)还实。
  4.1KB / 3.7KB。打包通过。
- 本日全部音频工作已沉淀为技能 `game-audio-sfx-pipeline`（采集→特征筛选→ffmpeg 加工→接线四段），
  含 afade 静音陷阱 / loudnorm 短素材失效 / alimiter 不生效 / 循环音效需独立通道 等坑。
  下次「加个音效」「这个太轻」直接走它。
- ★ 指标教训：选素材要看「裁掉首尾静音后的**有效段 RMS**」，不是峰值也不是 25ms 窗峰值。

## 对话/访客给物品 → 右上角播报（2026-09-17 晚）

需求：**"访客给物品会有提示"** —— 此前 `applyEffects` 是静默入包，玩家不知道拿到了什么。

### 改法（三层，各司其职）
1. **`DialogueSystem`** 新增 `DialogueGrant{kind:'item'|'relic', id, count, success}` + 可选 `onGrant` 回调。
   `applyEffects` 里 `item` 分支取 `addItem` 的返回值当 `success`（背包满 = false）；`relic` 恒 true。
   **系统层仍然零 DOM**——只把"到手了什么"报出去。
2. **`WorldMode`** 接线：`onGrant: (g) => this.onDialogueGrant(g)`；新方法 `onDialogueGrant`
   → `worldUIManager.showPickupResult(id, success, count)`；
   仅 `kind==='item' && success` 时再 `flashItemAndRefresh`（**遗物不入背包，没有格子可闪**）。
3. **`WorldUIManager.showPickupResult`** 的取名抽成 `displayNameOf(itemId)`：
   archetype 命中就用它，否则回退 `RELIC_ITEM_CONFIG[id].name`。
   ★ **不抽这一步，对话给遗物会播报成 `获得了 black_crown`（原始 id）。**

观感统一、零新组件、零新 z-index 坑。
